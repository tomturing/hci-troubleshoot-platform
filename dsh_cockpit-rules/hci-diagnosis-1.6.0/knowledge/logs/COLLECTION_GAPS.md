# 采集完整性与证据缺口

本页描述判定方法，不记录某个支持包的具体缺失项。采集失败表示证据不可用，不等价于产品组件故障。

## 检查顺序

1. 确认目标组件应在哪类节点运行，是否选对 `<NODE_BUNDLE>`。
2. 检查当前包中目标路径及已知路径变体是否存在。
3. 检查故障时间是否在活动日志、滚动文件、日期目录或归档覆盖范围内。
4. 检查实际采集记录，例如旧包 `collect_record.txt`、`log_list.json` 或根/节点 `metadata/` 中的 `summary.txt`、`files.tsv`、`commands.tsv`。以本包版本、实际成员和执行状态为准，不按文件名推断已收全。
5. 区分“未采集”“组件未部署”“当期无输出”“零字节状态文件”“压缩未展开”和“知识未覆盖的新路径”。
6. 寻找替代证据，并把未取得的资料记录为证据缺口。

## 状态定义

| 状态 | 判定依据 | 可否据此排除假设 |
|---|---|---|
| AVAILABLE | 文件存在且覆盖目标时间/对象 | 可以继续验证，不能仅凭无关键词直接排除 |
| OUT_OF_RANGE | 文件存在但不覆盖故障窗口 | 不可以 |
| COLLECTION_FAILED | 采集记录明确报错、权限拒绝或命令失败 | 不可以 |
| PATH_ABSENT | 当前包中候选路径及变体均不存在 | 不可以；先判断版本、节点和组件部署 |
| EMPTY_EXPECTED | 标志、锁、状态文件或当期无输出导致空文件 | 视文件语义判断 |
| EMPTY_UNKNOWN | 普通日志为零字节且无采集解释 | 不可以，标记不确定 |
| ARCHIVED | 资料位于压缩包，尚未按需读取 | 不可以 |
| UNSUPPORTED_FORMAT | 数据存在但当前工具不能安全解析 | 不可以 |
| QUERY_FAILED | 当前读取/解析/工具执行失败 | 不可以，区别于材料采集失败 |
| PARTIAL_READ | 扫描上限、输出截断或部分成员尚未读取 | 仅支持已查部分，不能作完整排除 |

## 常见大型或特殊资料

| 类型 | 示例模式 | 读取策略 |
|---|---|---|
| SQLite | `**/log_new.db` | 只读打开；先 schema，再按时间/对象限定字段查询 |
| SQL 导出 | `cmd-output/*.sql` | 先检索表名和资源 ID，不整文件加载 |
| zstd tar | `sf/log/*.tar.zst` | 先列成员，只提取目标组件 |
| gzip 日志 | `*.gz` | 流式定向搜索，不批量解压 |
| blackbox | `blackbox/<DATE>/`、`blackbox/<DATE>.tar.gz` | 只读取命中时间和指标的快照 |
| core/dump | `dump/`、`kdump/`、`pstore/` | 先记录元数据；不得把二进制直接放入模型上下文 |

## 替代证据原则

- `cmd-output/` 先核实际命令、节点/容器命名空间、时间、状态与输出；只读到了失败命令的内容不代表检测通过。
- 采集时状态、SQL/网络合并视图按其来源与时点解释；同一原文派生结果不算独立佐证。`not_run`、`unavailable`、`failed`、策略/mtime 排除、去重别名和缺文件分别处理。
- `nodes/`、未展开归档和旧节点目录按实际布局发现；仅保留容器命令的包不能凭缺少容器原生文件断言组件不存在。

- journal 不可用时，查产品服务日志、启动日志、kernel 和进程状态快照。
- 业务日志缺失时，查 API/Web 入口、任务记录、上下游组件和告警历史。
- kernel core 缺失时，可使用 kdump dmesg、MCE、pstore、IPMI 和重启时间交叉判断。
- 单节点缺失时，只在确认服务角色允许的前提下检查其他节点，不能把其他节点日志当成本节点证据。

输出缺口时必须说明：缺少什么、期望节点、目标时间、影响哪个假设、尝试过哪些路径变体、需要用户补充什么。
