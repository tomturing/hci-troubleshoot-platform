# 按需场景核查提示

只读与当前问题相关的行；这些是来源候选和检查问题，不是根因答案或必跑流程。路径均相对当前节点根，适用性以实际文件、版本和记录核实。目录日号、端口、采样间隔不预设。

| 现象 | 优先取得的证据 | 要区分什么 |
|---|---|---|
| 开机失败、启动超时 | 对应 task/请求；实际存在的 `sfvt_vtpdaemon.log*`、`vm-manager-api.log*` 或 `conductor.log*`；该 VM 的 QEMU 日志 | 已执行到参数/资源准备、进程创建、控制通道连接还是运行后检查；外层超时不自动说明网络、QMP 或资源是根因 |
| 镜像忙/加锁失败 | 同一镜像路径/磁盘 ID 的任务与 QEMU 记录；故障窗口的 `LOG_ps_user.txt` 或同类进程快照 | 是否为仍有效的备份/导出/编辑、实际残留、存储锁问题或路径/配置冲突；进程名或锁错误不能单独证明“应杀进程” |
| VM 黑屏/无响应 | VM/宿主及进程身份、QEMU/控制通道响应、guest 指标、宿主资源和设备事件 | 控制通道可响应只支持该通道可用，不能直接排除 guest、存储或转发问题；按当前对象和时段检查 |
| 操作成功但界面无记录 | 请求/任务结果、日志产生/推送/入库记录、只读操作库和页面查询条件 | 操作执行、日志生成、入库、同步副本及展示过滤分别是否成功；“接口成功”与“用户操作完成”须核语义 |
| 主机离线/网络不通 | 已采集的 `LOG_ping_statistic.txt*`、`LOG_mgmt_ping_statistic.txt*`、接口/路由、成员变化及内核/BMC/保护动作 | 按源节点、目标地址、网络平面和采样块关联；ICMP 不通只是不可达观察，重启后恢复不能单独排除网络或确诊主机悬挂 |
| 容量满/资源不足 | 告警产生时使用的值与查询返回；相关 `LOG_df.txt`、`LOG_df_sffs.txt`、`LOG_sffs_stat.txt`、挂载与内核记录（实际存在时） | 容量口径、单位、目标设备/挂载是否一致；查询失败、无效值或旧快照不能当真实资源耗尽 |
| IO 异常/外置存储问题 | 目标 VM 磁盘到卷/设备映射；相关 `sfvtk_all.log*`、`multipathd.log*`、`iscsid.log*`、kernel 与存储状态记录 | 请求失败发生在客户端、文件系统、路径还是设备；同窗异常未证明对象关联前不合并为根因 |

## 来源补充

- VM 控制来源可能包括 `sfvt_vtpdaemon.log*`、`sfvt_vtpperlproxy.log*`、`sfvt_vtpscheduled.log*`，也可能有 `conductor.log*`、`domino.rpc.log*`、`vmman-compute.log*`、`litevirt.log*`。只在当前节点与相关目录有限发现，用实际请求/trace/VMID 关联；不据某个版本号硬切全部调查路径，也不固定先扫每个核心日志。
- 操作记录问题可查实际存在的 `*vtplogd*.log*`、日志推送来源、`sfvt_sqlite_backup.sh.log*`、`sfvt_sqlite_db_check_and_sync.sh.log*` 及 DB/副本时点。日志文件名只提供线索，不证明固定同步周期、主从角色或文件覆盖行为。
- 黑盒/网络黑盒可能包含 `.gz`、`.zip` 或 tar 成员。先列成员和实际时间范围，在已有授权临时产物区定向读取，保留原归档成员定位。

## 关键关联要求

进程占用判断绑定节点、PID/启动身份、完整镜像路径或磁盘 ID及采样时点；日志中的备份/导出操作与快照不是同一时点时，不能直接确认残留。保留同时存在的合法任务解释。
网络探测按一个采样块回读时间、源、目标与统计，不将相邻块拼接；核实际采样间隔及空档，不假定全天连续。正常节点之间可达只能缩小观察范围，不能完全排除目标链路；管理网可达不能证明业务/存储网络健康。
读取当前/历史日志后才判断覆盖；一次末尾抽样可能漏掉失败前置条件。新线索应沿请求、对象或实际时间关系回读，而不是仅扩大 ERROR 搜索。

若证据只到直接失败条件，就保留该层结论和待核机制。日志出现的函数/文件位置只作记录定位或检索线索，不要求克隆仓库、查看产品源码或推断函数体。任何处置须遵守 [知识协同](KNOWLEDGE_USE.md) 的适用 KB 原文要求，不从本表生成操作命令。
