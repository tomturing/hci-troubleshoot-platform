# 阶段三：日志定位与分析准备

## 目标
* 根据第二阶段制定的排查思路，了解相关日志的结构、位置及用途，确定后续验证需要分析的日志范围。
* 本阶段重点是建立排查思路与日志的关联关系，为下一阶段的证据验证做好准备。

## 执行步骤

### 1. 了解日志结构
* 优先读取 `knowledge/logs/INDEX.md`，根据日志分类逐级查阅相关说明，了解日志文件的位置、用途、格式及关键字段。
* 按需读取日志知识，不一次性加载全部说明文件。

### 2. 定位相关日志
* 根据排查思路及诊断对象，确定需要分析的日志类型、所属节点、目录及具体文件。
* 结合实际离线日志目录确认文件位置，必要时在授权范围内进行有限探索。

### 3. 确定分析范围
* 根据故障时间、对象标识、错误特征及日志关联关系，缩小需要分析的文件和时间范围。
* 对于涉及多个对象或组件的排查思路，明确相关日志之间的关联关系及所需参数。
* 优先定位与主故障对象、时间窗口及排查假设直接相关的日志。
* 默认从主故障时间窗口开始检索，必要时根据任务生命周期、异常持续时间或已有证据扩大范围。
* 对于时间窗口之外的异常，应先确认其与主故障的关联关系，再决定是否继续定位相关日志。

### 4. 检查日志可用性
* 确认目标日志是否存在、是否覆盖故障时间，以及是否包含验证所需的信息。
* 对于缺失或无法定位的日志，记录具体情况，判断是否可以通过其他日志完成验证。

### 5. 形成日志分析计划
* 建立排查思路与目标日志的对应关系，明确需要查询的日志范围、关键字段及预期验证内容。
* 优先复用已定位的日志和已有信息，避免后续重复探索。

## 完成条件
* 已确定主要排查思路对应的日志位置、分析范围及所需信息，能够指导下一阶段执行验证。
* 对无法定位或缺失的日志已记录原因，不影响其他可执行思路继续验证。

## 执行原则
* 优先利用已有日志知识，根据实际需要逐级读取，不无目的遍历全部日志。
* 日志知识用于辅助定位，实际文件位置和内容以当前离线日志为准。
* 不得凭空假设日志路径、字段或对象关联关系。
* 本阶段主要负责日志定位与分析准备，具体证据获取和故障判断在下一阶段完成。
* 不强制固定日志定位方式，允许 Agent 根据实际情况自主选择合理方法。
