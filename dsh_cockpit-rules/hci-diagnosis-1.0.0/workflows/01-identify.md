阶段一：故障理解与诊断起点确认

## 目标
* 理解用户反馈的问题，优先通过离线日志中的报错、错误记录和告警，锁定具体故障事件及主要诊断对象。
* 遵循用户最小输入原则，能够自主获取的信息不要求用户提供。

## 执行步骤

1. 理解问题
* 理解故障现象、业务影响及已知线索，判断主要涉及的对象类型（虚拟机、宿主机、业务服务等）。

2. 发现故障
* 优先根据用户描述，在相关错误日志、报错和告警中查找故障事件，提取错误信息、发生时间及关联对象。

3. 锁定对象
* 根据 IP、VMID、HostID、任务 ID 等信息关联日志，尽可能缩小故障对象及事件范围。
* 如果是虚拟机相关的，必须让客户确认是哪一台虚拟机，或者是全部虚拟机才能继续

4. 确认起点
* 唯一明确：直接锁定诊断起点。
* 存在多个候选：优先自主过滤，仍无法区分时，请用户确认故障时间或具体对象。
* 无法定位：请求用户补充最少必要信息。

5. 确定主故障事件
* 根据用户描述、错误日志、告警及任务记录，确定当前需要诊断的主故障事件。
* 明确主故障对象、关联节点、发生时间、错误信息及相关任务，形成统一的诊断起点。
* 根据故障事件及日志时间精度确定初始分析时间窗口，后续排查以该事件为主要参照。
* 如果存在多个无法区分的故障事件，应先通过已有日志进一步关联，仍无法确定时再请求用户确认。

## 完成条件
明确以下信息后，进入第二阶段：
* 故障现象：发生了什么问题。
* 主要对象：具体需要排查哪个对象。
* 故障事件：需要分析的是哪次异常。
* 关联依据：为什么确定是该对象及事件。

## 约束
1. 优先自主获取信息，减少用户输入。
2. 只检索相关日志，避免无目的遍历。
3. 不得凭空推断对象或故障事件。
4. 存在重大歧义时，必须先让用户确认。
5. 本阶段不进行根因分析，仅确定诊断起点。
