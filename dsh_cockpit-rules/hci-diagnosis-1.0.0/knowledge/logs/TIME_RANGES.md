# 时间范围、轮转与时区

本页只描述时间识别规则，不保存任何案件的实际起止时间。每次诊断必须从当前日志包重新计算覆盖范围。

## 常见布局

| 布局 | 路径模式 | 判断方法 |
|---|---|---|
| 日号目录 | `sf/log/<DAY>/<component>.log*` | `<DAY>` 只表示月内日期，需结合采集时间、正文年份和相邻目录确认年月 |
| 组件目录 | `sf/log/<component>/app.log*` | 当前文件与轮转文件共存；从文件名和正文首尾确定范围 |
| 日期后缀 | `*.log-<YYYY-MM-DD>[.gz]`、`*.log-<YYYYMMDD>` | 文件名提供候选日期，仍需抽样正文确认 |
| 按日快照 | `sf/log/blackbox/<YYYYMMDD>/`、`sf/log/vn-blackbox/<YYYYMMDD>/` | 目录日期是快照分组，不保证所有成员覆盖全天 |
| 按日归档 | `sf/log/<DAY>.tar.zst`、`<YYYYMMDD>.tar.gz` | 先列成员，仅提取目标日期和组件 |
| 任务文件 | `sf/log/vtp/tasks/<UPID...>` | 解析 UPID 并核对正文；不能只用文件 mtime |
| 现场快照 | `cmd-output/`、`tmp/` | 多数没有逐行时间戳，以采集记录和命令输出内容为准 |
| 崩溃资料 | `sf/log/kdump/`、`pstore/`、`dump/` | 文件名可能包含崩溃时间；历史崩溃不等于本次故障 |

## 动态确定覆盖范围

1. 根据用户时间生成目标窗口，默认保留故障前后必要缓冲时间。
2. 检查当前节点实际存在的活动日志、轮转文件、日期目录和归档。
3. 对文本日志只抽样首个和末个有效时间戳；不要扫描全部正文来生成目录。
4. 对 `.gz` 使用流式首尾或定向检索；对 tar 先列成员。
5. 记录每个目标日志的 `最早时间、最晚时间、时间格式、时区、验证方式`。
6. 覆盖不足时标记证据缺口，不得将“无匹配”写成“无异常”。

## 时间格式和校准

- 常见正文格式包括 `YYYY-MM-DD HH:MM:SS[.毫秒/微秒]`、syslog 月日格式和 Unix 时间戳。
- Unix 时间戳必须通过样本确认秒/毫秒单位；数据库字段名不能替代验证。
- 产品日志通常使用现场系统时间，但不能预设固定时区；先从采集元数据、系统时间输出或多日志同一事件校准。
- IPMI/BMC 可能使用独立时钟，应结合 `ipmitool sel time get` 类输出校准。
- 跨节点关联前先检查节点时钟偏差；必要时扩大窗口并记录偏差。
- 文件 mtime、归档时间和业务事件时间含义不同，不能混用。

## 读取建议

- 文本：先按日期分钟和对象标识检索，再读取少量上下文。
- `.gz`：使用定向流式搜索，禁止为浏览方便全部解压。
- `.tar.*`：先列成员，再按组件和日期提取目标成员到临时位置。
- SQLite：先查看 schema 和时间字段样本，再做限定时间查询。
