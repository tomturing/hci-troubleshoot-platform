# 界面告警、报错与弹窗

用户问告警时从当前包识别其对象与事件，已唯一匹配则自主继续；无法区分且影响判断时才追问。用户问某次操作失败时先找对应任务/请求，不以更显眼的告警替换目标。告警文案须回到检测输入及产生链核实。

## 数据源与路径变体

| 层级 | 候选路径/资料 | 内容与用途 | 说明 |
|---|---|---|---|
| 告警主数据 | `sf/log/log_new.db`；`sf/data/local/log_new.db`；有限查找 `log_new.db` | 告警历史、对象、级别、状态 | 路径随版本/采集方式变化；只读打开 |
| 告警文本 | 数据库中的 `alert_translation` 或同类表 | 界面语言、对象名和描述 | 必须先检查实际 schema |
| 操作/事件 | `log`、`log_translation` 或同类表 | 操作、事件、任务结果 | 不与告警候选混为一类 |
| 告警检测 | `sf/log/<DAY>/sfvt_vtpalertd.log*`、其他 `*vtpalertd*` | 指标读取、规则判断、告警生成 | 文件名和目录可能变体 |
| 解析/入库 | `sf/log/<DAY>/sfvt_vtplogd.log*`、其他 `*vtplogd*` | 解析、翻译、写库链路 | 通过 log_id/时间关联 |
| 推送 | `alert-pushd.log*` | PushTrap/外部通知 | 通过 logID、trace 关联 |
| 界面查询 | `sf/log/sf-openapi/`、`sf/log/apache2/` 或实际 Web/API 日志 | 页面查询、接口和展示异常 | 数据已入库但页面异常时使用 |
| 当前检测状态 | `tmp/.alert.*` | 部分硬件、磁盘、网卡和 VM 检测状态 | 是采集时快照，不是历史告警 |
| 告警规则 | `cfs/alert.conf`、`cfs/alert/` | 阈值、屏蔽、邮件和短信策略 | 配置不等于告警事实 |

## 常见字段

数据库 schema 必须现场读取。若存在下列字段，可用于候选和关联，但不能假设所有版本都有相同字段或枚举：

| 字段 | 用途 |
|---|---|
| `start`、`end` | 开始和恢复时间；确认秒/毫秒单位与时区 |
| `type`、`level` | 告警类型和级别 |
| `host`、`hostname`、`vm` | 主机或 VM 线索 |
| `object_type`、`object_id`、`object_name` | 对象类别、唯一标识和显示名称 |
| `description` | 原始告警描述 |
| `status`、`process` | 状态/处理状态；枚举含义按版本验证 |
| `log_id` | 检测、入库、推送链路关联键 |
| `upid` | 后台任务关联键 |

## 候选告警流程

1. 从用户描述提取大致时间、告警文字、对象名称、IP、VMID 或截图信息。
2. 在相关节点定位实际告警数据库；不存在时使用告警处理文本日志生成候选。
3. 只读检查 schema、时间字段样本和覆盖范围，再按已有条件查询。
4. 优先关联翻译表取得界面显示文字；缺失时回退原始描述。
5. 同类重复记录可分组显示，保留原记录键、开始/恢复与事件边界；不能把多次不同事件合并为一次。
6. 每项至少展示：时间、对象、类型、描述、状态和关联依据；内部保留 log_id、UPID、节点和来源路径。
7. 已唯一匹配直接继续；候选仍有关键歧义时，请用户选择或说明“以上都不是”。
8. 用时间、对象、log_id、UPID 和 trace 关联检测、入库、推送及业务组件。检查依赖查询是否成功、输入值是否有效；不把“容量/内存不足”直接当真实资源耗尽。

候选格式示例：

```text
1. <告警时间>
   对象：<对象类型和标识>
   类型：<告警类型>
   内容：<界面文字或原始描述>
   依据：<节点及数据源>

2. 以上都不是
```

占位内容仅定义交互格式，不能作为故障事实。

## 确认后的分支

| 现象 | 后续首查 |
|---|---|
| 数据库无记录，但检测日志显示已产生 | 解析、翻译、写库错误及数据库可用性 |
| 数据库有记录，但界面不显示 | OpenAPI/Web、查询时间、权限和过滤条件 |
| 页面显示正常，但外部通知未收到 | 推送日志、邮件/短信配置、外部通道 |
| 告警内容或对象错误 | 翻译、对象映射、检测输入和版本字段含义 |
| 告警频繁重复 | 类型＋对象＋开始/恢复时间、阈值、恢复条件、屏蔽策略 |
| 告警是否真实 | 转入计算、存储、网络、硬件或 VM 路由，以业务证据验证 |

## 安全和证据规则

- 数据库必须只读；禁止修改、修复或写回。
- 不查询全表正文；先 count/schema/时间范围，再限定字段和条件。
- 数据库记录只能证明告警被记录，不能单独证明告警根因真实。
- 输出前按需脱敏用户名、内部 IP、VM 名称和业务标识。
- 数据库未采集或时间不覆盖时，记录缺口，不得宣称“没有告警”。
