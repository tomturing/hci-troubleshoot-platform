# cockpit-v1 使用说明

规则修订：cockpit-v1.6（2026-11-11，待实测）。轻量 Markdown 优化版，继续使用现有 DeepSeek Harness 和日志读取工具；当前没有新增运行插件、诊断引擎或数据库要求。

## 日常使用

1. 将本目录的 `AGENTS.md`、`workflows/`、`knowledge/` 放入选定的日志工作区根，明确本次授权案件目录；已有同名规则时先选择要采用的一套，不混用冲突版本。
2. 在 Harness 打开该工作区，直接描述故障或查询目标。确认能读到根 AGENTS 和知识入口；如果未自动加载，在首次消息中明确要求读取根 AGENTS。
3. 同会话继续追问、补充对象/时间或新日志。Agent 复核受影响判断，已读且未变的规则不反复加载。
4. KB 已可用时指明本地资料或现有查询工具；无 KB 也可调查原因。提供具体处置必须回读适用案例原文。

入口：[AGENTS.md](AGENTS.md)。流程文件按需读取，知识入口是 [knowledge/logs/INDEX.md](knowledge/logs/INDEX.md)。文档描述行为要求，不表示沙箱、脱敏、缓存或规则检查程序已经实现。

## 本次重点

- 操作失败优先锁定对应任务，其他问题按真实对象调查；告警文案不直接定根因。
- 删除强制重复确认 VM、固定单域、每次从头执行和机械来源数量要求。
- 加强输入值/完成条件、并发写回、配置与运行状态、时钟及保护动作的区分检查，均按当前问题选用。
- 区分失败条件和上游原因，保留反证与覆盖；CPU 累计时间不作正常运行证明。
- 复用可核对的查询，合并同源读取，失效或截断如实说明；不要求全包预处理。
- 首答围绕结论与范围、关键证据与原因链、恢复状态、方案或下一步展开；字段和明细查询按需回答；适用 KB 方案与原因分别核验。
- 按需使用 [场景核查提示](knowledge/logs/SCENARIO_CHECKS.md)：区分开机阶段、镜像占用者、操作记录链、网络探测视角和容量统计来源。
- 相关轮转/压缩日志按实际覆盖读取；错误码、原句特征和场景互补检索；同编号案例核标题/原文，草稿和匹配分数不当作权威结论。

本版借鉴 hci-dev-ai-troubleshoot 的日志导航和方法，改写为自包含 Markdown。未接入其仓库克隆、分支切换、源码分析、远程拉取、多 Agent 编排和自动自进化脚本；场景提示不依赖该目录存在，也不将其内置案例自动认定为已核验方案。

v1.3 进一步借鉴 solvia 的 HCI 案例检索与核验经验：中性事实查询、保留否定信息、新证据重检索、不同机制代表候选对照、必要条件核对、完整原文/附件与实际参数确认。详见 [知识协同](knowledge/logs/KNOWLEDGE_USE.md)。只在已有授权 HCI 知识入口上使用，不引入 AF 内容或 solvia 的运行工具依赖。

## 使用前核对

v1.6 将定位规则前移到原因调查首次检索前，验证规则前移到找到代表失败后的下一步决策。首次需要结构化解析时探测已有只读能力；关键数字区分配置、现场观测、产品统计和模型推算；成功对照同时核需求量、阈值、输入获取和完成阶段。保留模型自主调查和原有KB方案要求，不把“有统计异常”预设为所有问题的原因，也不机械要求多个来源才允许确认根因。

选择若干有授权原包的代表问题，分别验证操作失败、主机/服务异常、字段查询、跨域调查和补证。首次输出前隔离旧报告与人工答案，保存首次结果后再复核；同一问题看过答案后的重跑不能算独立效果验证。
v1.6 尚未在 Harness 上完成真实支持包验证，不能将行为要求视为已实现的效果。部署时保留所采用文件的修订副本，与此前规则分开创建工作区和会话。文档不包含评测案件的标识、数值或预期答案。
