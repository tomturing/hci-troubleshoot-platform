# 证据验证与结论修正

每个关键判断回到当前包的对象、操作、有效时间和原文。记录现象、直接失败条件、因果机制和产品缺陷分别判断；证据充分只确认其实际支持的范围。

## 按当前问题选择区分检查

| 可见线索 | 下一步核对 |
|---|---|
| 告警说内存/容量/网络异常 | 谁生成告警、依赖哪些值、这些值是否获取成功；错误转述不能作独立佐证 |
| 操作失败或进度长期不动 | 对应请求/任务的实际失败步骤、完成条件、状态/计数语义；负值或 -1 不自动代表异常 |
| 文件/配置存在但行为不符 | 配置、运行状态、历史生效与对象路径是否一致；采集时配置不能替代故障时配置 |
| 同对象多次操作、锁或状态残留 | 区分任务和时间重叠、持锁/写回对象及先后；“锁存在”不单独证明并发缺陷 |
| 服务停止、网络断开或多盘异常 | 区分初始失败、平台保护/隔离动作、升级/维护动作与后果，核事件先后及关联 |
| 启动日志结束或错误很多 | 对比可比成功样本，并查运行行为；末行、错误数量、两份相同日志均不能单独证明卡死或健康 |
| 无匹配或某时段后没错误 | 检查查询词、覆盖、轮转及采集截止；无异常记录不能直接作排除或恢复证据 |
| ping 丢包后恢复、某节点单向不可达 | 核源/目标、网络平面、采样窗口及保护动作；恢复只证明该观察变化，不能单凭它排除链路故障或确认主机悬挂 |

这些是查询提示，不是固定根因表；只执行能改变当前判断的检查，不机械逐行扫完。
保留原时间和精度，跨节点先核时钟；文件 mtime 不代表谁改过或是否从未改过。CPU 累计时间不等于墙钟运行时长，也不能单独区分正常运行和初始化忙循环。

## 原因成立需要什么

找到代表失败或关键判据就进行本节核验，用于选择下一查询，不只用于报告检查。当结论依赖程序计算的值/状态，或使用“调整后成功”作原因依据时，选一个代表失败；有可比样本时选一个对照。先指出哪项关键前提仍未知，再查能改变结论的来源；无需另建完整台账。

| 待核项 | 失败与对照分别确认 |
|---|---|
| 归属和阶段 | 对象、节点、请求/父子关系、时段；比较的是哪一步，最终完成到哪一步 |
| 决定性输入 | 完整原值、单位、有效时点、获取成功/失败、缓存/默认值与纠正；标明是配置、现场观测、产品统计还是模型推算 |
| 判定关系 | 配置/阈值、实际比较值和返回；计算关系来自何处，哪些语义尚未确认 |
| 变化与未变化 | 配置/阈值、需求量/负载、输入获取、异常、时点和完成阶段分别怎样变化；其他条件未知时不说“只有一个变量变化” |

优先查询能补关键未知或区分解释的来源。直接读到产品告警只证明产品记录了该值；结合对象、时点、上游采集/缓存和计算口径核它能否证明真实状态。不同文件、进程或节点可能共享同一统计源；独立性未知就保留未知，不直接宣布已互证，也不因此否定全部产品统计。输入完整可信且作用关系已核实的产品统计可以支持原因，无需机械要求第二个来源。

同一统计链的报错、纠正值与反推量不能相互证明真实状态；即使公式成立，仍须验证输入。字段差分接近、趋势相似只支持候选关系，不证明公式或测量独立。配置快照与读取值一致支持配置存在，不单独证明该请求没有读缓存；记录mtime不自动等于快照采集/生效时刻。计算保留原值与单位并用工具核算；未知公式不能由试算不匹配证明输入必然缺失。

同一对象的后续尝试是更可比的对照，不等于同一请求或单变量实验。异常在失败和成功中都出现，只说明它不是单独充分条件；仍须核其影响与阈值等条件的共同作用，不能据此排除必要条件或确认根因。超时只证明调用异常，具体成因须用当前证据区分；几个选定样本不能代表全部时段。

排除某依赖前核它是否参与准备、元数据或状态查询。数据尚未传输、另一条路径成功或本地准备完成，均不能证明相关远端依赖健康。区分检查通过、准备完成、业务完成和持续恢复；配置调整后某一步成功不单独证明原机制已消除。

缺口优先从同请求上下文、独立观测和允许使用的对应版本资料核实，不以取得产品源码为前提。仅查与当前判断相关的项目；已无可核来源时保留失败环节和具体缺口，不为通过复核预先指定根因。

- 观察事实：原文存在且来源、对象和定位可信。
- 直接失败条件：状态/返回语义已核实，与目标事件匹配。
- 因果机制：作用关系及适用时间有证据；关键歧义或竞争解释有区分性核查，硬反证已解释。
- 产品缺陷：需要允许发布的适用缺陷资料、实现说明或受控复现等依据；没有源码不阻止其他有据原因判断，但不能臆造内部代码。

可用“已支持、部分支持、未确定、证据冲突、待专业复核”表达每项判断，不用百分比或来源数代替依据。单条权威记录可能足以支持限定机制；多个文件若同源仍只是一组信息。
未出现事件作反证前，应核目标/时段覆盖以及该机制应留下记录的依据；缺证只说明无法排除。

## 追问与纠正

用户/专家给出原因、KB 提供相似机制时，先作待核线索，再对照支持与反对原文；说明原判断保持、修正或仍不能验证。新对象/时段/批次只重查相关前提，不把较晚快照回填历史。
使用案例时核其必要条件与当前 E 的匹配/不匹配/未知/冲突；新证据指向现有候选未覆盖的机制时重新检索。案例示例和用户自述不冒充本次采集观察，关键前提未知不以“其他条件都很像”补齐。
新调查和盲测不读旧答案；补证后的修正不能冒充首次独立判断。会话中的“反思”也须核验，不能自动写回规则或知识。

证据已足够或材料已无法区分时结束本轮。对旁路线索保留简短关联状态；不必解释所有 ERROR 才输出主问题结果。
