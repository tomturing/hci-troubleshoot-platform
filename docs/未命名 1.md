## 变量声明
| 变量名 | 来源 | 实体 | 动作 | 触发时机 |
| --- | --- | --- | --- | --- |
| env_injection | env_context | 环境上下文 | 注入 | SOP执行初始化时批量 |
| is_sys_disk | user_confirm | 用户 | 确认 | JIT，工具推荐候选后确认 |
| disk_sn | user_input | 用户 | 输入 | JIT，完全阻塞 |
| asan_disks | tool | 工具 | 调用 | JIT，自动调用acli_storage_disk_list |
| disk_dev |  | Agent | 传递 | agent运行过程中赋值 |
| smart_info |  | Agent | 传递 | agent运行过程中赋值 |


## 前置检查：
1、执行以下指令执行操作（异常可忽略，6.8.0及以上版本执行后会进入aSAN容器，6.8.0以下版本执行会报错但是可以忽略）：

```bash
container_exec -n vs-cp-manager
```

2、{is_sys_disk}为true跳转【系统盘寿命异常】，{is_sys_disk}为false跳转【aSAN盘寿命异常】

## 系统盘寿命异常
### 前置检查：
1、获取系统盘盘符

```bash
lsblk | grep boot
```

+ 若回显包含 `sdX`（如 `sda1`），表示系统盘为非软RAID阵列，盘符为 `sda`，盘符内容赋值给变量{disk_dev}，跳转【非软RAID阵列盘】。
+ 若回显包含 `mdX`（如 `md0`），表示系统盘为软RAID阵列，盘符为 `md0`，盘符内容赋值给变量{disk_dev}，跳转【软RAID阵列盘】。

### 软RAID阵列盘
#### 判断方法
1、查看软RAID阵列盘有哪些成员盘及其盘符

```bash
mdadm --detail /dev/{disk_dev}
```

回显中带有 `sd` 前缀的设备即为实际盘符（如 `sdb`）。  
2、获取SMART信息（不清楚告警系统盘具体指向哪个成员盘情况下，成员盘的SMART信息都需要获取）

```bash
smartctl -a /dev/sdX   # sdX 为步骤1获取的盘符
```

+ 若提示 `Error smartctl args: '-a'`，请改用： 

```bash
smartctl.real -a /dev/sdX   # sdX 为步骤1获取的盘符
```

3、步骤2中可能获取两组SMART信息，根据变量{disk_sn}选择唯一的寿命异常盘的SMART信息

4、将SMART信息赋值给变量{smart_info}，跳转【硬盘厂商识别与寿命判断】

### 非软RAID阵列盘
#### 判断方法
1、获取SMART信息

```bash
smartctl -a /dev/{disk_dev}
```

+ 若提示 `Error smartctl args: '-a'`，请改用： 

```bash
smartctl.real -a /dev/{disk_dev}
```

+ 若提示 `device lacks SMART capability`，则可能为硬件 RAID 环境，则跳转【硬件RAID阵列盘】

2、将SMART信息赋值给变量{smart_info}，跳转【硬盘厂商识别与寿命判断】

## aSAN盘寿命异常
### 判断方法
1、根据告警硬盘标识{disk_sn}从aSAN硬盘列表{asan_disks}中获取对应的盘符，将盘符赋值给变量{disk_dev}  
2、如果盘符前缀为nvme，则跳转【NVME盘】  
3、获取SMART信息

```bash
smartctl -a /dev/{disk_dev}
```

+ 若提示 `Error smartctl args: '-a'`，请改用： 

```bash
smartctl.real -a /dev/{disk_dev}
```

+ 若提示 `device lacks SMART capability`，则可能为硬件 RAID 环境，则跳转【硬件RAID阵列盘】	

4、将SMART信息赋值给变量{smart_info}，跳转【硬盘厂商识别与寿命判断】

### NVME盘
#### 判断方法
1、获取SMART信息，查看Percentage Used项（使用寿命百分比），此项达到100%代表写入寿命耗尽，继续向盘内写入有数据安全性风险，达到90%即可提供解决方案为返修，SOP至此结束。

```bash
smartctl -a /dev/{disk_dev}
```

## 硬件RAID阵列盘
### 前置检查
1、确认 RAID 卡类型

```bash
lspci | grep -i "controller:" | egrep -i "raid|sas" | grep -v "Volume Management Device"
```

示例回显：

```plain
0000:18:00.0 Serial Attached SCSI controller: Broadcom / LSI SAS3008 PCI-Express Fusion-MPT SAS-3 (rev 02)
```

### MegaRAID 卡（如 SAS 9361-8i、INSPUR 3008IMR 等）
#### 判断方法
1、查看虚拟磁盘

```plain
/sf/bin/raidtools/bin/storcli64 /c0/vall show
```

2、查看物理成员盘，根据 {disk_sn}确认对应的DID

```plain
/sf/bin/raidtools/bin/storcli64 /c0/v1 show PDs   # 查看 VD1 的成员盘
```

3、查看物理盘 SMART信息

```plain
smartctl -a -d megaraid,<DID> /dev/{disk_dev}
```

+ 若提示 `Error smartctl args: '-a'`，请改用： 

```bash
smartctl.real -a -d megaraid,<DID> /dev/{disk_dev}
```

 4、将SMART信息赋值给变量{smart_info}，跳转【硬盘厂商识别与寿命判断】

### SAS RAID 卡（如 SAS3008、SAS9311-8i）
#### 判断方法
1、查看RAID卡信息，包含虚拟磁盘和物理盘 SAS Address

```plain
/sf/bin/raidtools/bin/sas3ircu 0 display | grep -A15 "IR Volume Information"
```

2、查看 by-path 设备

```plain
ls -l /dev/disk/by-path/
```

3、建立映射表（示例），根据 {disk_sn}确认对应的sg设备路径，将sg设备盘符名赋值给{disk_dev}

| RAID 类型 | Encl:Slot | SAS Address | sg设备 | sn |
| --- | --- | --- | --- | --- |
| RAID1 | 1:0 | 500605b001234567 | /dev/sg0 | xxx |
| RAID1 | 1:1 | 500605b001234568 | /dev/sg1 | xxx |
| RAID0 | 1:2 | 500605b001234569 | /dev/sg2 | xxx |


4、查看物理盘 SMART信息

```plain
smartctl -a /dev/{disk_dev}
```

+ 若提示 `Error smartctl args: '-a'`，请改用： 

```bash
smartctl.real -a /dev/{disk_dev}
```

 6、将SMART信息赋值给变量{smart_info}，跳转【硬盘厂商识别与寿命判断】

## 硬盘厂商识别与寿命判断
### 前置检查
1. <font style="color:#000000;">从{smart_info}变量中提取</font><font style="color:#222222;">Device Model</font><font style="color:#000000;">、</font><font style="color:#222222;">Model Number</font><font style="color:#000000;">和</font><font style="color:#222222;">Product</font><font style="color:#000000;">字段拼接作为硬盘型号信息</font>
2. **型号匹配规则**：`kcm*`、`kpm*`、`krm*`、`kcd*`、`kxd*`、`kfl*`、`klc*`、`khk*`、`*kioxia*`、`*toshiba*`跳转【Kioxia / Toshiba（铠侠 / 东芝）】
3. **型号匹配规则** ：`ssdsc*`、`ssdpe*`、`ssdpf*`、`mdtpe*`、`*intel*`跳转【Intel（英特尔）】
4. **型号匹配规则** ：`mz*`、`*samsung*`跳转【Samsung（三星）】
5. **型号匹配规则**：`mtfd*`、`*micron*`跳转【Micron（美光）】
6. **型号匹配规则**：`ts*`、`*transcend*`跳转【Transcend（创见）】
7. **型号匹配规则**：`hs-ssd*`、`*hikvision*`跳转【Hikvision（海康）】
8. **型号匹配规则**：`sts*`、`dts*`、`datssd*`跳转【大唐存储】
9. **型号匹配规则**：`hwe*`、`hssd*`、`*huawei*`跳转【Huawei（华为）】
10. **型号匹配规则**：`rsye*`、`*longsys*`跳转【Longsys（江波龙）】
11. **型号匹配规则**：`fi*`、`*foresee*`跳转【Foresee】
12. **型号匹配规则**：`liteon*`、`*ssstc*`跳转【Liteon / SSSTC（建兴）】

### Kioxia / Toshiba（铠侠 / 东芝）
#### 判断方法
1. **判断说明**：SMART 第 173 项的 `VALUE` 字段，当 `VALUE` 小于 100 时即可提供解决方案为返修，SOP至此结束。

### Intel（英特尔）
#### 判断方法
1. **判断说明**：SMART 第 233 项的 `VALUE` 字段，当 `VALUE` 小于或等于 10 时即可提供解决方案为返修，SOP至此结束。

### Samsung（三星）
#### 判断方法

### Micron（美光）
#### 判断方法

### Transcend（创见）
#### 判断方法

### Foresee

### Liteon / SSSTC（建兴）
#### 判断方法
1. **判断说明**：优先使用 SMART 第 202 项的 `VALUE` 字段，当 `VALUE` 小于或等于 10 时即可提供解决方案为返修，SOP至此结束。若无 202 项，则使用 SMART 第 177 项的 `VALUE` 字段，当 `VALUE` 小于或等于 10 时即可提供解决方案为返修，SOP至此结束。
