# KBD 生产者信号产出变量目录

KBD 管理页中的 QKV 生产者信号不再自由输入产出变量名。变量目录由"工具管理"中对应 QKV 工具的"产出变量（produces）"维护，保存后的 `parameters_schema.properties.produces.default` 是唯一数据源。

## 使用规则

1. 在工具管理中打开 `qkv_task`、`qkv_alert` 或 `qkv_dialog`，可新增、修改或删除产出变量及其 JSON 路径并保存。新增时会先保留一条空草稿供填写；只有保存后的具名变量才会进入 KBD 变量目录。可视化编辑器会将变量名规范化为全大写、JSON 路径规范化为全小写。
2. 在 KBD 管理中编辑生产者信号时，变量名下拉框只显示当前采集类型对应工具的已启用目录项；例如 `qkv_task` 只显示 `qkv_task` 的产出变量。选中变量时，页面会自动写入该目录项绑定的 JSON 路径；清空变量时也会清空路径，避免错误组合。
3. 删除目录项不会改写已有 KBD。旧信号会以"历史值"回显，允许审核者保留或替换为当前目录中的变量，避免目录调整造成历史工作稿无法保存。

## 别名（alias）使用说明

当**同一个 KBD 内有多个生产者信号需要产出同名变量**（如两个信号都需要产出 `END` 时间变量用于对比），可在"别名"输入框中为每个产出条目指定一个 **KBD 级局部变量名**：

- **`name`**：从目录选择的标准变量名（全局统一，由工具管理维护）。
- **`alias`**：可选的 KBD 级别名（如 `END1`、`END2`），**运行时写入变量池的实际 key**。留空则直接使用 `name`。
- **effective_key 规则**：`alias`（非空时）优先，否则 `name`。
- **格式约束**：alias 须全大写字母、数字、下划线，且以字母开头（与 name 规则相同）。
- **唯一性约束**：同一信号的多个产出条目中，effective_key 不得重复。

### 示例

两个 QKV 生产者信号都产出 `END`，通过 alias 区分：

| 信号 | name | alias | 运行时 key |
|------|------|-------|-----------|
| 信号一：起始时间 | END | END1 | END1 |
| 信号二：结束时间 | END | END2 | END2 |

消费者信号（QFK）中可用 `{{END1}}`、`{{END2}}` 分别引用两段时间。

目录读取失败时，KBD 编辑不会被阻塞，但不能新增受目录约束的变量；恢复后刷新页面即可重新加载目录。
