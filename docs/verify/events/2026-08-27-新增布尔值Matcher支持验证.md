# 新增布尔值 Matcher 判定类型支持验证

## 1. 需求与背景

在信号处理的第一步“取值 / AI 处理方式”中，输出类型支持收敛后的 4 种标准类型（文本 / 数值 / 布尔值 / 数组）。当第一步通过 AI 智能推导或 JSON 字段提取出布尔值（`True` / `False`）时，第二步“判断”原有的 7 种 Matcher（keyword / regex / state / threshold / delta / trend / exists）主要面向文本或数值，缺乏直接消费布尔真假的确定性判定器。

本次改造为第二步判断新增 **`boolean`（布尔值判定）** Matcher 类型，实现第一步布尔输出与第二步判定的完整闭环。

---

## 2. 变更范围与设计

### 2.1 前端变更
1. **`MatcherEditor.vue`**：
   - `allMatcherTypeOptions` 中注册 `{ label: '布尔值判定（判定真假）', value: 'boolean', desc: '判定布尔输出为 True 或 False' }`；
   - 切换到 `boolean` 类型时，默认将第一步提取模式（`extract.value_mode`）自动联动设置为 `boolean`；
   - 模板中为 `boolean` 提供专属的提示说明标签，并复用“期望（满足/不满足）”开关（开启：期望为 `True`，关闭：期望为 `False`）。
2. **`OutputProcessingEditor.vue`**：
   - 允许的 Matcher 类型列表 `matcherTypes` 同步扩充 `boolean`。

### 2.2 后端变更
1. **`backend/shared/signals/matcher.py`**：
   - 在 `evaluate_matcher` 中新增 `mtype == "boolean"` 的求值逻辑：
     - 调用 `_extract_predicate_values(text, matcher, "boolean")` 获取布尔值列表；
     - 判定规则：`matched = hit if expected else not hit`；
     - 输出结构化 `detail` 与具备可回查性的 `evidence` 审计日志。
2. **`backend/shared/signals/qkv_output_processing.py`**：
   - `_validate_match` 白名单加入 `"boolean"`；
   - `_assert_concrete_value` 中为 `"boolean"` Matcher 绑定 `"boolean"` 取值类型。
3. **校验与发布门禁**：
   - `backend/kb-service/app/routes/extract_signals.py`：`VALID_MATCHER_TYPES` 加入 `"boolean"`；
   - `backend/shared/schemas/acquirer_args.py`：`EFFECT_MATCHER_TYPES` 与 `_EFFECT_MATCHER_REQUIRED_FIELDS` 注册 `"boolean"`；
   - `backend/shared/schemas/capability_descriptor.py`：`supported_matchers` 注册 `"boolean"`；
   - `backend/shared/schemas/signal_schema.py`：`_MATCHER_REQUIRED_FIELDS` 注册 `"boolean"`，且放行智能推导（`derive`）与 AI 处理模式下的 `boolean` Matcher；
   - `backend/scripts/gen-schemas.py`：同步更新 Matcher 与 QKV Match 的 JSON Schema 枚举，并重新生成 15 份 Schema 文件。
