## 关键场景验证

### 真实 ps/grep/awk 等价转换

输入：

```bash
acli system ps auxf | grep -e '-id 8243094091404' | grep -v grep | awk '{print $2}'
```

转换结果：

```yaml
command: ps auxf
produces:
  - name: KVM_PID
    type: integer
    extract:
      type: text
      include:
        - "-id {{VM}}"
      column_mode: index
      column: 2
```

验证结论：宿主机只执行 `acli system ps auxf`；平台在内存中完成包含行筛选与第 2 列提取；`grep -v grep` 被安全删除；变量 `VM` 自动进入输入变量依赖。

### 完整输出与 Fail Closed

- 未截断 stdout/stderr 直接使用物理流，二者不会拼接。
- 截断时分别读取 `cmd_cache:{exec_id}` 与 `cmd_stderr_cache:{exec_id}`。
- 缓存缺失、缓存读取异常、输出超限、空输出、零匹配、多匹配、列越界、类型转换失败均返回稳定错误码，不写空变量。
- 产出变量模式下命令退出码非 0 返回 `QFK_COMMAND_FAILED`，后续依赖信号不会使用伪结果。

### 安全边界

- 转换器只解析字符串，从不执行输入。
- 支持常见字面量 grep、exclude、忽略大小写、单列 awk 与单列 cut。
- sed、sort、聚合/多字段 awk、未知管道、`||` 和不能无损表达的正则均被拒绝并标记人工复核。
- Signal Schema 禁止 QFK command 保存 `|`，禁止 QKV 使用文本 extract，并保证 `path` 与 `extract` 互斥。
