# bash_exec 容器化契约与工具调用前置校验验证方案

关联方案：[bash_exec 容器化契约与工具调用前置校验方案](../../solution/events/2026-06-11-bash_exec容器化契约与工具调用前置校验方案.md)。

## 验证目标

本验证方案确认三类能力：

1. 命令失败时，真实 `stderr` 能从 terminal_bridge 双通道一路保留到页面、LLM、审计。
2. `bash_exec` 必须指定容器，缺容器或容器注入行为在真实执行前被拦截。
3. `acli_exec` 在真实执行前基于 aCLI catalog 拦截不支持命令，并允许 LLM 重新规划。

## 自动化测试

### A1：BridgeRelayExecutor 双通道失败解析

**范围**：`backend/agent-service/tests/tools/test_executor.py`

**步骤**：

```bash
uv run pytest backend/agent-service/tests/tools/test_executor.py -q
```

**新增断言**：

- Redis 模拟返回：
  ```json
  {"stdout": "", "stderr": "invalid option", "exit_code": 2}
  ```
- 期望：
  - `result.exit_code == 2`
  - `result.stdout == ""`
  - `result.stderr` 包含 `invalid option`
  - 不出现 `cannot access local variable 'output'`

### A2：`bash_exec` schema 与语义校验

**范围**：新增或扩展 agent-service 单元测试。

**用例**：

| 用例 | 输入 | 预期 |
|------|------|------|
| 缺容器 | `{"command":"ps aux","reason":"检查进程"}` | `BASH_CONTAINER_REQUIRED` |
| 非法容器 | `{"container":"bad","command":"ps aux","reason":"检查进程"}` | `BASH_CONTAINER_INVALID` |
| 容器前缀注入 | `{"container":"asv-con","command":"docker exec x ps aux","reason":"检查进程"}` | `BASH_CONTAINER_PREFIX_FORBIDDEN` |
| aCLI 混用 | `{"container":"asv-con","command":"acli vm list","reason":"检查 VM"}` | `BASH_ACLI_FORBIDDEN` |
| 合法只读 | `{"container":"asv-con","command":"ps aux","reason":"检查进程"}` | 校验通过 |

### A3：`acli_exec` catalog 校验

**范围**：新增或扩展 agent-service 单元测试。

**用例**：

| 命令 | 预期 |
|------|------|
| `acli --formatter json vm list` | 通过 |
| `acli storage asan disk list` | 通过 |
| `acli storage disk list` | 拦截，不下发执行 |
| `acli acli command list` | 通过 |
| `acli vm list --formatter json` | 按策略返回 warning 或 error |

### A4：ReactEngine 校验失败自修正

**范围**：`backend/agent-service/tests/unit/`

**模拟**：

1. LLM 第一次返回缺容器 `bash_exec`。
2. `ToolSemanticValidator` 返回 error。
3. ReactEngine 不调用 `BridgeRelayExecutor`。
4. work_messages 中追加校验失败反馈。
5. LLM 第二次返回合法 `bash_exec`。

**预期**：

- 第一次不会产生真实执行。
- 第二次可以进入正常风险分级和执行流程。
- 不出现前端卡片等待输出的悬挂状态。

## 集成验证

### I1：不下发 terminal_bridge 验证

**步骤**：

1. 打开一个测试工单并连接 SSH。
2. 通过测试桩或提示诱导 LLM 调用：
   ```json
   {"tool_name":"bash_exec","args":{"command":"ps aux","reason":"检查进程"}}
   ```
3. 观察 conversation-service SSE 与 terminal_bridge 日志。

**预期**：

- 不出现 `agent_exec_command` SSE。
- terminal_bridge 不出现 `ssh_exec_process`。
- agent-service 日志出现 `tool_call_semantic_validation_failed`。
- LLM 重新规划时明确补充 `container`。

### I2：stderr 页面展示验证

**步骤**：

1. 使用合法容器执行一个确定会失败的只读命令，例如错误参数或不存在文件读取。
2. 等待工具卡片完成。

**预期**：

- 工具卡片状态为失败。
- 终端回显区域展示 stderr。
- 页面不展示“结果解析失败：cannot access local variable 'output'”。
- LLM 后续回复引用真实 stderr，而不是解析异常。

### I3：aCLI catalog 拦截验证

**步骤**：

1. 诱导 LLM 调用 `acli_exec(command="acli storage disk list")`。
2. 观察工具调用链路。

**预期**：

- 不下发 terminal_bridge。
- ReactEngine 注入规划反馈，指出该命令不在 catalog。
- LLM 后续应尝试 `acli storage --help` 或 `acli storage asan disk list`。

## 管理端验证

### M1：工具管理 schema 校验

**步骤**：

1. 打开管理端工具管理。
2. 编辑 `bash_exec`，删除 `container` 属性或从 `required` 中移除。
3. 点击保存或“校验工具定义”。

**预期**：

- 保存被阻断。
- 页面显示 error：`bash_exec 必须要求 container 为必填字段`。
- 点击“校验工具定义”时无需真实保存即可展示同一条 error。

### M2：usage_template 占位符校验

**步骤**：

1. 编辑任意插件工具，设置 `usage_template="acli plugins x --vm {vm_id}"`。
2. 从 schema properties 中删除 `vm_id`。
3. 点击校验。

**预期**：

- 返回 error：模板占位符在 schema 中缺失。
- 保存前自动触发同一校验，error 阻断保存。
- warning 场景不阻断保存，但页面必须保留校验结果提示。

### M3：前端构建校验

**步骤**：

```bash
cd frontend
pnpm --filter @hci/admin build
```

**预期**：

- TypeScript 类型检查通过。
- Vite 构建完成，无工具管理页面类型错误。

## SOP 发布验证

### S1：无容器 bash 命令

**步骤**：

1. 构造包含 `grep ERROR /sf/log/vtpdaemon.log` 的 SOP 诊断步骤。
2. 发布 SOP。

**预期**：

- 发布结果包含 validation issue。
- 若无法自动推断容器，至少 warning；若规则声明必须容器，则 error。

### S2：不支持 aCLI 命令

**步骤**：

1. 构造包含 `acli storage disk list` 的 SOP 诊断步骤。
2. 发布 SOP。

**预期**：

- 发布结果提示该命令不在 catalog。
- 建议使用 `acli storage asan disk list` 或先执行上级 help。

## 可观测性验证

### O1：日志字段

查询 agent-service 日志，校验失败记录必须包含：

- `trace_id`
- `exec_id`
- `tool_name`
- `validation_code`
- `validation_level`
- `command_preview`
- `container`

### O2：指标

Prometheus 查询示例：

```promql
sum by (tool_name, code) (agent_tool_validation_total)
```

预期能看到 `BASH_CONTAINER_REQUIRED`、`ACLI_COMMAND_NOT_IN_CATALOG` 等失败计数。
