# 工单排障核心缺陷修复与链路对齐 Walkthrough

本期修改成功解决并优化了以下排障诊断流程中的严重短板，确保系统在 SOP 决策树执行、Trace 链路染色、工具交互和审计判定上能够 100% 正确流转。

---

## 变更内容一览

### 1. SOP 决策树导航字段兼容
* **[nav.py](file:///aihci/hci-troubleshoot-platform/backend/agent-service/app/tools/sop/nav.py)**: 重构了 `_find_node_in_tree` 与 `_build_node_response`，使节点定位、子节点概览和节点响应数据结构同时兼容数据库实际存储的 `id` 与 `title` 以及代码预期的 `node_id` 与 `name`，解决了 `get_sop_node` 找不到节点的 Bug。

### 2. 工具调用 conversation_id 参数传递
* **[react_engine.py](file:///aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/react_engine.py)**: 在 ReAct 循环中执行工具时，显式传递 `conversation_id=session_id`。
* **[sop_tools.py](file:///aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/sop_tools.py)**: 当 `SopToolExecutor` 将非 SOP 的 diagnostic 工具（如 `acli_exec`）委托给默认的 `CompositeToolExecutor` 执行时，显式向下转发 `conversation_id=self._conversation_id`，解决了 acli 执行报缺少 conversation_id 的 Bug。

### 3. 分布式 Trace ID 链路继承与流式传输强注入
* **[conversation_service.py](file:///aihci/hci-troubleshoot-platform/backend/conversation-service/app/services/conversation_service.py)**: 重构了 `create_conversation()`。在创建会话时，显式执行 SQL 查询对应工单的 `case.trace_id` 并让会话继承该 ID，实现了会话继承工单 Trace ID 的设计。
* **[agent_client.py](file:///aihci/hci-troubleshoot-platform/backend/conversation-service/app/services/agent_client.py)**: 重构了 `AgentClient.stream(...)`，在向 `agent-service` 发起 HTTP 流式请求前，显式格式化并注入 `traceparent` 头，强行打通 Starlette `StreamingResponse` 迭代过程中的 OTel Context 阻断，保证 downstream 的工具审计和 LLM 审计记录拥有与排障工单完全一致的 Trace ID。

### 4. 审计 has_sop 精准判定
* **[prompt_audit.py](file:///aihci/hci-troubleshoot-platform/backend/agent-service/app/services/prompt_audit.py)**: 重构了 `has_sop` 自动推断机制。摒弃对 Prompt 纯文本中含有 "SOP" / "sop" 单词的贪婪正则匹配，改为精确查询数据库是否存在对应的 `sop_execution` 记录。这彻底根治了在 S0 阶段，系统提示词模板中包含 SOP 操作指引从而导致 has_sop 被误判置为 true 的问题。
