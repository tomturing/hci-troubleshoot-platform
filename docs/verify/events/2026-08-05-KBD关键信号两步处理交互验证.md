# KBD 关键信号两步处理交互验证

## 验证目标

验证管理台不是只更换标题，而是真正使用一个共享组件保证以下不变量：

```text
匹配模式：处理单元 → 第一步取值 → 第二步判断
产出变量：每个变量一个处理单元 → 第一步取值 → 第二步产出
```

| 用例 | 验证内容 | 结果 |
|---|---|---|
| U1 | 匹配模式只有一个处理单元，ValueExtract 与 Predicate 分属两个步骤 | ✅ 通过 |
| U2 | 第一步取值关键字与第二步判定关键字分别更新、互不覆盖 | ✅ 通过 |
| U3 | 两个产出变量渲染两个独立处理单元，步骤术语统一 | ✅ 通过 |
| U4 | 更新第一个变量的 Extract 不改变第二个变量 | ✅ 通过 |
| U5 | 新增变量自动生成 text/all/exactly_one/stdout 默认 Extract | ✅ 通过 |
| U6 | 模式选择只发出结构化切换事件，由父级维护 Match/Produce 互斥 | ✅ 通过 |

## 对抗性断言

- 产出模式不得出现“变量处理单元”；
- 第二步不得显示“第二步：产出变量”；
- KBD QFK 编辑区不得再显示“声明式取值”；
- Matcher 嵌入处理单元时不得重复渲染 ValueExtract；
- 多变量数组更新必须按目标下标创建新数组，其他变量语义保持不变；
- Match 与 Produce 均把 AI 提取保留在第一步 ValueExtract 内。
