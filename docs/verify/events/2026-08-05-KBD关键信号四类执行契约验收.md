# KBD 关键信号四类执行契约验收

## 验证目标

验证统一管道不是仅在表单或 Schema 局部成立，而是从保存到运行结果闭环：

```text
Schema → 运行时 Signal → Handler 命令 → Fake Executor
→ Filter/Extract/AI/Predicate → Match 或变量池
```

## 验收矩阵

| 用例 | 工具 | 输出模式 | 取值配置 | 预期 |
|---|---|---|---|---|
| C1 | qfk_log | Produce | 完整行 + include AND + exclude OR + AI | 写入 `DUP_IP=192.168.100.55` |
| C2 | qfk_system | Match | 文本表格列 + threshold | Use%=83，Match=True |
| C3 | qfk_service | Match | 完整行 + state | status=running，Match=True；写动作被拒绝 |
| C4 | qfk_vm | Produce | JSON 路径 | 写入类型化 `VM_ID` |

## 对抗性反例

- 一行只有“检测到IP”、另一行只有“冲突”，include AND 必须不成立；
- 同一命中行包含任一 exclude 且 exclude_mode=any，必须排除；
- 只有全部 exclude 同时出现且 exclude_mode=all，才排除；
- qfk_log 只有 exclude、没有 include/request_id 时必须拒绝保存；
- 非零 exit_code、SSH 未执行和 timeout 不得返回有效业务 False 或写变量；
- AI 返回不在引用行中的 IP 必须拒绝，变量池保持原子不变；
- qfk_service start/stop/restart 即使绕过页面也必须被 Handler 拒绝。

## 现场验证边界

本报告中的 Fake Executor 能证明配置、编译和确定性处理契约，不能冒充真实 HCI/aCLI 版本上的执行成功。PR 部署后仍需选择一台授权环境对四条只读命令做现场 replay，并关联 exec_id、stdout/stderr、exit_code；现场 replay 未完成前不记为 Expert Gold。
