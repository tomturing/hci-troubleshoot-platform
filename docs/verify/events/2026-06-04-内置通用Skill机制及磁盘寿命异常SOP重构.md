## 1. 针对 PR 386 CI 失败原因的定位与修复

针对 CI 中的 `unit-tests` 失败，我们在本地进行了复现，并逐一进行了如下深度的定位与彻底修复：

### 1.1 修复测试命名空间环境污染 (CORS 安全测试失败)
* **问题定位**：在运行全量测试时，`tests/unit/test_case_service.py` 优先加载并将 `case-service/app` 载入 Python 的 `sys.modules["app"]`。而 `tests/security/test_cors.py` 之前只在**模块导入阶段**进行了命名空间清理。这导致 `pytest` 在全量执行测试用例时，其他测试文件在收集/运行过程中再次将 `sys.modules["app"]` 污染成了其他服务，导致 CORS 运行阶段调用 `from app.config import settings` 时，拿到了不具备 `cors_origins` 属性的其他服务的 settings 对象，从而引发 AttributeError 与 ValueError 报错。
* **修复方案**：在 [test_cors.py](file:///mnt/d/aihci/hci-troubleshoot-platform/tests/security/test_cors.py) 中，将命名空间环境清理逻辑封装进 `setup_api_gateway_namespace()` 函数，并且在其 `app` 模块级别、`app` fixture 实例化阶段以及独立的 `test_credentials_not_used_with_wildcard` 运行阶段**进行多次强行对齐与隔离**，彻底根治了测试用例间由于 sys.modules 共享引发的环境污染。

### 1.2 补全 pytest 严格模式标记 (pytest.mark.e2e 报错)
* **问题定位**：部分 E2E 测试用例中使用了 `@pytest.mark.e2e` 标记，但由于 [pyproject.toml](file:///mnt/d/aihci/hci-troubleshoot-platform/pyproject.toml) 中的 pytest markers 声明只注册了 `unit`、`integration` 和 `slow`，且 pytest 开启了 `--strict-markers` 严格标记检查，因此未注册的 `e2e` 直接导致测试收集失败（ERROR / exit code 2）。
* **修复方案**：在 [pyproject.toml](file:///mnt/d/aihci/hci-troubleshoot-platform/pyproject.toml) 的 `markers` 列表中添加 `"e2e: End-to-end tests"`。

### 1.3 清理 API 网关遗留文件以修复 pytest 收集异常
* **问题定位**：先前虽然新增了 `capabilities.py` 及测试 [test_capabilities.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/api-gateway/tests/unit/test_capabilities.py)，但遗留 of 旧网关代理路由 `tools_prompts.py` 及对应的单元测试 `test_tools_prompts.py` 仍残留在磁盘中，这使得 pytest 收集测试时因为尝试加载不存在的模块引发了 Counter 冲突。
* **修复方案**：更新 [main.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/api-gateway/app/main.py) 的 `router` 注册导入，彻底删除了残存的 `tools_prompts.py` 和 `test_tools_prompts.py`，并将 `api-gateway/app/routes/__init__.py` 进行了重新格式化。

### 1.4 修复 `agent-quality-gate.sh` 脚本执行异常中断
* **问题定位**：质量门禁脚本在 `detect_changes` 变更检测中使用了 `while read` 搭配 here-string `<<< "$changed"`。在 bash 环境下，如果循环体内最后一次对无后缀文件（如 `uv.lock`）做 `[[ ... ]]` 正则判定返回 1，且脚本头部启用了 `set -e`，会导致整个脚本被异常捕获并直接以退出码 1 闪退。
* **修复方案**：在 `detect_changes` 中的判定语句后面追加 `|| true`，并在循环的 `read -r f` 逻辑中融入 `|| [ -n "$f" ]` 确保 EOF 安全读取，避免退出码非 0 中断质量门禁。

### 1.5 解决 pytest 单进程收集多个服务测试时的 SQLAlchemy 模型冲突
* **问题定位**：由于不同微服务测试（如 `case-service` 和 `api-gateway`）全部集中在根目录 `tests/` 下由 pytest 一起收集和运行，在同一进程下，各测试文件通过清理 `sys.modules` 的 `app` 和 `app.*` 来切换到各自 the 微服务目录以导入正确的代码。然而，这些微服务都从 `shared.database.postgres` 导入全局唯一的 `Base = declarative_base()`，其 `Base.metadata` 也是全局唯一的单例。当 `app.models` 在清除重载后被重新导入时，SQLAlchemy 试图在同一个 `Base.metadata` 实例中重新声明同名的表结构，导致抛出 `sqlalchemy.exc.InvalidRequestError: Table 'assistant_evaluation' is already defined for this MetaData instance` 错误。
* **修复方案**：我们在测试的切换命名空间钩子中融入了 `Base.metadata.clear()` 调用。在 [tests/conftest.py](file:///mnt/d/aihci/hci-troubleshoot-platform/tests/conftest.py) 以及 5 个具体的微服务测试文件（[test_cors.py](file:///mnt/d/aihci/hci-troubleshoot-platform/tests/security/test_cors.py)、[test_websocket.py](file:///mnt/d/aihci/hci-troubleshoot-platform/tests/integration/test_websocket.py)、[test_case_service_integration.py](file:///mnt/d/aihci/hci-troubleshoot-platform/tests/integration/test_case_service_integration.py)、[test_case_service.py](file:///mnt/d/aihci/hci-troubleshoot-platform/tests/unit/test_case_service.py)）的命名空间切换逻辑中，当需要重新加载 `app` 包时，主动清空 SQLAlchemy `Base.metadata` 中的全部已定义表描述，从而彻底消除了模型冲突问题。同时，我们在每个测试文件中添加了 `scope="module", autouse=True` 的 pytest fixture，确保在测试执行阶段也能够自动修正当前模块所关联的命名空间与环境配置。

### 1.6 修复技能定义测试 Ruff 代码检查错误
* **问题定位**：在 `backend/conversation-service/tests/unit/test_skill_definition.py` 中，存在两个重复定义的 `TestSkillDefinitionORM` 测试类，且导入模块（`unittest.mock` 及 `pytest`）位于文件中间、存在未使用的导入等，触发了 Ruff (I001 / F401 / F811) 静态分析错误，导致 CI 阶段 `CI / Lint` 任务失败。
* **修复方案**：删除了重复的 `TestSkillDefinitionORM` 测试类，将外部导入规范地统一整理到文件顶部，移除未使用的 mock 依赖，并修复了 Ruff 格式化报错。
