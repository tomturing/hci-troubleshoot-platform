# CI 最小激活与快速门禁验证报告

## 1. 验证范围

本报告验证 workflow 静态语法、job DAG、触发路径和本地等价命令。GitHub Hosted Runner 的实际排队时间须在 PR 更新后以 Actions 运行数据复核，不能用本地耗时替代。

## 2. 静态验证

已对 `.github/workflows/*.yml` 逐文件执行 Python YAML 解析，9 个仓库自有 workflow 全部解析通过。

关键静态结论：

- main ruleset 要求的 `Lint`、`前端检查（单元测试 + 构建）`、`unit-tests`、`security-tests`、`integration-tests`、`docs-governance` 名称未改变；
- `schema-contract` 不再是独立 job，但其校验命令仍在 Lint job 中执行；
- `unit-tests`、`integration-tests`、`security-tests` 仅依赖 `changes`，可与 Lint/Helm 并行；
- hci-sim 三个 gate 均以 `changes` 输出为条件，未受影响的 job 会被显式 skipped；
- `Build terminal_bridge` 不再监听 pull_request，仍监听 main push 与 workflow_dispatch。

## 3. 本地等价验证

在当前 checkout 执行以下命令作为 preflight：

```bash
go test ./...                         # hci_sim 与 terminal_bridge 分别在各自 go.mod 下执行
go test -race ./...
go vet ./...
go build ./cmd/hci-sim
go build ./cmd/hci-sim-smoke
uv run ruff check backend/ tests/
uv run python scripts/ci/check_signal_schemas.py
helm lint deploy/helm/hci-platform
helm lint deploy/helm/hci-sim
helm template hci-sim deploy/helm/hci-sim --namespace hci-sim-dev >/tmp/hci-sim-rendered.yaml
```

本报告不把本地通过解释为 GitHub 门禁通过；本地只验证命令与工作树的一致性。

本轮实际结果：Ruff、Signal Schema Contract、文档命名、模块文档同步、Helm lint/template 和 workflow YAML/DAG 检查通过；当前容器未安装 Go，因此 Go test/race/vet/build 与 actionlint 未在本地执行，需由 GitHub runner 在 PR 上补充证据。

## 5. 未决的线上证据

- 合并本 PR 后需要记录至少 3 个真实 PR 的 job 数量和 P50/P95 关键路径；
- 若某个 required check 显示为 skipped 并被 ruleset 错误阻断，应按任务文档的回滚步骤恢复兼容 job；
