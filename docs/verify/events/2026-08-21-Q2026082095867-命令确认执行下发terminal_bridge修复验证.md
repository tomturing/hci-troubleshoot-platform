# Q2026082095867 命令确认执行下发 terminal_bridge 修复复盘与验证报告

## 1. 现象与问题背景

**工单号**: `Q2026082095867`  
**现象**:
在 Customer UI 中，Agent 推送需要用户确认的命令（例如 `acli system cat /sf/cfg/gpu_info.ini`），用户在对话卡片中点击蓝色「确认执行」按钮后，命令未实际下发给目标 HCI 主机，本地 `terminal_bridge` 未记录任何执行请求日志，后端 `BridgeRelayExecutor` 在等待 125 秒后因 Redis `blpop` 超时，最终返回：
```
QFK_TERMINAL_FAILURE: 命令执行失败：终端会话缺失或桥未运行，未获得真实主机输出，无法判定信号。请先通过 Custom-UI 建立 SSH 连接（ssh_connect）后再触发诊断。
```

---

## 2. 第一性原理与根因剖析

### 2.1 架构事实
- **Customer UI**：默认连接本地桌面运行的 `terminal_bridge`（`ws://localhost:9999`）。
- **Admin UI**：连接 K3s 集群内置 Pod（`/terminal-bridge`）。

### 2.2 根因定位
1. **确认回调为 TODO 空实现**：
   在 `frontend/customer/src/components/MessageBubble.vue` 的 `handleExecConfirmApprove` 函数中，原实现仅向消息流追加了 `[确认执行]` 气泡并清空了 `pendingExecConfirm`，包含 TODO 注释而未真正通过 WebSocket 发送 `ssh_exec_process` 指令。
2. **状态模型不完整**：
   `chat.ts` 中 `pendingExecConfirm` 状态仅保存了基础字段，缺少透传给 `terminal_bridge` 隔离执行通道所需的完整上下文（`container`, `traceId`, `traceparent`, `toolCallId`, `timeoutSeconds`, `outputFilters`）。
3. **连接建立判定与响应式 Proxy 边界**：
   `chat.ts` 中 `markConnected()` 的内部判断使用了 `sshWebSocket.value !== socket`，在 Vue 3 响应式 `ref` 包装下产生身份判断异常，且缺少对非浏览器环境 `WebSocket.OPEN` 标识的兼容。

---

## 3. 修复方案

1. **`frontend/customer/src/stores/chat.ts`**：
   - 扩展 `pendingExecConfirm` 状态模型，补充完整上下文字段；
   - 在 `agent_exec_command` SSE 事件监听处完整采集字段；
   - 新增 `confirmAgentExec(execId)` 方法，复用与 `risk=1` 自动执行路径相同的 `buildAgentExecProcessMessage` -> `sshWebSocket.send` -> `waitForExecResult` -> `postExecResult` 闭环链路；
   - 优化 `markConnected` 连接状态判定。
2. **`frontend/customer/src/components/MessageBubble.vue`**：
   - `handleExecConfirmApprove()` 改为 `await chatStore.confirmAgentExec(ev.execId)`。
3. **单元测试与验证**：
   - 新增 `frontend/customer/src/stores/__tests__/chat.exec-confirm.spec.ts`，覆盖 SSH 正常时下发 `ssh_exec_process` 并在收到 `exec_result` 后回传结果的完整行为，以及 SSH 未连接时的优雅降级上报。
