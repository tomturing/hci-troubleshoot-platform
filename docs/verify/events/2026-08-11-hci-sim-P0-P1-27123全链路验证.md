### 2.2 两步 UI 验证

1. 打开 `/admin/` → “仿真测试”，输入 `27123`，确认 capability 显示 `authority_scope=dev_golden`、Runtime revision=1、requested revision=24 和 mismatch gap。
2. 点击“环境构建”，确认出现 `GET capability`、`POST build`；构建未成功前“开始测试”禁用。
3. 构建成功后点击“开始测试”，确认弹出“创建仿真测试工单”，且此点击发生 DOM 状态变化；F12 此时可以没有请求，这是刻意的状态迁移。
4. 填写标题/描述，点击“连接 SSH 并创建工单”，确认 Network 面板出现 TestRun、`/terminal-bridge` WebSocket 和 Result 请求。
5. 页面显示真实 `Q...` Case ID、Run Result passed、三条关键信号通过；不要把 Lease 密码写入截图或日志。

## 3. 数据与链路证据

```bash
# 仅输出 ID、状态、摘要；禁止输出 environment_context 中的 password/token。
kubectl logs -n hci-dev deploy/terminal-bridge --since=10m | grep -E 'ssh.connected|exec.done'
kubectl exec -n hci-sim-dev deploy/hci-sim -- sh -c 'wget -qO- http://127.0.0.1:8080/status'
```

在 hci_sim 数据库中查询：

```sql
SELECT external_id, support_id, kbd_revision, variant, execution_mode, status,
       environment_context->>'case_id' AS case_id,
       environment_context->>'authority_scope' AS authority_scope
FROM control_plane.run
WHERE support_id = '27123'
ORDER BY created_at DESC LIMIT 1;

SELECT r.external_id, r.status, rr.outcome, rr.report_uri
FROM control_plane.run r
LEFT JOIN control_plane.run_result rr ON rr.run_id = r.id
WHERE r.external_id = '<脱敏后的 run id>';
```

## 4. 通过/失败标准

| 层 | 通过条件 |
|---|---|
| UI | Start 有弹窗；表单重试保留；capability gap 可见 |
| Case | `case_id` 匹配 Case Service 的真实 `Q...` 记录 |
| Runtime | support/revision/digest/mode/context 全匹配，Case 绑定不可覆盖 |
| Bridge | 同源 WebSocket，SSH connected，三条 exec_result exit=0 |
| Result | `run_result.outcome=passed`，report URI 为 object://，无敏感字段 |

任一层失败即整条 P0–P1 验证失败；不能用 Pod Ready、HTTP 200 或历史 Golden 报告替代。

## 5. 证据边界

本方案通过后只能声明“dev_golden KBD 27123 基本仿真纵向链路通过”。由于 Runtime Fixture revision 1 与主库 active revision 24 不同，不能声明 production approved KBD 27123；Agent 产品级推理、真实 HCI 差分、23821 和 126 KBD 仍为后续 capability gap。
