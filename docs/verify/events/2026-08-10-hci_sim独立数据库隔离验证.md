# hci_sim 独立数据库隔离验证

对应需求：[hci_sim 独立数据库隔离需求](../../requirement/events/2026-08-10-hci_sim独立数据库隔离需求.md)

对应方案：[hci_sim 独立数据库隔离方案](../../solution/events/2026-08-10-hci_sim独立数据库隔离方案.md)

## 1. 验证原则

验证顺序必须是：

```text
inventory → backup/restore → expand → copy → verify → switch → observe → contract
```

禁止用“表能查到”替代权限、依赖、备份恢复和新写入验证。所有命令在隔离 dev/staging 数据副本执行，生产切换前必须重复关键门禁。

## 2. Inventory 验证

### 2.1 结构清单

```sql
SELECT table_schema, table_name
FROM information_schema.tables
WHERE table_schema NOT IN ('pg_catalog', 'information_schema');

SELECT table_name, column_name, data_type
FROM information_schema.columns
WHERE table_name LIKE 'agent_test_%'
ORDER BY table_name, ordinal_position;
```

同时导出：

- PK/FK/unique/check/default；
- index/sequence/trigger/view/function/RLS；
- owner/grants；
- 行数、大小、增长率；
- 代码/ORM/SQL 引用。

验收标准：每张待迁移表都有 owner、消费者、生命周期、敏感等级和迁移目标；`bridge_execution_*` 没有“未决定”。

### 2.2 硬编码扫描

```bash
rg -n "hci_troubleshoot|DATABASE_URL|agent_test_|bridge_execution_|public\." \
  backend hci_sim terminal_bridge database deploy frontend
```

验收标准：hci-sim 运行时代码没有主库 fallback；主库服务没有新 hci_sim 写路径；旧 `public.*` 引用都有迁移计划或兼容层。

## 3. Backup/restore 验证

1. 对源库目标表生成可恢复备份。
2. 创建临时恢复 database。
3. 恢复 backup。
4. 执行 schema、行数、PK、FK、sequence 和关键 TestRun 查询。
5. 记录恢复时长和失败点。

验收标准：恢复不依赖生产 Secret，不向生产网络发起连接，数据校验一致，RPO/RTO 达到环境约定。

## 4. 新数据库与权限验证

```sql
SELECT datname FROM pg_database WHERE datname IN ('hci_troubleshoot', 'hci_sim');
SELECT rolname, rolsuper, rolcreaterole, rolcreatedb FROM pg_roles
WHERE rolname LIKE 'hci_sim%';
```

使用三个连接分别测试：

| 角色 | 允许 | 必须拒绝 |
|---|---|---|
| owner | 受控管理 | 默认不用于应用 |
| migrator | hci_sim DDL | hci_troubleshoot 业务写入 |
| runtime | hci_sim 目标表 DML | DDL、主库连接、其他 schema |
| 平台 runtime | 平台业务表 | hci_sim 默认访问 |

必须实际执行 `SELECT/INSERT/UPDATE/DELETE/CREATE/ALTER/DROP` 负向测试，不能只查看 GRANT 文本。

## 5. Migration 验证

### 5.1 空库

```bash
atlas migrate lint --dir file://database/hci-sim-migrations --dev-url "$HCI_SIM_DEV_URL"
atlas migrate apply --dir file://database/hci-sim-migrations "$HCI_SIM_DATABASE_URL"
```

验收：所有目标表/schema/constraint/index/sequence/comment 创建，主库无 hci-sim DDL。

### 5.2 存量复制

- 在快照时间点复制；
- 记录批次、行数和 final delta；
- 重跑复制命令，验证幂等；
- 模拟中断，验证从断点继续。

校验项：

```text
count(source) == count(target)
PK 集合相等
FK 无 orphan
unique/check/default 相等
index/sequence 可用
摘要 hash 相等
```

## 6. 应用切换验证

1. 使用错误/空 `HCI_SIM_DATABASE_URL` 启动 hci-sim，期望 fail-closed。
2. 使用正确 runtime Secret 启动，期望 ready。
3. 创建 Build/Bundle/TestRun/Attempt/Event/Result。
4. 查询两个数据库的写入计数和审计。
5. 在主库旧表上设置写入告警或只读触发器。

验收标准：新控制面记录只出现在 hci_sim；主库业务 case/conversation/kb 仍正常；任何 hci_sim DB 连接失败不会回退到主库或真实 HCI。

## 7. Observe 与回滚验证

### 7.1 观察窗口

至少覆盖：

- 一个完整 Build；
- 一个正向 TestRun；
- 一个失败/过期 TestRun；
- 一个 hci-sim Pod 重启；
- 一个备份/恢复检查。

观察：旧表无新写入、连接池错误、migration/stale outbox、容量、备份 age、权限拒绝。

### 7.2 回滚

1. drain 新 TestRun；
2. 切换 Secret/config 回旧库；
3. 使用旧库只读窗口后的增量/回滚策略恢复；
4. 验证旧库能读历史，避免新数据静默丢失；
5. 新旧 TestRun ID 不重复、不双写。

如果无法证明切换期间新增数据如何回滚，回滚验证不通过。

## 8. Contract/drop 验证

只在观察窗口、备份恢复和 source code 扫描都通过后执行：

```text
旧表只读/重命名
→ 业务回归
→ 再删除旧表（独立 PR）
```

验收：主库 schema drift 检查通过，hci-sim migration 不再触发主库表创建，备份/恢复仍可用。

## 9. 阻断条件

- 行数、PK、FK、摘要不一致；
- runtime 有主库权限或 migration 权限；
- hci-sim DB 失败后发生主库 fallback；
- 旧表仍有写入；
- 备份无法恢复；
- 发现未清点的 SQL/public 引用；
- 发现真实 HCI execution 审计被错误迁移。
