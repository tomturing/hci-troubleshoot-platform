## 自动验证

执行：

```bash
./.venv/bin/pytest \
  backend/agent-service/tests/unit/test_kbd_differential.py \
  backend/agent-service/tests/unit/test_qfk_extractor.py -q
```

结果：

```text
59 passed in 1.05s
```

随后执行 Agent 全量单元测试：

```bash
./.venv/bin/pytest backend/agent-service/tests/unit -q
```

结果为 `405 passed, 1 skipped`；两条既有 `AsyncMock` 未 await warning 来自 `test_tool_audit.py`，与本次变更无关。

覆盖的关键断言：

1. 三步 production-equivalent chain 使用 `task get → VM/HOST/END → lsof → PID → ps -p PID -o cmd= → CMD`。
2. `cmd=` 的单行命令输出在 `include=["{{VM}}"]`、`exactly_one + whole` 下成功提取。
3. 同一输出配置 `include=["{{PID}}"]` 时稳定返回 `QFK_NO_MATCH`；命令行不含 VM 时也必须返回 `QFK_NO_MATCH`。
4. 成功报告显示检查说明、已完成状态和 VM/HOST/END/PID/CMD 中文标签。
5. 报告不含 `exec_id`、`evaluation_id`、参数 JSON。
6. ERROR 中 `QFK_OUTPUT_EMPTY` 转为用户态文案；BLOCKED 显示缺失变量。
7. `lsof: no pwd entry for UID 65535` 等 raw output 噪音不进入报告。
8. 既有确定性结论和参考案例门禁测试继续通过。

4. 变量池包含 `VM/HOST/END/PID/CMD`。

## 防复发判据

- 命令退出码、物理 stdout、筛选后 stdout、extract 结果必须分层核对，任何一层都不能代替另一层。
- 命令输出列/字段变化时，必须重新审查所有 include/exclude/column/cardinality，禁止机械复用旧提取规则。
- PASS 测试不仅断言状态，还必须断言实际产出值内容。
- 用户态报告只消费结构化事实；原始输出只能进入审计/日志和工具详情，不进入最终主报告。
