# Q2026072855923 S0 分类错位验证记录

## 1. 验证目标

证明以下三个故障点同时关闭：

1. 环境资源名 `ubu-sus-25.2` 不再被 Agent 解析成分类。
2. 候选前置非法项被过滤时，选择原③仍精确对应 `虚拟机-003`，不会变成压缩数组的第③项 `存储-020`。
3. 分类写入与 S0→S1 同事务完成，提交前不启动 S1。

设计依据见 [S0 分类稳定身份协议与候选治理方案](../../solution/events/2026-07-28-S0分类稳定身份协议与候选治理方案.md)。

## 2. 精确回归样本

### 2.1 Agent 原始模型回复

```text
判断依据：虚拟机 ubu-sus-25.2 开机失败。
① 虚拟机-038 虚拟机IO读写慢
② 虚拟机-003 虚拟机开机失败
③ 存储-020 虚拟存储性能告警
④ 虚拟机-036 虚拟机整体卡慢
```

预期：候选 code 精确为 `虚拟机-038/虚拟机-003/存储-020/虚拟机-036`，不含 `ubu-sus-25`。

### 2.2 现场旧 metadata 样本

```json
[
  {"optionId":"1","name":"ubu-sus-25 "},
  {"optionId":"2","name":"虚拟机-038 虚拟机IO读写慢"},
  {"optionId":"3","name":"虚拟机-003 虚拟机开机失败"},
  {"optionId":"4","name":"存储-020 虚拟存储性能告警"},
  {"optionId":"5","name":"以上都不是（请补充症状描述）"}
]
```

过滤后预期：

```json
[
  {"option_id":"2","code":"虚拟机-038","name":"虚拟机IO读写慢"},
  {"option_id":"3","code":"虚拟机-003","name":"虚拟机开机失败"},
  {"option_id":"4","code":"存储-020","name":"虚拟存储性能告警"}
]
```

`selection=3` 必须通过原 `option_id=3` 命中 `虚拟机-003`。

### 2.3 v2 样本

```json
{
  "optionId":"虚拟机-003",
  "code":"虚拟机-003",
  "categoryName":"虚拟机开机失败",
  "name":"虚拟机-003 虚拟机开机失败"

```

点击后必须调用：

```typescript
sendMessage("③", {
  kind: "intent_selection_response",
  selectedOptionId: "虚拟机-003",
  selectedCategoryCode: "虚拟机-003",
```

## 4. 部署后人工验收

### 4.1 操作

1. 新建一张与“虚拟机开机失败”一致的工单。
2. 等待 S0 显示候选，确认页面不出现 VM 名、host ID、request ID 等非分类字符串。
3. 点击名称为“虚拟机-003 虚拟机开机失败”的项，无论它当时显示为①、②还是③。
4. 等待进入 S1，不要只看页面阶段，同时检查用户消息 metadata、conversation 表和 S1 日志。

### 4.2 数据库核对

```sql
SELECT conversation_id, case_id, category_id, category_l1, category_l2, diagnostic_stage
FROM conversation
WHERE case_id = '<新工单号>'
ORDER BY created_at DESC
LIMIT 1;
```

唯一合格结果：

```text
category_id      = 虚拟机-003
category_l1      = 虚拟机
category_l2      = 虚拟机开机失败
diagnostic_stage = S1
```

检查用户响应 metadata：

```sql
SELECT content, metadata
FROM message
WHERE conversation_id = '<conversation_id>' AND role = 'user'
ORDER BY created_at DESC
LIMIT 1;
```

必须包含：

```json
{"kind":"intent_selection_response","selectedCategoryCode":"虚拟机-003"}
```

### 4.3 日志核对

必须在同一 `conversation_id/case_id/trace_id` 下观察到：

```text
s0_confirmation_committed category_id=虚拟机-003 old_stage=S0 new_stage=S1
InvestigationAgent category_id=虚拟机-003
```

不得观察到：

```text
triage options ... ubu-sus-25
conversation_category_updated 存储-020
InvestigationAgent category_id=存储-020
```

## 5. 失败注入验收

| 场景 | 预期 |
|---|---|
| 点击后 active 分类目录不可用 | 页面提示目录不可用，会话保持 S0 |
| 响应 stable ID 不属于最近候选 | 提示选项已失效，不写 category |
| 连续双击同一项 | 只有一次 S0→S1 更新，后续请求 rowcount=0 并不重复启动 S1 |
| 选择“以上都不是” | 保持 S0，不写 category，用补充描述生成新候选 |
