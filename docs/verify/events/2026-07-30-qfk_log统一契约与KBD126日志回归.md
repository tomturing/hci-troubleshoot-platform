# qfk_log 统一契约与 KBD 126 条日志回归验证

## 一、结论

本轮已完成统一 `qfk_log` 的代码、Schema、运行时、Admin、Prompt、数据库投影、Helm 配置和文档回归。blackbox、vn-blackbox、whitebox 与 `/sf/log/pods` 没有拆成独立工具，全部复用 `qfk_log + acli log get`。复核后纠正两项建模：`/sf/data/local` 不是日志族，只允许 request_id 辅助关联；`qkv_dialog` 是当前主控日志复合取值能力，不是不可执行截图分类。

验证通过项：

- 共享日志源 Catalog、绝对时间、路径根、归档前置检查和 BMC Capability Gap；
- qfk_log keyword/regex/state/threshold/delta/trend/exists；
- blackbox/vn-blackbox 默认路径与 `LOG_ifconfig.txt` 来源消歧；
- 探针自观测过滤、样本不足返回 Inconclusive；
- `qkv_dialog` 双目录查询、自观测过滤、`request_id:`/`request_id=`/trace 兼容及 END/REQUEST_ID/HOST 提取；
- aCLI Catalog 未知命令开发/验证进入 confirm，生产可配置 deny；
- KBD 审核页可编辑完整 qfk_log 参数和 matcher；
- 工具管理页同时展示数据库投影与只读代码 Capability；
- 126/126 原始案例来源完整性、转换和图片集合指纹保持通过。

不能据此宣称：

- 126/126 已完成业务专家审核；
- 126/126 已在真实故障现场命中；
- 59 条历史 qfk_log Proposal 已自动变成正确知识；
- 所有 parser 已实现通用结构化 AST；
- BMC、NBU、页面记录和 `/sf/cfg` 已有可执行 Capability。

2026-07-30 重新执行只读审计后的真实状态是：34 条日志契约通过、10 条活动信号阻断、12 条存在被拒绝日志候选、70 条没有活动日志信号。该结果用于专家复核排序，不是自动发布结果。

### 2.2 真实 HCI 只读验证边界

本轮设计使用的实机事实来自 2026-07-30 HCI 只读探索：

```text
/sf/log/today -> /sf/log/30
/sf/log/blackbox/today -> /sf/log/blackbox/20260730
/sf/log/vn-blackbox/today -> /sf/log/vn-blackbox/20260730
```

`acli log get --help` 确认：

```text
-k/--keyword
-i/--request-id
-t/--time
-f/--file
-c/--context
-E/--extend
-p/--path

```

时间只接受绝对日期/时间；`-f` 为 basename；常规日志 `-p` 只允许 `/sf/log`。`/sf/data/local` 不是日志族，仅在已有 request_id 时作为受限诊断产物关联域。探索期间没有修改 HCI 配置、重启服务、安装补丁、删除文件或执行写型 aCLI。

本轮没有把单节点“未找到某文件”写成所有 HCI 版本不存在；组件条件日志仍需在对应角色、版本和故障现场验证。

## 三、126 KBD Proposal 只读审计

### 3.1 可重复审计方法

权威领域实现：

```text
data-pipeline/kbd/signal_review.py
```

审查器输入为 `support_id + signals_json` JSON 数组。它不写 Proposal，直接调用 Shared Resolution Runtime。唯一入口 `python -m kbd.run review-signals` 可执行数据库只读查询，也可审查文件/stdin。

当前它是研发/批量回归 CLI 能力，不是页面按钮。仓库根目录可直接执行数据库指定案例或全量审计：

```bash
PYTHONPATH=data-pipeline:backend uv run python -m kbd.run review-signals \
  --all \
  --output /tmp/kbd-log-signal-audit.json
```

也可以继续使用只读 SQL 导出后通过 stdin 审计：

```bash
kubectl exec -n hci-dev postgres-0 -- \
  psql -U hci_admin -d hci_troubleshoot -Atc \
  "SELECT jsonb_agg(jsonb_build_object('support_id', support_id, 'signals_json', signals_json) ORDER BY support_id) FROM kbd_entry;" \
| PYTHONPATH=data-pipeline:backend uv run python -m kbd.run review-signals --stdin
```

也可以通过 `--file` 读取同结构 JSON。默认返回 0 表示审计器运行成功；发现 Proposal 问题不会返回非零，因为它是复核清单，不是静默发布门。CI 需要阻断活动不可执行信号时显式增加 `--fail-on-blocked`。后续页面化应直接在现有 `/knowledge/kbd-review` 增加“日志契约检查”与状态筛选，复用同一校验 API，不新建独立工作台。

状态语义：

| 状态 | 数量 | 含义 |
|---|---:|---|
| `PASS_SIGNAL_REVIEW` | — | 全部活动 Signal 通过 Shared Resolution Runtime 静态审查；不证明语义正确或现场命中 |
| `BLOCKED_SIGNAL_REVIEW` | — | 活动 Proposal 存在无法编译/解析的 Signal，发布前必须修复 |
| `NEEDS_SIGNAL_REVIEW` | — | 存在 needs_probe 或被生产门禁拒绝的候选 |
| `NO_ACTIVE_SIGNAL` | — | 当前 Proposal 没有活动 Signal，不代表原始案例没有信号需求 |

### 3.2 结构问题

| 问题 | 信号数 | 案例 |
|---|---:|---|
| BMC `CAPABILITY_GAP` | 1 | 27173 |
| 无效时间/路径 | 6 | 33882、34164、39532、39658、39723、40057 |
| 缺 file | 2 | 37150、37180 |
| 非法 qfk_log 字段 | 1 | 41818（历史 Proposal 的 `resource` 未注册） |
| rejected qfk_log candidate | 17 | 分布于 30396、30884、33882、34094、34278、34366、35986、36154、39471、39481、39559、39581、39597 |

10 条活动信号阻断案例：

```text
27173, 33882, 34164, 37150, 37180, 39532, 39658, 39723, 40057, 41818
```

12 条存在日志拒绝候选、需专家复核的案例：

```text
30396, 30884, 34094, 34278, 34366, 35986, 36154, 39471, 39481, 39559, 39581, 39597
```

### 3.3 审计结论的限制

`PASS_SIGNAL_REVIEW` 只回答“能否按 Shared Resolution Runtime 静态构建和确定性解释”，不回答以下问题：

- file 是否是该版本/角色的真实文件；
- pattern/metric/阈值是否正确表达原案例；
- role 为 must/should/exclude 是否正确；
- 日志条件是否足以确认案例，而不是仅提供相关性；
- 当前客户现场是否具备对应组件和故障时间证据。

因此 34 条仍需专家语义审核；10 条阻断与 12 条 rejected-candidate 案例应优先修复。70 条无活动日志信号还需要与“85 条正文涉及日志”的原始审计交叉检查，识别合理非日志来源和漏抽取。
