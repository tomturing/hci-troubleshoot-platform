# 工具调用可视化、交互卡片重构与原始环境注入验证报告

## 变更说明

本期开发对 HCI 智能排障平台进行了以下几个维度的重要改进，彻底解决了排障工具调用黑盒、用户变量交互粗糙以及环境数据加工损耗等问题：

### 1. 工具调用可视化与自动执行 (Tool Visibility & Auto-Execution)
- **后端支持**：在 `react_engine.py` 内部 `_execute_tool_call` 的生命周期中，在工具调用发起前广播 `tool_call` 事件（含 `exec_id`、风险等级及状态），在调用完成后广播 `tool_result` 事件（含耗时、退出码、结果及错误原因）。
- **签名适配**：修改了 `executor.py`、`sop_tools.py` 与 `main.py` 的执行签名，实现 `exec_id` 全链路透传。
- **SSE 转发**：在 `conversation_service.py` 的 SSE 循环中，捕获 `tool_call` 与 `tool_result` 的 `stage_update` 事件，直接以流式事件的形式推送给前端。
- **前端可视化与自动执行**：
  - 前端 `chat.ts` 监听 `tool_call` 与 `tool_result`，并在消息列表中动态更新/追加专门的工具卡片。
  - 新增全局自动执行（Auto-Run）模式切换：在 `Safe-only` 或 `Aggressive` 模式下，对于满足风险等级的命令（如 risk <= 1 或 risk <= 2），前端会自动静默回复授权确认，无感运行。
  - 聊天卡片内集成终端回显组件：以黑底 Terminal 风格折叠渲染标准输出与报错。

### 2. 变量交互与校验重构 (Variables Validation Redesign)
- **`variable_input` 重构**：升级为 inline 的表单卡片，失焦或输入时根据正则 `validation_pattern` 与 `required` 状态进行实时校验，格式错误时输入框呈现红框并展现警告提示，同时禁用提交按钮。
- **`variable_confirm` 重构**：升级为左右分栏对比验证框。左侧展示系统推断的推荐值并提供绿色一键确认大按钮；右侧允许微调修改，自带校验及蓝色提交按钮。

### 3. 原始环境数据注入与向下兼容 (Raw Environment Context)
- **原始注入**：当 `settings.USE_RAW_ENVIRONMENT_CONTEXT` 开启时，在 `conversation_service.py` 获取集群、告警、任务日志的原始数据作为 S0 Triage Context。
- **向下兼容**：在 `sop_execution.py` 的 `_resolve_env_variable` 中设计了 `is_raw` 自适应兼容层，自动将 Unix 时间戳格式化、数值状态映射为语义状态（“完成”/“失败”）、告警整型映射为优先级（“CRITICAL”/“WARNING”），保证历史 SOP 策略的完全兼容。
