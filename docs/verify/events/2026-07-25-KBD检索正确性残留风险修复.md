# KBD 检索正确性残留风险修复

**日期**：2026-07-25  
**范围**：KBD embedding、中文全文检索、相关性门禁、动态资源审计  
**前置事件**：[KBD 向量搜索失效根因分析与修复](2026-07-25-KBD向量搜索失效根因分析与修复.md)

## 结论

PR #616 修复了配置来源和查询文本，但仍存在五类正确性风险：入库路径仍可生成 hash 伪向量、中文原文无法被 PostgreSQL `simple` 配置正确切词、向量召回无最低相关性门禁、初召候选被误记为 `matched`、关键降级路径缺少测试。本次修复把这些隐式风险改为可验证的不变量。

## 正确性不变量

1. 查询向量与文档向量必须由同一个明确记录的模型生成；provider 失败、响应不完整、维度错误或包含 NaN/Infinity 时不得生成替代向量。
2. 发布端和查询端必须使用同一套 jieba + HCI 词典分词，随后交给 PostgreSQL `simple` FTS。
3. 向量候选必须同时满足 `embedding_model = 当前模型` 和 `similarity >= KBD_MIN_SIMILARITY`；无合格候选时降级到 FTS，两条路径均为空就返回空列表。
4. 搜索端点只完成候选初召，因此审计状态为 `retrieved`；只有下游验证后才能表达命中或执行成功。

## 实施内容

| 层 | 变更 |
|---|---|
| Embedding | 删除本地 BGE/hash 降级，只接受 provider 的非零有限数值、连续 index、正确数量与 1536 维向量；保留熔断，失败显式抛错 |
| 数据模型 | `kbd_entry` 新增 `embedding_model`、`embedding_content_hash`、`embedding_updated_at`，历史无来源向量自动退出检索 |
| 中文 FTS | 服务启动时预热 jieba；发布、重发布、路由和 KBD 搜索统一使用 HCI 词典分词 |
| 相关性 | 新增 `KBD_MIN_SIMILARITY`，默认 0.3；向量 SQL 使用绑定参数并增加模型与相似度门禁 |
| 降级 | embedding 不可用或无合格向量候选时执行 FTS；FTS 无结果直接返回空，不再按发布时间填充无关案例 |
| 审计 | 新增受控状态 `retrieved/success/failed`，历史 `matched` 迁移为 `retrieved`；记录 rank、score、search_path、模型及对话/工单 ID |
| 测试 | 覆盖向量校验、中文分词、SQL 门禁、空结果、审计语义和上下文透传 |

## 数据库迁移

`database/desired_schema.sql` 是 schema 唯一权威来源，同步增加 provenance 字段与审计状态 CHECK。`database/data-migrations/012_normalize_dynamic_resource_usage_status.sql` 在存量表存在时先把 `matched` 规范化为 `retrieved`；全新数据库在 Atlas 建表前执行该迁移时安全跳过。

旧 embedding 没有可信的模型来源，部署后不会参与向量检索；这段过渡期内历史 KBD 仍可通过中文 FTS 召回。

## 部署后回填

先重建全部已发布 KBD 的中文 FTS：

```bash
kubectl exec -n <namespace> deploy/kb-service -- \
  python -m app.cli.rebuild_kbd_search_index
```

确认 embedding provider 健康后，再重建真实向量及来源信息：

```bash
kubectl exec -n <namespace> deploy/kb-service -- \
  python -m app.cli.rebuild_kbd_search_index --with-embeddings
```

单条 embedding 失败时该条目的向量及 provenance 会保持 NULL，不会把旧向量重新带回检索。命令可重复执行；建议先在 staging 验证检索结果、失败数和接口延迟，再推广到 prod。

## 验收标准

- provider 返回错误维度或非有限值时请求失败，数据库不保存伪向量。
- `虚拟机镜像异常` 等中文查询被拆为多个 token，`peth0`、`IO超时` 等领域词保持完整。
- 低于阈值、模型来源缺失或模型不一致的向量不进入候选集。
- FTS 无命中时 `cases=[]`，不存在按发布时间兜底。
- 候选审计状态为 `retrieved`，且可关联 `conversation_id`、`case_id`、rank 和 score。
