## 关键断言

| 场景 | 预期 |
|------|------|
| 正常 `cat` 配置检查 + Matcher | 进入 `signals`，不进入拒绝列表 |
| 候选声明 `phase=solution`，且 match/produces 都为空 | 先报“处置动作不属于 KBD 关键信号”，不报结构二选一 |
| 明确 `restart` 等变更命令 | 自动抽取/专家保存拒绝 |
| rejected candidate | 完整保留候选 JSON、evidence 与可读原因 |
| 专家维护工作稿 | 返回 422，不写入处置 Signal |
| 历史 solution/明确写动作 | Agent 调度标记 blocked，不自动执行 |
| SOP | 不调用 KBD 专用整文档门禁，既有通用契约不变 |
| `sed` 命令 | 没有命令参数专项分支；本案例依赖结构化 `phase=solution` 拒绝 |

## 事实边界

- 单元测试能证明确定性门禁和错误顺序，不能证明真实 LLM 每次都生成相同候选；
- 本方案不自动纠正“缺少/取消”等源内容错误；
- 未声明 solution 且未命中既有明确写动作词表的自由命令，不由本方案推断 Shell 语义；
- 合并部署后仍需在 dev 验证 Prompt migration 和真实重抽结果。
