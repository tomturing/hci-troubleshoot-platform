# 阶段三（推理约束）与阶段四（评测闭环）集成与验证 Walkthrough

我们已经成功完成了排障 Agent 可靠性改造**阶段三：结构化推理与反幻觉**和**阶段四：评测闭环**的完整集成与优化。

## 变更内容

### 阶段三：结构化推理与反幻觉 (T3)

#### 1. SOP 决策树滑动窗口优化与前置条件拼接 (T3-1)
- **修改文件**：
  - [nav.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/tools/sop/nav.py)
  - [investigation_agent.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/investigation_agent.py)
- **实现**：优化了 SOP 导航接口，在 `children_summary` 中包含子节点的前置条件 `prerequisites`。在 InvestigationAgent 中生成 `branches_list` 时，显式拼接前置条件，并在系统提示词中格式化，使得大模型在进行决策树分支选择时拥有充分的判定依据。

#### 2. 关键节点输出 Schema 化与降级拦截策略 (T3-2)
- **新增/修改文件**：
  - [reliability.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/shared/models/reliability.py) [NEW]
  - [__init__.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/shared/models/__init__.py) [MODIFY]
  - [react_engine.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/react_engine.py) [MODIFY]
- **实现**：定义了 `Hypothesis` / `ReasoningOutput` / `Claim` / `ClaimVerification` 等 Pydantic 结构化数据模型。在 `ReactEngine.execute` 中动态支持 `response_schema`，并在推理及流式输出后对 JSON 结果进行 Pydantic 校验。校验失败时标记 `schema_validation_failed = True`，并在随后工具执行阶段降级拦截所有 `risk_level >= 2` 的写操作工具，确保模型失控/格式错误时不引发生产安全事故。

#### 3. CoT 思考过程外显与前端折叠展示 (T3-3)
- **修改文件**：
  - [react_engine.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/react_engine.py)
  - [MessageBubble.vue](file:///mnt/d/aihci/hci-troubleshoot-platform/frontend/customer/src/components/MessageBubble.vue)
- **实现**：在系统提示词中强制注入 `<reasoning>` 标签要求，令大模型按要求在该标签内进行四步 CoT 思考。前端 `MessageBubble.vue` 支持正则提取 `<reasoning>` 推理链并使用 Element Plus `el-collapse` 折叠卡片在气泡头部优雅展示，避免冗长的推理过程干扰用户阅读。

#### 4. 轻量级反幻觉规则引擎 (T3-4)
- **新增/修改文件**：
  - [hallucination_detector.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/services/hallucination_detector.py) [NEW]
  - [react_engine.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/react_engine.py) [MODIFY]
- **实现**：构建了纯正则的 `HallucinationDetector` 轻量服务，无二次 LLM 调用开销（延迟 < 100ms）。通过规则检测虚假引用工具 (phantom_tool)、过度自信断言 (overconfident_claim)、无数据来源数字 (ungrounded_number)。检测到幻觉时在 React 循环中自动触发一次 LLM Re-run（自我修正），若重试仍有幻觉则在最终回复拼接醒目的 `*待验证*` 幻觉风险警告。

#### 5. 校验优先闭环强制拦截 (T3-5)
- **修改文件**：[react_engine.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/react_engine.py)
- **实现**：监控 ReAct 会话内的写操作与读/验证操作。若模型在执行 `risk_level >= 2` 写操作后未执行任何状态查询/验证动作，且回复包含“已解决”、“已恢复”等 Closure 关键字时，系统强制拦截，注入校验引导指令并进入下一轮 ReAct 推理，杜绝了“只修不测、盲目关闭工单”的情况。

### 阶段四：评测闭环 (T4)

#### 1. FactStore 迁移至 PostgreSQL 与 Redis 缓存双轨读写 (T4-3)
- **新增/修改文件**：
  - [20260608000001_fact_store_postgresql.sql](file:///mnt/d/aihci/hci-troubleshoot-platform/database/atlas-migrations/20260608000001_fact_store_postgresql.sql) [NEW]
  - [fact.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/shared/models/fact.py) [NEW]
  - [fact_store.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/services/fact_store.py) [MODIFY]
- **实现**：设计了 `fact` 及 `claim_evidence_link` 数据库表用于持久化排障事实和证据链。在 `FactStore` 中引入 SQLAlchemy 双轨读写：写入时首先向 PostgreSQL 数据库作持久化，同时同步在 Redis 进行 5 分钟的加速缓存；读取时优先读缓存，未命中则读库并写回缓存。实现了即使在工单关闭 30 天后依然可以进行证据链溯源的要求。

#### 2. 核心可靠性指标监控接入 Prometheus (T4-2)
- **新增/修改文件**：
  - [metrics.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/agent-service/app/services/metrics.py) [NEW]
- **实现**：定义并暴露了 `AGENT_TOOL_CALL_TOTAL`（工具调用及成败）、`AGENT_SCHEMA_VALIDATION_TOTAL`（推理格式校验成败）、`AGENT_HALLUCINATION_DETECTED_TOTAL`（幻觉类型统计）和 `AGENT_VERIFICATION_BLOCKED_TOTAL`（验证拦截统计）等核心可靠性 Counter 指标至 Prometheus。

#### 3. 黄金工单评测集与离线 Replay Runner 及 CI 质量门禁 (T4-1, T4-4)
- **新增/修改文件**：
  - [golden_tickets.json](file:///mnt/d/aihci/hci-troubleshoot-platform/evaluation/golden_tickets.json) [NEW]
  - [replay_runner.py](file:///mnt/d/aihci/hci-troubleshoot-platform/evaluation/replay_runner.py) [NEW]
  - [agent-quality-gate.sh](file:///mnt/d/aihci/hci-troubleshoot-platform/scripts/ci/agent-quality-gate.sh) [MODIFY]
- **实现**：构建了包含 30 个典型 HCI 故障场景的黄金用例库 `golden_tickets.json`，包含了期望分类、期望工具集和期望事实。实现了 `replay_runner.py` 离线回放评估框架，对故障分类准确率（阈值 80%）、工具成功率（阈值 85%）、幻觉率（上限 35%）等指标进行门禁判别，并将其与 CI `agent-quality-gate.sh` 脚本绑定。
