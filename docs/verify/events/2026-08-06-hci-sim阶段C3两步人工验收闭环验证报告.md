# C3 两步人工验收闭环验证报告

## 验证环境

- dev Kubernetes context `default`，namespace `hci-dev`；C1 API 使用 `INTERNAL_API_TOKEN`。
- Docker 构建 `hci_sim/Dockerfile`，hci-sim 以单副本 host-network dev 容器运行，SSH `127.0.0.1:2222`、HTTP `127.0.0.1:8080`。
- Custom UI 与 terminal_bridge 使用仓库现有 WebSocket 协议。

## 两步操作与标准

### 案例 A：27736

1. 执行 `scripts/hci-sim/two-step-acceptance.sh 27736`，确认输出 `status`、`synthetic=true`、`variant=positive-minimal`，且 `/readyz` 成功。
2. Custom UI SSH 终端选择“仿真租约”，按 `connection.json` 填写并连接；欢迎语必须包含 `HCI-SIM KBD 27736`，执行 `qkv_task --keyword "设置集群IP失败" --limit 100 --is_failed true`。

通过标准：SSH 连接成功，退出码 0，输出 JSON 含 `synthetic:true`、`support_id:27736`、`signal_id:sig_001`；Bridge 消息含 `simulation=true/execution_mode=sim-ssh`。

### 案例 B：34164

重复以上两步，将 KBD 改为 `34164`。推荐命令必须为 `qkv_task --keyword "新建虚拟机" --limit 1 --is_failed true`，输出 `support_id:34164`。通过标准同案例 A，且不得命中 27736 的 Bundle 或结果。

### 案例 C：阻断

执行 `scripts/hci-sim/two-step-acceptance.sh 27123`。预期命令非零退出并显示 `capability_gap`/`TOOL_CONTRACT_STALE`；不产生 `connection.json`，不创建/重启 hci-sim 容器。

## 安全回归

- 将 Lease password 改一个字符：SSH 必须认证失败。
- 将 `execution_mode` 改为 `password` 或将命令改为未登记 argv：必须分别认证失败或返回 `fixture_not_found`。
- 检查 `docker logs hci-sim-c3-*`、Custom UI localStorage 和 Bridge 日志，不得出现 `htp2.` token。

## 当前结论

本报告覆盖的是 dev synthetic 两步闭环；它不覆盖真实 Artifact、真实客户输出、生产 CAS/多副本或真实 HCI 差分。后四项仍保持阻断，不能以本报告替代阶段 D/E 产品级验收。
