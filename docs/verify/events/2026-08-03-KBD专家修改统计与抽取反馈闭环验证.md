# KBD 专家修改统计与抽取反馈闭环验证

## 验证目标

验证 KBD30880 暴露的问题已经在产品语义、版本血缘、抽取门禁和部署迁移四个层面闭环：

1. “专家修改”只统计当前 Expert 相对其明确 Proposal baseline 的信号级变化，AI→AI 重抽不计入；
2. 发布后的当前 Expert 仍可正确统计，新 Proposal 重抽后旧 Expert 不得跨基线冒充当前版本；
3. evaluation export 不把 working/opened/saved 中间稿当作稳定监督目标；
4. 自动抽取将缺失或历史默认 10/30 秒 timeout 收敛到 120 秒，并拒绝无下游消费者的 QFK producer；
5. `/sf/cfg` 配置读取使用 `qfk_system command + command_args`，不再产生未注册的 `resource_keyword`；
6. DDL 与 Prompt 数据迁移可在现有 dev 数据上前向执行，并能在事务回滚后恢复原状态。

## 关键回归断言

| 场景 | 断言 |
|------|------|
| AI 重抽、专家未编辑 | `changed_signal_count=0`，Prompt、模型、Tool Contract 和 AI→AI payload Diff 不计入 |
| 一个 Signal 修改多个字段 | 按稳定 `signal.id` 只计 1 条修改 |
| Expert 新增/删除 Signal | 每个稳定 Signal 分别计 1 条新增或删除 |
| 发布后 working 指针清空 | 若 approved/published Expert 仍绑定当前 latest Proposal，继续使用该配对统计 |
| 再次重抽新 Proposal | 只绑定旧 Proposal 的 Expert 不再作为当前专家稿，统计回到 0 |
| 相同 Expert payload、不同 Proposal | 不跨 baseline 幂等复用，保留两条不同监督血缘 |
| evaluation export | 只选择 approved/published Expert；Proposal 来自显式 baseline 或历史 parent 链；返回 `diff_from_proposal` |
| dead QFK producer | 产出变量未被其他下游 Signal `requires` 时拒绝；producer 自引用不算消费；拒绝原文和原因可审计 |
| 合法 QFK producer | 至少一个其他下游 Signal 消费变量时不误拒绝 |
| 自动生成 timeout | 缺失、10、30 秒归一为 120；明确 180 秒等特殊值保持不变 |
| `/sf/cfg/gpu_info.ini` | 规范化为 `command="cat"`、`command_args=["/sf/cfg/gpu_info.ini"]`，不含 `resource_keyword` |
| Prompt v1.8 | 失败任务 `qkv_task`、QFK 消费关系、配置 matcher、120 秒、多图 `source_refs` 规则存在，且 StrictPromptLoader 无非法占位符 |

## 部署后 KBD30880 验收

本 PR 的代码级目标已经通过，但真实 LLM 输出具有非确定性，必须在合并部署到 dev 后重新抽取 KBD30880，完成以下现场验收：

```text
专家尚未编辑：专家修改：0 条关键信号

信号总数：3
  1 × qkv_task
  2 × qfk_system

共同约束：
  timeout = 120
  qkv_task produces HOST、VM
  qfk_system requires HOST
  不存在 GPU_INFO_CONTENT dead producer
  不存在 qfk_system.acquire.args.resource_keyword
  cat 文件路径位于 command_args
  evidence 与 source_refs 的多图引用一致
```

如 LLM 仍未稳定生成恰好三条，必须把原始候选、`rejected_candidates`、Prompt revision、模型名和生成 trace 作为 Bad Case 留存，再迭代通用 Prompt/门禁；禁止针对 `support_id=30880` 增加硬编码。

## 事实边界

- 尚未部署本分支；
- 尚未在部署后的 dev 对 KBD30880 执行真实 LLM 重抽；
- 单元测试、JSON Schema 和 Prompt 契约验证不能证明真实 HCI 命令已执行；
- approved/published 只表示稳定 Proposal→Expert 配对，不代表可信专家身份、Expert Gold、完整 Evidence/Execution Replay 或真实客户结果；
- runtime outcomes 仍是既有的 KBD 资源级审计聚合，本 PR 不把它伪装为精确 revision replay。
