# hci-sim 阶段 A/B 代码级实施验证报告

关联[阶段 A 需求](../../requirement/hci-sim/events/hci-sim阶段A目录收敛与基础门禁需求.md)、[阶段 B 需求](../../requirement/hci-sim/events/hci-sim阶段B运行时安全与确定性加固需求.md)、[阶段 A 验证方案](2026-08-05-hci-sim阶段A目录收敛与基础门禁验证方案.md)和[阶段 B 验证方案](2026-08-05-hci-sim阶段B运行时安全与确定性加固验证方案.md)。

## 本次 PR 的可验证结论

- 阶段 A 已在代码层收敛：唯一 Go Runtime 源码目录为 `hci_sim/`；历史 `hci-sim/` Spike 已删除，但 Helm/镜像/服务对外名仍为 `hci-sim`。
- 阶段 B 已在代码层升级为 Manifest v2、Lease v2 和精确 RouteKey；`exec` 与 controlled shell 共用队列、授权、路由和输出预算；Bridge 不再按 host 子串赋予 simulation 语义。
- KBD 27123 已可由已发布 Bundle 和 Lease 的 `support_id`、revision、checksum、bundle digest、virtual node 与 container 共同绑定；错误 KBD/Bundle/目标不会被路由为该 fixture。
- 当前结论仅覆盖本地代码、容器 Go 测试和 Helm render。未部署 dev namespace，未执行真实 SSH、Bridge 到 Runtime 的端到端、fuzz 长跑、Redis 多副本或容量试验；这些保留为阶段 C–E/环境验收阻断项，不能标记为已通过。

- 单副本内存 Tracker 不能用于多副本部署；若扩容，必须先实施并验证共享 Store。
- 历史 KBD 27123 Golden E2E 是历史参考，而不是此 PR 的部署验收证据。
- 真实 SSH 与实际 dev 集群的验证须取得目标和部署授权后执行；在此之前相关 VA-12、VB-20、VB-22 等用例保持 `blocked`。
