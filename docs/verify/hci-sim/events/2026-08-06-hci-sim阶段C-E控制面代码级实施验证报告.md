# hci-sim 阶段 C–E 控制面代码级实施验证报告

关联[阶段 C 需求](../../requirement/hci-sim/events/hci-sim阶段C-Fixture编译与注册控制面需求.md)、[阶段 D 需求](../../requirement/hci-sim/events/hci-sim阶段D-Scenario调度与通用KBD测试需求.md)和[阶段 E 需求](../../requirement/hci-sim/events/hci-sim阶段E产品级验证与规模化运营需求.md)。

## 已实施的代码级闭环

`hci_sim/internal/controlplane` 是独立于 SSH Runtime 数据面的控制面业务内核：

| 阶段 | 已验证能力 | 不变式 |
|---|---|---|
| C | 冻结编译输入、输入指纹幂等、Manifest v2 lint、Artifact 许可前置、草稿→验证→双角色审批→发布→stale、Bundle 再读完整性校验 | Runtime 只能读取 `published` Bundle；Compiler 不能自审；stale Bundle 不能创建新 Run。 |
| D | immutable Bundle pin、按 support ID/variant/node/container 创建 TestRun、idempotency 冲突保护、容量预留、短时 `htp2` Run Lease、Attempt、终态语义 | 不接受任意命令/host/Bundle URL；Lease 明文不落库；missing/stale Bundle 无副作用 fail-closed。 |
| E | 结构化 real/sim 差分、mutation 检出率、20 次稳定性统计核心、1→10→50→100→200 容量证据阶梯和跨 Scenario 污染 P0 停止条件 | 不允许把 exit/outcome 差异归一化；关键 mutation miss 与任何串线都不能通过。 |

数据库 desired schema 与 Atlas migration 已创建 `agent_test_scenario`、Bundle、依赖、provenance、审批、审计、Run、Attempt、Event、Result 和 Runtime capability 表。它们只保存 metadata、受控对象 URI、digest/哈希和审计关联，禁止保存 Artifact 原文或 Lease 明文。

## 代码级验证

```bash
docker run --rm --user "$(id -u):$(id -g)" \
  -e GOCACHE=/tmp/go-build-cache -e GOPATH=/tmp/go \
  -v "$PWD:/src" -w /src/hci_sim hci-go-cache:20260805 \
  sh -lc 'mkdir -p /tmp/go-build-cache /tmp/go && /usr/local/go/bin/go test ./... && /usr/local/go/bin/go vet ./...'

docker run --rm -v "$PWD:/src" -w /src arigaio/atlas:latest \
  migrate hash --dir "file:///src/database/atlas-migrations"
```

已在 2026-08-06 使用临时 `pgvector/pgvector:pg15` 完整复现 DB CI 路径：创建必需 extension，应用 `desired_extras.sql`、Atlas `schema apply`、全部 `database/data-migrations/*.sql`，再执行 `atlas schema diff`；结果为 `Schemas are synced, no changes to be made.`。查询确认 11 张新增 `agent_test_*` 表全部存在。临时容器已停止并自动移除，不包含任何业务数据。

单元测试覆盖：相同输入幂等与非确定输出拒绝、Bundle 完整性、Compiler 自审和同一人跨角色审批拒绝、专家/安全双审批、stale 传播、按 support ID/variant/node/container 解析并 pin Bundle、Run idempotency 冲突、缺失 route 拒绝、Run Lease 绑定、差分中 exit 差异不可忽略、关键 mutation miss 与容量串线停止。

## 真实环境阻断项

下列验收无法从本地 mock/内存 Store 推导，仍为 `blocked`，且本次不宣称通过：

- KBD 27123 active revision 与至少两个异构 KBD 的权威 Resolver、批准真实 Artifact、provenance、RBAC、PostgreSQL/对象存储 prepare/commit 和持久 CAS；
- Customer UI → Agent/CDD → Terminal Bridge → hci-sim 的真实 Headless Runner 适配与 1/10 并发；
- 受控只读 real HCI 校准、10–20 KBD 认证包、20-repeat、真实 fault/security 演练；
- 50/100/200 Scenario 资源、Redis/Registry/DB、网络隔离、浏览器/Agent 容量与 SLO 证据。

生产接入必须为 `Registry`、`Runner` 和 `RunStore` 提供 PostgreSQL CAS、对象存储、受信任 Lease issuer 及真实 Bridge 协议实现；不能用 `MemoryRegistry` 或直接调用 Runtime 代替。未获得上述授权、数据和环境前，产品状态只能是“C–E 代码级基础已就绪”，不能声明“指定 KBD 自动构建环境并验证效果已完成”。
