# KBD27123 环境构建持久化修复验证

## 1. 验证目标

确认 Admin UI 的“环境构建”能够完整走通：

```text
Admin UI → api-gateway → hci-sim HTTP 8080 → hci_sim PostgreSQL
```

并确认 hci-sim 在无法访问必需数据库时不会错误地报告 Ready。

## 2. 现场根因证据（修复前）

2026-08-11 13:17（北京时间）浏览器请求：

```text
POST /api/hci-sim/v1/simulations/build
HTTP 503
{"detail":"hci_sim persistence unavailable"}
```

Gateway 同时记录了：

```text
GET /v1/simulations/capabilities/27123 → 200
POST /v1/simulations/build → 503
```

现场 hci-sim Pod 的数据库目标为独立数据库 `hci_sim`，表结构和账号均存在；使用当前 Secret 从 PostgreSQL Pod 连接测试成功：

```text
current_user      | hci_sim_runtime
current_database  | hci_sim
```

但是修复前的 `hci-sim-allow-required` NetworkPolicy 仅允许 DNS、Tempo 和 api-gateway 出站，没有允许 PostgreSQL 5432。由 hci-sim Pod 到 PostgreSQL Pod 的 TCP 探针结果为：

```text
10.42.0.73 → 10.42.0.43:5432: Operation timed out
```

因此数据库本身、账号、迁移和 KBD Fixture 均正常，失败边界是 Kubernetes egress 策略遗漏数据库路径。

## 3. 修复内容

- Helm NetworkPolicy 增加 `hci-sim → hci-dev PostgreSQL Pod:5432` 的最小出站规则；
- 目标通过 `app.kubernetes.io/name: postgres` Pod selector 限定，不放行整个 namespace；
- hci-sim `/readyz` 增加数据库 Ping，持久化为必需项时数据库不可用则返回 503；
- hci-sim 写 Run、Lease、Event 失败时输出不含凭据的结构化错误，避免只留下笼统的 `persistence unavailable`；
- CI Helm gate 对渲染结果断言 PostgreSQL selector、5432 和 hci-dev namespace 均存在。

## 4. 部署后端到端验收

### 4.1 Argo 与 Pod

```bash
kubectl get application hci-sim-dev -n argocd
kubectl rollout status deployment/hci-sim -n hci-sim-dev
kubectl get networkpolicy hci-sim-allow-required -n hci-sim-dev -o yaml
```

验收：Application 为 `Synced/Healthy`；hci-sim Pod 为 `Ready 1/1`；策略包含 `hci-dev`、`app.kubernetes.io/name: postgres` 和 TCP `5432`。

### 4.2 Runtime readiness 与数据库连通性

```bash
kubectl exec -n hci-sim-dev deploy/hci-sim -- wget -qSO- http://127.0.0.1:8080/readyz
kubectl exec -n hci-sim-dev deploy/hci-sim -- nc -vz -w 3 postgres.hci-dev.svc.cluster.local 5432
```

验收：两个命令均成功；`/readyz` 返回 `200 ready`，TCP 探针成功。

### 4.3 Admin UI KBD27123

1. 在 Admin UI 输入 `27123`，等待能力预检显示“可构建”；
2. 点击“环境构建”，等待构建状态变为“成功”；
3. 确认页面日志没有 `hci_sim persistence unavailable`；
4. 点击“开始测试”，填写标题和描述，提交“连接 SSH 并创建工单”；
5. 确认 SSH 连接到 `hci-sim.hci-sim-dev.svc:2222`，三条 smoke 命令均返回 `exit=0`；
6. 如点击重试，确认复用原 Case，不产生 `test_run_case_binding_conflict`。

### 4.4 数据库证据

```bash
kubectl exec -n hci-dev postgres-0 -- sh -lc \
  'psql -U "$POSTGRES_USER" -d hci_sim -c "select external_id,support_id,status,environment_context->>''case_id'' from control_plane.run where support_id=''27123'' order by created_at desc limit 5"'
```

验收：最新 Run 存在于 `hci_sim.control_plane.run`，状态至少为 `leased`；成功完成后 `control_plane.run_result.outcome` 为 `passed`，且 `environment_context.case_id` 与真实工单一致。

## 5. 失败注入验收

在受控临时环境移除数据库 egress 后，`/readyz` 必须返回 503 且 Pod 从 Service Endpoints 摘除；恢复策略后 Pod 自动恢复 Ready。禁止通过关闭 `HCI_SIM_DATABASE_REQUIRED` 或连接 `hci_troubleshoot` 绕过故障。
