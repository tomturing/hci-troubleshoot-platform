# 审计日志与可观测性优化方案

> 版本：v1.0 | 日期：2026-06-05 | 状态：proposal

本方案旨在解决 HCI 智能排障平台中管理端的系统审计能力增强、Grafana 嵌入的免密体验以及用户端诊断进度的展示一致性问题。

---

## 1. 核心需求分析与第一性原理设计

### 1.1 系统监控重命名为“可观测性”及 Grafana 免登录
- **原理**：Grafana 提供原生匿名授权模式（Anonymous Auth）。通过在服务器环境上设置 `GF_AUTH_ANONYMOUS_ENABLED=true` 且组织角色为 `Viewer`，浏览器在 iframe 加载时能够静默获取只读视角，而不需要用户手动输入 `admin` 的用户名和密码。
- **改动范围**：
  1. 升级本地开发环境 `deploy/observability/docker-compose-obs.yml`，对齐 Helm 生产环境已有的 anonymous auth 配置。
  2. 重命名路由与菜单名称为“可观测性”。

### 1.2 新增“审查日志”页面查看 `audit_log` 数据
- **原理**：`audit_log` 存储的是大模型（LLM）的 System Instructions 构建快照与全量 Prompt 消息（`messages`）。这类记录属于大量的 JSONB 大文本，不能简单地用表格一览无余地显示。
- **交互设计**：
  - 在“可观测性”页面使用 `el-tabs` 实现二级标签页，将“监控面板（Grafana）”与“审查日志”并列展示。
  - **主表格**：显示审计基础信息，包含开始时间、轮次、链路 Trace ID、估算 Token、执行耗时、有无 SOP、异常信息等。
  - **工单过滤**：提供 `case_id` 过滤输入框。通过在 SQL 中 JOIN `conversation` 表（`audit_log.conversation_id == conversation.conversation_id`），直接快速过滤指定 `case_id` 的所有审计记录。
  - **预览与详情 (Detail Drawer)**：点击行时右侧拉出抽屉。抽屉里通过格式化折叠面板（`el-collapse`）展示每一条 message。由于 System Prompt 非常庞大，折叠面板可以方便用户一键展开阅读，也可以一键复制原始 JSON。

### 1.3 前端 custom-ui 诊断进度与 Agent 阶段一致性
- **原理**：目前 customer-ui 的 `DiagnosticProgress.vue` 使用的是一套硬编码的业务标签（`问题收集`、`信息确认` 等），而 AI 大脑（`triage_agent`、`investigation_agent`、`remediation_agent`）和数据库使用的是 `S0~S6`。
- **映射一致性**：
  - `S0` 对应 `意图识别`
  - `S1` 对应 `故障定位`
  - `S2` 对应 `假设生成`
  - `S3` 对应 `验证步骤`
  - `S4` 对应 `根因分析`
  - `S5` 对应 `解决方案`
  - `S6` 对应 `验证闭环`
  将 custom-ui 上的标签对齐为上述 Agent 阶段，并保持跳转逻辑完全一致。

## 2. 详细设计与接口定义

### 2.1 后端 API 定义 (conversation-service)

#### 1. 查询 Prompt 审计日志接口
- **Path**: `GET /api/v1/audit-logs/prompts`
- **Params**:
  - `case_id` (str, optional): 关联工单 ID 过滤
  - `conversation_id` (str, optional): 关联会话 UUID 过滤
  - `trace_id` (str, optional): 链路 Trace ID 过滤
  - `limit` (int, default=50)
  - `offset` (int, default=0)
- **Response**:
  ```json
  {
    "total": 120,
    "limit": 50,
    "offset": 0,
    "items": [
      {
        "id": "audit-uuid-1",
        "conversation_id": "conv-uuid-123",
        "turn_index": 2,
        "system_prompt_id": 12,
        "payload": {
          "case_id": "case-20260605001",
          "assistant_type": "htp-agent",
          "message_count": 3,
          "has_sop": true,
          "kb_chunks_count": 0,
          "kb_top_score": null,
          "messages": [
            {"role": "system", "content": "..."}
          ],
          "total_chars": 12000,
          "total_token_est": 4000
        },
        "error": null,
        "duration_ms": 1250,
        "started_at": "2026-06-05T23:00:00+08:00",
        "completed_at": "2026-06-05T23:00:01+08:00",
        "trace_id": "trace-id-123"
      }
    ]
  }
  ```

### 2.2 API 网关层代理 (api-gateway)
- 转发规则：将网关的 `/api/audit-logs` 路由代理转发至 `conversation-service` 对应的 `/api/v1/audit-logs`。

## 3. UI 交互设计 (ObservabilityView.vue)

```
+--------------------------------------------------------------------------------+
|  可观测性                                                                        |
+--------------------------------------------------------------------------------+
|  [ 监控面板 ]   [ 审查日志 ]                                                    |
|  +--------------------------------------------------------------------------+  |
|  |  工单ID: [ case-001    ]  Trace ID: [             ]  [ 🔍 查询 ] [ 🧹 重置 ]  |  |
|  |  +--------------------------------------------------------------------+  |  |
|  |  | 记录时间             | 工单 ID   | 轮次 | 耗时 | Token数 | 操作         |  |  |
|  |  +---------------------+-----------+------+------+---------+------------+  |  |
|  |  | 2026-06-05 23:10:15 | case-001  | 1    | 1.2s | 3.5k    | [查看详情]  |  |  |
|  |  | 2026-06-05 23:08:42 | case-001  | 0    | 0.8s | 2.1k    | [查看详情]  |  |  |
|  |  +---------------------+-----------+------+------+---------+------------+  |  |
|  |                                                        < 1 [2] 3 4 >     |  |
|  +--------------------------------------------------------------------------+  |
+--------------------------------------------------------------------------------+
```

### 3.1 抽屉详情面板展现内容
- **基础元数据**：以 `el-descriptions` 显示耗时、Token 数量、Trace ID。
- **对话上下文 (Messages)**：
  - 使用折叠面板展示 `messages` 中的每个角色。
  - 对于 `system` 消息，在卡片中提供快速复制，并将系统指令中包含的高冗余分类基线或长文档进行折叠，保持可读性。
  - 提供 `Raw JSON` 查看标签页，一键复制格式化的审计原始 JSON。

## 4. 迁移与部署影响

### 4.1 配置文件更新
- 本地开发需要重启可观测性服务：
  ```bash
  docker compose -f deploy/observability/docker-compose-obs.yml up -d grafana
  ```

### 4.2 API 契约兼容
- 旧的 `GET /api/v1/audit-logs` 获取工具执行审计不受影响，网关同样将其代理到 backend 相同路径。
