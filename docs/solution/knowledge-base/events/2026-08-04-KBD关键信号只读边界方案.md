# KBD 关键信号只读边界方案

## 背景与需求

KBD30880 的错别字把“缺少”变成“取消”，模型生成了删除配置项的处置候选。候选
本身已声明 `orchestrate.phase=solution`，但旧校验先执行 QFK 的 `match XOR produces`
结构门禁，因此页面只看到“必须且只能配置 match 或 produces”，没有暴露真正的
业务问题。

需求是识别正常关键信号与变更动作：正常事实继续保存；变更动作报错并保留给专家
审核。范围明确排除自动改正文、案例硬编码、`sed` 专项规则和通用 Shell 风险引擎。

## 方案（WHAT）

### 1. KBD 专用只读门禁

在共享代码中定义单一判定函数，但不修改跨 KBD/SOP 通用 JSON Schema：

- `orchestrate.phase=solution`：确定为处置候选；
- QFK `acquire.args.command` 命中平台已有明确写动作词表：确定为变更候选；
- 其他命令不做参数级猜测，不对 `sed` 特殊化。

整份 KBD 文档校验按稳定 `signals[index]` 抛出 `ValidationError`，使管理页仍可映射到
稳定 Signal ID 并跳转编辑。错误同时给出处理建议：修正排查描述，或将动作保留在
KBD 解决方案中。

### 2. 三层一致边界

```text
LLM Candidate
  → KBD 抽取门禁（先拒处置，再校验 match/produces）
  → rejected_candidates（原文 + 原因，供专家审核）

Expert Draft / Publish
  → KBD 专用整文档只读校验
  → 通用 Signal v2 / 工具参数 / 发布契约校验

Historical Runtime Signal
  → Agent 复用同一只读判定
  → blocked，不自动执行
```

SOP 仍可使用既有通用 `validate_*_signals_json`，不被 KBD 专用保存门禁连带改变。

### 3. Prompt 收口

Prompt v1.9 删除三处冲突引导：

- “写操作设置 `require_human_confirm=true` 和 `phase=solution` 后可抽取”；
- “明确处置/修复动作时才抽取”；
- “solution Signal 的 role 必须为 context”。

替换为：所有输出 Signal 必须为 `phase=diagnostic`；出现写入、配置变更、启停/重启、
删除、迁移等动作时不生成 Signal，只抽取邻近且证据充分的只读事实。data migration
020 前向更新已部署 Prompt 并追加最高优先级规则；不改写现有 KBD、Revision 或正文。

## 决策依据（WHY）

### 为什么拒绝而不是保存为待确认 solution Signal

Signal 是诊断证据图的一部分，解决方案是处置流程。将两者放入同一集合会让
“人工确认”同时承担证据质量审核和执行授权两种语义，并使错误正文有机会进入运行
计划。拒绝候选并交专家修正，能保持证据模型单一、训练样本清晰和运行时默认安全。

### 为什么不识别 `sed -i` 参数

本次根因是源内容错别字，并且候选已明确标记 `phase=solution`。为单一案例加入
`sed -i/--in-place/-n` 分支会把领域校验扩张为 Shell 语义引擎，仍无法完整覆盖 Python、
重定向、工具脚本或未来命令。当前最小策略只采信结构化 phase 与既有明确动作词表；
无法确定的内容由 Prompt 减少生成、专家审核和 Agent 既有执行安全体系处理。

### 为什么不直接修改通用 Schema

`signals_json` Schema 同时服务 KBD 与 SOP。KBD 的只读知识边界不能隐式改变 SOP
决策树/处置流程语义，因此门禁必须是 KBD 场景校验，而不是跨文档 Schema 枚举收窄。

## 影响范围

- KB Service：KBD 自动抽取、专家草稿、维护发布、审核/重新发布；
- Shared：KBD 只读判定与整文档校验；
- Agent Service：历史错误 Signal 的运行时纵深防御；
- Database：Prompt seed v1.9 与 data migration 020；
- 不改数据库表结构，不清理历史 Revision，不修改 SOP 保存契约。

## 验收标准

- 正常只读 Matcher/Producer 通过；
- `phase=solution` 候选在 QFK 二选一之前拒绝且保留原文；
- 明确写动作在专家保存入口返回可读 422；
- 历史 solution/明确写动作在 Agent 调度中 blocked；
- Prompt seed/migration 契约测试证明旧引导已消失；
- KB、Agent 相关测试、Ruff、文档检查和 CI 全绿。

## 回滚

- 应用回滚恢复旧门禁，现有 KBD 数据无需逆迁移；
- Prompt 通过受控前向迁移或激活前一版本回滚；
- migration 020 不修改业务数据，无数据回滚脚本；
- rejected candidates 属于 Proposal 审计内容，回滚时不应删除历史。
