# KBD 信号 QKV 关键词类型契约收敛方案

## 背景与需求

KBD 关键信号抽取出现如下 Rejected Candidate：

```text
acquire.args 校验失败: acquire.args.keyword 类型错误：期望 string，实际 list
```

候选使用了 `qkv_task.acquire.args.keyword = ["迁移虚拟机"]`。排查确认：

- `qkv_*` 的 `acquire.args.keyword` 是一次 aCLI `-k` 查询使用的单个字符串；
- `match.pattern` 才允许 `string|string[]`；
- `extract.rows.include/exclude` 才允许字符串数组；
- PR #669、#677 的 Prompt 追加规则使用了未限定路径的“keyword 多关键字使用数组”表述，给 LLM 留下了字段迁移歧义；
- 服务端门禁和 QKV 执行器的严格字符串契约是正确的，不应通过放宽 schema 掩盖抽取错误。

## 方案（WHAT）

### 1. Prompt 类型矩阵

在 seed Prompt 和存量数据库迁移中统一写入最高优先级类型矩阵：

| 字段 | 类型 | 语义 |
|------|------|------|
| `qkv_alert/qkv_task/qkv_dialog.acquire.args.keyword` | 非空 `string` | 单次 aCLI `-k` 查询词 |
| `match.pattern` | `string|string[]` | QFK Matcher 判定条件 |
| `extract.rows.include/exclude` | `string[]` | QFK 候选行筛选条件 |

多个任务动作拆成多条 `qkv` Candidate，不拼成一个数组，也不使用逗号、竖线或隐式 OR 连接。

新增 `023_align_qkv_keyword_type_contract.sql`，把已经执行过 021/022 的动态 Prompt 归一到 2.3，并以 SQL 断言保证没有旧的未限定数组指令残留。

### 2. 严格门禁与稳定错误码

继续保持 `qkv_*` 的 `keyword: string` Schema，不接受数组。对 QKV keyword 类型错误增加稳定码 `QKV_KEYWORD_MUST_BE_STRING`，错误信息同时指出正确字段路径和拆分方式。

不对多元素数组做 join 或隐式 OR/AND 转换；它们的语义不明确，必须作为 Rejected Candidate 交专家处理。

### 3. 回归与观测

新增 QKV 参数契约单测和 Prompt 契约测试，覆盖：

- 单字符串通过；
- 单元素/非字符串数组拒绝并带稳定错误码；
- Prompt 明确区分三个数组/标量字段；
- 旧的裸“keyword 使用数组”表述不再出现。

## 决策依据（WHY：为什么选此方案，为什么不选其他方案）

### 保留严格 string 门禁

QKV 执行器直接把 keyword 传给 `shlex.quote()` 并构造一个 `acli ... -k` 参数。放宽为数组无法定义现场查询的 AND/OR 语义，会把抽取错误推迟到执行阶段，并破坏 QKV/QFK 的职责边界。

### 不静默拼接多元素数组

逗号、空格、竖线和重复调用都可能代表不同查询语义。自动 join 会丢失原始意图，且无法保证任务 producer 与下游变量依赖仍然一一对应。

### 先修 Prompt，再考虑单元素兼容

单元素数组在数学上可以 unwrap，但若立即自动归一，会掩盖 Prompt 回归。首版只做明确拒绝和可审计错误；若线上历史数据仍大量出现单元素数组，再另行增加有开关、可观测的兼容归一化。

## 验收标准

1. `validate_acquire_args("qkv_task", {"keyword": "迁移虚拟机"})` 通过。
2. `keyword: ["迁移虚拟机"]` 被拒绝，并包含 `QKV_KEYWORD_MUST_BE_STRING`。
3. `match.pattern` 和 `extract.rows.include/exclude` 的数组语义继续保留。
4. seed 和 023 动态迁移 Prompt 均通过无占位符、无旧歧义词校验。
5. 相关 Python 单测和 Prompt 合同测试通过。
