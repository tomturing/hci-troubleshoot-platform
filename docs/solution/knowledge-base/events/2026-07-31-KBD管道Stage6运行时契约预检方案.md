# KBD 管道 Stage 6 运行时契约预检方案

## 背景与需求

操作人员从仓库根目录执行：

```bash
uv run python -m data-pipeline.kbd.run pipeline --ids 40061 --override --override-status all --force-fetch
```

Stage 1 至 Stage 5 已依次完成抓取、入库、识图、分类和 LLM 关键信号抽取；进入
Stage 6 时才因 `ModuleNotFoundError: No module named 'shared'` 终止。根因不是 KBD40061、
LLM 或单一 `qfk_log` 契约，而是 `signal_review.py` 复用 `backend/shared` 的 Shared Resolution Runtime，
而该命令入口只天然包含仓库根目录，未包含 `backend/`。

这违反数据生产的基本原则：一个完整 pipeline 的依赖必须在发生任何昂贵或有状态操作前
可验证；用户不应靠记忆手工 `PYTHONPATH` 才能运行已文档化的入口。

## 方案（WHAT）

1. 在 `data-pipeline/kbd/runtime.py` 建立唯一的仓库级运行时准备模块。它由当前源码
   文件位置解析仓库根目录，并把同一 checkout 的 `backend/` 加入 Python 搜索路径；不
   读取密钥、不连接数据库、不写业务数据。
2. `kbd` 包初始化时执行路径准备，因此无论使用推荐入口
   `python -m data-pipeline.kbd.run`，还是兼容入口 `python -m kbd.run`，Stage 6 的
   `shared.schemas` 都来自当前代码版本，而非另一份不确定的安装包。
3. 对独立 `review-signals` 及包含 Stage 6 的 `pipeline`，CLI 解析参数后、日志初始化
   和任何 Stage 开始前显式导入 `acquirer_args` 与 `log_source_catalog`。预检失败用 argparse
   的可读错误退出，不会执行 fetch/import/Vision/LLM。
4. 统一将推荐人工入口写为
   `uv run python -m data-pipeline.kbd.run <command>`。旧 `PYTHONPATH=data-pipeline:backend
   uv run python -m kbd.run` 保持兼容，但不再要求使用者配置。
5. 用不带 `PYTHONPATH` 的子进程回归测试真实入口和文件审计，防止未来把路径依赖重新
   推迟到 Stage 6。

## 决策依据（WHY：为什么选此方案，为什么不选其他方案）

Python 在当前运行方式下可以定位名为 `data-pipeline` 的源码目录，用户的实际执行已证明
这一点；不能因为目录含连字符就把可用入口写成“非法”。不过 Python 不会自动把相邻的
`backend/` 作为顶级模块根，因此必须显式处理这一仓库内部边界。

选择“单一小型 bootstrap + 命令级预检”，因为它同时满足：

- **确定性**：生产审计与 Agent 引用同一 checkout 的 `shared` 契约；
- **前置失败**：默认完整链路在副作用前验证 Stage 6 必需依赖；
- **低耦合**：只有 KBD 包边界知道源码布局，领域审计仍只表达 Schema/Catalog 规则；
- **兼容性**：CI 和既有自动化不需要一次性迁移；
- **可验证性**：真实 `-m` 子进程测试，而不是仅在 pytest 的 `sys.path` 夹具中通过。

不采用以下方案：

1. **仅在 README 要求 `PYTHONPATH`**：人为配置会遗漏，且本次正是在耗时生产后才暴露，
   不满足安全、可靠的批处理范式；
2. **把 `backend/shared` 复制进 data-pipeline**：会产生 Schema/Catalog 漂移，破坏“生产
   审计与消费运行时同契约”的设计；
3. **在 `signal_review.py` 临时修改 `sys.path`**：把仓库启动责任泄漏进领域逻辑，后续
   其他共享能力仍会重踩同一问题；
4. **只在 Stage 6 延迟导入**：可减少不需要审计的子命令的依赖，但不能让默认六阶段
   pipeline 在已经执行五阶段后才失败。保留延迟导入，同时增加提前预检。

## 影响范围

- 代码：`data-pipeline/kbd/__init__.py`、`runtime.py`、`run.py`；不改变数据库、LLM
  Prompt、KBD 内容或 Agent 执行语义；
- 操作：KBD README 和总览 README 的首选命令变为无需手设 `PYTHONPATH` 的仓库入口；
- 验证：增加真实子进程回归；
- 数据：无 Schema 变更、无数据迁移、无已有 KBD 重算。

## 验收标准

1. 从仓库根目录清空 `PYTHONPATH` 后，`uv run python -m data-pipeline.kbd.run
   review-signals --file <valid-json>` 能成功读取共享 Runtime 契约；
2. 默认 `pipeline` 在 Stage 1 前完成共享契约预检；缺少 `backend/shared` 时给出可操作的
   CLI 错误，而不是跑到 Stage 6 traceback；
3. `pipeline --stages fetch` 不被不相关的 Stage 6 依赖阻断；
4. 旧 `PYTHONPATH=... python -m kbd.run` 入口保持可用；
5. 文档明确推荐入口、兼容入口和失败处理；
6. 本次不宣称 KBD 语义正确、126 条 Expert Gold、真实客户 replay 或 LLM 质量提升。
