# 关键信号抽取与建模设计

本文只维护 Signal 的生产链：输入、分层抽取、模板、验证、自愈和人工接续。字段定义见[信号契约](关键信号架构设计.md)，运行时裁决见[CDD](KBD证据诊断与CDD闭环设计.md)，日常操作见[审核手册](../../user-guide/KBD审核与信号配置-使用手册.md)。

无信号案例可以发布为参考知识，因而“希望案例能被检索”不再构成强制抽取或补造信号的理由。抽取用于建立可信自动验证能力。

## 1. 输入和来源

- 标题、问题描述、告警信息和有效排查步骤提供原文材料；输入边界由抽取路由决定。
- 图片需按诊断章节和来源白名单进入证据链。解决方案、未知章节和模型自由推断不能伪装成现场采集事实。
- `provenance`、source refs 和原文片段保留来源。不能要求正文证据逐字等于每张 OCR 图片，也不能放宽为“模型说来自原文即可”。
- 处置/写操作与只读诊断分开；不能为让 DAG 闭合编造变量来源或未知命令。

入口：[extract_signals.py](../../../backend/kb-service/app/routes/extract_signals.py)。具体允许输入、归一化与拒绝原因以该入口及共享安全契约为准。

## 2. 四阶段与拓扑分层

| 阶段 | 负责什么 | 输出去向 |
|---|---|---|
| 计数 count | 原子观察、实体边界、去重和原文证据 | 候选意图及来源 |
| 分类 classify | 把意图映射到代码支持的采集能力 | 工具类别与分类结果 |
| 建模 model | 生成 acquire、取值、Matcher/produces 和依赖 | 待校验 Signal |
| 验证 verify | 对照原文、Schema、安全边界及 DAG 门禁；受限自愈 | 有效信号与拒绝候选 |

建模优先处理 Producer，收集其已声明变量后注入 Consumer 上下文，避免消费者不知道上游能提供哪些变量。END→DATE 的派生与共享 Schema、保存和运行时一致。

自动分类目录由共享能力定义决定：当前自动建模覆盖直接 QKV、条件视觉生产者和 QFK；效果验证由专家维护，`qkv_case_context` 属于非采集入口。不要在新 Prompt 或文档另建一套工具枚举。

调度、回退与自愈次数的权威实现是 [signal_orchestrator.py](../../../backend/kb-service/app/services/signal_orchestrator.py)。模型阶段完成不等于 Candidate 通过工程门禁，更不等于案例发布或现场验证。

## 3. Prompt、模板与黄金样本

| 资产 | 用途 | 维护边界 |
|---|---|---|
| `kbd_signal_count_v1` | 计数 Prompt | 只负责意图与来源拆解 |
| `kbd_signal_classify_v1` | 分类 Prompt | 对齐当前能力目录 |
| `kbd_signal_model_v1` | 建模 Prompt | 对齐参数、变量与处理契约 |
| `kbd_signal_verify_v1` | 验证 Prompt | 使用结构化错误纠偏并复检 |
| `signal_modeling_template` | 标准建模契约模板 | 工具类型、Schema、变量协议、反模式 |
| `signal_best_practice` | 专家确认的实例 | 保留来源和版本，不把未审核 Proposal 当黄金样本 |
| `signal_failure_extraction` | 异常复盘 | 阶段、原因、原文上下文、Trace 与 payload |

Prompt 由数据库及 StrictPromptLoader 管理；源文件修改后仍需按部署路径落实数据迁移/发布。不要假设只修改未被镜像打包的目录就能让线上 Prompt 生效。

资产构建和读取见 [signal_asset_service.py](../../../backend/kb-service/app/services/signal_asset_service.py)。管理端“模板实例库”用于查看模板和最佳实践，“可观测性→信号抽取”用于复盘异常。

## 4. 工程校验与自愈

必须分别守住：

1. JSON 结构、稳定信号 ID、工具与参数类型；QKV keyword 是字符串，不能复用 QFK pattern 数组语义。
2. 受控 JSON 点号路径及取值语法；不能直接使用通用 JSONPath 的 `$`、通配符等未支持语法。
3. QKV 的产出/后处理，QFK 的 Match 与 Produce 互斥关系。
4. 只读诊断边界和封闭执行参数，禁止用包装命令或自由管道绕过。
5. 变量声明、别名、内部处理与跨信号依赖，发布前 DAG 可达。
6. 原文来源、有效证据与有限自愈。自愈通过后不得残留同一候选的旧拒绝状态。

拒绝项保留给专家复核；部分有效不等于所有候选已通过。不得通过忽略 rejected 或将缺失信号自动视为通过来提高表面成功率。

## 5. 专家接续和生命周期

AI 产物作为 Proposal 保存；专家可修改内容、图片、信号和角色，形成工作稿。发布时重新执行当前契约审查并切换不可变运行快照。

专家删除信号、改变证据作用时，验证策略随存活信号重建；删除最后一条信号可以成为仅参考知识，但未处理的异常/拒绝候选仍须明确复核。不会因抽取任务完成而自动发布。

来源正文或图片变化后，已有信号可能失效。Prompt 变更只影响后续生成，不自动改写已发布内容；已发布修订仍走维护审核流程。

## 6. 任务运行和排障

- 当前命令只查 [Pipeline README](../../../data-pipeline/kbd/README.md)；本文不复制 CLI 参数。
- 管理端任务持久化、中断、重试见 [KBD 批量任务状态](KBD批量任务状态迁移说明.md)。
- 先确认案例级阶段是否完成，再看图片级或候选级统计；不能用一个粒度的成功数代替另一粒度。
- 门禁错误先定位 signal_id、field_path、reason 与 Trace ID，再决定修改原文、Prompt、模板或专家配置。
- 同样的正反例对比抽取前后，而不是只比较通过数量。单个案例的修复不能代替分类完整候选回归。
