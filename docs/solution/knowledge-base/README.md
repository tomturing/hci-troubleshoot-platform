# KBD 与关键信号文档入口

这是案例知识与信号的统一阅读入口。先按问题选文档，不必从历史方案逐篇拼出当前行为。

当前工作区已经实现无信号案例推荐：允许干净的空信号案例发布，以标题和问题描述检索；不把推荐当作现场确诊。该功能已做本地定向验证，尚未提交、部署或进行真实检索准确率评测。

## 四条路径，不要混淆

| 路径 | 找到依据 | 后续行为 | 允许的结论 |
|---|---|---|---|
| SOP | 已确认分类与执行上下文 | 按决策树继续；明确放弃后转 KBD | 基于 SOP 排查结果 |
| KBD 强信号 | 同分类可执行案例的任务、告警、弹框等入口 | 继续验证必要、排除、增强证据 | 证据门禁通过才确诊 |
| KBD 语义画像 | 用户描述、画像症状/锚点/范围 | 合格消费者可验证；否则人工指引/参考 | 匹配本身不确诊 |
| KBD 无信号 | 用户问题对标题、问题描述的匹配 | 提供历史案例、适用条件和处理建议 | 未验证参考，不进入 CDD |

完整流程图和 SOP 回退条件只在[运行流程](KBD证据诊断与CDD闭环设计.md#1-总流程)维护。两个关键区别：生产者命中不是根因确认；知识可发布不是诊断可执行。

## 文档维护规则

1. 修改对象/发布生命周期，更新总览；修改路由/证据裁决，更新运行流程；修改检索，更新语义推荐文档。
2. 修改字段，先更新代码和生成 Schema；架构文档解释含义，不再复制一整套枚举和默认值。
3. 修改操作入口或报错，更新用户手册；抽取 Prompt 和模板规则更新生产文档。
4. 新事件的结论蒸馏进对应主文档；历史 events 和归档只用于追溯，不承担现行规范。
5. 旧文件路径只做兼容跳转，禁止继续追加第二份规则。单一主题只保留一个正文维护点。
6. 代码级实现、本地自动测试、仿真和部署后现场通过分别记录，不能互相代替。
