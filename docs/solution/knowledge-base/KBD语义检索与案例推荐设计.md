# KBD 语义检索与案例推荐设计

本文合并语义画像、无信号标题匹配和参考推荐规则，是文本检索的唯一正文维护点。SOP 和强信号的优先顺序见[运行流程](KBD证据诊断与CDD闭环设计.md)，审核操作见[使用手册](../../user-guide/KBD审核与信号配置-使用手册.md)。

基线为当前工作区。无信号推荐已完成本地实现和定向测试，尚未提交、部署或进行线上检索效果验收。

## 1. 先区分三件事

| 能力 | 输入与结果 | 权限 |
|---|---|---|
| 文本召回/排序 | 用户问题与标题、问题描述、可选画像 → 相关案例 | 不能产生根因证据 |
| 受控语义验证 | 已有可执行画像满足原门禁 → 执行已审核的 Signal | 按现场证据裁决，不由排名裁决 |
| 案例参考 | 发布案例正文 → 历史根因、处理方法与适用条件 | 不执行正文命令，不写 S4，不标为已验证 |

标题里可以包含历史根因；这有助于找到文章，但不证明用户现场具有同一根因。相关度也不是“根因正确率”。

## 2. 无信号案例的发布

干净的空信号文档可以发布为派生能力 `reference_only`。不要求维护 `semantic_entry_profile`，也不补造 `qkv_case_context`。

内容、标题、分类、审核与版本锁约束仍然生效。存在非法 Signal、孤儿画像、过期抽取结果或待处理拒绝候选时，不会自动当作正常的无信号案例。具体发布规则只在[知识库设计](知识库设计.md#2-可以发布与可以执行分开)和使用手册维护。

`reference_only` 不是 KBD 状态或画像枚举。画像自身仍使用 `executable / guidance_only / capability_gap` 三档。

## 3. 有画像时如何使用

画像对普通案例推荐是可选增强。保留画像时，仍应和 `qkv_case_context` 成对，并符合原契约。

| 配置 | 用途 | 约束 |
|---|---|---|
| `canonical_symptoms` | 客户可能提供的现象 | 不把处理方案写成已发生现象 |
| `positive_anchors` | 明确报错和特征短语 | 受控画像验证仍使用锚点门禁 |
| `exclusion_anchors` | 明确不适用现象 | 命中排除条件时不推荐 |
| `applicability` | 产品、版本、组件、对象、操作范围 | 已知冲突排除；自动验证缺少范围仍受原门禁约束 |
| `semantic_disambiguation` | 已定义的澄清题与选项 | `support / exclude / neutral`；neutral 不凭空剔除候选 |
| `manual_evidence_request / manual_evidence_fields` | 人工补证据文字或结构化字段 | 不等于可执行命令或已验证证据 |
| `source_refs / source_evidence` | 画像来源与发布时原文核对 | 不将根因/解决方案作为问题侧原文证据 |

具体必填项、长度、枚举和 JSON 结构引用 [Schema](../../../backend/shared/schemas/signals/signal.v2.schema.json) 与 [semantic_entry.py](../../../backend/shared/schemas/semantic_entry.py)，不在文档内复制第二套定义。

## 4. 请求与发布快照

在线请求沿既有 `POST /api/kb/kbd/semantic-entry/resolve` 路径。

| 字段 | 含义 |
|---|---|
| `category_id` | S0 已确认分类；推荐不静默跨分类 |
| `case_context` | 用户原始问题及后续有效补充；允许受控结构化范围字段 |
| `strong_producer_status` | 保留 matched、no_match、source_unavailable 等真实强入口状态 |
| `expected_revisions` | 本轮分类成员及其发布修订，用于并发检查 |
| `include_reference_cases` | 显式启用标题/问题描述参考；默认 false，兼容旧调用方 |
| `excluded_kbd_ids` | 本轮已经被现场证据排除的案例，后续不得重新入选 |
| `recommendation_only` | 已验证过画像后的只读回退，不再次启动同一验证 |

服务读取 active 的不可变发布快照，并核对状态、分类、成员和修订；版本变化返回 409。工作稿标题不能配旧发布正文参与推荐。

用户上下文保留首条主诉和后续有效补充，跳过“继续”等控制词以及模型/工具消息；版本等范围只接受已有可信环境字段，不从文本猜测执行目标。

## 5. 标题优先的推荐池

共享实现：[kbd_recommendation.py](../../../backend/shared/schemas/kbd_recommendation.py)。

1. 对同分类可推荐的发布案例建立一个池，有画像和无画像的案例一起比较，不因填写画像而自动排名靠前。
2. 标题优先做中文双字词及英文词匹配，问题描述、报错与画像文本补充；缺少可展示正文的旧画像仍保留原有补证据路径。
3. 显式画像排除条件、澄清排除答案和已知范围冲突继续生效。缺少范围信息的只读参考标注待核对，不获得执行资格。
4. 允许时对整个候选池分批做语义向量检索；不先用词法 Top-K 丢掉同义表达候选。向量缓存按模型命名空间和检索文本摘要区分。
5. 独立 `root_cause / solution` 字段不拼入推荐向量；标题原文保持完整。通用案例 embedding 含根因，不能当作这条路径的标题检索分数。
6. 向量异常整批回到词法排名，不混合半批向量结果。没有合适案例就保留无匹配，不强选第一名。
7. 最多返回五篇参考；近分保留多篇并提示补充能区分的信息。

当前初始词法门槛为 0.45、向量门槛为 0.78、歧义间隔为 0.12。这些只是未经过真实查询集校准的检索参数。完整分数组合以函数实现为准，不应解释为概率。

明确否定/历史分句采用保守过滤。这不是完整自然语言理解；复杂纠正、多对象叙述、短错误码和宽泛描述仍需纳入真实查询集评测。

## 6. 强信号和参考的隔离

| 现场状态 | 受控语义验证 | 只读案例推荐 |
|---|---|---|
| 无强入口，或强入口完整未命中 | 满足原画像/消费者门禁时可执行 | 可用 |
| 强入口命中但 CDD 未确诊 | 不用相似度绕过已有强证据 | 可展示未验证参考 |
| 查询失败或不完整 | 不作为 no_match 放行执行 | 可参考，但保留失败说明与原 CDD 报告 |
| 案例已被现场证据 REJECTED | 不重新入选 | 也不能因标题相似重新入选 |
| 已有 DEFINITIVE 结论 | 由既有诊断链结束 | 不再启动兜底推荐 |

只读推荐不会改写 `candidate_states`，不产生 SUPPORTED、DEFINITIVE 或 S4。前端不把模型生成的 Markdown 变成自动执行请求。

## 7. 返回结果和客户呈现

新决策值 `case_recommendations` 返回案例号、标题、发布修订、匹配依据、问题摘录、历史根因、参考处理方法、范围提醒和 `verified=false`。

展示文案应说明“这是历史案例的原因和方法，当前尚未现场验证”。同症状不同根因可以同时展示。用户确认现象相似或照方案恢复，也不能被重写成“系统通过信号证明了该根因”。

旧 `semantic_recommendation` 仍作为兼容输出存在；新 Agent 显式启用参考池。已有可执行画像仍先按原准入验证，而不是把任意标题匹配案例直接变成自动执行目标。

## 8. 离线、观测与验证

- 离线参考入口复用共享推荐规则；无信号案例不生成 Collector、映射、Collection Profile 或空计划。
- 已有可执行案例改成仅参考后，同步对不再被引用的采集资源生成停用变更，由原审批流程生效。
- 语义路由返回 routing_version、耗时、降级、范围过滤、分数及发布修订；审计记录精确知识版本，模型失败保留词法降级说明。
- 回归包括标题正例、否定/历史/无关输入、同症状不同根因、范围冲突、向量异常、冻结修订、现场反证排除、SOP 放弃回退和不进入 S4。

实现入口：[语义路由](../../../backend/shared/schemas/semantic_routing.py)、[检索 API](../../../backend/kb-service/app/routes/kbd_search.py)、[Agent 编排](../../../backend/agent-service/app/adapters/agents/htp/investigation_agent.py)、[离线指引](../../../backend/diagnosis-service/app/services/collection_profile_service.py)。

真实查询集上线评测应比较标题独用、标题加问题描述的召回和误推荐，覆盖无答案、版本冲突及重复标题。此前历史样例的通过记录不代表新标题路径已经线上验收。
