# SSH 终端独立化与登录门禁统一方案

## 变更历史

| 日期 | 版本 | 变更内容 | 关联事件文档 |
|------|------|---------|------------|
| 2026-11-05 | v1.0 | 初版：删除「无工单 → 先建工单才能连 SSH」的三态逻辑；顶栏 SSH 终端入口改为统一登录门禁；创建工单与 SSH 登录弹框互斥并统一 append-to-body | — |

## 一、现场反馈

2026-11-05 现场截图（无活跃工单）：

1. 顶栏点「SSH 终端」后，右栏空状态只给一个按钮「连接 SSH 并创建工单」；
2. 点击该按钮弹出的是**创建工单**表单（标题 / 描述 / 助手 / SSH 表单），不是 SSH 登录框；
3. 创建工单弹框出现后，页面其它图层与弹框边缘互相穿插，观感上像"弹框被盖住了一半"。

用户原话：

> 现在连接 SSH 是一个单独的功能，同时给 Agent 排障、日志收集、文件下载三个功能使用。
> 现在点击 SSH 终端直接弹出来「连接 SSH 并创建工单」，明显还是之前 SSH 终端绑定
> Agent 排障的逻辑，完全不合理。

## 二、根因（第一性原理）

先把"事实"与"历史包袱"分开：

| 事实 | 说明 |
|---|---|
| SSH 会话是**基础设施** | 终端、文件下载、日志收集、Agent 排障共用 `caseID@nodeIP` 这一条 bridge 会话 |
| 工单是**归档维度** | 录像、回放历史、日志回采需要 `case_id`；连接本身不需要 |
| Bridge 是**前置条件** | 没有 bridge 就没有会话，与工单无关 |

旧实现的错误在于把三个独立维度串成了一条链：

```
无工单 → 不能连 SSH → 先走建单 + 采集环境 → 才拿到终端
```

这条链在 2026-04 是成立的（当时 SSH 只为"建单后排障"服务），但当 SSH 被抽成
四个功能共用的能力之后，链路的第一环就变成了**误前置**：

- 只想登进终端看一眼的用户，被迫填写标题/描述/助手并创建工单；
- 已有 SSH 会话的用户，再点终端入口仍可能被要求建单（三态只判断 `currentCase`）；
- 建单弹框与登录弹框是两条状态机，同时出现时层级不可控。

结论（不可再分的约束）：

1. **连接动作只受 bridge 与凭据约束**，不受工单约束；
2. **工单只影响归档**，缺失时应降级（不归档）而不是阻断；
3. **同一时刻只允许一个模态**，创建工单与 SSH 登录必须有明确互斥。

## 三、方案

### 3.1 顶栏「SSH终端」= 登录门禁（`stores/chat.ts`）

`checkAndOpenTerminal()` 由"只开面板"改为三分支：

| 会话状态 | Bridge | 行为 |
|---|---|---|
| 已连接 | 不探测 | 直接打开右栏终端页签（零探测，与排障门禁口径一致） |
| 未连接 | running | 打开右栏终端页签 + 统一登录弹框 `openSshFlowDialog(caseId, 'terminal-only')`，登录成功后由 `openTerminalSidebar()` 落到终端页签 |
| 未连接 | not-running | 同上打开右栏与登录框，框内 `bridge-guide` 视图提供下载与「已运行，点击刷新」（与文件下载 / 日志收集 / 面板内登录完全同构） |

`caseId` 取值优先聊天工单，其次日志收集绑定的人工工单，最后 `null`（桥侧兜底 `terminal-only`）。

### 3.2 终端面板两态化（`TerminalPanel.vue`）

删除 `terminalState` 三态与 `handleConnectAndCreate()`（唯一调用 `showCaseTemplate = true` 的终端入口）：

| 状态 | 文案 | 点击 |
|---|---|---|
| 未连接（无论有无工单） | 连接 SSH | `checkBridgeBeforeOpen()` → `openSshFlowDialog(..., 'terminal-only')` |
| 已连接 | 不显示按钮，直接 xterm | — |

未绑定工单时在按钮下方补一行弱提示：可连接，但「终端录像与回放历史需有工单后归档」。
录像启动条件由 `currentCase.case_id` 改为 `historyCaseId`（聊天工单 → 日志收集工单），
使"先连 SSH、后指定工单"的场景也能正确归档。

### 3.3 模态互斥与层级（`chat.ts` / `CaseCreateDialog.vue` / `SshConnectDialog.vue`）

- `openSshFlowDialog()` 入口统一执行 `showCaseTemplate = false`：
  先发消息触发的建单框、再从顶栏点 SSH 终端，不会出现两个弹框叠在一起；
- 两个 `el-dialog` 增加 `append-to-body`：遮罩与弹框挂到 `body`，不再成为
  `.chat-window` 的 flex 子项，避免内容列限宽/居中规则与就地渲染的 `fixed` 遮罩互相干扰。

> 为什么不是只调 `z-index`：`el-dialog` 的 z-index 本身由 Element Plus 递增分配，
> 实测遮罩已铺满视口（1600×900）；真正的风险是**两个模态同时存在**时的语义冲突
> 与 DOM 归属（就地渲染在 `.chat-window` 内）。先保证"只有一个模态"，再谈层级，
> 调数字只是掩盖问题。

## 四、对抗性审查

| 失效条件 | 处置 |
|---|---|
| 用户先连 SSH（无工单），再发消息建单 | 建单流程不依赖已有会话；建单成功后 `currentCase` 生效，后续录像按聊天工单归档（已连接期间的历史录像不补录，属已知降级） |
| 无工单连接后想看录像 | 面板明示"需有工单后归档"；`终端历史` 按钮仍可点，但提示先建单或指定工单号 |
| 登录弹框开着时用户点「发送」 | 建单流程沿用原逻辑，两者不会同时从终端入口触发；若已同时存在，建单侧关闭时不会误断已建立的会话（`handleCancelled` 只在未连接时清理） |
| Bridge 在检测后、登录前退出 | `SshConnectSection` 自身状态机在连接失败时进入 error 视图并给出重试，不依赖入口的检测结果 |
| 已有会话但桥已重启（假 connected） | 终端发送命令会收到 `ssh_error`，沿用既有错误提示；本次不改变会话健康探测口径 |
| 宽屏/窄屏布局 | 入口只改弹框与页签，`enforceOverlayExclusive('right')` 原样保留，不新增布局分支 |
| 文件下载页签未登录 | 仍走 `openSftpPanel()` 的登录门禁（`pendingRightPanelTab = 'sftp'`），与本次改动互不影响 |

| V1 | 无工单、未连接，点顶栏 SSH 终端 | 右栏展开并弹「连接 SSH 终端」登录框；无建单弹框 | `chat.ssh-standalone.spec.ts`「未连接时点击 SSH 终端…」 |

## 六、二轮对抗性审查（2026-11-06）

对已合并的 #1440 做红队复核，发现并修复以下问题：

| 编号 | 攻击点 | 事实 | 处置 |
|---|---|---|---|
| R1 | **入口语义分叉**：Bridge 未运行时，顶栏弹旧「SSH 终端插件」下载窗，文件下载 / 日志收集 / 面板内登录弹统一登录框 | `showBridgeDownload` 全仓仅由 `checkAndOpenTerminal` 触发；旧窗只有「下载并打开」，没有「已运行，重新检测」 | 删除旧弹窗（`App.vue` 模板/样式/`handleDownloadBridge`/`BRIDGE_DOWNLOAD_URL`、store 的 `showBridgeDownload`/`closeBridgeDownload`），四个入口统一走登录框的 `bridge-guide` |
| R2 | **挂起意图残留**：已连接分支写入 `pendingRightPanelTab='terminal'` 且永不消费 | 该值只在 `openTerminalSidebar()`（登录成功回调）消费；已连接不会再登录 | 已连接分支改为 `pendingRightPanelTab = null` |
| R3 | **录像归档与连接 caseId 不一致**：登录用 `logCollectCaseId`，录制用 `historyCaseId` | 两者现已同源（`currentCase → logCollectCaseId`），但属隐式契约 | 保持不变，由 `historyCaseId` 单点派生，避免两处各算一遍 |
| R4 | **建单弹框被强制收起**：`openSshFlowDialog` 直接 `showCaseTemplate=false`，若建单流程处于 progress 会打断可见性 | `el-dialog` 模态遮罩会拦截顶栏点击，实际不可达；仅在程序化调用时可发生 | 保留防御（单模态），并在 §五 遗留中标注建单流程未复用统一会话 |
| R5 | **折叠右栏是否断会话**：`TerminalPanel.onBeforeUnmount` 会 `disconnectSsh()` | `PanelShell` 内容与 `TerminalPanel` 均为 `v-show`，折叠/切页签不卸载，不会误断 | 无需改动，记录为已知前提 |

回归验证：`chat.ssh-standalone.spec.ts` 的 Bridge 不可用用例改为断言「弹登录框 + `bridgeStatus=not_running`」；
`TerminalPanel.ssh-entry.spec.ts` 新增「Bridge 不可用仍打开统一登录框」用例。

## 七、遗留

- Agent 排障建单流程（`CaseCreateDialog`）仍内置一套 SSH 表单与采集步骤；
  本次只切断"终端入口 → 建单"，未把建单里的 SSH 表单替换为统一登录组件。
  若后续要求"已连接时建单不再二次填写"，需要单独收敛建单流程的会话复用。
- 无工单期间的终端录像不归档：`startRecording` 需要 `case_id`，当前不做本地暂存/回填。
- 真机 UI 验收需在浏览器内确认：顶栏 SSH 终端 → 登录框 → 连接成功 → 终端页签，
  以及建单弹框与登录弹框不同时出现（本机自动化覆盖 DOM 与状态，视觉走查仍需人工确认）。
