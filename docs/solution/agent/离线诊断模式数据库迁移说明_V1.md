# 离线诊断模式数据库迁移说明

> 版本：V1
> 日期：2026-08-04
> 对应模块：`diagnosis-service`（诊断服务）

## 变更内容

本次声明式 Schema 增加：

- `diagnosis_session_status`：诊断会话状态枚举；
- `diagnosis_session`：离线诊断会话根实体；
  - `assigned_to` 保存当前负责审核和处置的工程师标识；
- `collection_plan`：记录画像版本、生成上下文、容量估算、权限和敏感数据声明；
- `collection_plan_item`：记录展开后的 Collector（采集器）、目标和绝对时间窗；
- `collector_definition`：Collector Registry（采集器注册表）事实源，记录定义、审批、
  禁用和乐观锁状态；
- `collector_artifact`：保存 Structured Collector Artifact（结构化采集器制品）、
  SHA-256、Ed25519 分离式签名、公钥、有效期、撤销状态及撤销审计字段
  `revoked_at/revoked_by/revocation_reason/revoked_trace_id`；
- `collector_artifact_item`：保存制品实际解析到的 Collector revision（采集器修订版本）、
  命令、输出契约、超时和总输出上限；
- `diagnosis_upload_session`：分片直传、断点续传、短期令牌哈希、整体大小和哈希；
- `diagnostic_evidence_bundle`：Diagnostic Evidence Bundle（诊断证据包）元数据、
  父子关系、隔离处理状态、加密元数据、留存、Legal Hold（法务保全）和对象引用；
  - `security_review_status/security_reviewed_by/security_reviewed_at/security_review_note`
    保存拒绝包安全事件的确认/清除状态和审计信息，不保存额外证据正文；
- `diagnosis_processing_job`：Diagnosis Worker（诊断工作进程）的可恢复异步任务；
- `evidence_item`：只追加的 Evidence Item（不可变证据项）及结构化有界预览；
- `offline_signal_collector_mapping`：Online Acquire Tool（在线采集工具）到
  Offline Collector（离线采集器）的版本化运营映射；
- `evidence_assessment`：Mandatory（必收）完整性、可诊断范围和算法快照；
- `diagnosis_run`、`signal_evaluation`、`diagnosis_candidate`：不可变 Run Manifest
  （运行清单）、三态 Signal Evaluation（信号评估）和 KBD Candidate（知识库候选）；
- `supplement_plan`：P0 唯一一次 Supplement Plan（补充采集计划）；
- `diagnosis_report`、`diagnosis_report_revision`：分级报告、审核状态、乐观锁和修改审计；
- `diagnosis_legal_hold_audit`：法务保全设置/双人解除的不可变审计；
- `diagnosis_deletion_job`：对象、结构化证据和临时数据的异步删除清单；
- `diagnosis_management_audit`：管理工作台跨会话读取、转派、任务重试、终止和安全事件
  处置的不可变访问审计；
- 租户级创建幂等唯一约束；
- 工单外键、版本和一次补采检查约束；
- 计划轮次、计划执行顺序和 Trace ID 索引；
- 租户范围已撤销制品部分索引，用于稳定生成签名 Revocation List（吊销清单）；
- 自动维护所有可变离线诊断控制面对象 `updated_at` 的触发器。

Collection Profile（采集画像）复用现有 `dynamic_resource_revision`
（动态资源修订版本）和 `dynamic_resource_active`（动态资源生效指针），不新建重复版本表。
离线诊断权威业务表清单以 `database/desired_schema.sql` 为准；原始大文件正文保存在对象存储适配器中，不进入
PostgreSQL。数据库只保存对象键、SHA-256、安全处理结果、有界结构化预览和审计信息。

### Structured Collector Artifact 1.2 迁移说明

- `collector_artifact.artifact_type` 新记录默认值为 `structured_collector`，`schema_version`
  新记录默认值为 `1.2`，`content_text` 保存签名的 JSON 执行清单，不再保存 Shell 脚本；
- 历史 `1.0/1.1` 制品不做原地改写。制品原始字节已经参与 Ed25519 签名，迁移时修改内容会
  破坏不可变性和审计链；验证包接口会拒绝旧 Shell 制品并要求按原计划重新生成；
- `collector_definition.executor=shell` 暂时保留为 Registry（注册表）的内部兼容枚举，服务端
  发布时将其安全解析成 `command + argv`。它不再表示客户机调用 `/bin/sh`，后续可在独立数据
  迁移中改名，不影响本次无 Shell 交付；
- 本次只改变新记录默认值和字段注释，无需回填历史签名数据。执行 `make db-sync` 后由 Atlas
  （数据库声明式迁移工具）同步默认值和注释。

## 字段兼容性

- 主要为新增类型和新增表；`case.customer_id` 用于正式对象级授权，不以浏览器
  自报租户替代；
- `case_id` 使用 `ON DELETE RESTRICT`，防止删除工单时静默丢失诊断审计链；
- `case` 表由 case-service（工单服务）拥有，诊断服务 ORM 将该外键标记为跨服务
  `use_alter`（延后解析），避免重复注册工单模型引入 ORM 副作用；数据库外键仍由
  `desired_schema.sql` 权威维护；
- P0 的 `tenant_id` 由通过 `INTERNAL_API_TOKEN`（内部接口令牌）验证的服务调用方提供；
  正式客户 API 接入后改由身份提供方签发，不使用浏览器可伪造的 `client_id`；
- `idempotency_key` 在租户范围内唯一；
- `request_hash` 用于拒绝同一幂等键对应不同请求体；
- 初始采集和补充采集分别使用 `plan_sequence=0/1`，数据库约束禁止 P0 出现第三轮采集；
- 计划保存画像 `revision/checksum`，画像后续更新不会改变历史计划；
- 深度采集项通过 `activation_state=deferred`（待激活）保留在初始计划中，不计入首轮容量估算；
- 所有会话记录必须保存非空 `trace_id`。
- `diagnosis_session.assigned_to` 可空，转派时由受信管理身份写入；
- 拒绝包的 `security_review_status` 仅允许 `open/acknowledged/cleared`
  （待处理/已确认/已清除），改变处置状态不会让拒绝包重新进入诊断链路；
- `diagnosis_session.legal_hold` 是会话级保全事实，新 Bundle 自动继承；
- 法务保全解除人不得与最近一次设置人相同，删除服务同时检查会话和 Bundle；
- `diagnosis_run.run_sequence` 和 `collection_plan.plan_sequence` 均限制为初始/补采两轮；
- Signal 缺证据、采集失败、不可读或无离线映射时只能保存为 `UNKNOWN`；
- Collector 定义审批后发布到现有 `dynamic_resource_revision`，制品执行内容以不可变
  revision 为准，不读取可变草稿生成命令；
- `collector_artifact` 在租户范围内约束幂等键，并在同一计划和目标节点范围内保持唯一；
- 制品签名公钥与指纹随元数据保存；公钥指纹须通过可信第二通道核对；
- 撤销只改变制品状态并写入撤销时间、操作者、机器可读原因码和 trace，不删除历史脚本、
  签名或制品项审计快照；存量已撤销记录允许审计字段为空，新撤销必须由服务完整写入。

开发环境：

```bash

```

## Offline Resource Sync（离线资源同步）增量迁移

本次迁移将 Collector（采集器）与 Collection Profile（采集画像）的业务来源统一为已发布
KBD（知识库文档）与 Tool Registry（工具注册表）修订，并新增候选发布、人工回滚和全过程审计：

- `offline_resource_sync_state`（离线资源同步状态）：分别保存 KBD 和 Tool 修订 Watermark
  （同步游标）和最近同步批次；
- `offline_resource_sync_batch`（离线资源同步批次）：保存模式、状态、起止游标、操作者、理由、
  校验摘要、资源计数、失败详情、时间和 `trace_id`（链路追踪标识）；
- `offline_resource_sync_change`（离线资源同步变更）：保存每项 Collector、Signal Mapping
  （信号映射）和 Profile 的 Before/Candidate/After（变更前/候选/变更后）完整快照、
  KBD/Tool 不可变来源修订及 `before_governance_json`（变更前治理快照）；
- `offline_resource_sync_event`（离线资源同步事件）：保存 Preview（预检）、Publish（发布）、
  Reject（驳回）和 Rollback（回滚）的开始与成功/失败事件。`event_sequence`（事件序号）在
  批次内唯一，保证同一时间戳下仍可稳定还原动作顺序。

数据库不存在离线诊断 Collector、Profile 或 Mapping 业务种子，也不通过迁移脚本删除业务数据。
升级完成后须在管理端首次执行 Full Sync（全量同步），审核候选差异后再发布；后续默认使用
Incremental Sync（增量同步）。在线、离线诊断共用 KBD 最终 `category_id`（分类编码）作为问题场景；
所有已发布 KBD 默认参与离线同步，不需要业务种子或离线专属元数据。发布 KBD 缺少最终分类时，
同步批次必须记录错误及 KBD ID，不得静默跳过。

存量数据库若已存在 `offline_resource_sync_event` 但缺少 `event_sequence`，迁移会按
`created_at, id` 回填序号后增加非空及批次内唯一约束。建议验证：

`027_align_qfk_tool_contracts.sql`（027 对齐 QFK 工具契约迁移）会为存量 QFK 的
Tool Registry（工具注册表）参数投影补齐共享权威 Schema 已支持但历史投影缺失的超时、目标主机、
信号语义说明和结构化执行参数。迁移不修改 KBD 或离线业务资源，也不移除已有枚举和风险边界；部署后
Conversation Service（对话服务）启动对账会发布新的不可变 Tool Revision（工具修订），
离线管理员随后执行增量检测即可消费该修订。

```sql
SELECT state_key, last_kbd_revision_id, last_tool_revision_id,
       last_batch_id, lock_version, trace_id
FROM offline_resource_sync_state;

SELECT batch_id, sync_mode, status, base_cursor, target_cursor,
       base_tool_cursor, target_tool_cursor, requested_by, approved_by, rollback_by, trace_id
FROM offline_resource_sync_batch
ORDER BY created_at DESC;

SELECT batch_id, event_sequence, action, result, actor_id, trace_id
FROM offline_resource_sync_event
ORDER BY batch_id, event_sequence;
```

数据库层回滚只应由应用的 Rollback API（回滚接口）完成，禁止删除同步批次、变更、事件或
不可变动态修订。应用回滚只允许最近一次成功发布的批次，恢复生效指针和同步游标，不改写
历史 Collection Plan（采集计划）、Collector Artifact（采集器制品）、Diagnosis Run
（诊断运行）或报告快照。

## 2026-08-04 命令唯一事实源与版本冻结迁移

- 删除 `tool_definition.offline_collection_spec`（工具离线采集规范）。该字段与
  `usage_template`（使用模板）形成了双事实源，且已由不可变 Tool Revision（工具修订）替代；
- 删除 `database/seeds/07_offline_collection_specs.sql`；`03_qkv_qfk_tools.sql` 改为
  `ON CONFLICT DO NOTHING`（冲突时不覆盖），仅用于首次部署的 Tool Capability Bootstrap
  （工具能力引导）；
- `collector_definition` 和 `collection_profile_definition` 新增 `managed_by`（治理归属）与
  `generation_metadata`（生成来源元数据）；存量数据默认按 `manual`（人工治理）处理，不会被误锁定；
- `collection_plan_item` 新增可空的 `collector_revision/collector_version/collector_checksum`。存量计划
  保持可读；新生成和重生成计划必须写入精确修订。Artifact（制品）对存量空值计划仅保留
  Active Revision（生效修订）兼容路径；
- Tool 的 Delete API（删除接口）调整为 Soft Disable（软停用）并发布 disabled revision
  （已停用修订），避免物理删除破坏 KBD → Tool → Collector 审计链。
- KBD 退回草稿、归档或停用复用现有 `dynamic_resource_revision` 表追加
  `status=disabled`、`contract_json.lifecycle.tombstone=true` 的不可变修订，并删除
  `dynamic_resource_active` 中对应 KBD 指针；不新增表或字段。增量同步以该修订的全局 `id`
  推进 Watermark，并根据墓碑保留的离线场景元数据生成下游禁用候选。

## 2026-08-10 P0/P1 容量与历史快照收敛

- `desired_schema.sql` 的 `ck_collector_definition_output_size` 将新写入的
  `collector_definition.max_output_mb`（采集器最大输出）限制为 1～4 MiB；存量超限数据须在
  执行声明式迁移前由环境负责人审查并收敛，不再提交一次性业务数据迁移脚本；
- 新证据包硬上限统一为 512 MiB。`diagnosis_upload_session.total_size_bytes` 数据库约束继续容纳
  历史审计记录，应用 Schema（结构模式）、客户 UI（客户界面）、Go Runtime（Go 运行时）和
  Worker（工作进程）共同拒绝新的超限上传，避免为了收紧新流量而破坏旧记录可读性；
- HCIEB2（第二版 HCI 加密证据包）属于对象内容格式升级，不新增数据库字段；
- `offline_signal_collector_mapping` 新增 `source_kbd_id/source_kbd_revision/source_signal_id` 和
  `execution_contract_checksum`。历史模糊映射保留为空来源字段供审计和回滚，但新 Plan（计划）
  只冻结精确映射；Full Sync 发布新映射后，历史模糊映射不再进入诊断运行；
  `diagnostic_evidence_bundle.encryption_metadata` 保存格式、算法、`key_id`（密钥标识）和分块参数，
  Worker 保留 HCIEB1（第一版 HCI 加密证据包）只读解密兼容；
- Collection Plan（采集计划）的 `kbd_ruleset_snapshot` JSONB（JSON 二进制）现在冻结完整
  KBD Revision（知识库修订）、Signal（信号）、Offline Signal Mapping（离线信号映射）、
  `verification_contract`（验证契约）、生成/发布校验元数据及校验和。无需新增列；旧计划缺失
  完整快照时分析返回 409，必须重建计划和制品，不允许回读当前 KBD 自动补齐。

部署环境由现有 `db-migrate` 声明式迁移流程执行：

1. Atlas 对比 `database/desired_schema.sql`；
2. 创建枚举、表、约束和索引；
3. 应用 `database/desired_extras.sql`；
4. 创建上传、证据包、任务、映射、补采、报告和删除等 `updated_at` 触发器；
5. 幂等注册缺失的 Platform Tool Capability（平台工具能力），不覆盖现有 Tool；
6. Collector（采集器）、Collection Profile（采集画像）和 Signal Mapping（信号映射）
   由管理员发布 KBD + Tool 同步批次生成，不由业务种子直接插入。

## 回滚说明

本变更不提供自动破坏性回滚。尚无业务数据且确认需要回退时，先停止
`diagnosis-service`，完成数据库备份后，再由数据库管理员人工删除触发器、表和枚举。
存在任何诊断会话数据时不得直接删除，应优先通过向前兼容迁移修复。

## Collector Lifecycle（采集器生命周期）增量迁移

本轮生命周期闭环新增 `collection_profile_definition`（采集画像事实表），用于保存草稿、
审批、启停和 `If-Match`（条件更新头）锁版本；批准后仍发布到
`dynamic_resource_revision`（动态资源修订表），运行时不读取可编辑草稿。

`collection_plan`（采集计划）新增：

- `plan_revision`：同一会话和采集轮次内递增的计划修订号；
- `kbd_ruleset_snapshot`：生成计划时使用的完整 KBD 规则集合；
- `kbd_ruleset_checksum`：规则集合的稳定 SHA-256（内容校验和）；
- 唯一约束调整为 `(session_id, plan_sequence, plan_revision)`；
- 部分唯一索引保证同一会话和轮次最多只有一条 `ready`（生效）计划。

Atlas（声明式数据库迁移工具）负责创建表和对齐约束；`desired_extras.sql` 同时提供存量环境
幂等补齐逻辑。Collection Profile（采集画像）不由种子回填；升级后通过 KBD + Tool
Offline Resource Sync（离线资源同步）候选批次建立基线。

迁移后建议执行：

```sql
SELECT profile_id, review_status, is_enabled, lock_version
FROM collection_profile_definition
ORDER BY profile_id;

SELECT session_id, plan_sequence, plan_revision, status,
       jsonb_array_length(kbd_ruleset_snapshot) AS kbd_count,
       kbd_ruleset_checksum
FROM collection_plan
ORDER BY created_at DESC;
```
