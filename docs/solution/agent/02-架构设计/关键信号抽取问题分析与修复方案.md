## 二、根因分析

### 2.1 真正的问题：LLM 抽取参数质量

**问题根因**：LLM 抽取信号时，将状态信息错误地混入关键词参数。

#### 错误的信号配置

\`\`\`json
{
  "acquirer": "qkv_task",
  "acquirer_args": {
    "keyword": "启动虚拟机失败",  // ❌ 错误：把"失败"状态混入关键词
    "limit": 100
  }
}
\`\`\`

#### 正确的信号配置

\`\`\`json
{
  "acquirer": "qkv_task",
  "acquirer_args": {
    "keyword": "启动虚拟机",  // ✅ 关键词只包含动作
    "status": "failed",        // ✅ 状态是单独参数
    "limit": 100
  }
}
\`\`\`

### 2.2 qkv_task 参数说明

| 参数 | 类型 | 说明 | 示例 |
|------|------|------|------|
| \`keyword\` | str | **必须**，关键词搜索 | \`"启动虚拟机"\` |
| \`status\` | str | 可选，状态过滤 | \`"failed"\` / \`"success"\` / \`"running"\` |
| \`limit\` | int | 可选，返回条数限制 | \`100\` |
| \`vm\` | str | 可选，按虚拟机 ID 过滤 | \`"4359974862144"\` |

### 2.3 实际命令格式

\`\`\`bash
# 正确的命令
acli --formatter json task get -k '启动虚拟机' -s failed -l 100

# 返回结果示例
{
  "data": [{
    "vm": "4359974862144",
    "host": "SVR_aCloud_670",
    "target": "Server-IMG",
    "errcode_tracing": "0x0100186F/..."
  }]
}
\`\`\`

### 2.4 之前的错误修复（已回滚）

PR #595 尝试通过参数校验来"修复"问题，但基于错误的理解：

| 错误假设 | 实际情况 |
|----------|----------|
| 认为 \`qkv_task\` 的 \`-k\` 是 vm_id | \`-k\` 就是关键词搜索参数 |
| 将 \`keyword\` 标记为 \`forbidden\` | \`keyword\` 是必须参数 |
| 通过校验拒绝"错误"参数 | 应该改进 LLM 抽取质量 |

**修复结果**：回滚了参数校验代码，保留了日志增强部分。

> **2026-07-23 补充（软校验设计）**：回滚的 PR #595 是"通过校验**拒绝**参数"（硬拒），与本节结论一致——方向错误。但"完全不做校验"也走到另一极端（漏诊静默）。新设计（`../../events/2026-07-23-QKV关键信号关键字分类基线校验设计.md`）明确了边界：
> - **输入容忍**：KBD 口语化/同义词/错别字由 LLM 抽取阶段兜底，**不应对原始输入做硬性校验或拒抽**；
> - **只软校验输出**：对抽取出的 `keyword` 做**软告警**（前端即时高亮 + 后端实时基线模糊匹配产出 `warnings`），**不阻断抽取、不拒绝落库**；
> - **实时基线**：校验读取运行时 `category_repo.get_all_active()`，**不硬编码** 198 类静态词表（基线会随运营持续调整）。
>
> 即：拒参是错的，零校验也错；正确做法是"软校验输出 + 实时基线 + 输入容忍"。前端生产者编辑区（`KbdReviewView.vue`）已实现"类型↔关键字性质"软告警；后端实时基线模糊匹配软校验为待实现项。

## 三、正确的问题解决方案

### 3.1 方案 A：改进 LLM 抽取 Prompt（推荐）

在 \`kbd_extract_signals_v1\` prompt 中增加参数分离示例：

\`\`\`
## 参数分离规则

### qkv_task 参数示例
- 关键词只包含动作本身，不包含状态
- 状态通过 status 参数单独指定

错误示例：
{"keyword": "启动虚拟机失败"}  ❌

正确示例：
{"keyword": "启动虚拟机", "status": "failed"}  ✅
\`\`\`

### 3.2 方案 B：后处理校准（备选）

在信号抽取后增加参数校准逻辑：

\`\`\`python
def _calibrate_signal_args(signal: dict) -> dict:
    """校准信号参数，分离关键词中的状态信息。"""
    args = signal.get("acquirer_args", {})
    keyword = args.get("keyword", "")
    
    # 检测关键词中是否混入状态
    status_keywords = {
        "失败": "failed",
        "成功": "success",
        "运行中": "running",
    }
    
    for cn_status, en_status in status_keywords.items():
        if keyword.endswith(cn_status):
            args["keyword"] = keyword[:-len(cn_status)]
            args["status"] = en_status
            break
    
    return signal
\`\`\`
