# 关键信号抽取问题分析与修复方案

> **文档编号**: KB-SIG-20260721
> **关联工单**: Q2026072154581
> **关联 KBD**: 27123（虚拟机开机失败-镜像忙）
> **创建日期**: 2026-07-21

---

## 一、问题概述

### 1.1 问题现象

工单 Q2026072154581 在执行诊断时未能正确匹配 KBD 27123，导致诊断链路断裂：

- **工单标题**: 虚拟机异常
- **匹配 KBD**: KBD 27123（虚拟机开机失败，报错虚拟机镜像忙）
- **预期行为**: 自动执行信号采集、匹配根因、返回解决方案
- **实际行为**: 信号执行失败，返回空结果，无法完成诊断

### 1.2 影响范围

| 影响维度 | 描述 |
|----------|------|
| **诊断成功率** | 依赖 `qkv_task` + `qfk_system` 组合的 KBD 可能受影响 |
| **变量传递** | 前端信号产出变量无法传递给后端信号 |
| **日志完整性** | 缺少关键链路日志，问题定位困难 |

## 二、根因分析

### 2.1 KBD 27123 signals_json 问题

#### 原始信号定义（问题版本）

```json
[
  {
    "id": "s1",
    "signal_category": "frontend",
    "acquirer": "qkv_task",
    "acquirer_args": {
      "limit": 100,
      "status": "failed",
      "keyword": "启动虚拟机失败"  // ❌ 错误：qkv_task 不支持 keyword 参数
    },
    "produces": [
      {"name": "VM", "path": "vm"},
      {"name": "HOST", "path": "host"},
      {"name": "ERRCODE_TRACING", "path": "errcode_tracing"}
    ],
    "requires": []
  },
  {
    "id": "s2",
    "signal_category": "backend",
    "acquirer": "qfk_system",
    "acquirer_args": {
      "sub_command": "lsof",
      "args": "| grep {{VM}}"
    },
    "requires": ["VM"]  // ❌ 依赖 s1 产出的 VM，但 s1 执行失败
  }
]
```

#### 问题点分析

| 问题 ID | 问题描述 | 根因分析 |
|---------|----------|----------|
| **P0-1** | `acquirer_args.keyword` 参数语义错误 | `qkv_task` 的 `-k` 参数是 `vm_id`，不是关键词搜索。LLM 抽取时生成了语义错误的参数。 |
| **P0-2** | 缺少前置信号获取 VM | 原信号设计假设用户输入或环境上下文已包含 VM 信息，但实际场景中 VM 需要从告警数据中获取。 |
| **P0-3** | 变量传递链断裂 | s1 执行失败后，s2 缺少 `{{VM}}` 变量，导致 `lsof` 命令无过滤条件，返回 67MB 无效数据。 |

### 2.2 实际执行日志分析

```json
// 来自 bridge_execution_logs 表
{
  "event": "exec.done",
  "command": "acli --formatter json task get -k '启动虚拟机失败' -l 100",
  "stdout_len": 17,  // 返回空结果 "[]"
  "success": true,
  "duration_ms": 1200
}

{
  "event": "exec.done",
  "command": "acli system lsof",
  "stdout_len": 70056444,  // 67MB！无过滤条件
  "success": true,
  "duration_ms": 86763    // 执行耗时 87 秒
}
```

**问题**：`acli task get -k '启动虚拟机失败'` 返回空结果，因为 `-k` 参数被误用为关键词搜索，而实际 `acli task get -k` 的 `-k` 参数期望的是虚拟机 ID。

### 2.3 terminal_bridge 日志缺陷

| 缺陷类型 | 描述 | 影响 |
|----------|------|------|
| `trace_id` 缺失 | 大部分日志未携带 trace_id | 无法进行端到端链路追踪 |
| `node_ip` 缺失 | 未记录执行目标节点 | 多节点环境定位困难 |
| 缺少信号匹配日志 | 未记录哪条信号被触发 | 无法追溯信号执行流程 |
| 缺少变量池变更日志 | 未记录变量赋值过程 | 无法追溯参数替换 |

#### 新增校验函数

```python
def _validate_acquirer_args(signal: dict[str, Any]) -> tuple[bool, str | None]:
    """校验 acquirer_args 是否符合采集器参数 Schema。"""
    acquirer = signal.get("acquirer", "")
    if acquirer not in ACQUIRER_ARGS_SCHEMA:
        return True, None

    schema = ACQUIRER_ARGS_SCHEMA[acquirer]
    args = signal.get("acquirer_args") or {}

    # 1. 检查禁止参数
    for key in schema.get("forbidden", []):
        if key in args and args[key]:
            return False, f"acquirer={acquirer} 不支持参数 '{key}'"

    # 2. 检查必填参数
    for key in schema.get("required", []):
        if key not in args or not args[key]:
            return False, f"acquirer={acquirer} 缺少必填参数 '{key}'"

    return True, None


def _validate_signal_dag(signals: list[dict]) -> tuple[bool, str | None]:
    """校验信号依赖关系是否构成有效的 DAG。"""
    produced_vars = set(DEFAULT_VARIABLE_SCHEMA)

    for s in signals:
        for p in s.get("produces") or []:
            name = p.get("name", "")
            if name:
                produced_vars.add(name)

    missing_deps = []
    for s in signals:
        for r in s.get("requires") or []:
            if r not in produced_vars:
                missing_deps.append((s.get("id"), r))

    if missing_deps:
        return False, f"信号依赖链断裂: {missing_deps[:3]}"

    return True, None
```
