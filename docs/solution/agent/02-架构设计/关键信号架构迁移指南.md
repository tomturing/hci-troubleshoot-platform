# 关键信号架构迁移指南

> 版本：v1.0  日期：2026-07-09

## 一、架构升级概述

### 1.1 核心变化

本次重构彻底建立了符合第一性原理的信号架构体系：

**旧架构（已废弃）**：
```
QKVSignal（工具特定命名）  ←→  KeySignal（后端信号专有名词）
```

**新架构（当前）**：
```
KeySignal（抽象基类）
    ├── FrontendSignal（前端信号 - 生产者）
    └── BackendSignal（后端信号 - 消费者）
```

### 1.2 命名映射表

| 旧命名 | 新命名 | 说明 |
|--------|--------|------|
| QKVSignal | FrontendSignal | 前端信号，提取告警/任务元数据 |
| KeySignal（作为后端信号） | BackendSignal | 后端信号，执行健康度判定 |
| - | KeySignal（新增） | 抽象基类，架构总称 |

## 二、代码迁移指南

### 2.1 导入路径变更

**❌ 旧代码（已废弃）**：
```python
# 前端信号
from app.tools.qkv import QKVSignal, QKVQueryType

# 后端信号
from app.tools.qfk import KeySignal, SignalType
```

**✅ 新代码（推荐）**：
```python
# 统一从 signal 模块导入
from app.tools.signal import (
    KeySignal,          # 抽象基类
    FrontendSignal,     # 前端信号
    FrontendQueryType,  # 前端查询类型
    BackendSignal,      # 后端信号
    BackendSignalType,  # 后端信号类型
)
```

### 2.2 信号创建方式

**前端信号（FrontendSignal）**：

```python
# ✅ 新架构
from app.tools.signal import FrontendSignal, FrontendQueryType

signal = FrontendSignal(
    query=FrontendQueryType.ALERT,
    keyword="配置存储服务备节点异常",
    limit=50
)

# 执行
result = await signal.execute(conversation_id)
```

**后端信号（BackendSignal）**：

```python
# ✅ 新架构
from app.tools.signal import BackendSignal, BackendSignalType

signal = BackendSignal(
    signal_type=BackendSignalType.LOG_KEYWORD,
    keyword="log_search",
    target={"scope": "${host}", "resource": "mysql.log"},
    keywords=["file system read-only"]
)

# 渲染模板后执行
rendered_signal = pool.render_backend_signal(signal)
result = await rendered_signal.execute(conversation_id)
```

### 2.3 类型判别机制

**新架构支持自动类型判别**：

```python
from app.tools.signal import KeySignal

# 从字典自动路由到派生类
signal = KeySignal.from_dict({
    "signal_category": "frontend",
    "query": "alert",
    "keyword": "备节点异常",
})
# 返回 FrontendSignal 实例

signal = KeySignal.from_dict({
    "signal_category": "backend",
    "signal_type": "log_keyword",
    "keyword": "test",
    "keywords": ["error"],
})
# 返回 BackendSignal 实例
```

## 三、从 KBD/SOP 提取信号（新功能）

### 3.1 使用信号提取器

```python
from app.tools.signal import SignalExtractor

# 从自然语言文本提取
kbd_text = "检查配置存储服务备节点异常告警，在备节点上检查 mysql-managed.log 是否有只读错误"

signal = SignalExtractor.extract_from_text(kbd_text)

# 自动判别类型
if isinstance(signal, FrontendSignal):
    # 前端信号：提取元数据
    print(f"前端信号，查询类型: {signal.query}")
elif isinstance(signal, BackendSignal):
    # 后端信号：健康度判定
    print(f"后端信号，类型: {signal.signal_type}")
```

### 3.2 批量提取

```python
# 一个 KBD 案例可能包含多个排查步骤
signals = SignalExtractor.extract_batch_from_text(kbd_text)

for signal in signals:
    # 按顺序执行每个信号
    if isinstance(signal, FrontendSignal):
        result = await signal.execute(conversation_id)
        pool.register_from_frontend_result(result)
    else:
        rendered = pool.render_backend_signal(signal)
        result = await rendered.execute(conversation_id)
```

## 四、变量流转机制（生产者-消费者）

### 4.1 变量池使用

```python
from app.tools.signal import VariablePool

# 创建变量池
pool = VariablePool(conversation_id="test-conv")

# 前端信号执行（生产者）
frontend_signal = FrontendSignal(
    query=FrontendQueryType.ALERT,
    keyword="备节点异常"
)
result = await frontend_signal.execute(conversation_id)

# 自动注册变量
pool.register_from_frontend_result(result)
# 变量池现在包含：host, vm, end, alert_type 等

# 后端信号使用变量（消费者）
backend_signal = BackendSignal(
    signal_type=BackendSignalType.LOG_KEYWORD,
    keyword="log_check",
    target={"scope": "${host}"},  # 使用占位符
    keywords=["error"]
)

# 渲染模板
rendered_signal = pool.render_backend_signal(backend_signal)
# target.scope 从 "${host}" 变为实际值（如 "node-001"）

# 执行
result = await rendered_signal.execute(conversation_id)
```

## 五、完整示例：KBD 案例 32090

```python
from app.tools.signal import (
    SignalExtractor,
    VariablePool,
    FrontendSignal,
    BackendSignal,
)

# 1. 从 KBD 文本提取信号
kbd_text = """
案例 32090：配置存储服务备节点数据库副本异常
排查步骤：
1. 检查配置存储服务备节点异常告警
2. 在备节点上检查 mysql-managed.log 是否有 file system read-only 错误
"""

signals = SignalExtractor.extract_batch_from_text(kbd_text)

# 2. 创建变量池
pool = VariablePool(conversation_id="kbd-32090")

# 3. 执行前端信号（生产者）
frontend_signal = signals[0]  # 前端信号
result = await frontend_signal.execute(conversation_id)
pool.register_from_frontend_result(result)

# 4. 执行后端信号（消费者）
backend_signal = signals[1]  # 后端信号
rendered_signal = pool.render_backend_signal(backend_signal)
result = await rendered_signal.execute(conversation_id)

# 5. 输出诊断结果
print(f"诊断结果: {result.matched}")
print(f"证据链: {result.evidence}")
```

## 六、架构优势总结

### 6.1 核心价值

1. **概念统一**：KeySignal 作为架构总称，不再是具体类名
2. **生产者-消费者模式**：明确变量流转方向
3. **自动类型判别**：LLM 提取后自动路由到对应派生类
4. **模板占位符**：优雅声明变量依赖关系

### 6.2 设计原则

1. **单一职责**：基类只定义接口，派生类实现具体逻辑
2. **开闭原则**：新增信号类型只需继承 KeySignal
3. **依赖倒置**：LLM 提取器依赖 KeySignal 抽象，而非具体派生类
4. **模板方法**：基类定义抽象方法，派生类实现细节

## 七、常见问题

### Q1: 为什么不再保留向后兼容？

**A**: 本次重构是架构级变革，不是简单的重命名：
- KeySignal 从"后端信号专有名词"变为"抽象基类"，语义完全改变
- 保留别名会导致同一名称有两种定义，造成概念混淆
- PR 未合入，所有代码都是新的，迁移成本为零

### Q2: 如何从 KBD/SOP 文本提取信号？

**A**: 使用 `SignalExtractor.extract_from_text()` 方法：
```python
signal = SignalExtractor.extract_from_text(kbd_text)
# 自动判别并返回 FrontendSignal 或 BackendSignal 实例
```

### Q3: 后端信号如何使用前端信号提取的变量？

**A**: 使用变量池的模板渲染机制：
```python
# 前端信号执行后
pool.register_from_frontend_result(frontend_result)

# 后端信号使用占位符声明依赖
backend_signal = BackendSignal(
    target={"scope": "${host}"},  # 占位符
    ...
)

# 渲染后执行
rendered_signal = pool.render_backend_signal(backend_signal)
```
