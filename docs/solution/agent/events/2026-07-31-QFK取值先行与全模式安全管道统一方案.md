# QFK 声明式取值与匹配模式统一方案

## 已确认的产品规则

1. 所有 QFK 判断都是“先取值、后判定”。`match.extract` 必填，Matcher 不再直接扫描原始全文。
2. `match.extract` 与 `orchestrate.produces[].extract` 共用同一个 `ValueExtract` Schema、运行时和 Admin 编辑器。
3. 取值方式是“完整输出 / 文本行列 / JSON 路径”；`JSON 路径`属于取值方式，不是 Matcher 类型。
4. Matcher 文案为“匹配模式”。可选 Predicate 为关键字、正则、状态、数值阈值、首末差值、变化趋势、存在性。
5. 文本提取支持多行和多列：行通过关键字或行号选择；列通过表头列名（可显式 aliases）或列号选择。
6. 不保留旧单列 TextExtract、QFK `produces.path`、无 extract 的全文 Matcher 或 `json_path` Matcher。保存和运行时均拒绝这些结构。

## 数据流

```text
完整 stdout/stderr
  → ValueExtract
  → ExtractionResult（原始值、类型化值、records、行号证据）
  → 匹配模式 Predicate 或原子写入变量池
```

提取失败、完整输出缓存不可得、输出过大、表头/列不存在或转换类型失败时均 Fail Closed。命令非零退出时不判定、不写变量。

## ValueExtract

### 文本：行选择、列选择、主值列

```json
{
  "type": "text",
  "source": "stdout",
  "parser": "whitespace_table",
  "header": {
    "mode": "contains",
    "required": ["Filesystem", "Used", "Use%"],
    "case_sensitive": false
  },
  "rows": {
    "mode": "keywords",
    "include": ["/dev/sda3"],
    "exclude": [],
    "include_mode": "all",
    "case_sensitive": true
  },
  "columns": [
    {"key": "USED", "selector": {"by": "header", "name": "Used"}, "value_mode": "string"},
    {"key": "USE_PERCENT", "selector": {"by": "header", "name": "Use%"}, "value_mode": "number"}
  ],
  "value_key": "USE_PERCENT",
  "cardinality": "all"
}
```

`rows.mode` 为 `all`、`keywords` 或 `indices`。行号从 1 开始，且必须声明基准：

- `physical`：物理输出行，含空行和表头；`sed -n` 与 `awk NR` 转换使用它。
- `non_empty`：仅非空行。
- `data`：成功识别表头后才存在的数据行；管理台默认。

每个 `columns[].key` 唯一。多列用于 Matcher 或标量变量时必须明确 `value_key`；其它列进入 evidence/records。`Used=2.6G` 必须保持字符串，`Use%=35%` 可转为数字 `35.0`。`Uesed` 不会被模糊纠正；需要时用 `aliases: ["Used"]` 显式声明。

无列选择的文本 Extract 仍合法，代表“选择整行”。完整输出的安全表示是：

```json
{"type":"text","rows":{"mode":"all"},"cardinality":"all","source":"stdout","value_mode":"string"}
```

### JSON

```json
{
  "type": "json",
  "source": "stdout",
  "path": "data[0].status",
  "cardinality": "exactly_one",
  "value_mode": "string"
}
```

仅接受受控点号路径和数组下标；不执行 jq、过滤器、函数或通配符。

## 匹配模式

- 关键字、正则：在已提取的值上判断。
- 状态：trim/casefold 后做精确相等，不做全文子串匹配。
- 数值阈值：消费已提取的 number；可选 first/last/max/min/sum/line_count/duration_seconds 聚合。
- 首末差值、变化趋势：消费行列 Extract 给出的数值样本。
- 存在性：判断提取结果是否存在。

`object` 必须对应单条 record，`array<object>` 必须使用 `cardinality=all`。多个变量写入先全部提取成功后再提交，禁止部分写入。

## 安全转换管道

管理台只识别并转换受控的 `grep`、字段投影 `awk`、`cut`、`sed -n`；从不执行原命令中的 Shell 管道。转换后保留当前“匹配模式/产出变量”模式，不切换模式。

- 关键字筛选生成 `rows.mode=keywords`。
- `sed -n 'N,Mp'`、`awk 'NR==N {print $C}'` 生成 `basis=physical`。
- 单列和多列都生成 `parser + columns[]`；不再生成 `include`、`column_mode` 或 `column` 顶层旧字段。
- 多个产出变量时，必须先由专家只保留一个明确目标变量；平台不会猜测第一个变量。
- Admin 先展示 command、extract 与 `conversion_id` 的 Preview，只有确认后才改草稿，不保存、不执行命令。

## KBD40061：检查 `/sf/log` 分区磁盘使用率

不要用 `df -h | grep '/sf/log'`。`/sf/log` 可能落在 `/` 挂载点，该行不含 `/sf/log`，会被错误过滤。

在已选择正确执行域后，命令填写：

```bash
df -P /sf/log
```

配置“匹配模式 → 数值阈值”，取值选择“文本行列”：表头必须包含 `Filesystem`、`Use%`；行选择 `indices / data / 1`；列选择表头 `Use%`，类型为数字；阈值如 `>= 80`。需要同时保留容量证据时再增加 `Used` 列（文本类型），并将 `value_key` 选择为 `USE_PERCENT`。

## 验收与发布边界

- Schema、运行时和管理台都拒绝旧 TextExtract 与 QFK `produces.path`。
- 新版的文本、JSON、多行、多列、多记录、别名、类型与原子写入均有定向单测。
- 构建与定向测试通过后，仍须由发布方将历史已存的旧 QFK 配置按新版重新编辑；旧配置不会在保存或运行时静默迁移。
