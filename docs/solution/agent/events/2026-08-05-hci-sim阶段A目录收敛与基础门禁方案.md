# hci-sim 阶段 A：目录收敛与基础门禁方案

## 背景与需求

仓库中 `hci_sim/` 与 `hci-sim/` 是两个实现相同业务目标的 Go module。前者已经进入 CI 镜像、K3s 构建、Helm 和历史 Golden E2E；后者是未接入正式链路的重复 Spike。阶段 A 必须先建立唯一事实源，才能避免阶段 B～E 在错误基线上演进。

需求见 [阶段 A 需求](../../../requirement/events/2026-08-05-hci-sim阶段A目录收敛与基础门禁需求.md)。

## 方案（WHAT）

### 1. 唯一命名模型

| 层级 | 唯一名称 | 说明 |
|---|---|---|
| 源码目录 | `hci_sim/` | 避免与外部资源名混淆，保留现有 import。 |
| Go module | 短期 `hci_sim` | 后续可独立迁移为仓库完整 module path，不与目录清理绑定。 |
| 二进制/镜像 | `hci-sim` | 面向用户和部署的产品名。 |
| Helm/Deployment/Service | `hci-sim` | 继续保持当前对外协议。 |
| Namespace | `hci-sim-{env}` | dev/staging 隔离，prod 默认禁用。 |

### 2. 代码处置矩阵

| 旧 `hci-sim` 内容 | 处置 | 理由 |
|---|---|---|
| 静态密码/accept-any | 删除 | 违反强 Lease 身份。 |
| 可选 Lease env | 删除 | 身份必须在 SSH auth 阶段绑定。 |
| score router | 删除 | 存在默认回退和约束绕过。 |
| 无界 goroutine/10 分钟 sleep | 删除 | 违反有界资源。 |
| raw command 日志 | 删除 | 可能泄密。 |
| README 的本地使用说明 | 迁移并修订 | `hci_sim` 当前缺少开发入口。 |
| 显式 timeout/chunk interval | 仅登记到阶段 B | 需求有价值，实现需重写。 |
| lifecycle/status | 仅登记到阶段 C | 应由 Registry 管理。 |
| 语义 fingerprint | 仅登记到阶段 B | 设计方向正确，parser 不可复用。 |

删除旧目录时只删除该目录本身。PR #652 同时修改的 `terminal_bridge/main.go` 属于独立增量，必须通过 diff 和回归测试保留；其中基于 host substring 的模拟标记问题登记到阶段 B 修复。

### 3. `hci_sim/README.md` 结构

README 固定包含：

1. 职责与非职责；
2. 源码/服务命名规则；
3. 本地 Go/容器运行；
4. Fixture Manifest 和 Lease 示例；
5. 单测、race、vet、build；
6. Terminal Bridge smoke；
7. Helm lint/template；
8. 稳定错误语义；
9. 安全边界；
10. 当前 P0 限制和 A～E 路线图。

README 不得把历史 dev E2E 写成当前在线状态。

### 4. CI 设计

新增独立 `hci-sim-go` job：

```text
checkout
→ setup-go（按 go.mod）
→ go mod download
→ go test -coverprofile
→ go vet
→ go build 两个 cmd
→ manifest lint/drift
→ Helm lint/template
```

`go test -race`：

- 修改 `hci_sim/**`、`terminal_bridge/**`、Manifest/Chart 时在 PR 执行；或
- 若执行时间不可接受，PR 运行关键包，nightly 运行全量；
- race 失败不得被重试掩盖。

门禁同时扫描：

```text
第二个 go.mod 是否出现
accept-any-password 是否出现
HCI_SIM_LEASE_HMAC_KEY 是否可空启动
Fixture 与 Helm 文件是否字节/摘要漂移
正式脚本是否引用 hci-sim/ 源码目录
```

### 5. 基线证据清单

阶段 A 验证报告必须记录：

- Git SHA；
- Go/Helm/Docker 版本；
- `go test/vet/build/race` 输出摘要；
- Helm render 摘要；
- 全仓引用扫描；
- 当前 K8s context 和 hci-sim namespace 状态；
- 当前 KBD 27123 active revision 与静态 Fixture revision；
- 未实现控制面清单。

### 6. 回滚

目录删除应独立 commit。若发现外部未登记构建仍引用旧目录：

1. 回滚目录删除 commit；
2. 不回滚 Terminal Bridge 其他改动；
3. 登记外部消费者；
4. 先迁移消费者再重新删除。

不得为了兼容外部脚本长期保留双实现；最多使用临时、带截止日期的 shim，并且 shim 不包含第二套源码。

## 决策依据（WHY：为什么选此方案，为什么不选其他方案）

### 为什么保留 `hci_sim`

它已经具有强制 Lease、Manifest digest、bounded worker/queue、OTel、metrics、Helm 安全基线和历史真实链路证据。继续在其上加固的迁移风险最低。

### 为什么不保留 `hci-sim`

旧实现默认接受任意密码、Lease 可选、场景可回退、并发无界，并且没有正式部署消费者。保留它需要重写几乎所有生产能力。

### 为什么不机械合并

两者的身份、路由、Fixture 和并发模型互相冲突。机械合并会产生双协议和安全降级；正确方式是保留一个实现，只迁移经过重新设计的需求。

### 为什么阶段 A 不顺便重构 Runtime

目录收敛是可独立验证、易回滚的变更。与大规模 Runtime 重构混在一个 PR 会扩大审查面，也无法确认失败来自清理还是新协议。

## 验收标准

- 唯一源码目录和命名模型无歧义；
- 旧能力处置矩阵逐项关闭；
- CI 覆盖测试、静态检查、构建、race、Manifest 和 Helm；
- 删除旧目录不会删除 Terminal Bridge 独立能力；
- 当前事实基线有实时证据；
- 阶段 B 不再需要处理双实现兼容。
