# KBD 关键信号输入边界泄漏修复方案

## 背景与需求

对 KBD27736“设置集群 IP 失败”的审核发现，拒绝候选 4 和 5 分别生成了删除
`/sf/cfg/if.d/eth0` 配置、进入 `vn-a` 重启 `vn-node-agent-rpc` 的处置动作。它们随后被
`write_signal` 工程门禁拒绝，因此不会成为有效 Signal 或进入自动诊断执行；但拒绝发生在
LLM 已经生成 Candidate 之后，不能说明输入边界正确。

审计当前 `kbd_extract_signals_v2`、KBD27736 数据和生成指纹后确认：

1. `extract_signals_for_kbd()` 不把 `root_cause`、`solution` 正文作为模板变量传入；二者均为
   空字符串，`entry_data` 与 generation fingerprint 也不包含这两个字段。
2. 同一函数却将 `images_json` 的所有图片交给 `_format_image_evidence()`；该函数此前无章节
   白名单，并把每张图的 `section`、`context_before`、`context_after`、OCR 和观察事实传给 LLM。
3. KBD27736 的 `img:3` 明确属于 `solution`：其 `context_before` 是完整解决方案正文，OCR 又包含
   `vn-node-agent-rpc restart`。实际格式化输入未截断，包含删除配置和重启服务的文字。
4. 候选 4 的 evidence 与解决方案正文逐字一致，却错误标注了排查图 `img:2`；候选 5 则直接引用
   `img:3`。现有 `source_section` 只是 LLM 自报枚举，非法值会回退为 `steps_text`，没有验证
   `source_refs` 与实际输入或 evidence 的一致性。

故障的本质不是“根因、解决方案字段被直接 format”，而是**解决方案和潜在根因图片及其自由文本
上下文绕过字段隔离，作为 Evidence IR 间接进入了 LLM 输入**。

## 方案（WHAT）

### 1. 以诊断章节白名单构造图片输入

图片与正文具有相同的信息阶段。关键信号的合法来源只允许：

```text
title / problem_description / alert_info / steps_text
```

`_format_image_evidence()` 只处理 `images_json.section` 位于该白名单的图片；`root_cause`、
`solution`、影响范围、建议等章节以及缺失 section 的历史图片全部 fail closed，不进入 Prompt。

### 2. 图片输入只保留原子观察，不携带自由上下文

即使图片属于诊断章节，`context_before` 和 `context_after` 仍可能跨越章节边界，或包含作者写下的
解释、根因和处置建议。Signal LLM 只接收区域的 `text_lines`、`fields`、`observed_facts` 和质量状态；
不接收 DESCRIPTION、inferences、legacy desc，也不接收截图前后文。

### 3. 将图片溯源和实际输入绑定

同一套已过滤的图片建立 `source_ref -> 原子事实` 索引，并在 KBD Candidate 校验期强制：

- `provenance.source_section` 如存在，必须是诊断章节；
- `provenance.source_refs` 如存在，必须全部指向本轮实际送入 Prompt 的图片区域；
- `provenance.evidence` 如引用图片，必须能在该图片区域的 OCR/fields/observed facts 中逐字找到。

违反任一条件的 Candidate 以 `run_failed` 保留到 `rejected_candidates`，给出明确的溯源越界原因，
而不是将来源伪回退成 `steps_text`。

### 4. 保持既有处置安全门禁

`write_signal` 仍拒绝 KBD 的写操作 Candidate；本修复不降低该门禁，也不让 solution Signal 回到
运行时。输入隔离和输出安全门禁是两层独立防线：前者防标签泄漏和错误诊断，后者防实际变更执行。

## 决策依据（WHY：为什么选此方案，为什么不选其他方案）

### 第一性原理：观察不能依赖答案

Signal 是“在尚未确认根因前可获取、可回放的一项原子观察”。根因和方案属于诊断输出；若用输出
生成输入，会形成标签泄漏和自证循环：系统可由“重启服务”反推出“应重启服务”，却无法证明现场
存在该案例。正确边界必须在 LLM 调用前由结构化数据执行，而不是由模型遵守自然语言约定。

### 为什么不只改 Prompt

当前 Prompt 已写明“根因/解决方案不作为信号来源”，但 KBD27736 仍泄漏。Prompt 是软约束，无法
撤销已拼入上下文的文本，也无法证明模型未使用它；模型、上下文压缩和模板演进都会改变其效果。

### 为什么不只保留写操作拒绝

写操作拒绝只在 Candidate 生成之后执行。它不会阻止模型从方案复制命令、污染 evidence，或把处置
改写成看似只读的诊断动作；也无法防止人工在审核页把错误来源的 Candidate 恢复。输入层白名单
是必要防线，输出门禁是补充防线。

### 为什么删除全部截图前后文

截图附近的正文不是截图的原子可见事实，且没有可靠的同段边界契约。正文诊断信息已经通过四个
明确字段单独输入；保留上下文收益有限，却能跨越图片 section 重新引入答案。默认删除最小化了
攻击面，后续若有需求，应先建立逐字符/逐段的同段定位契约再受控恢复。

## 影响范围

| 范围 | 影响 |
|---|---|
| `backend/kb-service` | KBD Signal Prompt 图片输入改为诊断章节白名单；新增图片 source ref/evidence 强校验 |
| 已有 KBD 数据 | 不修改原文、图片或历史 revision；下次重抽才使用新输入边界，旧结果可按 generation metadata 审计 |
| KBD27736 | 后续重抽不会再向 LLM 送入 solution 的 `img:3`、方案正文或重启命令；被引用的旧候选仍保留历史审计 |
| SOP 抽取 | 不传 KBD `images_json`，不改变现有 SOP 路径 |
| Agent 运行 | 不改变有效 Signal 的执行、Case Verification Contract 或既有 `write_signal` 门禁 |
| 文档与验证 | 新增本方案/任务事件、输入边界避坑条目、回归测试和冷启动状态 |

## 验收标准

1. `root_cause` 和 `solution` 直接字段继续以空值传给 KBD Signal Prompt；
2. root_cause/solution/未知章节的截图、OCR、fields、observed facts、`context_before`、`context_after`
   均不出现在格式化 Prompt；
3. 诊断章节截图仍保留其原子观察事实和稳定 `source_ref`；
4. Candidate 不能引用未进入本轮 Prompt 的图片，且不能用不属于该图片的文字伪造 evidence；
5. 写操作仍以 `write_signal` 拒绝，不进入有效 `signals`；
6. Vision Evidence 与 Signal generation 回归测试通过；
7. 不自动重抽、覆盖或发布任何既有 KBD，KBD27736 的业务结论仍须专家复核。
