# S0 分类 code 契约与漂移自愈方案（Q2026101026818 复盘）

- 日期：2026-10-10
- 背景：staging 工单 Q2026101026818（用户描述"导致跨集群迁移虚拟机失败"），S0 两轮候选均无法给出「虚拟机集群内或跨集群迁移失败」分类，且走 LLM 降级路径（`triage_llm_fallback`，AI 服务 IndexError）。
- 状态：已实施（代码防回归 + staging 数据修复）

## 1. 根因（三层）

1. **数据漂移（直接原因）**：基线 `category_baseline.yaml` 中 `虚拟机-015`~`020`（集群内/跨集群冷热迁移 6 叶）在 staging 库中被删除；其父节点 `虚拟机-L2-虚拟机集群内或跨集群迁移失败`（code 由 path 派生、末段中文）退化为"叶子形态"。
2. **S0 静默过滤**：`TriageAgent._format_categories` / `_deterministic_candidates` 按 `_LEAF_CODE_RE`（`^[一-鿿A-Za-z0-9-]+-\d+$`）硬过滤该节点 → 不进 Prompt、不进候选 → **管理页可见、AI 永不可选**的隐形分类。`_parse_intent_result` 的解析正则同样强制 `-\d+` 结尾，即使模型输出该 code 也会被拒。
3. **LLM 不可用放大**：AI 服务 IndexError 触发确定性兜底，仅 4 个候选槽位且打分为子串匹配（噪声：env 摘要中 sha 命中 "ha" 使 `虚拟机-032` 入选第 4 位）。

同类隐形节点全库共 2 个：`虚拟机-L2-虚拟机集群内或跨集群迁移失败`、`硬件-L3-硬盘离线或不识别`（后者为 `硬件-020~022` 的父节点）。

## 2. 方案决策（对抗性审查记录）

- **否决"中间层 code 改序号式"**：`kbd_entry` 有 62 条记录的 `category_id` 锚定在不合规 code 上（含 `虚拟机-L2-虚拟机集群内或跨集群迁移失败` 本身与 `虚拟机-L3-001` 等），改名/重建会破坏 KBD 引用；且 path 派生 code 保证"同 path 永远同 code"的导入幂等性，序号式会令重导产生新旧节点并存与 parent 关联冲突。
- **采用"双向夹住漂移窗口"**：
  - 消费侧（S0）：不合规 code 的叶子**放行 + 聚合告警**，不静默剔除；解析正则放宽形态、由 `cat_map`（权威分类字典）拒绝未注册 code——`ubu-sus-25.2` 类资源名误识别的防线不变。
  - 导入侧：**叶节点 id** 不合规/重复即 fail-fast 终止导入；域/中间层派生形态仅告警。
  - 数据修复：**基线重导**（`POST /api/kb/categories/import`，upsert、code 不变），补回 015~020、令两个隐形节点回归中间层形态、修复拖拽错位，KBD 引用零破坏。
  - 巡检：新增只读脚本对"E1 隐形分类 / E2 基线漂移 / W1 停用 / W2 path 不一致"做可观测审计，`--strict` 可作门禁。

## 4. 运维指引

```bash
# 巡检（staging 示例）
uv run python scripts/verify/verify_kb_category_tree.py --self-test
uv run python scripts/verify/verify_kb_category_tree.py --database-url "$DATABASE_URL" --strict

# 数据修复（漂移后）：基线重导，先 dry_run 预览再实际导入
curl -X POST "http://<kb-service>:8004/api/kb/categories/import?dry_run=true" \
  -H "Authorization: Bearer $INTERNAL_API_TOKEN" -F "file=@backend/kb-service/config/category_baseline.yaml"
curl -X POST "http://<kb-service>:8004/api/kb/categories/import" \
  -H "Authorization: Bearer $INTERNAL_API_TOKEN" -F "file=@backend/kb-service/config/category_baseline.yaml"
```

注意：
- 重导为 upsert，**不删除**手动创建节点；基线内节点被手工拖拽/改名会被归位（name/path_labels/level 覆盖回基线值，`is_active`/`keywords`/`hit_count` 不触碰）。
- 管理台分类树的手工删除/拖拽是漂移主因：删除基线叶节点会令整族语义从 S0 消失，删除后应执行巡检确认。
