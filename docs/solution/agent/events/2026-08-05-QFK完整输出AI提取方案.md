# QFK 完整输出 AI 提取方案

## 背景与需求

`ValueExtract` 已能确定性地选择完整输出、文本行列或 JSON 路径，但日志中的值常需要
语义定位。例如一行日志同时出现“检测到IP”和“冲突”，专家希望提取该行中的第一个 IP。
把“让 AI 判断关键字是否命中”和“从已经命中的原文中摘值”混在一起，会使故障判定、证据
和变量池都失去确定性。

本方案将 AI 限定为受控的字面量提取器，并使 Matcher 与 `orchestrate.produces` 复用相同
`extract.ai_extract` 契约。

## 方案（WHAT）

`text` 类型的 `ValueExtract` 可选增加：

```json
{
  "type": "text",
  "rows": {"mode": "all"},
  "cardinality": "all",
  "source": "stdout",
  "ai_extract": {"instruction": "提取其中的第一个 IP 地址"}
}
```

运行顺序固定为：

```text
完整 stdout/stderr
  → 确定性 ValueExtract（行/列选择）
  → 确定性 Matcher 命中
  → AI 仅在候选完整行中提取字面量
  → 引用行和提取值逐字回查
  → Matcher evidence 或 produces 变量池
```

- Matcher：只有确定性 Matcher 的真实 `hit` 后才调用 AI；AI 失败则本次 Signal 失败，不能把
  失败隐藏为“未命中”。成功的 `ai_value` 同时进入 QFK 结果、工具事件和面向用户的关键信号
  证据，因此示例最终可见值为 `192.168.100.55`。keyword AND 的 AI 候选必须由同一物理行同时
  包含全部关键字构成；NOT 没有正向候选行，禁止 AI 提取。
- 产出变量：所有声明 AI 提取的变量先完成并通过回查，再与普通确定性变量一起原子写入变量池；
  任一失败，零变量写入。
- AI 强制返回 JSON：`ok`、`value`、`evidence_lines`。引用行号必须属于实际候选，值（或数组中
  每个值）必须逐字存在于所引用的完整行。支持 string/integer/number/boolean/array，拒绝对象
  自由构造。
- 候选超过 200 行或序列化超过 64 KiB 时明确报错，要求专家收紧关键字或行选择；不截断后继续
  提取。调用/JSON/类型/溯源失败均 Fail Closed。
- 管理台在“完整输出”和“文本行列”下展示同一个可选“AI 提取”说明输入；JSON 路径不启用该
  能力。该字段由共享 Signal Schema 校验，旧数据不自动改写。

## 决策依据（WHY：为什么选此方案，为什么不选其他方案）

### 第一性原理：判定与定位是两种不同权力

“是否发生故障”是可重复、可比较的布尔事实，必须由确定性 Matcher 决定；“这一行中的哪一段
是所需值”是受自然语言表达影响的定位工作，AI 在这里有实际收益。让 AI 同时拥有两种权力，
会使同一输出在模型升级、提示词变化或日志注入后产生不同 Signal，无法审计或回归。

### 为什么要求逐字溯源而不信任 AI 的 JSON

JSON 只证明模型说过某个值，不能证明现场输出出现过该值。`evidence_lines` 属于候选集合且值在
引用行中逐字存在，才能把 AI 的结果降格为“受约束的定位索引”。这也阻断日志内提示注入、模型
猜测和跨行拼接凭空写入变量池。

### 为什么两个模式共用同一实现

Matcher evidence 与变量池都是后续诊断的事实输入；若二者使用不同 Prompt、不同候选范围或不同
回查规则，就会出现“页面显示的 Signal”和“下游命令消费的变量”不一致。共享 Schema、候选构造、
AI 调用与 Fail Closed 规则是最小且可验证的一致性边界。

### 不采用的方案

- 不让 AI 直接读全部原始输出：候选范围不可审计，且大输出会放大成本、注入和截断风险。
- 不用正则替代：IP 示例可用正则，但需求是通用的“按语义从已命中日志定位”，不应把每种日志格式
  硬编码为一条规则；AI 仍不能超越字面量回查。
- 不将 AI 结果作为硬门禁豁免：只读、可编译、依赖可达等机器执行契约与提取值无关，仍单独执行。

## 影响范围

| 范围 | 影响 |
|---|---|
| shared Signal Schema | `textExtract.ai_extract.instruction` 成为受限、可保存的可选契约。 |
| Agent QFK runtime | 新增受控提取器；Matcher evidence 可携带 AI 值与物理引用行。 |
| KBD Differential | produces 使用相同提取器，全部成功后原子写变量池。 |
| Admin UI | 完整输出/文本行列显示同一 AI 提取输入与失败边界说明。 |
| API | 现有 KBD 保存接口按 Schema 接受该字段；不新增 REST 端点。 |

## 验收标准

1. 示例日志中“检测到IP”和“冲突”同一行命中时，“提取其中的第一个 IP 地址”只能返回
   `192.168.100.55`，并记录该物理行；
2. AI 给出不存在的值、引用候选外行、非法 JSON、无客户端、超时或候选超限时均失败关闭；
3. AI 不能改变 Matcher 的命中判定，NOT 不发生 AI 提取；
4. 产出变量任一 AI 提取失败时变量池没有部分写入；
5. Signal Schema 漂移检查、Agent/KBD 定向回归和 Admin 构建通过。
