## 三、正则乱码问题

### 问题描述

`intent_agent.py` 和 `triage_agent.py` 中使用字面量汉字字符范围：

```python
# 含乱码风险的写法
confirmed_pattern = re.compile(r'已确认故障分类：([一-龥A-Za-z]+-\d+)\s+([^\n]+)')
candidate_pattern = re.compile(r'[①②]\s*([一-龥A-Za-z]+-\d+)\s+([^\n]+)')
```

`龥`（U+9FA5，CJK 统一汉字区段末字符）在部分编辑器/终端/CI 环境中可能出现乱码，导致正则编译失败或匹配范围错误。

另外，原正则还有两个附加问题：
- 只匹配全角冒号 `：`，LLM 有时输出半角冒号 `:`
- `\d+` 要求纯数字，无法匹配含字母的编号（如 `L2`，虽然 L2 是中间节点，但防御性更好）

### 修复方案

**`triage_agent.py`（生产文件，必须修复）**：

```python
# 修复前
confirmed_pattern = re.compile(r'已确认故障分类：([一-龥A-Za-z]+-\d+)\s+([^\n]+)')
candidate_pattern = re.compile(r'[①②]\s*([一-龥A-Za-z]+-\d+)\s+([^\n]+)')

# 修复后（Unicode 转义 + 兼容半角冒号）
confirmed_pattern = re.compile(
    r'已确认故障分类[：:]\s*([\u4e00-\u9fa5A-Za-z0-9]+-\d+)\s+([^\n]+)'
)
candidate_pattern = re.compile(
    r'[①②③]\s*([\u4e00-\u9fa5A-Za-z0-9]+-\d+)\s+([^\n]+)'
)
```

**`intent_agent.py`（@deprecated 文件，建议同步修复避免混淆）**：

同样替换正则，避免作为参考代码时误导后续开发者。

### 修复对比说明

| 项目 | 旧写法 | 新写法 |
|------|--------|--------|
| 汉字范围 | `[一-龥]`（字面量，乱码风险） | `[\u4e00-\u9fa5]`（Unicode 转义，安全） |
| 冒号兼容 | 仅全角 `：` | `[：:]` 兼容全角和半角 |
| 候选序号 | `[①②]` 仅两个 | `[①②③]` 覆盖三个候选 |
| 空白处理 | 无 | `\s*` 允许冒号后有空格 |
