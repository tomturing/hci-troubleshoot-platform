# Prompt 数据库化管理方案

**日期**：2026-06-01  
**优先级**：P2  
**目标**：将所有 Agent Prompt 从代码硬编码迁移到 `system_prompt` 表，通过 Admin UI 统一管理

---

## 现状

所有 Prompt 以 Python 模块级常量形式硬编码在各 Agent 文件中：

| 文件 | 常量 |
|------|------|
| `triage_agent.py` | `SEGMENT_IDENTITY`, `SEGMENT_METHODOLOGY`, `SEGMENT_REASONING_MODE`, `SEGMENT_S0_CONTEXT`, `SEGMENT_S0_CATEGORIES`, `SEGMENT_CONTEXT_TEMPLATE` |
| `intent_agent.py` | 同上（已 @deprecated） |
| `investigation_agent.py` | 各阶段 Prompt 常量 |
| `remediation_agent.py` | S5 Prompt 常量 |

已有基础设施：`system_prompt` 表已存在，但**零个 Agent 从此表加载 Prompt**。

---

## `system_prompt` 表结构

```sql
CREATE TABLE system_prompt (
    id          SERIAL PRIMARY KEY,
    stage       VARCHAR(10) NOT NULL,  -- S0/S1/S2/S3/S4/S5/S6/BASE
    name        VARCHAR(100) UNIQUE NOT NULL,  -- 唯一标识名
    description TEXT,
    content_template TEXT NOT NULL,    -- 含 {placeholder} 占位符
    version     INTEGER DEFAULT 1,
    is_active   BOOLEAN DEFAULT TRUE,
    created_at  TIMESTAMP DEFAULT NOW(),
    updated_at  TIMESTAMP DEFAULT NOW()
);
```

## Agent 改造方案

### 方案 A：启动时预加载（推荐）

在 `agent-service` 启动时，从 `kb-service` 或直接查询 DB 加载所有 Prompt，缓存在内存中。

```python
# agent-service/app/adapters/agents/htp/triage_agent.py

class TriageAgent(BaseAgent):

    # 内存缓存（启动时加载）
    _prompt_cache: dict[str, str] = {}

    @classmethod
    async def load_prompts(cls, kb_client: KBClient) -> None:
        """启动时调用，预加载所有 S0 Prompt"""
        try:
            prompts = await kb_client.get_system_prompts(stage="S0")
            cls._prompt_cache = {p["name"]: p["content_template"] for p in prompts}
            logger.info(event="prompts_loaded", count=len(cls._prompt_cache))
        except Exception as e:
            logger.warning(event="prompts_load_failed", error=str(e))
            # Fallback：使用代码中的默认值（见下方）

    def _get_prompt(self, name: str, fallback: str) -> str:
        """获取 Prompt，DB 不可用时使用 fallback"""
        return self._prompt_cache.get(name, fallback)
```

```python
# agent-service/app/main.py 启动时调用
@app.on_event("startup")
async def startup():
    await TriageAgent.load_prompts(kb_client=kb_client_instance)
```

### 方案 B：每次请求时按需加载（备选）

每次构建 Prompt 时调用 KB 服务获取，有额外 HTTP 开销，适合低并发场景。

## Fallback 策略

DB 不可用或 Prompt 未找到时，回退到代码中的默认值（保留现有常量作为默认值）：

```python
def _build_s0_prompt(self, ...) -> str:
    identity = self._get_prompt("s0_identity_v1", fallback=SEGMENT_IDENTITY)
    methodology = self._get_prompt("s0_methodology_v1", fallback=SEGMENT_METHODOLOGY)
    reasoning = self._get_prompt("s0_reasoning_mode_v1", fallback=SEGMENT_REASONING_MODE)
    # ...
```

## KB 服务新增接口

```
GET /api/kb/system-prompts?stage=S0
返回：[{"id": 1, "name": "s0_identity_v1", "content_template": "..."}]

PUT /api/kb/system-prompts/{id}
Body：{"content_template": "新内容", "version": 2}
```

---

## Admin UI 管理入口

通过 Admin UI 的 `PUT /api/kb/system-prompts/{id}` 接口：
- 更新 `content_template`：修改 Prompt 内容
- 切换 `is_active`：禁用旧版本，启用新版本
- 查看 `version`：追踪修改历史

---

## 实施顺序

1. **数据库**：执行初始化 SQL，写入现有 Prompt 内容
2. **KB 服务**：新增 `GET/PUT /api/kb/system-prompts` 接口
3. **Agent 服务**：改造 `TriageAgent` 启动预加载逻辑
4. **验证**：通过 Admin UI 修改 Prompt，重启服务后验证生效
5. **扩展**：逐步迁移其他 Agent（InvestigationAgent、RemediationAgent）的 Prompt

| 验收项 | 通过条件 |
|--------|----------|
| DB 正常时 | Agent 使用 DB 中的 Prompt 内容 |
| DB 不可用时 | Agent 降级使用代码默认值，服务正常运行 |
| Admin UI 修改 | 重载后新 Prompt 生效，无需代码发布 |
