# hci-sim 阶段 B：运行时安全与确定性加固方案

## 背景与需求

`hci_sim` 已具备 P0 SSH Runtime，但身份、路由、取消、输出和 shell 路径还没有形成同一强约束执行内核。阶段 B 在不引入 KBD 控制面的前提下，把数据面改造成安全、确定性、可观测、可被阶段 C/D 复用的 Runtime。

需求见 [阶段 B 需求](../../../requirement/events/2026-08-05-hci-sim阶段B运行时安全与确定性加固需求.md)。

## 方案（WHAT）

### 1. 数据面分层

```text
SSH transport
  → Authentication/LeaseContext
  → Channel adapter（exec/shell 统一）
  → Command lexer + Tool Policy
  → RouteKey builder
  → Authorization + expiry/revocation/quota
  → Dispatcher（bounded queue）
  → Fault/Stream executor
  → stdout/stderr/exit-status
  → Audit/OTel/Metrics
  → deterministic cleanup
```

SSH 层只处理协议，不理解 KBD 业务；RouteKey 和 Bundle 是只读输入。

### 2. Manifest v2

建议结构：

```json
{
  "schema_version": "2.0",
  "bundle": {
    "digest": "sha256:...",
    "status": "published",
    "signature": "..."
  },
  "kbd": {
    "support_id": "27123",
    "revision": 24,
    "checksum": "..."
  },
  "contracts": {
    "tool_revision": "...",
    "policy_revision": "..."
  },
  "variables": {},
  "limits": {
    "max_routes": 100,
    "max_output_bytes_per_command": 4194304,
    "max_bundle_bytes": 67108864
  },
  "routes": [
    {
      "id": "sig-002-positive",
      "signal_id": "sig_002",
      "variant": "positive-realistic",
      "route_key": {
        "tool": "qfk_system",
        "acquisition_key": "system:lsof",
        "argv": ["acli", "system", "lsof"],
        "node": "{{NODE}}",
        "container": "host"
      },
      "result": {"exit_code": 0, "stdout": "...", "stderr": ""},
      "stream": {"chunk_bytes": 128, "chunk_interval_ms": 0},
      "fault": {"type": "none", "after_ms": 0}
    }
  ]
}
```

解析采用 `json.Decoder.DisallowUnknownFields` 加显式语义验证。Bundle digest 对 canonical serialization 或发布原始字节计算，选择后必须固定且写入协议规范。

### 3. 命令解析和 RouteKey

禁止使用系统 shell。实现受限 lexer：

- 支持单/双引号和转义的必要子集；
- 拒绝未闭合引号、控制字符、NUL、换行和 shell operators；
- 输出 argv，不做变量展开、glob、substitution 或重定向；
- 使用与生产 QFK/QKV 相同的 Tool Contract 验证参数；
- 规范化可交换 flag、`--key=value` 和 `--key value`；
- 保留位置参数顺序和类型。

最终 RouteKey：

```text
bundle_digest
+ variant
+ scenario_id
+ tool_contract_revision
+ tool/acquisition
+ normalized argv
+ node/container
```

Manifest 加载时建立精确索引并检查冲突。运行时不得使用打分、软匹配或“第一个命中”。需要 regex 的字段必须在受限字段内全匹配，歧义直接拒绝整个 Bundle。

### 4. LeaseContext

Claims v2：

```text
jti, lease_id, test_run_id, scenario_id
support_id, kbd_revision, bundle_digest, variant
virtual_node_id, container, execution_mode
issued_at, not_before, expires_at, run_deadline
max_sessions, max_commands, max_output_bytes
```

验证分两层：

1. 握手：签名、issuer/audience、时间、mode、Bundle、用户名；
2. 每命令：expiry、revocation、Run 状态、context 一致性和原子 quota。

单副本可使用内存 Tracker，但接口抽象为 `LeaseStore`；多副本启用 Redis Lua/CAS，确保 session/command/output 消费原子。短 TTL 是主撤销机制，显式撤销用于取消和安全事件。

### 5. 统一 Channel Adapter

`exec` 直接产生 `CommandRequest`；controlled shell 只负责：

- 提示符；
- 读取一行；
- 识别 Bridge marker；
- 把真实命令转换成相同 `CommandRequest`；
- 等待相同 `CommandResult`。

`command -v acli` 等握手探针也作为显式内建 Route/Policy，不得成为绕过 quota/telemetry 的 if 分支。

### 6. Dispatcher 和取消

`CommandJob` 持有 connection context、deadline 和 cancellation cause。入队、等待、执行、stream 都监听同一个 Context：

```text
enqueue select(queue, ctx.Done)
worker recheck lease/run
fault executor select(timer, ctx.Done)
stream writer select(ctx.Done) + byte budget
defer release session/command/timer/metrics/span
```

队列满立即返回 exit 75/`sim_overloaded`。取消使用稳定错误 `sim_cancelled`，timeout 使用 `sim_timeout`；二者不能混为网络错误。

### 7. Fault Executor

Fault 类型是互斥枚举：

| 类型 | 语义 |
|---|---|
| `none` | 正常输出与 exit。 |
| `nonzero_exit` | 正常 stream 后指定非零 exit。 |
| `permission` | stderr + exit 13/约定码。 |
| `timeout` | 到 deadline 不发送 exit-status，响应取消且不占普通 worker。 |
| `disconnect` | 在指定字节或时间关闭 channel。 |
| `truncate` | 发送有界前缀并给出配置的错误/exit。 |

chunk size 与 interval 分开；所有随机 jitter 必须由 Bundle 固定 seed 和 Run 派生 seed 决定，并记录到 Artifact。

### 8. 输出预算

发布时限制 Bundle；Runtime 再执行防御性上限：

```text
route stdout/stderr ≤ per-command fixture limit
actual streamed bytes ≤ Lease command/run output budget
Bridge raw read/capture ≤ Bridge hard limit
Artifact retention ≤ storage policy
```

超限返回 `sim_output_limit_exceeded`，记录预期/实际字节数和 hash，不把截断内容判为业务 PASS。

### 9. 可观测性

所有路径创建 command Span，包括 policy deny 和 fixture miss。推荐指标：

- `hci_sim_ssh_connections_active/total`
- `hci_sim_commands_total{outcome,error_type}`
- `hci_sim_command_duration_seconds`
- `hci_sim_queue_wait_seconds`
- `hci_sim_queue_depth`
- `hci_sim_lease_reject_total{reason}`
- `hci_sim_fixture_total{outcome}`
- `hci_sim_output_bytes_total{stream}`
- `hci_sim_cancel_total{cause}`
- `hci_sim_bundle_load_total{outcome}`

低基数字段可作 label；run/scenario/fixture 等高基数字段只进入 Trace/Log，不进入 Prometheus label。

### 10. Bridge 收敛

SSHSession 创建时保存权威 `executionMode`。结果标记直接来自认证上下文：

```text
simulation = session.executionMode == sim-ssh
```

删除 `strings.Contains(host, configuredTarget)` 的身份判定；host allowlist 只用于目标授权，必须精确规范化匹配，不负责结果语义。

## 决策依据（WHY：为什么选此方案，为什么不选其他方案）

### 为什么使用精确 RouteKey 而不是 score router

仿真测试最怕错误 Fixture 静默命中。精确索引可以在发布时发现歧义；打分路由会把缺字段、默认候选和顺序变成隐式语义，导致串线难以审计。

### 为什么继续自定义 SSH 而不是 OpenSSH + shell

自定义 SSH Server 能覆盖真实 transport/channel/exit 协议，同时不提供系统 shell 和文件系统执行能力，攻击面和行为面更小。

### 为什么 Lease 每命令复验

SSH connection 可能长于 Lease TTL。只在握手验证会让过期/撤销 capability 继续生效；每命令复验才符合短期授权语义。

### 为什么 timeout 使用独立 fault executor

用长 sleep 占普通 worker 会让故障测试本身制造全局饥饿。timer/fault 路径也必须有界，但不能占用正常执行槽。

### 为什么不在 Runtime 访问 KBD 数据库

数据面应只消费已发布 Bundle。直接查询 KBD 会把发布状态、编辑中数据和数据库可用性耦合到 SSH 命令执行，破坏可复现性和最小权限。

## 验收标准

- RouteKey 强约束和歧义检测通过；
- Lease 过期/撤销/配额在长连接中生效；
- exec/shell 无旁路；
- timeout/cancel/overload/output limit 有稳定语义；
- 所有资源有界且可清理；
- Bridge 模拟标记唯一来源；
- 真实 ssh 模式无回归；
- 阶段 C 可以只依赖 Manifest v2 + Registry 接口，而无需再次改 Runtime 核心协议。
