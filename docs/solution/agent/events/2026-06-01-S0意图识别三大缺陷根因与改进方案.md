## 缺陷一：LLM 命中 L2 中间节点而非叶子节点

### 现象

用户描述虚拟机开机失败 + 告警日志明确，S0 阶段 AI 输出：

```
已确认故障分类：硬件-L2-硬盘 硬盘
```

`硬件-L2-硬盘` 是中间节点（L2 层），并非可操作的叶子分类。

### 根因链

```
category_repo.get_all()
  └─ SQL 无 leaf 过滤，返回所有层级节点
       └─ category_service.get_grouped_by_domain()
            └─ 直接透传给 triage_agent._format_categories()
                 └─ items[:20] 无过滤，L1/L2 中间节点混入 Prompt
                      └─ SEGMENT_REASONING_MODE："若特征明确，直接输出确认分类"
                           └─ LLM 贪心选最顶层匹配 → 命中 L2 中间节点
```

### 改进方案

**（1）数据层：增加叶子节点过滤（`category_repo.py`）**

```python
# 在 get_all() 查询中增加 leaf_only 参数
# 正确做法：用 NOT EXISTS 子查询，不依赖 level 值
# （部分叶子节点 level=2，不能用 level >= 3 过滤）

async def get_all(self, *, leaf_only: bool = False) -> list[KBCategory]:
    query = select(KBCategory).where(KBCategory.is_active == True)
    if leaf_only:
        query = query.where(
            ~exists(
                select(KBCategory.id).where(
                    KBCategory.parent_id == KBCategory.id
                )
            )
        )
    return (await self._session.execute(query)).scalars().all()
```

> ⚠️ 注意：`NOT EXISTS` 子查询需引用正确的别名，实际写法参考下方 SQL。

**正确 SQL（原生写法）**：

```sql
SELECT c.*
FROM kb_category c
WHERE c.is_active = true
  AND NOT EXISTS (
    SELECT 1 FROM kb_category c2 WHERE c2.parent_id = c.id
  )
ORDER BY c.level, c.domain;
```

**（2）`category_service.py` 透传 `leaf_only=True`**

```python
async def get_grouped_by_domain(self, *, leaf_only: bool = True) -> dict[str, list]:
    items = await self._repo.get_all(leaf_only=leaf_only)
    # ... 按 domain 分组逻辑不变
```

**（3）`triage_agent._format_categories()` 增加 code 格式校验（防御层）**

```python
import re as _re
_LEAF_CODE_RE = _re.compile(r'^[^-]+-\d+$')  # 合法叶子节点：前缀-纯数字

def _format_categories(self, categories: dict[str, list[dict]]) -> str:
    lines: list[str] = []
    for domain, items in categories.items():
        valid = [i for i in items if _LEAF_CODE_RE.match(i.get("code", ""))]
        if valid:
            lines.append(f"### {domain}域（{len(valid)}个）")
            for item in valid[:20]:
                lines.append(f"- {item['code']} {item['name']}")
    return "\n".join(lines)
```

**（4）`SEGMENT_REASONING_MODE` Prompt 删除直接确认指令**

删除或修改以下语句：
```
# 删除：「若特征明确，直接输出确认分类」
# 改为：「无论特征是否明确，必须输出候选列表供用户确认」
```

## 缺陷二：S0 未强制用户确认就直接推进 S1

### 现象

AI 输出确认文本后，`process()` 直接 `yield AgentStageUpdate(stage="S1", ...)`，用户没有任何确认交互，页面直接跳转到 S1 诊断阶段。

### 根因链

```python
# triage_agent.py process() 末尾
if result.category_id and not result.needs_confirmation:
    yield AgentStageUpdate(stage="S1", ...)  # ← 直接推进，无用户确认！
elif result.candidates:
    yield AgentInteractiveRequest(...)       # ← 只有多候选才让用户选
```

设计缺陷：将"AI 输出了确认文本"等同于"用户已确认"，跳过了人工确认环节。

### 改进方案

**废除直接确认路径，所有情况统一走 `AgentInteractiveRequest`**：

```python
# process() 末尾，替换原有逻辑
if result.category_id:
    # 单一候选：以确认卡形式呈现，让用户明确确认
    yield AgentInteractiveRequest(
        request_id=f"triage-confirm-{session_id}",
        acp_session_id=session_id,
        kind="intent_selection",
        title="请确认故障分类",
        prompt="根据您的描述，AI 判断故障分类如下，请确认：",
        options=[
            {"optionId": "1", "name": f"{result.category_id} {result.category_name}"},
            {"optionId": "2", "name": "以上不是，重新描述"},
        ],
        custom_input=False,
        metadata={
            "category_id": result.category_id,
            "category_name": result.category_name,
            "single_candidate": True,
        },
    )
elif result.candidates:
    # 多候选：让用户从列表选择
    options = [
        {"optionId": str(i + 1), "name": f"{c['code']} {c['name']}"}
        for i, c in enumerate(result.candidates[:3])
    ]
    options.append({"optionId": str(len(options) + 1), "name": "以上都不是"})
    yield AgentInteractiveRequest(
        request_id=f"triage-{session_id}",
        acp_session_id=session_id,
        kind="intent_selection",
        title="请确认故障分类",
        prompt="请选择最匹配的故障分类",
        options=options,
        custom_input=False,
        metadata={"candidates": result.candidates},
    )
# 兜底逻辑见缺陷三
```

## 缺陷三：解析失败后静默停止（前端卡死）

### 现象

当 AI 输出 `已确认故障分类：硬件-L2-硬盘 硬盘` 时：
- 正则 `[一-龥A-Za-z]+-\d+` 要求 `-` 后接**纯数字**
- `L2` 中 `L` 不是数字，匹配失败
- `IntentResult(category_id=None, candidates=[], needs_confirmation=False)`
- `process()` 三个分支均不满足，无任何 yield，SSE 流结束
- 前端 loading 状态永久挂起

### 根因链

```
LLM 输出非叶子节点 code（如 "硬件-L2-硬盘"）
  └─ confirmed_pattern 匹配失败（\d+ 不匹配 "L2-硬盘"）
       └─ candidate_pattern 也无匹配
            └─ IntentResult 全空
                 └─ process() 末尾无 yield
                      └─ 前端卡死
```

### 改进方案

**（1）修复正则，兼容更多输出格式**

```python
# 旧（有乱码风险 + 不兼容半角冒号）：
confirmed_pattern = re.compile(r'已确认故障分类：([一-龥A-Za-z]+-\d+)\s+([^\n]+)')

# 新（Unicode 转义 + 兼容半角冒号 + 兼容数字编号）：
confirmed_pattern = re.compile(
    r'已确认故障分类[：:]\s*([\u4e00-\u9fa5A-Za-z0-9]+-\d+)\s+([^\n]+)'
)
candidate_pattern = re.compile(
    r'[①②③]\s*([\u4e00-\u9fa5A-Za-z0-9]+-\d+)\s+([^\n]+)'
)
```

**（2）增加解析失败兜底 yield**

```python
# process() 末尾，在所有 if/elif 后添加 else 兜底
else:
    # 解析失败：提示用户重新描述
    yield AgentTextChunk(
        content="\n\n抱歉，暂时无法识别您的故障类型。"
                "请尝试更具体地描述问题现象，例如：'虚拟机无法开机，界面显示XXX错误'。"
    )
    logger.warning(
        event="intent_parse_failed",
        message="S0 意图识别解析失败，无候选也无确认",
        session_id=session_id,
        reply_preview=reply_text[:200],
    )
```

## 验收标准

| 验收项 | 验证方式 | 通过条件 |
|--------|----------|----------|
| 叶子节点过滤 | 查询 `/api/kb/categories?grouped=true` | 返回结果中无 `L1`/`L2` 标记的 code |
| 强制确认卡 | 发送一条明确描述的故障信息 | 前端必须展示确认卡，不能直接跳到 S1 |
| 解析失败兜底 | Mock LLM 返回 `已确认故障分类：硬件-L2-硬盘` | 前端显示"请重新描述"提示，不卡死 |
| 正则兼容 | 单元测试：输入含全角/半角冒号的确认文本 | 两种冒号均能正确提取 code 和 name |
