## 问题根因

LLM 的上下文窗口是其唯一工作内存。当用户点击「继续」后，conversation-service 加载 `message` 表重建历史，但原有设计中 `message` 表只有 `user`/`assistant`/`system`/`command` 文本消息，缺少 ReAct 工具调用轮次（`tool_calls` + `tool_result` 消息对）。

这导致大模型看不到任何工具执行历史，被迫从零推理，重复调用已完成的工具，造成：
1. **效率下降**：已执行的命令被重复执行
2. **资源浪费**：额外的 API 调用消耗
3. **用户体验差**：用户需要手动告知"刚才已经执行过了"

---

## 设计方案

遵循 OpenAI Function Calling 规范和 LangGraph Checkpointer 范式，将工具调用轮次作为一等公民持久化到 `message` 表。

### 数据库 Schema 变更

#### 1. 扩展 `message_role` ENUM

```sql
-- desired_schema.sql 中 ENUM 定义
CREATE TYPE message_role AS ENUM ('user', 'assistant', 'system', 'command', 'tool_call', 'tool_result');

-- tool_call: AI 发起的工具调用请求（content 存储含 tool_calls 的 JSON assistant message）
-- tool_result: 工具执行结果（通过 tool_call_id 关联对应的 tool_call 消息）
```

#### 2. `message` 表新增 `tool_call_id` 字段

```sql
ALTER TABLE message ADD COLUMN tool_call_id text;
COMMENT ON COLUMN message.tool_call_id IS
  'role=tool_result 时填写，关联 role=tool_call 消息中的 tool_call_id（OpenAI format），
   用于在恢复 ReAct 上下文时成对重建工具调用历史';
```

#### 3. 存量环境幂等补齐

`desired_extras.sql` 中包含幂等 ALTER TYPE 语句：

```sql
DO $$ BEGIN
  -- 先检查 message_role 类型是否存在（Atlas apply 后才有）
  IF EXISTS (SELECT 1 FROM pg_type WHERE typname = 'message_role') THEN
    -- 补齐 tool_call 角色
    IF NOT EXISTS (
      SELECT 1 FROM pg_enum
      WHERE enumtypid = 'message_role'::regtype AND enumlabel = 'tool_call'
    ) THEN
      ALTER TYPE message_role ADD VALUE IF NOT EXISTS 'tool_call';
    END IF;
    -- 补齐 tool_result 角色
    IF NOT EXISTS (
      SELECT 1 FROM pg_enum
      WHERE enumtypid = 'message_role'::regtype AND enumlabel = 'tool_result'
    ) THEN
      ALTER TYPE message_role ADD VALUE IF NOT EXISTS 'tool_result';
    END IF;
  END IF;
END $$;
```

### agent-service 实现

#### 1. `ReactEngine` 新增持久化参数

```python
class ReactEngine:
    def __init__(
        self,
        ...
        conversation_service_url: str | None = None,
        internal_token: str | None = None,
    ):
        self.conversation_service_url = conversation_service_url
        self.internal_token = internal_token
```

#### 2. `_persist_tool_turn()` 方法

每次工具执行完毕后，fire-and-forget 调用 conversation-service 的 `/tool-turn` 接口：

```python
async def _persist_tool_turn(
    self,
    conversation_id: UUID,
    tool_call_msg: dict,
    tool_result_msg: dict,
) -> None:
    """持久化工具调用轮次到 message 表（fire-and-forget）"""
    if not self.conversation_service_url:
        return

    async with httpx.AsyncClient() as client:
        await client.post(
            f"{self.conversation_service_url}/api/conversations/{conversation_id}/tool-turn",
            headers={"Authorization": f"Bearer {self.internal_token}"},
            json={
                "tool_call": tool_call_msg,
                "tool_result": tool_result_msg,
            },
        )
```

### conversation-service 实现

#### 1. 新增 `POST /api/conversations/{id}/tool-turn` 接口

```python
@router.post("/{conversation_id}/tool-turn")
async def persist_tool_turn(
    conversation_id: UUID,
    request: ToolTurnRequest,
    ...
):
    """持久化 ReAct 工具调用轮次（内部接口）"""
    # 1. 创建 tool_call 消息
    tool_call_msg = Message(
        conversation_id=conversation_id,
        role=MessageRole.TOOL_CALL,
        content=json.dumps(request.tool_call),
    )
    # 2. 创建 tool_result 消息（关联 tool_call_id）
    tool_result_msg = Message(
        conversation_id=conversation_id,
        role=MessageRole.TOOL_RESULT,
        content=request.tool_result.get("content", ""),
        tool_call_id=request.tool_result.get("tool_call_id"),
    )
    # 3. 持久化
    await repo.create(tool_call_msg)
    await repo.create(tool_result_msg)
```

#### 2. `history_messages` 构建逻辑重写

加载消息时包含 `tool_call`/`tool_result` 角色并正确还原为 OpenAI messages 格式：

```python
# 第一步：分离文本消息和工具消息
text_messages = [m for m in all_messages if m.role.value in ("user", "assistant", "system", "command")]
tool_messages = [m for m in all_messages if m.role.value in ("tool_call", "tool_result")]

# 第二步：文本消息按原有逻辑取最近 MAX_TEXT_MESSAGES 条
selected_text = text_messages[-MAX_TEXT_MESSAGES:]

# 第三步：工具消息重组为 OpenAI messages 格式
# 滑动窗口压缩策略：最近 TOOL_TURN_FULL_WINDOW 步完整保留，更早摘要化
tool_call_messages = [m for m in tool_messages if m.role.value == "tool_call"]
total_tool_steps = len(tool_call_messages)
cutoff_step = total_tool_steps - TOOL_TURN_FULL_WINDOW  # 超过此步骤的工具输出需要摘要化

reconstructed_tool_messages = []
for msg in tool_messages:
    if msg.role.value == "tool_call":
        assistant_msg = json.loads(msg.content)  # tool_call 消息的 content 是 JSON assistant message
        reconstructed_tool_messages.append(assistant_msg)
    elif msg.role.value == "tool_result":
        result_content = msg.content
        # 早期工具输出（步骤 <= cutoff_step）且内容过长时截断为摘要
        if cutoff_step > 0 and tool_step_idx <= cutoff_step and len(result_content) > TOOL_RESULT_SUMMARY_LEN:
            result_content = result_content[:TOOL_RESULT_SUMMARY_LEN] + "…（已截断，详情见工具执行日志）"
        reconstructed_tool_messages.append({
            "role": "tool",
            "tool_call_id": msg.tool_call_id,
            "content": result_content,
        })

# 第四步：将文本消息和工具消息按时间顺序合并
combined_messages = sorted(
    [(m, "text") for m in selected_text] + [(m, "tool") for m in tool_messages],
    key=lambda x: x[0].created_at,
)
```

---

### 滑动窗口压缩策略

| 参数 | 值 | 说明 |
|------|-----|------|
| `MAX_TEXT_MESSAGES` | 50 | 文本消息最多保留条数 |
| `TOOL_TURN_FULL_WINDOW` | 10 | 最近 10 步工具调用完整保留 |
| `TOOL_RESULT_SUMMARY_LEN` | 200 | 早期工具输出截断为 200 字符摘要 |

**设计原因**：
- ReAct 推理链条可能包含数十次工具调用，每次输出可能数千字符
- 若全部保留，token 爆炸会超过 LLM 上下文窗口
- 最近步骤对推理延续最关键，需完整保留
- 早期步骤已收敛，只需摘要供参考
