# HTP Agent 审计日志失效根因与修复方案

**日期**：2026-06-01  
**优先级**：P0  
**涉及文件**：
- `backend/conversation-service/app/services/conversation_service.py`
- `backend/shared/models/audit.py`

---

## 现象

`audit_log` 表中 `audit_type='prompt'` 的记录停止写入，`system_prompt_id` 字段无法关联，prompt 级别的审计追踪完全失效。

---

## 根因分析

### 1. `_write_prompt_audit()` 成了僵尸方法

`conversation_service.py` 第 904 行定义了 `_write_prompt_audit()` 方法，但**全文零次调用**：

```bash
$ grep -n "_write_prompt_audit" backend/conversation-service/app/services/conversation_service.py
904:    async def _write_prompt_audit(self, ...):   # 仅定义，无调用
```

### 2. 迁移到 agent-service 时未同步迁移审计逻辑

重构前（旧路径）：直接调用 `ai_registry` → 在调用前后有 `_write_prompt_audit()` 调用。

重构后（新路径）：改为 HTTP SSE 调用 `self._agent_client.stream()` → 迁移时遗漏了审计调用。

```python
# conversation_service.py 约第 324-450 行（新路径）
async for event in self._agent_client.stream(...):
    # 处理 SSE 事件...
    pass
# ← 此处没有任何 audit 调用
```

### 3. 影响范围

自切换到 `agent-service` HTTP 调用路径以来，所有会话的 prompt 审计记录均未写入，合规审计数据完全缺失。

---

## `AuditLog` 模型结构（`shared/models/audit.py`）

```python
class AuditLog(Base):
    __tablename__ = "audit_log"

    id: int
    conversation_id: str        # 关联会话
    audit_type: str             # "prompt" | "tool" | ...
    payload: dict               # JSONB，完整上下文
    system_prompt_id: int | None  # 关联 system_prompt 表
    trace_id: str | None        # 调用链 ID
    created_at: datetime
```

`payload` 应包含：
```json
{
  "case_id": "...",
  "model": "...",
  "messages": [...],       // 完整消息历史（喂给 Agent 的全量上下文）
  "token_count": 0,
  "stage": "S0",
  "env_context": true
}
```

---

## 修复方案

在 `send_message_stream_only()` 中，`_agent_client.stream()` 调用**结束后**，补充审计写入：

```python
# conversation_service.py send_message_stream_only() 方法内
# 在 async for event in self._agent_client.stream(...): 循环结束后添加：

asyncio.create_task(
    self._write_prompt_audit(
        conversation_id=conversation_id,
        case_id=case_id,
        assistant_type=resolved_assistant_type,
        trace_id=get_current_trace_id(),
        message_count=len(history_messages),
        audit_meta={
            "has_sop": False,
            "kb_chunks_count": 0,
            "kb_top_score": None,
            "context_breakdown": {
                "stage": current_stage,
                "env_context": bool(context_info),
            },
            "total_chars": sum(
                len(m.get("content", "")) for m in history_messages
            ),
        },
        sample_payload=history_messages,  # 完整消息历史
    )
)
```

### 注意事项

1. **使用 `asyncio.create_task()`**：审计写入不应阻塞主流程，失败也不影响用户响应。
2. **`_write_prompt_audit()` 内部需捕获异常**：写入失败只记录 warning，不向上抛出。
3. **`history_messages` 为完整上下文**：包含 system prompt + 所有历史消息，是审计的核心数据。
4. **`trace_id` 关联**：通过 `get_current_trace_id()` 获取当前调用链 ID，确保可追踪。

## 修复后验证

```sql
-- 验证审计记录正常写入
SELECT
    conversation_id,
    audit_type,
    payload->>'stage' AS stage,
    created_at
FROM audit_log
WHERE audit_type = 'prompt'
ORDER BY created_at DESC
LIMIT 10;
```

| 验收项 | 通过条件 |
|--------|----------|
| 审计记录写入 | 每次会话消息后，`audit_log` 新增 `audit_type='prompt'` 记录 |
| payload 完整性 | `payload.messages` 包含完整上下文消息列表 |
| 非阻塞 | 审计写入失败不影响正常响应流程 |
| trace_id 关联 | `audit_log.trace_id` 与请求链路 trace_id 一致 |
