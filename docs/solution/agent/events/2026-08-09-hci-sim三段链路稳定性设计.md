# hci-sim 三段链路稳定性设计

## 第一性原理

一次成功验收必须同时满足四个不变量：

```text
Lease 的签发密钥 = Runtime 的验签密钥
connection.json 的 host/port = Bridge 实际连接的地址
host:port 上监听的 Runtime = 生成该 Lease 的 Runtime
Lease 当前时间 < expires_at
```

任意一个不变量不成立，前端都可能只显示“SSH 握手失败”，因此错误必须在源头被阻断并提供具体证据。

## 设计决策

### 1. 验收脚本生命周期

`two-step-acceptance.sh` 对同一 KBD 停止旧的受管容器；对 SSH/HTTP 端口做预检；bootstrap 输出落在运行目录的 0600 文件；启动后循环检查 `readyz`，失败时打印 inspect/logs 并删除失败容器。脚本不打印 Lease。

默认优先使用 `2222/18080`，被其他实例占用时在隔离范围内自动分配端口；`connection.json` 是端口的唯一权威来源，避免操作者凭记忆填写旧端口。需要严格检测配置的 CI 可设置 `HCI_SIM_AUTO_PORTS=false`。

### 2. host key 生命周期

dev 验收使用主机级稳定 host key，并复制到每一轮运行目录。这样 Windows/Linux Bridge 的 `accept-new` known_hosts 只在首次运行接受，后续 Lease 重签不会改变 SSH 身份。该 key 仅用于 dev 验收，不进入 Git，不用于生产。

### 3. UI 入口

状态 A（无工单、无 SSH）增加“仿真租约连接（dev）”，直接打开已有 `SshConnectDialog` 的 terminal-only 模式；普通“连接 SSH 并创建工单”仍保持真实 HCI 采集语义，不把 synthetic Lease 送入环境采集器。

### 4. Linux 三段链路

dev/K3s 的 Customer UI runtime-config 必须显式设置为 `/terminal-bridge` 或 Linux Bridge 地址。空配置代表桌面兼容模式 `ws://localhost:9999`，在远端 Windows 浏览器场景下会错误指向 Windows 本机。

桌面拓扑则相反：浏览器在 Windows `172.28.24.22` 时，Bridge URL 必须是 `ws://localhost:9999`，由 Windows `terminal_bridge.exe` 再 SSH 到 Linux `172.28.24.21:<connection.port>`。这两个 URL 分别属于“浏览器到 Bridge”与“Bridge 到 hci-sim”两条不同链路，不能互换。

### 5. 可重复验证器

`hci-sim-smoke` 增加 `HCI_SIM_CONNECTION_JSON` 模式：读取本地连接文件，使用真实 WebSocket `ssh_connect`、`ssh_exec_process` 和 `ssh_disconnect`，只输出非敏感摘要。
