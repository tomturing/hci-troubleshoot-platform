# 智能体单步交互与单步命令执行控制方案

> [!IMPORTANT]
> 本方案针对系统当前“排障助手可能会在单次对话中同时输出多个问题（增加用户认知负载）或同时发起多个工具命令执行（增加高危环境运行风险）”的缺陷，提出了基于第一性原理的“单步交互契约（Single-Turn Interaction Contract）”重构设计。
>
> 方案由两部分构成：
> 1. **Prompt 强约束（提问维度限制）**：用于控制大模型的生成策略，使其每次只提问一个问题。由管理员在 Prompt 管理页面手动录入更新。
> 2. **代码硬性卡控（命令维度限制）**：在 ReAct 执行引擎中实施物理拦截，防止大模型并发下发多条 Shell 命令，确保排障操作的原子性与事务安全性。

---

## 一、 第一性原理与设计范式

根据 **人机协作控制理论（Human-Agent Interaction Control）** 与 **分布式系统状态机契约**：

1. **认知负载最小化（Cognitive Load Minimization）**：
   在复杂的 HCI 运维场景中，用户的注意力是稀缺资源。当 Agent 在一个气泡里堆砌 3 个以上跨度极大的问题时，会造成用户理解困难、回复格式混乱，进而破坏大模型的 Context 质量。每次只询问“当前最迫切的一个未知变量”，是保证数据收集准确率的唯一解。
2. **状态变迁原子性与事务化（State Transition Atomicity）**：
   超融合后台的诊断/修复动作多数属于非幂等的有状态命令。大模型并行输出并执行多个命令（如同时检查 IP、检测 SSD 状态和重启服务），会导致系统状态难以追踪。必须实现**“单步执行-结果观测-下一步决策”**的顺序串行循环（Serialized Loop）。
3. **业界最佳实践（LangGraph / CoALA 范式）**：
   - **LangGraph** 的 `Interrupt` 机制：当工作流需要用户输入时，立即挂起（Pause）当前 Graph，只显式抛出一个变量填报要求，直到接收到输入后再推进到下一个 Node。
   - **ReAct 串行卡点**：在涉及环境写操作或敏感读操作时，限制 LLM `tool_calls` 的最大并行度为 1，进行单步阻断。

## 二、 方案设计与实现

### 2.1 Prompt 优化方案（用户手动页面配置）

大模型直接打印多个问题的根源在于现有的系统提示词（如 [base_methodology_v1](file:///aihci/hci-troubleshoot-platform/database/seeds/02_system_prompts.sql#L107)）中，S1 阶段描述为 **“向客户提出 1-3 个精准确认问题”**。大模型会机械式地执行此“1-3”的指令，导致一次性输出多个问题。

#### 优化点 1：方法论模板 (base_methodology_v1)
请在平台“Prompt 管理”页面中，找到 `base_methodology_v1`（或对应的系统方法论配置项），将标准诊断流程中的 S1 和 S3 阶段描述进行如下微调：

* **修改前**：
  ```text
  S1 故障定位：向客户提出 1-3 个精准确认问题，定位到最小故障分类
  S3 验证执行：逐一执行诊断命令，收集系统状态证据
  ```
* **修改后**：
  ```text
  S1 故障定位：每次交互仅向用户提出 1 个最精准的澄清问题。如需收集特定环境参数，优先调用 sop_request_variable 工具获取。严禁在单次回复中罗列多个问题。
  S3 验证执行：每次 Thought 中只允许下发 1 个诊断命令工具调用，待观察到 Tool 输出后再决定下一步动作。严禁并发调用多个命令工具。
  ```

#### 优化点 2：增加系统级交互契约 (在 base_identity_v1 中追加)
为强化控制，建议在 `base_identity_v1`（或系统身份 Prompts）的最下方，追加如下【单步协作契约】：

```text
【单步协作契约（极其重要）】
1. 单步提问原则：无论处于什么诊断阶段，在向用户反馈时，你的发言中最多只能包含 1 个澄清问题或 1 个待确认的变量询问。严禁输出问题列表。
2. 单步工具原则：你在每轮思考中，只能输出 1 个 `tool_calls` 动作。严禁在同一次响应中批量执行多个命令或同时调用多个检索工具。
```

### 2.2 代码硬限制方案（ReAct 引擎串行阻断）

大模型即便有 Prompt 约束，在某些复杂场景下仍有可能绕过约束，一次性发起多个 `tool_calls`（Function Call）。为此，必须在 [ReactEngine.execute](file:///aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/react_engine.py) 代码层构筑物理防线。

#### 1. 限制单轮 Tool Call 并行度为 1
在 `ReactEngine` 执行工具调用循环时，如果大模型返回了多个 `tool_calls`，在进入 `for tc in invoke_result.tool_calls` 循环前，物理截断只保留第一个：

```diff
# backend/agent-service/app/adapters/agents/htp/react_engine.py
# 在将 assistant tool_calls 消息追加到历史之前

-            # 将 assistant tool_calls 消息追加到历史
-            assistant_msg: dict = {
-                "role": "assistant",
-                "content": None,
-                "tool_calls": [
-                    {
-                        "id": tc.id,
-                        "type": "function",
-                        "function": {
-                            "name": tc.name,
-                            "arguments": json.dumps(tc.arguments or {}),
-                        },
-                    }
-                    for tc in invoke_result.tool_calls
-                ],
-            }
+            # 硬限制：每轮交互最多仅允许执行 1 个工具调用，防止 LLM 并发下发多个命令
+            active_calls = invoke_result.tool_calls
+            if len(active_calls) > 1:
+                logger.warning(
+                    event="react_tool_calls_truncated",
+                    message=f"检测到 LLM 一次性发起 {len(active_calls)} 个工具调用，已强制拦截并截断，仅保留第一个执行",
+                    original_tools=[tc.name for tc in active_calls],
+                    session_id=session_id,
+                )
+                active_calls = active_calls[:1]
+
+            # 将处理后的单个 tool_call 消息追加到历史
+            assistant_msg: dict = {
+                "role": "assistant",
+                "content": None,
+                "tool_calls": [
+                    {
+                        "id": tc.id,
+                        "type": "function",
+                        "function": {
+                            "name": tc.name,
+                            "arguments": json.dumps(tc.arguments or {}),
+                        },
+                    }
+                    for tc in active_calls
+                ],
+            }
             work_messages.append(assistant_msg)
```

#### 2. 工具列表控制 (针对 S1 等提问动作的降级)
在 [SopToolExecutor](file:///aihci/hci-troubleshoot-platform/backend/agent-service/app/adapters/agents/htp/sop_tools.py) 执行 `sop_request_variable` 时，如果返回的 `VariableRequestResult` 指明需要用户输入（`needs_input=True`），代码层会抛出挂起中断。

配合 Prompt 限制后，大模型会老老实实通过调用 `sop_request_variable` 单步发出对变量的卡片请求，而不会在自然语言文本中罗列未捕获的常规变量提问。
