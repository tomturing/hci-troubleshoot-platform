# bridge 日志直传：让自动上报不再依赖浏览器

## 变更历史

| 日期 | 版本 | 变更内容 | 关联事件文档 |
|------|------|---------|------------|
| 2026-10-27 | v1.0 | 初版：短期令牌签发/校验、`/api/bridge-logs/direct` 直传端点、bridge 落盘 outbox 与串行上报、前端下发令牌并静默降级 | 无独立任务文档 |

---

## 一、要解决的问题

自动回采链是 `bridge → WebSocket → 浏览器 → 后端`。这条链把"日志能否到云端"押在
一个随机事件上：**标签页是否还活着**。

2026-10-27 现场（Q2026102701197 / 归档 Q2026102700862）的后果很具体：

- 14:37:49 会话被销毁，紧随其后的 `log_collect.session_missing`（唯一铁证，
  含 `active_sessions=0`、`session_keys=[]`）**在云端完全查不到**；
- 日志收集面板自建的 WebSocket 收到 `bridge_log` 直接 return，从不转发；
- 客户机资源枯竭（内存 95%）导致浏览器/外壳频繁抖动，断连窗口越来越长。

结论：**传输载体必须从浏览器换成 bridge 自己**，浏览器只负责"发放一次凭据"。

## 二、方案

```
前端(一次)                 bridge(常驻)                       平台
   │  POST /api/bridge-logs/token  │                             │
   ├───────────────────────────────────────────────────────────► │ 签发短期令牌
   │  WS: bridge_log_token         │                             │
   ├──────────────────────────────►│ 落盘 outbox + 单 worker      │
   │                               ├── POST /api/bridge-logs/direct ─► 落库
   │       （浏览器关闭后仍继续）    │                             │
```

### 1. 令牌（`app/security/bridge_token.py`）

格式 `v1.<base64url(payload)>.<hmac_sha256>`，payload 只承载四个事实：
`cid`（客户身份）、`case`（唯一可写工单）、`ins`（桥实例）、`exp`（过期时间）。

- 有效期默认 12 小时（上限同），覆盖一次完整采集+上传；
- 密钥取 `BRIDGE_LOG_TOKEN_SECRET`，留空回落 `INTERNAL_API_TOKEN`（不新增必填配置）；
- 校验失败一律返回 `None` → 路由统一 401，不区分"签名错/过期/格式错"，避免探测面。

### 2. 两个端点

| 端点 | 鉴权 | 用途 |
|---|---|---|
| `POST /api/bridge-logs/token` | 网关 `require_user` + HMAC 签名（客户身份） | 签发令牌，`case_id` 必须属于该 client |
| `POST /api/bridge-logs/direct` | `X-Bridge-Upload-Token`（**无 Cookie**） | bridge 直传落库 |

直传端点没有"归属校验"，只有"令牌是否允许写这个工单"：
条目自带别的 `case_id`（串用）或别的 `bridge_instance_id`（令牌被复制）一律丢弃并计 `forbidden`。

### 3. bridge 侧（`terminal_bridge/log_uploader.go`）

- 收到 `bridge_log_token` 后 `configure` 并拉起**唯一** worker；
- **串行**发送（`sendMu` 保护"取批→发送→出队"整段），批量 100 条、2 秒一次、gzip；
- 先落盘 `bridge-log-outbox/<instance>.jsonl` 再发送；成功后整批出队；
- 失败整批保留 + 指数退避（1s→60s）；后端按 `event_id` 幂等抵消重复；
- 重启时 `recoverOutbox` 把未发送日志读回队列（上限 5000 条）；
- 无令牌时 `enqueue` 是空操作：旧前端零影响。

### 4. 前端（`chat.ts`）

- `bridge_hello.detail` 带回桥实例号；
- SSH 连接**稳定后**（`markConnected`）申请令牌并通过 WS 下发；
- 任何失败都静默降级为原浏览器回采链路，绝不阻塞 SSH。

## 三、对抗性审查

| 风险 | 结论 / 处理 |
|---|---|
| 令牌泄露 → 伪造该工单日志 | 只写一个工单、绑定实例、写入 `user_id=bridge:<instance>` 可整批甄别 |
| 令牌被复制到另一台桥 | 条目 `bridge_instance_id` 与令牌不一致即丢弃 |
| 平台不可达 | 队列落盘 + 退避重试；outbox 8MB 上限，超限丢最旧并计数 |
| 客户机磁盘被写满 | outbox 目录 0600、字节上限、单实例单文件 |
| 与采集抢资源 | 单 worker、批量 100、gzip、2s 间隔；Atom 级机器可接受 |
| 无令牌/旧平台 | 完全降级为原链路，不报错不阻塞 |
| 密钥轮换导致存量令牌失效 | 401 → 前端下次 `ssh_connect` 重新签发 |

## 四、可观测

- 事件：`log_upload.configured` / `log_upload.token_received` / `log_upload.failed` / `log_upload.recovered`
- `/status` 新增 `log_upload`：`enabled / queued / dropped / instance / outbox`
- 后端日志事件：`bridge_log_token_issued`、`bridge_log_direct_ingest`（含 accepted/duplicates/skipped/forbidden）

## 五、验收

1. 关掉浏览器 10 分钟：`/status.log_upload.enabled=true` 且云端持续有 `log_collect.*` 事件；
2. 拔网 5 分钟：恢复后 `queued` 归零，云端条数与本地文件一致（按 `event_id` 去重后）；
3. 改 `case_id` 直传：返回 `forbidden>0` 且不写库；
4. 过期令牌：401，前端重新签发后恢复；
5. 无令牌：`log_upload.enabled=false`，原有回采不受影响。

## 六、边界（未做）
