# acli 同步恒定 session_missing：未装 acli 的环境为什么从来没被安装

## 一、现场证据（bridge 日志，2026-10-23 16:35）

```
16:35:06.838  ssh.connected            key=Q2026101401684@172.28.24.129
16:35:06.988  bridge.收到消息           type=acli_sync  node=（空）
16:35:06.988  acli_sync.session_missing
16:35:59.136  log_collect.probe         acli_installed=false arch=aarch64 可用 61287MB 日志服务器 200
```

有探测日志（`log_collect.probe`），**没有** `acli_sync.version_check` / `download` / `upload` / `install`
任何一条——说明安装链路根本没启动，不是下载失败。

## 二、第一性原理定位

1. bridge 的 SSH 会话键是 `caseID@nodeIP`（`ssh.connected` 里明确打印 `Q2026101401684@172.28.24.129`）。
2. `sessionKey(caseID, "")` 的实现是「caseID 非空且 nodeIP 为空 → 直接返回 caseID」（不带 `@`）。
3. 旧 `handleAcliSync` 只做两步：`resolveSession(msg)` → `get(sessionKey(msg.CaseID, ""))`。
   而前端 `buildAcliSyncMessage()` **从来没有输出 node_ip**。
4. 于是 `get("Q2026101401684")` 恒定查不到 → `acli_sync.session_missing` → 直接 return。

对照：`log_collect` 早前踩过同一个坑（见 `sessionByNodeIP` / `sessionByAddressHost` 的注释），
已补三层兜底；`acli_sync` 没有，所以只有它一直失败。

## 三、影响

- 「未安装 acli → 自动安装 → 下载 → 上传 → 安装」整条链路**在任何环境都不可达**；
- 面板准备阶段发现未安装 → 弹确认 → 走同一个 `sendAndWait('acli_sync')` → 同样 `session_missing`，
  所以"点确认也没反应"；
- 用户只能手工把安装包传上 HCI 再执行 `--install --force`。

## 四、修复

### 4.1 前端（立即生效，不需要换 bridge exe）

- `AcliSyncOptions` 增加 `nodeIp`，`buildAcliSyncMessage()` 输出 `node_ip`；
- `checkAndSyncAcli()` 用 `sshCurrentConfig.host` 填充（会话主机是唯一真值）；
- 面板 `confirmInstall` 的 `acli_sync` 用已派生的 `nodeIp.value`（与 probe/log_collect 同一锚点）。

bridge 的 `resolveSession` 在 `node_ip` 非空时按 `caseID@nodeIP` 精确匹配，所以**旧 exe 也能工作**。

### 4.2 bridge（兜底，随下一次 exe 发版生效）

新增 `resolveAcliSyncSession`，兜底顺序与 `log_collect` 一致：

```
精确键(caseID@nodeIP) → 按 node_ip 后缀 → 按会话实际地址 → 本工单唯一会话 → 失败
```

`onlySessionForCase` 是"有且仅有一条会话才用"，多条时返回 nil：**宁可不装，也不猜节点**——
装错节点比装不上更糟（会在错误的机器上以 root 执行 `--install --force`）。

## 五、对抗性审查

| 场景 | 结论 |
|---|---|
| 同工单连了两台节点、消息没带 node_ip | 不兜底，报 session_missing（不猜） |
| 消息带了 node_ip 但该节点没会话 | 依次尝试"任意工单下的同 IP 会话"、"会话实际地址"（单用户本地 bridge，无越权） |
| 工单号为空（terminal-global） | `onlySessionForCase` 直接返回 nil，不做全局唯一兜底 |
| 旧前端 + 新 exe | 三层兜底可命中唯一会话，能装上 |
| 新前端 + 旧 exe | `node_ip` 精确匹配，能装上 |
| 消息既无 node_ip、工单又有多条会话 | 明确失败，不静默装错节点 |

## 六、验收

- 前端：`pnpm test` 186 passed（新增「带上 node_ip」用例）、`vue-tsc`、`build` 通过；
- bridge：`TestResolveAcliSyncSessionFallsBackToOnlySession` 覆盖精确命中 / 唯一会话兜底 / 多会话不猜 / 不串工单；
- 现场：刷新前端 → 登录 SSH → 日志应出现
  `acli_sync.version_check` → `acli_sync.download` → `acli_sync.upload` → `acli_sync.install_done`，
  `probe` 随后 `acli_installed=true`。

## 七、仍未解决的风险（不在本次范围）

1. 安装包走 **HTTP 明文** 且**无 sha256/签名校验**，下载后直接 `chmod 0755` + `--install --force` 在集群所有节点以 root 执行；
2. `acli_sync` 无"仅检查"模式，SSH 登录后的自动同步会**直接改动集群**，没有确认；
3. 下载发生在 bridge（客户 PC），要求 PC 能访问 `acli.sangfor.com.cn:1110`，且无备用下载源入口。

建议后续：加 HTTPS/校验和、加 `check_only` 模式 + 首次安装确认、下载源可配。
