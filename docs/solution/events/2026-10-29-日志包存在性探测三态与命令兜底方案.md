# 日志包存在性判定：命令兜底 + 三态结论 + 错误码透传

## 变更历史

| 日期 | 版本 | 变更内容 | 关联事件文档 |
|------|------|---------|------------|
| 2026-10-29 | v1.0 | 初版：Q2026102900165 现场根因修复 | 2026-10-28-日志包存在性判定可观测性方案.md |

## 背景与需求

工单 Q2026102900165（2026-10-29）现场：客户节点上 `/sf/data/local/acli/tmp/data/log_collect/Q2026102900165.zip` 明明存在（29,900,423 字节，`acli log_collect progress` 报「收集任务已完成！」），客户 UI 却报：

> 压缩包已不在节点上（P1 发送成功后插件会自动删除），无法补交付；如需产物请重新采集

上一轮（2026-10-28）修的是「桥内部有结论、但字段没下发」；这一次是**桥的结论本身就是错的**。

## 现场证据链（平台库 + 节点终端）

| 时间（UTC） | 事件 | 事实 |
|---|---|---|
| 02:42:02 | `log_collect.stat` | `exit_code=127`、`error="Process exited with status 127"`、`size=0`、耗时 10ms |
| 02:51:08 | 任务终态 | `status=failed`、`error_code` 空、`error_message` 为前端那句红字 |
| 03:38:50 | 补交付再次 `stat` | 同样 `exit_code=127`；任务 `delivery_status=failed` |
| 03:44–04:18 | `log_collect.progress` | `archive_size=29900423`、`archive_exists=true`、`archive_probe_source=plugin`、diag 为空 |

两条结论：

1. **`stat` 在这条链路上从未成功过**：`exit 127` = command not found。aSV 受限 shell（`Sanfor: aSV/host-xxx /sf #`，vtpsh）的命令白名单里没有 `stat`，但有 `ls`——同一时刻 progress 用量条 `ls -l` 拿到了 29,900,423。
2. **平台把「测不到」翻译成了「不存在」**：`case "stat"` 只有单条 `stat -c %s`，失败即 `exists=false`，且 `Status` 恒为 `"ok"`，真诊断（stderr / exit 127）只进了 `Message` 之外的旁路，平台与界面都看不到。

同一缺陷还有三个孪生调用点，只是此前没被现场触发：

- `probeLogCollectArchiveSize`（progress 探测）：虽有 `stat → ls -l` 兜底，但兜底成功时 `return size, true, ""`，**把 `stat:exit=127` 的 diag 清空**，事后无法证明 stat 从来没工作过。
- `deliveryRunner.prepareDirect`：补交付作业里再 `stat` 一次，同样 127 → 「源包不可读」。
- `verifyArchiveComplete`：用 `tail | od | tr | grep` 校验 zip EOCD，受限 shell 可能整条链都不可用，会被误报成「压缩包不完整」。

## 方案概述 (WHAT)

四处改动，核心是把「探测失败」与「确认不存在」彻底分开：

1. **桥侧三态探测**（`terminal_bridge/log_collect.go`）：新增 `archiveProbe{Size, Exists *bool, Level, Diag}` 与纯函数 `decideArchiveProbe`，`stat -c %s` 失败后走 `ls -l`，只有「命令确实执行且明确报 no such file」才允许 `Exists=false`。
2. **`stat` 动作改造**：复用同一探测；`Exists=nil` 时返回 `Status:"error"` + 新错误码 `LC-TRANSFER-006`，并带出逐级诊断；`Exists=false` 仍返回 `LC-TRANSFER-001`（补交付的合法结论）。
3. **交付作业加固**（`terminal_bridge/delivery_runner.go`）：`prepareDirect` 复用三态探测；`verifyArchiveComplete` 区分「校验命令不可用」（降级放行并 WARN）与「包不完整」；`buildPullCommand` 在 `offset==0` 时改用 `cat`（与 `tail -c +1` 逐字节等价）。
4. **前端单判据出口**（`logCollectSync.ts` + `LogCollectPanel.vue`）：新增纯函数 `interpretArchiveProbe`，`runP2` / 「上传到平台」/ `fallbackToP2` 全部走同一个 `probeArchiveOnNode`，只有 `exists === false` 才允许说「已不在」。

## 详细设计

### 三态探测的判据顺序

`decideArchiveProbe(stat, ls)` 的顺序经过对抗性审查，任一步都不允许「用推测替代证据」：

| 顺序 | 条件 | 结论 | Level |
|---|---|---|---|
| 1 | `stat` 成功且大小可解析 | 存在 | `stat` |
| 2 | `ls` 成功 | 存在（大小可能未知） | `ls` |
| 3 | `stat` 成功但大小解析不出 | 存在 | `stat` |
| 4 | 某级**确实执行**且明确报 no such file | 不存在 | `missing` |
| 5 | 其余（126/127、权限、通道异常） | **无法确认**（`nil`） | `none` |

第 4 步的「确实执行」由 `saidMissingBy` 强制：`exit 126/127` 或 stderr 命中 `command not found` 的那一级**没有资格**给出 missing 结论。少了这条约束，`not found` 会再次被读成「文件不在了」——那正是本缺陷的原始形态。

### 诊断保留

`Diag` 记录每一级失败（`stat:exit=127 stat: not found | ls:ok`），并在三种通道落库：

- `log_collect.progress` 事件新增 `archive_probe_level`，`archive_probe_diag` 在兜底成功时**不再清空**；
- `log_collect.stat` 事件带 `probe_level` / `probe_diag` / `status` / `error_code`；
- WS `stat` 回包 `log_data.probe_diag`，界面直接可用。

### 错误码

| 码 | 语义 | owner | retryable | 界面行为 |
|---|---|---|---|---|
| `LC-TRANSFER-001` | 确认压缩包不存在 | customer | manual | 说「已不在」，指向重新采集 |
| `LC-TRANSFER-006`（新增） | 探测失败，无法确认 | customer | true | 说「无法确认」并展示节点诊断，不做重采引导 |

新增码同步写入 `backend/shared/resolution/catalogs/log_collect_error_catalog.json`（单一真源），`log_collect_errors_test.go` 强校验两侧一致。

### 前端判据收拢

`interpretArchiveProbe(reply)` 是唯一把回包翻译成结论的地方，返回 `{ size, exists, failure }`：

- `status === 'error'` → `failure`，`exists = null`（优先于存在性判据，避免拿缺省值猜）；
- `exists === false` → `failure`（文案保留原句）；
- 其余 → 可继续交付。

`probeArchiveOnNode` 只负责发消息、把 `failure.errorCode` 写入 `lastNodeErrorCode`、抛出 `failure.message`。`runP2` 与「上传到平台」不再各写一套判断。

### 交付作业的两处加固

- `prepareDirect`：`Exists=nil` 返回普通错误（可重试）；`Exists=false` 返回 `deliveryFatalError`（重试无意义）；`Size<=0` 报「大小无法确认」。不再出现「源包不可读（…）：Process exited with status 127」。
- `verifyArchiveComplete`：`exit 126/127`、stderr 报 not found、或 exitCode<0（通道异常）→ 返回哨兵 `errArchiveCompleteUnverifiable`，由 `prepareDirect` 记 WARN 后放行；只有命令真跑通且 `grep -c` 未命中（`exit 1`）才判「包不完整」。

## 决策依据 (WHY)

| 方案 | 优点 | 缺点 | 评分 |
|---|---|---|---|
| A：桥侧两级探测 + 三态 + 新错误码（选中） | 结论有物理证据，未知不再伪装已知；诊断可回溯 | 桥与前端需同步升级才能完全生效 | ★★★★★ |
| B：只在前端遇到 `status=error` 时改文案 | 改动最小 | 桥仍报 `Status=ok`，前端无从判断；交付作业里的 `prepareDirect` 仍 127 | ★☆☆☆☆ |
| C：`stat` 失败时直接当「存在」放行 | 用户立即能点上传 | 包真被删时会拉包失败再挂一次，用错误换便利 | ★☆☆☆☆ |
| D：桥内改用 `ls -l` 单命令替代 `stat` | 少一次往返 | `ls -l` 输出格式随 locale/busybox 变化，且丢失 stat 的精确大小；两级都保留才能既正确又省时 | ★★★☆☆ |

选择 A 的第一性原理：**存在性是一个物理事实，结论只能来自「命令真的读过盘」**。`stat` 与 `ls` 只是两种读法，`stat` 不存在不代表文件不存在；而「读不到」与「读到了、没有」必须表达为不同结论。界面只能表达「已知」与「未知」，把未知伪装成已知的代价，是把用户推向一次注定白跑的重新采集（本单重采只会把旧包 `mv` 进 `log_collect/archive/`）。

### 权衡与妥协

- 保留 `stat` 优先：GNU 节点上仍是一次往返拿到精确大小，`ls` 只在失败后触发。
- `buildPullCommand` 只在 `offset==0` 用 `cat`：续传仍依赖 `tail -c +N`（无等价替代），风险写进下节。
- 不新增桥版本协商字段：前端对 `exists === undefined` 一律按「未知」处理，旧桥行为不会倒退。

### API 兼容性

- WS `log_collect_result(stat)`：`log_data` 只增 `probe_level` / `probe_diag`；`exists` 语义由「bool」扩展为「bool / null」，与既有指针模型一致。
- `Status` 取值不变（`ok` / `error`），但探测失败现在真的返回 `error`——旧前端会走 `statResult.status !== 'ok'` 分支，这正是原本就该生效的死代码。
- 错误码只增不改，旧前端忽略未知码不影响主流程。

## 风险与缓解

| 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|
| 受限 shell 连 `ls -l` 也没有 | 仍无法确认 | 低 | 结论为「无法确认」+ 完整诊断，界面不再谎报「已删除」 |
| 续传路径依赖 `tail -c +N` | 断点续传在无 tail 节点失败 | 中 | 首次交付已走 `cat`；失败时错误信息可读，可清理本地副本重试 |
| `ls -l` 输出被 locale 改写 | 大小解析不出 | 低 | 解析失败时仍判「存在」、大小为 0，由前端按「大小未知」提示 |
| 旧桥（无 `probe_diag`）继续使用 | 诊断缺失 | 中 | 三态与错误码仍是新桥能力；前端对旧桥保持「未确认」不再误判 |

## 测试策略

Go（`terminal_bridge/log_collect_probe_test.go`，新增）：

- `stat` 127 + `ls` 成功 → `Level=ls`、`Exists=true`、`Diag` 含 `stat:exit=127`（兜底保留诊断）；
- 两级都 127 → `Exists=nil`（不得判 missing）；
- 命令不可用但文本像 `not exist` → 仍为 `nil`（`unavailable` 压过 `saidMissing`）；
- 两级明确 `No such file` → `Exists=false` 且 `Level=missing`；
- 0 字节包 → `Exists=true`；
- 无会话 / 空路径 → `nil` + 诊断。

Go（既有用例更新）：`buildPullCommand` 的 `offset==0` 期望 `cat `；引号回放用例同步。

前端（`logCollectSync.spec.ts`）：

- `LC-TRANSFER-006` → 文案含「无法确认」且**不含**「压缩包已不在节点上」；
- `LC-TRANSFER-001` → 才允许「已不在 + 重新采集」；
- 旧桥只回 `size` → `exists=null`、可继续交付；
- 空回包 / 缺 `log_data` → `null`，不判 `false`。
