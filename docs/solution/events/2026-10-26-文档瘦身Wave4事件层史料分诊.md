# 文档瘦身 Wave 4：事件层史料分诊与被证伪断言的订正

> 本文承接 Wave 3 留下的最后一项未决事项（W3-4）。Wave 3 把**现行层**失效引用清零并升为
> 阻断级门禁（见 [2026-10-26-文档瘦身Wave3现行文档准确性治理](2026-10-26-文档瘦身Wave3现行文档准确性治理.md)），
> 事件层的 527 条存量当时明确「另立方案」。本文就是那个方案，也是它的执行记录。
> 口径已写入 [文档管理规范](../../文档管理规范.md) **§8.3.2**，后续 Wave 不得重新评估。

## 背景与需求

Wave 3 收口时的分层实测：

| 层 | 条数 | 门禁行为 | 治理状态 |
|---|---|---|---|
| 现行全量文档 | **0** | 一律阻断（`--current-blocking`） | Wave 3 完成 |
| 事件文档（`*/events/`） | **527** | 仅阻断本次改动行 | **本文处理**（订正后 519） |
| 归档文档（`docs/archive/`） | 58 | 仅阻断本次改动行 | 只读冻结 |

需求来自一条用户裁定：**事件层「保留不动，仅证伪处订正」**——即不追求数字下降，
只把被实测证伪的事实断言按 §8.3.1 订正并留痕。

## 决策（WHY）

三个候选口径里只选第三个：

| 候选 | 内容 | 否决理由 |
|---|---|---|
| A 清零 527 条 | 全部改成现行有效路径 | **伪造历史**（§8.3 明文禁止）。事件文档的读者不照它行动，改它没有收益，只有失真风险 |
| B 只写口径、不动内容 | 规范里加一段说明 | 会漏掉真正危险的东西：527 条里混着少量**当天就写错**的断言，留着就是错地图 |
| **C 分诊 + 只订正被证伪者**（选定） | 用 git 判据把 527 条分档，只订正「既成事实口吻 + 能给出实测正确值」的少数 | 既保住史料，又消除错地图；代价是必须先建一把可复核的尺子 |

判据只有一条，来自 §8.3.1：**一条断言只有在有实测证据把它证伪时才可订正**。
「路径今天不存在」不是证伪——它可能在写下的那天是存在的。

## 方法：四档分诊（全部可复核）

基准集合取自 git，不靠人眼：

```bash
git rev-list --all --objects      # 31,084 个对象，覆盖所有可达历史的全部路径名
git log --all --reflog --oneline -- <path>   # 再扩到不可达历史，排除误判
```

| 档 | 判据 | 条数 | 处置 |
|---|---|---|---|
| ① 正常老化 | 目标**完整路径**曾在历史中出现 | **185** | 保留：写时为真，后来才失效 |
| ② 写法示例 | 目标含 `...`、通配符或无扩展名 | **24** | 保留：不构成路径断言 |
| ③ 链接不准 | 完整路径无匹配，但剥离 `YYYY-MM-DD-`、`NN_`、`NN-`、`T-` 前缀后文件名有匹配 | **283** | 保留：意图与目标都真实，只是路径写法随目录重构失效 |
| ④ 真幽灵 | 剥离全部前缀后，该文件名在**任何路径、任何历史提交**中都不存在 | **35** | 逐条人工定性 |

①+②+③+④ = 185+24+283+35 = **527** ✓（与门禁扫描的总数逐条对得上）

第 ④ 档 35 条的定性结果：**27 条保留 + 8 条订正**。保留的 27 条全部是**合法计划**——
原句带「（新建）」「（待创建）」「（如有）」「或对应组件」或未勾选的 `- [ ]`，
断言的是未来，永不可被证伪（例：`docs/task/agent/events/2026-05-15-pydantic-ai-C大脑实现任务分解.md`
§6 完成标准里的单测文件名，写文档时该大脑尚未实现，属验收判据而非既成事实）。

### 判据自身的四类假阳性（必须先排掉再动笔）

第一版判据只剥日期前缀，把 `05_AI助手层设计.md`（真实存在过）误分成幽灵——
这是本次唯一一次**尺子出错**，补剥 `NN_`/`T-` 前缀后重跑，④ 档从 42 条收敛到 35 条。
其余三类假阳性同样在人工定性阶段排掉：

- **外部仓库路径**：DSH 上游仓的 `docs/subsystems/web-server.md`（本仓不存在，属正常）
- **未跟踪的工作区文件**：本地 rm 过但从未 `git add`，git 无法反证
- **「PR 内新增后未合并」**：`docs/solution/events/2026-06-14-平台内置硬编码治理审计.md`
  第 56 行点名的回滚脚本本就不该进 main 历史，原文自陈「未合并」，自洽 → 保留
