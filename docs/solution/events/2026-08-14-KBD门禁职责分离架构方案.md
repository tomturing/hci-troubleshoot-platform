# KBD 门禁职责分离架构方案

**日期**: 2026-08-14
**关联**: PR #755、PR #757、fix/kbd-23821-sim-delta-ai-channel
**标签**: agent:gemini, env:dev:sf

---

## 背景与需求

KBD 23821（虚拟机-015 集群内热迁移失败）仿真测试持续报「证据不足」，历经
PR #743/#746/#749/#754/#755/#757 均未根治。

错误信息：`expert publish tool contract revision is stale`

命中路径：`shared/cdd/plan_compiler.py` L188-189 字节哈希硬比对
→ `compile_errors` → `NOT_EXECUTABLE` → `INCONCLUSIVE` → 「证据不足」

---

## 根因：双重门禁职责重叠（REDUNDANCY-2）

PR #755 确立了「校验器驱动」ADR：`playbooks.py` 的
`validate_publishable_signals_json` 是语义门禁唯一真相源，
`tool_contract_revision` 字节哈希**仅作变化探测，不阻断执行**。

但 `plan_compiler.py`（shared/cdd，被 agent-service 消费）未同步对齐，
仍保留字节哈希硬比对，形成双重门禁：

| 位置 | 逻辑 | 修复前状态 |
|---|---|---|
| `playbooks.py` Gate-1 | `validate_publishable_signals_json`（语义校验） | ✅ 正确 |
| `plan_compiler.py` Gate-2 | `tool_contract_revision` 字节哈希 | ❌ 与 #755 矛盾，REDUNDANCY-2 |

历次 PR 只修了 Gate-1 侧或其他路径，Gate-2 始终未触及。

---

## 方案（WHAT）

**门禁职责分离**，对齐 Kubernetes Admission Control 范式：

```
Gate-1（kb-service/playbooks.py）         Gate-2（shared/cdd/plan_compiler.py）
┌──────────────────────────────┐          ┌────────────────────────────────────┐
│ 语义门禁（Breaking Change）   │          │ 结构性门禁（信号图完整性）           │
│ validate_publishable_        │          │ ✅ publish_validation.status 检查   │
│ signals_json()               │          │ ✅ generation.status stale 检查     │
│ → executable=true/false      │          │ ❌ 字节哈希比对 → 移除              │
│ ← 已正确，不变 ✅            │          │                                    │
└──────────────────────────────┘          └────────────────────────────────────┘
```

**修改文件**：`backend/shared/cdd/plan_compiler.py`

1. 移除 `from shared.schemas.signal_generation import current_tool_contract_revision` 导入
2. 移除 `publish_validation` 分支的字节哈希硬比对（原 L188-189）
3. 移除 `generation` 分支的字节哈希硬比对（原 L193-194）
4. 保留：`publish_validation.status != "passed"` 检查（publish 流程完整性）
5. 保留：`generation.status == "stale"` 检查（显式标记，非哈希比对）

## 决策依据（WHY）

### 为什么不只保留一个门禁？

**只保留 Gate-1** 的风险：
- `diagnosis-service` 离线分析路径直接调 `shared.cdd`，绕过 playbooks API
- Agent 长连接 Session 存在 KBD 版本漂移时间窗口
- 违反 Defense in Depth 原则

**只保留 Gate-2** 的风险：
- 丧失 API `executable` 可见性（UI/调用方无法提前感知）
- plan_compiler（编译器）不应承担 schema 语义校验职责（单一职责原则）

### 为什么两层职责不重叠是最优解？

对齐业界范式：

| 范式 | Gate-1 | Gate-2 |
|---|---|---|
| **Kubernetes** | API Server Validating Webhook（策略/语义） | Kubelet 资源限制（结构执行） |
| **Google Zanzibar** | API 网关粗粒度鉴权 | 业务层细粒度资源检查 |
| **本系统** | `playbooks.py` 语义/Breaking-Change 检测 | `plan_compiler.py` 信号图结构完整性 |

两层共享同一个 `backend/shared/` 库，无需改变引用关系，只需修正 plan_compiler 调用的函数。

### 为什么不让 kb-service 引用 agent-service shared 库的门禁？

两者已共享同一个 `backend/shared/` 库，问题不是引用关系，
而是 plan_compiler **使用了错误的函数**（字节哈希）做了 Gate-1 应负责的事。
