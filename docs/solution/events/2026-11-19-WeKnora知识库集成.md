# WeKnora 知识库集成方案

需求文档：[docs/requirement/events/2026-11-19-WeKnora知识库集成.md](../../requirement/events/2026-11-19-WeKnora知识库集成.md)

## 一、关键事实（来自上游源码与集群实测）

| 事实 | 证据位置 | 对方案的约束 |
| --- | --- | --- |
| 前端 axios base 读取 `import.meta.env.BASE_URL` | v0.9.0 的 `utils/api-base.ts`（上游为 LocalHub 反代合入的补丁） | 用 vite `--base` 即可同时修正资源与 API 前缀 |
| axios baseURL 取 `import.meta.env.BASE_URL` | 上游 `utils/api-base.ts` | 前缀构建后 `/api/v1/*` 自动变成 `/weknora/api/v1/*` |
| UI Dockerfile 暴露 `ARG VITE_BASE_PATH` | 上游 `Dockerfile` | 自建镜像只需重跑前端构建 |
| 官方 embed 渠道 `/embed/{channelId}`，支持 iframe + CSP `frame-ancestors` | 上游 nginx 模板与 embed 渠道文档 | 问答入口不需 WeKnora 账号 |
| 发布令牌 `em_` 长效、会话令牌 `ems_` 30 分钟 | 同上 | 长期令牌不能下发浏览器 |
| 前端资源与 API 都是根绝对路径 | 构建产物 `index.html` / 各 `api/*.ts` | 同源子路径必须依赖 `VITE_BASE_PATH` 构建 |
| Docker Hub tag 是 `v0.9.0`，`0.9.0` 不存在 | registry manifest 实测 404 | 所有镜像 tag 写 `v0.9.0` |
| 节点拉 `wechatopenai/*` 返回 403 | kubelet `ImagePullBackOff` 事件 | 镜像必须先同步到 ghcr |

## 二、为什么是"同源子路径"而不是独立域名

对抗性审查排除了三条路：

1. **独立子域**（`weknora.acli.sangfor.com.cn`）：现场 DNS 泛解析到代理网段但不可达，
   且需要额外证书与网关放行 —— 依赖不可控的外部配置。
2. **独立端口**（如 `:8443`）：Traefik 只暴露 4888/4443，外部门关不放行新端口。
3. **代理层 `sub_filter` 改写**：只能改 HTML；打包后 JS 里的 `/api/v1/*` 动态拼接
   无法穷举，一旦上游升级就白屏，且故障形态是"部分功能静默失效"。

而 vite 的 `--base` 是官方参数，且 v0.9.0 的 `api-base.ts` 已读取 `BASE_URL`，
所以选同源子路径：iframe 天然同源，embed 的 `frame-ancestors 'self'` 直接成立，
不需要任何跨域白名单，也不引入新的网络暴露面。

## 三、架构

```
浏览器  https://acli.sangfor.com.cn:4443/admin/knowledge/weknora
   │
   ├─ /admin/  → admin-ui 静态资源（vite base=/admin/）
   └─ /weknora/ → admin-ui nginx：rewrite 剥离前缀 → frontend.hci-weknora.svc:80
                     │
                     ├─ /             → WeKnora UI（vite base=/weknora/）
                     ├─ /embed/<id>   → embed 页，auth_request 取 CSP
                     └─ /api/v1/*     → app.hci-weknora.svc:8080 → ParadeDB/Redis/docreader
```

网关入口 `GET /api/weknora/launch`（`require_admin`）返回：

```json
{
  "console_url": "/weknora/",
  "embed_url": "/weknora/embed/<channelId>?token=<ems_...>"
}
```

`embed_url` 为 `null` 表示尚未创建渠道。后端用集群 Secret 里的 `em_` 发布令牌
调上游 `POST /api/v1/embed/<channel>/exchange`（带 `Origin` 头），换 30 分钟
`ems_` 短令牌后拼进 URL；长期令牌不出集群。

## 五、明确的取舍与已知边界

- **长期令牌隔离**：`WEKNORA_EMBED_PUBLISH_TOKEN` 只进 `hci-secrets`，不下发浏览器；
  但 `ems_` 会出现在 iframe URL 里（与 DSH 的 `?token=` 一致），刷新页面即重新换取。
- **账号不打通**：管理台仍是 WeKnora 自己的账号体系。若要 SSO，需要接上游 OIDC
  （v0.8.0 起支持 JWKS），属于后续独立需求。
- **边缘功能前缀**：`VITE_BASE_PATH` 覆盖 axios 主链路；少量 `fetch('/api/...')`
  的边缘功能（集成示例、沙箱终端）在子路径下可能失效。沙箱默认关闭，主链路
  （登录/建库/上传/问答/SSE）不依赖它们。
- **不 prune**：Application 关闭 prune。WeKnora 的 `SYSTEM_AES_KEY` 丢失会让已加密
  的模型 Key 不可恢复，宁可留残留资源也不能被自动回收。


## 八、内嵌页交互优化（2026-11-19 追加）

- **菜单**：文案改「WeK知识库」，`order` 由 6.5 改为 4.7，从 KBD管理(6) 之后
  移到 DSH离线诊断(4.6) 之后——知识库是诊断辅助入口，与 DSH 相邻更贴使用路径。
  菜单断言在 `utils/__tests__/adminMenu.spec.ts`，改顺序必须同步。
- **高度链**：四个内嵌页（WeK知识库 / DSH诊断 / DSH离线诊断 / 可观测性）弃用
  `calc(100vh - Npx)` 的魔法数，改为 `容器 → el-card → body → tabs → 内容 → iframe`
  逐级 `flex:1 + min-height:0`。原来 N 是拍出来的，工具栏或告警高度一变就错位，
  表现为底部留白或页面出现第二条滚动条。
  关键约束：**不能给 `.admin-main` 加 `overflow:hidden`**——同层还有大量普通表单页
  依赖它滚动，改全局布局会裁掉长页面。只让内嵌页自己不吃满、不溢出。
  DSH 两页按要求保留外层滚动条作为兜底；WeK知识库页则在 tabs content 内
  `overflow:hidden`，滚动完全交给 iframe。
- **全屏**：新增 `composables/useFullscreen.ts`，四个页面工具栏各加「全屏 / 退出全屏」。
  全屏元素取页面根容器而非 iframe，这样工具栏与页签仍在全屏内，退出入口不会消失；
  全屏容器需自带 `background`，否则透出浏览器默认底色。浏览器不支持时按钮不渲染。
- **工单同步面板**：`DshTicketSyncPanel` 默认收起（原来约占 300px，把工作台挤到
  第二屏），点标题栏展开；收起态仍显示 `phase` 徽标，避免「同步中被藏起来」；
  `syncTip` 出现时自动展开，防止错误静默。

## 六、已踩到的坑（务必保留修复）

- **`base` 用环境变量无效**：v0.9.0 的 `frontend/` 里**没有** `vite.config.ts`
  （`VITE_BASE_PATH` 是 main 分支后来新增的），设 ENV 完全没效果；
  且镜像仍会构建成功，产物引用 `/assets/*`，被 SPA 回退兜成 HTML，
  控制台报 "Failed to load module script ... MIME type of text/html"。
  修复：改用 `npm run build -- --base=/weknora/`（vite 原生参数），并用 `:-` 兜底。
  教训：验证构建行为必须用**与 CI 相同的 tag 源码**，不能拿 main 分支验证。
- **admin-ui 与 customer-ui 不是同一个 origin**：`admin-ui-ingress` 走 `web`
  entrypoint（staging 4888），`hci-ingress` 走 `websecure`（4443）→ customer-ui。
  因此 embed 渠道白名单必须填 `https://acli.sangfor.com.cn:4888`，
  填 4443 会被上游按"未授权来源"拒绝。
- **app 启动早于 postgres**：上游 app 不重试数据库连接，首个 Pod 会
  `connection refused` panic；CrashLoopBackOff 自动重启后即可连上，
  不需要人工干预，但看日志容易被误判为配置错误。

## 七、验证步骤

1. `helm template` 校验渲染（CI 已内置，含镜像前缀断言）。
2. 部署后 `kubectl -n hci-weknora get pods` 全 Running；`/weknora/` 返回 UI。
3. 真浏览器：admin-ui → 知识库 → 管理台完成登录、建库、传文档、配模型。
4. 建 embed 渠道（允许域名 `https://acli.sangfor.com.cn:4443`），把 channelId 与
   `em_` 令牌注入 env 仓库，ArgoCD 同步后在「知识问答」页签提问并核对引用。
