## 验证结论（逐条）

### SRC-6320 dsh RCE —— 已修复（前序 PR #1639/#1641/#1642）

报告 4 步攻击链在 4443 上全部返回 customer-ui SPA；token 换取 30 天 Cookie 的
入口已摘除；新日志中明文 token 0 条。详见
[4443 端口管理面暴露隔离](2026-11-24-4443端口管理面暴露隔离.md)。

### SRC-5241 Forge 路径穿越 —— 不适用 / 已被网络层拦截

目标是另一个产品（Forge v1.0.0，14.17.59.69:1110），非本仓库代码。实测
`GET /api/openapi.json` 与 `GET /%2e%2e/.../etc/passwd` 均返回
403 `当前网络不允许访问该资源`，公网不可达。

### SRC-5356 工单/会话匿名未授权 —— 核心泄露面已修复

| 报告请求 | 实测 | 判定 |
|---|---|---|
| `GET /api/cases/clients` | 403 需要管理员凭证 | 已修 |
| `GET /api/cases/stats` | 403 | 已修 |
| `GET /api/cases/all` | 403 | 已修 |
| `GET /api/cases/?client_id=...` | 200 但 `[]`（`require_user` 自动签发 client_id，隔离后无数据） | 无泄露 |
| `GET /api/cases/{case_id}` | 404 Case not found | 已修 |
| `GET /api/conversations/case/{case_id}` 无头/伪造 `X-Client-ID` | 403 无权访问此工单 | 已修（自报头不再作为身份） |
| `GET /api/conversations/{id}/messages` 伪造头 | 403 无权访问此会话 | 已修 |

代码侧 `cases.py` 全部端点挂 `Depends(require_user)`，client_id 以服务端签发
Cookie 为准，忽略自报头。

### SRC-5358 internal/诊断域无鉴权 —— 大部分已修复，一处语义缺陷本次修复

| 报告请求 | 实测 | 判定 |
|---|---|---|
| `GET /api/internal/collectors` 等 5 条 | 403 需要管理员凭证 | 已修 |
| `GET /api/diagnosis-scenarios` | 401 缺少有效身份 Cookie | 已修 |
| `GET /api/diagnosis-sessions/{不存在}` | 404 DIAGNOSIS_SESSION_NOT_FOUND | 已修 |
| `GET /api/diagnosis-sessions/{不存在}/bundles`、`/reports`、`/runs` | **200 `[]`** | **本次修复** |
| `GET /api/diagnosis-sessions/by-case/{case_id}/workspace` | 404 CASE_NOT_FOUND_OR_FORBIDDEN | 已修 |

三个子资源列表 service（`EvidenceUploadService.list_bundles`、
`OfflineAnalysisService.list_runs/list_reports`）只查子表、不校验会话存在性，
导致"会话不存在"与"会话存在但无数据"都返回空数组，无法区分且提供会话 ID
探测 oracle。本次加 `_require_session_exists`（同租户 + 会话存在，`SELECT 1`），
不存在时抛 `DIAGNOSIS_SESSION_NOT_FOUND` 404，与 `/timeline` 等行为一致。

### SRC-5941/5942 3443 接口 —— 环境已下线，4443 同类问题已修复

- 3443 全部请求返回 `000`（连接失败），报告环境不存在。
- 4443 同类实测：`/api/cases/*` 403；`POST /api/bridge-logs` 匿名/伪造头/
  不存在 case_id 均返回 `accepted:0, forbidden:1`；中文内容不再 500。
- 代码侧 `bridge_logs.py` 挂 `Depends(require_user)`，下游校验 case_id 归属。

## 验收标准

```bash
# 部署后：不存在的会话子资源应返回 404，不再是 200 []
for p in bundles reports runs; do
  curl -sk -o /dev/null -w "$p → %{http_code}\n" \
    "https://acli.sangfor.com.cn:4443/api/diagnosis-sessions/00000000-0000-4000-8000-000000000000/$p"
done
# 期望：三行全部 404

# 已存在的会话应仍返回 200（回归检查，用真实会话 ID 替换）
curl -sk -o /dev/null -w 'existing → %{http_code}\n' \
  https://acli.sangfor.com.cn:4443/api/diagnosis-sessions/<真实ID>/bundles
```
