# 2026-11-17 日志收集 SPC 目录改用固定路径方案

## 背景与需求

见 [需求事件文档](../../requirement/events/2026-11-17-日志收集SPC目录改用固定路径.md)。核心事实：两个 spc 目录并存是正常的，日志收集固定使用 acli 插件目录下的那一个。

## 方案概述 (WHAT)

把 SPC 目录从"运行时 find 探测 + 多候选判定"改为"单一固定路径常量 + 存在性直判"，一次性移除三处重复探测（写入前、回滚、hint 校验分支）。

## 详细设计

### 核心常量

在 `log_collect_spc.go` 定义唯一权威常量：

```
const spcDeployDir = "/sf/data/local/acli/plugins/log_collect/tools/lmt_collect_info/support_bundle_cluster/spc"
```

该值与 `log_collect_spc_multi_test.go` 中既有的 `real` 常量逐字一致，现场已确认。

### 改动点

1. `buildSpcFindCommand` / `buildSpcDirCommand` / `parseSpcDirs` / `pickSpcDir` / `spcResolveDir`：目录判定收敛为固定路径。
   - 探测命令改为对固定路径做存在性校验：`[ -d <固定路径> ] && printf '%s\n' <固定路径>`；不再 find，不再多候选。
   - `spcResolveDir` 只接受"输出等于固定路径"一种成功情形：输出为固定路径→成功；为空→`spc_dir_missing`；其他→仍归 `spc_dir_missing`（不再有 ambiguous）。
2. `applySpcToHost`：写入前调用存在性校验脚本，固定路径不存在时仍报 `LC-SPC-001`。
3. `restoreSpcOnHost`：`dir` 为空时直接取固定路径，不再调用 find 重探测，消除"回滚失败 1 台"假告警。
4. 回归测试：
   - 新增"stdout 含两个目录时仍只取固定路径"（把原 find 的多行输出喂给 `spcResolveDir`，断言返回固定路径、无 ambiguous）。
   - 保留并调整既有 `TestBuildSpcFindCommandDepth` 等用例以适配新语义。

## 决策依据 (WHY)

| 方案 | 优点 | 缺点 | 评分 |
|---|---|---|---|
| A. 固定路径（选中） | 消除整层探测缺陷；代码更简单；现场已确认路径唯一权威 | 路径变更需改常量（但由平台自己部署，非外部依赖） | ★★★★★ |
| B. 修 find 的 exit 1 判定 + 双目录择一 | 保留动态适应性 | 仍需决定"选哪个目录"的业务规则；两目录并存是正常现象，择一规则无依据；三处探测都得改 | ★★☆☆☆ |
| C. 只在写入前修，回滚保留 find | 改动小 | 回滚假告警持续存在；与需求"回滚也用固定路径"不符 | ★☆☆☆☆ |

选择 A 的第一性原理：既然日志收集唯一的写入对象就是 acli 插件目录下的 spc，且该目录由平台自己部署，那么"探测"这一步不产生任何新信息，只是引入误判面。删掉它是最优解。

## 影响范围

- `terminal_bridge/log_collect_spc.go`、`log_collect_spc_fanout.go` 及相关测试。
- 不改契约错误码（`LC-SPC-001` 语义从"探测不到"精确为"固定路径不存在"，码不变，前端与 catalog 不动）。
- 改 `terminal_bridge` 必须重建 exe 并现场人工重装才生效（合并 ≠ 到达客户机）。

## 风险与缓解

| 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|
| 未来 acli 升级改了部署路径 | 固定路径失效 | 低 | 常量单点定义，改一处即可；现场版本已确认 |
| 节点未安装 acli 插件 | 固定路径真不存在 | 中 | 仍返回 `LC-SPC-001`，提示"固定路径不存在，请确认已安装平台插件版本" |

## 验收标准

- [ ] fanout 失败增量 0；`written=hosts_count`。
- [ ] 双目录节点上直接写入固定路径成功，无"目录不唯一"误报。
- [ ] 不存在"回滚失败/可能残留平台清单"假告警。
- [ ] Go 全量测试 + gofmt + docs 门禁通过。

## 测试策略

单元测试覆盖固定路径解析、双目录输出、目录缺失、回滚不再重探测；staging 按 case_id 拉 `spc_fanout_failed` 验证修复后无新增。
