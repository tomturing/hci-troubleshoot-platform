# 证据上报派生遮蔽导致 process-logs 接口 500

## 现象

工单 `Q2026091700436` 的日志收集最终已 `completed / delivered`，归档件核验通过（10,563,438,951 B），但客户界面「证据回传」阶段（S7）显示 **未知**，同时采集告警快照（`collect_alerts`）从未产出。

`case-service` 日志里可复现：

```
File "app/routes/log_collect_evidence.py", line 365, in put_process_log
    await _sync_collect_alerts(...)
File "app/routes/log_collect_evidence.py", line 421, in _sync_collect_alerts
    text("SELECT detail FROM log_collect_task WHERE task_id = :task_id"),
TypeError: 'str' object is not callable
→ POST /api/log-collect/tasks/{id}/process-logs 500
```

## 根因

两处叠加：

### 1. 局部变量遮蔽了模块级导入

```python
from sqlalchemy import text          # 模块级：SQL 构造器

async def _sync_collect_alerts(...):
    ...
    text = gzip.decompress(content).decode("utf-8", errors="replace")   # 同名局部变量
    ...
    row = await session.execute(
        text("SELECT detail FROM log_collect_task WHERE task_id = :task_id")  # 此时 text 是 str
    )
```

`text` 在函数体内被重新绑定成 `str`，第二处调用立即抛 `TypeError`。

### 2. 旁路派生没有兜底，把回执打成了失败

函数 docstring 承诺「证据正文已经落库，这一步是旁路派生：失败只记日志，绝不影响上报回执」，但调用点直接 `await _sync_collect_alerts(...)`，异常一路冒到路由：

- 进程日志正文其实已 `await session.commit()`（表里 26 条 `ok` 可证）；
- 桥收到 500，认为证据上报未成功，`artifact_manifest` 因此没有写入任务详情；
- 客户界面的 S7 判定依赖 `detail.artifact_manifest`，拿不到就落到 `unknown`。

即：一次变量命名错误，最终表现为「证据回传未知 + 采集告警永久缺失」，而正文数据完全正常。

## 修复

`backend/case-service/app/routes/log_collect_evidence.py`：

1. 局部变量改名 `log_text`，并在注释里写明为什么不能叫 `text`；
2. 调用点包 `try/except Exception` + `logger.warning(..., exc_info=True)`，兑现「派生失败只记日志」的契约——正文已提交，任何派生异常都不得把回执变 500。

## 验证

新增 `backend/case-service/tests/unit/test_log_collect_evidence_alerts.py`（3 例）：

- 正常路径必须执行到 `UPDATE log_collect_task`，且第一条参数是 SQLAlchemy `TextClause`（被遮蔽时会退化成 `str`，断言即红）；
- 非 `collection_log.log` 路径直接返回、不查库；
- AST 静态断言：`_sync_collect_alerts` 内禁止出现名为 `text` 的赋值（本次 bug 的最小复现条件）。

对抗性验证：把 `log_text` 改回 `text` 后重跑，用例复现线上同一条
`TypeError: 'str' object is not callable` 并失败；恢复修复后
`tests/unit` 相关 545 例全部通过。

## 影响面与遗留

- 影响的是**证据派生层**：进程日志正文、归档件、任务终态都不受影响，历史工单不需要重新采集；
- 已发生的 500 无法回溯补写 `artifact_manifest`，历史任务的 S7 仍会显示「未知」（平台不提供回填，避免伪造现场）；
- 修复上线后新的 `process-logs` 上报会正常写入证据清单，S7 恢复真实判定，采集告警也会重新产出。
