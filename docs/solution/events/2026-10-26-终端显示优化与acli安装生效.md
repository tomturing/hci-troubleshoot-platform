# 终端显示优化 + acli 安装后的「生效」步骤

## 一、acli 重新安装后 `acli: No such file or directory`

### 现场现象

```text
(安装日志：acli 安装并验证成功)
# acli
-bash: /sf/sbin/acli: No such file or directory
# acli
-bash: /sf/sbin/acli: No such file or directory
（重连 SSH 后正常）
```

### 根因（第一性原理推导）

拆到最底层，只有三个不可再分的事实：

1. 报错里带**绝对路径** `/sf/sbin/acli`，而不是 `command not found` —— 说明 bash 不是没找到命令，
   而是**已经缓存过这个路径**（bash hash 表），直接 exec 它；
2. `/sf/sbin/acli` 是 641B 的 bash wrapper，转发到 `/sf/bin/acli`（见
   [日志收集 bridge 执行通道](2026-10-22-日志收集bridge执行通道.md)）；
3. 安装器 `--install --force` 会**替换/挪动**可执行文件，旧路径可能就此不存在。

三者合起来：**bash 的路径缓存指向了安装前的旧文件**。hash 表只在新 shell（重连）或
显式 `hash -r` 时失效 —— 这正好解释"重连就好了"。

所以**不是缺安装步骤，而是缺"让已有 shell 重新解析 PATH"这一步**。

### 日志收集会不会受影响？

日志收集不走交互式 shell，每次都是**新进程**，不依赖 shell 缓存；但**是否带 PATH 前缀取决于动作**，
2026-10-27 之前并不统一（已在当天修复，见
[日志收集 acli 路径同源修复](2026-10-27-日志收集acli路径同源修复.md)）：

| 通道 | 代码位置 | 每次执行的方式 |
|---|---|---|
| 环境探测 / help / node list | `terminal_bridge/log_collect.go` `logCollectAcliInvoke` | `export PATH="$PATH:/sf/bin:/sf/sbin:…"; 绝对路径解析; "$__acli" …` |
| 创建 / 进度 / 取消 | 同上 `logCollectAcliInvoke` | 同上（**修复前是裸 `acli …`**，PATH 不含 `/sf/bin` 时报 `command not found`） |
| 安装与验证 | `terminal_bridge/main.go` `runQuickCommand` | `ssh.Client.NewSession()` 全新会话 + PATH 前缀 |
| 容器内命令 | `main.go` `wrapContainerCommand` | 同样前置 PATH |

即：`/sf/bin` 排在 `/sf/sbin` 之前，新装的二进制一定先被找到；且解析结果由 `$__acli` 承载，与探测同源。

### 修复（前端，无需重发 bridge）

`stores/chat.ts` 的 `checkAndSyncAcli()` 在 `acli_sync_result.status === 'installed'` 后：

- 终端抽屉开着 → 向该会话发送 `hash -r`，让**现有 shell 立即生效**（用户看到终端里执行了这一条，语义自解释）；
- 终端没开，或输入通道正被环境采集占用 → 不抢通道，改为在 acli 日志里给出可操作提示
  （"执行 hash -r 或重连终端即可，无需重装"）。

对抗性审查：抢输入通道会把采集命令的输出错路由到终端，因此加了 `sshCommandConsumer !== 'collection'` 的互斥。

## 二、终端显示：最后一行被输入区压住

### 实测到的三层问题

用真实页面 + 假 bridge 量出来的数据（`TerminalPanel` 在默认 400px 抽屉内）：

```text
.terminal-canvas  高 754px
.xterm（内容盒）   高 732px
.xterm-screen     高 722→上边界对齐后，旧样式下 779px > 771px  ← 多出 8px 被 overflow:hidden 裁掉
```

1. **半行被裁**：xterm 的字符高度是浮点值，`FitAddon` 按浮点算行数、渲染按整像素铺行，
   内容会比容器高出一行的一部分，被 `overflow: hidden` 从中间切掉 —— 观感就是"最后一行被压住"；
2. **零安全间距**：`.terminal-stage` 的底部 padding 是 `0`，终端画布与输入区直接贴边，双边框叠在一起；
3. **窄抽屉溢出**：抽屉默认 400px，头部五个动作按钮被顶出抽屉被裁（实测 `scrollWidth 598 > clientWidth 366`），
   输入框也被两枚按钮挤到不足一行字宽。

### 改动

| 位置 | 改动 |
|---|---|
| `fitTerminal()` | `fit()` 后核对 `.xterm-screen` 与 `.xterm` 的高度，超出就减一行（少一行不可见，半行很刺眼） |
| `.terminal-stage` | 四边 padding 统一 12px，画布不再贴住输入区 |
| `.terminal-input-area` | 快捷键提示并入输入区（删掉独立 footer），少一条分隔线、多 16px 给终端 |
| `.terminal-header` / `.header-actions` | 允许换行、收紧按钮内边距与字号，窄抽屉不再裁切 |
| `.terminal-input-row` | 允许换行，输入框 `min-width: 0`，不再把按钮顶出去 |
| `.terminal-panel` | 去掉 `min-height: 400px`（矮视口会撑破抽屉、把底部输入区裁掉） |
| xterm | 字体栈加 `JetBrains Mono/Cascadia Mono`、行高 1.3、`scrollback` 2000→5000、滚动条深色收窄 |

## 三、验证

- 单测 `stores/__tests__/chat.acli-hash-reset.spec.ts`（5 条）：安装成功 + 终端开 → 发 `hash -r`；
  终端没开不发；采集占用通道不发；`up_to_date` 不发；未连接直接跳过。
- 真实页面人工模拟（Playwright + 假 bridge WS，1600×1000）：
  - 终端最后一行距画布底 21px，**不再被裁**；输入区底边 987 < 视口 1000；
  - `header.scrollWidth - clientWidth = 0`，输入行溢出 0；
  - 截图见 PR 描述。
- 全量单测 218 条通过，`pnpm build`（含 vue-tsc）通过。
