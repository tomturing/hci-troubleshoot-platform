# 4443 公网端口管理面暴露隔离

## 背景

安全报告指出：`https://acli.sangfor.com.cn:4443/dsh/` 可匿名进入 DSH 诊断工作台，
在容器内执行任意命令、跨 workspace 读取文件元数据，并可列出真实工单会话。

复现链：匿名从 `4443/grafana` 的 Loki datasource proxy 查询日志 → DSH 进程启动时
把 launch token 打到 stdout 并被 Promtail 采集 → 用 token 换取 DSH 会话 cookie →
获得 Agent 执行能力。

## 第一性原理根因

一个 HTTP 请求能否到达后端，由三层决定：

1. **路由层**：Traefik entrypoint 上是否注册了对应的 Host+Path 规则。
2. **网络层**：来源 IP 是否被 `ipAllowList` 放行。
3. **应用层**：后端是否要求有效身份凭据。

本次事故是**三层全破**：

- 路由层：DSH/Grafana/Langfuse 的 Ingress 模板在 `.Values.ingress.tls` 非空时
  渲染成 `entrypoints: websecure,web`，同时注册到公网 4443 和管理口 4888。
  而环境仓库把顶层 `ingress.tls` 作为公共 values 注入所有 chart，使该条件恒成立。
- 网络层：这三个 Ingress 都没有挂任何 `ipAllowList`。
- 应用层：Grafana 匿名可读 Loki，直接绕过 DSH token 的 `require_admin` 分发边界。

## 修复（纵深分层）

### 第一层：路由摘除（主防线）

`hci-platform-dsh`、`hci-platform-obs` 的 3 个 Ingress 模板统一改为
`traefik.ingress.kubernetes.io/router.entrypoints: web`，不再根据 `ingress.tls`
推导。`/dsh`、`/dsh-offline`、`/grafana`、`/langfuse`（含 `/_next`、`/static`、
`/api/auth`、`/api/public`、`/api/trpc` 等伴随路径）从 4443 彻底消失。

**这一层不依赖任何 IP 判断**：公网请求在 4443 上匹配不到路由，落到 `/` 回退到
customer-ui 的 SPA，根本到不了管理面 backend。

### 第二层：管理 API 公网 guard（纵深）

新增 `deploy/helm/hci-platform/templates/admin-api-guard.yaml`：独立 Ingress 绑定
`websecure`，对 27 条管理 API 前缀（`/api/v1/kbd`、`/api/v1/sop`、
`/api/v1/log-collect/admin`、`/api/hci-sim`、`/api/dsh/launch` 等）挂
`ipAllowList`，公网源 403；4888 管理入口不受影响。

`/api/internal` 已有独立 `internal-guard`，此处不重复注册。

**已验证误伤面**：customer-ui 与 terminal_bridge 对这 27 条前缀 0 调用；
所有调用方均为 admin-ui，走 4888。

### 第三层：应用层鉴权加固

`backend/api-gateway/app/routes/capabilities.py` 的 `/api/v1/tools`、
`/api/v1/prompts`、`/api/v1/skills` 此前网关与上游 conversation-service 均无鉴权，
现补 router 级 `require_admin`。

### 可观测性

Traefik accesslog 的 `statuscodes` 过滤从 `500-599` 改为 `403,500-599`。
guard 拒绝的 403 现在会带 `RouterName`/`ServiceName` 落入 Loki，是隔离控制
是否真的生效的唯一可追责证据。

## 对抗性审查：guard 的已知边界

`ipAllowList` 读取 Traefik 直连 remote IP，而仓库当前没有配置
`entryPoints.<name>.forwardedHeaders.trustedIPs`。**若云 LB 以私网 IP 回源
（如 192.168.x.x），所有公网请求都会被视为内网源，guard 被整体绕过。**

因此：

- guard 只能作为纵深第二层，**绝不能**当作主防线；
- 主防线是第一层"路由不注册"，它不依赖任何 IP 判断；
- 现网验收必须实测 LB 回源 IP（见下）。

## 验收标准

### 路由层（必须全部通过）

```bash
# 4443 上管理路径应落到 customer-ui SPA（404/HTML），不得返回 DSH/Grafana 内容
curl -sk -o /dev/null -w '%{http_code}\n' https://acli.sangfor.com.cn:4443/dsh/
curl -sk -o /dev/null -w '%{http_code}\n' https://acli.sangfor.com.cn:4443/grafana/
curl -sk -o /dev/null -w '%{http_code}\n' https://acli.sangfor.com.cn:4443/langfuse/

# 4888 上管理路径应正常（管理员来源）
curl -sk -o /dev/null -w '%{http_code}\n' https://acli.sangfor.com.cn:4888/dsh/
curl -sk -o /dev/null -w '%{http_code}\n' https://acli.sangfor.com.cn:4888/grafana/
```

### guard 层与 LB 回源 IP（必须验证）

```bash
# 从公网源访问被 guard 的管理 API，期望 403
curl -sk -o /dev/null -w '%{http_code}\n' \
  https://acli.sangfor.com.cn:4443/api/v1/kbd/pending

# 查看 Traefik accesslog 是否记录了 403 及命中的 RouterName
kubectl -n kube-system logs deploy/traefik --tail=200 | grep '"Status":403'

# 确认 LB 是否透传真实客户端 IP：从公网访问后查 Traefik 看到的来源
# 若日志里的 RemoteAddr 是私网 LB IP，则 guard 无效，必须依赖第一层路由隔离
```

### 应用层

- 匿名 `GET /api/v1/tools` 返回 401/403，不再返回工具定义表。
- admin-ui 的「工具管理」「Prompt 管理」「技能管理」页面在 4888 上功能正常。

## 回滚

回滚分两层，按此顺序：

1. 恢复 Ingress 模板的 `websecure,web` 双绑定（**仅临时止血失败时**，会重新暴露漏洞）。
2. 删除 `admin-api-guard.yaml` 与 values 中的 `adminApiGuard` 配置节。
3. 回退 `capabilities.py` 的 `require_admin` 依赖。
4. 恢复 accesslog 过滤为 `500-599`。

更推荐的前滚修复：若 guard 因 LB 回源 IP 失效，保留路由隔离不动，额外在云 LB
层对 4443 监听器的 `/dsh*`、`/grafana`、`/langfuse*` 做 L7 路径拒绝。
