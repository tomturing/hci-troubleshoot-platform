# 交付失败原因可见性修复

- 日期：2026-10-30
- 关联：Q2026102801062（代传失败后界面与任务记录都查不到原因）
- 涉及：`frontend/customer`（`LogCollectPanel.vue`、`utils/logCollectDelivery.ts`）、`backend/case-service`、`backend/api-gateway`（注释口径）

## 一、现场事实

| 事实 | 证据 |
| --- | --- |
| 界面提示「归档到日志服务器失败，错误码见平台任务记录，可据此排查」 | 前端 `pollRelay` 在 `relay_status === 'failed'` 时抛固定文案 |
| 任务记录里 `error_code`、`error_message` 全空，`delivery_error` 只有同一句通用文案 | 查库确认，与「见任务记录」自相矛盾 |
| 后端 `_finish` 实际会写 `error_code` / `error_message` / `delivery_error` | `log_collect_relay_service.py` `_finish()`：失败分支同时写三列 |
| 前端交付失败时用 `delivery_error: errorMessage.value.slice(0, 500)` 回写 | `LogCollectPanel.vue` 交付失败 catch 分支 |

## 二、根因

**同一条事实有两个写者，且后写者不知道前写者写过什么。**

- 后端 `_finish` 写的是**权威原因**（5888 返回码、归档超时等原始文本）；
- 前端在轮询看到 `failed` 后，用自己手里那句**通用文案**回写 `delivery_error`，把权威原因覆盖掉；
- 而前端那句文案本身是「错误码见平台任务记录」——指向的正是被它自己覆盖掉的位置。

结果：用户被指向一个空记录，支持侧也无法从界面或库里判断失败类型。失败原因在**两个写者之间被稀释为零**。

## 三、本次改动

### 1. 前端不再写 `delivery_error`

`delivery_error` 归还给后端 `_finish` 独占。桥侧失败的真实原因改走 `error_code` / `error_message`
（PATCH 契约本就允许这两个字段），与代传原因共用同一条展示通道，语义不分裂。

### 2. 回写前先确认后端有没有记录

代传失败时，catch 分支拿到的 message 本身就是「[码] 原因」的转述；原样回写会让下次渲染
再拼一次码，变成 `[LC-X] [LC-X] ...`。因此先 `getTask` 读一次：已有 `error_message` 就只写
`delivery_status=failed`，不再回写原因。多一次 GET 只发生在失败路径上。

### 3. 失败文案改为转述任务记录

`pollRelay` 的 `failed` 分支改为读取任务记录并用 `formatFailureReason` 拼装：

| 任务记录 | 展示 |
| --- | --- |
| 有码有因 | `[LC-TRANSFER-003] 5888 返回 503` |
| 只有因 | `5888 返回 503` |
| 只有码 | `[LC-TRANSFER-002] <兜底文案>` |
| 都没有 | 兜底文案：平台未记录原因（可在桥日志中按工单号检索） |

**空值不能编造原因**：平台确实可能没记录（取消、历史任务、旧版本桥），只能如实说明。

### 4. 分片口径注释纠偏

`LOG_COLLECT_CHUNK_SIZE_BYTES` 早在 Q2026102801062 就由 32 MiB 降到 8 MiB，但两处注释仍写 32 MiB：

- `backend/case-service/app/routes/log_collect.py` 直传端点 docstring；
- `backend/api-gateway/app/routes/log_collect.py` 模块 docstring。

注释错值会让排障者按 32 MiB 反推网关超时与豁免额度，得出错误结论。

## 五、已知边界

1. **只在失败路径多一次 `getTask`**：失败时多一次请求，成功路径零额外开销。
2. **`getTask` 失败时按"平台未记录"展示**：不阻断提示，也不编造原因。
3. **错误码未细分**：5888 的 4xx/5xx 仍统一 `LC-TRANSFER-003`，细分需要外部系统契约，另立项。
4. **历史任务仍为空**：本次只保证「今后失败必有原因」，不回溯补写已空的记录。
