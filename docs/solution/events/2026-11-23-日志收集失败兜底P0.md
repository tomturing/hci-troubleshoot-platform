# 2026-11-23 日志收集失败兜底（P0）

## 背景

Q2026112300134 暴露了一条完整的失败链：acli 1.0.3 重装清空节点插件目录 → 3 台内置插件
未重建 → spc 备份失败 → 任务报 `LC-SPC-003`，而真正的根因（插件目录残缺）在平台侧
完全不可见。定责过程被迫依赖现场手工取 `acli.log`。

按「组件出问题也能闭环」的目标，把兜底拆成四层并落地 P0：

| 层 | 缺失 | 本次 |
|---|---|---|
| 感知 | 不知道节点插件已坏 | create 前逐台校验插件文件 |
| 拦截 | 带病下发，错误被包装成下游码 | 缺失即拒绝，给 `LC-INSTALL-010` |
| 归因 | `cp 2>/dev/null` 吞真因、拒绝不落逐台证据 | 保留 stderr、reject 回包带 `spc_hosts` |
| 取证 | 失败时不知道节点长什么样 | 失败现场快照 + 安装前后插件快照 |

## 改动

### 1. 前置插件校验（bridge）

- 新增 `log_collect_preflight.go`：对发起节点与集群各节点检查
  `/sf/data/local/acli/plugins/log_collect/{plugin,manifest.json,tools/lmt_collect_info/progress.json}`
  是否存在且非空（`[ -s ]`，空目录不算完整）。
- 缺失时拒绝 create，错误码 `LC-INSTALL-010`，Message 列出 `ip:path`；
  同时上报失败现场快照。
- 节点不可达不计入「插件不完整」（它有自己的 `LC-ENV` 码），避免误阻断。

### 2. spc 失败自证（bridge + 前端）

- `buildSpcPrepareCommand` 的备份 `cp` 不再 `2>/dev/null`：`cp: cannot stat` /
  `Permission denied` / `No space left` 会进入 detail。
- 新增 `SpcFailureDetail`：detail 至少形如
  `reason=backup_failed | cp: cannot stat '/…/vm_suspend.json': No such file or directory`。
- `spcRejection` 增加 `Hosts/Slot/Slots/RestoreStatus`，拒绝回包带 `log_data.spc_hosts`。
- 前端把 config/spc 回执补写**提前到 status 判断之前**：失败回包也要落库，
  否则逐台证据随抛错一起丢失。

### 3. 产物节点对账（bridge + case-service）

- `EvidenceConfig.ExpectedHosts` 由 create 的 `-i` 参数解析（`all`/空不参与对账）。
- `artifactManifest` 增加 `expected_hosts`，两条上报路径统一在 `postManifest` 补齐。
- 平台 `reconcile_manifest_hosts` 把目标集合与 `sp_<ip>.tgz` 做差集；
  缺台时 quality 从 `ok` 降为 `incomplete`，reason `missing_hosts`，
  `detail.artifact_manifest.missing_hosts` 可直接读。

### 4. 失败现场与安装前后快照

- 新增 `POST /tasks/{id}/failure-snapshot`：写入 `detail.failure_snapshot`
  （reason/host/files/disk/collected_at），只写证据容器，不碰状态。
- bridge 在 `create_failed` / `create_not_established` / `plugin_incomplete` /
  `spc_*` 四类失败上主动上报快照。
- acli 安装增加 `acli_sync.plugin_snapshot`（phase=before），
  `node_plugin_verify` 增加 `phase=after` 与 `missing_before`：
  从此能区分「本来就缺」与「这次安装打坏」。

## 验证

- `go test ./internal/logcollect/ -count=1` 全绿，新增 6 个用例（目标集合解析、
  插件探测语义、快照解析、detail 保留 stderr、prepare 命令不吞 stderr）。
- `uv run pytest backend/case-service/tests/unit/test_log_collect_evidence_service.py`
  32 passed，新增 2 例（缺台降级 incomplete、快照写 detail）。
- 错误码经 `contracts/log_collect_display.json` → `scripts/gen_log_collect_display.py`
  统一生成，catalog/Go/TS/Python 四端一致。

## 影响面

- 每次 create 多一次逐节点 probe（并发，通常 <2s）；节点不可达时放行，不改变原判据。
- 失败快照只在失败路径执行，且全程只读。
- 对账只对点名模式生效；`-i all` 的任务保持原判据，不引入误判。
