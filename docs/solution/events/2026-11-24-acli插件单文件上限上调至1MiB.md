# acli 插件单文件上限上调至 1MiB，并对齐保存校验与鉴权提示

## 文档信息

- **版本**: 1.0
- **创建日期**: 2026-11-24

- **关联代码**: `terminal_bridge/internal/acli/acli_plugin_manifest.go`、`backend/case-service/app/domain/acli_plugin_spec.py`、`frontend/shared/src/api.ts`、`frontend/admin/src/utils/auth.ts`、`frontend/admin/src/main.ts`、`frontend/admin/src/views/AcliPluginManageView.vue`
- **关联 PR**: #1660

## 一、现场问题

在 admin-ui 更新 `hci_lmt_check` 完整巡检脚本（629,375 字节 / 16,008 行，UTF-8）后，出现三个独立问题：

1. **保存成功、下发必失败**：桥侧 `acliPluginMaxFileBytes = 512KiB`，超过即整单拒收（`manifest_file_too_large`）；而平台侧 `validate_spec` **没有任何单文件大小校验**，admin-ui 照常返回 201。
2. **冒烟参数与脚本版本脱节**：新脚本把 `-s <section>` 改为必填，旧 `smoke_args = -m env -c cpu_load` 触发 `plugin_smoke_failed`，桥按设计自动回滚（回滚行为正确，但用户只看到「插件同步失败」）。
3. **鉴权失败被吞成通用错误**：管理端 JWT 4 小时过期后，axios 通道没有 401/403 统一处置，网关 403「需要管理员凭证」被页面 catch 收敛为「保存规格失败」；且 `redirectToLogin` 写死 `/login`，而 admin router base 是 `/admin/`，跳转会落到客户侧根路径。

## 二、修复

### 2.1 桥侧：单文件上限 512KiB → 1MiB

`terminal_bridge/internal/acli/acli_plugin_manifest.go`：

```go
acliPluginMaxFileBytes = 1 << 20
```

依据：lmt 完整脚本实测已达 ~615KiB；内联内容经 HTTP 拉取（非 WS 命令通道），1MiB base64 约 1.34MiB，仍远低于 `acliPluginManifestMaxBytes`(16MiB) 与 `CLIENT_MAX_CMD_BYTES`(10MiB)。

### 2.2 平台侧：保存时同口径校验

`backend/case-service/app/domain/acli_plugin_spec.py` 新增：

```python
MAX_PLUGIN_FILE_BYTES = 1 << 20
```

`validate_spec` 对 `script_content` 与 `extra_files[].content` 按 **UTF-8 字节数**校验（脚本常含中文注释，字符数会低估约 3 倍），超限返回 400 并逐条给出原因，避免「保存成功但永远下发失败」。

### 2.3 前端：预检与鉴权提示

- `AcliPluginManageView.vue`：保存前用 `TextEncoder` 做 1MiB 预检；catch 区分 401/403 与字段校验错误，不再统一显示「保存规格失败」。
- `shared/src/api.ts`：`createApiClient` 对管理端（传 `getToken`）的 401/403 派发 `hci:auth-error` 事件。
- `admin/src/main.ts`：监听事件，401 或 403（文案含「管理员/凭证/admin」）时清 token 跳登录。
- `admin/src/utils/auth.ts`：导出 `handleAuthExpired()`，登录页路径改为 `${BASE_URL}login`（即 `/admin/login`），`setupAuthFetch` 复用同一逻辑。

## 三、验证

- 自动化：桥侧 `go test ./internal/acli/...`、平台侧 acli 规格/管理/同步单测、`ruff`、`vue-tsc -b` 均通过；新增「超 1MiB 拒绝」「1MiB 边界通过」用例。
- 实机（HCI 24，桌面桥 `v2.37.0-9-gcef9e5fc`，HTTPS 自签平台）：工单 `Q2026112400007` 中 629KB 脚本成功下发，`hci_lmt_check` **overwrite × 3**（172.28.24.2/.3/.4），`failed=0`；三节点 `bin/troubleshoot.sh` SHA-256 与平台内容完全一致；冒烟 `-s env -c cpu_load` 输出非空，`device_status=success`。

## 四、后续约束

- 更新插件脚本时，必须同步更新「参数与选项」中的冒烟参数，否则会因 `plugin_smoke_failed` 自动回滚。
- 若未来脚本继续增长超过 1MiB，需要重新评估内联通道上限或引入 package 通道（当前桥侧明确不支持 package 通道，`manifest_package_channel_unsupported`）。
