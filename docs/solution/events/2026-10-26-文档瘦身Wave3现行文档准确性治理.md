# 文档瘦身 Wave 3：现行文档准确性治理

> 本仓库文档治理的既往节点：#1183 瘦身 P0（AGENTS.md 注入成本）、#1266 瘦身 P1（归档 18 篇 + 订正被证伪的
> PreSync 假设）、#1276 瘦身 Wave 2（frontmatter 规范化 + naming/frontmatter 门禁缺陷）。
> **Wave 3 = 内容准确性**——把「读者照着做会失败」的引用与断言清零。
> 本文是 Wave 3 的决策史料；各现行文档的对应改动记在其自身的变更历史节里。

## 背景与需求

`scripts/ci/check_docs_rot.py` 自 #770 起就在报失效引用，但一直只报告不阻断。
按「读者会不会照着它行动」切层（W3-3 开工时实测全仓 655 条 = 现行 63 + 事件 531 + 归档 61）：

| 层 | Wave 3 开工时 | 收口时 | 读者的使用方式 | 治理口径 |
|---|---|---|---|---|
| **现行全量文档**（`docs/` 去掉 `events/`、`archive/`） | 158（首轮全量扫描） | **0** | 会照着它动手 | **必须归零**，且升为阻断级 |
| 事件文档（`*/events/`） | 531 | 527 | 读的是「当时为什么这么决策」 | 史料，按 §8.3.1 只订正被证伪的事实断言 |
| 归档文档（`docs/archive/`） | 61 | 58 | 只读 | 冻结不动 |

需求来自 Wave 2 结束时确认的一条用户指令：**「优先更新全量、现行文档至项目最新状态」**——
即内容准确性优先于机械治理，且要「所有的文档都确认一遍」，不是只处理某一份方案文档。

## 方案（WHAT）

三类动作，按「先修尺子、再修内容、最后升门禁」的顺序落地。

### 1. 修门禁自身的语义缺陷（尺子不准，报出来的数就不能用来决策）

main 上的 `check_docs_rot.py` 会把**语义上有效**的引用判成失效。Wave 3 新增 5 类豁免，共 205 行：

| # | 缺陷（原实现会把正确的句子判成 rot） | 修正 |
|---|---|---|
| 1 | 指向**已存在目录**的链接（如 `docs/verify/pitfalls/`）被判失效 | 目录链接视为有效 |
| 2 | 行内代码里的 markdown **语法示例**（示范禁止写法用的 `` `![截图](URL)` ``）被判成 C1/C2 | `inline_code_spans()` 区间内的示例不参与判定 |
| 3 | 「旧版 X **已删除**」这类**历史陈述**中的路径被判失效 | `NEGATION_WORDS` 窗口化判定：前 30 / 后 60 字符内出现「历史路径/曾用名/已删除/不存在/git 历史」等才豁免，标注必须**与引用同行** |
| 4 | `status: archived` 的文档仍被要求引用完整 | `split_archived()` 整体豁免 C1/C2/C3（C6 密钥不豁免），并逐条产出可审计的豁免记录 |
| 5 | 被 `.gitignore` **刻意排除**的路径（`deploy/env/secrets.env`、`data-pipeline/kbd/.env`、`logs/` 等）被判失效 | 用 `git check-ignore -v --no-index` 判定，命中即豁免，并把命中的规则原文写进 `waive_reason` |

第 5 类的正当性推导：C3 检查存在**唯一**理由是「读者能按文档找到该文件」。
`secrets.env` 是仓库**故意不入库**的——要求它出现在检出里，等于逼文档写一句假话。
对抗性审查同时限制了它的逃逸面：豁免判据来自 `.gitignore` 而非作者，作者想靠它蒙混必须去改 `.gitignore`
（那是独立可评审的改动）；且全仓实测只有 4 条唯一路径落在 gitignore 命中范围内，射程可控。

### 2. 现行文档内容校准（158 条逐条到代码/git 核实归属）

每条都必须先确定「它本来该指哪儿」再动手，分四类处理：

| 组 | 判据 | 动作 | 代表 |
|---|---|---|---|
| A 机械修正 | 路径确实存在，只是写法坏了 | 展开省略号 `dir/.../file`、brace `{a,b}.json`、补全 `frontend/` → `frontend/customer/` | `KB与信号高依赖的局限性分析与改进方向.md` |
| B 外部仓库 | 路径属于 `sop-agent` 独立仓库 | 改成仓库限定式 `<sop-agent>/scripts/x.py` | 12 篇 `sop-agent/*.md` |
| C 真失效 | 路径曾存在、后被删除或改名 | **保留原文 + 行内标注**（历史路径/曾用名/已删除 + 提交号） | `agent设计.md` §12.5 |
| D 事实错误 | 断言与现行代码不符 | 就地订正为现行事实，并保留历史表述 | `S0-Prompt构建详解.md`、`debugging.md` |

D 组里最典型的一条：`离线诊断模式数据库迁移说明.md` 写着种子文件 `07_offline_collection_specs.sql`。
`git log --all` 全历史检索，这个路径的**唯一出处**是提交 `7384ff46`（#753）里文档自己写的这一行——
文件从未存在过。这不是「路径失效」，是文档凭空捏造路径，必须直接清除。

B 组用 `<sop-agent>/...` 而不是加一条新豁免规则，理由是：`REPO_PATH_RE` 要求路径以仓库白名单前缀开头，
尖括号形式天然不被匹配，于是不新增任何豁免面就消除了歧义——比往语义词表里塞「不在本仓库」更干净。

### 3. 拒绝的两个「偷懒放宽」（对抗性审查的产物）

- **不把「未执行」加进否定词表**。`debugging.md:88` 原文「数据库**未执行** `X.sql`」是在**断言 X 存在**，
  与「X 不存在」语义相反。加这个词等于给真缺陷开后门。正确处理是改写这条断言本身。
- **不擅自把 `PR #498` 改成 `#504`**。git 里 #498 没有合并提交，feature 实为 `243e9e28`（#504）；
  但 `Agent可靠性改造任务清单.md` 又把**另一个** feature 也标成 #498。两个出处冲突且无法证伪，
  于是只重定向死链，不裁定 PR 号——「无法核实的真相」不应该被写成「另一种看起来像的真相」。

### 4. 现行层升为阻断级门禁（归零之后才能上锁）

归零不是终点：不设阻断，下一轮改动又会漂回存量。本轮把判定接进硬门禁：

- `check_docs_rot.py` 新增 `is_current_layer()` 与 `select_blocking()` 两个纯函数（分级
  判定原先内联在 `main()`，要验证它就得手工构造 git 状态，高压下只能靠人肉看输出）；
- 新增 `--current-blocking`，`ci.yml` 的「文档腐化硬门禁」改为
  `--changed-only --current-blocking`：现行层不论是否本次改动一律阻断，
  事件层/归档层仍只按本次改动行判增量；
- 现行层的口径是「非 `docs/archive/` 且路径不含 `events/` 目录段」，有意包含仓库根的
  `README.md` / `AGENTS.md`——它们同样是读者会照着行动的现行文档；
- 回归测试 `scripts/ci/test_check_docs_rot_semantics.py` 扩到 **34 项**，新增一组分级
  门禁用例，其中一条专门守护「未开 `--current-blocking` 时行为与旧版逐字一致」，
  另一条把「同行堆词可逃逸否定窗口」这一已知边界锁成受测行为（而不是留成未知坑）；
- **登记修补**：该测试文件此前在 `ci.yml` 中零命中（paths-filter / ruff check /
  ruff format / pytest 四处都是显式清单），即从未被 CI 执行过。已四处登记。
  登记当场踩到第二道坑：33 个用例函数名原为中文，而本仓库 ruff `select` 含 `N`，
  直接报 33 个 N802；已按仓库惯例改 ASCII `snake_case` + 中文 docstring（详见 V-037）。

**e2e 实测（不只看单测）**：用一次性临时提交 + 工作区注坏链验证三条口径，验完即丢弃该提交：

| 场景 | 预期 | 实测 |
|------|------|------|
| 现行层存量（README.md 非改动行的死链） | 阻断 | exit 1，报「现行层存量 1 个」 |
| 事件层存量（非改动行的 5 条历史死链） | 仅警告 | exit 0，「均不在本次改动行且不属于现行层」 |
| 事件层本次改动行新增死链 | 阻断 | exit 1，报「本次改动行 1 个、现行层存量 0 个」 |

实测还纠正了两处自己的缺陷：① 首版输出把「全部来自现行层存量」误归因为「本次改动行
引入」，已改成分开计数；② 一行里的「不存在」会连带豁免同行另一个无关坏路径，
该逃逸面已在规范 §九 写明并锁成用例。

## 决策依据（WHY）

- **为什么先修尺子**：655 这个数字本身就是决策输入。尺子误报会让「清零」变成不可能任务，
  尺子漏报会让「已清零」变成假绿灯。实测验证过一次——只修尺子（5 类语义豁免）就把现行层报错
  从 92 压到 69，即其中约四分之一**不是文档错，是检查器错**；若反过来先做内容清零，
  等于强迫作者去改一批本身正确的句子。
- **为什么 C 组选择「保留原文 + 标注」而不是删掉**：这些文档同时是缺陷成因的记录
  （如 `agent设计.md` §12.5 那两个 CRITICAL 的根因就在旧文件名上）。删掉路径就删掉了可复核的证据链。
  标注格式统一为「（历史路径，#提交号 重命名为 X）」，读者既能按现行路径行动，也能回溯当时写的是什么。
- **为什么历史标注必须同行**：窗口化判定只看同行上下文。这是刻意的紧约束——
  跨行「已删除」会让「在 200 行外写一句本篇内容已过期」变成全篇豁免，等于关掉检查。
- **为什么事件层不做同等清零**：事件文档的读者不照它行动。把 527 条史料引用「修成现行」是伪造历史，
  规范 §8.3 明确禁止。事件层只允许 §8.3.1 的事实断言订正。
