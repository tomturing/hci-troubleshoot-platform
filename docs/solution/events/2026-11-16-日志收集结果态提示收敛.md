# 2026-11-16 日志收集结果态提示收敛方案

## 背景与需求

见 [需求事件文档](../../requirement/events/2026-11-16-日志收集结果态提示收敛.md)。核心：结果态同屏出现重复、自相矛盾、无决策价值的提示，用户无法判断「到底成功没有」。

## 方案概述 (WHAT)

从「信息是否有决策价值」这一第一性判据出发，把结果态提示收敛为三层：

1. **交付事实层**：字段表（产物位置、归档状态、完整性）客观呈现，不做价值判断。
2. **唯一提示层**：仅当存在可信节点路径时，显示一条「已归档 + 路径」；无路径则完全不显示提示。
3. **错误层**：只有真正失败（`failed`/`unfinished`）才显示 fault 归因与错误码。

已交付任务的 warning 级归因（S5 `LC-5888-002`、S7 `LC-BRIDGE-005`）一律不在客户侧呈现。

## 详细设计

### 1. 后端信号抑制（`backend/case-service/app/domain/log_collect_display.py`）

`_build_stages` 中 `log_server_down` 是探测快照，只决定 P1 是否可选。P2 中转拓扑下节点直连 5888 不可达是设计预期；字节已交付后该信号既不准确也无价值。

```python
if log_server_down and not delivered:
    signals.append(("S5", "LC-5888-002", True))
```

`S5` 阶段状态仍由 `delivery_status/relay_status` 独立判定，不受影响（已交付仍显示 `success`）。

### 2. 清理提示唯一化（`frontend/customer/src/services/logCollectCleanup.ts`）

- `buildNodeCleanupTip` 无可信路径返回空串（此前返回「不提供路径」告警）。
- 命中路径时文案只保留两行：`平台保留副本供回看；…请确认归属后自行处理：` + 路径；删除「请勿触碰 …」。
- 白名单 `trustedNodeArchivePath` 不变：只接受逐字等于 `/sf/data/local/acli/tmp/data/log_collect/Q{13位}.zip` 的路径，对象 key、路径穿越、其他工单包一律拒绝。

### 3. 候选补全（`frontend/customer/src/components/LogCollectPanel.vue`）

`resultCleanupTip` 的 P2 候选从 `[nodeArchivePath, node_archive_path]` 补为 `[nodeArchivePath, node_archive_path, archive_path]`。

依据：当前 P2 任务的 `archive_path` 落的是节点绝对路径（对象 key 独立存在 `object_key`），且白名单已提供二次校验——即使历史数据把对象 key 放进 `archive_path`，也会被拒绝，不存在误展示风险。

P1 分支的「无需人工清理」三连全部返回空串。

### 4. 横幅与定界卡（`logCollectDelivery.ts` / `LogCollectFaultCard.vue` / `LogCollectStatusCard.vue`）

- `buildResultHeadline`：已 `delivered` 时提前返回，description 为空，不再拼 `fault_attribution.customer_text`。
- `LogCollectFaultCard` 新增 `showFault` prop；`LogCollectStatusCard` 结果态按 `conclusion ∈ {success, partial}` 传入 `false`，只保留阶段条，不渲染 fault 卡正文与调用链（调用链仍在横幅/详情一处保留）。
- 真失败任务的 `showFault=true`，fault 卡与错误码照常显示。

## 决策依据 (WHY)

| 方案 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| A. 仅前端隐藏文案 | 改动小、无后端风险 | admin-ui 仍误报，非根治 | ★★☆☆☆ |
| B. 仅改后端信号 | 全端一致 | 已交付但证据未回传时客户仍看到 S7 告警，不满足「只留一条」 | ★★★☆☆ |
| C. 前后端同时收敛（选中） | 后端去误报 + 前端按交付事实裁剪，根治且满足用户极简要求 | 改动面涉及类型/测试 | ★★★★★ |

对抗性审查要点：
- **误删错误信息的风险**：以 `delivered`/`conclusion` 为硬门槛，只有字节确实交付才裁剪；失败路径完全不动。
- **错误路径风险**：候选虽增加 `archive_path`，但白名单逐字校验兜底，历史对象 key 不会通过。
- **admin-ui 回归风险**：后端信号抑制后，admin 侧 S5 不再挂 `LC-5888-002`，但 S5 状态仍由交付字段独立判定，不影响管理员定位真实失败。

## 测试策略

- 构建：vue-tsc + vite build。
- 真浏览器：挂载产品 UI，逐场景验证 `Q2026111600624` 结果态只剩一条提示。
