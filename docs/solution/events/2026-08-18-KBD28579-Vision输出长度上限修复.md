# KBD28579 Vision 输出长度上限修复

## 现象

staging 环境对 KBD28579 的大尺寸截图执行“重新识图”时，页面提示：
`重新识图失败：Vision 模型输出达到长度上限，结果不完整`。

## 根因

该条目 `seq=3` 图片约 1.75 MB，属于需要完整照录文字的长截图。kb-service 未注入
`VISION_MAX_TOKENS`，代码默认值 `1536` 被模型耗尽，返回 HTTP 200 但
`finish_reason=length`。服务端按质量门禁拒绝保存不完整结果并返回 503；这是正确的
数据保护行为，但过低的默认输出预算使正常截图无法完成识别。

## 修复

- kb-service、Docker Compose 和 Helm 默认将 `VISION_MAX_TOKENS` 统一为 `8192`。
- Helm 新增 `kbService.visionMaxTokens`，允许按模型上下文窗口覆盖。
- `finish_reason=length` 仍然触发失败门禁，避免把截断 OCR 写入知识库。

部署后重启 kb-service，使新的 ConfigMap/默认值生效，再对 KBD28579 的 `seq=3`
执行“重新识图”。若模型上下文窗口小于 8192，应在环境配置中下调该值并通过图片切片
或更短 Prompt 控制输出规模。
