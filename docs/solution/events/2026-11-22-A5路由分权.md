## 一、问题

审查文档 §4-A5 判的是：注册式路由只做了「表」，没做「分权」。

- `cmd/bridge/ws_routes.go` 520 行、19 个 handler 实现全在装配层；
- 各域即使想声明「我负责哪些消息」也做不到：域 import `app` 会撞门禁禁令 6。

代码里当时的自述理由是「域反向 import `app` 会成环」。**这个理由在 A1/A2/A3 完成后已经不成立**，
但它被写进了文件头注释，等于给后来者留了一条错误的「不要迁」指令。本次一并订正。

## 二、第一性拆解

不预设"应该按域拆目录"，先问三个不可再分的事实：

| 约束 | 事实 | 推出的结构 |
|---|---|---|
| handler 需要什么 | 只有三类能力：会话表、会话生命周期、连接级状态 | 上下文缝从 `*app.Bridge` 拆成 `Hub` + `Life` + 连接字段 |
| 谁来声明路由 | 消息的业务语义在域里，装配层对它一无所知 | 路由表必须在域能 import 的位置 |
| 域不能 import 什么 | `app`（禁令 6）、其他业务域（禁令 5，基线已清空） | 表与上下文放中立层；跨域能力靠注入 |

由此确定四步顺序：**上下文缝 → 注册表 → 按域归位 handler → 跨域调用端口化**。
顺序不能颠倒：先归位 handler 再下沉表，域仍然要 import `app`。

## 三、四步落地

| 步骤 | 内容 | 关键决定 |
|---|---|---|
| 1. 上下文缝 | 新增 `internal/wsctx`：`Context{Hub,Life,WS,CUI,ConnID,Role,Sub,Owned,ActiveKey,LastInputRejectAt}`、`Lifecycle`/`Subscriber` 端口、`Route` 类型；`app.WSContext` 改别名 | **不放 `shared`**：禁令 1 禁止 shared 依赖 sshx，而它必须持有 `*session.Hub`/`*sshx.SSHSession`；强行接口化会波及所有域函数签名，属过度设计。它的真实身份是协议边缘契约 |
| 2. 注册表 | `wsctx.Register/RegisterRoutes/Lookup/Snapshot`；`app.*` 改薄委托 | 批量注册**先整体校验再一次性写入**：逐条注册若半途 panic，前 N-1 条已进表，会留下「半个域在线」的表 |
| 3. handler 归位 | delivery(4)、logcollect(1)、sftp(1)、acli(1)、terminal(3)、会话族(7) 各自 `Routes()` | 逐字移动，goroutine 边界与参数顺序不变；delivery 保持 PORT_ONLY（只取 `WS`/`CUI`） |
| 4. 跨域端口化 | `ssh_connect` 的 `logcollect.RecoverSpcRestoreIntents` 改 `terminal.SessionDeps.RecoverSpcRestore`，装配层注入 | 不端口化就归位，会立刻产生终端域→采集域的边，撞禁令 5 |

顺带归位的两个符号（否则域侧仍要 import `app`）：

- `LogSessionCreated` / `sessionKeyNode` → `sshx/session.LogCreated` / `NodeFromKey`（会话建立事件属会话所有者）
- `InputRejectNoticeInterval` → `wsctx`（它约束的是 `ctx.LastInputRejectAt` 的写频率，与业务无关）

### 一个被 CI 逼出来的真实缺陷（附误判订正）

B1 与 B3 两次被 `obslog.TestSeedFromLocalLogsSkipsUploadedRange` 挡住，报错在清理阶段：
`t.TempDir RemoveAll: directory not empty`。

**第一轮判断是错的**：本地 `-count=20` 不复现，就按「CI 环境偶发」重跑通过了。第三轮 CI 给出了
具体错误行，说明这是真缺陷而不是噪声——`DefaultHub` 是进程级单例，`withLogDir` 退出时只把
`LogDir` 改回原值，**没有关闭指向测试目录的 `logFile` 句柄**；此后任何 publish/rotate 都会在
`RemoveAll` 之后把文件重建出来。

修复（`bootstrap_test.go`）：cleanup 里先关句柄、清 `logFileBytes`，再恢复目录与 `LogDirSource`。
本地 `-count=5` 与 `-race` 均通过。教训与 A3 那次一致：**"本地跑通"不能用来否定 CI 的失败**，
要么给出机制解释，要么按真缺陷处理。

## 五、两处归属判定

**1. `bridge_log_token` 留在装配层。**
它配置的是桥自身日志通道的凭据（`obslog.LogUpload.Configure`），不属于任何业务域。
为了把装配层 handler 数「清零」而硬塞进某域，会制造一个伪归属，下一次改动反而更难找。
判据：**消息的语义归属决定位置，不是行数归属决定位置。**

**2. `wsctx` 不放在 `shared`。**
第一版曾落在 `internal/shared/wsctx`，门禁立刻报禁令 1。两种"修正"都不对：
把 `*sshx.SSHSession` 全部接口化会污染所有域签名；把 sshx 也搬进 shared 会破坏「原语不认识上层」。
正确解法是承认它是一个**新的层**（协议边缘契约），而不是硬塞进已有的层。
这一点与 A3 里「无语义小工具不进工具包」是同一条原则的反面应用：**层不对，位置就不对。**
