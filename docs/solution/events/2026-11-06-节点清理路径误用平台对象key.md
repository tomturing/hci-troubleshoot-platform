# 结果态清理提示：只给准确路径，不给删除命令

## 用户约束（最高优先级）

> 只告诉路径，让用户自行确认处理；不能提示 rm 这类删除命令。
> 一定要提供准确的路径，不要提供错误的路径，不然会误删数据。

因此本修复的输出只有两种：**一条经核对的绝对路径**，或一句**「平台不提供路径」**。
界面上不出现任何删除命令，也不给"看起来差不多"的路径。

## 现象与根因

`Q2026110600940` 走 P2 中继，9.59 GiB 包归档成功。结果态的清理提示曾拿
`task.archive_path` 拼删除命令，但该字段在 P2 下是**平台对象 key**：

```
task.archive_path = Q2026110600940/dea7ccec-e402-43fd-997b-c6f59859c509.zip
task.object_key   = 同上
```

来源见 `log_collect_upload_service.py` 的 `complete`：`task.archive_path = object_key`，
模型注释也写明「archive_* 在 P1 是节点路径」。于是用户看到的是一条相对路径，
既指向不了 HCI 节点上的包，又可能被当成可执行指令。

而节点上的真实路径来自 acli 的 `log_collect.progress` 报告，被 bridge 原样写入
`bridge_execution_logs`：

```
/sf/data/local/acli/tmp/data/log_collect/Q2026110600940.zip
```

实测该工单在 07:14:33、08:04:41、08:04:46 均报告过同一路径；全库所有工单的
节点包路径格式一致：固定目录 + `<case_id>.zip`。

## 修复设计

### 1. 服务端：随任务返回可信路径

- 新增 `services/log_collect_node_path.py`，只认一种值：
  `/sf/data/local/acli/tmp/data/log_collect/<case_id>.zip`，且 `case_id` 必须符合 `Q\d{13}`。
- 新增 `node_archive_path` 响应字段（`LogCollectTaskResponse`）。仅当
  `bridge_execution_logs` 里确实存在该工单的 `log_collect.progress` 且报告的
  `archive_path` 与目标值逐字相等时，才由 `list_tasks` / `get_task` 附加。
- 证据查询失败或查不到 → 字段保持 `None`，**绝不退回**用 `archive_path` / `object_key`
  推导；只读旁证查询异常也不会让任务列表 500。
- api-gateway 对控制面响应是原样透传（`Response(content=upstream.content)`），
  新字段无需改网关。

### 2. 前端：独立再校验一次，且只展示路径

- 新增 `services/logCollectCleanup.ts`：与后端同规则的白名单，作为最后一道闸门
  （防缓存旧响应、字段被改写、mock 数据混入对象 key）。
- 候选按可信度排序：本次会话节点对账得到的 `nodeArchivePath` > 服务端
  `node_archive_path`。
- `buildNodeCleanupTip()` 命中可信路径时**只输出路径**，并附「请确认归属后自行处理」；
  未命中时输出「当前无法确认准确路径，为避免误导，平台不提供路径」。
- 结果态 `resultCleanupTip` 与会话内 `cleanupTip` 两处都改为调用同一个生成器，
  杜绝任何一处再自行拼路径。

### 被拒绝的输入（单测锁定）

平台对象 key（相对路径）、路径穿越、任意绝对路径、其他工单的包、
带空格/后缀/大小写差异的路径、非法工单号、空值。任何一项都返回 `None`。

## 为什么不做"降级提示"

「根据工单号猜一个路径」看似友好，但一旦 acli 换了目录或包已被移走，
用户拿到的就是一条不存在的路径；而用户可能据此进行操作。**信息不确定时，
明确说"不提供路径"比给一个近似值安全得多**。

## 验证

- 后端 73 passed：路径白名单、证据查询（有/无/异常/非法工单号）、
  `list_tasks` / `get_task` 路由接线（断言对象 key 不会冒充节点路径）。
- 前端 119 passed：生成器（含"任何输入都不产生删除命令"的遍历断言）、
  组件结果态两条（有证据时展示准确路径且无删除命令；无证据时不给路径且无删除命令）、
  既有面板回归。
- `vue-tsc -b` 通过。

本单修复后，结果态会展示：

```
/sf/data/local/acli/tmp/data/log_collect/Q2026110600940.zip
```

仅为路径信息，由用户确认归属后自行决定如何处理。
