## 一、问题

设计文档 §6.1 记的债是：「`shared/reconcile/kinds/{acli,spc,config}/` 不存在，`kinds.go` 只是 Kind 枚举，消费者内联」，且"'新增链路只加 DesiredState'未验证过"。

设计给的两个选项是"建目录"或"明确废弃并说明替代守卫"。

## 二、为什么不搬目录

第一性拆解后，"kinds 目录"想解决的问题其实有两个，价值完全不同：

| 诉求 | 是否真的缺 |
|---|---|
| 骨架不认识消费者 | **不缺**。门禁「shared 禁止 import 业务域」已经把这条钉死，`reconcile` 至今只 import `remote` 与标准库 |
| 新增链路不用改骨架 | **缺的是可验证性**。四条链路的 `DesiredState` 构建散在 `acli.go` / `acli_package.go` / `log_collect_config.go`，但没有任何机制能回答"哪些链路真的接进来了、接到哪一层" |

把 `DesiredState{}` 字面量搬进 shared 目录，只会让 `kinds/acli` 需要接收 acli 域的版本判序函数、路径常量、插件清单——等于把产品语义搬进共享层，还把 `acli` 的判定函数拖走一半。这是"为设计图而搬"，不是收口。

真正缺的是**可枚举 + 可断言**。

## 三、落地：登记册

`internal/shared/reconcile/kinds/registry.go`：

```go
type Descriptor struct {
    Kind    string   // 必须来自 reconcile.AllKinds()
    Mode    Mode     // plan_activate | compare_only | intent_only | declarative
    Owner   string   // 实现所在业务域
    Explain string   // 期望态从哪来、写到哪去
    Note    string   // 尚未接入骨架的部分（债务显式声明）
}
```

四条链路的实际接入程度（由装配层 `cmd/bridge/kinds_wire.go` 登记）：

| Kind | Mode | 说明 |
|---|---|---|
| `acli_binary` | `compare_only` | 无账本，只租三态判定；节点事实是唯一真相 |
| `config_file` | `plan_activate` | Provider → DesiredState → Plan → Run → Verify 全流程 |
| `spc_slot` | `intent_only` | **只租持久还原意图，写入脚本自管** |
| `plugin_bundle` | `declarative` | DesiredState 只当"安装后落盘校验"的目标清单 |

`spc_slot` 的 `Note` 直接把缺口写死在声明里：

> 写入未接 Plan/Activate：自愈顺序（先放回历史备份再备份）与 cmp 保真校验骨架尚未表达，硬接会破坏 golden 命令序列

## 四、守卫

| 守卫 | 位置 | 拦住什么 |
|---|---|---|
| `Registry.Missing()` 为空 | `cmd/bridge/kinds_wire_test.go` | 新增 Kind 但没在装配层登记（"定义了链路却没人接"） |
| `Mode/ Owner / Explain` 非空且合法 | 同上 | 只登记名字、不声明接入程度 |
| `intent_only` 只有 `spc_slot` | 同上 | 又有链路悄悄退化成"写入自管"而不更新债务说明 |
| `AllKinds()` ↔ `ValidKind` 双向一致 | `reconcile/allkinds_test.go` | 加 Kind 忘改 switch（守卫静默失效） |
| `Register` 侧校验 | `kinds/registry_test.go` | 未知 Kind / 非法 Mode / 重复登记 / 空说明 |

`MustRegister` 在装配期 panic：链路声明错误意味着编排走错分支，运行期才暴露会表现为"同步成功但节点没变更"，极难定位。

## 五、验收

- `go test ./internal/shared/reconcile/... ./cmd/bridge/` 通过；守卫测试会打印四条链路的 mode/owner/explain/note（可直接对账）
- 全量 `go test ./...` 绿；`gofmt -l` 空；`go vet` 无输出
- `go build -tags telemetry` 与 `GOOS=windows` 通过
- 门禁 `check_bridge_imports.py`：域间依赖边仍为 0（`kinds` 只 import 父包，不碰业务域）

## 六、遗留

`spc_slot` 的写入仍未接骨架。要接必须先给骨架补两项能力：

1. **写前自愈**：把历史备份放回 target 后再备份（否则本次备份存下的是上次的平台清单）；
2. **保真校验**：备份与原件 `cmp -s` 逐字节比对，且只在"本次刚创建备份"的分支执行。

这两项是 SPC 在 2026-11-17 与 2026-11-20 两次误报事故后形成的硬约束，不能为了"结构统一"简化。登记册已把这件事变成显式事实，不再是隐性债务。
