# 信号抽取超时链路倒置修复（2026-09-15）

## 问题现象

KBD 条目详情页点击「重新抽取关键信号」按钮，前端弹出错误：

```
重新抽取关键信号失败：KB Service unavailable
```

## 根因分析

### 超时链路倒置

`kb-service` LLM 最长总耗时（120s × 3次 = ~360s）> `api-gateway` 代理超时（240s）。

当 api-gateway 在等待 241s 后先触发 `httpx.TimeoutException`（属于 `httpx.RequestError`），
被 `_kbd_proxy` 捕获并返回误导性的 `"KB Service unavailable"`，而不是实际的 LLM 超时原因。

真实底层错误：`glm-5.3-flash` 在处理 16384 token 的 JSON 输出时响应超时。

## 修复方案

引入 `EXTRACT_SIGNALS_LLM_TIMEOUT` 专属超时变量（默认 70s），满足：

```
EXTRACT_SIGNALS_LLM_TIMEOUT × LLM_MAX_ATTEMPTS < api-gateway 代理超时
70s × 3 = 210s < 240s  ✓
```

## 变更文件

- `backend/kb-service/app/routes/extract_signals.py`：使用 `_EXTRACT_LLM_TIMEOUT` 专属超时
- `deploy/helm/hci-platform/templates/configmap.yaml`：注入 `EXTRACT_SIGNALS_LLM_TIMEOUT`
- `deploy/helm/hci-platform/values.yaml`：新增 `extractSignalsLlmTimeoutSec: "70.0"`
