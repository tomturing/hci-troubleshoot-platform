# SRC-L1 管理台身份上下文收敛 与 L3 工单归属可观测 设计方案

> 关联需求：[2026-10-08-SRC-L1管理台身份上下文收敛与L3工单归属可观测需求](../../requirement/events/2026-10-08-SRC-L1管理台身份上下文收敛与L3工单归属可观测需求.md)
> 日期：2026-10-08

## 一、总体思路

身份上下文（`X-Tenant-ID` / `X-Actor-ID`）的唯一可信来源收敛为 **网关对 admin JWT 的派生**，
删除 nginx/helm/compose/契约中所有静态注入与透传默认值；L3 以**只读审计**固化归属完整性。
**不改 api-gateway/diagnosis-service 运行时逻辑**——`_resigned_upstream_headers` 的
admin-realm 派生分支（`routes/diagnosis.py:127-129`）已是正确实现，本次仅用单测锁定并
清除上游死配置。

## 二、身份传播架构（收敛后）

```
浏览器(已登录 admin) --JWT--> admin-ui nginx --透传 Authorization--> api-gateway
   │ nginx 不再发送 X-Tenant-ID/X-Actor-ID（既不写死也不透传）
   ▼
IdentityMiddleware 验签 JWT → state.auth(realm=admin,user_id) → is_admin
   ▼
_resigned_upstream_headers:
   realm=admin → X-Tenant-ID = AUTH_DEFAULT_TENANT_ID（服务端配置，非客户端）
                 X-Actor-ID  = user_id（来自 JWT sub）
   customer   → X-Tenant-ID = default, X-Actor-ID = cust-<client_id>
   回退共享令牌(enforce=false,无JWT) → 读客户端头（现已无 nginx 伪造）→ 缺省兜底 default/gateway-admin
   ▼
diagnosis-service InternalTokenIdentityVerifier 信任网关重签头（零回归）
```

关键点：网关对下游身份头是**白名单重建**（`FORWARDED_REQUEST_HEADERS` 不含
X-Tenant-ID/X-Actor-ID），故移除 nginx 注入不会让任何客户端伪造值直达下游；
`X-Tenant-ID`/`X-Actor-ID` 在网关被无条件覆盖。

## 四、L1 防回退守卫

- `scripts/verify/verify_identity_resign.py`：
  - 场景 2（静态注入）扫描面由 `frontend/customer/nginx.conf` 扩为**同时**覆盖
    `frontend/admin/nginx.conf`，禁止出现 `proxy_set_header X-Tenant-ID/X-Actor-ID/X-User-ID`
    （`Authorization $http_authorization` 透传不在此禁令内）。
  - 场景 2b：渲染产物 admin-ui Deployment 容器 env 前缀白名单新增 `ADMIN_API_TENANT_ID`/
    `ADMIN_API_ACTOR_ID` 命中即报错（与既有 `CUSTOMER_API_*` 同构）。
  - 更新脚本 docstring：admin 侧收敛已完成。
- 网关单测 `backend/api-gateway/tests/unit/test_diagnosis_proxy.py`：新增
  `test_admin_jwt_realm_derives_tenant_and_actor_ignoring_self_report`——以 fake
  verifier 注入 `GatewayActor(realm=admin, audience=AUTH_JWT_AUD_ADMIN, user_id=admin-1)`，
  请求携带 `X-Tenant-ID: attacker-tenant`/`X-Actor-ID: spoofed`，断言上游
  `X-Tenant-ID == settings.AUTH_DEFAULT_TENANT_ID`、`X-Actor-ID == "admin-1"`。

## 五、L3 只读审计设计

新增 `scripts/verify/verify_case_ownership.py`（纯 Python，无框架耦合）：

- **纯函数** `classify_client_id(value) -> Literal["ok","empty","placeholder","null","anon_shape_ok"]`
  可脱离数据库单测：空串/NULL/`client-session-placeholder-token`/纯空白 → 异常；
  `client-<随机>`、`hci-sim-admin`、32-hex、`regression-client` 等 → 归属形态合法（平台
  无客户登录，`client_id` 即 Cookie 归属键，存在即可回访，非孤儿）。
- **连库审计模式**（可选 `--database-url` 或 `DATABASE_URL` env，psycopg/asyncpg 择一可用）：
  只读 `SELECT` 统计：总数、异常归属（empty/placeholder/NULL）、conversation 无对应 case、
  case.user_id 无对应 user（若 user 表存在）。默认**只报告、不改数据**；`--strict` 时
  异常数>0 则非零退出，用于运维巡检/发布前门禁。
- CI 无库环境：脚本以纯函数单测为主（pytest 不需 DB）；连库模式标注为运维手动执行。

### staging 现状结论（本次已登库实测 2026-10-08）
- `"case"` 453 行：空 client_id = 0、占位 token = 0、client_id IS NULL = 0、
  `case.user_id` 无对应 `"user"` = 0、`conversation` 无对应 `case` = 0。
- client_id 形态：`client-<随机>` 228（正常会话）、`hci-sim-admin` 212（仿真系统身份）、
  其余为测试种子（`regression-client`/`client-conv-*` 等）。
- **判定**：无归属完整性缺陷；"匿名工单"是"无客户登录、以 Cookie client_id 为归属键"
  模型的设计固有属性，Cookie 丢失即不可回访，**不可用 SQL 判定、不得删除**（毁真实数据）。
  故 L3 以"可观测审计 + 契约"收口，非数据清理。

## 六、回滚与风险

- 回滚=还原上述文件即可（无 DB schema 变更、无运行时逻辑变更）。
- 风险点与消解：
  1. **透传回退更糟** → 四处联动删净，verify 守卫兜底。
  2. **admin-ui 滚动重启语义丢失**（删 checksum 注解）→ admin-ui 已不持任何内部身份，
     无需因 secret 轮转而重启，语义本就失效，删除是纠偏。
  3. **config-contract 漂移** → 同步删契约，CI `REQUIRE_HELM=1 config-contract-check` 把关。
  4. **helm test 断言方向** → 显式翻转为 notContains/isNull，`helm unittest --strict` 把关。
