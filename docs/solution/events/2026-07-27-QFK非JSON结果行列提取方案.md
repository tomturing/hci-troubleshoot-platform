# QFK 非 JSON 结果行列提取方案

## 背景与需求

`acli system` 下大量命令只是 Shell 原生命令的封装，`--formatter json` 对 `ps auxf` 等命令并不会把输出变成 JSON。人工审核人员需要像 grep/awk 一样按行、按列定位结果，但平台不能开放任意管道。

## 方案演进

第一版通用 ETL 设计曾包含 `ExecutionArtifact`、raw/json/lines/whitespace_table/delimited_table/key_value/regex_capture、where/select/cardinality/type cast 和管理端解析预览。能力完整，但简单信号需要约十个字段，且没有先解决完整 stdout，因此不符合“AI 初抽取 + 人工快速审核”的当前阶段。

| 方案 | 结论 | 原因 |
|------|------|------|
| 直接开放 Shell 管道 | 拒绝 | 命令注入、能力扩张和审计边界不可控 |
| 暴露 grep/awk 原始脚本 | 不采用 | 会逐步演化成受限 Shell/awk 解释器 |
| 十字段通用解析器 | 暂缓 | 表达力强，但审核 UX 过重 |
| 行筛选 + 值提取 | 采用 | 覆盖高频场景，心智模型成熟，结构可校验 |
| 专用 acquirer | 补充 | 用于聚合、跨行计算等少量复杂场景 |

## 方案（WHAT）

```text
完整物理流
→ 按行拆分
→ 包含/不包含筛选
→ 匹配数量校验
→ 整行/第 N 列/从第 N 列到末尾
→ 类型转换
→ 写变量池
```

### 数据契约

JSON 保持现有 `path`：

```json
{"name":"HOST_IP","type":"string","path":"data.0.ip|ip"}
```

文本使用受控 `extract`：

```json
{
  "name": "KVM_PID",
  "type": "integer",
  "extract": {
    "type": "text",
    "include": ["-id {{VM}}"],
    "column": 2,
    "column_mode": "index"
  }
}
```

`path` 与 `extract` 互斥。默认值为 source=stdout、连续空白分隔、trim、区分大小写、多 include 为 AND、标量必须唯一匹配。高级项支持 exclude、大小写、AND/OR、单字符分隔、first/last/all、stdout/stderr。

### 完整输出

展示仍使用 `ExecResult.stdout ≤ 4000`、`stderr ≤ 1000`。提取时：

- 未截断：直接读取物理流。
- 截断：stdout 读取 `cmd_cache:{exec_id}`，stderr 读取 `cmd_stderr_cache:{exec_id}`。
- 缓存丢失：`QFK_OUTPUT_TRUNCATED_SOURCE_UNAVAILABLE`，不降级。
- 默认上限 1 MiB，硬上限 4 MiB；超限要求专用采集器缩小结果集。
- stdout 与 stderr 不拼接。

### 错误语义

稳定错误码包括 `QFK_OUTPUT_EMPTY`、`QFK_NO_MATCH`、`QFK_MULTIPLE_MATCHES`、`QFK_COLUMN_OUT_OF_RANGE`、`QFK_TYPE_CAST_FAILED`、`QFK_EXTRACT_INVALID_SPEC`、`QFK_OUTPUT_TOO_LARGE`。任何错误都不写空变量，当前信号为 ERROR，依赖它的后续信号不执行。

### AI 抽取与确定性转换

Prompt 引导与纯函数转换器双重保障：

| 安全子集 | 结构化结果 |
|----------|------------|
| grep / grep -e / grep -F | include |
| grep -v | exclude |
| grep -i | case_sensitive=false |
| `awk '{print $N}'` | column=N |
| cut -dX -fN | delimiter=X + column=N |
| grep -v grep | 删除 |

转换器使用 shlex tokenizer，只识别白名单且从不执行输入。复杂 awk、sed、sort、未知段或含正则歧义时返回 needs_review；原 evidence 与错误原因保留。

### 管理台

简单模式显示变量名、类型、输出格式、筛选行和提取值；高级默认折叠。检测到管道时不能保存，用户可点击“安全转换管道”预览并应用。输入变量从 args/include/exclude 的 `{{VAR}}` 自动推导，只读展示。

### 真实样例

原命令：

```bash
acli system ps auxf | grep -e '-id 8243094091404' | grep -v grep | awk '{print $2}'
```

保存后宿主机命令为 `acli system ps auxf`，extract 为 include=`-id {{VM}}`、column=2、type=integer、name=KVM_PID。`grep -v grep` 被删除，因为平台没有启动 grep 进程。

## 决策依据

本方案保留 grep/awk 的行列心智模型，但把能力限制为数据结构而非脚本语言；Schema 能静态校验，运行时能确定性执行，管理台能用少量字段呈现。它首先解决完整输出与 Fail Closed，再提供 UI，避免“页面能配置、运行时从截断摘要取错值”。
