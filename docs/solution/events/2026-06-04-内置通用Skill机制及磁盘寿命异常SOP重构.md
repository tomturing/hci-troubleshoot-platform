# Artifact Archival, Deprecation Cleanup, and Code Decommissioning Implementation Plan

本方案旨在针对上轮任务遗留及代码库清理需求，实施以下四项工作：
1. **多环境 Git Hook 归档自动化**：解决上轮 pre-commit hook 仅在本地生效的问题，通过 package.json 的 prepare 钩子实现多开发环境及 CI 管道中 Hook 的无感配置。
2. **废弃 Vibe Kanban (VK) 清理**：基于第一性原理，清理已被废弃的 VK 相关配置文件、Makefile 目标及 CI 脚本中的 VK 引用。
3. **Gateway 路由文件重命名**：将 `api-gateway` 路由中混合代理 `tools`、`skills` 和 `prompts` 的 `tools_prompts.py` 重命名为更契合架构定义的 `capabilities.py`。
4. **后端僵尸代码与废弃模型下线**：清理 `backend/` 下未被引用、已废弃或被持久化机制取代的僵尸文件和废弃内存模型。

## Proposed Changes

### 1. 多环境 Git Hooks 自动配置

#### [MODIFY] [package.json](file:///mnt/d/aihci/hci-troubleshoot-platform/frontend/package.json)
- 在 `scripts` 中增加 `"prepare"` 钩子，配置在运行 `pnpm install` 时，自动利用 git 特性将 core.hooksPath 指向当前仓库绝对路径下的 `scripts/git-hooks`：
  ```json
  "prepare": "git config core.hooksPath \"$(git rev-parse --show-toplevel)/scripts/git-hooks\" || true"
  ```
- 从而使任何克隆了此仓库并在新开发环境、容器、CI 中运行安装步骤的开发者自动激活 Pre-commit 归档 Hook。
