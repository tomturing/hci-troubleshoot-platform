# 「日志收集」图标在 Windows/Edge 显示成黑块：emoji 默认文本呈现的坑

## 一、现象

Windows Edge 下，顶栏「日志收集」按钮与建单后的引导卡片图标显示为一个压扁的黑色小方块
（看起来像打印机/黑块）；同一页面的「✅ 关闭工单」「📋 工单信息」显示正常。

## 二、根因（第一性原理）

图标用的是裸 emoji `🗂`（U+1F5C2 CARD INDEX DIVIDERS），**不带变体选择符 U+FE0F**。

Unicode 中每个 emoji 都有 `Emoji_Presentation` 属性：

| 字符 | 码位 | 默认呈现 | Windows 实际字体 |
|---|---|---|---|
| 🗂 | U+1F5C2 | **text**（默认文本） | Segoe UI Symbol → **单色细线字形** |
| 📋 | U+1F4CB | emoji | Segoe UI Emoji → 彩色 |
| ✅ | U+2705 | emoji | Segoe UI Emoji → 彩色 |
| 📦 | U+1F4E6 | emoji | Segoe UI Emoji → 彩色 |
| ⚙️ | U+2699 U+FE0F | 显式 VS16 | Segoe UI Emoji → 彩色 |

所以不是"字体缺失"，而是 `🗂` **默认就是文本字形**：Windows 落到 Segoe UI Symbol，
在 16~22px 下细节糊成一团。macOS 的 Apple Color Emoji 对该码位有彩色字形，所以在 Mac 上看不出问题
（跨平台差异的典型来源）。而 `⚙️` 因为显式带了 VS16 才正常。

## 三、修复选择

| 方案 | 结果 | 取舍 |
|---|---|---|
| 加 VS16（`🗂️`） | Windows 变彩色 | 仍依赖系统 emoji 字体，风格随平台变，小尺寸细节依旧糊 |
| 换 SVG 图标（采用） | 跨平台一致、尺寸/颜色可控 | 需要引入图标组件（项目已用 `@element-plus/icons-vue`） |

实现：`FolderOpened`（Element Plus）替换两处 `🗂`，与顶栏 `SSH终端` 的 `Monitor` 用法保持一致；
引导卡片的 `.guide-icon` 用 `color: var(--el-color-primary)` + `flex: none` 固定尺寸与配色。

## 四、盘点

用 Unicode 官方 `emoji-data.txt` 逐个码位核验，而不是凭「看起来正常」判断：

```
🗂  U+1F5C2  Emoji_Presentation=No   App.vue / LogCollectEntryCard   ← 默认文本，已修
🖥  U+1F5A5  Emoji_Presentation=No   MessageBubble                    ← 文本默认，靠 VS16 才彩色
⚠  U+26A0   Emoji_Presentation=No   MessageBubble(3 处裸字符)         ← 无 VS16 → Windows 单色细线
▶  U+25B6   Emoji_Presentation=No   MessageBubble(折叠箭头)           ← 文本字形，颜色不受控
▼  U+25BC   非 emoji（几何图形）     MessageBubble(折叠箭头)           ← 字体缺失时可能空白
✓  U+2713   非 emoji（Dingbats）     DiagnosticProgress(步骤完成)      ← 同上
📋  U+1F4CB  Emoji_Presentation=Yes  App.vue / EnvironmentSummary / MessageBubble   正常
📦  U+1F4E6  Emoji_Presentation=Yes  EnvironmentSummary                             正常
⚙  U+2699   需 VS16（文件中已带）     MessageBubble                                  正常
```

规则：**图标不要用 `Emoji_Presentation=No` 的裸 emoji**（🗂 🖥 ⚠ ▶ ✓ 这类），要么补 VS16，
要么用 SVG/图标——后者是唯一不依赖终端用户系统字体的方案。

## 五、统一收口（customer 端全部图标位）

即使 `Emoji_Presentation=Yes`，emoji 仍是「彩色位图、风格随平台变、不受 `color` 控制」。
因此 customer 端把 **所有图标位**统一改为 Element Plus 图标组件（内联 SVG）：

| 位置 | 原字符 | 现图标 |
|---|---|---|
| 语义入口卡标题（MessageBubble） | 🔎 | `Search` |
| 控制台截图观察 / 近黑屏唤醒卡 / 终端回显折叠头 | 🖥️ | `Monitor` |
| 操作效果复核卡标题 | 🎯 | `Aim` |
| 变量输入 / 变量确认 / SOP / 信息确认 卡标题 | 📋 ❓ | `EditPen` / `Select` / `Document` / `QuestionFilled` |
| 视觉复核提示、执行确认卡 | ⚠（裸）⚠️ | `Warning` |
| 工具调用头 | ⚙️ | `Setting` |
| 参数列表折叠头 | 🔧 + ▶/▼ | `Tools` + `ArrowRight` / `ArrowDown` |
| 诊断依据摘要标题栏 | ⓘ | `InfoFilled` |
| 诊断步骤条完成态 | ✓ | `Check` |
| 终端面板连接按钮 / 终端历史 / 关闭 | 🖥 📹 ✕ | `Monitor` / `VideoCamera` / `Close` |
| 终端回放播放控制 | ◀ ⏸ ▶ | `ArrowLeft` / `VideoPause` / `VideoPlay` / `ArrowRight` |
| SSH 表单自动填充提示 | 💡 | `InfoFilled` |
| 顶栏/建单/SSH/环境摘要/命令块 | 🗂 📋 ✅ ❌ 🔄 ⬇ | `Tickets` `Finished` `Warning` `Refresh` `Download` `CircleCheck` `CopyDocument` `Upload` `Box` `Bell` 等 |

图标与文字的对齐统一用 `display:flex/inline-flex + align-items:center + gap:6px`，
不再用 `margin-right` 或全角空格凑间距（emoji 宽度随字体变化，margin 无法对齐）。

**刻意不动的两处**：

1. `①`~`⑨`（选项序号）与 `▊`（流式输出光标）——属文案/光标，不是图标位；
2. `stores/chat.ts` 里注入对话流的 `> 🔍 正在查询` / `> 🤔 步骤` / `⚠️ 高危命令已自动拒绝`
   ——这些是 markdown 正文内容，要改必须走 HTML 注入，风险大于收益；且三者均为
   `Emoji_Presentation=Yes` 或带 VS16，Windows 下正常显示。

`el-dialog` / `el-alert` 的 `title` 是纯文本通道，无法嵌组件，因此这两处只删 emoji 不加图标
（`ConfirmDialog` 的风险等级已由 `el-alert` 的 `type=error|warning` 表达）。

  交互卡标题必须渲染图标组件）、`vue-tsc -b`、`pnpm build` 通过；
