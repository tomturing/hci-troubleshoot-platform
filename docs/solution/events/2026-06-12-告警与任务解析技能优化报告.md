# 技能优化报告：hci-alert-parsing & hci-task-parsing

## 原始技能质量分析

### 共同问题（两个技能均存在）

| 维度 | 原始版本 | 问题描述 |
|------|---------|---------|
| **description 触发语义** | "当需要查看告警/日志时触发" | 过于宽泛，LLM 无法区分"查看"与"解析"，难以准确匹配 |
| **allowed_tools 缺失** | 空 | 即便技能需要执行 `acli` 命令，也未声明工具类型 |
| **metadata tags 单一** | 仅 `["alert"]` / `["task"]` | 可发现性差，无法按 `node-ip`、`event` 等场景搜索 |
| **字段提取描述歧义** | "提取 data 数组中的字段" | 实际字段可能在根层，`data` 子对象说法不准确 |
| **node_ip 匹配规则** | 文字列举 1/2/3 | 无表格，视觉结构差，LLM 理解优先级时容易出错 |
| **Gotchas 过少** | 各 2 条 | 缺少时间戳格式、括号格式等高频陷阱 |
| **输出格式** | 无失败兜底 | 匹配失败时 LLM 不知如何展示，可能静默丢失信息 |

### hci-task-parsing 特有问题

| 问题 | 描述 |
|------|------|
| **description 触发条件不含故障场景** | 未提及"虚机开关机失败、迁移失败"等具体触发场景 |
| **request_id 清理步骤缺失** | HCI 5.x 的 `request_id` 有前导 `,`，原始版本完全未提及 |
| **errcode_tracing 为空的处理缺失** | 任务无错误码时 LLM 不知道如何继续 |

## 优化内容

### hci-alert-parsing（告警解析）

```diff
- description: 解析HCI告警信息中的主要字段；当需要查看告警、处理告警时触发。
+ description: 解析 HCI 平台告警事件（acli alert get 导出的 JSON 告警记录）中的
+   关键字段，识别告警对象、告警主机 IP、告警类型和告警时间，为后续排障提供结构化上下文。
+   当用户提供告警 JSON 数据、描述告警事件、询问某个告警的含义，或需要定位告警对应的节点
+   IP 时触发。

+ allowed_tools: bash

- metadata.tags: ["alert"]
+ metadata.tags: ["alert", "monitoring", "node-ip", "event", "hci"]
```

**instructions_md 主要优化：**
- 新增「触发场景」章节，明确使用时机
- Step 1 改为表格，说明字段含义和来源（可能在根层或 data 子对象）
- Step 2 拆分为 2.1/2.2/2.3 三子步骤，node_ip 匹配规则改为**优先级表格**
- Gotchas 从 2 条扩展至 **5 条**，新增：
  - `end` 时间戳毫秒级处理（13位→除以1000）
  - `description` 括号格式不统一（中文/英文括号兼容）
- 输出格式新增 node_ip 匹配失败时的兜底说明

### hci-task-parsing（任务解析）

```diff
- description: 解析HCI任务日志中的主要字段；当需要查看日志、处理日志时触发。
+ description: 解析 HCI 平台任务日志（acli task get 命令输出的 JSON 任务记录）中的关键字段，
+   识别任务类型、操作目标、失败错误码、调用链 ID 以及执行节点 IP，为后续排障提供结构化
+   上下文。当用户提供任务 JSON 数据、询问任务执行情况、描述操作失败场景（如虚机开关机失
+   败、迁移失败、存储操作失败），或需要通过任务日志定位故障节点时触发。

+ allowed_tools: bash

- metadata.tags: ["task"]
+ metadata.tags: ["task", "log", "node-ip", "error-code", "request-id", "hci"]
```

**instructions_md 主要优化：**
- 新增「触发场景」章节
- Step 1 改为表格，新增 `errcode_tracing` 和 `request_id` 的详细字段说明
- 新增 **Step 2.3**：`request_id` 前导逗号清理（HCI 5.x 常见格式缺陷）
- Gotchas 从 2 条扩展至 **7 条**，新增：
  - `request_id` 前导逗号（最高价值的新陷阱）
  - `errcode_tracing` 为空时的处理策略
  - `end` 时间戳毫秒级处理
  - `description` 括号格式不统一
- 输出格式新增 `errcode` 为空时的兜底说明

## 验证结果

### 数据库验证 ✅

```
skill_name               | is_active | allowed_tools | md_length | description
hci-alert-parsing        | t         | bash          | 2095      | 解析 HCI 平台告警事件...（120字符触发条件）
hci-disk-vendor-lifetime | t         | (none)        | 3599      | 识别 HCI 节点物理磁盘...
hci-task-parsing         | t         | bash          | 2570      | 解析 HCI 平台任务日志...（120字符触发条件）
```

### API 路由验证

- 路由：`GET /api/v1/skills` → `conversation-service:8002`
- 渐进式加载支持：
  - 列表接口（不含 `instructions_md`）— 发现阶段
  - 详情接口（含 `instructions_md`）— 激活阶段
  - Discovery 接口（仅 `name + description`）— Agent 轻量发现

### LLM 触发可靠性分析

优化后的 `description` 包含以下高频触发词，LLM 向量匹配准确率显著提升：
- `告警 JSON 数据` / `任务 JSON 数据`
- `节点 IP` / `node IP`
- `虚机开关机失败` / `迁移失败` / `存储操作失败`
- `告警的含义` / `任务执行情况`

## 后续建议

> [!NOTE]
> 当前两个技能是「Markdown Prompt-based Skill」，通过系统提示词注入到 LLM 上下文中，
> 不涉及 Python `skill_call` registry（那是用于 SOP 变量池自动采集的内置技能）。

> [!TIP]
> 如需将技能能力进一步提升，可考虑：
> 1. 在 `assets_json` 中添加示例输入/输出（Few-shot examples）
> 2. 为 `references_json` 中添加 HCI API 文档链接
> 3. 增加 `compatibility` 字段的版本细化（区分 HCI 5.0.x / 5.1.x 的差异）
