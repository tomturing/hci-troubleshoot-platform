# AI 智能推导与确定性复算实现

## 问题

KBD 41398 的主机时间输出包含多个日期文本。旧的 `ai_extract` 只能返回候选行中
逐字存在的值，因此模型计算出的秒差（例如 `300`）无法通过原文回查，最终报
`QFK_AI_EXTRACT_FAILED`。为该场景新增 `clock_skew` Matcher 会让案例数量驱动
运行时类型膨胀，无法覆盖同类的时间、版本、容量和状态归一化需求。

## 设计

`ai_extract.mode` 缺省为历史兼容的 `extract`，明确指定 `derive` 时使用智能推导。
AI 不提交比较结论或归一化数值，只提交逐行可回查的 `source_value`；代码按受控
格式、时区和 normalizer 把源值转换为数值，再复用既有 Matcher。

```text
完整 stdout
  -> 确定性候选行选择
  -> AI 返回 records[].source_value + evidence_lines
  -> 原文逐字回查
  -> datetime_epoch 代码归一化
  -> threshold aggregation=range
  -> operator/value/expected 的确定性判定
```

这条路径没有案例专用 Matcher。`range` 是 `threshold` 的通用聚合，表示所有数值
样本的 `max - min`，且少于两项时返回无法定值。

## 配置示例

```json
{
  "type": "threshold",
  "aggregation": "range",
  "operator": ">",
  "value": 2,
  "expected": true,
  "extract": {
    "type": "text",
    "rows": {"mode": "all"},
    "cardinality": "all",
    "source": "stdout",
    "ai_extract": {
      "mode": "derive",
      "instruction": "从每行识别主机系统时间",
      "derive": {
        "normalizer": "datetime_epoch",
        "formats": ["%a %b %d %H:%M:%S %Z %Y"],
        "timezone": "Asia/Shanghai"
      }
    }
  }
}
```

对于 `11:05:24`、`11:00:24`、`11:00:26`，AI 必须分别返回原文时间和对应行号；
代码计算极差 `300`，再确定性判断 `300 > 2` 为真。AI 直接返回 `300`、epoch 或
不存在于引用行的时间文本都会失败。

## 管理端交互

QFK 的“第一步：取值”和 QKV 的“提取方式：AI”均显示相同的 AI 处理方式：

```text
AI 处理方式  [ 原文取值 ] [ 智能推导 ]
处理说明 *    [................................]
提取类型      [ 日期时间 -> Unix 秒 ]
结果数量      [ 全部候选行 ]
时间格式      [ %a %b %d %H:%M:%S %Z %Y ]
时区          [ Asia/Shanghai ]
```

选择“原文取值”保持旧配置兼容，并只在确定性 feature/split 无法取值时作为兜底。
选择“智能推导”会强制走 AI 源值标注与代码归一化主路径，并保存
`ai_extract.mode=derive` 和归一化配置；QKV 同时将目标变量限制为数组，避免把多个
时间样本错误写入标量变量。

## 安全与可观测性

- `records` 只能含 `source_value` 和 `evidence_lines`，每条源值在其自身引用行中
  逐字回查；AI 不能跨行借证据或直接输出推导结果。
- `formats`、IANA `timezone`、normalizer 和结果类型在保存时校验；未知模式、字段和
  时区全部拒绝。
- QFK 记录 `qfk_ai_extract_started/finished/failed` 日志、Langfuse observation 和
  `otel_trace_id`；新增 `hci_qfk_ai_processings_total` 与
  `hci_qfk_ai_processing_duration_seconds`，按有限的 `extract/derive` 模式区分终态。
