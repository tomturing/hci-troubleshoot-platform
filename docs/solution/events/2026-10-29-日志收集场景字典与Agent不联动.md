# 日志收集场景字典与 Agent 不联动

## 一、现场提出的三个问题

1. 点开「日志收集」后，右侧排障 Agent 仍然并排可见，用户以为可以让 Agent 参与收集日志；
2. 右侧应该展示登录后的 SSH 终端（采集本来就在终端里跑 `acli log_collect`）；
3. 截图里 acli 透出的「故障场景」十几项，用户不知道每一项收什么、该选哪个。

前两条是**界面语义**问题，第三条是**信息缺失**问题，但它们的根因是同一个：
日志收集这条路的能力边界从来没在界面上说清楚。

## 二、先核实的三条事实（推翻了此前的默认理解）

改代码之前先把「现在到底怎么跑」查清，否则容易改错地方：

| # | 原本的（错误）理解 | 核实结果 |
|---|---|---|
| 1 | 「故障场景」10 项由集群 acli 透出 | **不是**。`parseLogCollectModuleCatalog` 只用来确认集群支持 `-m` 枚举；label 与顺序一律取 `terminal_bridge/log_collect.go` 的 `logCollectModuleLabels` + `logCollectModuleCatalogOrder`。面板上「目录来自集群 acli」的真实含义只是「集群返回过至少一个枚举」 |
| 2 | 默认勾选项与工单症状有关 | 恒为 `vm_suspend`（`form.modules` 初值），与工单内容无关 |
| 3 | 后端会挡住互斥组合 | **不会**。后端只校验枚举白名单 + 去重，`-m other,vm_suspend` 可以同时提交 |

另外两条实现层面的约束，直接决定了方案选型：

- `TerminalPanel` 的 `onBeforeUnmount` 会调用 `disconnectSSH()`。任何导致组件卸载的“搬位”
  （例如把 xterm 实例挪到中央区）都会**断掉用户的 SSH 会话**；
- `enforceOverlayExclusive('right')` 在窄屏下开右栏会反向关闭 `logCollectVisible`。
  自动开终端时若不先判 overlay，会把用户刚打开的日志面板关掉。

## 三、方案

### 3.1 中央 Agent 隐藏 + 复用右栏终端（不搬 xterm）

| 选项 | 结论 |
|---|---|
| 把 xterm 组件搬到中央区 | ❌ 组件卸载 ⇒ `disconnectSSH()` ⇒ 会话中断 |
| 中央留白收起 + 复用右栏终端 | ✅ 宽度让给日志表格与终端，会话零风险 |

- `resolveWorkspaceLayout` 新增 `centerHidden` 入参：单开取 `viewport - RAIL_WIDTH(48)`
  并允许突破 `leftMax/rightMax`；双开时左栏 `clamp(偏好比, leftMin, leftMax)`、右栏吃掉全部剩余，
  两栏之和恒等于视口，`centerMaxWidth` 返回 0；
- `App.vue` 的 `<main>` 收为 `flex: 0 0 0; width: 0; overflow: hidden`——**不能用 `display:none`**，
  否则两侧不会重新分配像素；`ChatWindow` 用 `v-show`，会话消息、滚动位置、输入草稿必须保留；
- overlay 分支**忽略** `centerHidden`（覆盖态本来就是一次看一块）；
- 三种情况不隐藏、改为标题栏常驻 `el-tag`「日志收集进行中 · 与排障 Agent 不联动」：
  SSH 未连接、bridge 未运行、右栏被文件下载占用。这时藏掉 Agent 只会让中间空一块。

自动切终端用 `watch(logCollectVisible)`，一处覆盖 header 按钮、rail 图标、建单引导卡、
工单号弹框四条入口；前置条件是 `sshConnectionState === 'connected'`、右栏未被文件下载占用、
且「两侧都开」的求解结果不是 overlay。**关闭日志收集不关右栏终端**——那条会话用户可能还在用。

### 3.2 故障场景字典（入库 + 管理端可维护）

字典只描述**展示事实**，不定义能力边界：

```
acli probe（能力边界）  ──┐
                          ├─→ 交集 = 客户端可选场景
log_collect_scenario（文案）─┘
```

- `database/desired_schema.sql` 新增表 `log_collect_scenario`（Atlas 声明式，唯一权威）；
  `database/data-migrations/056_log_collect_scenario_seed.sql` 幂等 seed 10 行
  （`ON CONFLICT (value) DO NOTHING`）；
- case-service：客户读 `GET /api/log-collect/scenarios`（只出 `enabled`，按 `sort_order, value`）；
  管理端 `/internal/log-collect/scenarios`（`require_admin_token`，`value` 不可改，写操作落
  `operation_audit`）；
- api-gateway：客户读单独一条 `GET /api/log-collect/scenarios`（**不复用** `/tasks{path}` 前缀代理，
  那条按工单归属做 BOLA，而字典是平台级配置）；管理端 `/api/v1/log-collect-scenarios` 以
  `INTERNAL_API_TOKEN` 重签下游，操作者取 `X-Admin-User` 或 JWT `sub` 兜底；
- 客户端：`prepare()` 内与 probe **并行**拉字典，字典失败只降级不阻塞探测；以 probe 的 `modules`
  为能力边界，按 `value` 补文案并套用字典顺序，缺失项追加尾部；三层回退
  （字典 → bridge 短名 → 原值 + 「平台未维护该场景说明」）；`exclusive` 项双向互斥；
- 文案改正：`catalogSourceText` 拆成两行——「可选场景由集群 acli 提供（读取于 hh:mm:ss）」
  与「场景说明来自平台字典（更新于 …）」。

## 四、测试锁住的边界

| 层 | 文件 | 锁什么 |
|---|---|---|
| 求解器 | `workspaceLayout.spec.ts` | centerHidden 单开/双开/overlay 忽略；**不传该参数时结果与旧值完全一致**（回归保证） |
| store | `chat.log-collect-focus.spec.ts` | 已连接才自动开终端；覆盖态不动右栏；文件下载时不抢页签；关闭日志收集不关终端 |
| 外壳 | `App.log-collect-focus.spec.ts` | `<main>` 收合类与 `v-show`（源码断言禁止 `v-if`）；标题栏 tag 的出现/消失 |
| 面板 | `LogCollectPanel.spec.ts` | 字典合并与排序、能力边界只认 probe、`exclusive` 双向互斥、字典失败不阻塞、来源文案不再出现“目录来自集群 acli” |
| case-service | `test_log_collect_scenarios.py` | 只返回启用项、管理端含停用项、无凭证 403、`value` 不进更新白名单、审计被调用、PATCH 只写显式字段 |
| api-gateway | `test_log_collect_scenarios_proxy.py` | 客户读要求身份且直达字典端点、匿名 401、管理端 403/内部令牌重签/操作者兜底、下游不可达 503 |
| 管理台 | `LogCollectScenarioView.spec.ts` | 停用与待审核可见、开关只提交 `enabled`、弹窗按差量提交、校验不过不发请求 |

## 五、仍需人确认的两点（不阻塞上线，但影响文案定稿）

1. `collects` / `typical_symptoms` / `duration_hint` 无法从 acli 取得，首版由方案起草，
   seed 中 `review_state = pending_review`，**需支持工程师审核后改为已审核**；
2. `-m other,vm_suspend` 的实际行为需实机确认一次。平台侧暂按“互斥”处理；若实测为叠加语义，
   只需把字典里 `other` 的 `exclusive` 置 false，不涉及代码结构。
