# KBD 分类与识图功能及 UI 布局修复设计方案

## 背景与需求
在 KBD 知识条目管理页面的日常使用中，用户发现了以下几项问题：
1. 点击 KBD 管理页面的“重新分类”和“重新识图”按钮时，浏览器原生 confirm 弹窗提示信息不够美观，且存在标题截断（如截取 30 字符导致语义不连贯的问题）。
2. 在触发“重新分类”和“重新识图”操作后，后台常报错误：重新分类失败 HTTP 503，重新识图失败 HTTP 500。
3. 列表页面的操作列中展示“重新分类”和“重新识图”按钮极不合理，导致列表行操作空间拥挤。
4. 需要将上述重分类和重识图功能调整到“KBD条目详情”弹窗内部：
   - “AI 建议分类”标签旁边新增一个刷新按钮（触发重新分类）。
   - “其他截图”或“截图框”旁边新增一个刷新按钮（触发重新识图）。

## 方案概述 (WHAT)

### 1. 接口配置规范化与彻底清理（第一性原理修复）
- **故障根因**：
  1. **代码变量名残留错误**：在 `kb-service` 里的 `classify.py` 与 `vision_processor.py` 中，虽然代码定义的 Python 变量名为 `LLM_BASE_URL` 与 `LLM_API_KEY`，但是从系统环境变量读取时，却错误地写成了 `BASE_URL` 和 `API_KEY`（遗漏了前缀）。
  2. **容器环境变量缺失**：在 `deploy/docker/docker-compose.yml` 中，`kb-service` 服务容器的环境变量块中未透传 `LLM_BASE_URL` 和 `LLM_API_KEY`。本地的 `.env` 开发配置也漏配了这两个配置，导致环境变量未成功注入。
  3. **架构防退化原则**：此前 PR 曾特意清理了 OpenClaw 与 `ZAI_*` 的废弃配置，如果在代码中强行引入 `settings.ZAI_*` 作为 fallback，将导致已弃用的 `ZAI_*` 变量继续在代码中残留，破坏了系统在配置规范上的一致性。
- **修复设计**：
  1. 修正 `classify.py` 和 `vision_processor.py` 中的读取名称，统一使用标准的 `LLM_BASE_URL` 和 `LLM_API_KEY`。
  2. 在 `deploy/docker/docker-compose.yml` 的 `kb-service` 容器段，补齐 `LLM_BASE_URL` 与 `LLM_API_KEY` 的定义与透传。
  3. 在本地开发 `.env` 文件中配置 `LLM_BASE_URL` 与 `LLM_API_KEY`，使其与 GitOps 部署规范中的 ConfigMap / Secret 命名契约保持一致。此外，彻底清除了项目根目录下 `root/.env` 与 `root/.env.example` 中已随 OpenClaw 移除而废弃多年的 `OPENCLAW_GATEWAY_TOKEN` 和 `OPENCLAW_BASE_URL` 等无效环境变量。
  4. **KBD 数据管道废弃配置清理**：由于 `data-pipeline/kbd` 已完全改造成调用 `kb-service` API 的薄封装，不需要本地独立直接调用 LLM，因此彻底清除了管道配置 `config.py` 与 `run.py` 内部的 `ZAI_API_KEY`、`ZAI_BASE_URL`、`VISION_MODEL`、`CLASSIFY_MODEL`、`LLM_TIMEOUT`、`VISION_MAX_TOKENS` 等未清理的废弃残留，并同步精简了 `.env` 与 `.env.example`，避免了配置杂乱和安全泄露隐患。同时，为解决重构引起的潜在兼容性问题，在 `image_proc.py` 中补全了 `_find_images` 工具方法，确保流水线工具运行无虞。

### 2. 前端 UI 布局重构与操作流程升级
- **移除列表页多余按钮**：从 `KbdReviewView.vue` 列表的 `el-table-column` 中移除“重新分类”和“重新识图”按钮，优化列表的操作列宽度（从 340px 缩减至 220px）。
- **详情弹窗内置重组**：
  - 在“AI建议分类”标签右侧添加带有 `Refresh` 图标的小按钮，触发重新分类。
  - 在详情弹窗内的 Markdown 预览截图卡片 header，以及原图列表（images_json）的 header 部分，添加重识图的 `Refresh` 图标按钮。使用 `.stop` 阻止事件冒泡，防止点击按钮时触发手风琴组件的收起/展开。
- **确认交互美化**：使用 Element Plus 的 `ElMessageBox.confirm` 替换浏览器的 native `confirm` 弹窗。显示完整条目标题，避免 `.slice(0, 30)...` 字符串截断。
- **状态即时刷新**：在重分类与重识图执行成功后，不仅更新列表的对应行数据，同时即时更新详情弹窗状态（包括 `parsedSegments` 和 `parsedImagesJson` 的重新解析），确保数据一致性与顺畅的用户体验。

### 关键技术点

#### 1. 后端配置统一化
```python
# app/routes/classify.py
# LLM 配置（从环境变量读取，统一使用 LLM_* 命名）
LLM_BASE_URL = os.environ.get("LLM_BASE_URL", "").rstrip("/")
LLM_API_KEY = os.environ.get("LLM_API_KEY", "")
```

#### 2. 前端事件防冒泡与即时刷新
在截图组件的 header 中嵌入刷新按钮时，使用 `@click.stop` 以避免事件向父元素（折叠面板折叠/展开行为）冒泡：
```html
<el-button
  type="warning"
  link
  size="small"
  @click.stop="handleReanalyzeImages(detailEntry)"
  title="重新识图"
>
  <el-icon><Refresh /></el-icon>
</el-button>
```

在重分析（重新识图）成功后，重新抓取数据并刷新本地预览的片段：
```typescript
const fresh = await detailResp.json()
detailEntry.value = fresh
parsedImagesJson.value = parseImagesJson(fresh.images_json || [])
parsedSegments.value = parseContentMd(fresh.content_md || '')
```

## 决策依据 (WHY)

### UI 按钮交互设计
- **方案 A（选中）**：将重分类按钮放置在“AI建议分类”旁边，重识图按钮直接嵌入截图预览框和图片列表的 header 栏中。
  - *优点*：布局完全切合内容上下文，交互极为直观，完全不占用列表或基本表单区域。
  - *缺点*：需要处理折叠面板事件冒泡。
- **方案 B**：在详情弹窗的 footer 放置“重新分类”和“重新识图”文字按钮。
  - *优点*：无需处理冒泡。
  - *缺点*：与对应模块（建议分类、图片描述）存在物理视觉间隔，不够直观。
