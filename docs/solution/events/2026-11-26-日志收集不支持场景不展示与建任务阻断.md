# 日志收集不支持场景不展示与建任务阻断

## 一、背景

工单 `Q2026112600025` 第二次采集选择 `host_offline, slowdisk, core, performance, system`，
在两台节点上以 `LC-SPC-003 场景清单备份失败` 结束。界面提示「目录不可写、磁盘空间不足或权限不足」，
但数据库证据显示：

- 同一批 `host_offline.json`、`slowdisk.json` 备份与写入均成功，目录可写；
- 节点可用空间约 568 GiB，磁盘不是瓶颈；
- 唯一失败项是 `core.json`：`cp: cannot stat '.../spc/core.json': No such file or directory`；
- probe 已给出 `node_modules`，其中没有 `core`，并附 `catalog_note=节点 help 未列出专项 core`。

旧实现把 `probe.modules`（平台白名单全集）当作可选集合，只对 `node_modules` 之外的项做
「可能不支持但仍可勾选」的非阻塞警示。用户勾选后，平台照常生成 core 槽位，
bridge 在备份原件时才发现文件不存在，错误被归到 `LC-SPC-003`，排查方向被引向磁盘与权限。

## 二、第一性原理与硬约束

1. **能力事实只有一个来源**：目标节点 acli `log_collect create --help` 真实列出的专项。
2. **展示即承诺**：界面出现的场景必须可提交、可执行；不支持的不展示。
3. **能力未知不猜测**：旧 bridge 不返回 `node_modules`、acli 未安装或 help 解析失败时，
   保持原行为，不能凭版本号或平台白名单删用户的选择。
4. **拒绝发生在副作用之前**：后端必须在建任务、算清单、开通道之前拒绝，不能留下失败任务行。

## 三、改动

| 端 | 位置 | 变更 |
|---|---|---|
| 前端 | `LogCollectPanel.vue` | 新增 `nodeSupportedModules`；`moduleOptions` 只保留节点 help 列出的场景 |
| 前端 | `LogCollectPanel.vue` | 删除「节点可能不支持、仍可勾选」徽标与汇总警示 |
| 前端 | `LogCollectPanel.vue` | 历史回填/重试统一走 `filterSelectableModules`，移除不支持项并提示「历史场景被自动移除」 |
| 前端 | `LogCollectPanel.vue` | create 返回 4xx 时优先展示平台 Problem Details 的 title/detail/user_hint，不再只显示 `Request failed with status code 422` |
| 后端 | `log_collect_capability.py` | 新增能力判据：仅 `catalog_source=acli_help` 且 `node_modules` 非空时返回支持集合 |
| 后端 | `routes/log_collect.py` | 建任务前校验 `payload.modules`（自定义 spc 场景校验 core）；不支持返回 422 `LC-PLUGIN-016` |

| bridge | `log_collect_spc_fanout.go` | 备份失败时区分「原件 stat 不到」→ `spc_module_missing`（映射 `LC-PLUGIN-016`）与权限/磁盘导致的 `backup_failed` |

## 四、行为变化

- 节点 help 未列出 `core` 时，界面不再出现 core 选项，历史任务回填也会移除；
- 直接调 API 提交不支持场景，返回 422 `LC-PLUGIN-016`，任务不会创建；
- 旧 bridge 或 help 解析失败时保持现有可选集合，不误删；
- 极端情况下仍走到 bridge 备份阶段，`core.json` 不存在会报 `LC-PLUGIN-016 节点上没有所选专项`，
  而不是 `LC-SPC-003 场景清单备份失败`。

## 五、验证

- Go：`go test ./internal/logcollect/...` 与 `gofmt` 通过；
- Python：`uv run pytest` 覆盖能力判据与 create 拒绝路径；
- 前端：`pnpm test` 覆盖四项能力门禁用例，`vue-tsc` 与 `vite build` 通过；
- 真浏览器：节点 help 无 core 时 core 不渲染；有 core 时可勾选；历史回填 core 被移除并出现提示。

## 六、部署注意

前端与 case-service 随镜像发布即可生效。bridge 的归因加固需要重建 exe 并由现场人工重装；
未重装时平台侧仍会阻断不支持场景，不会影响本次修复的主路径。
