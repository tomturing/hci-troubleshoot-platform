## 安全说明
- 默认密码 `aihci@aclient2025` 为演示账号，密码以 argon2id 哈希入库（不可逆）；上线/生产须尽快改密或轮换，并配置 `AUTH_RSA_PRIVATE_KEY_PEM`（稳定 RSA 私钥，避免 pod 重启换密钥导致已签发 JWT 失效）。staging 缺省空密钥 → 启动期临时内存密钥即可运行。
- nginx `Authorization` fallback 与网关 `AUTHN_ENFORCE_ADMIN=False`（默认）共同保证灰度安全：未登录旧前端仍可用（共享令牌），登录后 JWT 优先。开启 `AUTHN_ENFORCE_ADMIN=True` 后，未带有效 JWT 的共享令牌不再赋予 admin，必须登录。

## 上线后修复：auth-service 容器启动崩溃（依赖漂移）

现象：staging `auth-service` CrashLoopBackOff，日志
`ModuleNotFoundError: No module named 'opentelemetry.exporter'`
（`shared/observability/otel.py` → `OTLPSpanExporter`）。

根因：Dockerfile 里硬编码了一份 pip 依赖清单，与 `pyproject.toml` 漂移后漏装
`opentelemetry-exporter-otlp`；而单测只覆盖 `app/security`，从不 `import app.main`，
所以 CI 全绿、镜像却在启动时才炸。

修复：
1. Dockerfile 改为与 api-gateway 同构（`uv pip compile pyproject.toml` 编译安装），
   **pyproject 作为唯一依赖声明源**，消除双份清单漂移。
2. `pyproject.toml` 补 `opentelemetry-exporter-otlp`。
3. Dockerfile 增加**构建期依赖闭包冒烟** `RUN python -c "import app.main"`：
   缺依赖时构建直接失败，不再产出"能推不能跑"的坏镜像。

教训：新增服务/共享层新增三方依赖时，CI 单测覆盖不到入口模块，
必须在镜像构建期做 import 冒烟，否则故障要到容器运行时才暴露。

## 上线后修复③：auth-service 镜像缺 instrumentation 依赖（被构建期冒烟拦下）

现象：#1081 合入后的 main 构建，镜像 job `构建并推送镜像（auth-service）` 直接失败：

```
#19 [stage-0 10/10] RUN python -c "import app.main"
ModuleNotFoundError: No module named 'opentelemetry.instrumentation'
ERROR: failed to build: process ... did not complete successfully: exit code: 1
```

根因：`shared/observability/otel.py` 用到 httpx/sqlalchemy/logging/fastapi 四个 instrumentation，
auth-service 的 pyproject 只声明了 api/sdk/exporter-otlp。
**本地用根虚拟环境验证是发现不了的**——根依赖里恰好有这些包。

修复：pyproject 补齐四个 `opentelemetry-instrumentation-*` ；
验证改用**与镜像等价的隔离 venv**（`uv pip compile pyproject.toml` → 独立 venv → `python -c "import app.main"`），
不再用根环境结论充当镜像结论。

价值：上一个 PR 加的构建期 import 冒烟在这里立刻兑现——缺陷在构建期红，而不是等到容器 CrashLoopBackOff。


## 上线后修复④：登录 500（text() 里 `::` 类型转换与绑定参数冲突）

现象：auth-service 起来后 `POST /api/auth/admin/login` 返回 500 INTERNAL_ERROR，
日志：`asyncpg.exceptions.PostgresSyntaxError: syntax error at or near ":"`，
SQL 为 `SELECT roles FROM "user" WHERE user_id = :uid::uuid`。

根因：SQLAlchemy `text()` 的绑定参数解析与 PostgreSQL `::` 转换语法冲突——
`:uid::uuid` 被解析后下发到 asyncpg 变成非法语句。
**三类既有防线都没拦住**：单测用 mock session（不解析 SQL）、
构建期 import 冒烟（只验导入）、IDE/lint（无法判断 SQL 语义）。

修复：
1. `CAST(:uid AS uuid)` 取代 `:uid::uuid`（已用真实库在 pod 内验证可用，`OLD_FAIL / NEW_OK`）。
2. 既有单测 `test_get_roles_reads_user_jsonb` 此前把错误写法固化成断言（要求含 `::uuid`），
   改为断言 `CAST(:uid AS uuid)` 且不含 `::`。
3. 新增静态契约 `app/tests/test_sql_bind_safety.py`：扫描生产代码的 `text()` SQL，
   禁止出现 `::`（含红→绿验证：改回问题写法即失败）。

教训：mock 单测覆盖不到"真实 SQL 解析"这一层，凡是原生 SQL 都要有静态契约 + 真实库冒烟兜底。

## 发布链路修复总览（阶段1.x 上线暴露的 4 类接线缺陷）
1. Dockerifle 依赖与 pyproject 漂移 → 改为单一依赖源 + 构建期 import 冒烟
2. instrumentation 依赖缺失 → 隔离 venv（等价镜像）验证
3. 晋级脚本未登记 authService → 契约测试钉住"镜像矩阵 deploy key ⇄ 晋级脚本映射"

## 上线后修复⑤：admin 走 JWT 后下游必填 client_id 路由会 401（强认证前置阻塞项）

现象（A/B 实测，`/api/diagnosis-scenarios`）：
- 有效 admin JWT → **401**「缺少服务端签发身份」
- 伪造 JWT → 200（验签失败回落匿名 Cookie 身份）
- 共享内部令牌 → 200

即**网关其实已正确验签**（RS256 + JWKS 走通），真正的问题是：
`IdentityMiddleware` 在 admin 验签成功后跳过 Cookie 匿名身份签发，
`_apply_actor` 又只写 `is_admin` 不写 `client_id`，
而下游大量路由以 `request.state.client_id` 为必填身份 → 401。

后果：只要前端改为携带 JWT（含将来开 `AUTHN_ENFORCE_ADMIN`），
管理台这批接口会整体 401——属于"登录之后反而打不开"的回归。

修复：`_apply_actor` 在 admin 分支补 `request.state.client_id = actor.user_id`（JWT 的 sub）。
新增单测 `test_identity_jwt_admin_client_id.py` 锁定该行为（红→绿验证：移除修复即失败）。

顺序要求：此修复必须先落地，才可以开启 `AUTHN_ENFORCE_ADMIN`。


## 上线后修复⑥：登录返回 400（管理台 /api/auth 与 Langfuse Ingress 路径冲突）

现象：管理台输入账号密码 → **400 Bad Request**
`This action with HTTP POST is not supported by NextAuth`（nginx 访问日志里**没有任何这条 POST**）。

根因：观测 chart 的 `langfuse-ingress`（host=acli.sangfor.com.cn，entrypoints 含 **web=4888**）
占用了路径 `/api/auth`（Langfuse 自己的 NextAuth 登录，不可删）。
Traefik 匹配规则是「Host 更具体 + 路径最长前缀」优先：
`/api/auth/admin/login` 命中 langfuse 的 `/api/auth`（更长且 Host 具体），
压过 admin-ui 的 `/api`（通配 Host）→ 请求被 Next.js 截走并返回 400。

⚠️ 验证盲区（重要）：用 IP 直连（Host=IP）时不会命中 langfuse 的 Host 规则，
请求落到 admin-ui → 200；**只有带真实域名 Host 才复现**。
此前"登录已打通"的结论正是被这个盲区误导。

修复：
1. 认证路径整体改为 `/api/platform-auth/*`（auth-service 路由 + 网关代理 + 前端调用），避开 Langfuse。
2. 新增静态契约 `backend/auth-service/app/tests/test_path_collision.py`：
   解析 auth-service/网关的认证路径与 langfuse ingress 路径，禁止互为前缀（已红→绿验证）。

后续方向：管理面收敛到独立域名 `admin.acli.sangfor.com.cn`（B3），从根上避免与其它应用抢路径。
