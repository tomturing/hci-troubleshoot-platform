## 安全说明
- 默认密码 `aihci@aclient2025` 为演示账号，密码以 argon2id 哈希入库（不可逆）；上线/生产须尽快改密或轮换，并配置 `AUTH_RSA_PRIVATE_KEY_PEM`（稳定 RSA 私钥，避免 pod 重启换密钥导致已签发 JWT 失效）。staging 缺省空密钥 → 启动期临时内存密钥即可运行。
- nginx `Authorization` fallback 与网关 `AUTHN_ENFORCE_ADMIN=False`（默认）共同保证灰度安全：未登录旧前端仍可用（共享令牌），登录后 JWT 优先。开启 `AUTHN_ENFORCE_ADMIN=True` 后，未带有效 JWT 的共享令牌不再赋予 admin，必须登录。

## 上线后修复：auth-service 容器启动崩溃（依赖漂移）

现象：staging `auth-service` CrashLoopBackOff，日志
`ModuleNotFoundError: No module named 'opentelemetry.exporter'`
（`shared/observability/otel.py` → `OTLPSpanExporter`）。

根因：Dockerfile 里硬编码了一份 pip 依赖清单，与 `pyproject.toml` 漂移后漏装
`opentelemetry-exporter-otlp`；而单测只覆盖 `app/security`，从不 `import app.main`，
所以 CI 全绿、镜像却在启动时才炸。

修复：
1. Dockerfile 改为与 api-gateway 同构（`uv pip compile pyproject.toml` 编译安装），
   **pyproject 作为唯一依赖声明源**，消除双份清单漂移。
2. `pyproject.toml` 补 `opentelemetry-exporter-otlp`。
3. Dockerfile 增加**构建期依赖闭包冒烟** `RUN python -c "import app.main"`：
   缺依赖时构建直接失败，不再产出"能推不能跑"的坏镜像。

教训：新增服务/共享层新增三方依赖时，CI 单测覆盖不到入口模块，
必须在镜像构建期做 import 冒烟，否则故障要到容器运行时才暴露。


## 上线后修复②：发布晋级被"未知服务 key"整批中断

现象：main 发布后 dev/staging 的 image tag 全部停在旧值，环境看似正常实则没发布：
```
========== 更新 dev 环境 ==========
更新 apiGateway.image.tag -> 20260923-1727-b5dc6fa
错误：未知服务 key：authService
```

根因：新增服务的 deploy key 只登记在镜像构建矩阵 `resolve_image_build_plan.py`，
未同步登记到晋级脚本 `scripts/ops/sync-env-repo-tags.sh` 的 `service_repository()` 映射；
脚本按未知 key 报错，**整批 tag 都不再更新**（只在环境仓库补 values key 无效，错在脚本白名单）。

修复：
1. `sync-env-repo-tags.sh` 增加 `authService) echo "auth-service"`。
2. 新增契约测试 `scripts/ci/test_env_repo_sync_contract.py`：
   镜像矩阵输出的每个 deploy key 必须能被晋级脚本解析（已先验证其能捕获 authService 缺失），
   并接入 ci.yml 的触发清单/ruff 清单/pytest 清单。

复盘：这是"新增服务漏接线"的第三次复发（镜像矩阵→单测映射→晋级脚本），
凡跨脚本的服务登记点都必须有自动化契约兜底，不能靠人工记忆。


## 上线后修复③：auth-service 镜像缺 instrumentation 依赖（被构建期冒烟拦下）

现象：#1081 合入后的 main 构建，镜像 job `构建并推送镜像（auth-service）` 直接失败：

```
#19 [stage-0 10/10] RUN python -c "import app.main"
ModuleNotFoundError: No module named 'opentelemetry.instrumentation'
ERROR: failed to build: process ... did not complete successfully: exit code: 1
```

根因：`shared/observability/otel.py` 用到 httpx/sqlalchemy/logging/fastapi 四个 instrumentation，
auth-service 的 pyproject 只声明了 api/sdk/exporter-otlp。
**本地用根虚拟环境验证是发现不了的**——根依赖里恰好有这些包。

修复：pyproject 补齐四个 `opentelemetry-instrumentation-*` ；
验证改用**与镜像等价的隔离 venv**（`uv pip compile pyproject.toml` → 独立 venv → `python -c "import app.main"`），
不再用根环境结论充当镜像结论。

价值：上一个 PR 加的构建期 import 冒烟在这里立刻兑现——缺陷在构建期红，而不是等到容器 CrashLoopBackOff。
