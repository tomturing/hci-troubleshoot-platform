# 日志收集面板进度条：从「节点采集百分比」改为「整条链路分段映射」

## 变更历史

| 日期 | 版本 | 变更内容 | 关联事件文档 |
|------|------|---------|------------|
| 2026-10-30 | v1.0 | 初版：锁定进度条分段口径，修复「0 字节却显示 100%」 | 2026-10-27-日志收集交付路径与已采集包补交付.md |

## 背景与需求

现场（工单 `Q2026102901049`，2026-10-30 10:09）截图事实：进度条顶在 **100%**，
同一屏的状态文案是 **「正在从 HCI 拉取：0 字节」**，步骤条停在「上传」。
用户无法判断任务到底走到哪、还要等多久。库内同期任务记录：

```
task_id af4b8397-…  status=uploading  delivery_status=queued  upload_mode=bridge_relay
```

## 根因（第一性原理）

进度条只有一个标量，但一次日志收集有两套互不相干的分母：

1. **节点侧**：`acli log_collect progress` 的 percent。它在「采集 + 打包」结束时就到 **100**；
   P1 直传时还继续覆盖「发送中 85% → 发送成功 100%」。
2. **交付侧**：bridge 交付作业 `deliveryJob.progress()`，拉取占前 50、上传占后 50，
   与节点百分比没有任何换算关系。

旧实现：

```ts
return Math.max(nodePercent, 60 + Math.round(transfer.percent * 0.3))
```

`Math.max` 只有在一段「尚未被用满」时才有意义。节点 percent 在交付刚开始时已经是 100，
于是 60-90 的交付区间**永远不可能生效**——进度条从「采集结束」到「归档完成」全程钉在 100%。
这不是显示误差，是把两个不同的量强行合并成一个量的必然结果。

## 方案（WHAT）

进度条按阶段分段，每段只用**该阶段自己的可测数据**（`frontend/customer/src/services/logCollectProgress.ts`）：

| 阶段 | 区间 | 数据来源 |
|------|------|---------|
| 探测 / 采集 / 打包 | 0 → 60 | 节点 percent |
| 拉取 + 分片上传（P2） | 60 → 90 | 交付作业 progress（拉取 0-50、上传 50-100） |
| 归档（平台代传） | 90 | 无可分段测量维度，如实停在分界，由文本给状态 |
| 完成 | 100 | 平台回写 `completed` |

约束与例外：

1. **单调性**：每段起点等于上一段终点（60 / 90），只有 `done` 给 100，同一次任务内不倒退。
2. **P1 直传例外**：节点 percent 本来就是「采集 + 打包 + 发送」的整条链路，套分段反而压扁真实进度，
   因此 `direct` 时原样使用节点百分比。
3. **`pulling` 一定是平台中转**：P1 由节点插件直发日志服务器，平台侧不搬字节，从不经历拉取阶段。
   这条判据顺带修正了「P1 失败自动降级 P2」的场景——那时 `upload_mode` 已被改写、
   `remote_url` 仍在，仅靠 `isDirectDelivery` 会把中转误判成直传。
4. **补一道防线**：组件侧传入 `direct = isDirectDelivery && transfer.partCount === 0`，
   拿到分片进度就说明是平台中转。

同时修正同屏文案的两处误导：

- 交付作业刚下发时 bridge 仍处于 `waiting_collect`（等节点把包写完），此时一个字节都还没拉。
  文案改为「节点采集已收尾，等待压缩包写入完成（尚未开始传输）」，不再说「正在拉取 0 字节」。
- 拉取文案补上分母：`正在从 HCI 拉取：1.2 GB / 2.9 GB`（job 的 `source_size`），
  只有分子无法判断还要多久。

## 影响面

- `frontend/customer/src/services/logCollectProgress.ts`（新增，纯函数 + 单测）
- `frontend/customer/src/components/LogCollectPanel.vue`（`percent` 改为调用该函数；`transfer` 增加
  `totalSize` / 原始 phase；新任务下发时整组归零 `resetTransfer()`）
- 后端、bridge、接口契约、数据库：**无变更**

## 验证

- 单测 `frontend/customer/src/services/__tests__/logCollectProgress.spec.ts`：
  覆盖「采集 100 → 60」「拉取 0 字节 → 60」「作业 50 → 75」「上传 100 → 90」「归档 90 → 完成 100」
  全链路单调、P1 直传原样、越界/缺省夹取。
- 组件回归 `frontend/customer/src/components/__tests__/LogCollectPanel.spec.ts`：原有 46 例全绿（无行为回退）。
- 端到端（需真实 bridge + HCI 节点，本地无法复现）：发起一次 P2 收集中转，观察
  采集结束时进度条停在 60%，拉取/上传期间在 60-90 之间移动，归档成功后到 100%。

## 仍未覆盖

- P1 直传阶段没有分段进度可测（节点 percent 与「发送」不是一一对应），仍原样透出。
- 归档（平台 → 5888）无字节级进度，停在 90 是刻意选择，避免伪造百分比。
