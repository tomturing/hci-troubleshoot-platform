# 2026-11-16 链路定界弹框可读性修复

## 问题

管理端日志收集详情的「S1-S8 阶段时间线」有三处 UI 缺陷：

1. 标题右侧感叹号帮助按钮明显大于左侧标题文字。
2. 点击感叹号后的「三段五组件设计说明」弹框局促，一屏显示内容过少。
3. 弹框内「问题描述」与「建议动作」各自带滚动条，原本一一对应的关系完全丢失。

## 第一性原理解构

- **按钮过大**：不是字符字号问题，而是几何尺寸问题。`el-button circle size="small"` 的圆形包围盒远大于 `13px` 标题行高，视觉上自然"大一号"。
- **弹框局促**：宽度上限 `min(92vw, 860px)` 与正文高度上限 `68vh` 双重压缩了可用空间。
- **对应关系丢失**：`problems` / `actions` 是两个平行数组，分别渲染进 `max-height:168px; overflow-y:auto` 的独立容器。数据在契约层本按错误码一一对应，渲染层却拆成两个互不联动的滚动域，滚动任一列必然错位。

## 对抗性审查

| 候选方案 | 否决理由 |
| --- | --- |
| JS 同步两列滚动条 | 滚动条宽度、触控惯性、平滑滚动都会失步，靠事件联动维持对齐本质脆弱 |
| 仅视觉对齐、保留双滚动 | 两侧文本行数不同仍会错位，未触及根因 |
| 扩大热区的自定义图标 | 需要额外覆盖 Element Plus 内部变量，易受版本升级破坏 |

采用的方案在数据层把同一错误码的 `problem` / `action` 绑定为单个 `pair`，渲染为同一行的三格（错误码 / 问题描述 / 建议动作），移除列级滚动，统一由弹框正文滚动。配对关系由数据结构保证，不依赖任何同步逻辑；窄屏下同一 `pair` 上下堆叠，配对语义仍成立。

## 修改范围

- `frontend/admin/src/views/components/LogCollectAttribution.vue`
  - 帮助按钮直径收敛到 `18px`、字号 `12px`，与 `13px` 标题匹配。
  - 弹框宽度上限提升到 `min(94vw, 1180px)`，正文高度上限提升到 `80vh`。
  - `componentRows` 输出 `pairs`，模板按行渲染错误码/问题描述/建议动作，删除 `.ref-items` 列级滚动。
- `frontend/admin/src/views/components/__tests__/LogCollectAttribution.spec.ts`
  - 新增断言：无列级滚动容器；配对行数量等于契约条目数；每行错误码、问题描述、建议动作均来自同一契约条目。

无后端、接口、契约生成物变更，客户侧不受影响。

- 单测：组件 3/3 通过；admin 全量 25 文件 / 233 例通过。
- 类型检查与生产构建：`pnpm build` 通过。
- 真浏览器（playwright + chromium，1680x1100）：10/10 通过。关键实测值：

  - 弹框宽度 `1180px`，正文可视 `880px`、内容 `3766px`（整体滚动）；
  - 91 个配对行三格全部同行对齐；整体滚到底后首行偏差 `0.0px`；
  - 页面无 JS 异常。
