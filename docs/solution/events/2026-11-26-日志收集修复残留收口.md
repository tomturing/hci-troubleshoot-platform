# 方案事件：日志收集修复残留收口

## 背景与需求

参见 [需求事件](../../requirement/events/2026-11-26-日志收集修复残留收口.md)。核心是把“已修代码”与“用户可见闭环”之间的四层缺口逐层补上。

## 方案概述（WHAT）

1. **事实与结论分离**：客户侧新增 `case_archive_verified` 条件，后端按工单扫描权威交付证据，前端沿用 `display.conditions` 渲染；
2. **交付边界校验**：在 bridge 的 submit 与 waitCollect 两处用 `filepath.Base(path) == caseID + ".zip"` 做归属校验；
3. **证据端点全覆盖**：补齐 `process-logs` / `evidence-error` / `failure-snapshot` 三个端点的 `X-Bridge-Version` 记录；
4. **巡检脚本时区修复**：改用从 `datetime` 模块导入 `UTC`；
5. **exe 重建**：本轮改 `terminal_bridge/` 后由 CI 复用 PR #1677 更新下载目录。

## 决策依据（WHY）

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 在客户列表查询时计算工单级归档事实 | 只加只读条件，不动状态机；跨客户端也能看到同工单事实 | 列表多一次轻量查询 | 选中 |
| 让 `derive()` 直接把 failed 翻成 success | 用户看不到红条 | 违反“事实与结论分离”，会掩盖本轮失败；历史包/手工上传易误判 | 否决 |
| 在 `ParseProgress()` 校验工单号 | 单点改动 | 纯解析函数没有期望工单号，且 P1/P2 调用链不同 | 否决 |
| 在 delivery 两个边界校验 | 覆盖前端 submit 与 bridge 自取包两条路径 | 需要改 exe 并现场重装 | 选中 |
| 新增 `LC-TRANSFER-016` | 错误更精确 | 触发七份生成物与契约连锁，超出最小修复 | 否决 |

## 详细设计

- 契约 `contracts/log_collect_display.json` 的 `condition` 新增 `case_archive_verified: "本工单已有权威归档"`，由 `scripts/gen_log_collect_display.py` 重新生成七份产物；
- `derive()` 新增可选参数 `case_archive_verified`，只把 key 加入 `_build_conditions()`，`conclusion` 不变；
- `list_tasks` / `get_task` 通过服务层按 `case_id` 读取全部任务，任一 `delivery_evidence_ok()` 为真即置位；
- bridge 在 `remote` 包新增 `ValidateArchiveOwnership(path, caseID)`，`caseID` 为空时放行（不猜测），非空时严格比对 basename；
- 不一致时 `delivery.submit` 回 `LC-TRANSFER-001`，`waitCollect` 返回带同码的 fatal，并落 WARN 事件 `delivery.archive_path_case_mismatch`；
- 证据端点统一声明 `x_bridge_version` 并调用 `_record_bridge_version()`。

## 影响范围

- 后端：`case-service` 路由、domain、契约生成物、单测；
- 前端：`customer` 只复用既有条件渲染，不改 `LogCollectFaultCard.vue`；
- Go：`terminal_bridge` 交付边界、路径白名单、单测；
- 脚本：`scripts/audit/audit_log_collect_5888.py` 与新增单测；
- 文档：本事件三件套、`docs/solution/case/工单设计.md`、`docs/task/case/工单任务.md`、`docs/README.md`、根 `README.md`。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 工单级查询漏掉其他客户端创建的任务 | 提示漏显 | 查询不带 `created_by` 过滤 |
| 旧 exe 不上报版本头 | 版本字段仍空 | 界面按“未上报/旧桥”解释，不把空串当版本号 |
| 归属校验误伤合法包名 | 交付被拒 | 只校验 basename 严格等于 `<case_id>.zip`，`case_id` 为空时放行 |
| CI exe PR #1677 与本次分支冲突 | 分发版本滞后 | 复用机器人分支，合入 main 后自动 force-update |
