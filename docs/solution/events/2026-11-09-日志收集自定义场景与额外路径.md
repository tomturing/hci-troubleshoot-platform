## 一、背景

客户侧的日志收集此前只能从平台字典里选专项（`acli log_collect create -m`），
无法收集**业务自定义目录、配置文件或其他散落文件**。现场的替代做法是让客户登录节点手工执行
`acli`，产物因此脱离平台的交付链（分片上传、摘要校验、P1/P2 都不覆盖）。

本次补齐两个缺失能力：

1. **额外收集路径（`-p`）**：在既有专项之外临时追加目录/文件；
2. **自定义场景（`-c`）**：由管理台预先定义一组路径，客户在面板上一键选用。

## 二、事实基线（acli 源码确证）

以下结论来自 acli 源码只读分析，设计不得偏离；标注【推断】的项尚未实测。

| 编号 | 事实 | 证据 |

## 三、能力边界

### 3.1 可以做

- 在任意专项（默认 `other`）之外追加一组**字面路径**（目录或文件），目录整体 `cp -r`；
- 追加内容与专项日志一起打进 `extra_tar.tar.gz`，随最终压缩包交付；
- 支持 P1 直传与 P2 中转两条既有交付路径。

### 3.2 不能做（必须如实告知客户）

- **不能关闭专项日志**：`config.modules` 不生效，自定义场景只能「加」，不能「减」；
- **不能表达通配符与日期占位**：`*` 会被 `os.path.exists` 判假后静默跳过；平台需自行展开 `{date}`；
- **不能表达 `command` / `script` 类采集**：`-c` 的 `paths` 只走 `cp -r`；
- **不能保证收全**：路径不存在或无权限都会被静默跳过，任务仍显示成功。

### 3.3 与内置专项的差异

内置 `spc` 清单可以混合 `copy` / `command` / `script`，并支持 `{date}` 占位与 `/*` 通配。
自定义场景只覆盖其中的 `copy` 子集，且必须由平台把占位展开为字面值。因此
**自定义场景不能等价复刻内置专项**，产品文案不得暗示「替代」。

## 四、交互设计

### 4.1 视觉互斥、底层叠加

客户侧只看到两种模式，但底层始终是「专项 + 附加 paths」：

```
故障场景
(•) 默认场景     ( ) 自定义场景
                 └─ 自定义模式下不展示专项勾选，底层固定 -m other
```

- **默认场景**：维持现有 `-m` 多选，不传 `-c`；
- **自定义场景**：不展示专项，底层固定 `-m other`（`other ≡ system`），
  由 `-c` 提供附加路径。客户不需要理解 `other` 的存在，但界面须说明
  「会同时包含系统基础日志」。

### 4.2 额外路径（`-p`）

放在表单末尾的「高级选项」折叠区，默认收起：

- 输入绝对路径后回车成 tag，支持一次粘贴多条（逗号或换行分隔）；
- 数量上限 20（与后端 schema 一致），达上限后输入框禁用并给出可执行提示；
- 非法项**不入列**，一次性展示最多 3 条原因；
- 与自定义场景并存时，路径合并进 `config.paths`，**不单独传 `-p`**（否则 config.paths 被丢弃）。

### 4.3 管理台

日志收集场景页拆为两个 tab：

- **默认场景**：现有字典表格（`value` 只读、文案可编辑）原样保留；
- **自定义场景**：列表 + 编辑器。编辑器双形态（勾选列表 / JSON 编辑），
  两者是**同一份数据的两个视图**，不是两条保存路径。

JSON 编辑只允许 `paths` 一个键；出现其它键直接拒绝保存——因为它们会被插件静默忽略。

## 五、数据与接口契约

### 5.1 平台内部模型 ≠ 下发格式

平台存结构化路径项（可带分类、备注），下发时只取 path 拼成逗号串：

```
平台模型: [{ path: "/sf/log/cluster/", category: "log", note: "集群管理" }]
          ↓ 序列化（ensure_ascii=True，UTF-8 无 BOM）
下发:     {"paths":"/sf/log/cluster/,/sf/etc/cluster.conf"}
```

### 5.2 命令形态

```
acli log_collect create -s <工单号> -m other -d <起>,<止> -i all|<IP> \
  -c /sf/data/local/acli/tmp/platform/log_collect/cfg-<task_id>.json
```

- `-c` 的 config **只写 `paths`**：其余字段写了也不生效（F3），写进去只会误导后来人；
- `-p` 始终不传（F4）；
- 配置文件写入走 `base64 -d`，禁止 heredoc 直写（JSON 中的引号与 `$` 会被 shell 展开）；
- 写入后回读校验 sha256，不符直接拒绝执行。

### 5.3 新增字段

`log_collect_task`：

| 字段 | 说明 |
|------|------|
| `custom_scenario_id` | 选用的自定义场景（可空） |
| `custom_scenario_revision` | 场景版本快照，保证历史任务可解释 |
| `config_path` | 节点上的配置文件路径 |
| `config_sha256` | 下发内容摘要 |
| `path_count` | 展开后的路径条数 |
| `preflight_missing` | 预检不存在的路径清单（JSON） |

## 六、静默失败防护

acli 的三类失败都不改变退出码（F8），因此平台必须自己造出「显式失败」：

| 层 | 时机 | 动作 | 失败处理 |
|---|------|------|---------|
| L1 保存/提交 | 编辑器保存、任务创建 | 只允许字面绝对路径；禁 `*`、`{date}`、逗号、空格、shell 元字符、`..`；条目上限 200 | 直接拒绝，不提供「强制保存」 |
| L2 下发前 | bridge 写配置后、执行 create 前 | 对展开后的每条路径在发起节点 `test -e` | 不存在 → 二次确认后允许强制下发，并记入 `preflight_missing` |
| L3 事后 | 任务落库、交付完成 | 记录 `config_path/sha256/path_count`；P2 拉包前 `unzip -l` 确认 `extra_tar` 存在 | P1 无副本，结果页如实提示「无法核对自定义路径是否完整收录」 |

L2 的已知局限：`paths` 在**每台目标主机**解析（F5），而 bridge 只连发起节点，
因此预检只能覆盖发起节点；多主机场景下的缺失只能由 L3 事后发现。

## 八、验收标准

- [ ] 合法路径可添加为 tag，非法路径不入列且给出原因；
- [ ] 提交时 `extra_paths` 出现在平台任务记录与 bridge 的 `log_collect.create` 消息中；
- [ ] 「重新收集」时额外路径被回填，不丢失上次范围；
- [ ] 含空格、逗号、`..`、`*`、`$()` 的路径在提交前被拒绝；
- [ ] 自定义场景模式下不出现专项勾选，且下发命令固定 `-m other`；
- [ ] 配置解析失败或路径缺失时，平台有可见提示，不出现「任务成功但少收」；
- [ ] 历史任务可回答「当时用的是哪份配置」（`config_path` + `config_sha256`）。

## 九、风险与遗留

1. **`other ≡ system`**：既有字典文案「不收集上述场景日志」与事实相反，客户会低估体积；
   需单独立项修正 `database/seeds/06_log_collect_scenarios.sql` 的文案。
2. **占位专项**：`network` / `slowdisk` / `storage` 是 122–131B 的占位文件，
   客户勾选后几乎收不到内容且任务显示成功；与本设计无关，但同属静默失败，建议一并立项。
3. **`-v` 不可用**：对外不可达（F14），本次不做，也不在 UI 暴露入口。
4. **自定义场景不可复刻专项**：`command` / `script` / 通配符无法表达（F6、F9），
   产品文案不得暗示「替代内置专项」。
