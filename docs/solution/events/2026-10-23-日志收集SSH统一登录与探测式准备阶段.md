# 日志收集：SSH 统一登录与探测式准备阶段

> 版本：v1.0
> 日期：2026-10-23
> 关联：`docs/solution/custom-ui/客户端设计.md` §5.7、`docs/solution/events/2026-10-22-日志收集任务控制面API.md`
> 关联代码：`frontend/customer/src/components/SshConnectSection.vue`、`LogCollectCaseDialog.vue`、`LogCollectPanel.vue`、`terminal_bridge/log_collect.go`

---

## 一、背景与问题

日志收集依赖 `acli log_collect`，而该命令必须通过 **terminal_bridge 已建立的 SSH 会话**执行。
上线后暴露两个可用性问题：

1. 「指定工单号」弹框没有 SSH 入口，用户看到「发起节点」却不知道密码该在哪填；
2. SSH 表单/连接状态机原本内嵌在 `SshConnectDialog` 中，日志收集若要复用只能复制一份——违反"单一模板"。

同时采集表单的「故障场景」「目标主机」是写死的：

- 故障场景硬编码 10 项（`LogCollectPanel.MODULES`），与 acli 实际支持能力可能漂移；
- 目标主机只能手填或 `all`，用户无法知道集群有哪些节点。

## 二、事实核查（2026-10-23 实机 `acli log_collect create --help`）

```
-m|--modules=STRING   日志收集专项，使用英文逗号拼接指定的专项，示例：vm_suspend,network
                      可直接选择的选项，不设置则默认 other，枚举值：
                      vm_suspend（虚拟机挂起专项）   vm_start（虚拟机开机失败专项）
                      host_offline（主机离线专项）   network（网络专项）
                      storage（虚拟存储专项）        slowdisk（卡慢盘专项，单天收集时间约4min）
                      performance（性能专项）        system（中台专项）
                      core（core收集专项）           other（默认收集专项，不收集上述n个场景日志）
-i|--ips=STRING       主机 ip，示例 1.1.1.1,1.1.2.3,4；不设置默认收集当前主机日志，设置 all 收集所有主机
```

结论：

| 能力 | 可行性 | 实现 |
|---|---|---|
| 故障场景 | ✅ help 明确列出 `-m` 枚举 | bridge 执行 `acli log_collect create --help`，解析「可直接选择的选项」段落；解析失败回退平台默认 10 项并标注来源 |
| 目标主机 | ✅ `acli --formatter json platform node list`（命令目录已收录） | bridge 执行并容错解析节点 IP；失败回退 `all` + 手工输入 |
| 节点列表字段 | ⚠️ 实机 JSON 结构未固化 | 递归查找 `ip/address/host` 字段；解析不到视为空，不阻塞 |

## 三、组件架构（单一 SSH 模板）

```
SshFormSection.vue        纯字段（host/port/username/authType/password|key）——唯一
        ▲
SshConnectSection.vue     状态机 + 视图（bridge 引导 / 表单 / 连接中 / 失败 / 已连接）——唯一
        ▲                    ▲
SshConnectDialog.vue      LogCollectCaseDialog.vue
（el-dialog 薄壳）        （mode="inline" 内嵌）
```

约束：

- 任何调用方**不得**再写 SSH 字段或连接逻辑；
- `SshConnectSection` 通过 `connected(host)` 事件对外暴露主机，由调用方决定后续（开面板 / 填充发起节点）；
- `dialog` 模式保留 1.5s 自动关闭；`inline` 模式不自动关闭，成功后折叠为状态条。

## 四、用户旅程

### A. 首次使用（无 SSH 会话，bridge 已运行）

```
点「🗂 日志收集」
→ openLogCollect() 检测 sshConnectionState !== 'connected'
→ 打开「指定工单号」弹框：工单号 + 内嵌 SSH 登录区（先检测 bridge）
→ 填 IP/账号/密码 → 连接成功
→ SSH 区折叠为「● 已连接 root@10.10.1.21 [重新登录]」
→ 自动带出「发起节点 = 10.10.1.21」
→ 确定 → 面板打开 → 准备阶段（①~⑤）→ 就绪
```

### B. 已有 SSH 会话

```
点「日志收集」→ 已连接 → 跳过弹框，直接打开面板
面板顶部显示「归档工单 Qxxx  ·  SSH root@10.10.1.21」
```

### C. bridge 未运行

```
SSH 区显示「SSH Bridge 未运行」+ [⬇ 下载] [🔄 已启动，重新检测]
工单号可先填，「确定」保持禁用（tooltip：请先登录 SSH）
```

### D. 连接中断 / 换节点

```
准备阶段断开：该阶段失败 + 「重新登录」；不自动关闭面板
采集阶段断开：顶部警告「SSH 会话已断开，采集可能中断」；任务状态以平台为准
换节点：重新登录 → host/port/username 预填（不含密码）→ 成功后发起节点自动更新
采集中禁止更换（running 时按钮禁用）
```

## 五、准备阶段（点确定后）

```
① 登录会话   ✓（弹框内已完成，面板只展示）
② 环境探测   架构 / acli 版本 / 磁盘余量 / 5888 连通性
③ acli 检查   未安装 → 自动安装（下载/分发/校验，展示进度，不再弹确认）
④ 场景加载   help 解析；失败回退平台默认
⑤ 主机加载   node list；失败回退 all
→ ready：表单解禁，场景/主机已填充
```

阶段状态机：

```
idle → preparing{env-probe → acli-sync → catalog-load} → ready
                                                      ↘ failed（该步可重试，不整单失败）
ready → collecting → pulling/uploading → relaying → done
```

- 场景/主机加载失败属于**降级**，不置 failed；
- ③ 失败置 failed 并给「重试安装」，其余步骤不可继续。

## 六、探测契约（bridge `probe` 扩展）

```json
{
  "architecture": "x86_64",
  "acli_installed": true,
  "acli_version": "x.y.z",
  "available_mb": 20480,
  "log_server_reachable": true,
  "modules": [{"value": "vm_suspend", "label": "虚拟机挂起专项", "source": "acli_help"}],
  "hosts": [{"ip": "10.10.1.21", "name": "node-1"}],
  "catalog_source": "acli_help | platform_default",
  "catalog_note": "help 解析失败，已回退平台默认场景"
}
```

解析规则（help）：

- 截取 `可直接选择的选项` 之后的文本；
- 正则 `([a-z_]+)\（([^）]*)\）` 提取 value/label；
- 去重并保持出现顺序；`other` 保留但 UI 标记为"默认收集"。

解析规则（node list）：

- `acli --formatter json platform node list`，逐层查找含 `ip|address|host` 且形如 IPv4 的字符串；
- 失败 / 超时（5s）→ `hosts=[]`。

## 七、交互规则

| 元素 | 规则 |
|---|---|
| 未登录 SSH | 「确定」禁用（强制），提示"请先登录 SSH" |
| 已有会话 | 跳过弹框，直接进面板 |
| 发起节点 | 连接成功自动填 host；准备阶段只读展示，可手动改 |
| 故障场景 | 准备阶段④完成后加载；来源标注 `acli help` / `平台默认` |
| 目标主机 | 准备阶段⑤完成后加载；默认 `all`，可选具体节点 |
| 自动安装 | 去掉确认框，阶段③直接展示进度 |
| 密码 | 不落盘（localStorage 仅 host/port/username） |
| 采集中 | 禁止换工单 / 重新登录 / 修改场景 |

## 八、异常与兜底

| 场景 | 处理 |
|---|---|
| help 无枚举 / 语言不同 | 回退 10 项，`catalog_source=platform_default`，UI 提示 |
| node list 解析失败 | `hosts=[]`，UI 只给 `all` + 手工输入 |
| acli 安装失败 | 阶段③ failed + 原因 + 「重试安装」 |
| 准备阶段断开 SSH | 当前阶段 failed + 「重新登录」入口 |
| 采集阶段断开 SSH | 警告条；任务状态按平台快照展示 |
| 页面刷新 | 会话丢失 → 下次打开回到未连接 |

## 九、测试与验收

单元测试：

- `SshConnectSection`：bridge 未运行→引导；检测通过→表单；连接失败→错误留在表单；成功→emit `connected(host)`；
- `LogCollectCaseDialog`：未连接时确定禁用；connected 后启用且发起节点被填充；
- store：`openLogCollect` 已连接直开面板 / 未连接开弹框；
- 后端/bridge：help 解析（标准输出、无枚举、乱码）、node list（正常 JSON、非 JSON、超时）。

staging 人工验收：

1. 无会话点入口 → 弹框内先检测 bridge；
2. 连接成功 → 发起节点自动填充 → 确定 → 面板准备阶段可见 ①~⑤；
3. acli 未安装场景 → 自动安装并展示进度；
4. 场景/主机来自探测（或明确标注平台默认）；
5. 已有会话点入口 → 不弹框直接进面板。
