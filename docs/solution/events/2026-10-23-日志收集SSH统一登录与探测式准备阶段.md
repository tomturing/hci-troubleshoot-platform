## 一、背景与问题

日志收集依赖 `acli log_collect`，而该命令必须通过 **terminal_bridge 已建立的 SSH 会话**执行。
上线后暴露两个可用性问题：

1. 「指定工单号」弹框没有 SSH 入口，用户看到「发起节点」却不知道密码该在哪填；
2. SSH 表单/连接状态机原本内嵌在 `SshConnectDialog` 中，日志收集若要复用只能复制一份——违反"单一模板"。

同时采集表单的「故障场景」「目标主机」是写死的：

- 故障场景硬编码 10 项（`LogCollectPanel.MODULES`），与 acli 实际支持能力可能漂移；
- 目标主机只能手填或 `all`，用户无法知道集群有哪些节点。

## 二、事实核查（2026-10-23 实机 `acli log_collect create --help`）

```
-m|--modules=STRING   日志收集专项，使用英文逗号拼接指定的专项，示例：-m vm_suspend,network
                      可供选择的专项，不设置则默认other，枚举值：
                        vm_suspend（虚拟机挂起专项）      vm_start（虚拟机开机失败专项）
                        host_offline（主机离线专项）      network（网络专项）
                        storage（虚拟存储专项）           slowdisk（卡慢盘专项，单天收集时间约4min）
                        performance（性能专项）           core（core文件专项）
                        system（中台专项）                other（默认收集专项，不收集上述n个场景日志）
-i|--ips=STRING       主机 ip，格式 1.1.1.1,1.1.1.2；all 收集所有主机
错误: 未定义参数: --help          ← 注意：help 文本完整打印，但退出码为 1
```

三个反直觉事实（直接决定了实现方式，也是初版文档写错的地方）：

1. **`--help` 退出码是 1**：插件把 `--help` 判为未定义参数，但仍完整打印正文。
   → 解析器**不能以退出码为准**，只能认输出内容；否则永远解析失败、永远回退内置目录。
2. **枚举按两列排版**：同一行出现两个「名称（标签）」。
   → 任何"逐行只取一个匹配"的写法会丢掉一半场景，必须全量正则扫描。
3. **`node list` 结构是固定的**：`{"data":[{"ip","id","master","name","controller","status","alert"}]}`。
   → 不需要"递归找 ip/address/host"的猜测式兜底，按字段解析 + IPv4 校验即可。

结论：

| 能力 | 可行性 | 实现 |
|---|---|---|
| 故障场景 | ✅ help 明确列出 `-m` 枚举 | bridge 执行 `acli log_collect create --help`，解析「枚举值」到「说明」之间的段落；解析失败回退平台内置 10 项并标注来源 |
| 目标主机 | ✅ `acli --formatter json platform node list`（命令目录已收录） | bridge 执行后按 `data[].ip` 解析并校验 IPv4；失败回退 `all` + 手工输入 |
| 节点列表字段 | ✅ 实机字段已固化（`ip`/`name`/`master`） | 直接读 `data[].ip`，非法 IP 与重复 IP 丢弃；解析不到视为空，不阻塞 |

## 三、组件架构（单一 SSH 模板）

```
SshFormSection.vue        纯字段（host/port/username/authType/password|key）——唯一
        ▲
SshConnectSection.vue     状态机 + 视图（bridge 引导 / 表单 / 连接中 / 失败 / 已连接）——唯一
        ▲                    ▲
SshConnectDialog.vue      LogCollectCaseDialog.vue
（el-dialog 薄壳）        （mode="inline" 内嵌）
```

约束：

- 任何调用方**不得**再写 SSH 字段或连接逻辑；
- `SshConnectSection` 通过 `connected(host)` 事件对外暴露主机，由调用方决定后续（开面板 / 填充发起节点）；
- `dialog` 模式保留 1.5s 自动关闭；`inline` 模式不自动关闭，成功后折叠为状态条。

## 四、用户旅程

### A. 首次使用（无 SSH 会话，bridge 已运行）

```
点「🗂 日志收集」
→ openLogCollect() 检测 sshConnectionState !== 'connected'
→ 打开「指定工单号」弹框：工单号 + 内嵌 SSH 登录区（先检测 bridge）
→ 填工单号 + IP/账号/密码 → 点「确定」（登录与提交合并为一步，见 2026-10-26 修订）
→ 登录成功 → 弹框关闭 → 左侧面板直接滑出，不弹 SSH 终端抽屉
→ 自动带出「发起节点 = 10.10.1.21」
→ 准备阶段（①~⑤）→ 就绪
```

### B. 已有 SSH 会话

```
点「日志收集」→ 已连接 → 跳过弹框，直接打开面板
面板顶部显示「归档工单 Qxxx  ·  SSH root@10.10.1.21」
```

### C. bridge 未运行

```
SSH 区显示「SSH Bridge 未运行」+ [⬇ 下载] [🔄 已启动，重新检测]
工单号可先填；点「确定」会现探一次 bridge，仍不通则提示「SSH Bridge 未运行：请先下载并启动…」，
不登录、不提交（2026-10-26 起「确定」不再因未登录/未就绪而禁用）
```

### D. 连接中断 / 换节点

```
准备阶段断开：该阶段失败 + 「重新登录」；不自动关闭面板
采集阶段断开：顶部警告「SSH 会话已断开，采集可能中断」；任务状态以平台为准
换节点：重新登录 → host/port/username 预填（不含密码）→ 成功后发起节点自动更新
采集中禁止更换（running 时按钮禁用）
```

## 五、准备阶段（点确定后）

```
① 登录会话   ✓（弹框内已完成，面板只展示）
② 环境探测   架构 / acli 版本 / 磁盘余量 / 5888 连通性
③ acli 检查   未安装 → 标记「需要安装」+ 一键安装（下载/分发/校验，展示进度）
④ 场景加载   help 解析；失败回退平台默认
⑤ 主机加载   node list；失败回退 all + 手填
→ ready：表单解禁，场景/主机已填充
```

阶段状态机：

```
idle → preparing{env-probe → catalog-load} → ready
                                          ↘ failed（可点「重新读取」，不整单失败）
ready → collecting → pulling/uploading → relaying → done
```

- 场景/主机加载失败属于**降级**，不置 failed；
- ③ 安装失败仍走开始收集时的显式确认与重试，面板不因未装 acli 而 failed。

## 六、探测契约（bridge `probe` 扩展）

```json
{
  "architecture": "x86_64",
  "acli_installed": true,
  "acli_version": "x.y.z",
  "available_mb": 20480,
  "log_server_reachable": true,
  "modules": [{"value": "vm_suspend", "label": "虚拟机挂起专项"}],
  "hosts": [{"ip": "10.10.1.21", "name": "node-1", "master": false}],
  "catalog_source": "acli_help | platform_default",
  "catalog_note": "help 解析失败，使用平台内置场景目录"
}
```

`modules` 不逐项带 `source`：同一次探测产出的目录必然同源，逐项重复反而制造"一半 acli 一半内置"的伪状态；来源统一由 `catalog_source` 表达。

解析规则（help）：

- 截取 `枚举值` 之后、`说明` 之前的文本（结尾的 `错误: 未定义参数: --help` 天然被排除）；
- 正则 `([a-z][a-z_]+)（([^）]{1,40})）` 全量扫描（两列排版），value 必须命中 bridge 白名单；
- 去重并保持出现顺序；到期文案改版导致「枚举值」缺失时整段放弃、回退内置目录，不做猜测。

解析规则（node list）：

- `acli --formatter json platform node list`，截取最外层 `{...}` 后按 `data[].ip` 解析；
- `ip` 必须匹配 IPv4 且去重，`master == 1` 标记主控；
- 失败 / 超时（8s）→ `hosts=[]`。

## 七、交互规则

| 元素 | 规则 |
|---|---|
| 未登录 SSH | 「确定」一键完成登录 + 提交（不再有独立「连接」按钮）；登录失败不提交工单，且不弹 SSH 终端抽屉 |
| 已有会话 | 跳过弹框，直接进面板 |
| 发起节点 | **只读事实**：派生自当前 SSH 会话（`sshCurrentConfig.host` → `lastSshHost`），展示时标注「当前 SSH 会话」，不提供输入框；重登录到另一节点触发重探（500ms 防抖），采集中不重探 |
| 故障场景 | 面板打开即加载；来源标注 `集群 acli` / `平台内置`；不在目录中的旧选中项自动收敛 |
| 目标主机 | 有节点清单时用多选（不选=全部在线节点），无清单回退手填 |
| 自动安装 | **保留一次显式确认**：面板打开即准备，若自动装会把"打开面板"变成"变更集群" |
| 密码 | 不落盘（localStorage 仅 host/port/username） |
| 采集中 | 禁止换工单 / 重新登录 / 修改场景 |

## 八、异常与兜底

| 场景 | 处理 |
|---|---|
| help 无枚举 / 语言不同 | 回退 10 项，`catalog_source=platform_default`，UI 提示 |
| node list 解析失败 | `hosts=[]`，UI 只给 `all` + 手工输入 |
| acli 安装失败 | 阶段③ failed + 原因 + 「重试安装」 |
| 准备阶段断开 SSH | 当前阶段 failed + 「重新登录」入口 |
| 采集阶段断开 SSH | 警告条；任务状态按平台快照展示 |
| 页面刷新 | 会话丢失 → 下次打开回到未连接 |

## 九、测试与验收

单元测试：

- `SshConnectSection`：bridge 未运行→引导；检测通过→表单；连接失败→错误留在表单；成功→emit `connected(host)`；
- `LogCollectCaseDialog`：未连接时点「确定」先登录再提交（`connect → confirm` 顺序），登录失败不提交；
- store：`openLogCollect` 已连接直开面板 / 未连接开弹框；
- 后端/bridge：help 解析（标准输出、无枚举、乱码）、node list（正常 JSON、非 JSON、超时）。

staging 人工验收：

1. 无会话点入口 → 弹框内先检测 bridge；
2. 连接成功 → 发起节点自动填充 → 确定 → 面板准备阶段可见 ①~⑤；
3. acli 未安装场景 → 自动安装并展示进度；
4. 场景/主机来自探测（或明确标注平台默认）；
5. 已有会话点入口 → 不弹框直接进面板。

### 后续修正（staging 实测发现）

上线后实测暴露两处缺口，已在
[2026-10-23-日志收集准备阶段触发与勾选交互修复.md](2026-10-23-日志收集准备阶段触发与勾选交互修复.md) 中修复：

1. **探测不触发**：`App.vue` 用 `v-if="logCollectCaseId"` 挂载面板，而工单号与 `visible`
   在同一 tick 赋值，组件"带着 `visible=true` 首次挂载"；`watch(visible)` 缺 `immediate`
   导致 `prepare()` 一次都没执行，界面长期停在「尚未读取集群目录，当前展示平台内置项」。
2. **会话键不匹配**：本弹框内嵌的 `SshConnectSection` 未传 `case-id`，`connectSSH` 退化为
   `terminal-only`，面板按工单号取会话必然 `session_missing`（LC-ENV-006）。
   现补 `:case-id`，并在 bridge 侧增加"同节点会话回退"兜底。

同时把「故障场景」「目标主机」由下拉多选改为勾选框全量平铺，取消折叠标签。

### 后续修正（发起节点去输入化）

「发起节点」原为可编辑输入框（自动填充 + 允许手改），与 bridge 的会话语义冲突：
会话键是 `caseID@nodeIP`，用户改成一个没有会话的 IP 只会换来 `session_missing`，
改成另一台已登录节点的 IP 则会让采集跑在与界面显示不一致的机器上。

- `LogCollectPanel`：`form.nodeIp` 移除，改为派生值 `nodeIp = sshCurrentConfig.host（connected 时）→ lastSshHost → props.nodeIp`；
  界面用只读文本 + 「当前 SSH 会话」标签展示，不提供输入框；`sendAndWait` 不再让 `props.nodeIp` 覆盖 payload，所有 bridge 动作锚定同一派生值。
- 重探触发条件随之变为"会话主机变化"（重登录到另一节点，500ms 防抖），采集中不重探，避免展示值与运行中任务错配。
- 覆盖：`LogCollectPanel.spec.ts` 新增用例，锁定「会话主机优先于 props.nodeIp」与「无输入框、仅只读事实」。
