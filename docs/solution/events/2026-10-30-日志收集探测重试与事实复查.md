# 日志收集：探测失败自动重试与「事实复查」

- 日期：2026-10-30
- 现场工单：Q2026102901049（面板 acli 未安装 / 可采节点未获取，终端 acli 已可用）
- 涉及：`frontend/customer`（`LogCollectPanel.vue`）

## 一、现场事实

| 事实 | 证据 |
| --- | --- |
| 面板显示 acli「未安装」并提示「acli 未安装，无法自动读取节点清单」 | 目标主机区手填提示只在 `probeResult.acli_installed=false` 时出现 |
| 节点清单失败详情为「acli 未安装，使用平台内置场景目录」 | bridge `probeLogCollectCatalog` 在 `!AcliInstalled` 时提前返回 |
| 同一时刻可用空间有值（540088 MB）、架构 x86_64 | 说明那次探测**本身成功**，只是读 acli 这一步落在未安装分支 |
| SSH 终端里 `acli --version` 正常（1.0.1） | 装 acli 发生在探测之后 |
| 面板显示「探测于 09:50:04」，之后无自动刷新 | 探测结论是快照，重探只由 4 个时点触发 |
| 用户点「重新探测」无反应，F5 刷新页面后才更新 | `prepare()` 在 `prepareState === 'probing'` 时静默 `return false`；F5 重建组件把该状态归零 |

## 二、根因

1. **重入被状态挡死且失败不可见**：`prepare()` 首行 `if (prepareState === 'probing') return false`，
   一旦某次探测的等待器丢失（回包被同 action 的后到请求覆盖、组件重挂载丢 waiter），
   状态永久停在 `probing`；此后不管点按钮还是重开面板都不会再探测，只有 F5 能复活。
   早退分支（token 不匹配）也不复位 `prepareState`，等于把「一次失败」升级成「永久失效」。
2. **探测失败没有重试**：瞬态失败（90s 超时、bridge 通道被踢）与永久失败（会话缺失）同等待遇，
   用户必须自己发现「再点一次就好了」。
3. **成功 ≠ 就绪，且没有复查**：探测成功只代表「这次读到了集群」，acli 可能在探测之后
   被创建工单流程的自动安装装上、节点可能上下线、日志服务器权限可能被放开；
   这些都不改变探测结果，却让面板结论过期，而界面没有任何收敛机制。
4. **手动入口不可见**：`重新探测` 原先埋在探测表下方的小字行，现场找不到。

## 三、本次改动（customer-ui）

### 两类失败、两套节奏

| 类型 | 判定 | 处理 |
| --- | --- | --- |
| 瞬态失败 | probe 超时、bridge 通道断开、连接超时、未知桥侧异常 | 指数退避重试 3 次：2s / 4s / 8s（±20% 抖动） |
| 永久失败 | `LC-ENV-006` / `session_missing` / 未连接 SSH | 不重试，直接告警（重试只会把同一个失败重放 3 次） |

- 抖动是多客户端同时探测时避免同相位冲击同一节点。
- 重试期间 `prepareState` 保持 `probing`，按钮 loading，并在表单上方显示
  「环境探测失败（原因），N 秒后自动重试（第 i/3 次）」——用户必须能分清「没反应」与「正在重试」。
- 重试成功即收敛，不再发下一次。

### 成功标准（与现场确认）

**通道通 + acli 已装 + 节点清单非空** 视为探测成功，停止重试。

- 日志服务器可达性**不参与**成功判定：它是网络现状（ACL/端口），不是探测故障。
- `acli 未安装` 不是故障而是事实，重试一万次也不会变——所以它不进重试，进复查。

### 事实复查

- 触发条件：`!acli_installed` 或 `hosts` 为空或 `log_server_reachable=false`。
- 节奏：面板可见时每 30s 复查一次，最多 3 次，页面不可见或采集中不复查。
- 复查不复用重试（`retries: false`），避免「重试 3 × 复查 3」放大成 9 次 SSH 调用。
- 复查自身触发的探测**不归零**复查计数；手动重探 / 换工单 / 换节点才归零。
- 达成成功标准后不再复查，实现「在终端装好 acli，面板自己点亮」。

不重试的两处例外（都属「用户已经在等一个确定结果」）：

- 「开始收集」时的现场补探（`handleStart`）：退避叠加会把一次下发拖上几分钟，等待时间必须可预期。
- 面板内 `acli_sync` 安装成功后的重探（`confirmInstall`）：安装已是既成事实，
  重探失败不拖住用户；真没读到则由事实复查在 30s 后补读。

### 卡死自愈

- 新增 `probingStartedAt`：超过 120s（`PROBE_STALL_MS`）仍为 `probing` 判定为卡死，允许强制重入。
- `visible` 打开时的重探不再用 `prepareState !== 'probing'` 做前置判断——用状态挡会把
  「上一次探测卡死」变成「永远不再探测」。

### 入口调整

- 「重新探测」移到归档工单工具条「刷新进度」右侧，常驻可见；采集中禁用。
- 探测表下方的重复入口移除，只保留「探测于 HH:MM:SS + 实际命中的 acli 路径」。

## 四、验收

1. 首次 probe 回 `probe 超时（90s）` → 出现「自动重试（第 1/3 次）」；2s 后发第二次 probe；
   成功后面板刷新为新的 acli 版本与可采节点数，且不再发第三次（已覆盖单测）。
2. probe 回 `LC-ENV-006` → 不重试，20s 内 probe 总数保持 1（已覆盖单测）。
3. 首次 probe 回 acli 未安装 → 30s 后自动发第二次 probe；成功后「acli 未安装」提示消失，
   120s 内不再继续探测（已覆盖单测）。
4. 工具条同时含「刷新进度」「重新探测」，且不含「关闭 / 钉住」（已覆盖单测）。
5. 探测进行中点「重新探测」→ 按钮 loading + 提示「正在探测集群环境，请稍候」，不再静默无反应。

## 五、未覆盖（后续）

- 同机多份 acli 的版本分歧：现场面板读 `/sf/bin/acli` 为 1.0.0，终端手敲为 1.0.1。
  bridge 已把命中路径回传（`acli_binary`），但「哪一份才是应采集的」需要现场确认后再定策略。
- 日志服务器从节点侧不可达（HTTP 0 / curl 缺失）仍只做单次告警，不自动降级交付路径。
