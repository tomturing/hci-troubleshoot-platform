# 2026-11-17 日志收集写入去除 base64 依赖方案

## 背景与需求

见 [需求事件文档](../../requirement/events/2026-11-17-日志收集写入去除base64依赖.md)。HCI 宿主机无 `base64`，而 bridge 在宿主机执行写入，导致 `LC-SPC-004 write_rejected`。

## 方案概述 (WHAT)

1. spc 写入改为 `printf '%s' <shellQuote(content)> > <target>`，校验改为 `printf '%s' <content> | cmp -s - <target>` 逐字节比对。
2. `-c` 配置写入同改；校验保留 `sha256sum` 优先，缺失时降级 `printf` 重传 + `cmp` 逐字节比对。
3. prepare/write/restore 三个 marker 失败分支都把 stderr 并入 `error_detail`。

## 详细设计

### 为什么 `printf '%s'` 安全

- `printf` 是 bash/dash/busybox 的 shell 内建，宿主机必在；`base64` 是可选外部命令。
- 内容用 `shellQuote` 单引号包裹：`$`、反引号、`"`、`*` 都不展开；单引号按 `'\''` 转义。
- `printf '%s'` 不追加换行、不解释参数里的转义，写入字节与原始内容完全一致（`spc_sha256` 不受影响）。

### 为什么不用 heredoc

heredoc 会在内容末尾追加换行，导致写入字节比 `spc_sha256` 多 1 字节，破坏摘要自洽；且若 delimiter 与内容行冲突会截断。`printf '%s'` 无此问题。

### 校验方式

```sh
printf '%s' '<content>' | cmp -s - '<target>'
```

- 逐字节比对，不经过 shell 变量：`$(cat)` 命令替换会剥掉**末尾换行**，清单原文若以换行结尾（合法 JSON 空白）会写对了也误判 `verify_mismatch` 并回滚，故弃用。
- `cmp` 已是 prepare 阶段备份保真校验（`cmp -s`）的硬依赖，宿主机实测具备，不新增工具假设；`base64`/`sha256sum` 均不再作为校验前提。
- 不在 stdout 打印内容，避免污染 `SPC_` marker 解析。

### 归因

`applySpcSlotToHost` 的 prepare/write 失败分支与 `restoreSpcSlotOnHost` 的 restore 失败分支统一改为 `spcOutputTail(spcJoinDiag(out, errOut), ...)`，把 stderr 一并落进 `error_detail`（此前只取 stdout，现场只剩 `write_rejected`/`copy_failed` 短名，Q2026110302166 无法自证根因）。

## 决策依据 (WHY)

| 方案 | 优点 | 缺点 | 评分 |
|---|---|---|---|
| A. printf 直写 + cmp 逐字节校验（选中） | 只依赖 shell 内建与 prepare 已有的 cmp；字节精确；改动小 | 内容极大时命令行较长（场景清单有 512KB 上限，实际 ~KB） | ★★★★★ |
| B. 保留 base64，宿主机装 base64 | 不改代码 | 需改客户机系统；不可控 | ★☆☆☆☆ |
| C. 走容器内执行写入 | 容器有 base64 | 依赖容器名/运行时，链路更脆 | ★★☆☆☆ |
| D. heredoc 写入 | 不依赖 base64 | 多一个换行，破坏摘要自洽 | ★★☆☆☆ |

选择 A：第一性原理上写入只需要"把已知字节落到文件"，`printf` 就能做到，`base64` 只是传输编码，在宿主机不可用时是纯负担。

## 影响范围

- `terminal_bridge/log_collect_spc.go`、`log_collect_spc_fanout.go`、`log_collect_config.go` 及相关测试。
- 不改契约错误码；`LC-SPC-004` 语义不变，但 `error_detail` 信息量提升。
- 需重建 exe 并现场人工重装才生效。

## 风险与缓解

| 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|
| 内容含单引号导致引用错误 | 写入失败 | 低 | `shellQuote` 按 POSIX 转义，补单测 |
| 内容超长导致命令行限制 | 写入失败 | 低 | 场景上限 512KB，实际 KB 级；超限由既有校验拒绝 |
| 宿主机缺 `cmp` | 校验失败即回滚 | 低 | prepare 备份保真校验已硬依赖 cmp，缺 cmp 时更早的 prepare 就会失败并带 stderr 归因 |

## 验收标准

- [ ] 写入命令不含 base64 且字节一致（含尾换行原文的真 shell 回归）。
- [ ] `-c` 通道同步修复。
- [ ] prepare/write/restore 失败时 `error_detail` 含 stderr。
- [ ] Go 全量测试 + gofmt + docs 门禁通过。

## 测试策略

单测覆盖：写入命令不含 base64、含单引号/`$`/`*` 的内容可正确引用、校验命令用 `printf | cmp` 逐字节比较（禁止 `$(cat)` 命令替换）、marker 失败分支诊断保留 stderr；另以本地 `sh -c` 真跑写入+校验脚本验证尾换行原文字节级自洽。现场需重装 exe 后复测 Q2026110302166。
