# 平台内置硬编码治理审计

## 一、背景

HCI 智能排障平台的目标不是把某个具体排障案例写进代码，而是提供一套可运行、可插拔、可热生效的 Agent 能力平台。KBD、SOP、工具、技能和 Prompt 应由数据驱动；代码只保留稳定的执行内核、协议适配、安全边界和可观测性。

本次审查 PR 461 时发现，平台已有管理页面和数据库表，但多个运行时链路仍存在内置注册表、固定分支、启动期缓存和业务规则硬编码。其直接后果是：管理员在页面上新增或修改资源后，Agent 运行时并不一定使用新资源，甚至会继续走旧代码路径。

## 二、第一性原理

平台代码应回答“如何安全执行”，业务数据应回答“执行什么、何时执行、如何解释”。

| 层次 | 应放在代码中 | 应放在数据中 |
|---|---|---|
| 内核协议 | HTTP/SSE/Redis/DB 访问、鉴权、审计、trace_id、事务边界 | 不适用 |
| 安全底座 | 命令净化器、确认门禁、权限模型、沙箱边界、失败语义 | 风险规则、允许容器、工具启停、策略参数 |
| 能力定义 | 通用解释器、schema 校验器、资源加载器 | Tool/Skill/Prompt/SOP/KBD 定义、版本、状态 |
| 业务规则 | 不应写死具体 SOP 规则 | 告警解析规则、厂商寿命规则、变量派生规则、分类知识 |
| 运行状态 | 状态机实现 | execution/context/fact/audit 记录 |

判断某段代码是否属于不合理硬编码，可以问三个问题：

1. 运维人员是否希望不发版就修改它？
2. 它是否包含某个具体业务场景、SOP、工具名、告警类型或厂商规则？
3. 它是否已经在数据库管理页面存在对应资源，但运行时没有读取？

任一为“是”，就应优先下沉到数据驱动能力面。

## 五、允许保留在代码中的内核能力

不是所有固定逻辑都应消失。以下内容可以保留在代码中，但必须有清晰边界：

| 类型 | 可保留原因 | 约束 |
|---|---|---|
| 协议适配器 | 外部系统协议本身稳定，例如 Redis/SSE/HTTP 客户端 | 不包含具体业务工具名 |
| 安全 fail-closed | 数据缺失时必须保守拒绝 | 拒绝规则可配置，默认拒绝留在代码 |
| 通用解释器 | JSON Schema 校验、模板渲染、表达式求值器 | 解释器通用，规则来自 DB |
| 审计与可观测性 | trace_id、exec_id、审计落库、指标 | 所有动态资源调用都必须透传资源版本 |
| 数据访问仓储 | CRUD、事务、锁、缓存实现 | 不包含业务资源内容 |

## 六、治理原则

1. 单一事实源：每类资源只有一个权威定义表，代码不得重复维护同一份业务定义。
2. 运行时读取：管理页修改后，Agent 必须通过统一加载器读取最新发布版本，不能只在启动时加载。
3. 强校验：资源保存、发布、运行前都要校验引用完整性，缺失 tool/skill/prompt 时 fail-loud。
4. 可观测：每次 Agent 使用动态资源时记录 resource_type、resource_name、version、revision、trace_id、exec_id。
5. 可回滚：资源版本化，不用脚本回滚未合并 PR 的错误状态；生产回滚通过激活旧版本完成。
6. 微内核：平台内核只提供通用 provider、runner、validator、cache、audit；业务能力通过数据资源扩展。

## 七、PR1 验收标准

- `skill_call` 生产链路不再调用 Python 内置业务技能，新增/修改 active `skill_definition` 后下一次变量请求可读取新 Skill。
- Python 内置注册表不再包含 `disk_vendor_lifetime`、厂商匹配或 SMART 解析业务规则。
- `env_injection` 不再从告警/任务列表语义猜测 `node_ip/disk_sn/request_id`，只做确定性 `env_info` 字段直取。
- `alert_logs/task_logs/env_info` 可作为显式依赖事实源进入变量池，供动态 Skill 解析。
- 工具定义不再靠重启才能刷新，ReAct/Composite 执行前通过运行时 registry 获取工具定义。
- `get_failed_tasks` 命令构造完全来自数据库 `usage_template`，执行器不再按该工具名拼命令。
- `bash_exec` 可执行容器集合来自工具定义 JSON Schema，不再由执行器或管理端写死具体容器枚举。
- 幻觉检测不再内置默认工具清单，只能基于当前工具 registry 快照识别未执行工具引用。
- Markdown 明确声明的新变量策略、`depends_on`、`output_path`、`fallback_strategy` 能同步到 `variable_schema`，不会被旧自动推断策略锁死。
- 未合并 PR 的错误数据变更直接删除，不提交 `revert_is_sys_disk_skill.sql`。
