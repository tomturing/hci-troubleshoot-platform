# KBD 终极解耦重构方案实施计划（双通道语义数据模型改造）

本计划旨在完美落地 [KBD生产管理消费设计.md](file:///mnt/d/aihci/hci-troubleshoot-platform/docs/solution/knowledge-base/KBD生产管理消费设计.md) 中规划的**“双通道数据分离存储”**终极解耦重构方案。

我们将为 KBD 知识条目数据库表和应用层模型注入 `content_raw`（无噪纯文本语义通道），同时在入库与编辑时实现工业级的自动去 Markdown 标记与占位符去燥处理，并对审核阶段的 Embedding 向量表示生成过程进行终极纯净化改造。

---

## 1. 用户审核与核心技术决策

### 1.1 新增数据库物理字段 `content_raw`
* **表与列**：在数据库 `kbd_entry` 中新增字段 `content_raw` (Text 类型)。
* **用途**：作为专供 AI 代理、LLM 智能搜索以及 RAG 检索的高纯度物理语义通道，消除所有 `![img:N]`、HTML 标签、星号/下划线 Markdown 语法标记的噪点。
* **物理迁移**：生成并应用 Atlas 数据库迁移。

### 1.2 工业级去 Markdown/占位符正则过滤器
* 在 `kbd_entry.py` 中实现高效的 `strip_markdown` 核心函数，通过 9 个精心编排的清洗阶段彻底剔除所有格式化标记，而对字面量文字不作任何截断和损伤。

### 1.3 双通道协同更新控制逻辑
* **入库时（Ingest）**：当 API 接收到 `content_md` 时，如果未显式提供 `content_raw`，系统自动使用 `strip_markdown` 进行全量去燥并生成 `content_raw`。
* **编辑时（PATCH）**：当管理员编辑章节字段引发 `content_md` 自动重建时，系统同步调用 `strip_markdown` 重建对应的 `content_raw` 并写入数据库。
* **展示/查询时**：API 详情与列表响应均补充返回 `content_raw`，供 AI 智能体零噪音地直接消费。

### 1.4 高精度 Embedding 优化
* 在 KBD 审核通过（Approve）生成向量阶段，将拼接的标题、问题描述、告警信息与根因（Question-side fields）传入 `strip_markdown`，确保语义模型生成的 1536 维 pgvector 向量处于绝对纯净的向量表示空间，完全杜绝 Markdown 符号引发的余弦距离偏差。
