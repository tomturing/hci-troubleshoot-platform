# 5888 上传进度端点与重启窗口

## 变更历史

| 日期 | 版本 | 变更内容 | 关联事件文档 |
|------|------|---------|------------|
| 2026-11-10 | v1.0 | 为 P1 直传补 `/upload_progress` 只读端点；给出权威补丁、硬门禁、隔离验证与回滚 SOP，闭合 PR #1478 留下的 `unsupported` 降级 | [日志上传管理页与进度代理](./2026-11-10-日志上传管理页与进度代理.md) |

## 一、问题：平台已就绪，数据源缺一个端点

PR #1478 上线了管理端「日志上传」页，P1 行按产物名调 5888 的
`/upload_progress?filename=Q{13位}.zip`。`SangforRelayClient.upload_progress()`
对 404 就地降级为 `unsupported`，因此平台可以先发布；代价是所有 P1 行都
显示「该日志服务器不支持进度查询」。5888 是独立部署在
`192.168.0.2:/acli` 的**无 remote 本地 git 仓库**，改它必须约重启窗口。

用户诉求：「确认现在 P1 是否有正在上传的任务，如果没有可以重新 5888；
并完成相关验证」。

## 二、第一性原理：把约束拆到不可再分

| 事实 | 推出的硬约束 |
|---|---|
| P1 由节点 acli 自己 `init_upload`，平台没有 `upload_id` | 产物名是两侧唯一公共键，端点必须按 `filename` 查询 |
| 5888 会话文件是单进程 gunicorn 4 worker 共享的唯一进度真源 | 只读扫描；**不能** `load_upload_session()`（它过期时会删会话与分片） |
| `session_reaper.py` 24h 清会话，归档件永久保留 | 只查会话会把「已交付的 P1」显示成「暂无记录」，必须兜底读归档事实 |
| 平台 `_session_matches_generation` 拿 `start_time` 与 aware `created_at` 比较 | 必须返回带 `+00:00` 的 UTC ISO；naive 字符串会 `TypeError` → 500 |
| `查不到 ≠ 失败`（Q2026110600940、Q2026111000243 两次事故） | 无记录返回 `found=false` 且 HTTP 200，平台不写任何任务状态 |
| 重启会替换 worker，破坏的是在途分片与合片进程 | 硬门禁只能看 5888 主机上的直接证据，平台 DB 只是交叉验证 |

## 三、对抗性审查找出的 5 个致命点（均已修）

1. **`timezone` 未导入**：现网 `app.py:17` 只有 `datetime, timedelta`，
   `datetime.fromtimestamp(..., tz=timezone.utc)` 会 `NameError` → 500。
   补丁同步补上 import。
2. **naive ISO 代际比较**：平台 `_iso()` 返回的 naive datetime 与 aware
   `created_at` 比较会抛 `TypeError`。新增 `_unix_to_utc_iso()`，旧会话里
   的 naive ISO 先按本机时区解释再转 UTC，不粗暴补 UTC。
3. **终态丢失**：会话被回收后仅剩归档件。新增 `_latest_archived()` 兜底，
   回报 `status=done / progress=100 / target_path`，并把归档 mtime 作为
   `start_time`，让平台仍可做代际校验。
4. **`difflib` hunk 行数错误**：把 164 行代码块当单个列表元素时，生成的
   hunk 头是 `+1440,7`（只 +1 行），`patch --dry-run` 直接 FAILED。
   `build_patch.py` 改为 `splitlines(keepends=True)` 逐行展开。
5. **TCP 状态码写反**：`/proc/net/tcp` 里 `0A` 是 `TCP_LISTEN=10`，
   `01` 才是 `TCP_ESTABLISHED=1`。初版硬门禁把 5888 自己的监听 socket
   当成在途上传，**永远拒绝重启**；实测采样（仅 LISTEN + FIN_WAIT1 +
   本地 healthz 的 TIME_WAIT）校正后修正。

## 七、回滚

平台侧**无需回滚**：404 就地降级为 `unsupported`，管理页只显示「不支持
进度查询」，不报错、不写库。5888 侧执行 `rollback.sh` 从最近备份恢复并
校验回到基线 sha256，再让 worker 生效即可。

## 八、已知限制

- 会话 `status=failed` 会如实回传 `error`，但平台 `_map_progress` 把非
  `uploading`/`done` 统一显示「暂无记录」（PR #1478 既有语义），本次不改
  平台代码；要精确呈现上传失败需另开迭代。
- 归档兜底只有落盘事实，`digest` 为空；会话回收后 sha256 需查
  `/upload_status/<upload_id>` 或归档索引。
- 端点每次扫描整个会话目录（当前 22 个文件），平台侧 30s 轮询 + 10s TTL
  缓存已限流；会话数到千级应改按产物名建只读索引。
