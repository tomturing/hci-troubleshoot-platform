## 一、问题

设计文档 §6.1 记的债是：**根目录有 5 个 `package main` 孤儿测试（无对应实现）**，而跨域守卫归属不清；同时 `sshx` 这个承载全部节点连接的包**零测试覆盖**——它的行为测试滞留在了根目录。

零测试 + 行为测试错位，等于"断连、保活、通道回收这些最容易出事故的地方，改动后没有任何回归保护"。

## 二、孤儿测试的归属判据

只看一个问题：**被测符号住在哪个包，测试就搬到哪里**。不看"它以前在哪"。

| 孤儿文件 | 被测对象 | 新位置 | 判据 |
|---|---|---|---|
| `probe_and_classify_test.go` | `sshx.ClassifyExecFailure` / `DeviceAbsentFromProbe` / `ProbeLevel` | `internal/sshx/probe_classify_test.go`（`package sshx_test`） | 纯函数，属节点探测层 |
| `wrap_container_test.go` | `sshx.WrapContainerCommand` / `ScanFirstShellToken` | `internal/sshx/wrap_container_test.go`（`package sshx_test`） | 容器包装语法，属节点执行层 |
| `ssh_input_routing_test.go` | `session.Hub` 的输入路由与会话键 | `internal/sshx/session/input_routing_test.go`（`package session_test`） | 路由在 Hub |
| `session_busy_test.go` | `Bridge.Set/ReleaseSession` + 长任务保护 + 重连摘表 | `internal/app/session_busy_test.go`（`package app`） | 编排在 Bridge（app），不是 Hub 本身 |
| `remote_convergence_test.go` | 全仓 import 图 + 跨包字节 golden | **保留根目录** | 只有仓库根有"整个仓库"的视野；任何业务包都扫不全 |

`remote_convergence_test.go` 的文件头已写明它是**唯一**允许留根的测试，并列出其余四个的去向，避免下一个人再把它当"没搬完"。

## 三、四组测试的取材（不是凑数）

### 3.1 租约（`hub_lease_test.go`）

| 断言 | 对应事故形态 |
|---|---|
| `Release` 幂等且刷新空闲起点 | 页面刷新触发第二次 Release，若不刷新，刷新反而让会话更快被回收 |
| 保护期内 `ReapCandidates` 把起点推到当前 | 2026-10-28：保护解除后按"终端早已断开"的旧起点立刻回收，交付卡在 uploading |
| 无租约簿记的键不参与回收 | 与 `onExit` 形成两条并行销毁路径（状态双写） |
| `TTL<=0` 禁用回收 | 参数语义必须显式，避免"设 0 变成立即回收" |

### 3.2 keepalive（`keepalive_test.go`）

- `SshKeepAliveInterval`：默认 30s、env 覆盖、`0`/负值关闭、非法值回落；
- `ProbeKeepAlive` 无 client → 立即报 `ssh client 已关闭`（不能等 10s 探测超时）；
- `StartKeepAlive` 对手工构造会话（`Done==nil`）短路，不留永不被回收的 goroutine；
- `SessionBusyGrace`：默认值、env 覆盖、`0` 关闭保护；
- PTY 配套：`NormalizePtyOutput` 幂等且不动孤立 `\r`；`PtyTerminalModes` 显式关 `ECHO/OPOST/ONLCR`（回显会污染 stdout，ONLCR 会把 base64 回读与 cmp 保真校验打偏）。

### 3.3 端口恢复（`session_busy_test.go` 迁入 app）

重连必须摘掉旧会话但**不腰斩长任务**——这是"端口恢复"最容易写错的地方：直接 Destroy 会让在途交付拿到 `session_missing`；只 Set 不 Release 会让旧租约永远挂着。用例同时覆盖二者。

### 3.4 SFTP channel（`sftp_channel_test.go`）

| 断言 | 为什么 |
|---|---|
| 无会话 → `SSH 会话已关闭`，不尝试协商 | 协商必然失败且耗时 |
| 已有缓存 → 返回同一实例 | 每个文件重建通道会多出数百毫秒 |
| `Drop` 关闭一次并清空 | 缓存死通道比不缓存更糟：后续每次列表都失败到用户重连 |
| `Drop` 幂等 | 调用方常在错误路径与 defer 里各调一次 |
| 并发取通道 | `sftpMu` 保护的有效性 |
| 下游错误原样冒泡 | 调用方靠这个错误决定是否 Drop 重试 |
