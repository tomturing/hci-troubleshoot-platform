# 2026-11-23 节点日志采集范围扩展到 acli 全目录

## 背景与需求

工单 Q2026112300134（staging，客户环境 192.168.8.x）日志收集在「准备采集」阶段被
`LC-SPC-003 场景清单备份失败` 拒绝。排查时发现：

- acli 1.0.3 重装清空了 5 台节点的 `plugins/` 目录，其中 8.11/8.14/8.15 三台的内置
  插件没有重建成功（`acli.log` 里全是 `rsync: rename/mkdir ... No such file or directory`）；
- 平台侧只有 `log_collect_process_log` 里的两份文件可用于定位，且只覆盖
  `/sf/log/today/acli/plugins/log_collect/` 这一层；
- 缺失的 `acli.log`（351 KiB，记录 `built_in_plugin` 初始化失败全过程）与
  `cmd_output/*.log` 都不在采集范围内，现场只能让客户手工登录设备拷贝。

需求：**把节点 `today/acli` 目录下所有 `.log` 文件都收上来**，避免下一次排障
再向现场要日志。

## 第一性原理与边界

- 插件/工具自身排障要看它自己的运行日志，而不是「它采了什么日志」；
- 这条链路只依赖 **SSH 读文件**，不调用 acli —— acli 自身坏掉时恰恰最需要这份日志，
  不能再让它成为依赖；
- 目录结构随 acli 版本变化，用**固定深度 glob**（`acli/*.log`、`acli/*/*.log`、
  `acli/*/*/*.log`）而不是递归 `find`：HCI 宿主机是极简系统，`find -printf/-newermt`
  不保证存在，而 glob 由远端 shell 展开，零外部依赖；
- 收取范围仍然有界：单文件 2 MiB、单任务 20 MiB、最多 20 个文件；超限按优先级
  （`acli.log` → `plugins/log_collect/` → `cmd_output/` → 其它插件）保留高价值文件，
  并按 `truncated/skipped` 留痕，不静默少收。

## 改动

### 1. bridge：拆出节点日志采集，扩展为全目录

- 新增 `terminal_bridge/internal/logcollect/log_collect_node_logs.go`：
  `nodeLogListCommand`（三层 glob）、`parseNodeLogPaths`（越界/非 `.log`/`..`/超深
  一律丢弃并去重）、`nodeLogPriority`（超限时的保留顺序）、`collectNodeLogs`。
- `log_collect_evidence.go` 只保留证据协议（票据、网络探测、zip 中央目录、失败陈述），
  不再承载节点日志采集；`gzip`/`sha256`/`hex`/`base64` 四个 import 随实现迁走。
- 调用点 `log_collect.go` 改调 `collectNodeLogs`；仍只在任务终态触发一次
  （`evidenceOnce` 去重），事件名保持 `log_collect.process_logs_*` 兼容既有检索。
- 新增事件：`process_logs_collected`（上报完成，带 found/collected/skipped/bytes）、
  `process_logs_empty`（目录里没有 `.log`，属于事实而非失败）。

### 2. case-service：白名单同步放宽并收紧后缀

- `PROCESS_LOG_DIR` 由 `/sf/log/today/acli/plugins/log_collect/` 改为
  `/sf/log/today/acli/`；
- 入参校验增加 `path.endswith(".log")`，前缀相似目录（如 `acli_eval/`）仍被拒绝。

> 两处必须同改：bridge 发出、case-service 校验，任一侧漏改就是 400 全量丢证据
> （与 2026-11-12 的 404/422 事故同一类）。

### 3. 命名：为什么没有改成 `acli_log_evidence.go`

该文件承担的是「日志收集证据链」（票据与 TLS、网络探测、zip 中央目录、失败陈述、
节点日志），acli 日志只是其中一块；`logcollect` 域内统一用 `log_collect_*` 前缀，
而 `acli_*.go` 属于 `internal/acli` 域（安装/插件同步）。改名会造成跨域语义混淆，
因此选择**拆文件**而不是改名：证据协议留在 `log_collect_evidence.go`，节点日志采集
单独成 `log_collect_node_logs.go`。

## 验证

- `go test ./internal/logcollect/ -count=1` 全绿；新增 4 个用例覆盖 glob 层级、
  路径过滤与优先级顺序；
- `uv run pytest backend/case-service/tests/unit/test_log_collect_evidence_service.py -k process_log`
  4 例通过（含新增：根目录 `acli.log`、`cmd_output/*.log` 可入；`.txt`、`acli_eval/`、
  目录穿越被拒）。

## 影响面与回滚

- 只影响 S7 证据链的「进程日志」页签与 `log_collect_process_log` 表；不影响采集、
  打包、交付主流程（该链路全程尽力而为，失败只留 WARN）。
- 旧 bridge + 新平台：旧桥仍只报 `plugins/log_collect/` 下文件，前缀在新白名单内，
  行为不变；新 bridge + 旧平台会被旧白名单拒绝，属于既有的版本先后约束
  （平台先上、桥后更新）。
- 回滚：还原三处代码即可，已入库的历史日志行保留。
