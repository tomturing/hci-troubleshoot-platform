# 中央区铺满与抽屉退出动画统一

## 一、现场反馈

1. 「只开一个抽屉时，右侧/会话两侧还留着空白，看起来像没撑满」；
2. 「左右抽屉折叠效果不一样：左侧会收窄成一个按钮的特效，最后这个按钮又没了，
   还不如右侧直接消失」。

## 二、第一性原理：留白来自"限制错了层级"

界面上"空白"有两种完全不同的成因，混在一起看就会误判成"宽度算错了"：

| 成因 | 表现 | 正确处理 |
|---|---|---|
| 容器宽度不足，容器外侧露出页面底色 | 两条**白色**竖带，顶栏渐变也断开 | 限制应下沉到内容，容器吃满可用宽度 |
| 内容宽度受限，容器内侧留白 | 同一底色下的**浅灰**留白 | 这是可读行长，属于设计意图 |

实测（1920×1080）：只开左抽屉时 `.app-container` 宽度固定 900、`margin: auto`，
左右各 250px 是 `body` 白底——这就是用户看到的"空白"。`max-width` 加在了错误的层级：
它约束的是「外壳」，而真正应该受约束的是「一行文字读多长」。

同理，抽屉"收窄成按钮"不是动画参数问题，而是**宽度被重置**：
`resolveWorkspaceLayout` 在「该侧未打开」时返回 `width = 0`，而 `el-drawer` 的
`size` 是内联 `width`、**没有 transition**——关闭瞬间宽度先跳成 0，再走 `translateX`
滑出动画。宽度为 0 的抽屉里，标题栏的关闭按钮被挤出来一格，看起来就是
"收窄成一个按钮后凭空消失"。右侧表现不同只是因为它宽度更大、压缩比例在视觉上更明显。

## 三、方案

### 3.1 容器铺满，内容限宽

- `.app-container` 去掉 `max-width`，改为 `width: 100%`（顶栏渐变随之通栏）；
- `.header-content`、`.input-tips`、`.input-row` 取 `var(--ws-center-max)` 并 `margin: 0 auto`；
- `.messages-area` 背景铺满，子项 `width: 100%` + `max-width: 860px`
  （消息条目保持 860 可读行长，窄屏自动退化）。

### 3.2 宽度是面板属性，不是开合结果

- 新增 `standaloneWidth(viewport, side, preferred)`，expanded / 单开分支里
  **未打开的一侧也返回合法宽度**；
- 只有 `leftOffset / rightOffset` 表达"让位"，未打开侧恒为 0；
- 这样退出动画与打开动画同速同向，左右两侧表现一致。

## 四、对抗性审查

| 场景 | 结论 |
|---|---|
| `.messages-area > *` 被 MessageBubble 自身 `max-width:100%` 压掉 | 选择器带到 `.message-bubble`（权重更高）才生效，已在代码注释里写明原因 |
| 系统提示撑满 860 宽的空灰条 | 系统消息 `width: fit-content`；分隔线单独恢复 `width: 100%` |
| 双开 → 单开时另一侧宽度跳变 | 属于设计意图（单开取偏好宽度），且宽度不再归 0，跳变幅度可控 |
| 视口 375px（手机） | 关闭态宽度仍为 `leftMin/rightMin`，抽屉不可见、无副作用 |
| 单测旧断言 `leftWidth === 0` | 语义已变更，改为「关闭态两侧宽度为正且等于偏好」，并在连续视口扫描里区分 offset 与 width |

## 五、验收

- `workspaceLayout.spec.ts` 47 例通过（新增 12 例：关闭态宽度为正、任意开合组合、
  1024~2560 连续视口扫描里 offset 与 width 分开断言）；
- customer 全量 301 例 + `vue-tsc` 通过；
- Playwright 实测（1920×1080）：

| 场景 | 容器宽度 | 顶栏 | 消息条目 | 边缘探针 |
|---|---|---|---|---|
| 无抽屉 | 1920 | 1920 通栏 | 860 | 命中 container |
| 单左（520） | 1400 | 1400 通栏 | 860 | 左侧为抽屉，其余命中 container |
| 单右（720） | 1200 | 1200 通栏 | 860 | 右侧为抽屉，其余命中 container |
| 双开 | 560 | 560 | 340 | 两侧为抽屉 |

- 关闭动画逐帧采样：左抽屉宽度恒 520（x: 0 → −20 → …）、右抽屉恒 720
  （x: 1200 → 1228 → …），全程无 0 宽帧（修复前存在）。
