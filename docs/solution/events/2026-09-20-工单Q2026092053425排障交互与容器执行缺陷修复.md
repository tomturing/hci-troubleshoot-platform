# 工单 Q2026092053425 排障交互与容器执行缺陷修复方案

## 1. 概述与背景

工单 **Q2026092053425** 记录了一次基于 SOP 手册（ID=4，硬盘坏道）排障处理过程中的三个交互与执行异常：
1. **截图 1（人工提供告警信息仍弹出变量输入）**：用户在对话中已将完整告警信息复制输入，AI 仍弹出变量输入卡片要求手动填写变量 `告警原始数据`。
2. **截图 2 & 3（命令执行失败异常）**：
   - 工具 `acli_exec` 执行报错 `bash: acli: command not found` (exit code 127)。
   - 工具 `bash_exec`（容器 `vs-cp-manager`）执行报错 `fatal msg="execing command in container: input is not a terminal"` (exit code 1)。
3. **截图 4（卡片点击无反应随后超时取消）**：前端弹出风险等级为 2 的 `bash_exec` 执行确认卡片，用户点击“确认执行”选项后页面无任何响应，卡片未关闭，120 秒后系统输出“操作已取消”。

---

## 2. 第一性原理与根因解构 (First Principles Analysis)

### 2.1 截图 1 根因：SOP Markdown 变量表格列错位与悬空依赖
- **事实链路**：
  - SOP ID=4（硬盘坏道）Markdown 中 `## 变量声明` 表格第一行 `alert_logs` 的列值发生错位：
    `| alert_logs | json | 工具调用 | acli_exec | 告警原始数据 |  | stdout | {"reason": "获取集群磁盘相关告警", "command": "acli --formatter json alert get -k 磁盘"} |`
  - 列解析映射后：
    - `说明` 变成了 `"acli_exec"`；
    - `依赖` (`depends_on`) 变成了 `["告警原始数据"]`；
    - `来源` (`source`) 填写了 `"工具调用"`，未被解析器识别为 `tool:acli_exec`，回退为 `user_input`。
  - 当 LLM 或执行引擎尝试推进 SOP 时，检测到 `alert_logs` 具有未满足的前置依赖 `告警原始数据`，而该变量未在 schema 中定义，无法自动获取。
  - LLM 在上下文发现用户已在聊天中粘贴告警，遂调用 `sop_request_variable(variable_name="告警原始数据", reason="用户已在对话中提供告警原始数据...")`。
  - `variable_pool/engine.py` 判定此为缺失变量，向前端下发 `variable_input` 交互卡片，造成“人工已输入却仍弹窗要求输入”的反直觉体验。

### 2.2 截图 2 & 3 根因：SSH 隔离会话环境变量缺失与容器非交互式伪终端要求
- **事实链路**：
  - **`acli: command not found`**：
    - Terminal Bridge 通过 SSH 建立独立 session 执行命令（`execCommandIsolated` / `execCommand`），使用的是非登录、非交互式 Shell。
    - 目标宿主机不会加载 `/etc/profile` 或用户环境变量，默认 `$PATH` 仅为 `/usr/bin:/bin`，而 HCI 自研工具位于 `/sf/bin` 和 `/sf/sbin`。
  - **`execing command in container: input is not a terminal`**：
    - `terminal_bridge/main.go` 中的 `wrapContainerCommand` 仅构造：
      `container_exec -n <container> -c '<command>'`
    - HCI 节点的 `container_exec` 底层在非 `-d`（detached/no-tty）模式下默认要求 stdin 为 TTY 终端。独立 SSH 会话无终端输入管道，容器运行时直接 fatal 报错退出。

### 2.3 截图 3 & 4 根因：内部服务鉴权令牌缺失与前端错误静默吞咽
- **事实链路**：
  - 用户在前端点击“确认执行”选项后，前端向 `conversation-service` 发送 POST `/api/chat/interactive-response`。
  - `conversation-service` 的 `AgentClient.react_confirm` 请求 `agent-service` 的 `/v1/agent/react-confirm`。
  - `agent-service` 开启了内部 API 鉴权，要求请求头包含 `Authorization: Bearer <INTERNAL_API_TOKEN>`。
  - `AgentClient` 初始化时未传入 `internal_token`，`react_confirm`、`submit_interactive_response` 等调用未附带鉴权头部，导致请求被拦截返回 **`401 Unauthorized`**。
  - `conversation-service` 向上返回 503 异常，前端 `MessageBubble.vue` 捕获异常后仅打印 `console.warn`，未向用户反馈错误提示，卡片也未移除。
  - `agent-service` 中的 Redis `BRPOP` 等待超时（120 秒），判定为 `TIMEOUT`，触发取消逻辑并回复“操作已取消”。

## 3. 对抗性审查 (Adversarial Review)

1. **攻击场景 1：如果仅在 `AgentClient` 补齐 Token，是否可能因 Token 过期或配置漂移导致再次静默失效？**
   - **审查与加固**：
     - `backend/conversation-service/app/main.py` 在启动 lifespan 中强制校验并注入 `settings.INTERNAL_API_TOKEN`；
     - 前端 `MessageBubble.vue` 增加统一的 `ElMessage.error` 弹窗与控制台错误跟踪，彻底消除“点击无反应”感知盲区；
     - 调整 `submit_interactive_response` 顺序：本地变量写库不受下游 Agent Client 阻断。
2. **攻击场景 2：如果 SOP Markdown 中作者继续输入非标准来源中文（如“工具调用”），是否会再次意外降级为人工输入？**
   - **审查与加固**：
     - 在 `backend/shared/utils/acquisition_strategy.py` 的 `_ALIAS_MAP` 中显式扩展中文别名（`工具调用`、`工具`、`技能调用`、`技能`、`用户输入`、`用户确认`、`环境注入`、`派生`）；
     - 数据库直接清洗 SOP 4 的 `content_md` 与 `variable_schema`，移除悬空依赖 `告警原始数据`。
3. **攻击场景 3：如果命令本身包含单引号或已带有 `-d` 参数，`wrapContainerCommand` 是否会导致语法错误或重复参数？**
   - **审查与加固**：
     - `wrapContainerCommand` 使用 `strings.ReplaceAll(command, "'", "'\\''")` 安全转义单引号；
     - 前置检查 `!strings.Contains(trimmed, " -d")`，避免重复追加。

## 4. 修复实现明细

1. **`backend/conversation-service/app/services/agent_client.py`**：
   - 构造器增加 `internal_token: str | None = None`；
   - 在 `react_confirm`、`submit_interactive_response`、`resume_stream` 中统一注入 `Authorization: Bearer <token>` 请求头。
2. **`backend/conversation-service/app/main.py`**：
   - 实例化 `AgentClient` 时传入 `settings.INTERNAL_API_TOKEN`。
3. **`backend/conversation-service/app/services/conversation_service.py`**：
   - 前置分离 `variable_input` 本地处理逻辑，对依赖下游的 `tool_confirm`/`sop_fallback` 等类型前置检查 `agent_client` 可用性。
4. **`frontend/customer/src/components/MessageBubble.vue`**：
   - 引入 Element Plus 的 `ElMessage`，在提交交互选项、变量及自由文本失败时弹出错误提示。
5. **`terminal_bridge/main.go`**：
   - `wrapContainerCommand` 中：
     - 对容器命令统一追加 `-d` 参数，规避容器环境 `input is not a terminal` 异常；
     - 对宿主机命令自动注入 `/sf/bin:/sf/sbin:/usr/sbin:/usr/local/bin` PATH，彻底解决 `acli: command not found`。
6. **`backend/shared/utils/acquisition_strategy.py`**：
   - 扩展中文策略别名支持，防止 SOP 解析意外降级。
7. **数据库 SOP ID=4 数据订正**：
   - 更新 `sop_document` 表中 ID=4 的 `content_md` 与 `variable_schema`，修正列对齐并清空 `alert_logs` 的悬空依赖。
