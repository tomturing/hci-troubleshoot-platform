# 统一认证系统 — 阶段1.z：admin 前端共享令牌清除与 JWT 统一注入

- 日期：2026-09-24
- 环境：staging
- 类型：安全收口（SRC-2026-5358 管理台强制认证 · L1 删回退 + L3 前端守卫）
- 上游：阶段0（schema + auth-service 骨架）、阶段1（网关验签）、阶段1.x（默认管理员登录打通）
  详见 `docs/solution/events/2026-09-23-统一认证系统-阶段1x-默认管理员登录打通.md`

## 1. 目标与定位

把 admin 管理台的"身份来源"从**前端硬编码/缓存的共享内部令牌**彻底切换为**登录签发的 RS256 JWT**，
并删除前端与 nginx 中"未登录即回退共享令牌"的通路。

这是阶段1.x 的必然收口：阶段1.x 打通了登录链路（网关验签 admin JWT、`_apply_actor` 补 `client_id`、
网关对下游管理端点重签内部令牌），但当时为灰度兼容保留了共享令牌回退。本次把该回退在**前端与 nginx 侧移除**，
使"未登录 = 无法以管理端身份访问"成为前端侧的硬约束；网关后端强制（`AUTHN_ENFORCE_ADMIN`）留待后续独立 PR。

## 2. 与阶段1.x 的差异（DELTA）

| 维度 | 阶段1.x（改前） | 本 PR（改后） |
|---|---|---|
| fetch 拦截器鉴权来源 | JWT 优先，未登录回退共享内部令牌 | 仅注入登录 JWT，无回退 |
| 未登录发起 `/api` | 以共享令牌伪装管理端放行 | 路由守卫先强制跳登录页 |
| nginx `Authorization` | 客户端无凭证时回退注入共享令牌 | 透明透传客户端 JWT（`$http_authorization`） |
| 管理台视图令牌来源 | 多处硬编码 `VITE_INTERNAL_API_TOKEN` / localStorage | 清除；统一由拦截器/axios 注入 JWT |
| 会话过期处理 | 无统一处理 | 401 统一清令牌 + 跳登录（带 `redirect` 回跳） |

## 3. 改动清单

### 3.1 认证核心 `frontend/admin/src/utils/auth.ts`
- 删除共享内部令牌回退常量与其一切引用；构建产物不再携带任何内部服务令牌。
- `authHeaders()`：仅在有登录令牌时返回 `Authorization: Bearer <JWT>`，否则空对象。
- `isAuthenticated()`：解析 JWT 载荷 `exp` 做前端过期预判（容忍 30s 时钟偏移）；无法解析 `exp` 时不阻断，
  交由服务端 401 + 拦截器兜底，避免误判把管理员挡在门外。**前端过期判断仅为体验优化，安全边界始终是服务端 JWKS 验签。**
- `setupAuthFetch()`：全局 fetch 拦截器为所有 `/api` 请求（登录端点 `/api/platform-auth/` 除外）注入 JWT；
  捕获 401 → 清令牌 + 跳登录（防重入，避免并发 401 触发多次整页跳转、避免登录端点自身 401 造成重定向死循环）。
- `logAuthEvent()`：结构化认证事件日志（`redirect_to_login`/`unauthorized`/`logout`），带 `traceId` 与时间戳，纳入前端可观测性。
- `login()` 指向 `/api/platform-auth/admin/login`；`logout()` 清令牌后跳登录页。

### 3.2 同源身份桥接 `frontend/admin/src/main.ts`
- 挂载前安装拦截器，并暴露 `window.__HCI_AUTH__ = getAccessToken`，供同源诊断页取用登录令牌，
  使离线诊断等原依赖独立令牌的路径统一走 JWT。

### 3.3 登录强制 `frontend/admin/src/router/index.ts`
- 路由守卫：未登录访问任意受保护路由 → 重定向 `/login?redirect=<原地址>`；登录后回跳。

### 3.4 axios 通道 `frontend/shared/src/api.ts` + 管理台视图
- `createApiClient` 新增可选 `getToken`：axios 实例不经全局 fetch 拦截器，须显式注入 JWT。
- 6 个 axios 视图接入 `getToken`；其余原生 fetch 视图（如 `frontend/admin/src/views/CaseDetailView.vue`、
  `frontend/admin/src/composables/useCategories.ts` 等）清除硬编码共享令牌，鉴权统一交由拦截器注入。

### 3.5 反代 `frontend/admin/nginx.conf`
- `/api/`：`Authorization` 改为透明透传 `$http_authorization`，删除"无凭证即注入共享令牌"的回退块。
  `X-Tenant-ID`/`X-Actor-ID` 属身份上下文（非认证），其静态注入收敛与 `ADMIN_API_AUTHORIZATION` 的 chart 注入清理一并留待后续 PR。

## 4. 为什么删除回退是安全的（第一性原理）

请求发起前，身份来源收口为三层，任一层都保证"已登录才发请求、发的就是真实 JWT"：
1. 路由守卫强制登录后才渲染受保护页并发起数据请求；
2. 原生 fetch 经全局拦截器注入 JWT；
3. axios 经 `createApiClient.getToken` 注入 JWT。

后端链路已在阶段1.x 验证通过：网关 `IdentityMiddleware` 对有效 admin JWT 验签并补 `request.state.client_id`；
下游管理端点由网关以内部令牌重签访问（不透传客户端 JWT）。因此前端只要携带真实 JWT，即被识别为 admin，
删除共享令牌回退不改变正常流量行为，仅消除"未登录伪造管理端身份"的能力。

## 5. 对抗性审查与边界

- **登录端点豁免**：拦截器跳过 `/api/platform-auth/`，登录请求以 body 携带凭证、不注入历史 JWT；登录失败 401 不触发重定向，杜绝死循环。
- **过期令牌**：`exp` 过期后 `isAuthenticated()` 判假 → 守卫跳登录；即便前端判断遗漏，服务端 401 也会被拦截器兜底清令牌。
- **无悬空引用**：清除 `internalToken` 定义的文件已确认无残留内联引用；保留内联调用的少数视图将令牌源置空并由拦截器覆盖，编译期与运行期均无未定义引用。
- **构建产物泄露归零**：全仓库不再存在共享内部令牌字面量（`docs`/代码检索 0 命中），杜绝"打包即泄密"。

## 6. 灰度顺序（不可颠倒）

1. **本 PR（前端收口）**：删前端/nginx 共享令牌回退，强制登录 + JWT。网关仍保持非强制模式（`AUTHN_ENFORCE_ADMIN=false`），
   即后端此时仍接受共享令牌通路（用于 customer-ui 等尚未收口的面），互不影响。
2. **后续 PR（网关后端强制）**：开启 `AUTHN_ENFORCE_ADMIN`、清理 `ADMIN_API_AUTHORIZATION` chart 注入、
   收敛 `X-Tenant-ID`/`X-Actor-ID` 静态注入、补齐 L4（HttpOnly Cookie CSRF、登录限流）。
