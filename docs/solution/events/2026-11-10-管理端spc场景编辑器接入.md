# 管理端接入 spc 通道：自定义场景编辑器双通道改造

| 日期 | 版本 | 变更内容 | 关联事件文档 |
|------|------|---------|------------|

## 一、被修复的事实

到 2026-11-10 为止，spc 通道在链路上已经打通：桥侧逐台覆写（`log_collect_spc_fanout.go`）、任务四列落库、客户侧还原卡片都已上线，但**管理端无法创建 spc 场景**：

- `frontend/admin/src/views/components/CustomScenarioPanel.vue` 从 #1465 起只做 `-c` 清单，
  文件头注释还写着「在 PR3 接入前，手工录入 + 批量粘贴是唯一不撒谎的交互」；
- 后端 `LogCollectCustomScenarioCreate` 接受 `source`，但 `Update` 不接受，**建错通道后连纠正入口都没有**；
- `GET /internal/log-collect/custom-scenarios/catalog`（11 份 spc 快照、带 `usable_by_config`）
  已随 #1472 上线，却没有任何前端消费方；
- 结果是 spc 场景只能靠 SQL 改 `source` 创建，客户侧那条链路实际不可达。

## 二、第一性原理：通道是结构选择，不是展示偏好

`-c` 与 `spc` 最终都是"节点上的一个文件"，但**不是同一个文件的两种写法**：

| 维度 | `-c` | spc |
|---|---|---|
| 文件内容 | `{"paths":"a,b,c"}` | `[{...}]` 数组 |
| 条目能力 | 只 `cp -r` | `copy` / `command` / `script` |
| 过滤 | 不支持（写了会被 `os.path.exists` 判假静默跳过） | 支持 `filters` / `{date}` / `docker` / `interpreter` |
| 分组 | 无 | `{"note": "..."}` 行 |

由此推出三条硬约束（落到代码里）：

1. **通道切换必须重新校验条目**：`-c` 装不下的条目（非 copy、通配符、带 filters）不能让保存"成功"，
   否则插件静默跳过、任务显示成功但少收内容；
2. **勾选必须保真**：从快照勾来的 `filters` / `date_placeholders` / `docker` / `interpreter`
   要原样提交。这与迁移 057 踩过的坑同类——用 `jsonb_build_object` 重建条目会静默丢字段；
3. **预览必须来自服务端**：两条通道的序列化差异大，前端复刻一份必然漂移，
   管理员看到的预览就会与节点上实际写入的不一致。

## 三、改动

### 后端（case-service）

| 落点 | 改动 |
|---|---|
| `schemas/log_collect_custom_scenario.py` | `LogCollectCustomScenarioUpdate` 增加 `source`（通道可纠正）；`CustomScenarioValidationResponse` 增加 `preview_kind` + `preview_text` |
| `services/log_collect_custom_scenario_service.py` | `update` 改用**新**通道序列化（`changes.get("source") or current.source`）；`validate` 返回真实序列化文本 |
| `routes/log_collect_custom_scenarios.py` | `validate` 捕获通道与条目不匹配的 `ValueError`，返回 `ok=false` + `issues`（此前会 500） |

`source` 语义在本轮被明确为**下发通道**（不再是"录入方式"）：`spc` 走 `serialize_spc`，
`visual`/`json` 走 `serialize_config`。

### 网关（api-gateway）

新增 `GET /api/v1/log-collect-custom-scenarios/catalog`，透传到
`/internal/log-collect/custom-scenarios/catalog`（`require_admin` + 内部令牌重签）。

### 管理台前端

`CustomScenarioPanel.vue`：

- 表单新增「下发通道」单选，默认 `spc`；编辑时回显场景实际通道，切换时若存在 `-c` 装不下的条目
  立即提示（不静默剥离字段）；
- 新增「从插件清单勾选」面板：模块下拉（11 份快照，标注条目数与 `-c` 可用数）+
  分组/路径过滤 + 逐条勾选，勾选后 `filters`/`date_placeholders`/`docker`/`interpreter`/分组备注原样带入；
- `-c` 通道下拒绝对 `usable_by_config=false` 的条目勾选，并说明原因；
- 按 `path` 去重：`other`/`system`/`host_offline` 三份清单条目高度重合，
  跨模块重复勾选会因后端 `_normalize_items` 去重被静默合并，必须当场提示；
- 列表新增「通道」列，编辑抽屉的预览改为展示服务端 `validate.preview_text`，
  删除前端 `previewConfigText`（消除第二份序列化实现）；
- 条目表格在 spc 通道下支持编辑 `action`；编辑条目后 400ms 防抖自动试算，并用请求序号丢弃过期响应。

## 五、已知限制

- 快照是**随镜像发布的静态清单**，不代表节点实时文件；节点漂移需靠后续「从集群刷新」
  （本期未实现，用 `sha256` 对比可发现）；
- 切到 spc 后，目标节点若无 spc 目录会在桥侧探测阶段被剔除并显式报错（不静默走旧链路）；
- 场景体积预检、备份 TTL、桥启动扫历史备份仍为已知未实现项（见 #1474）。
