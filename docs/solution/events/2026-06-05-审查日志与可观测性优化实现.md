# 审查日志与可观测性优化实现计划

本计划旨在管理端（admin-ui）引入 Prompt 级审计日志（`audit_log` 表）查询界面，重命名“系统监控”为“可观测性”，使内嵌 Grafana 在开发环境实现免密自动登录，并对齐用户端（customer-ui）诊断进度条标签与 Agent 实际诊断阶段。

## User Review Required

> [!IMPORTANT]
> **Grafana 免登录风险说明**
> 开启匿名访问（GF_AUTH_ANONYMOUS_ENABLED=true）后，处于同一内部网络或能够直连 Grafana 服务的用户将无需输入密码直接以 `Viewer` 角色访问 Grafana。该设置符合内嵌监控面板免密的最佳实践，且生产环境已经默认启用。本次修改将本地开发环境对齐。

## Proposed Changes

### [Component: Backend]

#### [MODIFY] [audit.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/conversation-service/app/routes/audit.py)
- 导入 `AuditLog` 和 `Conversation` 模型，以及 `uuid` 模块。
- 增加 `GET /api/v1/audit-logs/prompts` 路由。
- 路由接收 `case_id`, `conversation_id`, `trace_id` 过滤参数以及分页参数。
- 使用 `select(func.count(AuditLog.id))` 实现精确的总数分页统计。
- 使用 `select(AuditLog)` 进行查询，在有 `case_id` 过滤条件时，与 `Conversation` 联表（JOIN）查询，并按时间倒序（`started_at.desc()`）排序。

#### [NEW] [audit.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/api-gateway/app/routes/audit.py)
- 新建网关代理路由，接收来自管理端的 `/api/audit-logs`（工具执行审计）和 `/api/audit-logs/prompts`（Prompt 审计）请求。
- 使用 `httpx` 将其透明转发到 `conversation-service` 对应的 `/api/v1/audit-logs` 端点。

#### [MODIFY] [main.py](file:///mnt/d/aihci/hci-troubleshoot-platform/backend/api-gateway/app/main.py)
- 导入并注册全新的 `audit` 路由：`app.include_router(audit.router)`。

### [Component: Frontend - admin-ui]

#### [MODIFY] [index.ts](file:///mnt/d/aihci/hci-troubleshoot-platform/frontend/admin/src/router/index.ts)
- 重命名 `/monitoring` 路由：
  - path 改为 `/observability`
  - name 改为 `'Observability'`
  - meta.title 改为 `'可观测性'`
  - component 动态导入改为 `() => import('@/views/ObservabilityView.vue')`

#### [NEW] [ObservabilityView.vue](file:///mnt/d/aihci/hci-troubleshoot-platform/frontend/admin/src/views/ObservabilityView.vue)
- 替换/升级原有的监控面板视图。
- 使用 `el-tabs` 提供两个并列页签：“监控面板”和“审查日志”。
- “监控面板”承载原 Grafana iframe 嵌入，右侧附带“在新窗口打开 Grafana”按钮。
- “审查日志”包含：
  - 查询过滤器栏：支持按工单号（Case ID）、Trace ID 精准检索，带“查询”与“重置”按钮。
  - 主表格 `el-table`：展示记录时间、工单号、会话 ID、对话轮次、Token 估算、耗时、异常及操作列。
  - 分页组件 `el-pagination`：支持翻页和每页数量切换。
  - 详情抽屉 `el-drawer`：右侧弹窗展示当前审计记录的详细 JSON。由于 `messages` 数组通常极其庞大，用折叠面板 `el-collapse` 或格式化 JSON 查看器让用户能清晰预览，并提供“一键复制”功能，大幅提升可读性和排障效率。
