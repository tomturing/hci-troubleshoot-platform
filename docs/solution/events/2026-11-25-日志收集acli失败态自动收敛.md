## 一、背景

工单 `Q2026112501114` 的 acli 安装后验证失败，根因是节点 `/sf/log/today -> 25/` 在失败窗口为悬空软链，`acli --version` 初始化日志目录时返回 `EEXIST`。节点恢复后，用户点击「重新探测」仍看到失败卡片和顶部常驻红条。

调查确认是两套状态没有回流：

1. `acliFailure` 为人工确认态，`prepare()/probeOnce()` 成功只更新 `probeResult`，不清失败态；
2. 页面 5 秒自动刷新只同步任务/节点进度，不探测；事实复查为 30 秒 × 3，且成功也不清失败态。

此外，「重新探测」只作用于当前 SSH 节点，不会逐台探测集群所有机器。失败卡片来自 `.100`，用户当时在 `.103` 重探，因此不能也不应清除 `.100` 的错误证据。

## 二、改动

| 端 | 位置 | 变更 |
|---|---|---|
| 前端 | `LogCollectPanel.vue` | `acliFailure` 增加 `nodeIp`、toast 句柄、`autoRecheckExhausted` |
| 前端 | `LogCollectPanel.vue` | `acli_sync` 发送时记录目标节点，迟到回包不按当前连接节点误归属 |
| 前端 | `LogCollectPanel.vue` | `probeOnce()` 成功后同节点对账：acli 可用且版本非空 → 清卡片 + 关红条 + 停复查 |
| 前端 | `LogCollectPanel.vue` | 事实复查从固定 30s×3 改为 3s/5s/8s×3，带 ±20% 抖动，恢复即停 |
| 前端 | `LogCollectPanel.vue` | 3 次复查仍失败时，卡片追加「已自动复查 3 次仍未恢复」 |
| 前端 | `logCollectFault.ts` | `showCustomerFault()` 返回 message handler，供精准关闭本次红条 |
| 测试 | `LogCollectPanel.spec.ts` | 覆盖同节点清除、异节点不清除、3 次复查耗尽提示 |

不改后端、不改 acli 安装/验证判定、不把重新探测升级为集群 fan-out。

## 三、行为契约

- 失败卡片只由**同一节点**的探测恢复清除；异节点探测成功不清。
- 手动「重新探测」与自动事实复查共用同一对账逻辑。
- 3 次短复查全部失败后停止轮询，保留卡片并显示已自动复查提示。
- 顶部常驻红条与卡片同生命周期；只关闭本次 acli 失败对应的句柄，不调用 `ElMessage.closeAll()`。
- 切换 SSH 节点不清旧节点错误；切回原节点且探测成功才清。
