## 一、问题从哪来

对 `Run` 的 write → install → smoke 三段做逐行审查，判断标准只有一条：**回执里的每一条证据，是否真的断言了它声称的事实**。据此发现 6 处缺口，其中 2 处会让排查走错方向，1 处会让人误以为校验已通过。

## 二、逐条修法

| 项 | 原行为 | 风险 | 修法 |
|---|---|---|---|
| 安装证据 | 只有失败时记 `install_exit` | 成功回执看不出"装没装"，只能去节点翻文件 | 成功也记 `install_kind` / `install_exit`；`InstallNone` 归一为 `none`，区分"没配"与"配了" |
| 备份清理 | `rm -f` 返回值丢弃，却无条件写 `backup_kept=false` | 删除失败（只读盘/权限）时备份残留，回执却称已清 | 校验退出码；失败记 `backup_cleanup_failed=<路径>`、`backup_kept=partial` 并置 `Degraded` |
| 冒烟错误码 | 冒烟渲染器缺失报 `install_unsupported` | 同一个码在 install 段另指"安装动作无渲染器"，排查误入安装段 | 改用 `verify_failed`（`retryable=false`）。不新增码：`LogCollectErrorFields` 对未登记码返回空 layer/owner/retryable，新增码等于新增一处无层级错误 |
| 降级归因 | 节点缺 sha256sum 时，冒烟失败文案称"原文不可用于逐字节比对" | 真因是节点缺摘要工具，文案把定责引向校验层 | 写 `digest_unavailable=<路径>`；失败文案带出实际 `integrity` 档位（`size_only` / `md5` / 空） |
| 死赋值 | `verifySpec.Data = data` | `VerifyWrite` 只比 size/摘要，从不读 `Data`；回填让人误以为这里做了逐字节比对 | 删除赋值并注明逐字节比对在 `runSmoke`；同时标注 `CopyFile` 后的二次 `VerifyWrite` 是有意兜底，不可当冗余删除 |
| 空切片 | `desired[0]` 无长度守卫 | provider 返回空切片且 err 为 nil 时 panic，位置在采集主路径 | 补 `len(desired)==0` 显式错误 |

另把两条边界固化为注释，避免后续误用：

- `Deps.Activator` 必须每次 `Run` 新建。它只增不删、`Entries()` 返回全量，跨调用复用会让回滚/还原作用到上一轮条目，其中包含删除上一轮备份——而备份是 `task_terminal` 还原的唯一来源。
- `AppliedState` 是"应用意图"而非节点当前状态。策略配了 immediate 还原时，写入成功后原件会被放回，`DesiredHash` 却仍留在账本里；因此 `Compare` 必须以节点事实优先（`plan.go` 中 `factAligned` 先于 `ledgerAligned`），否则会把"已还原"误判成"已同步"。

## 三、为什么没有强收紧 `size_only`

审查中一度提出：`VerifyWrite` 在节点算不出摘要时直接返回失败。**该修法被否**，原因是它会让极简宿主机链路整体不可用：

- `logcollect` 写配置走 `SourceInline + SmokeSHA256`，节点无 `sha256sum` 时依赖 `size_only` + `cmp` 逐字节比对兜底；
- 若在 `VerifyWrite` 阶段就失败，流程轮不到 `cmp`，原本能跑通的场景会变成失败。

因此只做"归因准确化"：保留 `size_only` 可写入、可由冒烟兜底的行为，新增 `digest_unavailable` 证据与更准确文案。这是**证据增强**而非行为收紧。

## 四、验证

- 新增 3 条验收测试：成功路径安装证据、备份清理失败降级、冒烟未登记渲染器归 `verify_failed`；
- `go test ./internal/shared/reconcile/... ./internal/shared/remote/... ./internal/logcollect/...` 全绿；
- `gofmt -l` 无输出，`go vet` 无告警；
- 未改任何导出签名，未改远端原语语义。

## 五、未包含

`AppliedState.RestoredAt` 未加。`OnSuccessRestore` 目前在生产 descriptor 中无使用者，改账本结构收益为零、风险非零；先用注释把边界钉住，等真正启用 immediate 还原时再加字段，并把"已还原"做成 `Compare` 的显式不一致源。
