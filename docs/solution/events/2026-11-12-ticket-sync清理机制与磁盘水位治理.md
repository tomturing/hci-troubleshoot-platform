## 1. 事故的事实链

2026-11-12 16:18~16:54 CST，单节点 staging 全栈不可用约 36 分钟。取证结论：

| 事实 | 数据 | 证据来源 |
|---|---|---|
| 磁盘是共享的 | `/sf/tickets` 与 k3s imagefs/nodefs 同一个 2.1T LV | `df` |
| 事故当天拉取量 | 86 次拉取/解压，16:26 单次 27 GiB | `journalctl --user -u hci-ticket-sync` |
| imagefs 使用率 | 10:01 87% → 16:31 96% | `image_gc_manager.go:391` 日志 |
| 驱逐触发 | `nodefs.available` 跌破 114,853,190,729 B | `eviction_manager.go` |
| 清理实际执行次数 | 当天 **1 次**（00:06:48） | `ticket_sync_maintenance_last_run_timestamp` |
| 保留期删除量 | **0**（进程自 11-10 起 3 次日维护均删 0） | `ticket_sync_expired_removed_total` |
| 容量淘汰释放量 | 268.9 GiB（把总量压到 1022.3 GiB / 上限 1024 GiB） | `容量检查完成` 日志 |

结论：**不是发版、不是节点重启、不是单个应用缺陷**，是"容量治理一天只跑一次" +
"按记账而不是按磁盘剩余做判断"共同造成的结构性缺陷。

## 2. 第一性原理：唯一可信的判据是磁盘剩余空间

原实现有三层判据，逐层失效：

| 判据 | 假设 | 为什么失效 |
|---|---|---|
| 保留期 7 天 | 时间到了自然会删 | `TICKET_MIN_KEEP_DAYS=3` 允许容量淘汰更早动手，淘汰总是先删完，保留期**永远删 0 个** |
| `TICKET_MAX_TOTAL_BYTES`（已用量） | 记账等于磁盘 | 记账只统计顶层 `Q\d{13}` 目录；`.tmp` 在途归档与解压产物**完全不计入**；记账本身还会漂移 |
| `TICKET_MIN_FREE_BYTES=60 GiB` | 有红线就安全 | 检查在**每层解压之后**；服务路径（`fetch()`）根本没有前置检查，只有 CLI 有 |

### 2.1 记账漂移的实测数据

```
DB artifacts: 115 行 / 1467.1 GiB
磁盘实际:      74 个目录 / 889.5 GiB
▶ 41 行幽灵记账 577.6 GiB，0 条墓碑，20 小时未对账
```

这 41 个目录是事故期间为腾空间**人工 rm** 掉的，走了程序外路径，程序完全不知道。
影响是双向的：

- **多删真实数据**：淘汰按虚高的 1467 GiB 算，要一路删到 1024 GiB，多删约 443 GiB；
- **漏算在途占用**：`.tmp` 里 2 并发 ×（归档 20 GiB + 解压上限 400 GiB）不在账上。

因此把"已用量上限"降级为第三重保险，主控改为 `shutil.disk_usage().free`。

## 3. 改造内容

### 3.1 磁盘水位双阈值

| 阈值 | 变量 | 默认 | 语义 |
|---|---|---|---|
| 软阈值（主动淘汰） | `TICKET_EVICT_FREE_BYTES` | 400 GiB | 余量低于它删最旧产物，删到回升 |
| 硬阈值（熔断拒绝） | `TICKET_MIN_FREE_BYTES` | 250 GiB | 余量低于它直接拒绝，一个字节都不写 |
| 差额 | — | 150 GiB | 让"淘汰"先于"熔断"发生 |

反推过程（每一项可复算）：

1. kubelet 驱逐线实测 114,853,190,729 B ≈ **107 GiB**（绝对不能碰的地板）；
2. 单任务峰值写入 = 归档 30 GiB（上限 20，实测最大 27）+ 单层解压增量 ≤ 60 GiB ≈ **90 GiB**；
3. **硬阈值 = 107 + 90 + 53（安全边际）= 250 GiB**；
4. **软阈值 = 250 + 150（一轮淘汰需腾出 1.5 个任务的空间）= 400 GiB**。

启动时强制校验 `EVICT > MIN`，配反了直接 `SystemExit`，不许带着错误的水位跑。

### 3.2 写入前闸门（三处）

| 位置 | 阶段标识 | 说明 |
|---|---|---|
| 任务开始 | `stage=start` | 磁盘不安全时连远端探测（一趟 ssh）都不做 |
| 拉取之前 | `stage=fetch` | rsync 一开跑就写整个归档 |
| 每层解压之前 | `stage=depth=N` | `max_depth=12`，攒到解完再判必然写穿 |

新增错误码 `low-disk`（与 `no-space` 区分）：前者是"提前拦下的预防"，后者是
"已经写满的事实"。前端文案不同，避免用户以为数据被写坏。

### 3.3 清理频率：每天一次 → 每 30 秒一轮

每轮固定五步，前一步是后一步的前提：

1. **幽灵行对账**（`reconcile_missing`）：只做 `is_dir()`，删掉"记账有行、磁盘无目录"的行；
2. **保留期删除**：`completedAt` 超过 3 天；
3. **容量 / 水位淘汰**：`total > max_total` **或** `free < evict_free`，删到两者都满足；
4. **回收站清空**：历史遗留 `.trash` 整体删除；
5. **`.tmp` 陈旧回收**：超过 2 小时未更新。

体积重算（`reconcile_artifacts`，冷缓存下数分钟）单独降频到 10 分钟，
准确性由第 1 步兜住。

### 3.4 保留期判据：同步完成时刻，不是工单号日期

`<工单目录>/.sync-meta.json` 的 `completedAt` 是发布时写死的显式事实。工单号里的
日期不可用：**客户可能把历史工单隔几天再上传**，按工单号日期算会把它判成早已过期。

保留期 7 天 → **3 天**。远端 `/sf/log` 保留期远大于 7 天且有独立备份，本地删掉后
可随时重拉；保留期的目的不是"存数据"，而是"避免重复拉取"，3 天覆盖绝大多数
48 小时内的排障。

同时把 `TICKET_MIN_KEEP_DAYS` 3 → **1**：必须小于保留期，否则容量淘汰抢在保留期
之前删完，保留期仍是死代码（启动时校验）。

### 3.5 取消回收站

`publish()` 不再把旧版本 rename 到 `.trash`，直接删除。理由：原件在日志源服务器上
可随时重拉，"可回退"不构成保留几十 GiB 的理由，而这份占用不在容量记账内。

### 3.6 清理动作落库

新增 `cleanup_events` 表（工单号、字节数、**动作当时的磁盘余量**、依据、类型），
保留 30 天，通过 `GET /cleanup-events` 查询。清理是唯一会无声删除用户数据的路径，
没有流水就无法回答"我的日志去哪了"。

### 3.7 「已清理」阶段

新增 `Phase.CLEANED`。产物被保留期或水位淘汰后，工单不再从列表消失，而是以
「已清理」标签展示，并明确提示"原件仍在日志源服务器上，可重新同步"。

为什么必须单独一个阶段：删除后凭空消失，用户无法区分"从没同步过"和"同步过但被
清掉了"；而后者只要点一次就能恢复，前端不能让它看起来像数据丢失。

## 4. 验收标准

1. `GET /cleanup-events` 返回的 `thresholds` 中 `evictFreeBytes > minFreeBytes`；
2. 服务启动后 `journalctl --user -u hci-ticket-sync | grep 清理轮次完成` 每 30 秒一条；
3. 人为把余量压到软阈值以下，下一轮必须出现 `容量淘汰` 记录，且 `已清理` 标签出现在 `/artifacts`；
4. 人为把余量压到硬阈值以下，`POST /jobs` 必须立刻返回 `low-disk` 且**不产生任何写入**；
5. `ticket_sync_expired_removed_total` 必须随保留期删除增长（不再恒为 0）；
6. `.trash` 目录在升级后一轮内被清空且不再重新产生。

## 5. 失效边界（对抗性审查）

| 场景 | 行为 | 说明 |
|---|---|---|
| 一天涌入 > 350 GiB（软硬阈值差额） | 淘汰跑不过写入，可能连续熔断 | 熔断是正确的：宁可任务失败，也不能让 kubelet 驱逐整栈 |
| 非本服务占用暴涨（镜像、日志、数据库） | 本服务无可淘汰产物，`容量淘汰后余量仍低于软阈值` 报错 | 只能靠外部介入；指标已给出 `free` 与阈值 |
| 产物均未满 `MIN_KEEP_DAYS` | 只告警不删 | 有意为之：不误删刚同步进来的数据 |
| 远端保留期若短于本地保留期 | 本地删后无法重拉 | 当前远端远大于 7 天且有备份，已知安全 |
| 人工 `rm` 目录 | 下一轮对账清掉幽灵行 | 20 小时内漂移 577 GiB 的情形不会再发生 |
