### 1.2 staging 认证现状实测（本机直连 traefik `4888` + `Host: acli.sangfor.com.cn`）

| 用例 | HTTP | 判读 |
|------|------|------|
| (a) 匿名无凭证打 admin 端点 | **403** | PR-C 已封"匿名经管理入口伪装 admin" ✅ |
| (b) 带 `INTERNAL_API_TOKEN` 经 4888 | **200** | ⚠️ **共享令牌后门仍开**（`AUTHN_ENFORCE_ADMIN=false`） |
| (c) 真实登录 JWT | 200 | 登录链路可用 ✅ |
| (d) 伪造 JWT | 403 | JWKS 验签生效 ✅ |

**对抗性关键修正**：旧文档称"剥离 nginx fallback 后共享令牌注入对下游完全冗余、剥离即断链"。
实测 (b) 证伪——PR-C 删的是 nginx 主动**注入**，但 nginx 现**无条件透传**客户端 `Authorization`；
任何持有 `INTERNAL_API_TOKEN` 者经 4888 仍恒被网关判为 admin（`identity.py:60-66`，受
`AUTHN_ENFORCE_ADMIN` 门控，当前 false）。**唯一能真正关闭此后门的开关是 `AUTHN_ENFORCE_ADMIN=true`，即 PR-D。**

## 二、PR-C 人工回归清单（浏览器，开启 PR-D 的硬前置）

> 只有本清单全绿，才允许推进 PR-D 强认证（否则会把管理员锁在门外）。

### 2.0 前置
- **内网**访问（`admin-guard` ipAllowList 默认放行 RFC1918；公网需出口 IP 进 sourceRange 或走 VPN）。
- 打开 `https://acli.sangfor.com.cn:4888/login`，**强制硬刷**（Ctrl/Cmd+Shift+R）避开旧 admin-ui JS 缓存
  （旧版仍调已废弃的 `/api/auth`，会 400）。

### 2.1 登录/登出闭环
- [ ] 默认管理员登录：账号框填 **`admin`**（后端字段 `identifier`，非"用户名/邮箱"），密码见
      `database/seeds/05_authn_default_admin.sql` → 成功进仪表盘。
- [ ] 错密码 → 401 且提示"用户名或密码错误"，**不**跳登录、无重定向死循环。
- [ ] 未登录直接访问受保护 URL（如 `/admin/cases`）→ 自动跳 `/login?redirect=%2Fcases`。
- [ ] 登录成功后按 `redirect` 回跳原目标页。
- [ ] 点"退出"→ 跳 `/login`；浏览器后退不能重回受保护页（令牌已清）。

### 2.2 各管理页读写（逐一确认无 401/403）
- [ ] 仪表盘 / 可观测性
- [ ] 工单列表、工单详情（含状态流转写操作）
- [ ] 用户管理（客户列表）
- [ ] 分类基线、Catalog 基线
- [ ] KBD 管理（审阅、发布/无法发布状态、责任人）
- [ ] SOP 管理、工具管理、技能管理、Prompt 管理
- [ ] 离线诊断（**关键**：同源诊断走 `window.__HCI_AUTH__` 注入 JWT，回归高发区）
- [ ] 仿真测试、Bundle 工厂、模板实例库
- [ ] Console 审计

### 2.3 会话过期
- [ ] （可选）把 localStorage `hci_admin_access_token` 改成过期值 → 任一请求 401 → 自动清令牌跳登录带 redirect。

### 2.4 本机测不到的项（须由用户侧带外验证）
- [ ] 公网访问 4888 → 期望 403（admin-guard 拦 RFC1918 之外）；本机在 RFC1918 内，**只能验"能进"，不能验"公网封禁"**。

## 三、PR-D 强认证方案（网关后端强制；**第 1 项开关已提 PR，其余待办**）

> 目标：把 `AUTHN_ENFORCE_ADMIN` 落地为可运维开关并置 true，关闭 (b) 共享令牌后门；
> 同步清理 PR-C 遗留的冗余注入，补齐 L4 加固。**分阶段、每步可回滚。**
> 当前进度：§3.1-A 开关（默认 `false`、合并后行为不变、可秒级回滚）已随本 PR 落地；
> §3.1-A′ **关后门前的回退审计埋点**（`identity.py` 旁路观测，flag 仍 `false`、零行为变更）已落地，
> 使 §3.2 第 3 步从"无数据可观测"变为"可量化判据"；B/C/D/E 待后续。

### 3.1 变更点（按文件）

**A. 网关强制开关（P0-2）**
- `deploy/helm/hci-platform/values.yaml`：新增 `apiGateway.authnEnforceAdmin: false`（默认向后兼容）。
- `deploy/helm/hci-platform/values.schema.json`：补该字段。
- `deploy/helm/hci-platform/templates/api-gateway/deployment.yaml`：env 增
  `AUTHN_ENFORCE_ADMIN: {{ .Values.apiGateway.authnEnforceAdmin | quote }}`。
- `deploy/config/config-contract.yaml`：登记 `AUTHN_ENFORCE_ADMIN`（否则 config-contract-check 失败）。
- 环境仓 `environments/staging/values.yaml`：先 `false` 部署验行为不变，再置 `true`（两步）。

**A′. 共享令牌→admin 回退审计埋点（关后门实测判据使能项；flag 仍 `false`、零行为变更）**
> §3.2 第 3 步"观察共享令牌后门命中计数"此前**无数据可观测**：`identity.py` 回退分支无日志/指标，
> 且 staging 近 24h 仅 `/health` 探针、无真实流量。本埋点补齐该判据，是关后门前的安全网，
> 同时兑现"所有模块可观测性 + 唯一调用链"的团队规范（admin 授权决策此前是审计盲区）。
- `backend/shared/observability/metrics.py`：新增 `hci_authz_shared_token_admin_total{method}`
  （仅低基数 `method` label；完整 path/IP/UA 只进日志，**规避任意请求路径造成 Prometheus 高基数**）。
- `backend/api-gateway/app/middleware/identity.py`：命中"共享令牌→admin 回退"时旁路
  `logger.warning(event="authz_shared_token_admin_fallback", trace_id, method, path, client_ip, user_agent)`
  + counter 自增。**安全红线**：绝不记录令牌本身（logger 对 `authorization`/`internal_api_token`/`Bearer`
  双重脱敏，中间件亦不传入 `auth` 头）；携带唯一调用链 `trace_id`（`X-Trace-Id` 头或 uuid）。
- 判据用法：flag=`false` 部署后，在真实流量下（dev，或在 staging **主动**跑一遍 admin 各页 + agent
  `vm_console`/`acli` executor/scheduler 等服务间链路）观测
  `increase(hci_authz_shared_token_admin_total[观察窗]) == 0` → 无合法调用方依赖后门 → 方可置 `true`。
- 回滚：纯旁路代码，flag 未翻则行为零变化；彻底移除 revert 本 commit 即可。

**B. 清 `ADMIN_API_AUTHORIZATION` 注入（PR-C §8 遗留）— ✅ 本 PR 已落地**
- `admin-ui/deployment.yaml`：删除 `ADMIN_API_AUTHORIZATION` env（nginx 已改透传 `$http_authorization`，此 env 系死变量）。**保留同块 `ADMIN_API_TENANT_ID`/`ACTOR_ID`（属 C）**。
- `secret.yaml`：全仓 grep 确认 `INTERNAL_API_AUTHORIZATION` 唯一消费者即上述 env（其余仅契约/helm test/文档）→ 已移除该键及其 `if internal` 块；canonical `INTERNAL_API_TOKEN` 保留不动。
- `config-contract.yaml`：`helm_only_runtime` 同步删 `ADMIN_API_AUTHORIZATION`、`INTERNAL_API_AUTHORIZATION` 两条孤儿登记（Makefile `config-contract-check` 不带 `--strict-orphan`，孤儿仅告警，仍按卫生清除）。
- helm test `diagnosis_identity_proxy_test.yaml`：两处失效断言反转为**锁定"不存在"**（`isNull stringData.INTERNAL_API_AUTHORIZATION` + `notContains ADMIN_API_AUTHORIZATION`），防后门回归；`checksum/diagnosis-internal-auth`（对 secret.yaml 全文 sha256）随之变值但仍非空，`isNotNull` 断言不受影响。

**C. 收敛 `X-Tenant-ID`/`X-Actor-ID` 静态注入（PR-C §8 遗留）**
- `admin-ui/nginx.conf:66-67`：由固定 env 改为透传真实头（`$http_x_tenant_id`/`$http_x_actor_id`）或删除；
  下游租户/操作者由网关按已验签 JWT 重签（`identity.py` `AUTH_DEFAULT_TENANT_ID` / `client_id=sub` 已具备）。
- `admin-ui/deployment.yaml:65-68`：随之移除 `ADMIN_API_TENANT_ID`/`ADMIN_API_ACTOR_ID`。
- **补契约护栏**：扩展 `scripts/verify/verify_identity_resign.py`，把 **admin** nginx.conf 的
  `proxy_set_header X-Tenant-ID/X-Actor-ID`（固定值注入）纳入静态禁止检查（现仅查 customer，见其第 97-105 行）。

**D. 网关默认拒绝加固（P1-6/7/8）**
- 审计所有 admin 面路由均挂 `require_admin`（防"漏点 fail-open"）；白名单显式枚举
  `login/health/metrics/ws/direct 数据面`。实测匿名 403 说明未 fail-open 到 cookie→admin，良好，仍需路由级复核。
- 验签失败明确 401，不回退共享令牌。

**E. L4 加固**
- **登录锁定（P2-10，实测坐实缺陷）**：`auth-service/app/services/repository.py` 现仅
  `failed_attempts+1`，**从不写 `locked_until`** → 锁定形同虚设。补"达阈值 → `SET locked_until=now+lockout`"，
  成功登录清零（已有）。
- `IDENTITY_COOKIE_KEY` 与 `INTERNAL_API_TOKEN` 解耦（P1-9，可视范围并入 PR-D 或拆 PR-D2）。
- HttpOnly Cookie CSRF、IP 级登录限流（可拆 PR-D2）。

## 四、对抗性自审（方案在何条件下失败）
1. **置 true 后有内部/监控走共享令牌** → 大面积 401。缓解：§3.2 第 3 步先观察日志再切；回滚仅改 flag。
2. **B 删 `INTERNAL_API_AUTHORIZATION` 但有隐藏引用** → admin-ui 启动异常。缓解：删除前全仓 grep 确认。
3. **C 改透传后下游 diagnosis 依赖固定 tenant/actor** → 422。缓解：网关重签已覆盖，且 `verify` 契约护栏补齐回归。
4. **白名单漏列数据面（`/api/direct/*`、`/ws`）** → 误伤上传/终端。缓解：显式枚举 + §2.2 全量页面回归。
5. **私钥泄露**（既有）→ JWT 可伪造。缓解：Secret 注入 + `kid` 轮换，本 PR 不扩大暴露面。
