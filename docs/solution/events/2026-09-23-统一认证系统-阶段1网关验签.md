# 统一认证系统 — 阶段 1：网关 JWT 验签 + admin 灰度（PR #1078）

> 本文是 `docs/solution/events/2026-09-23-统一认证系统设计方案.md` 与 `...-auth-service实现说明.md` 的阶段 1 实现层补充。

## 1. 背景与目标

阶段 0 已落地 schema + auth-service（RS256 / JWKS 签发 admin / customer JWT）。
阶段 1 让**网关成为唯一 JWT 验签边界**：admin 通过 auth-service 登录拿 JWT，经网关验签后获得 admin 身份，逐步取代 `INTERNAL_API_TOKEN` 共享令牌（B3 安全闭环第一步：admin 不再"网络可达 = 管理员"）。

## 2. 方案 WHAT

- 新增 `api-gateway/app/security/jwt_verify.py`：`JwtVerifier`（RS256 + JWKS 缓存验签，验证 auth-service 签发的 JWT：iss / aud / realm / roles / exp）。
- `api-gateway/app/middleware/identity.py` 改造：优先用 `Authorization: Bearer <JWT>` 验签；按 realm 设置 `request.state.is_admin` / `request.state.auth`（GatewayActor）。
- `api-gateway/app/main.py`：lifespan 初始化 `JwtVerifier`（缓存 auth-service JWKS 公钥；auth-service 短暂不可用不影响已登录用户）。
- `api-gateway/app/routes/diagnosis.py`：管理面 admin 分支优先用 JWT 可信身份（`X-Actor-ID = user_id`），闭环 B3「操作者可追溯」。
- `AUTHN_ENFORCE_ADMIN` feature flag（默认 False）：开启后共享令牌不再赋予 admin（必须 JWT 登录）；关闭时维持现状兼容，可灰度回滚。

## 3. 对抗性审查关键发现（为何不直接复用 OidcJwtIdentityVerifier）

`diagnosis-service` 既有 `OidcJwtIdentityVerifier` 的 `ActorContext` 契约**强制 `tenant_id` / `customer_id` claim**，而 auth-service 签发 JWT 的 claims 为 `(iss / sub / realm / roles / aud / exp / tv)`，**无 `tenant_id`** → 直接复用会因 `_validate_claims` 缺失 claim 返回 401 而失败。

**决策**：网关**独立验签** JWT，验签后**复用 B1 已建立的下游信任头模型**（`X-Actor-Roles` / `X-Actor-Customer-ID` / `X-Tenant-ID`）向下游传播身份；下游 `diagnosis-service` 仍用既有 `InternalTokenIdentityVerifier` 信任网关注入的头，**零回归**。这也是职责边界正确划分——网关做入口统一鉴权，diagnosis 的 OIDC 类仍服务于「直接持 JWT 调用 diagnosis 的客户端」场景。

## 4. 影响范围

- 仅改 `api-gateway`（config / pyproject / identity / main / diagnosis / tests）；auth-service 与 schema 不变。
- 现有 Cookie 身份路径、共享令牌 admin 路径（flag 关闭时）**完全兼容**，无破坏性。
- `case-service` 路径：其 admin 端点经网关透传 `INTERNAL_API_TOKEN`（不变），阶段 1 不改 case-service（共享令牌去化留阶段 1.x）。

## 5. 配置项（环境变量 / helm）

| 变量 | 默认 | 说明 |
|---|---|---|
| `AUTH_JWKS_URL` | `http://auth-service:8007/.well-known/jwks.json` | JWKS 公钥端点 |
| `AUTH_JWT_ISSUER` | `hci-auth-service` | 必须与 auth-service `JWT_ISSUER` 一致 |
| `AUTH_JWT_AUD_ADMIN` | `hci-admin` | 必须与 auth-service admin `aud` 一致 |
| `AUTHN_ENFORCE_ADMIN` | `false` | 开启 = admin 必须 JWT 登录 |
| `AUTH_DEFAULT_TENANT_ID` | `hci-platform` | JWT admin 未自报租户时网关重签用 |
| `AUTH_JWT_CLOCK_SKEW_SECONDS` | `60` | 验签时钟容差 |

## 6. 验收标准

- `uv run pytest app/tests`：**8 项全过**（验签成功 / aud 不匹配 / iss 不匹配 / 过期 / 缺角色 / 签名篡改 / 未知 kid / 缺 kid）。
- `ruff check` / `ruff format --check` 通过。
- 端到端（需 auth-service 部署 + 前端登录 UI，留阶段 1.x）：admin 密码登录 → 拿 JWT → 网关验签 → 访问管理面正常；开启 `AUTHN_ENFORCE_ADMIN` 后仅 JWT 可访问 admin。

## 7. 后续

- **阶段 1.x**：前端 admin-ui 登录页（拿 JWT 注入请求头）、`case-service` 改用 JWT 头（去共享令牌）。
- **阶段 2**：customer 账号密码登录（含轻注册）+ 网关 customer JWT 验签（本期 `_apply_actor` 已预留 customer 分支）。
- **`token_version`(tv) 即时失效**：本期验签已读取 `tv`，查库 / 缓存比对留后续（需接 Redis / DB 短 TTL 缓存）。
