# 2026-11-23 SSH 会话整体保活（心跳终身化 + 任务钉住 + 会话自愈）

## 背景

Q2026112300730 的日志收集跑了几十分钟，中途页面红字「SSH 会话未连接」。
排查结论与包本身无关，是**会话生命周期没有覆盖业务时长**：

- 节点交互 shell 带 `TMOUT=600`，采集阶段**完全没有**心跳注入；
  交付（P2 拉取）期间的保活也只覆盖那一小段。
- 会话回收只看 `idle_ttl`（默认 5 分钟）与 `refs`/`MarkBusy` 窗口，
  长任务期间一旦无人持有、又不在活跃窗口内，就会被 reaper 收走。
- 会话真的掉了以后，除了让用户重新输密码，没有任何自愈路径。

一句话：**保活是按"业务段"做的，而业务是"按小时"跑的**。

## 三层机制

### 1. 心跳终身化（`internal/sshx/session.go`）

- `Start()` 成功即启动 shell 心跳（`startShellHeartbeat`），随 `Close()`/`Done` 退出；
  `sync.Once` 保证 `RespawnShell` 反复调用也不会叠加协程。
- 间隔 `shellHeartbeatInterval = 120s`，向 stdin 注入 `NUL`——
  在 bash 里等价 `set-mark`（无副作用），对 `TMOUT` 计时有效。
- 用户输入 30 秒内跳过本轮（`shouldSkipHeartbeat` + `LastInputAt`）：
  NUL 落进 `vi`/`less`/`top` 这类前台程序会干扰界面。
  跳过一轮后下一次 tick 在 120s 后，距上次输入最多 150s，仍远小于 600s。
- 写入失败（stdin 已关闭）只报一次 `ssh.shell_heartbeat_failed`，
  重建交给读取侧的 EOF 处理，不在心跳里并发 respawn。
- `StartShellHeartbeat(caseID)` 保留为幂等触发器，返回的 `stop` 是空操作：
  **心跳属于会话，不属于某个业务域**，否则交付一结束就把采集期间的保活带走。

### 2. 任务钉住（`internal/sshx/session/hub.go`）

- `Pin(key, ttl)` / `Unpin(key)` / `PinExpiry(key)`：租约式时间戳，
  `ReapCandidates` 遇到未过期的 pin 会把 `idleAt` 刷新到当前并跳过。
- **不用 `refs` 的原因**：`refs` 是 0/1 状态位、没有对称递减点，
  业务侧一旦累加就永远归不了零，会话永久泄漏；pin 到期自动失效，最坏多留一会儿。
- 续期只延长不缩短（多次调用取更晚的到期时刻），避免短任务压回长任务的保护窗口。
- 调用点：日志收集每次动作 `Pin` 一次、交付取会话时 `Pin` 一次；
  `ForgetLease`/销毁会一并清理。
- 时长 `HCI_BRIDGE_SESSION_PIN_TTL_SECONDS`，默认 **7200（2 小时）**——
  对应「任务结束 + 2 小时」的保留口径，覆盖「关页面去查资料/开会，回来再看结果」。

### 3. 会话自愈（`internal/app/bridge.go` + `internal/logcollect`）

- 新增 `Bridge.ReconnectSession(caseID, nodeIP, connID)`：
  带互斥 + 双检（等锁期间别人已重连成功就复用），用已保存的 `lastAuth` 后台重建，
  事件 `ssh.session_reconnected`（`role`/`source` 区分调用方）。
- `Lifecycle` 端口新增该方法，日志收集入口注入为 `ReconnectFunc`：
  会话缺失时先自愈一次，成功则继续本次动作并落 `log_collect.session_auto_reconnect`；
  失败落 `log_collect.session_auto_reconnect_failed`，仍按原样报错。
- 前端（`LogCollectPanel.vue` / `stores/chat.ts`）：
  - `LC-ENV-006` / `session_missing` 不再直接判定为永久失败，
    而是先用内存凭据 `reconnectSSHSilent()` 重建会话，成功当场重试；
  - 整轮探测**只重建一次**，避免掩盖真正的认证失败（密码错、账号被锁）；
  - 凭据只存在内存（`sshLastCredential`，不写 localStorage/sessionStorage），
    用户主动断开即清空。

## 边界（明确不覆盖）

- **bridge 进程重启 + 浏览器刷新同时发生**：内存凭据丢失，
  只能提示用户手工重新连接。这两个动作都是用户可见/可控的，不做持久化换安全。
- 心跳只保 shell 层；节点 sshd 重启、网络闪断仍会断链——
  这类由第 3 层自愈兜底（或等待下一次业务动作触发）。
- `refs>0` 的会话本来就不回收，不受 pin 影响；pin 只解决「无人持有但业务仍在跑」。

## 可观测事件

| 事件 | 含义 |
| --- | --- |
| `ssh.shell_heartbeat` | 会话级保活已启动（含间隔与静默窗口） |
| `ssh.shell_heartbeat_failed` | 心跳写入失败，shell 可能已退出（每会话一次） |
| `session.pinned` | 会话首次按任务钉住（含到期时刻） |
| `ssh.session_reconnected` | 会话掉线后已用已存认证自动重建 |
| `log_collect.session_auto_reconnect` | 日志收集动作触发的自愈成功 |
| `log_collect.session_auto_reconnect_failed` | 自愈失败，需人工重连 |
