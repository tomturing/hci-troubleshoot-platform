# Implementation Plan - Fix Command Timeouts and Diagnostic Stage Restore

This plan addresses two issues observed during testing of the HCI troubleshooting platform:
1. Command execution times out (`timeout` status) even when commands succeed.
2. The UI is stuck at the "意图识别" (Intention Recognition, S0) stage even after the category is confirmed in the database.

## User Review Required

> [!IMPORTANT]
> The `terminal_bridge` binary needs to be rebuilt after modifying `terminal_bridge/main.go`. In local development, the user should rebuild the bridge or the dev environment will auto-rebuild.

## Proposed Changes

### Component 1: SSH Terminal Bridge

#### [MODIFY] [main.go](file:///mnt/d/aihci/hci-troubleshoot-platform/terminal_bridge/main.go)
Strip hyphens from `execID` in `checkMarkers` and `on_output_start` to match the marker format generated by `terminal.ts`.

### Component 2: Frontend Customer App Store

#### [MODIFY] [chat.ts](file:///mnt/d/aihci/hci-troubleshoot-platform/frontend/customer/src/stores/chat.ts)
In `loadConversationHistory`, restore `diagnosticStage.value` from the loaded conversation's `diagnostic_stage` field.

## Verification Plan

### Manual Verification
1. Rebuild and run terminal bridge.
2. Test acli command execution and verify it returns results successfully without timeout.
3. Refresh the page or switch case, and verify the diagnostic stage is correctly restored from the database (e.g., displaying "故障定位" S1 instead of reverting to "意图识别" S0).
