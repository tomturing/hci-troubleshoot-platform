# 日志收集详情可读性改造方案

## 背景与需求

见 `docs/requirement/events/2026-11-16-日志收集详情可读性改造.md`。核心矛盾是「展示层读到的证据」与「数据库真实存在的证据」不一致，且固定契约说明挤占了工单相关信息的展示空间。

## 方案概述 (WHAT)

- 前端：详情结果安全合并回抽屉数据；把静态链路设计说明改为 S1-S8 标题旁的弹框；阶段状态着色；证据空态按归因分流。
- 后端：管理端详情/列表 SQL 的 detail 白名单补回 `probe` 等派生所需字段，使 `derive()` 不必在缺字段时降级为 unknown。

## 详细设计

### 数据面

`backend/case-service/app/routes/log_collect_admin_tasks.py` 的 `_EVIDENCE_DETAIL` 增加 `probe`、`create_ack`、`evidence_enabled`、`capabilities` 四个键。它们是 `_build_stages()` 判定 S1/S2/S3/S7 的客观信号；不增加 `spc_hosts` 等大字段，列表 IO 增量可控。`_task_row()` 与列表共用同一白名单，避免「列表看到 unknown、详情看到 success」的二次分叉。

### 前端合并与竞态

`openDetail()` 调用 `getAdminTask(task.task_id)` 后，仅在抽屉仍打开且当前任务 ID 未变时，把返回对象合并进 `detailTask`。这防止快速切单时旧请求覆盖新任务。合并后结构化原文读取完整 `detail`，键为空时显示解释文案而不是裸 JSON。

### 展示层

- `LogCollectAttribution.vue` 的 `variant="panel"` 只保留 S1-S8 阶段表；标题右侧感叹号按钮打开 `el-dialog`，弹框内用「组件标签 / 职责 / 问题描述 / 建议动作」卡片列表展示固定契约说明。
- 阶段状态使用 `el-tag`：成功 `success`、失败 `danger`、未知 `info`、进行中 `primary`、等待中/未启用 `warning`/`info`；文字标签保留，颜色只是辅助。未知状态提供 tooltip 说明「无客观证据不等于失败」。
- 证据空态优先级：`bridge_outdated` → `LC-BRIDGE-005`/S7 失败（使用契约中已有但此前未启用的 `report_failed` 文案并附调用链）→ 任务失败且无传输样本（未进入该环节）→ 通用「尚无上报记录」。

## 决策依据 (WHY)

| 方案 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| 扩展 SQL 白名单（选中） | 一处修复列表与详情派生；保持单一事实源 | 列表单行略增 | ★★★★★ |
| 仅前端按 `detail.probe` 二次推断 | 不动后端 | 前后端各算一套，必然漂移 | ★☆☆☆☆ |
| 详情接口单独再查全量 detail 派生 display | 不动列表口径 | 列表仍显示假阴性，抽屉与列表不一致 | ★★☆☆☆ |
| 静态说明改弹框（选中） | 不占常驻空间，窄列可读性可控 | 需更新验收脚本 | ★★★★☆ |
| 静态说明横向滚动表格 | 改动最小 | 用户已明确否决，长文本仍难读 | ★☆☆☆☆ |

## 影响范围

- `backend/case-service/app/routes/log_collect_admin_tasks.py`：派生输入字段完整性。
- `frontend/admin/src/views/components/LogUploadPanel.vue`、`LogCollectAttribution.vue`：详情交互与展示。
- `frontend/admin/verify/*`：真浏览器验收页与截图脚本随布局调整。
- 文档：`docs/solution/admin-ui/管理台设计.md`、`docs/task/admin-ui/管理台任务.md`、`docs/solution/case/工单设计.md`、`docs/task/case/工单任务.md`。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 存量任务 S1/S2 由未知变成功引发疑问 | 中 | 事件文档说明是白名单假阴性修正；不改 conclusion/bucket |
| 切单竞态导致旧详情覆盖新任务 | 中 | 应用前校验 task_id 与抽屉可见性 |
| 弹框在 46% 抽屉内被遮挡 | 低 | `el-dialog` 默认 teleport 到 body，宽度按视口独立设置 |
| 空态误判为上报失败 | 中 | 仅在 S7 明确失败或归因码为 `LC-BRIDGE-005` 时使用失败文案 |

## 测试策略

- 前端单测覆盖：详情合并、切单竞态、状态颜色类名、弹框文案、四种空态分流。
- 后端用真实 `derive()` fixture 验证含探针任务 S1/S2 为成功且结论不变。
- 真浏览器：验收页点击感叹号弹框并截图；管理端页面打开截图工单 drawer 验证。

## 验收标准

- 需求文档全部验收项满足；`pnpm test`/`vue-tsc`/`vite build`、后端相关单测、docs 五门禁、真浏览器断言全通过。
