# CI 最小激活与快速门禁方案

## 1. 第一性原理

一个 CI job 只有在满足下面任一条件时才有理由在当前 PR 启动：

```
变更可能破坏该 job 保护的契约
或
该 job 是合并规则要求的独立证据
```

“同一 workflow 被触发”不是充分理由。执行时间的关键路径则是：

```
runner 调度 + checkout + 依赖安装 + 测试/构建 + 必要的跨 job 等待
```

因此优化优先级为：先减少 job 数，再去除无意义的 needs，最后利用缓存和超时控制尾部风险。

## 2. 本轮架构

### 2.1 CI workflow

`ci.yml` 的 `changes` job 同时承担两项职责：

- 使用 `dorny/paths-filter` 计算 backend、frontend、platform Helm、docs 变更输出；
- 在 PR 上执行 `docs-governance`。

这样保留原有 required context `docs-governance`，但只 checkout 一次。Schema 契约校验并入 `Lint` job，与 Ruff 共用一次 `uv sync`。

后端测试 job 只依赖 `changes`，不再等待 `lint`、`helm-validate`、`probe-alignment`；这些 job 互不共享运行时状态，等待只会拉长关键路径。main ruleset 仍分别要求 Lint、unit、integration、security 全部成功。

平台 Helm 过滤器收窄为 `deploy/helm/hci-platform/**`。hci-sim Helm 由 `hci-sim-runtime` 的 Manifest/Helm gate 保护，避免两个 workflow 对同一 hci-sim chart 重复启动。

### 2.2 hci-sim-runtime workflow

新增一个轻量 `hci-sim 变更范围` job，输出三个独立范围：

| 输出 | 触发路径 | 消费 job |
|---|---|---|
| `runtime` | `hci_sim/**`、本 workflow | hci-sim Go quality gate |
| `bridge` | `terminal_bridge/**`、本 workflow | terminal bridge simulation-auth gate |
| `manifest` | `hci_sim/**`、`deploy/helm/hci-sim/**`、本 workflow | published bundle and Helm gate |

任一模块变化只启动它能影响的 gate；本 workflow 增加同分支并发取消和 5/10 分钟超时。

### 2.3 terminal_bridge 构建 workflow

Windows exe 是 main 合并后的发布产物，不是 PR 源码质量门禁。删除 `pull_request` 触发，只保留 main push、手动触发。PR 的 Go 格式、单测、race、vet 由 hci-sim-runtime gate 负责；机器人产物 PR 继续使用 `[skip docs] [skip doc-sync]`，避免二进制回写触发文档门禁。

## 3. 为什么不选其他方案

### 方案 A：所有 job 合并成一个大 job

不选。虽然可减少 checkout，但会把独立失败信号和并行能力合并掉，单个前端失败也会隐藏后端测试状态，critical path 反而可能变长。

### 方案 B：完全删除 hci-sim-runtime

不选。hci-sim 的 Go race/vet/build、Manifest digest 与 Helm 渲染是独立于 Python/前端的运行时契约，删除会让目录合入缺乏针对性门禁。

### 方案 C：仅依赖本地 preflight

不选。本地无法证明干净 Ubuntu runner、真实 PR SHA、全新依赖安装和 GitHub 权限边界；本地命令应作为 preflight，不能替代合并门禁。

## 4. 保留的防线

- `go test -race`、`go vet`、构建和 Manifest digest 未删除；
- Helm lint/template、探针路径对齐和 Helm unittest 未删除；
- Atlas/PostgreSQL 数据库 workflow 仍由数据库路径精确触发；
- required status 名称保持不变，跳过仅限未受影响的非必需 job；
- concurrency `cancel-in-progress` 防止同一分支旧 SHA 占用 runner。

## 5. 后续可选阶段

后续可在独立 PR 中将 main push 的镜像 matrix 改为“变更服务集合”动态矩阵，并按 Dockerfile/shared/lock 文件建立影响图；这会减少发布分钟数，但涉及镜像依赖图和回滚语义，本轮不贸然实施。
