# 2026-11-24 日志采集长尾观察窗口误判修复

## 现象

工单 `Q2026112400468` 在 12:44 截图显示：

- 错误码 `LC-PLUGIN-010`；
- 结果态“失败，已结束”；
- 黄色提示“平台已判失败/取消，但节点任务仍在运行”；
- SSH 终端反复出现 `timed out waiting for input: auto-logout`。

但同一时点节点侧事实是：8/8 台收集完成、进度 85%、`upload_state=发送中`、`exit_code=0`、包大小 `10,592,819,584` 字节、`node_state=running`。

## 根因（第一性原理）

`bridge_execution_logs` 显示 `log_collect.progress` 从 11:30:22 到 12:42:10 正好 720 次；12:42:15 case-service 记录 `task.error_code_derived ... code=LC-PLUGIN-010 stage=collect` 并收到 PATCH。

前端 `pollUntilCollected`：

- 循环上限 `attempt < 720`；
- 每轮 `sendAndWait(..., 60000)` 加 `sleep(5000)`，实际约 72 分钟；
- 循环耗尽返回 `null`；
- `resumeTaskFlow` 抛出 `Error('采集未完成')`；
- 外层 catch 写 `status=failed / error_message=采集未完成`；
- 后端按 `error_message` 规则派生 `LC-PLUGIN-010`。

因此这不是节点插件失败，也不是 SSH `TIMEOUT-600`；是**前端观察预算被当成业务失败**。SSH 自动登出后 progress 仍连续成功，旧 aCLI 也已在 11:30 自动分发安装。

## 决策

采用前端闭环（B 方案）：

- 观察窗口按墙钟时间、按采集/上传阶段分别计算；
- 到窗口且节点仍 `running` 时，抛出专用错误，不写平台终态；
- 主流程退出，保持 `collecting/uploading`，交给现有自动对账；
- 交接写 `detail.observation_handoff` 作为审计；
- 不新增契约码、不改数据库状态机、不改 bridge。

否决方案：

- A 只调大 720 次：只是推迟误杀；
- C 新增全链路超时码：需要契约、七份生成物、状态语义、迁移、三端与 exe 发布，成本过大；且只加码不改状态仍会误判。

## 实现要点

1. `logCollectSync.ts` 新增阶段预算与 `decideObservationWindow` 纯函数。
2. `LogCollectPanel.vue` 的 `pollUntilCollected` 改为墙钟预算；新增 `CollectionObservationWindowError`。
3. 外层 catch 先处理该错误：不 PATCH failed、不改 stage、设置长尾提示与 `longTailObservation`。
4. `resumeAutoSync` 在长尾模式使用 30 秒间隔；新任务/取消/重新收集复位。
5. 交接审计通过现有 PATCH `detail` 合并写入。
6. 单测覆盖采集/上传预算边界与“720 次后仍 running 不失败”。

## 影响范围

- `frontend/customer/src/services/logCollectSync.ts`
- `frontend/customer/src/services/__tests__/logCollectSync.spec.ts`
- `frontend/customer/src/components/LogCollectPanel.vue`
- 事件文档与设计文档

不改 `backend/`、`contracts/`、`terminal_bridge/`。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 长尾提示被误认为卡死 | 文案明确节点仍在发送、后台继续对账，并提供刷新入口 |
| 交接后完成感知变慢 | 长尾 30 秒对账；用户可手动刷新 |
| detail 写失败 | 审计是旁路，失败只记前端日志，不影响主流程 |
| 状态机被破坏 | 交接不写 status，仅写 detail |

## 验证

- 前端单测覆盖 59/61、119/121 分钟边界；
- 回归断言 720 次后节点仍 running 不产生 failed；
- `vue-tsc`、`pnpm build`、前端测试通过；
- 人工模拟长上传，页面不红、任务保持 collecting，完成后自动完成。

## 部署边界

只改前端，不需要 bridge/exe 重装。合并后随 customer-ui 镜像发布；用真实浏览器验收页面长尾提示与自动完成。
