# 日志收集：一步登录并直开面板

## 背景与需求

客户现场反馈「指定工单号」弹框的登录动线是两段式的：

```text
填 SSH → 点「连接」→ 右侧自动滑出「SSH 终端」抽屉 → 关掉终端 → 点「确定」→ 左侧滑出「日志收集」面板
```

三个动作里有两次是纯打扰：

1. 「连接」只是一个中间态，用户真正的意图是「采日志」，不是「开终端」；
2. 右侧终端抽屉弹出的内容用户并不需要看，反而挡住了弹框；
3. 两个按钮都要点，且「确定」在未登录时是禁用的，用户容易以为卡住。

目标：**一个按钮、一次点击**完成"登录 + 提交"，且只打开一个抽屉（左侧日志收集）。

## 事实核查（改动前的真实行为）

| 行为 | 代码位置 |
|---|---|
| 「连接」成功后无条件打开右侧终端抽屉 | `SshConnectSection.vue` `chatStore.openTerminalSidebar()` |
| 「确定」在未登录时禁用 | `LogCollectCaseDialog.vue` `:disabled="!sshConnected"` |
| 登录与提交是两个独立入口 | 登录在 `SshConnectSection`，提交在弹框 `submit()` |

关键约束（决定实现方式，不能靠"界面把按钮藏起来"绕过）：

- bridge 的会话键是 `caseID@nodeIP`，登录时若工单号非法，会话会挂在服务端不认的键上，
  后续采日志必然 `session_missing` → **必须先校验工单号、再登录**；
- 登录结果必须是可 await 的布尔值，否则宿主要么"未登录就先提交"，要么只能轮询 store；
- `SshConnectSection` 同时被 `SshConnectDialog`（SSH 终端弹框）复用，那边的
  「连接 → 自动开终端」是正确行为，**不能一起改掉**。

## 方案概述 (WHAT)

1. `SshConnectSection` 增加两个开关，把"谁触发连接、连完开不开终端"交给宿主决定：
   - `show-connect-button`（默认 `true`）：`false` 时不自带「连接」按钮；
   - `open-terminal`（默认 `true`）：`false` 时连接成功不打开右侧终端抽屉。
2. `SshConnectSection` 通过 `defineExpose({ connect })` 暴露 `connect(): Promise<boolean>`，
   把连接结果回传给宿主；字段缺失仍用 toast，连接失败仍落在区内错误态（不重复报错）。
3. `LogCollectCaseDialog` 的「确定」改为单入口：校验工单号 → 未登录则 `await connect()` →
   成功才 `confirmLogCollectCase()`；按钮不再因"未登录"禁用，只在提交中 loading。
4. 内嵌登录区去掉「连接」按钮与"未登录"提示文案的旧措辞，改为说明「确定」会先登录。

## 详细设计

### 1. 提交顺序（为什么先校验工单号）

```text
点「确定」
 → ① 本地校验 Q+8位日期+5位序号（失败即止，不碰 SSH）
 → ② 已连接？是 → 跳到 ④
 → ③ bridge 结论不是 running → 现探一次（3s，复用并发中的探测）
        仍不通 → 报「SSH Bridge 未运行」，不登录、不提交
        通 → await SshConnectSection.connect()（caseId 用输入框里的工单号）
        返回 false（字段缺失/认证失败）→ 结束，错误由登录区展示
 → ④ confirmLogCollectCase(caseId) → 关闭弹框、打开左侧日志收集面板
```

顺序上把工单号校验放在登录之前，是为了避免用非法工单号建立 `caseID@nodeIP` 会话。

### 2. bridge 探测改为可等待

原 `detectBridge()` 只写 `bridgeStatus`，`submit()` 同步读这个值。用户填完立刻点「确定」时
探测可能还在飞，会读到 `'checking'` 并误报"Bridge 未运行"。

改为返回 Promise，并用模块内 `bridgeCheckPromise` 做在途去重：弹框打开时的预检与
「确定」触发的复检共享同一次探测，不会叠加 3s 超时。已有 `running` 结论时不再重复探测。

### 3. 为什么用 expose 而不是新事件

`connected(host)` 事件是"通知"，宿主收到时提交动作已经在事件回调里，错误无法回流到
`submit()` 的 try/catch；而「确定」需要的是"结果"。因此 `connect()` 返回布尔值，
`connected` 事件保留给其他关心该信号的调用方（当前是折叠状态条与发起节点回填）。

## 对抗性审查（改动会怎么坏）

| 风险 | 结论 / 处理 |
|---|---|
| 隐藏按钮后用户没有"先测连通"的手段 | 不需要：一次点击就是登录+提交，失败会停在登录区错误态，可「重试」或再点「确定」 |
| 登录成功但工单解析失败（如归属 404） | 弹框保持打开并显示错误，SSH 会话保留；用户改工单号再点「确定」不会重连 |
| 登录成功却没开终端，会话"看不见" | 会话仍可用（面板按 `caseID@nodeIP` 复用）；需要看终端可点顶栏「SSH 终端」 |
| `bridge-checking` 时点「确定」 | 已改为等待探测结论，不再误报 |
| 连点「确定」 | `submitting` 守卫，且按钮 loading，避免重复 `connectSSH` |
| 影响 SSH 终端弹框（`SshConnectDialog`） | 两个新开关默认值保持原行为，`SshConnectDialog` 未改一行；回归用例 3 条仍通过 |

## 测试与验收

单元测试（`frontend/customer`）：

- `SshConnectSection.spec.ts`：`show-connect-button=false` 时不渲染「连接」按钮且
  `connect()` 回传 `true`；`connect()` 失败回传 `false` 且不 emit `connected`；
  `open-terminal=false` 时 `openTerminalSidebar` 不被调用；
- `LogCollectCaseDialog.spec.ts`：未登录点「确定」按 `connect → confirm` 顺序执行；
  「确定」不再禁用；登录失败不提交；bridge 不通时不登录不提交；
  内嵌登录区收到 `show-connect-button=false` / `open-terminal=false`。

验收口径（staging 人工）：

1. 未登录状态点顶栏「日志收集」→ 弹框出现，**没有「连接」按钮**；
2. 填工单号 + SSH 信息 → 点「确定」→ 不出现右侧 SSH 终端抽屉；
3. 登录成功 → 弹框关闭 → 左侧「日志收集」面板直接滑出，发起节点 = 刚登录的主机；
4. 密码填错 → 弹框不关、无面板、区内显示失败原因；
5. 已登录状态点「日志收集」→ 行为不变（跳过弹框直开面板）。
