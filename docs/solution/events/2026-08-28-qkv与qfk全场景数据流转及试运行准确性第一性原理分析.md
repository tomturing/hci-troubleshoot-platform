# QKV 与 QFK 信号全场景数据流转与试运行准确性第一性原理深度分析

> **方法论声明**：本文档严格统一运用**第一性原理**（拆解至底层不可再分的物理执行、数据模型与运行时契约）和**对抗性审查**（红队视角极限施压、边界条件测试与脆弱性审计），对平台中 QKV 和 QFK 信号在生产运行时与管理端试运行中的全链路数据流转、变量落池机制及验证范围准确性进行完整闭环归档。

---

## 一、QKV 信号三大场景物理全解

QKV（Query Key-Value）的物理本质是：**从结构化/半结构化 API 响应（JSON 数组）中提取变量并完成断言或智能推导**。

```
[原始采集输出 (30+ 字段 JSON 数组)] 
              │
              ▼ 【第一步：字段投影 (orchestrate.produces)】
[已提取的精简变量字典 (如 ERRCODE_TRACING, DESCRIPTION)]
              │
              ▼ 【第二步：处理流水线 (orchestrate.output_processing)】
              ├── 派生 derive (确定性正则/切分 / AI 智能推导)
              └── 断言 assert (阈值比较 / 包含判断 / 正则匹配)
              │
              ▼ 【第三步：业务终态与变量池沉淀】
```

---

### 1. 场景一：不带变量处理逻辑（纯 Producer）

#### ① 物理事实与第一性原理
- **契约定义**：仅配置 `orchestrate.produces`，`orchestrate.output_processing` 为空。Signal 扮演**纯数据生产者**角色，不对数据做业务好坏的断言判定。
- **输入（Input）**：前端 API 采集到的原始 JSON records 数组（包含 30 多个内部冗余字段）。
- **中间处理（Processing）**：
  - 调用 `_extract_by_produces(records, produces)`；
  - 遍历每个 `produces` 项（如 `name: "ERRCODE_TRACING", path: "errcode_tracing"`），执行候选路径查找、大小写兼容与空值清洗。
- **输出与变量池（Output & Pool）**：仅包含声明字段的精简字典列表 `[{"errcode_tracing": "0x1900006c", "description": "..."}]`。
- **终态判定（Status）**：
  - 成功提取出至少 1 条非空记录 ➡️ `PASS`；
  - 原始数据中未能提取出任何有效字段 ➡️ `FAIL`。

#### ② 对抗性审查（红队攻击与防御）
- **边界攻击（假值陷阱）**：若上游返回 `"status": 0` 或 `"enabled": false`。
  - *防御加固*：底层采用 `val is not None and val != ""`，严禁使用 Python 隐式布尔判断 `if val:`，确保 `0` 和 `False` 能够完整提取入变量池。
- **失效攻击（字段改名）**：若 API 字段重构导致 produces 全未命中。
  - *防御加固*：生产 parser 与试运行均立刻判定为 `FAIL`，阻断下游读取空变量导致的异常。

---

### 2. 场景二：带变量处理逻辑且不含 AI（确定性后处理）

#### ① 物理事实与第一性原理
- **契约定义**：在 `produces` 提取后，挂载了确定性 `output_processing` 流水线（包含 `derive` 变量派生与 `assert` 规则断言）。
- **输入（Input）**：原始 JSON records 数组。
- **中间处理（Processing）**：
  1. 先按 `produces` 提取精简变量集合；
  2. 按照数组下标顺序依次执行 `output_processing`：
     - `derive`：利用正则/字符串切分派生新变量（如从 `description` 中提取 `VM_NAME`）；
     - `assert`：对目标变量执行关键字、正则或数值阈值断言（如 `判断 {{ERRCODE_TRACING}} 包含 [0x1900006c]`）。
- **输出与变量池（Output & Pool）**：包含初始变量与新派生变量的 records 数组，以及各单元的执行报告（`assertions`）。
- **终态判定（Status）**：
  - 流水线中**所有 `assert` 单元全部为 PASS 时，最终结论才为 PASS**；
  - 只要有任一断言不满足即为 `FAIL`。

#### ② 对抗性审查（红队攻击与防御）
- **依赖攻击（未就绪占位符）**：断言单元引用了前序未派生的变量 `{{NOT_EXIST}}`。
  - *防御加固*：`apply_output_processing` 严格按照依赖拓扑进行占位符替换，若未命中直接标记该断言单元为 `UNKNOWN/FAIL`，杜绝未定义变量被静默吞掉。
- **多行记录短路攻击**：当输入包含 10 条虚拟机任务记录时。
  - *防御加固*：QKV 遵循列表过滤语义，只要有一条记录满足全部断言链路，即代表捕获到目标故障实体。

---

### 3. 场景三：变量处理逻辑中含 AI（智能推导与混合流水线）

#### ① 物理事实与第一性原理
- **契约定义**：流水线中某一个 `derive` 单元启用了 `ai_processing`（如从非结构化文本中由大模型推导出根本原因或跨时间差计算）。
- **输入（Input）**：原始 JSON records 数组。
- **中间处理（Processing）**：
  1. `produces` 提取 ➡️ 前序确定性 `derive` 变量派生；
  2. 遇到 AI 单元时，组装上下文调用大模型；
  3. 大模型返回推理值，同时**必须提供证据行（Evidence Grounding）进行逐字交叉回查**；
  4. 校验通过后将 AI 推理结果写入当前 record 作为新变量；
  5. 继续执行后续的确定性 `assert` 断言。
- **输出与变量池（Output & Pool）**：挂载了 AI 推导产物的 records 数组，以及可审计的 `ai_raw_response`。
- **终态判定（Status）**：大模型调用成功 + 证据链回查一致 + 后续所有断言满足 ➡️ `PASS`；模型超时、幻觉被拦截或断言失败 ➡️ `FAIL/UNKNOWN`。

#### ② 对抗性审查（红队攻击与防御）
- **幻觉攻击（模型编造数值）**：模型自己捏造了不存在的时间或错误码。
  - *防御加固*：底层 `extract_ai_value` 强制执行 `grounding` 校验：引用的 `evidence` 必须能与输入的真实文本实现逐字完全匹配，否则直接判定 `HALLUCINATION_REJECTED`。
- **网络抖动与限流攻击**：若大模型服务异常。
  - *防御加固*：系统输出 `UNKNOWN` 状态并完整保留 `error_code` 和调用链，不会将系统级异常误判为业务正常的 `FAIL`。

# 二、QFK 信号全场景物理全解（含产出变量）

QFK（Query Free Knowledge）的物理本质是：**从非结构化 CLI 终端命令的 `stdout / stderr` 文本流中完成取值、变量沉淀与模式判定**。

QFK 依据最终使命分为两大形态：
1. **Match 判定型信号**（`match` 非空，`orchestrate.produces` 为空）：验证现场是否出现特定故障模式；
2. **Produces 产出型信号**（`orchestrate.produces` 非空，`match` 为 null）：采集现场数据并提取变量注入全局变量池，供下游信号消费。

```
[CLI 命令执行文本 (stdout / stderr)] 
              │
              ▼ 【第一步：取值 (extract)】
              ├── 方案 1：确定性取值 (正则 / 行索引 / JSON Path / 文本截取)
              └── 方案 2：AI 智能取值 (大模型语义理解 / 复杂上下文推理)
              │
              ├───► 形态 A：Produces 产出型 (orchestrate.produces)
              │     ▼ 【第二步：产出变量落池】
              │     将取值结果映射为目标变量名（如 HOST, PID, TIME_DIFF）注入全局变量池
              │     ▼ 【终态】：PASS（提取成功） / FAIL（未提取到）
              │
              └───► 形态 B：Match 判定型 (match)
                    ▼ 【第二步：模式匹配 (match.type)】
                    ├── keyword (关键字包含 / 排除)
                    ├── regex (正则表达式匹配)
                    └── threshold (数值阈值 / 时间差对比)
                    ▼ 【终态】：布尔结论 (PASS / FAIL / UNKNOWN)
```

---

### 1. 形态 A：Produces 产出型信号（变量生产者）

#### 场景 1.1：第一步取值不含 AI（确定性变量生产）
- **物理事实**：通过确定性正则、行号或 JSON Path 从命令输出中提取特定值，并赋予变量名存入变量池。
- **代码证据**：
  - `backend/shared/schemas/signal_schema.py` 第 743 行：`signals[{index}] 是产出变量信号，必须配置 orchestrate.produces 且 match 必须为 null`；
  - `backend/agent-service/app/tools/qfk/engine.py` 第 180 行：`execution_mode="produce" 只取得完整输出，交由 KBD 编排层按 orchestrate.produces 写入变量池`。
- **输入（Input）**：命令 stdout 文本流。
- **中间处理（Processing）**：执行 `extract_value` 提取目标值。
- **输出与变量池（Output & Pool）**：产出形如 `{"HOST": "192.168.1.10", "PID": "41398"}` 的字典并落入会话变量池，后续信号可通过 `{{HOST}}` 动态渲染命令。
- **终态判定（Status）**：成功提取 ➡️ `PASS`；提取为空 ➡️ `FAIL`。

#### 场景 1.2：第一步取值含 AI（智能语义变量生产）
- **物理事实**：命令输出为非标准文本（如堆栈日志或多节点状态），由大模型结合 Few-shot 候选与指令提取目标变量。
- **输入（Input）**：命令 stdout 文本流。
- **中间处理（Processing）**：调用 `extract_ai_value`，模型完成语义推导并逐字校验 evidence 证据行。
- **输出与变量池（Output & Pool）**：将模型提取的语义变量存入变量池，附带 `ai_raw_response`。
- **终态判定（Status）**：提取合规且证据吻合 ➡️ `PASS`。

---

### 2. 形态 B：Match 判定型信号（业务断言判定）

#### 场景 2.1：第一步取值不含 AI（纯确定性断言）
- **物理事实**：取值和匹配完全由本地 Python 运行时执行确定性计算（零大模型开销，耗时 < 1ms）。
- **输入（Input）**：命令 stdout 文本流。
- **中间处理（Processing）**：
  1. `extract_value` 提取目标文本/数值；
  2. `evaluate_matcher` 将提取值与预期值对比（如正则匹配 `ERR_.*` 或数值 `<= 10`）。
- **输出与终态（Output & Status）**：匹配期望 ➡️ `PASS`；不匹配 ➡️ `FAIL`；同时输出高亮证据行号列表。

#### 场景 2.2：第一步取值含 AI（AI 取值 + 确定性断言）
- **物理事实**：由大模型提取高度复杂的语义指标（如“两台主机心跳时间差”），提取出的数值送入第二步确定性 Matcher（如判断 `<= 3秒`）。
- **输入（Input）**：命令 stdout 文本流。
- **中间处理（Processing）**：
  1. `extract_ai_value` 语义取值（带 evidence 回查）；
  2. `evaluate_matcher` 对取出的值执行阈值/模式判定。
- **输出与终态（Output & Status）**：大模型提取成功且 Matcher 判定符合期望 ➡️ `PASS`。

# 三、试运行“两种验证范围”输入、输出与中间处理的准确性分析

在管理端试运行弹窗中，专家可切换 **【整个 Signal】** 与 **【当前 AI 处理】**。

```
                                  ┌─►【整个 Signal】 (端到端业务闭环)
                                  │   全量流水线 ➡️ 最终业务 PASS / FAIL ➡️ 可保存到 Bundle
【试运行验证范围 (verificationScope)】─┤
                                  │
                                  └─►【当前 AI 处理】 (契约与模型能力靶向验证)
                                      截断后续业务断言 ➡️ 仅验证 AI 本身 ➡️ 不产出业务结论
```

---

### 1. 验证范围 A：【整个 Signal】（端到端业务验证）

| 维度 | 准确性与物理事实 |
| :--- | :--- |
| **输入范围** | 接受原始输入（QFK 为 stdout 字符串，QKV 为原始 JSON records 数组）。 |
| **处理过程** | **执行完整链路**：<br>• QKV：`_extract_by_produces` 投影 ➡️ `derive` 派生（含 AI） ➡️ `assert` 业务断言。<br>• QFK：`extract`（含 AI） ➡️ `Matcher` 业务匹配（或 produces 变量生产）。 |
| **输出结果** | • `status`：代表当前 Signal 的**最终业务结论**（`PASS / FAIL`）；<br>• `value`：最终落入变量池的干净变量字典；<br>• `evidence`：完整的业务判定说明。 |
| **保存权利** | 只有在【整个 Signal】且状态为 `PASS` 时，才允许签发 `preview_token` 并保存为 Bundle 草稿。 |

---

### 2. 验证范围 B：【当前 AI 处理】（AI 契约与单点能力测试）

#### ① 为什么必须截断后续业务断言？（第一性原理）
- **核心痛点**：专家配置了一个 AI 提取时间差（当前时间差是 8 秒，模型提取出了 `8`，非常准确）；但后续断言规则是 `阈值 <= 2 秒`。
- 若不截断，整个 Signal 会因为业务超标判定为 `FAIL`，导致专家无法分辨是 **“大模型提取有误”** 还是 **“业务规则判定不达标”**。
- 因此，【当前 AI 处理】的唯一使命是：**只验证大模型是否按契约从当前输入中准确提炼出了目标值**。

| 维度 | 准确性与物理事实 |
| :--- | :--- |
| **输入范围** | 包含当前 AI 单元所需的前序确定性上下文。 |
| **处理过程** | **精准截断**：试运行仅执行到当前选中的 AI `derive` / `extract` 单元为止，**跳过所有后续的业务断言与规则匹配**。 |
| **输出结果** | • `status`：仅代表 **AI 提取动作本身是否合规成功**（`PASS` 代表 AI 成功按契约提取且证据链吻合）；<br>• `value`：AI 提取的原生中间值（如 `8`）；<br>• `ai_raw_response`：模型原始输出、Token 消耗及推理过程。 |
| **安全阻断** | 该模式仅供专家微调 Prompt 与调试模型，**严禁将其作为整个 Signal 的结论直接保存入 Bundle**（保存按钮被自动置灰禁用）。

| **QKV 场景 3** | 混合 AI 处理 | 整个 Signal | 30+ 字段原始 JSON 数组 | 先投影 ➡️ AI 智能派生(带回查) ➡️ 断言匹配 | 声明变量 + AI 派生变量 |
| **QKV 场景 3** | 混合 AI 处理 | 当前 AI 处理 | 30+ 字段原始 JSON 数组 | 先投影 ➡️ 执行至目标 AI derive 即截断 | 仅展示该 AI 单元的推导产物 |

| **QFK 场景 1.2** | 纯生产者 (含AI) | 当前 AI 处理 | 原始 stdout/stderr 文本 | 仅执行大模型语义提取 ➡️ 截断 | AI 提取的目标值 + AI 原始响应 |
| **QFK 场景 2.1** | Matcher判定 (无AI) | 整个 Signal | 原始 stdout/stderr 文本 | 确定性文本/正则取值 ➡️ Matcher 比较 | Matcher 判定结果与证据行 |
| **QFK 场景 2.2** | Matcher判定 (含AI) | 整个 Signal | 原始 stdout/stderr 文本 | AI 取值(带回查) ➡️ Matcher 比较 | Matcher 判定结果 + AI 原始响应 |
| **QFK 场景 2.2** | Matcher判定 (含AI) | 当前 AI 处理 | 原始 stdout/stderr 文本 | 仅执行大模型语义提取(带回查) ➡️ 截断 | AI 提取的目标值 + AI 原始响应 |
