# 方案事件：会话代际与单一权威终态（2026-11-06）

关联设计：[docs/plans/2026-11-06-交付一致性-design.md](../../../plans/2026-11-06-交付一致性-design.md)

## 一句话

不再把「包大小」当身份，也不再让客户端写终态：会话绑定内容指纹与代际，分叉时自动重签；终态由服务端单一写入者按持久化事实推进；前端只表达「结果未知」。

## 根因（第一性原理）

| 事实 | 硬约束 |
| --- | --- |
| 交付对象是字节序列，文件名+大小不是身份 | 会话必须绑定内容指纹 |
| 分片几何在 init 冻结 | 之后字节变化必然逐片失败，重试无意义 |
| 同工单存在多代作业 | 旧代写入必须被 fencing 拒绝 |
| 浏览器请求失败 ≠ 业务失败 | 终态只能由服务端在事实发生后写 |
| 现场 exe 不自动升级 | 核心修复必须服务端/前端独立闭环 |

## 方案对比

| 方案 | 结论 |
| --- | --- |
| A 只补三个点（重排判据、通道分类、回写 status） | 否决：包变化仍必现，只是报错更清楚 |
| **B 三支柱 + Go 纵深** | 选中：内容指纹与代际自愈、单一权威终态、前端结果未知与自动重签 |
| C 事件溯源重写 | 否决：数周工作量且 exe 不升级，收益无法落地 |

业界范式仅作候选：内容寻址、fencing token、single-writer、CAS、协作式取消、Unknown ≠ Failed。

## 落地清单

| 层 | 改动 |
| --- | --- |
| `case-service` | `DeliverRequest`/`UploadInitRequest` 增可选指纹与代际；`upload_service.init` 指纹变化自动 abort 重建；`update_task` 忽略客户端终态写且禁止 delivered→failed；`_finish(success)` 收敛 status/错误字段并带 CAS；终态写入统一走服务端函数 |
| `customer` | `isOutcomeUnknownError` 覆盖 WS 通道断开；结果未知不 PATCH；收到会话作废码自动重新 stat + deliver + submit；采集未收尾禁止提交；移除前端终态 PATCH |
| `terminal_bridge`（纵深） | `deliveryJob` 增代际/废弃标记；`runJob` 与重排检查 ctx + membership；各阶段入口检查 `ctx.Err()`；废弃作业不暴露 error_code |
| 可观测性 | 四类计数事件 + `trace_id` 贯穿：`delivery.session_rebuilt`、`delivery.epoch_rejected`、`task.terminal_write_ignored`、`task.outcome_unknown` |
| 数据库 | 不新增列，复用 `detail` JSONB 存代际与既有 `trace_id` |

## 对抗性审查要点

摘要取不到时指纹降级为 size+mtime+stable；老 exe 忽略新字段但服务端/前端自愈链路独立生效；忽略客户端写终态走静默 + 审计而非 422；`failed→completed` 由专用终态函数显式允许并留痕；自动重签限 2 次且指纹相同幂等复用；旧 relay 迟到写由 epoch CAS 拒绝；`detail` JSONB 避开 Atlas DDL 顺序事故。
