## 2. A1：拆 `app.Bridge`（本次完成第 1 条验收）

### 依赖账本先行

不按"52 个函数签名"这种二手数字开工，先用脚本按函数签名提取参数名、再收集函数体内的成员访问，得到真实账本：

| 域 | 实际用到的 Bridge 成员 | 处置 |
|---|---|---|
| `logcollect` | `Get/Resolve/SessionByNodeIP/SessionByAddressHost/OnlySessionForCase/Count/Keys` | 全部是会话能力 → 改收 `*session.Hub` |
| `sftp` | `SftpTasks/SftpTasksMu/Count/Keys` | 任务表归还域内；会话改 `*session.Hub` |
| `acli` | `AcliMu/AcliBusy/AcliCache/ResolveAcliSync` | 状态归还域内；会话改 `*session.Hub` |
| `delivery` | `ReconnectDeliveryNode` + 1 处跨域借用 | 定义 `Reconnector` 端口 + 注入 Hub |
| `terminal` / `sshx` | 无 | — |

结论：域需要的从来不是"装配壳"，而是**会话注册表 + 各域自有状态 + 一个重连回调**。

### 落地动作

1. **状态所有权下沉**：`sftp` 任务表（原 `map[string]any` + 类型断言）与 `acli` 的传输互斥/包缓存归还各域，消除两处运行期 panic 缝。
2. **跨域借用归位**：`ResolveLogCollectSession` 原是四个域共用的会话回退序列，却住在 `logcollect`（sftp/delivery 反向借它）。整体迁为 `session.Hub.ResolveForNode`，`logcollect` 侧导出版删除。
3. **指标下沉**：`app.PromMetrics` 被 sftp 直接用，迁到 `shared/metrics`（零依赖包），否则"域→app=0"无法成立。
4. **兼容包装退场**：`SessionCount/SessionKeyList/ListSessions/ResolveSession/ResolveAcliSyncSession/ResolveInputSession` 六个薄包装删除，调用方直接用提升后的 Hub 方法。
5. **夹具迁移**：`app.NewBridgeWithSessions` 删除，改 `session.NewHubWithSessions`（仍走 `Set`，保持 refs=1 不变量）。

## 3. A2：obslog 门面化（本次完成第 2 条验收）

### 为什么不直接注入构造函数

域内 `obslog.*` 调用点 200+ 处（Emit 159 / EmitContext 42 / 脱敏与链路原语 10）。逐个改成 receiver 注入会把一次架构调整摊成 200 处噪声改动，且与仓库既有范式不一致——`shared/telemetry` 已经是"门面 + 双实现"，obslog 却让 7 个包直连实现。

### 落地动作

新增 `internal/shared/evidence`：只定义 `Sink` 接口（8 个方法）+ 转发函数，用 `atomic.Value` 保存注入实现，未注入时退化为 Nop（测试可直接跑）。装配层 `cmd/bridge/evidence_wire.go` 写唯一适配器，`main` 在 obslog 初始化之后、业务 goroutine 启动之前注入。

- 域内 `import shared/obslog`：15 个文件 → **0**
- 调用点零语义变化（`obslog.Emit` → `evidence.Emit`，签名完全一致）
- 未注入时不会静默丢弃证据：装配层是唯一入口，`installEvidenceSink()` 与 `obslog` 初始化在同一函数内相邻，删掉即编译不过（`evidence` 无默认实现能落盘）

## 5. A4：delivery 端口化（完成验收第 3 条）

### 端口设计

delivery 需要的是"执行 + 生命周期"，不是会话对象：

```go
type NodeSession interface {
    remote.Runner          // RunQuickCommand / WriteStdin
    remote.StreamsRunner   // RunQuickCommandStreams（分轨，区分 exit 127）
    remote.StreamRunner    // ReadStream（流式拉取，20 GiB 不进桥内存）
    BeginLongTask(); EndLongTask()
    StartShellHeartbeat(caseID string) func()
    MarkBusy()
    RunCommandPty(ctx, cmd, timeout)
}
```

`Reconnector` 只保留两件事：`Wrap(key)`（把注册表里的会话适配成端口，只有装配层知道具体类型）与 `ReconnectDeliveryNode`。适配器在 `cmd/bridge/delivery_wire.go`。

### 顺带完成的"物归原主"

- `RunCommandPty` 从 `logcollect` 下沉为 `sshx.SSHSession` 方法，PTY 参数（40×160、关闭 ECHO/OPOST/ONLCR）在 sshx 单一来源，`terminal` 保留别名；
- `ProbeSourceDigest` / `ProbeLogCollectArchive` / `PullArchive` 三个被借用的原语改为接收 `remote.Runner` / `remote.StreamsRunner` / `remote.StreamRunner`（它们本来就只调用执行原语）；
- `sshx.NewSSHRunner` 返回组合接口 `sshx.Runner`，调用方按需赋给任意 remote 窄接口，不需要类型断言。

指标：delivery 生产代码 import `sshx` **1 → 0**；`*sshx.SSHSession` 出现 **0**（仅测试构造夹具用真实类型）。

## 6. A5：门禁加固（完成验收第 4 条）

`scripts/check_bridge_imports.py` 新增：

- **禁令6**：业务域不得 import `app`（含测试）——A1 已清零，加规则防回退；
- **禁令7**：`PORT_ONLY_DOMAINS`（当前 `delivery`）不得 import `sshx` 具体类型，只扫生产代码（测试用真实类型构造夹具是合理的，逼测试造假货反而失真）；
- **基线 sunset**：`BASELINE_SUNSET = 2026-12-31`，到期后基线本身成为失败项，逼迫收紧而不是永久冻结现状（对应审查文档 §10.2 盲区 3）。

门禁有效性做了**阳性对照**：临时注入 `import _ "terminal_bridge/internal/app"`，扫描立即报 `[禁令6]`，证明规则不是空转。

## 6. 决策记录

- **不用服务定位器式全局 Registry**：会话注册表是唯一被共享的可变状态，其余状态（sftp 任务表、acli 缓存）必须回域内，否则只是把上帝对象拆成三个小上帝对象。
- **门面而非构造注入**：横切关注点用门面，业务状态用构造注入。判据是"是否需要域测试替换行为"——证据通道在测试里不需要替换（Nop 即可），业务状态需要。
