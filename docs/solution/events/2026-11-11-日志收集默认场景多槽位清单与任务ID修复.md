# 日志收集：默认场景多槽位清单与 create 任务 ID 修复

## 变更历史

| 日期 | 版本 | 变更内容 | 关联事件文档 |
|------|------|---------|------------|
| 2026-11-11 | v1.0 | 初版：现场报错修复 + 默认场景可编辑清单 | [需求](../requirement/events/2026-11-11-日志收集默认场景清单可编辑与任务ID修复需求.md) |

## 背景与需求

现场工单在 spc 自定义场景点「开始收集」后被桥以「缺少合法的任务 ID，无法确定备份归属」拒绝。根因是前端 create 消息未带 `exec_id`，而桥用任务 ID 命名备份且不会兜底生成。同时用户要求：自定义场景能定义日志与配置文件，默认场景也应能按场景修改默认收集清单。

## 方案概述

- 修复：create 消息携带平台任务 ID 与唯一调用链 ID；`invalid_task_id` 纳入规范错误码。
- 新功能：平台按模块保存「默认场景清单覆写」，下发时由桥**逐槽位写入各自清单文件**、逐槽位备份与还原，acli 仍按原模块枚举收集。

## 详细设计

### 数据模型

- 新增按模块的覆写表：模块唯一键、条目 JSON、版本、摘要、启用标记、更新者与唯一调用链。只存覆写行，不存全量种子；未覆写模块取随镜像发布的清单快照，「恢复默认」即删覆写行。
- 任务侧新增槽位集合与清单证据字段，保留既有单槽位字段以兼容存量任务。

### 服务与接口

- 管理端：按模块列表（含快照/覆写标记）、保存覆写（版本递增、条目校验、试算预览）、恢复默认、只读 JSON 预览。
- 客户侧：按已勾选模块返回只读清单预览。
- 所有新增管理端可达路由按项目规范在网关逐条补代理。
- 建任务时，默认场景若命中任一覆写，按已勾选模块生成逐槽位载荷（槽位、原文、摘要），随建任务响应一次性返回；前端原样透传给桥。

### 桥侧多槽位扇出

- 保留单槽位 `spc_json` 通道不变（存量自定义场景零改动），新增逐槽位载荷通道。
- 每台目标节点只探测一次目录，随后逐槽位执行「写前自愈 → 按任务隔离备份 → 写入 → 回读校验」；任一槽位失败即整轮拒绝并全量回滚，保持「写不全绝不下发」不变量。
- 终态还原、失败/取消还原、平台兜底还原均按槽位集合执行；备份名自描述任务号，桥重启后仍可重放。
- 采集模块集合收窄为写入成功的槽位，与写入范围严格一致。

### 兼容性与版本门控

- 旧桥不认识新载荷会静默按节点原清单收集，这是最危险的失败形态；因此客户侧必须先确认桥版本支持多槽位，否则拒绝启用平台清单并提示升级，绝不静默降级。
- 未编辑任何默认场景时，建任务不生成逐槽位载荷，行为与现状完全一致。

### 可观测性

- 建任务与下发共用唯一调用链；清单选择、逐槽位写入、回滚、还原事件都带任务 ID、槽位集合、摘要与逐台结果。
- 任务详情记录本次各模块清单来源（快照/覆写）与摘要，事后可回答「到底按哪份清单收的」。

## 决策依据

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A 平台合并为单槽位清单 | 不改桥、交付快 | 多模块语义被压平成一份清单 | 未选 |
| **B 逐槽位扇出（选中）** | 每个场景写自己的清单文件，语义与 acli 模块一一对应 | 必须改桥并现场人工重装 exe | **选中** |
| C 仅编辑作参考 | 改动最小 | 不改变实际收集内容，不满足需求 | 未选 |

**为什么选 B**：用户明确选择「每个模块写各自的清单文件」。从第一性原理看，acli 的模块语义就是「按模块读取同名清单」，合并会丢失模块边界并让产物难以解释；B 保留该语义。

**为什么不选 A**：A 用交付速度换语义正确性，但平台清单已按模块组织，压平后每个场景的自定义标记与还原证据都要额外翻译层，长期成本更高。

**权衡与妥协**：B 引入桥版本依赖。桥可执行文件不随平台发版自动更新，必须由发布流程重建并在现场人工重装；在版本门控生效前，客户侧不会启用平台清单，避免「看起来成功了」。

## 影响范围

- 终端桥：新增逐槽位载荷与还原能力，需重新构建可执行文件。
- 平台：新增覆写表、接口、网关代理、建任务分支。
- 前端：管理端新增编辑器，客户侧新增清单预览与版本门控。
- 文档：接口设计、数据库设计、管理台设计、README 第一屏与避坑记录。

## 测试策略

- Go：单槽位存量测试全绿 + 多槽位写入/回滚/还原新用例；命令拼装与注入边界。
- 后端：覆写保存、校验、恢复默认、逐槽位载荷生成、建任务回归。
- 前端：管理端编辑与恢复、客户侧预览与门控、create 消息契约。
- 端到端：浏览器模拟人工编辑默认场景清单并下发，核对逐槽位写入与还原回执。

## 验收标准

- [ ] 自定义场景 create 带合法 `exec_id` 与调用链，不再报 `invalid_task_id`。
- [ ] 默认场景各模块可分别编辑清单并生效，产物按模块边界可读。
- [ ] 任一槽位写入失败即整轮回滚，且不残留平台清单。
- [ ] 成功、失败、取消终态均完成逐槽位还原。
- [ ] 旧桥版本被门控拦下，不出现静默按错清单收集。
- [ ] 未编辑清单时行为零变化；全量测试、文档门禁与浏览器验证通过。
