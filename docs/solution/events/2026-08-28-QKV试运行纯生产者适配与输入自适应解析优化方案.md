# QKV 试运行纯生产者适配与输入自适应解析优化方案

## 一、 背景与问题定位

在 HCI 排障平台关键信号（Signal）编辑与试运行交互中，用户在对 QKV 信号进行仿真资产试运行及样本调试时，遇到了以下两个阻塞问题：

1. **自动加载资产无法直接试运行（截图 1）**：
   * **现象**：在选择“仿真测试（bundle资产）”并自动加载服务端数据集（内容形如 `{"data": [{"type": "0x1900006c", ...}]}`）后，点击“试运行”，前端直接弹出报错：`QKV 输入必须是 JSON records 数组`。
   * **根因**：服务端仿真测试资产存储的是底层 acli 执行后输出的原始标准输出（Raw Stdout），包含顶层封装对象 `{"data": [...]}`。但前端 `SignalDryRunDialog.vue` 的客户端校验只接受纯数组 `[...]`，导致直接拦截。

2. **手动修改为 JSON 数组后仍报错 `UNKNOWN`（截图 2）**：
   * **现象**：用户手动剥离外层 `{"data": ...}` 修改为数组 `[{"type": ...}]` 再次试运行，后端返回错误 `QKV Signal 没有可试运行的 output_processing`，试运行结论为 `UNKNOWN`。
   * **根因**：当前被测试的 QKV 信号是一个纯生产者（Producer Signal），其定义中只配置了 `orchestrate.produces` 变量提取规则（将 `host`、`vm` 等写入全局变量池），未配置 `orchestrate.output_processing` 后处理流水线。后端的 `_evaluate_qkv` 试运行路由硬编码要求必须存在 `output_processing`，遗漏了对纯 `produces` 变量提取场景的试运行支持。

## 二、 第一性原理 (First Principles) 与对抗性审查 (Adversarial Review)

### 1. 第一性原理剖析
* **数据流动契约**：
  * 排障平台中的 Signal 数据源形态天然具备多样性（acli JSON 响应、结构化 Records 数组、纯对象）。
  * 解析层的核心职责是将不同来源的输入统一转换为规格化的 Record 列表，而不应强求上游或用户在每次交互时手工调整格式。
* **信号职责分类**：
  * **QKV（生产者信号）**：负责前端/状态采集并注入变量池，其核心生命周期包括 `produces` 变量提取与可选的 `output_processing` 派生/断言。试运行应支持纯变量提取验证（提取成功即代表该生产者信号在当前样本下正常工作，标记为 `PASS`）。
  * **QFK（消费者信号）**：负责后端命令探针执行与特征判定，其试运行基于命令文本输出通过提取器与 Matcher 判定 `PASS`/`FAIL`。

### 2. 对抗性审查
* **边界 1（输入形态容错）**：当输入为合法 JSON 对象（如 `{"data": [...]}`、`{"items": [...]}` 或单个对象 `{...}`）时，解析层应自适应提取 records，保证试运行顺畅。
* **边界 2（字段匹配完整性）**：当输入数据中不包含 `produces` 声明的任何变量字段时，试运行必须明确判定为 `FAIL`，并在证据中指出无法提取，禁止误判为 `PASS`。
* **边界 3（AI 范围边界）**：当纯 Producer 信号被指定以 `verification_scope="ai_step"` 进行调试时，应明确拦截并提示未配置 AI 单元，防止非法状态扩散。

## 三、 解决方案与架构设计

### 1. 前端（`SignalDryRunDialog.vue`）自适应预处理
在发起试运行前，对 QKV 输入进行自适应解析：
* 若输入为包含 `data` 数组的对象，提取 `data` 作为 payload；
* 若输入为包含 `items` 数组的对象，提取 `items` 作为 payload；
* 若输入为单个对象，封装为单元素数组；
* 若输入为合法数组，直接使用；
* 仅当输入不是合法 JSON 时，提示友好错误。

### 2. 后端（`signal_dry_run.py`）完善 QKV 生命周期支持
在 `_evaluate_qkv` 执行引擎中：
1. **输入归一化**：通过 `_normalize_qkv_records` 对 `payload` 进行自适应解包与结构检查。
2. **分支分流**：
   * **分支 A（配置了 `output_processing`）**：保持现有流水线，执行 `apply_output_processing_async`，由断言和派生规则决定状态。
   * **分支 B（纯 Producer，仅配置 `produces`）**：调用 `_extract_by_produces(records, produces)` 提取变量字典。
     * 若成功提取到变量，返回 `status="PASS"`，`value=extracted_records`，并在 `derivation` 中记录产出的变量清单；
     * 若未能提取到任何有效变量，返回 `status="FAIL"`，并在证据中明确说明。
   * **分支 C（既无 `output_processing` 也无 `produces`）**：抛出配置不合法异常。

---

## 四、 链路影响与回归验证

1. **兼容性**：完全向后兼容已有配置了 `output_processing` 的 QKV 信号与全部 QFK 信号。
2. **闭环能力**：纯 Producer 信号可成功获得 `PASS` 判定，使专家可以正常将其保存为已验证 Bundle 资产。
3. **可观测性**：试运行请求日志与 Prometheus 耗时/计数指标完整覆盖 QKV 纯生产者路径。
