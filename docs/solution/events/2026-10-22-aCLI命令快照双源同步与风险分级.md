# aCLI 命令快照双源同步与风险分级

## 一、背景与问题

`backend/shared/resolution/catalogs/acli_command_catalog.json` 是 Agent 执行前语义校验与
`RiskClassifier` 的权威命令快照，快照滞后会直接导致两类故障：

1. **可用命令被拦**：新命令不在快照中 → `classify_acli` 判为未知 → 强制人工确认（`ACLI_UNKNOWN_COMMAND_POLICY=deny` 时直接拒绝）。
2. **错误命令被放行**：快照中存在但实机不可执行的命令 → 判为 risk=1 自动执行 → 必然失败。

本次排查在 HCI 6.11.1_R1（acli 1.0.1）上确认了第 2 类故障已经发生：

| 证据 | 结论 |
|---|---|
| `acli plugins --help` → `错误：未知的命令或者命名空间(plugins)` | acli 1.0.1 不存在 `plugins` 命名空间 |
| `acli log_collect --help` → 可用命令 `cancel / create / progress` | 插件是顶层命名空间 |
| 官方命令页 `:6888/commandList`（更新时间 2026-10-09）仍写 `acli plugins log_collect create` | 文档滞后于运行时 |
| `acli acli command list` 349 行，不含任何 `log_collect` 条目 | 插件命令动态注册，核心命令表不覆盖 |

即：**上游文档快照里的 `acli plugins log_collect *` 被自动放行，但运行时必然失败；真正可用的
`acli log_collect *` 反而不在快照中**。这是典型的安全倒挂。

## 二、设计原则（第一性原理）

真值只存在于运行时。因此采用三段式，禁止无脑覆盖：

```
文档页（覆盖最广，但滞后）
  ∪ 旧快照（保留上游删减但实机可能仍可用的条目）
  → override 表（实机验证后的强制修正）
  → 动作 token 推导 risk_hint
```

关键决策：

1. **只提升、不降低**：`risk_hint` 只能把命令提升为 write(2)/danger(3)；
   `read` 不参与判定，继续走原有正则与 fail-closed 逻辑。避免一条错误的 `read`
   标注把写命令放行。
2. **danger 边界收敛**：仅 `delete/remove/format/wipe/destroy/purge` 进入 danger；
   `reboot/shutdown/reset` 保持既有 risk=2 语义，防止同步动作无意改变线上阻断策略。
3. **宁保留不误删**：上游删除的 `acli system qmpcmd` 显式保留。依据是
   `acli acli command list` 不覆盖 system 子命令白名单全量，且既有契约测试依赖该路径；
   删除等于把可能可用的命令降级为"未知"。

## 三、变更内容

| 文件 | 变更 |
|---|---|
| `backend/shared/resolution/catalogs/acli_command_catalog.json` | 337 → 489 条；新增 `schema_version/risk_hint/source` 字段；修正 25 条 `plugins` 前缀 |
| `backend/shared/resolution/catalogs/acli_catalog_overrides.json` | 新增。记录实机验证证据、前缀重命名、显式补充与风险覆盖 |
| `scripts/tools/sync_acli_catalog.py` | 增强为「文档 + 旧快照 + override + 可选实机校验」；输出风险分布；`--from-node` 用 `ssh -tt` 抽取实机清单（插件命令必须 PTY） |

| `backend/agent-service/tests/tools/test_classifier_catalog_risk.py` | 新增回归：无 `plugins` 残留、写命令不得自动执行、停机类命令不误升级 |

## 四、同步结果

```
文档 488 条 | 合并后 489 条 | 重命名 25 删除 0 补充 1 | 风险分布 {'read': 314, 'write': 167, 'danger': 8}
```

- 重命名 25 条：`acli plugins <p> <cmd>` → `acli <p> <cmd>`（source=override，可追溯）
- 补充 1 条：`acli system qmpcmd`
- danger 8 条：`vm delete`、`network bond/anet mirror/pfc delete`、`hardware usb blacklist delete`、
  `vm config pending delete`、`vm hotplug whitelist delete`、`log_collect cancel`

## 五、验证

```bash
uv run pytest backend/agent-service/tests/tools/test_classifier_catalog_risk.py \
                backend/agent-service/tests/tools/test_classifier.py \
                backend/agent-service/tests/unit/test_shared_resolution_runtime.py -q
uv run pytest backend/kb-service/tests/test_resolution_catalogs.py -q
uv run ruff check backend/agent-service/app/tools/acli/classifier.py \
                 backend/shared/resolution/catalog.py scripts/tools/sync_acli_catalog.py
```

结果：124 + 8 项全部通过；`ruff check` 通过。

关键断言：

| 命令 | 期望 | 说明 |
|---|---|---|
| `acli log_collect progress` | 1 | 只读 |
| `acli log_collect create` | 2 | 集群写盘，需确认 |
| `acli log_collect cancel` | 3 | 会 kill 全集群采集进程 |
| `acli hardware usb blacklist add` | 2 | 同步新增写命令 |
| `acli vm shutdown` | 2 | 回归：不得被提升为 3 |
| `acli network nic list` | 1 | 只读不误升 |

## 六、风险与回滚

| 风险 | 缓解 |
|---|---|
| `risk_hint` 推导误判导致只读命令被要求确认 | 只提升不降低；误判代价是"多一次确认"，不是"多一次执行" |
| 同步后命令面扩大 | 167 条 write + 8 条 danger 全部不自动执行；属性测试逐条断言 |
| 实机版本差异 | `--from-node` 输出"实机存在但 catalog 缺失"清单，可人工补 override |
| 回滚 | 单文件级回滚 `acli_command_catalog.json` + `classifier.py`；override 表可清空 |

## 七、后续

1. 将 `--from-node` 纳入 nightly（需可达环境），漂移 >5% 告警。
2. CI 增加门禁：catalog 变更必须同时出现 `classifier.py` 或 `acli_catalog_overrides.json` 变更。
3. 日志收集功能（PR-2/PR-3）将复用本次修正后的 `acli log_collect` 快照与风险等级。
