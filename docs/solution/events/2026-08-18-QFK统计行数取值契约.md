# QFK 统计行数取值契约

## 问题

“结果数量”的既有选项选择的是哪一条或哪些已筛选行作为输出。它们都输出行内容，不能表达“将命中行集合的大小作为数值再判断或写入变量池”。第二步已有 `aggregation=line_count`，但它是 Matcher 内的聚合策略，不是第一步可复用、可产出的数据类型。

## 第一性原理

一次文本取值可拆为两个不可混淆的阶段：先由 `rows` 得到有稳定物理行号的命中集合，再选择输出投影。`cardinality=count` 的投影恒为 `len(matched_rows)`，类型恒为 `integer`；它不读取列、不解析表格、不调用 AI，也不依赖内容中是否包含数字。

因此，`count` 只属于 `type=text`。`header` 与 `delimiter` 可保留，用于定义“数据行（不含表头）”的边界；它们不参与列值提取。空集合仍按现有 `QFK_NO_MATCH` 失败，不把零误写为“已完成的正常取值”。成功时保留全部命中行和物理行号，保证诊断结论可审计。

## 契约与门禁

```json
{
  "type": "text",
  "rows": {"mode": "keywords", "include": ["failed"], "exclude": [], "include_mode": "all"},
  "cardinality": "count",
  "source": "stdout",
  "value_mode": "integer"
}
```

- 仅允许阈值 Matcher，且不能再配置旧的 `aggregation=line_count`，防止两个阶段对同一行集合重复计数。
- 产出变量仅允许 `integer` 或 `number` 类型。
- 禁止 `parser`、`columns`、`value_key` 和 `ai_extract`，防止“统计行数”被误配置为列值统计或 AI 内容提取；可保留 `header`、`delimiter` 以界定数据行。
- JSON 路径仍只有原有四种结果数量选项；JSON 数组长度不是文本行数，必须显式由另一项能力表达。

## 对抗性审查

| 风险 | 防护 |
| --- | --- |
| 前端外的 API 直接提交错误配置 | JSON Schema、保存语义校验和运行时提取器三层独立拒绝。 |
| 切换到统计后保留列/AI 配置 | 管理台切换时清理，Schema 与运行时也拒绝残留字段。 |
| 空筛选结果被当成 0 | 继续 Fail Closed，返回 `QFK_NO_MATCH`。 |
| 仅输出 `2` 而无法解释来源 | `ExtractionResult` 和 Matcher detail 都保留命中原文及物理行号。 |
| 与旧 `line_count` 混用 | 保存时拒绝，前端将旧选项标为“旧聚合”。 |

## 验收

1. 对筛选出的两行文本，`count` 输出整数 `2`，并保留两条原文与物理行号。
2. `count` 能用于 `threshold` 与 `integer`/`number` 变量，不能用于 `exists`、字符串、数组或对象变量。
3. 携带列解析、AI 提取、非整数 `value_mode`，或 `aggregation=line_count` 的配置均被拒绝；表头可用于界定数据行。
4. 管理台只在阈值判断和数值变量中提供“统计行数”，切换后固定整数类型并移除不兼容配置。
