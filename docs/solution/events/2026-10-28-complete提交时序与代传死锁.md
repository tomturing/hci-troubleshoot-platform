# 2026-10-28 complete 提交时序与代传死锁（Q2026101500828）

## 现象

工单 Q2026101500828（task `b14b14e5`，285,595,135 字节 / 272MB）：面板显示
「探测✓ 采集✓ 上传✓ 归档✗」，库里 `delivery_status=failed`、
`delivery_error=平台尚无制品，无法代传`、`error_code=LC-TRANSFER-003`，
但平台 objects 下已有与桥端字节数一致的完整 zip。

## 证据链（逐段核验，非 UI 推断）

| 时刻(UTC) | 事件 | 来源 |
|---|---|---|
| 08:00:27→08:01:40 | 首轮直传 4443 被 x509 拦下 4 次 → job failed | bridge_execution_logs |
| 08:01:53 | 改走平台中转，9 片 PUT 全 200 | case-service access log |
| 08:03:12.618 | PG `FATAL: terminating connection due to idle-in-transaction timeout` | postgres 日志 |
| 08:03:12.659 | complete 请求提交时抛 `asyncpg InternalClientError: cannot switch to state 15` | case-service 日志（同一 trace） |
| 08:03:12.675 | 代传日志 `平台尚无制品，无法代传`（LC-TRANSFER-001） | case-service 日志（同一 trace） |
| 08:03:13 | bridge 上报 job done（pulled=uploaded=285,595,135） | bridge_execution_logs |

48 小时内该模式共出现 **11 次**（每条 asyncpg 异常都与一条 idle-in-transaction
FATAL 成对出现，时间差 <100ms）。

## 根因：两个事务对同一行互等

`complete` 路由在**同一个请求**里做两件事：

1. `upload_service.complete()`：`task.archive_* = ...` 后只 `flush()`——
   UPDATE 已发出、行锁已持有，但事务未提交；
2. `relay_service.trigger()`：**另一个 session** 对同一行执行
   `UPDATE ... SET relay_status='running'`。

于是：请求事务持锁等 trigger 返回，trigger 等请求事务的行锁——死锁。
30s 后 `idle_in_transaction_session_timeout`（postgres.py 连接参数）强杀
请求事务：`archive_*` 回滚丢失；trigger 拿到锁继续，后台 `run()` 读到空
`archive_path`，立即以 LC-TRANSFER-001 失败。桥端则因 complete 返回 200
而认为交付完成——**三方各执一词，现场只见"归档失败"**。

前一提交（收尾长事务）只解决了"合并 IO 跨事务被 30s 强杀"，落库仍是
flush，死锁路径原样保留——本次是它的补全。

## 修复

1. `log_collect_upload_service.complete()`：落库由 `flush()` 改为
   `commit()`——trigger 启动前，制品元数据必须已对其它事务可见。
2. `log_collect_relay_service`：`run()` 捕获异常时透传
   `SangforRelayError.code`（如 LC-TRANSFER-001），`_finish()` 不再把所有
   错误统一改写成 LC-TRANSFER-003——"没制品"与"传输失败"必须可区分。

## 验收与回归护栏

- `test_complete_commits_before_merging`：断言 complete 返回时 commit 恰好
  2 次（合并前清事务 + 落库放行）；
- `test_complete_retry_reuses_merged_object`：失败注入点从 flush 移到
  **第二次** commit（合并前的清事务不能先失败，否则测不到"成品已落盘但
  元数据丢失"的真实形态）；
- `test_run_keeps_sangfor_relay_error_code` /
  `test_finish_preserves_original_error_code`：错误码保留契约。

## 现场补救（已执行）

不重采：回填 `archive_path/archive_size/archive_sha256`（sha256 现算），
复位 `relay_status='none'` / `delivery_status='queued'`，重新触发
`POST /tasks/{id}/relay`。45 秒内 28/28 片推到 5888，
`upload_status` 返回 404（会话已删 = 归档完成），三字段
`relay_status=success / delivery_status=delivered / relay_restarts=1`。
