# acli 插件单文件上限进一步上调至 5MiB

## 文档信息

- **版本**: 1.0
- **创建日期**: 2026-11-25
- **状态**: 已完成，待实机验证
- **关联代码**: `terminal_bridge/internal/acli/acli_plugin_manifest.go`、`backend/case-service/app/domain/acli_plugin_spec.py`、`frontend/admin/src/views/AcliPluginManageView.vue`
- **关联文档**: `docs/solution/events/2026-11-24-acli插件单文件上限上调至1MiB.md`

---

## 一、背景

2026-11-24 已把单文件上限从 512KiB 调到 1MiB，解决了 629KB lmt 脚本被整单拒收的问题。后续运维提出需要支持更大的插件脚本，确认目标为 **5MiB**。

## 二、改动

| 端 | 位置 | 变更 |
|---|---|---|
| 桥 | `acliPluginMaxFileBytes` | `1 << 20` → `5 << 20` |
| 平台 | `MAX_PLUGIN_FILE_BYTES` | `1 << 20` → `5 << 20`；错误文案按常量推导 MiB |
| 前端 | `AcliPluginManageView.vue` | 保存前预检阈值 `1MiB` → `5MiB` |
| 测试 | `test_acli_plugin_spec.py` | 超限断言改为按常量推导的 `5MiB` |

## 三、容量约束

- 单文件上限：5MiB（UTF-8 字节）。
- manifest 总量上限不变：`acliPluginManifestMaxBytes = 16MiB`。
- 内联内容 base64 膨胀约 1.34 倍：单个 5MiB 文件约占 manifest 6.7MiB（约 42% 总量）；若同时放多个大文件，仍可能触发总量上限，此时需要精简或等待 package 分片通道（当前桥侧未实现，`manifest_package_channel_unsupported`）。

## 四、验证

- 自动化：`go test ./internal/acli/...`、`uv run pytest tests/unit/test_acli_plugin_spec.py`（34 passed）、`npx vue-tsc -b` 全部通过。
- 实机：待部署后按既有流程（建单 → acli_sync → 阶段二三态）验证；超 5MiB 保存应在平台侧直接 400。
