# acli 新增插件信息收集模板

> 用途：当只拿到「一份脚本 + 一份使用说明」（例如《[HCI-V1] 1mt 排障工具使用方法》）时，按本模板逐项补齐 acli 插件管理机制要求的信息，再在 admin-ui「acli 插件」页选择「从模板新建」填写。服务端 `/api/v1/acli-plugins/templates` 返回同结构的 JSON 模板，可直接下载导入。

## 1. 必须先确认的硬性前提

| 项 | 要求 | 说明 |
|----|------|------|
| 目标环境 | 选一个已登记的环境代号（如 `24` / `25`） | 页面不填 IP、端口、口令；由服务端环境表 + Secret 解析 |
| 插件名 `plugin_name` | `^[a-z][a-z0-9_]{0,63}$`，不得与出厂 7 个插件重名 | 24 环境出厂：`asan_ops` / `asys` / `log_collect` / `netdoctor` / `performance_tools` / `vm_suspend` / `vm_start` |
| 更新模式 | 新增填 `third_party`；覆盖出厂插件填 `builtin_override` | `builtin_override` 需二次确认，且强制备份 |
| 冒烟参数 `smoke_args` | 必须能真实跑通并产生非空输出 | 例如 1mt：`-m env -c cpu_load`；只用 `--help` 不算生效 |

## 2. manifest.json 必填 15 字段

| 字段 | 类型 | 填写要求 | 示例 |
|------|------|----------|------|
| `id` | string | 插件 UUID，新增时由平台生成，更新内置插件时沿用原值 | `b1f...` |
| `name` | string | 同 `plugin_name` | `hci_1mt_check` |
| `version` | string | 语义化版本，每次下发递增 | `0.0.1` |
| `source` | int | `1` 官方包 / `2` 运维包 / `3` 第三方包 | `3`（新增）、`1`（覆盖 netdoctor） |
| `title` | object | `zh_cn` / `en_us` 双语标题 | `{"zh_cn":"1mt 排障工具","en_us":"1mt Check"}` |
| `vendor_name` | object | `zh_cn` / `en_us` | `{"zh_cn":"HTP","en_us":"HTP"}` |
| `description` | object | `zh_cn` / `en_us`，写清用途与是否只读 | — |
| `change_log` | object | `zh_cn` / `en_us`，本次变更说明 | — |
| `arch` | int | 固定 `1`（x86） | `1` |
| `container` | string | 手工插件固定 `""`（宿主机执行） | `""` |
| `hci_version` | string | 允许空；有明确版本要求时填写 | `""` |
| `acli_version` | string | 版本约束 | `>=1.0.0` |
| `dependencies` | object | 无依赖填 `{}` | `{}` |
| `hash_algo` | int | 固定 `1`（SHA-256） | `1` |
| `hash` | object | **除 manifest.json 自身外**每个文件的相对路径 → 小写 SHA-256；由平台 Builder 计算，不需人工填 | `{"plugin":"...","bin/troubleshoot.sh":"..."}` |

> `hash` 是 acli 校验插件完整性的核心，必须由平台按最终文件字节确定性生成；手填或与文件不一致会在 HCI 侧被判为损坏。

## 3. 目录结构与文件清单

```
/sf/data/local/acli/plugins/<plugin_name>/
├── plugin                  # 0755，wrapper（平台生成）
├── bin/<script_filename>   # 0755，原始脚本（用户提供）
├── lib/…                   # 可选，附加依赖文件
└── manifest.json           # 0644，平台生成
```

附加文件在页面「附加文件」里逐条给 `path` / `mode` / `content`，路径不得出现 `..` 或绝对路径。

## 4. wrapper 模板（`plugin`，平台生成，仅供核对）

```bash
#!/bin/bash
# GENERATED BY htp-acli-plugin-builder. DO NOT EDIT.
set -u
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
SCRIPT="$SCRIPT_DIR/bin/<script_filename>"
case "${1:-}" in
  -h|--help|help) echo "<usage>"; exit 0 ;;
esac
bash "$SCRIPT" "$@"
rc=$?
exit $rc
```

核对点：有 shebang、权限 0755、`SCRIPT_DIR` **不能**被单引号包住、参数用 `"$@"` 原样透传、退出码回传。

## 5. 注册项模板（`plugin_register.json`，平台生成）

```json
{
  "id": "<uuid>",
  "name": "<plugin_name>",
  "version": "0.0.1",
  "status": 1,
  "source": 3,
  "built_in": false,
  "last_updated_at": "<ISO8601 +08:00>"
}
```

- 新增插件：`built_in=false`；注册表由 `jq` 写临时文件后 `mv` 原子替换，禁止直接覆写。
- 覆盖内置插件：`built_in=true`、`source=1`、`id` 沿用现场原值；不改 `/sf/etc/acli/plugins/plugins.json` 与 `last_built_in_plugins_init.json`。
- 注册表更新与 `acli plugin install/uninstall/sync` 共用 `plugin_register.lock`，需 `flock` 互斥。

## 6. 脚本约束（HCI 定制系统）

- **只有** `bash` 内建、`jq`、`flock`、`sha256sum`、`/sf/bin/acli` 可用；**没有** `base64`、`python3`。
- 平台下发一律用 `printf '%b' <escaped> > <file>` 落盘并逐文件 SHA-256 自证，不依赖任何外部解码器。
- 脚本优先只读巡检；需要写操作时必须在 `description` 中说明，并由管理员评估风险等级。
- 禁止脚本内部再调用 `acli plugin install` / 直接改注册表。

## 7. 参数声明与补全

页面「参数与选项」逐条填写 `flag` / `description` / `required` / `default`，用于生成 wrapper 帮助文本与可选 Tab 补全。补全片段追加到 `/sf/cfg/acli/etc/completion/bash_completion.conf`，重复下发必须先去重，避免多次追加。

## 8. 生效验证清单（验收必须逐条留痕）

1. `acli --formatter json plugin list` 出现该插件，版本与 `source` 与配置一致；
2. 注册项字段与第 5 节一致，`built_in` 符合更新模式；
3. 插件目录下每个文件 SHA-256 与 `manifest.hash` 一致；
4. `/sf/bin/acli --timeout 60 <plugin_name> <smoke_args>` 退出码 0 且 stdout 非空；
5. 平台 `acli_plugin_deployment` 回执 `status=succeeded`，`trace_id` 可在 bridge 日志中检索到。

```json
{
  "env_code": "24",
  "update_mode": "third_party",
  "plugin_name": "<小写下划线，必填>",
  "plugin_uuid": "<新增留空由平台生成；覆盖内置插件填现场原值>",
  "display_name": "<列表显示名>",
  "title_zh": "<中文标题>",
  "title_en": "<英文标题>",
  "description_zh": "<中文用途说明，注明是否只读>",
  "description_en": "<英文用途说明>",
  "vendor_name": "HTP",
  "change_log": "<本次变更说明>",
  "version": "0.0.1",
  "acli_version": ">=1.0.0",
  "hci_version": "",
  "source": 3,
  "status": 1,
  "arch": 1,
  "container": "",
  "interpreter": "bash",
  "script_filename": "troubleshoot.sh",
  "script_content": "#!/bin/bash\n<粘贴原始脚本>",
  "parameters": [
    {"flag": "-m", "description": "巡检模式", "required": true, "default": ""}
  ],
  "extra_files": [],
  "enable_completion": true,
  "passthrough_help": false,
  "enable_pid_lock": false,
  "timeout_seconds": 120,
  "smoke_args": "-m env -c cpu_load",

```

> 模板里**没有** `node_ip` / `password` / `private_key` / `bridge_url` / `case_id` 字段：这些属于服务端运行环境，不属于插件规格。若某次新增插件需要新增字段，先更新本模板与 `SpecValidator`，再改页面。
