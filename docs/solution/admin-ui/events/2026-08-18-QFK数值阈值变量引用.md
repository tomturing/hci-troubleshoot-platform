# QFK 数值判定支持变量阈值

## 问题

匹配模式的第二步“判断”中，`threshold`、`delta` 和 `trend` 原先只能填写固定数字。这样同一条关键信号无法复用上游生产者取得的动态基线，例如把当前值与 `{{THRESHOLD}}` 比较。

## 方案

- 编辑器提供“固定数值 / 变量”切换；变量值必须填写完整的 `{{大写变量名}}` 占位符，也支持 `{{VM.NAME}}` 形式。
- Signal v2 Schema 对数值目标保留旧的 number/integer 配置，同时只放行完整占位符字符串，拒绝任意文本。
- 保存与发布时，输入变量推导会扫描 Matcher 全部字段，阈值引用自动进入 `orchestrate.requires` 的依赖图。
- QFK 执行前沿用现有变量池占位符解析；解析结果由确定性比较器转换为数字。变量缺失或不可转换时返回 inconclusive，禁止把它当作 True/False。

## 兼容与观测

旧的固定数字信号无需迁移。执行日志继续沿用 QFK 的 `trace_id`、`exec_id` 和结构化 Matcher evidence，可检索实际比较值、解析后的目标值和失败原因。

## 验证

覆盖固定数字、`{{THRESHOLD}}`、点号变量名、任意字符串拒绝和编辑器切换回归；前端依赖使用 `pnpm`，Python 校验使用 `uv`。
