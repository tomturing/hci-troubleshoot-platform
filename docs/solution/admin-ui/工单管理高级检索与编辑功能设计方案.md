# 工单管理模糊搜索与编辑功能设计方案

本项目旨在优化 `admin-ui` 的 **“工单管理”** 页面 (`/admin/cases`)。我们将完善工单检索的高级过滤器（支持模糊查询、时间范围），并引入全套工单编辑能力，保障管理员在管理台对工单全生命周期的可控性。

---

## 🎨 视觉与交互设计 (UI/UX Design)

### 1. 筛选栏升级（高级检索表单）
我们将升级现有 `CaseListView.vue` 中的筛选表单，使其更紧凑、易用，支持以下条件的复合查询：
* **工单号 (case_id)**：文本输入框，支持模糊检索。
* **客户端ID (client_id)**：文本输入框，支持模糊检索。
* **工单标题 (title)**：文本输入框，支持模糊检索。
* **状态 (status)**：下拉选择框（待确认、已确认、处理中、已解决、已关闭、已取消）。
* **创建时间范围 (created_at)**： Element Plus 日期范围选择器 (`el-date-picker` type="datetimerange")，精确到秒，映射为后端的 `start_time` 与 `end_time`。

### 2. 工单编辑功能 (Edit Case Dialog)
* **入口**：在数据表格的操作列中，新增 **“编辑”** 按钮（使用 Element Plus 精美文本按钮，带 `Edit` 图标）。
* **编辑弹窗 (`el-dialog`)**：
  * **标题**：`编辑工单 - {case_id}`
  * **表单内容**：
    1. **工单标题 (title)**：必填输入框 (`maxlength="200"`)。
    2. **工单描述 (description)**：多行文本输入框 (`textarea`，可自适应高度)。
    3. **工单状态 (status)**：下拉选择框，支持管理员手动流转工单状态（如强制处理中、已关闭等）。
    4. **优先级 (priority)**：下拉选择框（高 `high`、中 `medium`、低 `low`）。
    5. **工单分类 (category)**：文本框（支持修改 AI 分类识别的结果）。
    6. **AI助手类型 (assistant_type)**：下拉选择框（`htp-agent`、`ops-agent`、`triage-agent`）。
  * **交互与验证**：点击“保存”时发起 `PUT /api/cases/{case_id}` 请求，添加 `v-loading` 状态防重复点击，保存成功后浮现 `ElMessage.success` 并重新静默加载当前页数据。

## 🛠️ 技术架构与前后端契约 (Technical Architecture)

### 1. 后端数据结构更新 (`schemas.py`)
新增 `CaseUpdate` 架构，所有字段均为可选，便于增量更新：
```python
class CaseUpdate(BaseModel):
    """更新工单请求"""
    title: str | None = Field(None, max_length=200, description="工单标题")
    description: str | None = Field(None, description="工单描述")
    status: CaseStatus | None = Field(None, description="工单状态")
    priority: str | None = Field(None, description="优先级")
    category: str | None = Field(None, description="分类")
    assistant_type: str | None = Field(None, description="AI助手类型")
```

### 2. 后端 API 路由更新
* **搜索增强**：`GET /api/cases/all` 接口扩展查询参数：
  ```
  GET /api/cases/all?case_id=Q2026&client_id=client-&title=虚拟机&status=created&start_time=2026-05-20T00:00:00&end_time=2026-05-30T00:00:00
  ```
* **新增编辑端点**：`PUT /api/cases/{case_id}` 接收 `CaseUpdate` Payload，在 SQLAlchemy 事务内完成对象状态更新。
  * **状态机转换规则**：在 `update_status` 或 Repository 更新中，当 `status` 被改变且变更为 `closed` 时，自动同步计算 `closed_at = datetime.utcnow()`。

### 3. API Gateway Proxy 更新
在 `api-gateway/app/routes/cases.py` 中，增加 `PUT /api/cases/{case_id}` 的 Proxy 代理转发，保障微服务架构的网络边界一致性：
```python
@router.put("/{case_id}")
async def update_case(case_id: str, request: Request):
    """[Admin] 编辑工单"""
    payload = await request.json()
    response = await proxy_request("PUT", f"/{case_id}", payload)
    if response.status_code == 404:
        raise HTTPException(status_code=404, detail="Case not found")
    return JSONResponse(content=response.json(), status_code=response.status_code)
```
