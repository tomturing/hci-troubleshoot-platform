# 日志收集会话状态自愈与中继重试（需求）

## 背景

2026-10-28 现场 24 小时内 8 条日志收集任务失败，错误码全部为 LC-ENV-006（SSH 会话不存在），且集中在 P2 经平台中转路径。另有一批任务采集已在节点侧成功、仅中继上传失败，却被直接判 `delivery_status=failed`，已生成的压缩包无法自愈补传。

两类问题分别发生在「采集开始前」与「采集完成后」两端，核心采集链路本身没有缺陷。

## 现状事实

- 桥侧 `handleLogCollect` 在会话缺失时**秒级**返回 `session_missing`（`terminal_bridge/log_collect.go`），后端 `create_task` 不做任何会话校验——不存在多分钟等待，失败是即时的。
- 前端 `sshConnectionState` 依赖 SSH 终端连接上的 `ssh_disconnected` 事件置否；但日志收集面板使用独立 WS 连接，未必是会话属主，收不到该事件时状态陈旧，UI 仍显示「已连接」。
- 中继 `run()` 对任何异常一律写 `failed`；但 `_run` 已持久化 `upload_id`，分片续传能力本来就存在，只是没有被重试机制利用。

## 需求

1. SSH 未连接时，「开始收集」按钮必须禁用并显示明确文案（秒级视觉反馈），而不是点击后才弹 toast。
2. 面板收到桥侧权威判定 LC-ENV-006（会话不存在）时，必须立即把 `sshConnectionState` 置否，杜绝陈旧状态反复误发。
3. 中继对瞬时错误（网络超时/连接失败/5888 5xx）自动退避重试并复用 `upload_id` 续传；仅永久错误（无制品/空文件/4xx）或重试耗尽才落 `failed`。

约束：

- 置否动作只针对 LC-ENV-006；采集自身的失败（如磁盘不足、节点拒绝）不得误清 SSH 状态。
- 重试期间 `relay_status` 保持 `running`，交付状态不得落 `failed`；错误码保留异常原始分类，不得统一改写。
- 重试参数可配置（次数/退避基数/上限），向后兼容默认值。

## 验收

- SSH 断开时按钮置灰显示「请先连接 SSH」；点击守卫仍兜底拦截。
- 收到 LC-ENV-006 后 UI 立即变为未连接，重复点击被拦截，不再产生新的 LC-ENV-006。
- 中继瞬时失败后自动补传成功（`delivery_status=delivered`）；重试耗尽或永久错误仍落 `failed` 且错误码保留原始分类。
- 前端 vitest 与后端 pytest 回归全绿。
