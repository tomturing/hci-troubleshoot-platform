# 2026-11-18 日志收集场景语义与 S7 证据判定修复

## 背景与问题

工单 `Q2026110302166` 按 `#1542 / #1546` 现场重装新 exe 后复测，采集与 P1 直传成功（`acli log_collect progress` 显示 100%、日志服务器状态成功），但页面仍有两处与事实不符：

1. **收集场景**显示 `core文件`，而用户实际选的是自定义场景 `test`。
2. **S7 证据回传**显示 `失败`（挂 `LC-BRIDGE-005`），而证据其实已经回传成功。

## 现场取证

同一任务 `ea2ae126-84ba-45bd-a2d6-c3cbbb6a6f7b` 的时间线（UTC）：

| 时刻 | 事实 |
|---|---|
| 00:10:17 | 任务创建，`modules={core}`，`detail` 无场景字段 |
| 00:10:31.887 | `p1_archive_check` 落库（页面「归档已核验」） |
| 00:10:32.126 | 任务终态 `finished_at`，前端停止高频轮询 |
| 00:11:03.351 | `log_collect_artifact_manifest` 写入 1 行 + `detail.artifact_quality` 回写 |

证据比终态晚 **31 秒**。在线上镜像里用该任务行复算派生，去掉 `artifact_quality/artifact_reason/artifact_evidence` 后输出：

```
S7 = failed / LC-BRIDGE-005 / condition=artifact_uninspected
```

与截图逐字一致；保留证据字段后复算，S7 变为 `unknown`（仍不是成功）。

数据库侧同时确认：`log_collect_artifact_manifest` 的 1 行内容为 `quality=invalid, reason=unreadable, entry_count=0`，`evidence.reader="unzip -Z1 + zipinfo -t"`。

## 根因

### 场景显示

- 前端「收集场景」只读 `task.modules`（`LogCollectPanel.vue`）。
- 自定义场景（spc）下发时 acli 要求 `-m core`，平台把 `payload.modules` 覆写成 `["core"]`（`routes/log_collect.py`，槽位固定 core 是物理约束）。
- 用户选择的场景 ID 存在表列 `custom_scenario_id`，但展示层完全不用它，也没有名称快照。

### S7 证据回传

1. **时序竞态**：证据是 bridge 的异步动作，必然晚于任务终态；前端在终态后降频到 30s，页面很容易永久停在「证据未到」的那一帧。
2. **判定错误**：`derive` 在 `quality == "unknown" and delivered` 时直接判 `S7=failed` 并挂 `LC-BRIDGE-005`，与同文件注释「查不到证据的阶段一律 unknown，绝不把平台没数据当成失败」自相矛盾。
3. **结构缺陷**：客户侧 `_attach_display` 调 `build_display_payload(task)` 不传 `manifest`。证据表有行也不会参与派生，S7 在客户侧**永远**无法成功；刷新最多变成「未知」。
4. **物理约束**：节点侧读取依赖 shell `unzip -Z1` + `zipinfo -t`。HCI 宿主机是极简系统（`#1542` 已证明连 `base64` 都没有），且客户包全条目加密，`zipinfo -t` 对加密包必然非零退出。而 `assess_artifact` 的注释明确写着「禁止用 unzip -t 推导，加密包会误判损坏」——节点侧实现恰恰违反了这条。

## 历史修复为何未收敛（复盘）

| 轮次 | 改动 | 为何没解决 |
|---|---|---|
| #1517 | ingress 补 `/api/direct/log-collect/` | 只修「写不进去」的 404 |
| #1526 | SQL 参数 500、`samples` 422 | 仍是写侧 |
| #1521 | 管理端列表白名单 | 只影响管理端展示 |

三个结构性问题：

1. **验收指标错位**：一直用「证据表行数 > 0」当通过标准（写侧），而用户看的是页面 S7（读侧派生）。本次恰好证明写侧早已通。
2. **单测锁定了错误行为**：派生单测都显式传 `manifest`，路由真实调用形态（不传）从未被覆盖，且断言 S7=failed 的用例把错误行为钉成了契约。
3. **错误不可区分**：写不进去、读不出来、还没到，三种情况在页面都是同一个「失败 + LC-BRIDGE-005」，修完再看还是「失败」，于是继续在写侧加补丁。

## 功能需求

1. 场景展示必须表达「用户选了什么」：自定义场景显示场景名（创建时快照），`core` 只作为技术槽位事实，不出现在用户语义里。
2. S7 语义收敛为「证据有没有回传到平台」：证据写入即成功；包内容是否可读由产物质量单独表达。
3. 证据未到不得判失败：窗口内为等待、窗口外为未知；只有桥显式上报失败才判失败并归因。
4. 客户侧派生必须能读到「证据已回传」这一事实（detail 快照），不得因不查窄表而永远无法成功。
5. 节点侧读取包内容不得依赖 `unzip/zipinfo`；失败必须留下 exit code 与 stderr。

## 验收标准

- [ ] 自定义场景任务页面显示「<场景名>（自定义场景）」，不显示 core 文件。
- [ ] 证据已回传的任务 S7 显示成功，且与包内容是否可读无关。
- [ ] 交付终结后 2 分钟内、证据未到时 S7 显示等待中，不显示失败。
- [ ] 桥显式上报证据失败时 S7 显示失败并带 `LC-BRIDGE-005`。
- [ ] 加密包中央目录仍可读出条目数与加密标记。
- [ ] 前端单测、Go 全量测试、后端单测、docs 门禁全部通过。
