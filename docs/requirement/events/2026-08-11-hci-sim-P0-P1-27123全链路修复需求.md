# hci-sim P0–P1：KBD 27123 全链路与“开始测试”修复需求

## 1. 问题定义

用户在 Admin UI 点击“开始测试”没有状态变化、没有 HTTP 请求。根因不是浏览器：原实现的点击处理器只有 `expanded = ['true']`，它没有发起任何动作。

同时，Runtime 的 TestRun 接口返回 `sim-case-*`，该值不是 `case-service` 创建的真实工单，不能绑定 Agent、审计或工单详情。若继续沿用，页面显示成功也无法证明平台链路成立。

## 2. 第一性原理不变量

1. **可观察动作**：每个可点击动作必须产生可见状态迁移或结构化错误；不能用展开日志冒充开始测试。
2. **真实身份**：平台 Case ID 只能由 case-service 生成；Runtime 不得生成 `sim-case-*` 伪工单号。
3. **绑定不可变**：`case_id`、`test_run_id`、support ID、Runtime revision、Bundle digest、`execution_mode=sim-ssh` 必须在 `hci_sim.control_plane.run.environment_context` 中显式绑定；重试只能复用相同绑定，不能覆盖到另一个 Case。
4. **能力先于执行**：Admin UI 在 Build 前取得 Runtime capability；未加载 KBD、Bundle 缺失或未获授权时 fail closed，并展示结构化 `capability_gap`。
5. **凭据最小生命周期**：Lease 只存在于当前浏览器内存和一次 Bridge 连接，日志、localStorage、Case 描述和数据库禁止保存密码/Token。
6. **证据分层**：HTTP 200、Pod Ready、SSH handshake 和三条命令 exit=0 分别记录；不得把它们单独表述为 Agent 产品级结论。

## 3. 功能需求

### P0-1 Admin UI capability 预检

- 新增 `GET /api/hci-sim/v1/simulations/capabilities/{kbd_id}` Gateway 代理。
- 返回 `requested_revision`、`runtime_revision`、`bundle_digest`、`bundle_status`、`authority_scope`、`buildable`、`capability_gap`。
- `buildable=false` 时“环境构建”置灰，页面展示差距；构建错误必须展示响应 body 的 `detail`。
- dev KBD 27123 使用显式 `dev_golden` 范围时允许基本验证，同时展示主库 revision 与 Fixture revision 不一致，禁止宣称 production approved。

### P0-2 开始测试状态机

- Build 未成功前“开始测试”置灰。
- 点击后进入“创建仿真测试工单”步骤并聚焦标题；该点击必须有 DOM 状态变化。
- 失败重试保留 KBD、标题、描述、客户端 ID 和日志。

### P1-1 真实工单和 TestRun 绑定

- Gateway 的 TestRun 提交先调用 case-service 创建真实 Case，再把 `case_id` 注入 Runtime 请求和 environment context。
- Runtime 校验 `case_id` 与 connection/context/TestRun 一致；重复绑定同一 Case 幂等，不同 Case 冲突。
- Runtime Result 接口回写 `hci_sim` Run Result，报告 URI 必须是 `object://` 且摘要不可包含凭据。

### P1-2 KBD 27123 基本纵向验证

- Admin UI 使用 Build 返回的 Lease 连接同源 K3s terminal_bridge。
- Bridge 通过 `hci-sim.hci-sim-dev.svc:2222` 执行三个确定性 positive-realistic 关键信号命令：task、lsof、ps。
- 三条命令全部 exit=0 后回写 `passed` Result；任一失败都显示原始结构化错误并保持可重试。
- 该验证证明 Admin → Gateway → hci_sim → K3s Bridge → hci-sim SSH → Result；不把它扩展为 Agent/真实 HCI/生产 Bundle 结论。

## 4. 非目标和限制

- 本需求不把 KBD 27123 主库 active revision 24 伪装成当前 Fixture revision 1；要消除 gap 必须另行生成并审批 revision 24 immutable Bundle。
- 不开放 Admin UI 直接访问 Runtime，不绕过 NetworkPolicy，不启用真实 HCI 回退。
- 不在本 PR 承诺 23821 approved Bundle、126 KBD 全量、Agent 产品级 E2E、20 次稳定性或容量阶梯。

## 5. 验收退出标准

自动测试覆盖状态机、capability gap、真实 Case 注入和错误保留；现场可取得一条脱敏证据链：真实 `Q...` Case ID、`run-27123-*`、hci_sim context 的 case binding、Bridge `ssh.connected`/`exec.done`、三条 exit=0 和 `run_result.outcome=passed`。
