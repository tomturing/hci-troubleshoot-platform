# 日志收集：默认场景清单可编辑 + create 任务 ID 修复需求

## 变更历史

| 日期 | 版本 | 变更内容 | 关联事件文档 |
|------|------|---------|------------|
| 2026-11-11 | v1.0 | 初版：现场报错归因与新需求 | 本文 |

## 背景与问题

- 现场工单 Q2026110302155 在「自定义场景（spc 通道）」点「开始收集」后立刻失败，提示「缺少合法的任务 ID，无法确定备份归属」。平台任务实际已创建成功，节点探测、SSH 会话、磁盘、直传路径均正常。
- 平台已有 11 份随镜像发布的默认场景清单快照，管理端自定义场景编辑器也能定义日志与配置文件条目；但「默认场景」下这些清单只读，且从不参与下发，用户无法修改每个默认场景实际收集的日志、配置文件。

## 需求描述

1. 修复 create 消息缺失平台任务 ID 的契约缺口，使 spc 场景可正常下发；同时让建任务与下发共用唯一调用链，失败有规范错误码。
2. 让默认场景的每个场景（core / network / storage 等）都可以修改其默认收集的日志、配置文件清单，修改后对后续收集生效，且可恢复为平台快照默认。
3. 客户侧默认场景需能看到当前生效清单与「已自定义」标记；未做任何修改时，收集行为与现状完全一致。

## 功能需求

- 管理端按模块编辑清单条目（路径、动作、类别、备注、过滤条件），保存版本化并留审计；提供恢复默认。
- 客户侧默认场景展示已勾选模块的清单预览与自定义状态。
- 存在自定义清单时，按平台清单下发并复用既有的节点覆写、备份、终态还原能力；不改动桥梁可执行文件。
- create 消息携带平台任务 ID 与同一调用链 ID；`invalid_task_id` 有规范错误码。

## 非功能需求

- 可观测性：清单选择、覆写与还原均带唯一调用链，任务详情可回答「本次用了哪些模块清单、各自摘要」。
- 安全：路径白名单与条目上限沿用既有场景校验，不接受任意路径。
- 兼容性：未启用自定义清单时零行为变化；新旧桥梁混跑不得静默按错清单收集。

## 验收标准

- [ ] 自定义场景 create 消息含合法 `exec_id`，桥梁不再返回 `invalid_task_id`。
- [ ] 无自定义清单时，默认场景 create 消息不含 spc 载荷，行为与现状一致（回归用例覆盖）。
- [ ] 管理端可分别编辑 11 个默认场景清单，保存后版本递增、摘要更新、可恢复默认。
- [ ] 客户侧默认场景能看到已勾选模块的清单条目与自定义标记。
- [ ] 启用自定义清单后，节点清单被覆写、按任务隔离备份，终态还原；失败/取消同样还原。
- [ ] 全量单测、类型检查、构建、文档门禁与浏览器端到端验证通过。

## 约束条件

- 桥梁可执行文件不会自动更新，方案不得依赖现场重装桥梁。
- Python 环境用 uv，前端包管理用 pnpm。
- 新增管理端可达路由必须同步在网关逐条补代理。
- 数据库变更需同步声明式 schema 与迁移，且不得改动已执行迁移。

## 风险与假设

- 平台清单快照与节点 acli 内置清单可能随版本漂移；以平台快照为默认基线，用摘要对比显式标注，不猜测节点内容。
- 现有 spc 通道只覆写单一槽位，多模块清单需合并为一份下发；产物内按分组保留场景边界。
