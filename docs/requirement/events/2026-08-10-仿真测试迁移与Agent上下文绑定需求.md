# 仿真测试迁移与 Agent 上下文绑定需求

## 1. 背景

当前“仿真租约”入口位于 Custom UI，并且只建立 `terminal-only` SSH 会话。它无法完成完整 Agent E2E 的关键前置条件：仿真 TestRun 未显式绑定到工单和 Agent 环境上下文，导致 KBD scope 为 `UNKNOWN`，Agent 不执行任何 Signal。当前入口还把 Runtime/Bridge 烟测和 Agent KBD 诊断混为一体，难以判断失败层级。

本需求将仿真能力从面向客户的 Custom UI 迁移到面向内部人员的 Admin UI，重命名为“仿真测试”，并在一个页面中完成环境构建、TestRun 创建、工单创建、Agent 验证和证据查看。

## 2. 产品目标

### 目标流程

```text
Admin UI 左侧「仿真测试」
  → 输入 KBD_ID
  → 环境构建
  → 展示构建进度/可展开日志
  → 构建成功后「开始测试」可用
  → 自动弹出创建工单窗口
  → 用户补充标题/描述
  → 点击「连接 SSH 并创建工单」
  → Admin UI → K3s terminal_bridge → K3s hci-sim
  → TestRun context 绑定 Agent
  → Agent 执行完整 KBD Signal 并返回验证结果
```

### 迁移要求

1. 产品名称由“仿真租约”统一更名为“仿真测试”；API/数据库内部兼容字段可在迁移期保留，但不得继续作为用户可见名称。
2. Custom UI 删除仿真入口、Lease 表单、connection.json 解析、推荐命令提示和仿真连接逻辑，恢复到引入仿真租约 PR 之前的客户侧代码语义。
3. Admin UI 左侧栏新增“仿真测试”，页面包含“环境构建”和“开始测试”两个核心按钮。
4. KBD_ID 只能输入合法数字；环境构建必须针对指定 KBD 解析当前 published revision、Capability、Fixture 和 Bundle。
5. 构建进行中“开始测试”必须置灰；只有构建成功且 TestRun/Bundle/Lease 均处于可运行状态时才可点击。
6. 构建日志按事件流展示，支持展开、折叠、关闭、复制非敏感摘要；Lease password/HMAC key/私钥不得出现在页面日志或浏览器持久化中。
7. 点击“开始测试”自动打开创建工单页面，沿用 SSH 连接和环境采集表单，但仿真连接字段由 TestRun 自动注入，用户只需补充标题、描述并点击“连接 SSH 并创建工单”。
8. Admin UI 只能连接 K3s terminal_bridge；不得依赖 Custom UI、本地 Windows terminal_bridge 或真实 HCI。
9. TestRun 必须在 Agent 调用前显式绑定 `case_id/conversation_id/support_id/kbd_revision/scenario_id/bundle_digest/scope_context`。
10. KBD 23821 必须补齐完整 Fixture Bundle，至少覆盖 `sig_001 qkv_task`、`sig_002 qfk_log` 和专家 `qfk_system` Signal 的成功/失败/边界结果。
11. 仿真 TestRun 的证据必须标记 `simulation=true`、`execution_mode=sim-ssh`，不得计入真实 HCI 成功率或客户生产审计。

## 3. 状态与幂等需求

环境构建状态至少包括：

```text
idle → validating → building → ready
                     ├→ failed
                     └→ cancelled
ready → expired
```

TestRun 状态至少包括：

```text
created → lease_issued → case_binding → running
                                ├→ passed
                                ├→ inconclusive
                                ├→ failed
                                └→ expired
```

要求：

- 同一 KBD、同一构建请求幂等，不重复创建活动 Bundle；
- “开始测试”重复点击不得创建多个工单或多个活动 Lease；
- 浏览器刷新后可恢复最近一次构建状态和非敏感日志；
- 构建失败重试保留 KBD_ID 和日志，重新开始测试前必须使用新 Lease；
- Lease 过期、Bundle stale 或 KBD revision 变化时自动阻止开始测试。

## 4. 权限与安全需求

- 仅具备 Admin 仿真测试权限的管理员可构建或运行 TestRun；
- 仿真日志默认只对管理员可见；
- 标题和描述可以进入工单，但 Lease 明文、内部 token 和 fixture 原始敏感 Artifact 不得进入对话历史；
- Admin UI 不能调用任意 shell；命令只能来自已发布 KBD/Bundle；
- 构建 API、日志 API、开始测试 API 必须校验管理员身份、CSRF/Origin 和幂等键；
- TestRun 只能绑定一个明确 execution mode，不允许从 sim-ssh 回退真实 SSH。

## 5. 非功能需求

- 页面打开后 2 秒内显示当前构建列表或空状态；
- 构建进度事件至少每 5 秒有心跳或阶段变化；
- 日志大于页面预算时服务端分页/游标化，前端不得一次性渲染无限输出；
- 构建、运行、命令、结论均有同一 `test_run_id/trace_id/exec_id` 可追踪；
- 失败必须显示阶段、错误码、重试建议和是否可重试，而不是只显示“SSH 失败”。

## 6. 不在本需求范围

- 不让普通 Customer 用户看到仿真测试入口；
- 不在 Custom UI 保留兼容的“仿真租约”按钮；
- 不把仿真测试直接改造成真实 HCI 测试；
- 不在本需求内解决 hci_sim 数据库所有历史表的最终删除；数据库隔离由第二组独立完成，但本组必须预留独立控制面接口；
- 不以一条 `recommended_command` 的手工执行结果代替完整 Agent KBD 结论。

## 7. 验收门槛

- Custom UI 构建产物中不存在“仿真租约”入口和仿真连接逻辑；
- Admin UI 左侧栏存在“仿真测试”，页面可完成环境构建→开始测试→创建工单；
- 构建未成功前“开始测试”不可点击，失败日志可展开/关闭；
- KBD 23821 的 TestRun context 在 Agent 开始前可查询，scope 不再因缺失环境而 UNKNOWN；
- Admin UI 到 K3s terminal_bridge 到 K3s hci-sim 的完整链路可验证；
- 23821 完整 Fixture 三条必需 Signal 的结果与结论一致；
- 无 Windows Bridge、无 Custom UI、无真实 HCI 依赖时仍可完成验收。
