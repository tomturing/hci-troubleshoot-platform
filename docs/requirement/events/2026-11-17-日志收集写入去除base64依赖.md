# 2026-11-17 日志收集写入去除 base64 依赖

## 背景与问题

工单 `Q2026110302166` 复测自定义场景时，失败码从 `LC-SPC-001`（目录缺失）→ `LC-SPC-003`（备份失败）→ 最终停在 `LC-SPC-004`「场景清单写入或校验失败」。数据库 `log_collect.spc_fanout_failed` 显示 `error_type=write_rejected`，但 `error_detail` 只有「槽位 core：write_rejected」，真实原因被丢弃。

现场证据（172.28.25.2）：

```
# 宿主机（bridge SSH 登录的 asv-controller，-bash）
$ printf 'aGVsbG8K' | base64 -d
-bash: base64: command not found
base64_d_exit=127

# 容器内（container_exec -n asv-c）
$ printf 'aGVsbG8K' | base64 -d
hello
base64_d_exit=0
```

即：**base64 只存在于容器内，宿主机没有**。而 bridge 通过 SSH 登录宿主机执行 `printf '%s' <base64> | base64 -d > core.json`，必然 exit 127 → `write_rejected`。这也解释了「备份成功（cp/ls/mkdir 都在）、写入失败（唯独 base64 不在）」。

同一缺陷也存在于 `-c` 配置通道：`writeLogCollectConfig` 写入与降级回读都用 `base64`，在宿主机同样无法工作。

## 功能需求

1. spc 写入不再依赖 `base64`，改用宿主机必定存在的 shell 内建命令。
2. spc 写入后仍能证明"写下去的就是平台签发内容"（回读校验不能退化成跳过）。
3. `-c` 配置通道的写入与校验同步去除 `base64` 依赖。
4. 写入/备份失败时，把 stderr 并入 `error_detail`，不再只剩一个 `write_rejected`。

## 非功能需求

- 写入内容不得改变字节（不能因换行导致与 `spc_sha256` 不一致）。
- 兼容 HCI 极简宿主机：只依赖 `printf`（shell 内建）、`cat`、`cp`、`cmp`、`mkdir`。

## 验收标准

- [ ] `buildSpcWriteCommand` 生成的命令不包含 `base64`，且写入字节与原始内容一致。
- [ ] `-c` 配置写入与校验不包含 `base64`。
- [ ] 写入失败时 `error_detail` 包含真实 stderr（如 `command not found` / `Permission denied`）。
- [ ] Go 全量测试、gofmt、docs 门禁通过。
