# WeKnora 知识库集成需求

## 目标

在 admin-ui 中内嵌 [Tencent/WeKnora](https://github.com/Tencent/WeKnora)（MIT，v0.9.0），
提供两个入口：

1. **知识问答**：基于已上传文档的 RAG 问答（带引用），访客免登录；
2. **知识库管理**：WeKnora 完整控制台，用于建库、传文档、配模型与渠道。

实现方式与服务部署**参照 DSH 诊断工作台的既有模式**：独立 Helm chart、独立命名空间、
独立 ArgoCD Application、网关代持凭据、前端 iframe 内嵌。

## 硬性约束

| 约束 | 来源 | 影响 |
| --- | --- | --- |
| 平台对外只有 `https://acli.sangfor.com.cn:4443` 一个可用 origin | 现场 DNS/网关实测 | 不能给 WeKnora 开子域或新端口 |
| WeKnora 前端默认以站点根部署，API 走同源 `/api/v1` | 上游仓库的 vite 配置与 api-base 模块 | 与本平台 `/api/` 冲突，必须做前缀构建 |
| 集群节点无法直连 Docker Hub 第三方 namespace | kubelet 实测 403 | 上游镜像必须先同步到私有 registry |
| 无 embedding 模型无法建索引 | 上游 RAG 流水线设计 | 必须同时配置 LLM 与 Embedding |
| WeKnora 自带账号体系 | 上游 `internal/handler/auth.go` | 平台 JWT 不能透传，管理台需单独登录 |

## 验收标准

- [ ] `/weknora/` 可在 admin-ui iframe 内打开，管理台可完成登录与建库；
- [ ] 知识问答入口无需 WeKnora 账号即可提问，且回答带文档引用；
- [ ] 浏览器地址栏与 iframe 内始终是平台域名，不暴露集群 Service 地址；
- [ ] 长期 embed 发布令牌不出现在浏览器、接口响应或日志中；
- [ ] 未创建渠道时页面给出"尚未创建问答渠道"的明确指引，而不是报错；
- [ ] 部署、升级、回退步骤可在 `weknora/README.md` 内闭环。
