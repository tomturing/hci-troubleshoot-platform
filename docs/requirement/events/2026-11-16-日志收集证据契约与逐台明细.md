# 需求：日志收集证据契约与逐台明细（2026-11-16）

## 背景与问题

管理端详情可读性改造上线后，用户继续反馈三类数据缺失：

1. 逐台明细对所有工单都为空。实测 452 个任务在 `detail.spc_hosts` 与 `spc_hosts` 列中均为 0 行；该字段语义为「自定义场景写入回执」，没有任何代码把采集逐台输出写进去。
2. S7 仍失败。新工单 Q2026111601055（晚于 #1517 ingress 修复）中传输 279 条、进程日志 2 条正常入库，但 `network-probe` 返回 422、`artifact-manifest` 返回 500。
3. 网络探测为空，根因与第 2 点的 422 相同。

## 功能需求

1. 桥端在采集完成时，把 acli 进度原文里已解析的逐台主机（IP/状态/百分比）结构化上报；管理端「逐台明细」只展示这份事实，缺证据时明确说明「需新版本 terminal_bridge 重新采集」。
2. 修复 `artifact-manifest` 端点的 SQL 绑定语法，使包内容清单可正常落库，S7 能按真实证据判定。
3. 让 `network-probe` 契约与桥端实际发送的整型 RTT 样本对齐，消除 422。
4. 存量工单不做数据伪造；修复后需新采集才能产生新证据。

## 验收标准

- [x] 桥端测试证明逐台明细按任务去重、过滤空 IP，且不伪造百分比。
- [x] 后端单测证明整型 samples 被接受、SQL 不再出现 `:param::jsonb`。
- [x] 管理端只读端点从桥日志回读逐台明细，无证据返回空列表。
- [x] 前端单测与真浏览器验证逐台明细展示与空态说明。
- [x] 文档、三层事件文档与现行文档同步更新。

## 约束

- 不改 `status`/`conclusion`/五桶统计口径。
- 逐台明细只来自节点自报，不由平台推断。
- bridge 变更需要重建 exe 并由现场重新安装；平台侧修复随镜像部署。
