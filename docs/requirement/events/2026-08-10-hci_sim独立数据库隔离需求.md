# hci_sim 独立数据库隔离需求

## 1. 背景与问题

当前 `hci_troubleshoot` 主业务库中混入 `agent_test_*`、fixture、artifact、TestRun、runtime 和 bridge execution 等 hci-sim 控制面表。主业务库因此同时承担客户业务、知识库和仿真测试控制面职责，形成数据污染、权限越界、迁移耦合、备份膨胀和生命周期混乱。

本需求把 hci-sim 控制面完整迁移到独立 PostgreSQL database `hci_sim`，并要求新建仿真测试不再向 `hci_troubleshoot` 写入 hci-sim 表。

## 2. 目标与原则

### 目标

- 创建独立数据库 `hci_sim`；
- 使用独立角色、Secret、连接池、migration history 和备份策略；
- 明确 hci-sim 表的 ownership、schema、权限和生命周期；
- 以可回滚方式迁移既有数据；
- 迁移完成后主库不再产生 hci-sim 表的新写入；
- 任何 hci-sim 数据库不可用都应明确阻断仿真测试，不得回退写入主库。

### 不变量

```text
hci-sim runtime 只能使用 HCI_SIM_DATABASE_URL
hci_troubleshoot 账号不能成为 hci-sim 的默认写入账号
hci-sim migration 不得由主库 migration job 执行
跨数据库不得使用隐式外键
迁移失败不能丢失源数据或破坏主业务
```

## 3. 初步表边界

### 归入 hci_sim 的表

```text
agent_test_scenario
agent_test_fixture_bundle
agent_test_fixture_dependency
agent_test_fixture_provenance
agent_test_fixture_approval
agent_test_fixture_audit
agent_test_run
agent_test_run_attempt
agent_test_run_event
agent_test_run_result
agent_test_runtime_instance
agent_test_artifact
agent_test_artifact_scan
agent_test_artifact_approval
agent_test_fixture_stale_outbox
```

### 需要引用审查后决定的表

```text
bridge_execution_artifacts
bridge_execution_logs
```

如果只服务于 hci-sim，迁移到 `hci_sim.execution`；如果平台真实诊断也使用，必须拆分 ownership 或建立独立域，禁止整表盲迁。

### 保留在 hci_troubleshoot 的业务表

```text
case
conversation
customer
environment
diagnostic_item
fact
kb_*
认证/授权表
平台通用审计表
```

最终归属必须同时依据创建者、生命周期和 hci-sim 卸载后的保留要求确认，不能仅按表名前缀决定。

## 4. 功能需求

1. 提供 `hci_sim` 数据库及独立 owner/admin/runtime 角色。
2. hci-sim 服务、编译器、调度器和测试控制面必须读取独立 Secret，不得读取平台 `DATABASE_URL`。
3. 主平台 db-migrate 不得执行 hci-sim migration；hci-sim 必须拥有独立 migration job/history/schema。
4. hci-sim 控制面表必须有清晰命名、schema 分类、索引、唯一约束、序列和审计字段。
5. 必须保留 `support_id/kbd_revision/bundle_digest/test_run_id/scenario_id` 等跨服务关联标识，但不在主库创建跨数据库外键。
6. 数据迁移必须支持 dry-run、备份、校验、切换、观察、冻结和回滚，禁止直接 DROP。
7. 切换后 hci-sim runtime 写入 `hci_sim`；主库对应旧表在观察窗口内不得出现新写入。
8. 主平台账号对 `hci_sim` 默认无权访问；hci-sim runtime 对主库默认无权访问。
9. hci_sim 的备份/恢复、容量、保留、告警和审计必须独立可查询。
10. hci_sim 不可用时，Admin “仿真测试”页面显示可定位错误，不得悄悄降级到主库或真实 HCI。

## 5. 非功能需求

- 数据迁移可重复、幂等、可观测；
- RPO/RTO、保留周期和容量上限可配置；
- runtime 使用最小权限，admin migration 使用独立短期凭据；
- 备份必须能实际恢复到隔离数据库并通过校验；
- 不把 Lease password、HMAC key、原始客户 Artifact 和完整命令输出写入控制面表；
- hci_sim 的 SQL、migration、连接配置和权限变更必须有独立 CI gate。

## 6. 不在本需求范围

- 不迁移平台核心业务表；
- 不把两个数据库合并到一个 PostgreSQL schema 伪装成隔离；
- 不在没有表 inventory 和依赖图的情况下执行生产迁移；
- 不在同一个变更中删除旧表和切换应用；
- 不以“创建数据库成功”替代数据一致性、权限和恢复验收。

## 7. 验收门槛

- inventory 清单、所有权判定和引用关系有审查记录；
- 新数据库、角色、Secret、migration 和备份均可用；
- 迁移前后行数、主键、外键、索引、约束、序列和摘要校验通过；
- 新建 TestRun/Bundle/Artifact 只写入 `hci_sim`；
- 主库旧 hci-sim 表无新写入并经过观察窗口；
- 断开 hci_sim 后仿真测试 fail-closed，主平台真实工单不受影响；
- 回滚后 TestRun 可恢复到旧连接，且没有双写或数据分叉。
