# 2026-11-17 日志收集跨集群目标残留与回滚假告警

## 背景与问题

工单 `Q2026110302166` 复测时报 `LC-SPC-007`（目标节点 SSH 认证失败），失败节点是 `172.28.25.2`。但现场实际 SSH 连接的是 `172.28.24.1`（24.x 集群），前端"目标主机"列表也只有 `172.28.24.3 / 24.2 / 24.4`，用户只勾选了 `172.28.24.2`。

日志显示前端提交的是：

```
log_collect.start: {"ips": "172.28.25.2,172.28.24.2", ...}
```

即 24.x 与 25.x 是两个独立集群，而 25.x 集群的旧选择被带入了 24.x 会话。

第二个问题：失败后提示"回滚失败 1 台，这些节点可能残留平台清单（重试前须人工核对）"，但失败节点 `written=false`——它从未写入成功，根本不存在残留，属假告警。

## 第一性原理

1. 目标主机选择必须与会话所属集群一致。切换 SSH 会话等于换了集群，旧集群的节点清单与已选 IP 不再有意义，必须作废。
2. 回滚的语义是"撤销已完成的写入"。从未写入的节点不需要回滚，也不应被计入回滚失败。

## 功能需求

1. 切换 SSH 会话（集群）时，清空旧节点清单，目标主机重置为 `all`。
2. 写入失败回滚时，只回滚 `written=true` 的主机；`written=false` 的节点不参与回滚、不计入 `restore_failed`。
3. 正常生命周期恢复（平台显式 restore、任务恢复）行为不变。

## 验收标准

- [x] 从 25.x 集群切到 24.x 集群后，提交的 `ips` 不包含任何 25.x 地址。
- [x] 写入失败且存在未写入节点时，不出现"可能残留平台清单"提示。
- [x] 已写入节点回滚失败时，仍正确提示。
- [x] 前端单测、Go 全量测试、gofmt、docs 门禁通过。
- [ ] 现场重装 bridge exe 后复测 `Q2026110302166`（bridge 改动不自动到达客户机）。
