# hci-sim 三段验收链路稳定性需求

## 背景

C3 验收的事实链路是：

```text
Custom UI → terminal_bridge → hci-sim → synthetic RouteKey
```

此前脚本可以生成 Lease，但没有保证“生成的 Lease 一定对应正在监听的 Runtime”，且远端 Windows Bridge 与 Linux hci-sim 的 host key 生命周期不一致，导致端口冲突、Lease 错配、主机指纹漂移和过期凭据都被前端压缩成“SSH 握手失败”。

## 必须满足的需求

1. 同一 KBD 的验收入口最多存在一个活动 hci-sim 实例；新 Lease 不得连接旧实例。
2. 生成 Bundle/Lease 前必须预检 SSH/HTTP 端口；端口冲突要在签发 Lease 前失败。dev 多实例时默认端口被占用应自动选择隔离端口，并把最终端口写入 Lease；CI 可通过开关要求冲突直接失败。
3. Runtime 未在规定窗口内通过 `readyz` 时，脚本必须非零退出并输出容器状态/日志。
4. dev 验收的同一 `<host>:<port>` 重跑不得因为每次生成新 host key 触发 Bridge 指纹漂移。
5. `connection.json` 必须包含 `issued_at/expires_at/ttl_seconds`，操作者能判断 Lease 是否仍有效。
6. Lease password、HMAC key 和完整连接 JSON 不得进入终端普通输出、应用日志或验收报告。
7. 无工单的 Custom UI 初始状态必须有直接进入仿真租约的 dev 入口；不得要求先创建无 SSH 工单。连接弹窗应支持粘贴完整 `connection.json`，自动填充字段并显示推荐命令。
10. 切换到“仿真租约”时，表单默认值必须使用 hci-sim 的 `host/2222/sim` 语义；连接失败重试不得覆盖用户本轮已填写的连接信息。
8. Linux Bridge 链路必须能通过真实 WebSocket 协议验收，不得以 Paramiko 直连替代 Bridge 证据。
9. 必须明确 Windows 桌面 Bridge 与 Linux Bridge 的浏览器拓扑，禁止让远端浏览器把 `localhost` 误解析成错误的 Bridge。

## 验收边界

本需求只覆盖 dev synthetic signal-contract-only；不把 synthetic 结果表述为真实 HCI Artifact 或生产 E2E。
