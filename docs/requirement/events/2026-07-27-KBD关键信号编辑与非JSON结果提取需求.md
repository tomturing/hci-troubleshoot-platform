## 背景

关键信号先由 AI 从 KBD 自然语言中抽取，再由运营人员在管理台审核、修正、发布。当前 AI 抽取结果中相当一部分不能直接执行，因此“简单、易懂、好用”和“保存后真实可执行”比配置能力的理论完备性更重要。

本轮需求源自 KBD 27123 与真实工单 `Q2026072630367`：QKV 能从任务日志得到 VM、HOST、STATUS，但 HOST 初值是节点名 `SVR_aCloud_668` 而非 terminal bridge 可路由的 IP；后续进程检查原始命令又依赖 `grep | awk` 从 `ps auxf` 的行列文本中取 PID。平台出于安全原因不能开放任意 Shell 管道。

## 已暴露的问题

1. 给 KBD 27123 的 `qkv_task` 增加 `END` 产出变量时曾出现“保存失败，请重试”；保存链路需要返回准确的 422/500 原因，不能只给统一提示。
2. QKV 结果里的 `host=SVR_aCloud_668` 不能直接用于后续 QFK 路由，必须通过 `acli --formatter json platform node list` 按 name/hostname/id 转换为 IP。
3. 后端信号需要在“关键字判定”和“产出变量”之间二选一；产出变量应写入同一变量池，供后续信号用 `{{VAR}}` 引用。
4. `qfk_system.container=host` 必须表示直接在宿主机执行，不能进入任何容器。
5. 1–300 秒超时时间必须从管理端一路透传至 terminal bridge，并在超时后真正停止独立 SSH session。
6. QFK 从“关键字判定”切换到“产出变量”时不能灰屏；字段命名、顺序和互斥展示需符合人工审核心智模型。
7. `resource_keyword` 对 qfk_system 实际只是一个经安全引用后追加的单一命令参数，不是结果匹配词，也不能表达多参数或管道。
8. JSON 输出继续用 `path`；非 JSON 行列文本需要一个不开放 Shell、但能覆盖高频 grep/awk 用法的简单方案。
9. 展示层的 4000 字符截断不能影响产出变量提取；提取必须使用完整 stdout，缓存丢失时不得从摘要猜值。

## 用户故事

作为 KBD 审核人员，我希望把：

```bash
acli system ps auxf \
  | grep -e '-id 8243094091404' \
  | grep -v grep \
  | awk '{print $2}'
```

配置为少量直观字段：

- 执行命令：`ps auxf`
- 筛选行（包含）：`-id {{VM}}`
- 提取值：第 2 列
- 变量名：`KVM_PID`
- 变量类型：整数

宿主机只执行 `acli system ps auxf`，平台在内存中筛选与取列；因为没有启动 grep 进程，`grep -v grep` 应自动删除。

## 范围

### 第一阶段支持

- JSON：现有点路径及 `|` 候选路径。
- 文本：包含/不包含、AND/OR、区分大小写、整行/第 N 列/从第 N 列到末尾、连续空白或单字符分隔、唯一/首行/末行/全部、stdout/stderr、基础类型转换。
- 安全转换：grep 常见字面量子集、`awk '{print $N}'`、`cut -dX -fN`。
- 输入变量：从 args 与文本筛选条件中的 `{{VAR}}` 自动推导并只读展示。

### 明确不支持

- 任意 Shell、sed、完整 awk 语言、排序、分组、聚合、跨行计算。
- 无法无损解释的 grep 正则或未知管道。
- 依靠 LLM 从截断数据猜测变量值。

复杂场景应增加专用 acquirer，而不是把管理台逐步扩展成受限 Shell IDE。

## 验收标准

1. 真实 `ps auxf` 样例可稳定提取整数 PID，且宿主机命令不含管道。
2. `path` 与 `extract` 互斥；QKV 禁止文本 extract；旧 JSON path 配置继续有效。
3. stdout/stderr 物理分离；完整输出缓存缺失、零匹配、多匹配、列越界、类型转换失败均返回稳定错误码并停止后续依赖。
4. 管理端能一键预览并应用安全管道转换，不能识别时显示明确原因。
5. AI Prompt 与确定性转换器同时生效，不能只依赖 Prompt 遵循。
6. 前端构建、Schema 契约、Agent/Kb-service 单测和真实样例验证全部通过。
