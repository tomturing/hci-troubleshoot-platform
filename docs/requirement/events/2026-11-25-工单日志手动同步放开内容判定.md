# 工单日志手动同步放开内容判定

## 背景与问题

管理端"工单日志同步"面板提供手动同步按钮。当前自动与手动共用同一套下载前内容判定：归档条目命中 `vmdumpcore`、`.dump` 等转储特征且条目数较少时，直接判 `non-log-payload` 并停止自动重试。

现场诉求是 `sp_<宿主机IP>/vmdumpcore` 这类采集包需要同步下来分析；工单 `Q2026112500553` 的包内只有 `1125.dump`，也被同一规则拦住，无法手动同步解压。

## 需求描述

- 自动同步：逻辑完全不变，继续按现有规则跳过转储包、写终态、停止自动重试。
- 手动同步：完全放开内容判定。用户点击按钮即视为**用户已经判断过该同步、该解压**，程序不再判断包里是不是日志。
- 判断权归属：由人决定，不由程序决定。

## 功能需求

1. 手动任务不得因归档内容被判定为转储而跳过、失败或转终态。
2. 手动任务不得为内容判定额外发起远端列目录请求。
3. 手动任务成功后不再展示"可能仅含转储文件"的提示；内容事实仍写入元数据供容量淘汰使用。
4. 自动任务的判定、终态、提示与日志保持原样。

## 非功能需求与边界

- 磁盘水位、归档密码、归档损坏/体积/层级超限等物理与资源约束**不在放开范围内**。
- 同工单串行、手动绕过并发闸门的行为不变。
- 请求链路日志保持唯一 `request_id` 可追踪。

## 验收标准

- [ ] 自动任务遇到纯转储包仍为 `failed / non-log-payload`，且不再自动重试。
- [ ] 手动任务遇到纯转储包为 `ready`，归档被下载并解压，无 `non-log-payload` 错误码。
- [ ] 手动路径不调用远端列目录探测。
- [ ] 手动同步成功的任务消息不含"可能仅含转储文件"。
- [ ] 磁盘余量不足时，手动同步仍被水位闸门拒绝。
- [ ] 用 `Q2026112500553` 在页面手动同步后可得到解压产物。

## 存量策略

已有 11 个 `non-log-payload` 终态工单**不批量修改**，需要分析的由人在页面逐单点手动同步；手动通道本就不受终态限制。
