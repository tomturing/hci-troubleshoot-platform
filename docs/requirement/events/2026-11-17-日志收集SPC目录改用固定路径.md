# 2026-11-17 日志收集 SPC 目录改用固定路径

## 背景与问题

工单 `Q2026110302155` 的自定义场景验证从 2026-11-12 起反复失败，截至本次已累计 6 次 `spc_fanout_failed`（11-12×2、11-13×2、11-14、11-17）。现场 `LC-SPC-001`「场景清单目录缺失」的错误详情显示：`find /sf/data/local -maxdepth 10 -type d -name spc -path '*support_bundle_cluster*'` 在节点 172.28.24.2 上实际找到了**两个** spc 目录且退出码为 1：

- `/sf/data/local/aDeploy/aDeploy/atools/log/support_bundle_cluster/spc`
- `/sf/data/local/acli/plugins/log_collect/tools/lmt_collect_info/support_bundle_cluster/spc`

代码先判 `err != nil` 直接归成"目录缺失"，完全不解析 stdout；即使修好退出码，`spcResolveDir` 对两个候选返回"目录不唯一"仍拒绝下发；`written=0` 时回滚重探测再次失败，追加"回滚失败 1 台，可能残留平台清单"的假告警。

## 需求确认（第一性原理）

现场已确认两条事实，作为本需求的硬约束：

1. 节点上同时存在这两个目录是**正常现象**，不是异常。
2. 整个日志收集功能**只使用** `/sf/data/local/acli/plugins/log_collect/tools/lmt_collect_info/support_bundle_cluster/spc`，其他目录不关心；可以直接使用该固定路径，不需要 find 探测。

这条约束把问题从"如何可靠地探测目录"降级为"平台自己部署的固定路径，直接用"——从根上消除目录探测层。

## 功能需求

1. 移除目录动态探测（find），写入前直接使用固定路径。
2. 目录真实不存在时仍给出 `LC-SPC-001`，提示语义改为"固定路径不存在"而非"探测不到/不唯一"。
3. 回滚路径同样使用固定路径，不再重探测，消除假告警。
4. 补齐回归用例：节点上存在多个 spc 目录时仍固定使用指定路径。

## 验收标准

- [ ] 写入前不再执行 `find`，直接使用固定路径。
- [ ] 存在 2 个 spc 目录时，`spcResolveDir`/等价逻辑返回固定路径且无歧义错误。
- [ ] 目录真实不存在时仍返回 `spc_dir_missing`（`LC-SPC-001`）。
- [ ] 回滚探测的 find 被移除，不再产生"回滚失败/可能残留平台清单"假告警。
- [ ] Go 全量测试与 gofmt 通过，docs 门禁通过。
