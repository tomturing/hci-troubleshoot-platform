# QFK 历史管道分步修复可用性需求

## 背景

QFK 现在严格禁止保存 Shell 管道，但已发布的旧 KBD 可能同时存在多条含 `|` 的信号。KBD 27123（当前环境的内部 `kbd_entry.id=1`）就有以下两条历史命令：

```text
sig_002: lsof | grep {{VM}}
sig_003: ps auxf | grep
```

旧页面每次点击一条“保存”都会将整份 `signals_json` 发给后端。当审核人员已安全转换 `sig_002` 时，后端仍会因未编辑的 `sig_003` 包含管道而拒绝整段保存；反过来也无法先保存 `sig_003`，因为 `sig_002` 的转换只在单条草稿中。

## 需求

1. 同一 KBD 中的多条信号必须可以在一个审核会话中依次修改和暂存。
2. 如果仍有任何 QFK command 包含 `|`，页面必须在发起 PATCH 前指出确切的第几条、`sig_*` 和信号说明。
3. 所有暂存修改只能在整份 v2 契约通过后一次性写入。
4. 不开放任何“历史管道可继续保存”的后端兼容后门，不自动猜测或改写无法无损转换的命令。

## 验收标准

1. 修改 `sig_002` 并切换到 `sig_003` 时，`sig_002` 的安全转换结果不丢失。
2. 保存时如仍存在 `sig_003` 的管道，提示必须包含 `第 3 条 sig_003`，而不是笼统的后端契约错误。
3. 将 `sig_003` 改为不含管道的基础命令后，两条修改在一次 PATCH 中成功保存。
4. 服务端仍然拒绝任何新增或遗留 `|` 的 QFK command。
