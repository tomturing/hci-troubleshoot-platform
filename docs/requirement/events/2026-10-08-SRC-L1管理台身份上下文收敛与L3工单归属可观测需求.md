## 一、背景

网关身份重签（B1）与 PR-D 强制认证闭环后，SRC 残留项 L1、L3 仍未落地：

1. **L1（管理台身份上下文静态注入）**：`frontend/admin/nginx.conf` 对 `/api/` 仍
   `proxy_set_header X-Tenant-ID "${ADMIN_API_TENANT_ID}"` 与
   `X-Actor-ID "${ADMIN_API_ACTOR_ID}"` 静态注入，取值来自 helm
   `diagnosisService.internalIdentity.*`（如 `hci-platform` / `admin-ui`）。
   经代码核对，这两头**仅 diagnosis-service 消费**，且 api-gateway
   `routes/diagnosis.py::_resigned_upstream_headers` 在管理台已登录（admin JWT，
   `realm=admin`）分支**已从 JWT 派生并覆盖**为 `AUTH_DEFAULT_TENANT_ID` +
   `sub(user_id)`；因此静态注入值对合法流量早已是"死配置"，仅在共享令牌后门
   （`AUTHN_ENFORCE_ADMIN=false` 回退）路径下才会被下游审计读取，等于把"能访问
   Admin UI 入口"写死成某个租户/操作者身份，审计归属失真且阻碍未来多租户。
   `identity-resign.md §6` 明确"静态注入的收敛留待 PR-D/L4"。
   **陷阱**：`frontend/admin/Dockerfile` 把这两个变量的 envsubst 默认值设为
   `$http_x_tenant_id` / `$http_x_actor_id`（透传客户端头）。若只删 helm 注入而
   不删 nginx 引用与默认值，nginx 会回退为**透传客户端可伪造头**——比静态注入更糟。

2. **L3（历史匿名工单归属）**：`create_case` 已由 #1111 改为 `require_user` 并以
   网关签发的 `client_id` 覆盖归属，新工单不再匿名。需登库核验 staging 是否存在
   空/占位/无归属的历史工单，并把"归属完整性"固化为**可复跑、非破坏性**的审计，
   防止回退（对齐团队"所有模块必须可观测性设计"约束）。

## 二、第一性原理拆解（硬性约束）

- 身份的唯一可信来源 = auth-service 签发的 JWT（经网关 RS256 验签），
  下游只能消费**网关重签**的身份头，任何前端/静态注入的身份头都不可信。
- "不注入"必须优于"透传客户端头"：nginx 既不得静态写死 X-Tenant-ID/X-Actor-ID，
  也不得以 `$http_*` 透传（透传=把浏览器伪造能力重新引入）。
- 数据库归属完整性不得被本迭代破坏：审计**只读**，绝不做 DELETE/UPDATE 生产数据。
- 契约一致性：`config-contract.yaml` 声明的每个 `template_env` 必须真实存在于渲染
  产物，删注入即删契约，避免 `config-contract-check` 孤儿漂移。

## 三、目标

1. 删除 admin-ui nginx 对 `X-Tenant-ID` / `X-Actor-ID` 的静态注入，且**不引入透传回退**
   （同步删除 nginx 引用、Dockerfile envsubst 默认值、helm env、compose env、
   config-contract 条目、`internalIdentity.tenantId/adminActorId` 死值）。
2. 管理台身份上下文唯一来源收敛为网关 admin JWT 派生；用**网关单测锁定**：
   admin realm 下上游收到的 X-Tenant-ID/X-Actor-ID 来自 JWT（`AUTH_DEFAULT_TENANT_ID`
   + `user_id`），客户端自报值一律无效。
3. `scripts/verify/verify_identity_resign.py` 增加 admin 侧静态注入防回退守卫。
4. L3：提供**只读**工单归属审计脚本（纯函数可单测、连库可复跑），并在文档固化
   staging 现状结论（0 空/占位/无 FK 孤儿；匿名归属是"无客户登录"模型的设计固有属性，
   非缺陷、不可删）。

## 四、验收标准

- [ ] `frontend/admin/nginx.conf` 无任何 `proxy_set_header X-Tenant-ID/X-Actor-ID`；
      `Authorization $http_authorization` 透传保持不变。
- [ ] `frontend/admin/Dockerfile` 无 `ADMIN_API_TENANT_ID/ADMIN_API_ACTOR_ID` 默认值。
- [ ] helm 渲染 admin-ui Deployment **不含** `ADMIN_API_TENANT_ID/ADMIN_API_ACTOR_ID` env；
      helm unittest 断言由"包含"翻转为"不包含"。
- [ ] `config-contract.yaml` 移除 `DIAGNOSIS_DEV_TENANT_ID/DIAGNOSIS_DEV_ACTOR_ID`
      与 `helm_only_runtime` 中的 `ADMIN_API_*`；`REQUIRE_HELM=1 make config-contract-check` 通过。
- [ ] 新增网关单测：admin JWT（realm=admin, aud=admin）自报 X-Tenant-ID=attacker
      → 上游 X-Tenant-ID == `AUTH_DEFAULT_TENANT_ID`、X-Actor-ID == `user_id`。
- [ ] `verify_identity_resign.py --require-helm` 对 admin nginx/Deployment 静态注入报错。
- [ ] 新增 `verify_case_ownership.py`：纯分类函数单测通过；连库对 staging 只读审计
      输出"异常 0"；对注入的空/占位 client_id 样本判异常（exit≠0）。
- [ ] 三层事件文档 + `docs/security/identity-resign.md` §5/§6 更新，docs-governance 通过。

## 五、测试点

1. 网关 `test_diagnosis_proxy.py`：admin-realm 派生矩阵（新增）+ 既有 13 项不回归。
2. `verify_identity_resign.py`：admin nginx 静态注入 → 报错；admin-ui Deployment 注入 → 报错。
3. `verify_case_ownership.py`：空串 / `client-session-placeholder-token` / NULL → 异常；
   `client-<随机>` / `hci-sim-admin` / 随机 hex → 视为合法归属（非异常）。
4. helm unittest + config-contract-check 全绿。
5. staging 运行态：管理台登录后台上仍 200，审计操作者=真实管理员 user_id（非 `admin-ui`）。

## 六、非目标（本次不做）

- 不引入租户/操作者多租户隔离逻辑（仅收敛身份来源）。
- 不删除任何工单数据（L3 只读审计；匿名孤儿属设计固有、删之毁真实数据）。
- 不改 `AUTHN_ENFORCE_ADMIN` 开关语义（关后门已由 PR-D 闭环）。
