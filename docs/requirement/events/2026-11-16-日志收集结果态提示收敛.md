# 2026-11-16 日志收集结果态提示收敛

## 背景与问题

工单 `Q2026111600624` 复盘发现客户侧 custom-ui 结果态同屏出现多条互相冲突、重复、无决策价值的提示：

1. 「日志服务器5888：日志服务器不可达；请检查节点到5888的网络，或改用P2平台中转」在结果横幅描述与「一眼定界」卡正文**逐字重复两次**。该工单是 P2 平台中转交付，`probe.log_server_reachable=false` 是既定拓扑下的预期事实，中文案属于画蛇添足。
2. 清理提示同屏两条：一条给出可信节点路径，另一条却说「当前无法确认节点上的准确路径，平台不提供路径」，自相矛盾。
3. 清理提示末尾「请勿触碰 /sf/data/local/acli/plugins 与 tasks 目录。」对用户无决策价值。
4. 结果态还存在「无需人工清理」「观察事实」等多条纯告知型 warning/info，每多一条都增加用户负担。

权威事实（staging 库）：`status=completed`、`delivery_status=delivered`、`relay_status=success`、`archive_size=object_size=1284061124`、`integrity_state=verified`。**日志包已交付成功**，不存在失败。

## 需求描述

用户明确要求：全面梳理结果态提示，只显示正确的内容；custom-ui 不保留「有疑问的告警」，只保留「准确且严重的错误」；页面上每多一条信息就是多一份负担。

该工单最终**唯一允许保留**的提示为：

```
日志包已归档到日志服务器(1284061124 字节)。
平台保留副本供回看;HCI 节点上的采集包路径如下，请确认归属后自行处理:
/sf/data/local/acli/tmp/data/log_collect/Q2026111600624.zip
```

且末尾「请勿触碰 …」必须删除。

## 功能需求

1. 已交付（`delivered`）任务的结果横幅与定界卡不再显示 `LC-5888-002` 及任何 fault 归因文案；真正失败的任务仍必须显示准确错误。
2. 结果态清理提示收敛为唯一一条；无可信节点路径时不显示「不提供路径」告警，而是不显示该提示。
3. 清理提示候选必须纳入 `archive_path`、`node_archive_path` 等节点侧证据，经白名单逐字校验后才展示。
4. 删除「请勿触碰 …」以及结果态「无需人工清理」三连等纯告知文案。
5. 后端不再对已交付任务生成 S5 `LC-5888-002` 信号（日志服务器可达性只决定 P1 可用性，P2 交付后该探测快照已过期）。
