# 需求事件：日志收集修复残留收口

## 变更历史

| 日期 | 版本 | 变更摘要 |
|------|------|---------|
| 2026-11-26 | v1.0 | 初版：基于近四天 43 条失败任务与既往修复复盘，确立五项残留收口需求 |

## 背景与问题

近四天 25 个工单出现 43 条失败任务，17 个客户视图当前显示失败。逐项回溯近期修复后发现四类残留：

1. 客户侧看不到“同工单已有权威归档”：失败行仍显示红色结论，历史成功被最新失败遮蔽，#1572/#1576 的标记只在管理端；
2. 节点上报了别的工单的 zip 包：`Q2026112500790` 的 progress 指向 `Q2026080200163.zip`，#1644 的新旧包判定只拦住了交付，未拦住错误归属；
3. 桥版本不可知：部分任务 `detail.bridge_version` 为空，无法证明现场 exe 是否带修复；
4. 5888 归档巡检脚本在真实数据上抛 `AttributeError`，对账不可用；
5. #1676 的平台侧阻断已部署，但桥侧归因修复尚未进入可下载 exe。

## 需求描述

在不改变任务状态机、不提供节点删除路径的前提下，完成五项最小收口：客户侧只读归档事实提示、包归属校验、桥版本证据覆盖、巡检脚本修复、exe 重建触发。

## 功能需求

1. 客户侧失败行在 `display.conditions` 中新增“本工单已有权威归档”，判据复用 `delivery_evidence_ok()`，只展示事实不改结论；
2. bridge 在 delivery submit 与 waitCollect 两处校验归档包 basename 等于 `case_id`，不一致时拒绝并落结构化事件，不新建错误码；
3. 全部证据上报端点都记录 `X-Bridge-Version`；
4. `scripts/audit/audit_log_collect_5888.py` 修正时区常量并补 `verdict_of()` 单测；
5. 本轮涉及 `terminal_bridge/` 的改动合入 main 后，由既有 CI 自动更新 exe PR #1677。

## 验收标准

- [ ] 同工单存在已核验交付证据时，客户失败行出现“本工单已有权威归档”，且不出现节点路径或删除命令；
- [ ] 归档包归属不一致时交付被拒绝，产生 `delivery.archive_path_case_mismatch` 事件，错误码仍为 `LC-TRANSFER-001`；
- [ ] 六个证据端点均声明并记录桥版本；
- [ ] 巡检脚本对带 mtime 的归档返回判定而非异常；
- [ ] 契约生成物 `--check` 全绿，Go/前端/后端相关单测通过，文档门禁通过。

## 约束条件

- 不改任务 `status` / `delivery_status` / `conclusion`；
- 不向用户提供节点侧路径或删除命令；
- 不新增 `LC-*` 错误码，避免七份生成物与展示字典连锁漂移；
- Python 用 `uv`，前端用 `pnpm`，所有代码改动在 worktree 完成。
