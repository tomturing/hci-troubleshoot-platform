# SOP 未解决切换 KBD 闭环需求

## 问题与根因

同一分类同时命中 SOP 和 KBD 时，Agent 已支持读取 `sop_execution.status=aborted` 后跳过 SOP 并选择 KBD，但生产链路没有任何可达交互或 API 会把 SOP 写为 `aborted`。原有 S6 选择方法只有定义、没有调用方，而且问题会话停留在 S1，不能依赖 S6 到达条件。因此，仅实现 Agent 的 `aborted -> KBD` 路由不能形成用户可用闭环。

## 必须满足的闭环

1. Agent 本轮实际进入 SOP，且本轮没有变量输入、工具确认或人工升级等阻塞交互时，conversation-service 必须发送 `kind=sop_fallback` 的去向卡。
2. 去向卡必须提供“继续按当前 SOP 排查”和“SOP 未解决，切换 KBD”两个明确选项，不得从自然语言猜测用户意图。
3. 卡片的 `request_id`、SOP 文档 ID、SOP 状态、阶段和调用链 ID 必须持久化到 `conversation.pending_resolution`，用于刷新恢复、审计和一次性校验。
4. 用户选择切换 KBD 时，必须在同一数据库事务和行锁范围内完成：校验快照、SOP 标记 `aborted`、清空待填变量、归档未归档诊断项、阶段回退 S1、清空快照、保存用户选择消息。
5. 同一次消息 SSE 必须继续调用 Agent；Agent 读取 `aborted` 后跳过同分类 SOP，立即执行同分类 KBD。没有可执行 KBD 时沿用既有人工升级路径，不得重新进入 SOP。
6. 用户选择继续 SOP 时，只清空一次性快照并保存选择，保留 SOP 状态和当前诊断阶段。

## 安全与并发边界

- `request_id` 必须和会话中待处理快照恒定时间比较；缺失、伪造、过期或重放均拒绝推进。
- Conversation 与 SopExecution 必须加行锁；并发点击只能有一个事务消费快照，后续请求必须被拒绝。
- 快照中的 SOP 文档 ID 必须与当前执行一致，禁止旧卡片终止新 SOP。
- 存在工具确认或其他诊断去向快照时，不得覆盖或追加 SOP 去向卡。
- 选择消息与状态迁移必须原子提交，禁止出现“页面显示已切换但 SOP 仍 active”的分裂状态。

## 可观测性

- 日志事件：`sop_fallback_prompt_sent`、`sop_fallback_prompt_skipped`、`sop_fallback_choice_committed`、`sop_fallback_choice_rejected`，均携带 conversation、request、SOP、stage 和 trace 上下文中的适用字段。
- 链路跨度：`conversation.sop_fallback.prompt` 与 `conversation.sop_fallback.decide`。
- 指标：`hci_sop_fallback_prompts_total{sop_status,stage}` 与 `hci_sop_fallback_decisions_total{choice,status}`；`choice` 只允许两个合法值或固定 `invalid`，禁止用户输入制造高基数标签。

## 回归验收

- SOP 流结束会生成并持久化去向卡；存在变量输入、工具确认或人工升级时不生成第二张卡。
- `switch_kbd` 原子写入 `aborted`、归档诊断项并回退 S1；`continue_sop` 保持 SOP 状态和阶段。
- 伪造或重放 `request_id` 被拒绝；SOP 文档不匹配或已终止时被拒绝。
- 前端点击切换选项必须使用普通消息流提交结构化 metadata，不得调用 ops-agent 的 resume 接口。
- 刷新恢复必须区分协议归属：未回答的 SOP 去向卡可恢复交互态；已回答的 SOP 去向卡不得误连 ops-agent `resume-stream`。
- 助手正文先于交互卡持久化，刷新后顺序稳定且已提交卡片不可再次选择。
- Agent 既有回归必须证明 `aborted` SOP 会降级到同分类 KBD；同分类无可执行 KBD 时进入人工升级。
