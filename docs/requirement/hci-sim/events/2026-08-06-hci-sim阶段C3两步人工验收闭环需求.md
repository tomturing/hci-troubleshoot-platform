# hci-sim 阶段 C3：两步人工验收闭环需求

## 1. 目标

把“指定 KBD_ID 自动搭建仿真环境”和“Custom UI 连接后验证诊断效果”收敛为两个用户动作。第一步必须从 C1 只读 capability API 获取已发布 KBD 的不可变输入；第二步必须走既有 Custom UI → Terminal Bridge → `sim-ssh` → hci-sim 链路。

## 2. 范围与事实边界

- 首批仅允许 `27736`、`34164`，二者当前状态为 `ready_for_artifact_binding`。
- 生成物必须标记 `synthetic=true`、`variant=positive-minimal`、`not_real_artifact=true`。
- synthetic 输出只验证 Signal/Tool/Policy 合约、RouteKey、Lease、Bridge 和 UI 链路，不代表真实 Artifact、真实客户输出、realistic 或真实 HCI E2E。
- `capability_gap`、`TOOL_CONTRACT_STALE`、未发布 KBD 必须原样阻断；不得用 support_id 猜 revision/checksum，不得把 `echo` 伪路由当 KBD 能力。

## 3. 两步验收体验

1. 执行 `scripts/hci-sim/two-step-acceptance.sh <KBD_ID>`。脚本构建镜像、调用 C1、生成并校验 Bundle、启动单副本 hci-sim，并输出一次性 `connection.json`。
2. 在 Custom UI 的 SSH 终端选择“仿真租约”，填入 `host/port/username/password(auth_type=lease)/execution_mode/test_run_id`，执行输出中的 `recommended_command`；应看到 synthetic 标记结果和 KBD/scenario 欢迎语。

## 4. 非功能要求

- Lease 最短有效期、绑定 Bundle/KBD/Scenario/目标并受命令/输出配额限制；token 不进日志、localStorage 或普通 API。
- Bundle Manifest v2 必须通过未知字段、digest、argv 规范化、精确 RouteKey 和输出限制校验。
- 环境启动失败必须可诊断（C1 gap、Bundle 校验、容器 readiness），不得静默回退到真实 HCI。
- 退出容器即释放本次 dev 环境；生产多副本 CAS、对象存储和真实 Artifact 仍是后续工作。

## 5. 验收案例

| 案例 | 输入 | 预期 |
|---|---|---|
| A | `27736` | 启动成功，推荐命令包含“设置集群IP失败”，返回 synthetic qkv_task 结果 |
| B | `34164` | 启动成功，推荐命令包含“新建虚拟机”，返回 synthetic qkv_task 结果 |
| C | `27123` | 第一步阻断并显示 `TOOL_CONTRACT_STALE`，不创建容器、不输出 Lease |
