# hci-sim 阶段 B：运行时安全与确定性加固需求

## 1. 背景

阶段 A 收敛唯一源码后，`hci_sim` 仍是单 Manifest P0 Runtime。当前 scenario/node/container 没有真正参与路由，Lease 只在握手时检查过期，controlled shell 绕过 worker queue，输出和 cancellation 也未形成完整预算闭环。本阶段目标是把 Go 数据面加固成可承载后续控制面的安全执行内核。

## 2. 核心不变量

1. 任何命令都不进入真实 shell。
2. 任何执行都必须绑定已验证的 Lease 和不可变 Bundle digest。
3. scenario、run、KBD revision、variant、node、container 必须参与授权或严格路由。
4. unknown、歧义、过期、撤销、超额、过载一律 fail closed。
5. interactive shell 和 exec 必须经过同一执行管道。
6. 所有等待、输出、连接、队列和状态都有上限并支持取消。

## 3. 功能需求

### B-FR-01 Manifest v2 严格契约

Manifest v2 必须包含：

- schema version；
- `support_id/revision/checksum`；
- tool contract/policy revision；
- bundle digest 与 provenance；
- variants；
- 严格结构化 route key；
- stdout/stderr/exit；
- fault、stream profile 和 limits；
- oracle metadata；
- published 状态证明。

解析器必须拒绝 unknown fields、重复 route、路由歧义、未知模板变量、越界输出和不合法正则。

### B-FR-02 结构化命令指纹

命令处理必须使用不执行 shell 的 lexer/argv parser，并按 Tool Schema 规范化：

```text
tool + normalized args + target node + container + acquisition key + policy revision
```

不得仅靠空白压缩或 raw substring 得出安全身份。

### B-FR-03 强场景路由

路由必须同时校验：

- Lease 中的 support ID/revision/bundle digest/variant；
- scenario/test run；
- virtual node/container；
- acquisition key；
- canonical command fingerprint。

缺失任何 Manifest 声明的约束都必须拒绝，不允许默认 Fixture 跨 scenario 回退。

### B-FR-04 Lease 全生命周期

- SSH 握手和每个 command/channel 提交时都必须验证 expiry。
- 支持短 TTL、唯一 `jti`、撤销检查和 run deadline。
- session、command、output byte quota 必须原子消费。
- 多副本前，配额和撤销状态必须外置到 Redis/CAS；单副本模式必须明确标注限制。
- `VirtualNodeID`、container 等声明必须和执行上下文一致。

### B-FR-05 统一执行管道

`exec` 和 controlled shell 都必须进入：

```text
auth → policy → route → quota → bounded queue → worker/fault executor
→ stream budget → exit-status → telemetry → cleanup
```

禁止任何 shell 特例绕过 queue、指标、Span、fault 或 cancellation。

### B-FR-06 Fault 与流式模型

必须支持确定性的：

- normal；
- nonzero exit；
- permission；
- timeout；
- disconnect；
- delayed first byte；
- fixed-size chunk；
- fixed chunk interval；
- truncated output。

随机行为必须由 manifest seed 固定；timeout 不得长期占用普通 worker。

### B-FR-07 输出、取消和过载

- Manifest、route、stdout、stderr、单 Lease 和单 Run 都有字节预算。
- 客户端断开、context cancel、deadline 到达后必须释放 queue、worker、timer 和 channel。
- queue full 返回结构化 `sim_overloaded`，不得无界等待。
- Runtime 和 Bridge 均保留原始字节计数/hash，但只返回有界内容。

### B-FR-08 统一观测

成功和失败路径都必须记录：

- trace/exec/run/scenario；
- support ID/revision/bundle/fixture；
- route/fault/worker；
- queue wait/duration；
- exit/error type；
- stdout/stderr bytes/hash/truncated；
- lease reject/revoked/expired/quota；
- timeout/cancel/overload。

Bridge 的 `simulation` 标记必须来源于认证后的 execution mode，不得用 host substring 推断。

## 4. 非功能需求

| 编号 | 要求 |
|---|---|
| B-NFR-01 | 任何单请求不能造成无界内存、goroutine、timer 或输出增长。 |
| B-NFR-02 | 相同 Bundle、variant、命令和 seed 必须产生确定性结果。 |
| B-NFR-03 | 真实 HCI 网络在 NetworkPolicy 和凭据层均不可达。 |
| B-NFR-04 | Runtime 不依赖 KBD 数据库写权限，不负责编辑或发布 Fixture。 |
| B-NFR-05 | 所有错误具有稳定 error type 和非零 exit/status。 |

## 5. 范围外

- 不在本阶段实现 KBD Compiler、审核 UI 或 TestRun API。
- 不允许客户端上传任意 Bundle URL。
- 不支持通用 Bash/OpenSSH。
- 不宣称 100+ 容量已经通过。

## 6. 验收标准

- [ ] 对抗测试证明 scenario/node/container 不能串线。
- [ ] 已连接会话在 Lease 过期或撤销后不能继续执行。
- [ ] shell 与 exec 使用同一 bounded dispatcher。
- [ ] timeout/cancel/断连后资源归零。
- [ ] Manifest v2 对 unknown、歧义、超限、模板缺失 fail closed。
- [ ] 结构化 fingerprint 对允许的等价命令稳定，对越权参数拒绝。
- [ ] 过载明确返回 `sim_overloaded`，无 OOM 和无界等待。
- [ ] 成功、miss、policy、expiry、quota、timeout、cancel、overload 均有 Trace/Metric/Log。
- [ ] 真实 `ssh` 模式回归无变化。
