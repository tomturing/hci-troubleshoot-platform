# hci-sim A～E 三个交付 PR 闭环需求

## 1. 目的与完成边界

本事件把阶段 A～E 以及 2026-08-10 的三组重构，收敛为最多三个可独立审查、可回滚、可验收的纵向 PR。PR 数量是交付组织约束，不是把未实现能力包装成已完成的依据。完成定义仍然以真实运行证据为准：代码、部署、数据、UI、SSH/Bridge/Agent 链路和产品级报告必须同时闭环。

## 2. 第一性原理不变量

1. **唯一事实来源**：Go Runtime 源码只有 `hci_sim/`；外部 K8s/镜像/Service 名称保持 `hci-sim`。
2. **执行隔离**：sim TestRun 的 `mode=sim-ssh`、Bundle digest、KBD revision、target 和 Agent environment context 在创建时冻结；任何缺失或漂移 fail closed，禁止回退真实 HCI。
3. **数据隔离**：hci-sim 控制面只使用 `hci_sim` 数据库及其四个 schema；平台业务继续使用 `hci_troubleshoot`。跨库只保存 support ID、revision、checksum、digest 和审计关联，不建立跨库外键。
4. **证据独立**：synthetic、positive-realistic、negative、near-miss、unknown、timeout 和 permission 结果必须保留来源、版本、digest 和 Oracle 语义，不能把命令成功压平为业务 PASS。
5. **可操作闭环**：用户在 Admin UI 输入 KBD_ID，点击“环境构建”，等待可见的构建状态/日志；构建未成功前“开始测试”禁用；成功后自动带出 SSH 仿真环境信息，用户只补标题/描述并创建工单。

## 3. 三个 PR 的范围

### PR1：基础运行面与环境门禁

- 修复 ArgoCD migration Hook 依赖顺序；
- dev 实际创建 `hci_sim`、角色、schema、表并完成权限正负向验证；
- 以 K3s/GitOps 受管方式部署 `hci-sim-dev` 的 Deployment/Service/Secret/Fixture/NetworkPolicy；
- Runtime 显式读取 `HCI_SIM_DATABASE_URL`，缺失时 fail closed，禁止回退 `DATABASE_URL`；
- terminal_bridge → `hci-sim.hci-sim-dev.svc:2222` → SSH handshake/exec-result E2E；
- 记录 A/B 的真实部署和对抗性验证证据，修正当前事实文档。

### PR2：控制面、TestRun、23821 与 Admin UI 产品入口

- 将 C/D 的内存参考适配器替换为 PostgreSQL `hci_sim` 持久化 Repository、CAS 状态机、Outbox 和 Runtime capability；
- 提供按 KBD_ID 构建环境、查询进度、展开/关闭详细日志、创建/查询/取消/重试 TestRun 的内部 API；
- 补齐“TestRun → Agent environment context”的显式绑定和授权透传；
- 生成并审批 immutable Fixture Bundle，完成 23821 的真实 published fixture bundle，不以 synthetic 代替；
- customer-ui 删除“仿真租约”入口；admin-ui 新增“仿真测试”页面，包含“环境构建”和“开始测试”两个按钮及自动创建工单弹窗；
- 仅保留两步用户验证：环境构建 → Admin UI 开始测试/SSH 连接工单。

### PR3：产品级验证与规模化运营

- 完成 27123、23821 及至少一个结构异构 KBD 的 positive/negative/near-miss/unknown/timeout/permission 验收；
- 执行 real/sim differential、关键 mutation、20 次稳定性和 1/10/50/100/200 容量梯度；
- 建立 PR affected suite、nightly 核心 suite、周期校准、Evidence Manifest、dashboard、告警、SLO、waiver 到期和 runbook；
- 以真实证据更新阶段 A～E 验证报告和产品声明；未通过的 KBD 只输出 capability gap，不得宣称“126 个 KBD 已全部支持”。

## 4. 验收总则

每个 PR 必须同时包含需求/设计/任务/验证变更、代码测试和回滚说明。PR 合入不等于阶段 Go；只有当对应现场命令、原始日志、数据库查询、UI 操作和 Evidence Manifest 可重放时，才允许把条目从 pending 改为 passed。
