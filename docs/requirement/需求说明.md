## 1. 项目背景

### 1.1 业务场景

HCI（超融合基础设施）是一种将计算、存储和网络资源集成在一起的 IT 架构。运维人员在日常工作中需要处理各种复杂的技术问题，如：

- 虚拟机启动失败
- 存储性能下降
- 网络连接异常
- 集群节点离线
- 备份任务失败

传统排障方式依赖运维人员的经验和知识，效率低下且容易遗漏关键步骤。

### 1.2 解决方案

开发一个**智能排障平台**，采用云端Server为核心、多客户端接入的架构。

## 2. 需求目标

### 2.1 核心目标

| 目标 | 描述 |
|------|------|
| **即时排障** | 用户用自然语言描述问题，平台即时打通客户端和AI引擎通路 |
| **智能调度** | 根据API Gateway的Session智能调度拉起和关闭AI引擎POD |
| **知识积累** | 记录排障过程（Conversation信息落库），形成可复用的知识库 |
| **系统对接** | 支持对接第三方系统，如工单系统、知识库系统等 |

### 2.2 功能需求

#### MVP阶段功能

**Web端功能**（MVP测试验证工具）:
1. **case管理**: 查询case、创建case、确认case、关闭case
2. **session建立**: 与gateway建立session
3. **对话交互**: AI响应case请求，与用户对话
4. **命令展示**: 显示AI建议的命令

**云端Server核心功能**:
1. **case管理**: 根据web端唯一标识ClientID查询Case、创建Case、更新Case、关闭Case
2. **session管理**: session创建、关闭、状态维护
3. **对话管理**: 所有对话信息落库，同一CaseID，所有对话信息落库
4. **容器管理**: 根据CaseID，拉起或关闭AI引擎POD，基于OpenClaw + Zhipu API的智能对话理
5. **可观测性**: 全链路TraceID追踪、指标采集、结构化日志

#### 可观测性设计

**监控范围说明**: 可观测性系统用于监控**排障平台自身**（云端Server），确保排障平台的稳定性和可维护性，而不是监控用户的HCI集群环境。

**TraceID全链路追踪**:
- 格式: `hci-{timestamp}-{random}`
- 贯穿: 网关 → 服务 → 数据库 → OpenClaw调用 → 日志
- 用途: 完整追踪每个请求在排障平台内的调用路径

**监控对象**（排障平台自身）:
- ✅ API Gateway: 请求路由、TraceID生成、响应时间
- ✅ 工单服务: 工单CRUD操作、数据库操作
- ✅ 对话服务: OpenClaw调用成功率、响应时间
- ✅ 数据采集服务: 环境信息写入性能
- ✅ PostgreSQL: 连接池、慢查询、trace_id索引查询
- ✅ Redis: 缓存命中率、内存使用

**不监控的对象**:
- ❌ HCI集群: 这是被排障的对象，不是监控对象
- ❌ OpenClaw内部: 独立服务，有自己的可观测性（我们只监控调用它的成功率和响应时间）
- ❌ Zhipu API: 第三方服务（我们只监控调用成功率）

**观测点示例**:
- API Gateway: HTTP请求统计、TraceID生成、路由转发耗时
- 微服务: 业务逻辑耗时、数据库操作耗时、OpenClaw API调用耗时
- 数据库: SQL查询性能、trace_id索引查询性能
- 日志: 结构化日志（JSON格式），所有日志包含trace_id字段

> **重要说明**: Web前端仅为MVP阶段的测试验证工具，用于验证云端Server功能完整性，不是正式客户端功能。正式客户端为Windows客户端。

#### 未来功能（不在MVP范围）
- 用户认证和授权系统
- 环境信息采集
- 知识库系统

## 4. 用户故事

### US-001: 打开排障助手
**作为**临时或者认证用户
**我想要**打开排障助手聊天页面
**以便**获得工单状态

**验收标准**:
- 通过ClientID自动获取到工单信息
- 如果没有工单，提示新建工单；如果有工单，确认是继续排障还是关闭工单
- 关闭工单后提示新建工单；系统生成唯一工单号 (QYYYYMMDDXXXXX)
- 新建工单后，自动连接热备AI引擎POD，并建立session

### US-002: 对话排障助手
**作为**临时或者认证用户
**我想要**创建工单或者选择已有工单后进入聊天页面，描述问题
**以便**获得 AI 的排障建议

**验收标准**:
- AI 根据工单描述信息给出初始响应
- 客户端自动收集用户信息，现场环境信息包括但不限于客户信息、环境信息
- 多次沟通引导客户排障；支持追问和补充信息
- 保留对话历史

### US-003: 获取操作命令
**作为**临时或者认证用户 
**我想要**对话过程中，获取具体的操作命令
**以便**直接执行排障命令

**验收标准**:
- AI 提供可执行的命令
- 命令有适当的说明
- 警告危险操作

### US-004: 关闭工单
**作为**临时或者认证用户 
**我想要**对话结束后，关闭工单
**以便**结束排障

**验收标准**:
- AI 已提供最终解决方案
- 提出关闭工单的建议
- 确认关闭工单

## 8. KBD 关键信号人工审核与结果提取

- 关键信号由 AI 初步抽取、人工审核后发布，管理端优先保证字段少、语义直观、保存即真实可执行。
- “专家修改 N 条关键信号”只比较当前专家稿与其明确审核的 AI Proposal；AI 重抽和技术元数据变化不得计入，无专家稿时为 0。
- LLM 必须完整提出 Candidate，不得在生成阶段过滤写动作、catalog 缺失或验证失败候选；服务端逐条分流为 Signal 或 Rejected Candidate。
- Rejected Candidate 只使用 `write_signal`、`not_exists`、`run_failed` 三个稳定分类，并完整保留候选、证据和具体原因。`qkv_task` 是历史任务查询，其 keyword 中的动作词不属于写操作。
- 当前 aCLI catalog 是生成知识和能力缺口基线，不是可执行性的充分条件；catalog 未登记需要专家确认，catalog 已登记但验证/运行失败必须作为 `run_failed` 重点处理。
- 专家主页面只显示当前 AI Proposal、当前专家稿和必要的当前生效版；后台保留有学习价值的不可变完整快照，训练/评估必须筛选明确 Proposal→Expert 配对，不能直接消费全部历史。
- 失败任务需为后续检查提供 HOST/VM 时应生成 `qkv_task`；QFK producer 的产出必须有其他下游消费者，配置事实优先使用 matcher；自动生成或缺省的 QKV/QFK timeout 为 60 秒，历史显式值保持不变。
- QFK 后端信号在关键字判定和产出变量之间严格二选一；产出写入统一变量池。
- JSON 用 path；非 JSON 用受控的行筛选与列提取，不开放任意 Shell/awk。
- 命令展示可截断，变量提取必须使用完整 stdout/stderr；缓存缺失时 Fail Closed。
- host、container=host 与 1–300 秒 timeout 必须在真实 terminal bridge 链路生效。
- 最终报告中的关键信号结果只展示检查说明、用户态状态、检查结果和结构化产出；内部 ID、参数与原始输出保留在审计层。
- KBD 27123 的进程确认使用 `ps -p {{PID}} -o cmd=`，通过 `include={{VM}}` 确认命令行仍关联目标镜像并产出唯一 `CMD`；不要求命中特定进程名。

详细验收见 [KBD关键信号编辑与非JSON结果提取需求](events/2026-07-27-KBD关键信号编辑与非JSON结果提取需求.md) 和 [KBD关键信号结果展示与ps输出提取需求](events/2026-07-28-KBD关键信号结果展示与ps输出提取需求.md)。

## 9. hci-real/hci-sim 双轨 Agent 测试

- 平台同时保留真实 HCI 与 hci-sim；生产诊断只使用 real，日常自动回归和 100+ 并发只使用 sim；
- 一次 Agent run 在创建时固定 `execution_mode`，禁止同次混用和 sim 失败 fallback real；
- hci-sim 通过 SSH 与 Terminal Bridge 对接，不在 Bridge 中硬编码 KBD；
- 100+ 环境首期采用 Scenario Lease 驱动的逻辑隔离，共享 2～4 个模拟器 Pod，不默认每 KBD 创建 Pod；
- hci-sim 部署在 dev/test K3s 独立 namespace，prod 默认不部署，网络上禁止访问真实 HCI；
- real 与 sim 共享 Agent、SSH/result/Trace/Artifact/Matcher/CDD 契约，但隔离目标、凭据、状态、fixture 和统计；
- 真实 HCI 作为低频 Oracle，负责版本、SSH/aCLI/PTY/output 校准，不能被日常 100+ 回归调用；
- 100+ Bulk Agent E2E 与 100 浏览器 UI 负载是不同验收项，必须分别报告；
- 在宣称完成前，必须通过 KBD 27123 Golden real/sim diff、完整 Trace、negative/near-miss/error 和 100/200 并发隔离门禁。

详细需求见 [HCI真实环境与仿真环境双轨测试需求](events/2026-07-30-HCI真实环境与仿真环境双轨测试需求.md)。
