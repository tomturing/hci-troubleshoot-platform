# KBD 无信号案例推荐与诊断能力分离

日期：2026-09-23。本文描述工作区实现；部署与检索阈值现场评测需单独验收。

## 使用方式

没有任何信号的案例可以作为参考知识审核发布。审核人员维护案例标题、分类和正文即可，不必为检索补建 `qkv_case_context` 或语义画像。管理端空信号区域显示“仅案例推荐”。

发布为参考知识不代表允许自动诊断。系统派生 `reference_only` 能力，不创建虚构 Signal，不增加新的知识事实表，不改变原始正文。

有信号的案例仍通过原有结构、变量依赖、必要证据、消费者覆盖和执行边界校验。抽取结果过期、候选全被拒绝、损坏的信号结构或孤儿画像不能静默作为正常空信号发布。首次发布、维护发布和重新发布共用消费者覆盖门禁；批量通过复用首次发布入口。

## 在线路由

1. 已确认分类有 SOP，且会话未放弃该 SOP：继续原 SOP；SOP 分支不会自动混跑 KBD。
2. 无 SOP，或 SOP 被标记为 `aborted` / `sop_fallback_requested`：进入同分类 KBD。
3. 有可执行的强入口案例：使用既有 CDD 执行任务、告警、弹框及案例验证信号；必要、排除、增强证据规则不变。达到确定性结论后，不运行参考推荐。
4. 无可执行候选，或 CDD 未确诊：调用分类发布快照上的语义路由，允许补充标题推荐。
5. 已有可执行语义画像满足原有准入条件：继续受控现场验证。画像既有强信号、范围和消费者门禁不放宽。
6. 其余情况下，在同一参考候选池比较标题、问题描述、报错和可选画像。返回 `case_recommendations`，仅展示未验证的历史案例。

强信号查询失败可以展示参考，但保留 `source_unavailable` 和原始 CDD 报告，不把失败改成未命中。CDD 已判为 `REJECTED` 的案例通过 `excluded_kbd_ids` 从本轮后续画像验证和标题推荐中排除。

用户输入使用首条问题及后续有效补充，排除“继续”等控制词以及模型/工具输出。推荐不从描述生成 HOST/VM_ID，不执行正文命令，不产生 `SUPPORTED` 或 S4。

## 检索与返回

- 使用当前分类完整的、已发布且激活的不可变 KBD 修订；校验调用方的分类成员和修订，避免维护工作稿污染。
- 标题优先的中文双字词/英文/错误码匹配，问题描述和报错补充；有画像时使用其症状和锚点，并保留明确排除条件与澄清排除答案。
- 可用时批量进行语义向量检索，候选向量缓存以模型命名空间和检索文本摘要区分。不会先按词法 Top-K 截断整个分类，避免同义表达漏召回。
- 独立 `root_cause`、`solution` 字段不拼入检索向量；标题原文仍保持完整。历史根因及处理方法从发布正文对应字段取出，绝不由标题临时生成。
- 已知版本/产品范围冲突时排除；缺少范围信息时标记待核对，推荐仍不具有执行权限。
- 对明确否定/历史分句采取保守词法处理；这不是完整自然语言理解。复杂纠正与多对象叙述需要现场评测。
- 向量异常整批降级为词法检索，不混用半批向量结果；没有合适候选时沿用补充信息/人工路径，不强行选第一名。
- 返回最多五条参考，同分或近分保留多个候选并提示补充完整报错/版本；分数仅用于相关性排序，不显示为根因概率。

初始词法门槛 0.45、向量门槛 0.78、歧义间隔 0.12 是保守检索参数，不是经过真实查询集校准的准确率承诺。上线前应使用真实问题、同症状不同根因、无答案、版本冲突与否定反例做检索评测。

## 离线与展示

`reference_only` 不生成 Collector、映射、采集画像或空计划。原可执行案例转为参考知识后，同步按已有停用流程清理不再被引用的采集资源。离线“相关案例和补证据指引”入口支持同一批参考知识。

客户侧显示案例号、标题、问题描述、历史案例根因、参考处理方法和发布修订，注明尚未现场验证。普通 Markdown 仍只是展示，不获得自动执行权限。

## 兼容与回归

语义解析 API 和 KBClient 新增可选的 `include_reference_cases`、`excluded_kbd_ids`、`recommendation_only` 字段；默认不改变旧调用方的画像行为。在线 Agent 显式启用参考推荐，离线指引也显式启用。旧画像没有可展示正文时仍保留补证据指引。

回归覆盖空信号发布、非法文档拒绝、冻结修订、采集失败参考、现场反证排除、歧义保留、向量降级、SOP 放弃回退、零信号不进入 CDD/S4、离线不生成采集和客户展示。
