# KBD 专家复核、版本治理与生产消费闭环实施任务

## 对应方案

[KBD 专家复核、版本治理与生产消费闭环方案](../../../solution/agent/events/2026-07-29-KBD专家复核与全生命周期闭环方案.md)

## 当前状态与实施边界

本任务处于**方案待确认**状态。本轮只完成当前代码审计、目标架构、迁移路线、风险和验收口径归档；尚未新增数据库表、后端 API、Admin 工作台或 Agent Capability 运行逻辑。

用户确认方案前，不得把下表中的任务状态改为“进行中/已完成”，也不得开始正式修改 122 条 Proposal。尤其不能在不可变 baseline 建立前，让专家编辑、重识图、重分类或重抽覆盖当前模型产物。

## 任务目标

将当前：

```text
可变 kbd_entry
→ 有限内容审核
→ 审核与发布同一动作
→ Agent 消费 dynamic active snapshot
```

升级为：

```text
Immutable Source
→ N 个 LLM Proposal
→ Expert Review + Decision
→ Immutable Candidate Bundle
→ Prepared Runtime Revision + Search Artifact
→ Full Validation
→ Approval Attestation Set / Expert Gold
→ Immutable Release
→ Append-only Activation / Active Release Pointer
→ Agent Usage + Runtime Feedback
```

并建立：

```text
生产/审核发现诊断意图无法表达
→ Capability Request
→ Registry/Handler/Operator 实现和测试
→ 受影响 Proposal 重编译
→ 专家确认
→ 新 Candidate Bundle
→ Validation / Gold Approval Set
→ Release / Activation
```

## 已确认的当前基线

- 126/126 仅表示真实来源完整性已通过，不表示业务 Gold；
- 122 条为自动 Proposal，尚未正式专家审核；
- 4 条工程 fixture 为 `engineering_fixture/pending_expert`；
- 4 条的 positive/strong-negative/unknown/error 测试属于 outcome-level Decision Replay；
- 只有 KBD27123 的全部 QFK 路径通过当前真实 `ToolSemanticValidator`；
- KBD37150、37180、41818 存在关键命令在 terminal bridge 前被 aCLI Catalog 拒绝；
- 当前管理页还不能作为正式 Proposal→Gold 工作台；
- `kbd_entry` 的分类、Vision、Signal/Contract 仍可能被覆盖；
- dynamic resource revision 可复用为运行时 Release，但不能替代 Proposal/Expert lineage。

## 实施硬约束

1. 先固化完整 126 条迁移 manifest（122 条 Proposal baseline + 4 条 engineering fixture + 已有 runtime revision/active pointer），再允许正式专家编辑；
2. Proposal、Expert、Candidate Bundle、Approval Attestation/Gold Set、Search Artifact、Runtime Observation 和 Release 均不可原地修改；
3. 模型重跑只创建 Challenger，不覆盖 Expert/Active；
4. Gold Approval Set 绑定 exact Validation Run，并与 Runtime Publish 分离；
5. `kbd_active_release` 是唯一生产指针，Agent 只读取其所固定的 snapshot；
6. Compiler 必须经过真实执行器的语义门；
7. 非零 exit、截断、不完整观察 fail closed；
8. Capability executable semantics 通过代码审查和测试发布，不由 Admin 热编辑；
9. 遗留血缘缺失必须诚实标记，不伪造 raw response、run 或专家 decision；
10. 执行前授权、Evidence attestation 和 Verdict finalization 不得共用一个 `require_human_confirm` 布尔值；人工证明必须绑定 exact subject ID/hash；
11. 所有阶段都更新方案、任务、验证报告和用户可见口径。
