# KBD 轻治理、自动化优先闭环实施任务

## 对应方案

[KBD 轻治理、自动化优先的知识生产消费闭环方案](../../../solution/agent/events/2026-07-29-KBD专家复核与全生命周期闭环方案.md)

## 当前状态

用户已确认轻治理方向，允许开始实施。实施采用小型纵向切片，不再建设独立工作台、双审、多表生命周期和 Catalog→Registry 长流程。

事实口径：

```text
126/126 真实来源完整；
122 条为自动 LLM Proposal；
4 条为 engineering Contract fixture；
仅 KBD27123 的全部 QFK 路径通过当前真实语义门；
0/126 Expert Gold；
0/126 正式业务专家批准。
```

## 目标

将当前：

```text
LLM/人工覆盖同一 kbd_entry
→ 普通保存可能隐式发布
→ Admin 状态与 runtime active 可能不一致
→ 工具定义、Schema、Handler、Validator 分散
```

收敛为：

```text
Source
→ append-only Proposal Revision
→ 自动 Validation
→ 单专家就地确认/修改
→ Expert Revision
→ 现有 Dynamic Resource Revision / Active
→ Agent exact revision 使用与反馈
→ LLM 评估和优化
```

## 实施约束

1. 只新增一张 KBD 核心 revision 表，不建设完整治理表族；
2. `kbd_entry` 当前保持主记录和兼容读入口；
3. 复用现有 `dynamic_resource_revision/active/usage_audit`；
4. 保存专家草稿不能切 active；
5. 发布、撤回、回滚必须真正改变 Agent active；
6. Proposal、Expert 和 Active 可定位、可 Diff；
7. 当前全部单专家，允许同一专家编辑并发布；
8. 审核身份从认证上下文取得，不信任 body 中任意 reviewer_id；
9. Capability Descriptor 由代码契约生成，数据库工具记录不能伪造实现状态；
10. 生产 Agent 不允许自由 Shell 兜底；
11. 未支持、截断、错误和不完整证据 fail closed；
12. 代码、数据库和前端变更必须同步更新方案、任务和验证文档。

### 专家易用性验收

- 专家能在 10 秒内识别当前案例有多少错误、警告和能力缺口；
- 每个问题能定位到章节、图片或 Signal；
- 所有 LLM 产物都有明确编辑入口；
- 普通路径为“打开→确认/修改→完成审核并发布”；
- 无需理解 revision、bundle、attestation、registry；
- 修改后立即显示 Validation 结果；
- 发布成功后立即显示 exact active revision；
- 验证失败不改变旧 active。

## 测试矩阵

| 层 | 必测内容 |
|---|---|
| Migration | 新表/字段、索引、FK、幂等、现有 active 不变 |

| LLM Data | Proposal/Expert 不覆盖、Diff 可重算、reason 分类可统计 |
| Agent | exact runtime revision usage audit，错误/截断/不完整 fail closed |

## 回滚边界

- Schema 使用扩展式迁移；旧读路径在纵向切片内保留；
- `kbd_revision` 失败时仍可读取现有 `kbd_entry`；
- Revision 改造不得迁移或切换现有 active；
- 发布失败保持旧 active；
- Descriptor API 失败时审核页显示“能力状态未知”，不得误显示可用；
- Capability 新实现先通过代码测试和受控验证，不能依赖自由 Shell 直接生产发布。
