## T-AGT-01：P-NEW-1 修复 direct 模式 `async for` 误用

### 背景与问题

```
【背景】
diagnostic_agent.py 的 direct 模式（SOP 轨、KBD 轨、机制推理）通过
chat_completion_stream 获取 LLM 输出流。

【问题】
第 217 行：`for chunk in ai_client.chat_completion_stream(...)` 
chat_completion_stream 是 async def，返回 AsyncGenerator，
在 async def process() 中必须用 async for 才能迭代。
结果：所有 direct 模式请求在第一个字符输出前抛出
TypeError: 'async_generator' object is not iterable
前端收到 error SSE，无任何输出。
```

### 任务目标

1. `diagnostic_agent.py` 第 217 行 `for chunk in` 改为 `async for chunk in`
2. 添加单元测试确认 direct 模式流式输出正常

### 涉及文件

| 文件路径 | 操作 | 说明 |
|---------|------|------|
| `backend/agent-service/app/adapters/agents/htp/diagnostic_agent.py` | 修改 | L217：`for chunk in` → `async for chunk in` |
| `backend/agent-service/tests/unit/test_diagnostic_agent_direct.py` | 新增 | 单元测试 |

### 依赖关系

- **前置任务**：无
- **后续任务**：T-AGT-02（同文件，一起修复）

### 实现步骤

**Step 1：定位并修改**

```bash
cd backend/agent-service
grep -n "for chunk in" app/adapters/agents/htp/diagnostic_agent.py
```

找到第 217 行附近（`for chunk in ai_client.chat_completion_stream`），修改为：

```python

    yield AgentTextChunk(content=chunk)

# 修改后：

    yield AgentTextChunk(content=chunk)
```

**Step 2：添加单元测试**

创建 `tests/unit/test_diagnostic_agent_direct.py`，mock `ai_client.chat_completion_stream` 返回 `AsyncGenerator`，断言 `process()` 能正常 yield `AgentTextChunk`。

## T-AGT-05：P-NEW-3 修复 ReactEngine 双重执行工具

> 注：此任务严重度 HIGH，与 P0 紧急修复一并处理，因为涉及写操作副作用

### 背景与问题

```
【背景】
ReactEngine 主循环执行工具后，将结果追加到 messages 继续推理。

【问题】
react_engine.py 主循环中工具调用存在两次执行：
① async for event in self._execute_tool_call(...)
   内部已调用 await self._tool_executor.execute(tool_name, tool_args) 并写审计日志
② 循环结束后再次调用 tool_result = await self._get_tool_result(tc.name, tc.arguments)
   内部重复执行同一工具

写操作工具（acli_service_restart、acli_network_nic_up 等）会被执行两次，
产生重复变更副作用（服务重启两次、网卡禁用后立即重新启用等）。
```

### 任务目标

1. 删除主循环中多余的 `_get_tool_result()` 调用
2. `_execute_tool_call()` 改为通过 yield 或 return 将工具执行结果传回，主循环直接消费构造 `tool` 消息
3. 确保审计日志只写一次

### 涉及文件

| 文件路径 | 操作 | 说明 |
|---------|------|------|
| `backend/agent-service/app/adapters/agents/htp/react_engine.py` | 修改 | 删除重复的 `_get_tool_result()` 调用 |
| `backend/agent-service/tests/unit/test_react_engine_no_duplicate.py` | 新增 | 验证工具只执行一次 |

### 依赖关系

- **前置任务**：T-AGT-01、T-AGT-02（修复 async for 后才能正确测试 react 流程）
- **后续任务**：T-AGT-03

### 实现步骤

**Step 1：阅读 ReactEngine 主循环**

```bash
grep -n "_get_tool_result\|_execute_tool_call" app/adapters/agents/htp/react_engine.py
```

**Step 2：重构工具执行逻辑**

推荐方案：在 `_execute_tool_call()` 最后 `yield` 一个 `ToolResultEvent(result=tool_output)`，主循环消费该事件取得 `tool_output`，删除 `_get_tool_result()` 调用：

```python
# 修改前（主循环片段）：
async for event in self._execute_tool_call(tc):
    yield event
tool_result = await self._get_tool_result(tc.name, tc.arguments)  # 重复执行！
context.append({"role": "tool", "content": str(tool_result)})

# 修改后：
tool_result = None
async for event in self._execute_tool_call(tc):
    if isinstance(event, ToolResultEvent):
        tool_result = event.result
    else:
        yield event
context.append({"role": "tool", "content": str(tool_result)})
```

**Step 3：验证审计日志**

确认 `tool_result` 表每次工具调用只写入一条记录。

### 验收标准

| # | 验收项 | 通过标准 |
|---|--------|---------|
| 1 | 单元测试 | mock 工具执行，断言工具 executor 只被调用一次 |
| 2 | 审计日志 | 单次工具调用后 `tool_result` 表只新增 1 条记录 |
| 3 | 写操作工具 | `acli_service_restart` 执行后服务只重启一次 |

## T-AGT-03：P-NEW-4 修复 ConfirmService 确认回路断裂

### 背景与问题

```
【背景】
ReactEngine 对 risk_level≥2 的工具调用暂停并等待用户确认。

【问题】完整断裂链：
1. ReactEngine 调用 confirm_service.request_confirm(session_id) 
   → Redis BRPOP confirm:{session_id} 阻塞等待 120s
2. 前端收到 interactive_request SSE（kind=tool_confirm），用户点确认
3. 前端 POST conversation-service /interactive-response
4. conversation-service 调用 ops_adapter.submit_acp_response()（ACP 协议，针对 ops-agent）
5. ❌ 没有任何代码路径调用 confirm_service.submit_confirm(session_id, confirmed=True)（即 Redis LPUSH）
6. BRPOP 必然超时（120s），工具被取消，输出"操作已取消"

所有 risk_level=2 写操作工具（acli_service_restart、acli_network_nic_up 等）
经用户确认后仍被取消，前端永远显示"操作已取消"。
```

### 任务目标

1. `agent-service` 新增 `POST /v1/agent/react-confirm` 端点
2. `conversation-service` 的 `/interactive-response` 按 `kind` 字段分叉路由：
   - `kind=tool_confirm` → 调用 `agent-service /v1/agent/react-confirm`
   - ACP 类型 → 保持原有 `ops_adapter.submit_acp_response()`
3. 端对端验证：用户点确认后工具正常执行

### 涉及文件

| 文件路径 | 操作 | 说明 |
|---------|------|------|
| `backend/agent-service/app/routes/agent.py` | 修改 | 新增 `POST /v1/agent/react-confirm` 端点 |
| `backend/agent-service/app/adapters/agents/htp/confirm_service.py` | 修改 | 确认 `submit_confirm()` 方法签名正确 |
| `backend/conversation-service/app/services/conversation_service.py` | 修改 | `submit_interactive_response()` 按 kind 分叉 |
| `backend/conversation-service/app/routes/conversations.py` | 修改 | 调用链更新 |

### 依赖关系

- **前置任务**：T-AGT-05（ReactEngine 修复后 react 流程才可靠）
- **后续任务**：无

### 实现步骤

**Step 1：新增 agent-service 确认端点**

```python
# backend/agent-service/app/routes/agent.py 新增：
@router.post("/v1/agent/react-confirm")
async def react_confirm(
    body: ReactConfirmRequest,  # {session_id: str, confirmed: bool, authorized_by: str}
    confirm_service: ConfirmService = Depends(get_confirm_service),
):
    await confirm_service.submit_confirm(
        session_id=body.session_id,
        confirmed=body.confirmed,
        authorized_by=body.authorized_by,
    )
    return {"ok": True}
```

**Step 2：conversation-service 分叉路由**

```python
# conversation_service.py submit_interactive_response() 修改：
async def submit_interactive_response(session_id: str, kind: str, payload: dict):
    if kind == "tool_confirm":
        # 路由到 agent-service /v1/agent/react-confirm
        await self._agent_client.react_confirm(
            session_id=session_id,
            confirmed=payload["confirmed"],
            authorized_by=payload.get("authorized_by", "user"),
        )
    else:
        # 原有 ACP 路径
        await self._ops_adapter.submit_acp_response(session_id, payload)
```

**Step 3：端对端测试**

1. 触发 `acli_service_restart`（risk_level=2）
2. 前端收到 `interactive_request` SSE，点击确认
3. 确认 `confirm_service.submit_confirm()` 被调用（日志可见 LPUSH）
4. BRPOP 返回，工具正常执行，前端收到工具结果事件
