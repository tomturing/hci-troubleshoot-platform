**Step 2：实现 `extract_sop_variables()`**

```python
import re

# 变量名启发式规则（来自 §12.7.3）
STRATEGY_HINTS = {
    r".*_ip$|^node_ip$|^cluster_ip$":         "env_context",
    r"^vm_name$|^vm_id$":                     "tool:get_vm_list",
    r"^disk_id$":                              "tool:acli_storage_disk_list",
    r"^nic_name$":                             "tool:acli_network_nic_list",
}

def _infer_strategy(var_name: str) -> dict:
    for pattern, strategy in STRATEGY_HINTS.items():
        if re.match(pattern, var_name):
            if strategy.startswith("tool:"):
                return {"acquisition_strategy": "tool", "acquisition_tool": strategy[5:]}
            return {"acquisition_strategy": strategy, "acquisition_tool": None}
    return {"acquisition_strategy": "user_input", "acquisition_tool": None}

def extract_sop_variables(content_md: str, tree: SOPNode | None) -> tuple[list[dict], list[str], list[str]]:
    """
    返回：(variable_defs, undeclared_errors, orphan_warnings)
    """
    # 1. 解析 ## 变量 章节获取 declared_vars（变量名 → 手动描述）
    declared_vars = _parse_variable_section(content_md)

    # 2. 扫描全文 + tree_json 中的 {placeholder}
    used_vars = set(re.findall(r'\{([a-z][a-z0-9_]*)\}', content_md))
    if tree:
        # 递归扫描 tree 各节点 commands
        used_vars |= _extract_from_tree(tree)

    # 3. 双向 diff
    undeclared = used_vars - set(declared_vars.keys())  # Error：用但未声明
    orphan = set(declared_vars.keys()) - used_vars      # Warning：声明但未用

    # 4. 构建 SopVariableDefinition 列表
    variable_defs = []
    for var_name in used_vars:
        declared = declared_vars.get(var_name, {})
        strategy_info = declared.get("acquisition_strategy") or _infer_strategy(var_name)
        variable_defs.append({
            "name": var_name,
            "display_name": declared.get("display_name", var_name),
            "description": declared.get("description", ""),
            "type": declared.get("type", "string"),
            "required": True,
            **strategy_info,
            "validation_pattern": declared.get("validation_pattern"),
            "default_value": declared.get("default_value"),
            "auto_generated": var_name not in declared_vars,
        })

    return variable_defs, list(undeclared), list(orphan)
```

**Step 3：approve 接口集成**

```python
# admin.py approve 流程扩展：
# ① 解析决策树（现有）
# ② 提取变量 + 双向校验（新增）
variable_defs, undeclared, orphan_warnings = extract_sop_variables(content_md, tree)

if undeclared:
    raise HTTPException(
        status_code=422,
        detail={
            "error": "undeclared_variables",
            "message": f"SOP 正文使用了未声明的变量：{undeclared}，请在 ## 变量 章节中声明",
            "undeclared": undeclared,
        }
    )

# ③ 同一事务写入 variable_schema（与 tree_json 一起）
await sop_repo.update(id, tree_json=tree_json, variable_schema=variable_defs)

# ④ 响应体追加
return {
    ...,
    "variable_count": len(variable_defs),
    "warnings": [f"变量 '{v}' 已声明但未在正文中使用" for v in orphan_warnings],
}
```

### pending_variable_name 流程

```
LLM 调用 sop_request_variable("vm_name")
  → strategy=user_input：
      1. SET sop_execution.pending_variable_name = "vm_name"
      2. yield AgentInteractiveRequest(kind="variable_input", variable_name="vm_name")

      7. 恢复 LLM 推理
```

## T-AGT-26：三路合并（SOP 重新导入后变量池维护）

### 背景与问题

```
【背景】
§12.7.4 Q2：SOP 内容更新后重新 approve，变量 Schema 需要与旧版合并，
绝对禁止覆盖人工编辑的字段（source、description、acquisition_strategy 等）。
```

### 任务目标

实现三路合并策略：
- 两版都有的变量 → **保留人工编辑的 Schema 字段，不覆盖**
- 新版新增的变量 → 自动添加，标记 `auto_generated=true`
- 旧版有但新版消失的变量 → **标记 `deprecated=true`，不删除**，管理端告警

### 涉及文件

| 文件路径 | 操作 | 说明 |
|---------|------|------|
| `backend/kb-service/app/services/sop_parser.py` | 修改 | 新增 `merge_variable_schema()` 函数 |
| `backend/kb-service/app/routes/admin.py` | 修改 | approve 时调用 merge（而非直接覆盖） |

### 依赖关系

- **前置任务**：T-AGT-24
- **后续任务**：T-AGT-28（管理端 UI 展示 deprecated 告警）

### 合并逻辑规格

```python
def merge_variable_schema(
    old_schema: list[dict],         # 旧版（可能含人工编辑）
    new_schema: list[dict],         # 新版（自动解析结果）
) -> tuple[list[dict], list[str]]:  # (merged_schema, deprecated_names)
    """
    三路合并规则：
    1. 两版都有 → 保留 old 的 description、acquisition_strategy、acquisition_tool、
                   validation_pattern（人工知识），更新 auto_generated=False
    2. 仅新版有 → 直接追加，auto_generated=True
    3. 仅旧版有 → 标记 deprecated=True，保留在列表中
    """
    old_by_name = {v["name"]: v for v in old_schema}
    new_by_name = {v["name"]: v for v in new_schema}
    deprecated = []
    merged = []

    # 新版变量（保留旧版人工字段）
    for name, new_var in new_by_name.items():
        if name in old_by_name:
            old_var = old_by_name[name]
            merged_var = {**new_var}
            # 保留人工编辑字段
            for human_field in ["description", "acquisition_strategy", "acquisition_tool",
                                 "acquisition_prompt", "validation_pattern"]:
                if old_var.get(human_field) is not None:
                    merged_var[human_field] = old_var[human_field]
            merged_var["auto_generated"] = False
            merged.append(merged_var)
        else:
            merged.append({**new_var, "auto_generated": True})

    # 旧版独有（标记 deprecated）
    for name, old_var in old_by_name.items():
        if name not in new_by_name:
            merged.append({**old_var, "deprecated": True})
            deprecated.append(name)

    return merged, deprecated
```

### 验收标准

| # | 验收项 | 通过标准 |
|---|--------|---------|
| 1 | 人工字段保留 | 重新 approve 后，人工编辑的 `description` 不被覆盖 |
| 2 | 新增变量追加 | 新版新增的变量出现在 `variable_schema` 中，`auto_generated=true` |
| 3 | 消失变量标记 | 旧版有但新版无的变量 `deprecated=true`，不删除 |
| 4 | 管理端告警 | approve 响应 `warnings` 包含 deprecated 变量名 |
| 5 | 单元测试 | `pytest tests/unit/test_sop_variable_merge.py` pass |
