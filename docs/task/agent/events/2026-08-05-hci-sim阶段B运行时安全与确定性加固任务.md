## 实现检查

- [x] JSON 使用 unknown-field 拒绝和语义校验，所有 limit 有硬上限。
- [x] parser 不执行 shell，不做 glob、变量展开、substitution 或重定向。
- [x] RouteKey 使用 variant/tool/acquisition key/argv/node/container，加载时拒绝歧义；Bundle 和工具/策略 revision 由 Lease 绑定。
- [x] 握手和每命令都验证 Lease；单副本内存 Store 的 expiry/revoke/quota 使用互斥锁原子操作。
- [x] exec、shell 和内建探针共享授权、配额、调度、telemetry 和 cleanup。
- [ ] timeout 不占普通 worker 长 sleep；queue、timer、goroutine 和输出均有界。
- [ ] chunk size、interval 和 fault seed 可复现并进入报告。
- [ ] Bridge 不再用 host substring 推断 simulation。
- [ ] metrics label 无 run/scenario/fixture 等高基数字段，日志不含 Lease/raw secret。

## 测试任务

- [ ] parser table/property/fuzz：引号、转义、NUL、换行、shell operators、等价 flag。
- [ ] 路由：强匹配、歧义、缺字段、node/container/variant 串线和未知 schema 字段。
- [ ] Lease：长连接跨 expiry、revoke、并发 quota、issuer/audience/mode/target 错误。
- [ ] channel：exec/shell/探针同语义，无旁路。
- [ ] fault：normal/nonzero/permission/timeout/disconnect/truncate 与 cancel 组合。
- [ ] 压力：queue 满、worker 饥饿、取消风暴、output overflow、连接断开清理。
- [ ] Bridge：host substring 反例、权威 mode、真实 SSH 回归。
- [ ] 运行 `go test -race`、fuzz smoke、vet/build、Manifest/Helm 门禁。

## 迁移与部署

1. 在测试环境双读或离线 lint v1/v2，但执行语义只能选择一个明确版本。
2. 发布支持 v2 的 Runtime，再发布 v2 Fixture；旧 v1 设定截止日期。
3. 多副本启用前必须部署 Redis Store 和原子配额测试。
4. 观察拒绝原因、fixture miss、queue、cancel、output 和真实 SSH 回归。
5. 无法保证安全时回滚镜像与 Fixture；不得通过关闭 Lease/校验恢复可用性。

## 阻断条件

- 阶段 A 未 Go；
- Lease 或 RouteKey 协议仍存在可选/模糊路径；
- exec/shell 无法统一或存在系统 shell 执行；
- timeout/cancel/overflow 会泄漏 worker、timer、session 或 goroutine；
- Bridge 真实/仿真语义仍依赖 host 猜测；
- 真实 SSH 回归或 telemetry 泄露敏感数据。
