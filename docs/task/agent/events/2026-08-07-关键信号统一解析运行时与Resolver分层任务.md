## 任务目标

建立唯一的 `Shared Resolution Runtime` 注册入口和统一生命周期，挂载领域 Resolver：

```text
LogResolver              qfk_log
SystemResolver           qfk_system
DomainResolver           qfk_vm/network/storage/hardware/platform
ServiceResolver          qfk_service
QkvResolver              qkv_alert/task/dialog
VariableResolver         HOST/END/VM 等变量
```

确保：

```text
LLM/专家原始字符串
  → SignalIntent
  → ResolutionPlan
  → ResolvedAcquisition
  → Executor
```

未经解析、验证和审计的输入不得进入执行器。

## 关键实现约束

### 1. 命令必须结构化为 argv

禁止直接把 LLM 输出作为命令字符串执行：

```text
错误：acli.vm.config.get
```

必须先编译为：

```python
["acli", "vm", "config", "get"]
```

最后一层才按执行器要求渲染命令文本。

### 2. Resolver 与 Executor 解耦

Resolver 只产生：

```text
ResolvedAcquisition
```

Executor 只执行已验证的 acquisition，不负责：

```text
纠错、猜路径、补全命令、识别未知命令
```

### 3. 生产门禁与消费校验共用实现

生产门禁调用：

```text
compile()
```

消费前校验调用：

```text
resolve()
```

二者不得各自复制一套近似的 Catalog、命令正则或路径规则。

### 4. 数据与算法分离

```text
Python：解析算法、状态机、探针和安全策略
Git Catalog：文件、命令、别名、布局、归档和参数声明
Database：草稿、审核、发布版本、运行审计和反馈
```

数据库草稿未经编译、审核和发布不得热改变执行语义。

## 验证计划

### 单元测试

- `acli.vm.config.get` → `acli vm config get`。
- 不存在命令 → `UNSUPPORTED_COMMAND`，执行器调用次数为 0。
- vtpdaemon 服务别名 → canonical filename。
- vtpdaemon D/DD、vt/根目录候选排序。
- `path=None`、空字符串和显式 path 语义一致。
- 多候选 → `AMBIGUOUS`。
- 未解析 `{{END}}` → `UNRESOLVED_VARIABLE`。

### 集成测试

- Mock HCI 能力探针返回不同 aCLI 版本。
- Mock 高/低版本白盒目录。
- Mock `.gz` 和 `tar.gz` archive handler。
- qfk_log/qfk_system/qfk_service 均通过同一 Runtime Registry 路由。
- 保存门禁编译结果与运行时解析结果使用相同 Catalog 版本。

### 真实 HCI 验证

- `acli --help` / domain help 能力探测。
- `/sf/log/D/vt`、`/sf/log/D`、today 和 gzip rotation。
- blackbox/vn-blackbox 日期归档和 tar member。
- `/sf/log/apache2`、`kafka`、`checkitem`、`sf-openapi` 的轮转/结构化文件形态，以及 `log_new.db` 的 SQLite schema 与 aCLI task/alert 交叉验证。
- `ResolvedAcquisition.absolute_path` 与现场实际文件一致。
- 目标文件轮转、跨天和 symlink 变化时不发生错误节点误查。

## 发布和维护流程

```text
Catalog 修改
  → compiler
  → schema/冲突/安全检查
  → fixture/版本矩阵
  → 真实 HCI canary
  → PR 审核
  → 发布 immutable catalog_version
```

新增普通命令、日志源或版本路径优先增加 Catalog 数据；仅当出现新协议或新解析语义时修改 Python Resolver。
