# KBD 截图证据与可执行诊断契约实施任务

## 对应方案

[KBD 截图证据、关键信号与可执行诊断契约方案](../../../solution/agent/events/2026-07-28-KBD截图证据与可执行诊断契约方案.md)

## 任务目标

在不破坏 KBD 人类叙事的前提下，将截图和文本转换为可追溯证据，把关键信号从 LLM 直出 JSON 升级为可编译、可回放的原子观察，并在其上建立轻量的案例验证契约，使 Agent 能对 KBD 输出 confirmed、rejected 或 inconclusive，而不是仅凭自然语言相似度推断。

实施必须始终保持以下三层知识边界：

- 操作性隐形知识由 QKV/QFK Tool Adapter 承载；
- 语义性隐形知识由 extract/assert、matcher 和 provenance 承载；
- 认识论隐形知识由 Case Verification Contract 的 scope、must/should/exclude 和失败语义承载。

任何实现如果重新把三层责任压回单次 LLM Prompt，或把 `UNKNOWN/ERROR` 压成证据不成立，均视为偏离方案，不得进入发布阶段。

## 当前实施结论（2026-07-29）

核心工程闭环已完成第一阶段并通过本地回归：截图上下文进入 `images_json`，Vision 结果形成 Evidence IR，信号抽取同时消费正文和截图观察事实，Schema、QFK Handler command-shape Build、变量 DAG、outcome-level Decision Replay、Coverage 与 Case Verdict 已连通。Case Verification Contract 作为 `signals_json` 的版本化扩展持久化，运行时输出 `confirmed/rejected/inconclusive`，不会把权限失败、超时或缺变量压成反证。后续真实执行器复核确认 Compiler 尚未调用 `ToolSemanticValidator`，raw observation Evidence Replay 与完整 Execution Replay 也尚未形成发布门，不能把该阶段概括为“真实执行全链路已通过”。

截图保真、生成版本和审核链路也已完成第一阶段落地：小 PNG 保留原始字节，超长文字截图按 1800 px、180 px 重叠切片，Evidence provenance 保存 tile 与源图 bbox；`generation_metadata` 持久化正文、Prompt、模型和全部 Signal/QKV/QFK Schema 指纹，正文/分类或 Vision Evidence 更新会将旧产物标为 stale，Playbook 与运行时 Compiler 会拒绝 stale 或工具契约版本不一致的产物；管理端已分栏显示上下文、Observed Facts、Inferences、质量、provenance、Signal source refs 和 stale 门禁。这里的 Tile 是可读性与坐标追溯能力，不等同于独立 OCR/Layout 或真实 UI region 检测。

## 文档与实现同步门禁

本任务涉及 Evidence、Signal、Contract、Compiler、Replay、Coverage 和 Verdict 等核心概念，任何代码或数据模型变更都必须同步维护权威方案文档，不能只在 PR 描述、对话或测试代码中出现新结论。

每个阶段关闭前检查：

1. **结论一致**：对话、方案、任务、代码注释和管理台文案不得给出互相冲突的职责定义；
2. **契约一致**：文档中的 JSON 示例必须与当前 Schema 和真实 Handler 同源；
3. **状态一致**：文档明确区分已确认事实、方案决策、待实施项和未决问题；
4. **示例可运行**：正式示例必须通过 Compiler/Replay，纯说明示例必须明确标注“非生产配置”；
5. **读者友好**：权威文档使用结论先行和渐进披露，原始代码审计下沉到后半部分或附录；
6. **内容完整**：不能为了简短删除决策依据、替代方案、风险、边界、验收或回滚；
7. **反向同步**：最终交付对话若形成文档中没有的新概念或更清晰结论，必须先回写文档再结束工作；
8. **变更历史**：现行全量文档和事件文档索引按管理规范更新。

推荐交付顺序：

```text
事实审计
→ 第一性原理模型
→ 方案比较与决策
→ 权威方案文档
→ 实施任务
→ 代码与测试
→ 验证报告
→ 对话摘要
→ 文档/对话差异复核
```
