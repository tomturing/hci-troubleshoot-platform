## P1 重要修复

### T-AGT-06：P4 `_build_sop_prompt()` 无 token 上限保护

#### 背景与问题

```
【问题】
_build_sop_prompt() 将完整 content_md 直接拼入 system prompt，无截断逻辑。
大型 SOP（>10000 字符）可能超出 LLM 上下文窗口，或大幅压缩对话历史空间，
导致输出质量严重下降（幻觉增多）或 API 返回 400 错误。
```

#### 任务目标

短期保护措施（长期方案见 T-AGT-22 导航工具化）：在 `_build_sop_prompt()` 中对 `sop_content` 按字符数截断，并追加截断提示。

#### 涉及文件

| 文件路径 | 操作 | 说明 |
|---------|------|------|
| `backend/agent-service/app/adapters/agents/htp/investigation_agent.py` | 修改 | `_build_sop_prompt()` 追加截断逻辑 |

#### 实现步骤

```python
# _build_sop_prompt() 中修改：
MAX_SOP_CHARS = 8000  # 约 2000 token，为对话历史留余量

def _build_sop_prompt(self, sop_content: str, ...) -> str:
    if len(sop_content) > MAX_SOP_CHARS:
        sop_content = sop_content[:MAX_SOP_CHARS]
        sop_content += "\n\n[注意：SOP 文档已截断，请基于已有信息分步推理，" \
                       "必要时通过工具获取更多细节]"
    ...
```

#### 验收标准

| # | 验收项 | 通过标准 |
|---|--------|---------|
| 1 | 截断生效 | 注入 system prompt 的 sop_content 字符数 ≤ 8000 |
| 2 | 截断提示 | 超长 SOP 时 prompt 末尾含 `[注意：SOP 文档已截断]` 字样 |
| 3 | 短 SOP 不截断 | 字符数 ≤ 8000 时 prompt 完整，无截断提示 |

### T-AGT-09：P2 SOP 路由加语义排序（短期：全文检索）

#### 背景与问题

```
【问题】
kb-service SOP 路由查询仅按 updated_at DESC 排序，
同分类下有多篇 SOP 时，返回的是最新修改的而非最匹配的。
```

#### 任务目标

短期方案：对 `content_md` 用 PostgreSQL `ts_rank` 全文检索排序。  
长期方案（独立迭代）：为 `sop_document` 加向量列，改用向量相似度排序。

#### 涉及文件

| 文件路径 | 操作 | 说明 |
|---------|------|------|
| `backend/kb-service/app/routes/route.py` | 修改 | SOP 轨查询加 `ts_rank` 排序 |

#### 实现步骤

```sql
-- 修改 route_by_category() 中的 SQL：
SELECT *, ts_rank(to_tsvector('chinese', content_md), plainto_tsquery('chinese', :query)) AS rank
FROM sop_document
WHERE category_id = :category_id AND status = 'published'
ORDER BY rank DESC, updated_at DESC
LIMIT :top_k
```

注意：需确认 PostgreSQL 已安装 `zhparser` 或使用 `simple` 配置。

#### 验收标准

| # | 验收项 | 通过标准 |
|---|--------|---------|
| 1 | 排序生效 | 多篇 SOP 时，`query` 关键词匹配度更高的排在前面 |
| 2 | 无性能回退 | 查询耗时 < 100ms（同等数据量） |
