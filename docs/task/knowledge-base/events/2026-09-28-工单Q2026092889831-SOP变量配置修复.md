## 📋 问题描述

### 故障现象

工单 Q2026092889831（内存 ECC 故障）在 SOP 执行过程中失败，具体表现：

1. Agent 匹配到 SOP 文档 ID=5（内存条 ECC）
2. 调用 `sop_request_variable(check_meth)` 和 `sop_request_variable(memory_tag)` 失败
3. 错误信息：`动态 Skill「memory-fault-detect」已执行，但未返回变量的可用值：请检查技能指令与 SOP 变量的 output_path 配置`
4. Skill 执行时 `context_variables` 为空，无法获取必要的系统数据（dmidecode、EDAC 计数等）

### 根因分析

**问题 1：SOP 变量配置缺失 `output_path`**

SOP 文档 ID=5 的变量 `check_meth` 和 `memory_tag` 配置如下：

```json
{
  "name": "check_meth",
  "type": "string",
  "source": "skill:memory-fault-detect",
  "description": "内存 ecc 检测结果"
  // ❌ 缺少 output_path 字段
}
```

Skill 执行后，系统不知道如何从输出中提取变量值，导致 `_extract_value()` 函数返回 `None`。

**问题 2：Agent 跳过 SOP 前置条件**

Agent 没有按照 SOP 前置条件的顺序执行：

- ❌ **实际行为**：直接调用 `sop_request_variable` 获取变量
- ✅ **预期行为**：先执行前置条件（获取告警、解析 node_ip 等），再获取变量

前置条件要求：
1. 执行 `acli alert get -k "内存"` 获取告警数据
2. 调用 `skill:hci-alert-parsing` 解析告警，获取 `node_ip` 和 `alert_type`
3. 如果 `node_ip` 不是本机，使用 ssh 连接到目标节点
4. 在目标节点上执行 `memory-fault-detect` Skill

系统提示词中没有明确强调必须先执行前置条件，导致 Agent 跳过了这些步骤。

---

## 🔧 修复方案

### 修复 1：SOP 变量配置（output_path）

为 SOP 文档 ID=5 的变量添加 `output_path` 字段：

```json
{
  "name": "check_meth",
  "type": "string",
  "source": "skill:memory-fault-detect",
  "description": "内存 ecc 检测结果",
  "output_path": "check_meth",
  "acquisition_tool": "memory-fault-detect",
  "acquisition_strategy": "skill_call"
}
{
  "name": "memory_tag",
  "type": "string",
  "source": "skill:memory-fault-detect",
  "description": "故障内存位置",
  "output_path": "memory_tag",
  "acquisition_tool": "memory-fault-detect",
  "acquisition_strategy": "skill_call"
}
```

**迁移脚本**: `database/data-migrations/038_fix_sop_variable_output_path.sql`

### 修复 2：系统提示词优化

更新 `s1_sop_react_new_v1` 系统提示词模板，添加【SOP 执行规范】章节：

```
【SOP 执行规范 - 必须严格遵守】
1. **前置条件优先**：进入 SOP 节点后，必须先检查并执行 prerequisites（前置条件）中列出的所有步骤
2. **前置条件通常包括**：
   - 获取相关告警数据（如 `acli alert get -k "关键字"`）
   - 解析告警获取关键信息（如调用 `skill:hci-alert-parsing` 获取 node_ip、alert_type）
   - 在目标节点上执行诊断命令（如果 node_ip 不是本机，需要使用 ssh）
3. **变量获取顺序**：只有在完成前置条件、context_variables 已填充必要数据后，才能调用 sop_request_variable 获取变量值
4. **禁止跳过前置条件**：不得直接调用 sop_request_variable 而跳过前置步骤，否则 Skill 将因缺少必要上下文数据而失败
```

**迁移脚本**: `database/data-migrations/039_update_sop_react_prompt_with_prerequisites.sql`
