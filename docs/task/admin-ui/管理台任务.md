## 2026-04-22 分类管理页面 Bug 修复记录

### 修复说明

`fix/category-manage-view-bugs` 分支，涉及文件：`frontend/admin/src/views/CategoryManageView.vue`、`backend/kb-service/app/repositories/category_repo.py`

| # | 问题 | 根因 | 修复方式 |
|---|------|------|---------|
| 1 | 分类详情中 SOP/KBD 列表始终为空 | 前端直接调用 `/api/admin/sop`、`/api/admin/kbd/pending` 等内部路径，api-gateway 未注册这些路径（404） | 改为走 api-gateway 统一入口：`/api/v1/sop`、`/api/v1/kbd/pending`（4 处路径全部修正） |
| 2 | 分类编码排序错误（如 虚拟机-010 排在 虚拟机-009 前） | SQL `ORDER BY c.code` 按字符串排序，数字部分补零位数不同时顺序错误 | `SPLIT_PART` + `LPAD` 实现自然数字排序，`get_all` 和 `get_all_active` 两处同步修改 |
| 3 | 分类详情标题行（分类详情 / 启用禁用 / 保存修改）三者高度不一致 | `.detail-header` 使用 `justify-content: space-between` 将三项均匀分布，radio 组被推到容器中央 | 改为 `gap: 16px` + 保留 `.detail-actions { margin-left: auto }` 推按钮靠右，标题与 radio 自然左对齐 |

## PR #200 分类详情页 UI 修复与 Markdown 渲染改进（2026-04-22）

涉及文件：`frontend/admin/src/views/CategoryManageView.vue`、`frontend/admin/package.json`

| # | 问题 | 修复方式 |
|---|------|---------|
| 1 | detail-header 标题/单选/按钮垂直对齐错位 | 消除 `.detail-form h3` 全局规则对 `.detail-title` 的 `padding-bottom` / `border-bottom` 影响，显式 reset |
| 2 | 分类命中次数（S0 路由计数）单独 form-item 展示，与文档命中次数（知识检索计数）语义混淆 | 合并入信息表第三行，重命名为"分类命中次数"并加 tooltip 说明区分含义 |
| 3 | 自写 Markdown 渲染器缺代码块/表格/嵌套列表支持，弹窗宽度不足 | 引入 `marked`（GFM 模式）+ `DOMPurify` 白名单清洗，外部链接补 `rel="noopener noreferrer"`；弹窗宽度改为 `min(960px, 90vw)`，采用 GitHub 风格排版 |
| 4 | `@types/marked` 废弃 stub 包（marked 自带类型）混入 dependencies | 移除 `@types/marked`，依赖整理为仅保留 `marked` + `dompurify` |
| 5 | tooltip 触发元素为不可聚焦 `<span>`，键盘/读屏不可达 | 改为 `<button type="button" aria-label="...">` + `:trigger="['hover','focus']"` |
