# KBD 管理列表页搜索栏布局与文案精简

**Goal:** 消除 KBD 管理列表页（`frontend/admin/src/views/KbdReviewView.vue`）搜索过滤栏的多余横向滚动条，精简搜索框占位文案，去掉与分页重复的「共 N 条」独立计数，并压缩「案例 ID」输入框与表格列宽到合理宽度。

**关联改动：** `KbdReviewView.vue` 过滤栏模板、主列表表格列、`.total-info` 样式。

---

## 根因：搜索栏横向滚动条

过滤栏 `el-row.filter-row` 内各 `el-col :span` 之和为
`3(案例ID)+4(标题)+3(样例集)+3(分类)+3(置信度)+3(状态)+3(责任人)+2(按钮)+3(共N条) = 27 > 24`。
Element Plus `el-row` 以 24 栅格为满宽基准，叠加 `:gutter="12"` 的负外边距，
span 总和溢出容器宽度即触发整条卡片的横向滚动条（表现为「重置」按钮被挤出可视区）。

## 处理

1. **删除「共 N 条」独立计数列**（`span=3`）：主列表底部分页 `el-pagination` 的
   `layout="total, sizes, prev, pager, next"` 已内置总数展示，搜索栏再放一份属重复。
   `total` ref 仍被分页 `:total="total"` 使用，删除展示不会使其成为孤儿变量。
2. **压缩「案例 ID」搜索输入框列宽**：`el-col :span` 由 `3` → `2`（5 位数字 ID 足够显示）。
   处理后 span 之和降为 `2+4+3+3+3+3+3+2 = 23 ≤ 24`，溢出消除，滚动条不再出现。
3. **精简占位文案**：去掉「按…搜索/检索」的冗余前后缀，只留关键提示——
   `按案例 ID 精准搜索 → 案例 ID`、`按标题关键字搜索 → 标题关键字`、`按样例集标识检索 → 样例集标识`。
4. **压缩表格「案例 ID」列宽**：`el-table-column width` 由 `100` → `84`（兼顾排序箭头与 5 位 ID）。
5. 清理随第 1 项失效的 `.total-info` 样式规则。

## 追加调整（2026-10-20）

- **案例 ID 输入框占位符再精简**：`案例 ID 精准 → 案例 ID`。该输入框本就只按案例 ID 做精确匹配，
  「精准」二字属多余说明，保留「案例 ID」即可自解释。

## 验证

- `pnpm --filter admin build`（vue-tsc 类型检查 + vite 构建）通过。
- `pnpm --filter admin test`（vitest 178 用例）全绿。
- 布局为纯展示调整，无数据/接口契约变更；新增或改动单列宽度不触发既有 spec。

## 通用教训

> **凡 `el-row` 内 `el-col :span` 之和可能超过 24 的过滤/工具栏，都会因 gutter 负边距溢出产生横向滚动条。**
> 新增过滤项时应复核 span 预算（含响应式换行需求），或改用 `el-space`/自适应 flex，而非机械累加 `:span`。
