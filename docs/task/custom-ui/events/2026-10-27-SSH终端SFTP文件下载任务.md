# SSH 终端 SFTP 文件下载任务

## 关联方案

[2026-10-27-SSH终端SFTP文件下载方案.md](../../../solution/custom-ui/events/2026-10-27-SSH终端SFTP文件下载方案.md)

---

## 背景

用户需求原话：

> 在 custom-ui 上面 ssh 终端下面新增一个 sftp 文件下载功能；支持在连接 ssh 后可以下载目的主机上的相关文件。

补充背景（用户澄清）：

> 现在是测试日志收集打包上传（包括直传和平台中转）功能有异常；但本身 acli 在 HCI 后台打包日志是没有问题的；现在就是需要把已打包好的文件直接下载到 terminal_bridge 运行的远程机上面即可；类似于 xshell 或者 mobaxterm 的文件上传下载功能。

因此不做“浏览器下载 / 平台制品中转”，而是新增 **HCI 主机 → bridge 所在机器** 的直连下载能力，交互形态为「路径输入 + 目录浏览」。

## 任务清单与执行记录

### T1：bridge 侧 SFTP 下载能力

- **文件变更**：`terminal_bridge/sftp.go`（新增）、`terminal_bridge/main.go`、`terminal_bridge/go.mod`、`terminal_bridge/go.sum`
- **内容**：
  - 新增 `github.com/pkg/sftp` 依赖，复用既有 `*ssh.Client` 开 subsystem（会话上懒加载缓存，会话关闭时一并回收）。
  - `sftp_op` 三种动作：`list` / `download` / `cancel`，下载跑在独立 goroutine，不阻塞交互式 shell 的消息循环。
  - 落盘目录按 `HCI_BRIDGE_SFTP_DIR` → `$HOME/Downloads/hci-sftp` → `/var/lib/terminal-bridge/downloads` → `$TMPDIR/hci-sftp` 探测可写项。
  - 文件名清洗（路径穿越、控制字符、Windows 保留名、结尾点空格、超长截断保留扩展名），同名文件不覆盖（同大小幂等跳过，不同大小加 `-2` 后缀）。
  - `.part` 临时文件 + 大小核对 + 原子 rename + SHA-256；中断重试自动续传。
  - SFTP subsystem 不可用时降级 `tail -c +N` exec 通道。
  - 并发上限 2、单文件上限 5 GiB（`HCI_BRIDGE_SFTP_MAX_BYTES`）、进度节流 200 ms、断连回收任务。
  - Prometheus 计数器 `bridge_sftp_downloads_total` / `bridge_sftp_download_errors_total`，14 个 `sftp.*` 结构化日志事件。
- **状态**：✅ 已完成，`gofmt` 干净，`go build` / `go vet` / `go test ./...` 全部通过。

## 已知边界

1. 远端文件在下载过程中被改写只做大小核对，不做 mtime/内容前置校验。
2. SFTP subsystem 不可用时目录浏览不可用，只能靠手动输入绝对路径下载（降级链路已明确提示）。
3. 桌面模式 `AllowedOrigins=*` 是既有风险面：本功能通过“落盘目录由 bridge 决定 + 文件名清洗”把风险收敛到“下载目录内写文件”，但不能防御用户被诱导下载。
4. 集群模式下文件落在 Pod 持久卷 `/var/lib/terminal-bridge/downloads`，取证/取文件仍需运维介入（Pod 侧无浏览器通路）。
