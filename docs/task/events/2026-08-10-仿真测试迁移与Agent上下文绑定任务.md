# 仿真测试迁移与 Agent 上下文绑定任务

对应方案：[仿真测试迁移与 Agent 上下文绑定方案](../../solution/events/2026-08-10-仿真测试迁移与Agent上下文绑定方案.md)

## 1. 交付拆分

```text
P0-1 控制面 API/状态机/权限
P0-2 Admin UI 仿真测试页面
P0-3 TestRun → Case/Conversation/Agent context 绑定
P1-1 K3s hci-sim Runtime/Bundle 扩展
P1-2 23821 full Bundle 与负向变体
P1-3 共享组件迁移与 Custom UI 清理
P2 运营、容量和长期回归
```

建议每个 P0/P1 子项独立 PR；页面迁移与 Custom UI 删除不得先于 Admin 新入口在 dev 可用。

## 2. P0-1：控制面 API 和状态机

- [ ] 定义 Build、BuildEvent、TestRun、Attempt、SimulationContext DTO 和错误码。
- [ ] 实现 KBD_ID 校验、published revision/capability gate、幂等 key 和并发锁。
- [ ] 实现 build 状态机：validating/resolving/compiling/registering/scheduling/probing/ready/failed/cancelled/stale。
- [ ] 实现 TestRun 状态机和唯一 binding 约束。
- [ ] 实现事件游标 API；日志包含 seq、stage、code、retryable、progress，禁止敏感字段。
- [ ] 增加 Admin 权限：build/run/view，服务端每次校验。
- [ ] hci_sim 控制面使用独立数据库连接，不写主库 hci-sim 表。

## 3. P0-2：Admin UI 页面

- [ ] 在 router 增加 `/simulation-tests`，meta title=“仿真测试”、图标和菜单顺序。
- [ ] 新增 KBD_ID 输入、环境构建按钮、开始测试按钮、状态卡、进度条。
- [ ] 构建中开始测试置灰；ready 才启用；failed 支持重试；expired/stale 禁用。
- [ ] 新增构建事件日志抽屉/面板：展开、折叠、关闭、游标加载、复制脱敏摘要。
- [ ] 页面刷新恢复 build/TestRun 状态和日志游标，不恢复 Lease password。
- [ ] 开始测试后弹出创建工单对话框；只让用户填写标题、描述，仿真连接信息只读/自动注入。
- [ ] 复用共享 SSH/工单表单组件，补齐 admin base `/admin/`、鉴权和错误处理。
- [ ] 增加前端单测、组件测试、无障碍键盘操作和超长日志渲染测试。

## 4. P0-3：TestRun → Agent Context

- [ ] TestRun ready 后生成不可变 SimulationContext，包含 scope、revision、digest、execution mode 和 virtual node。
- [ ] 实现 bind-case API，保证 case/conversation/test_run 一对一或明确重复绑定策略。
- [ ] Agent 请求时按 case/conversation 获取 context，并校验 TestRun 状态、digest/revision freshness。
- [ ] 将 context 注入独立命名空间，CDD scope evaluator 优先使用 sim context；禁止与真实 environment 混合。
- [ ] context 缺失/过期/real+sim 冲突时返回结构化 blocked reason，并在 Admin 页面展示。
- [ ] 增加审计：管理员、case、conversation、test_run、binding 时间和状态变更。
- [ ] 用最小 `qkv_task` route 验证 scope 不再 UNKNOWN，且 command 可实际进入 K3s Bridge/hci-sim。

## 5. P1-1：K3s hci-sim Runtime/Bundle 扩展

- [ ] 为 hci-sim 编译器增加 required Signal route completeness 检查。
- [ ] 将 positive-minimal 与 positive-full 明确区分，页面显示 Bundle variant 和验证边界。
- [ ] 为 qkv_task/qfk_log/qfk_system 统一定义 RouteKey、argv、输出、exit code、limits 和 digest。
- [ ] 为缺失 route、超时、非零退出、输出截断定义可预期结果。
- [ ] Runtime 与 Bridge 以同一 TestRun ID 关联 Lease、route 和 exec 日志。
- [ ] 增加 K3s Service/NetworkPolicy/Secret/health probe 验收。

## 6. P1-2：KBD 23821 full Bundle

- [ ] 固定 KBD 23821 revision 2、checksum、tool contract、policy revision。
- [ ] 编译 `kbd-23821-positive-full`：sig_001 产出 VM/HOST/END，sig_002 matcher satisfied，expert qfk_system satisfied。
- [ ] 编译 `kbd-23821-negative-ready-present`：ready 出现时结论 rejected/不支持，不得输出根因。
- [ ] 编译 `kbd-23821-inconclusive-missing-log`：required route 缺失/timeout 时结论 inconclusive。
- [ ] 对每条 route 做 payload digest、provenance、approval 和 immutable manifest ���验。
- [ ] 将 full Bundle 发布到 hci_sim 控制面后，重新运行 Agent E2E。

## 7. P1-3：共享组件迁移和 Custom UI 恢复

- [ ] 用 git 对比确定“仿真租约”PR 引入的 Customer UI 文件和行为变更集合。
- [ ] 把通用 SSH 连接、连接状态、错误码、Case 创建能力抽取到 shared/可复用包。
- [ ] 在 Admin UI 组合新流程，不复制 Customer UI 整个页面。
- [ ] 删除 Customer UI 仿真入口、仿真字段、Lease parser、推荐命令 UI 和相关状态/tests。
- [ ] 保留真实 SSH 流程、Windows Bridge 兼容路径和客户侧普通工单创建。
- [ ] 确认 customer-ui bundle、runtime-config 和路由中没有“仿真租约”文本/代码。
- [ ] 更新前端测试快照和文档，避免历史测试误要求 Customer UI 保留仿真入口。

## 8. P2：运维和回归

- [ ] Admin 页面支持最近构建/TestRun 筛选、过期清理和失败重试。
- [ ] 增加并发构建/租约配额、队列深度和 TTL 清理任务。
- [ ] 增加真实/仿真结果分开统计和报表导出。
- [ ] 增加 126 KBD capability matrix 批量回归入口；23821 作为第一条 full gold case。
- [ ] 增加 browser refresh、Bridge Pod restart、hci-sim restart、Lease expiry 端到端恢复测试。

## 9. 完成定义

- Admin 仿真测试页面可独立完成 build → run → case → Agent E2E；
- Customer UI 不含仿真入口且真实客户流程不回归；
- TestRun context、Bridge、hci-sim、Agent 日志可按同一 ID 关联；
- 23821 full positive/negative/inconclusive 变体均通过；
- 无 Custom UI、Windows Bridge、真实 HCI 依赖；
- 任务、接口、数据库、部署、验证和 README 现行文档已同步。
