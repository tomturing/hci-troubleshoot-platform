## 2. P0 技术 Spike

目标：在不改变生产执行路径的前提下，验证一个 KBD 的完整闭环。

- [ ] 创建最小 SSH 可登录的 hci-sim 镜像。
- [ ] 实现一个 `acli log get` 命令路由。
- [ ] 配置一个 positive 和一个 negative fixture。
- [ ] 使用现有 Terminal Bridge 的 `sim-ssh` 目标完成命令执行。
- [ ] 验证 stdout、stderr、exit_code、timeout 和 unknown fixture。
- [ ] 验证 Windows Bridge 和 WSL/K3s Bridge 都能连接。
- [ ] 验证 `trace_id -> exec_id -> fixture_id -> evaluation_id` 关联。
- [ ] 验证模拟模式不会修改真实 HCI 运行配置。

## 3. P1 hci-sim 运行时

### 3.1 SSH 与命令执行

- [ ] SSHD、用户、密钥和最小权限配置。

- [ ] 未知 command 返回 `fixture_not_found`，禁止空成功。

- [ ] chunk/delay profile。

### 3.2 场景隔离

- [ ] Stateless Router。
- [ ] Stateful Scenario Worker。

## 10. 并发验收矩阵

### 10.1 规模

- [ ] 1 场景基线。
- [ ] 10 场景。
- [ ] 50 场景。
- [ ] 100 场景。
- [ ] 200 场景压力上限。

### 10.2 隔离

- [ ] 相同 command、不同 scenario 返回不同 fixture。
- [ ] 相同 fixture、不同 variant 不串线。
- [ ] 相同 node_ip、不同 test_run 不串线。
- [ ] 一个场景 timeout 不影响其他场景。
- [ ] 一个场景 unknown fixture 不影响其他场景。
- [ ] 断开一个 SSH session 不影响其他 session。

### 10.3 输出

- [ ] stdout/stderr 分流。
- [ ] chunk 顺序一致。
- [ ] 大输出 bounded capture。
- [ ] output filter 正确。
- [ ] artifact hash 正确。
- [ ] 结果回传幂等。

## 11. 安全验收

- [ ] replay/sim-ssh 不能在 prod namespace 启用。
- [ ] NetworkPolicy 只允许 terminal-bridge 访问 hci-sim。
- [ ] fixture 未发布时不能被批量运行。
- [ ] lease 过期后命令失败。
- [ ] 未知 command fail closed。
- [ ] fixture 禁止任意 shell 注入。
- [ ] fixture 扫描 password/token/private key。
- [ ] 测试输出与生产指标隔离。
- [ ] ephemeral 场景资源自动清理。

## 12. 回滚边界

- hci-sim 和 scheduler 使用独立 Helm values，默认关闭。
- 生产 Terminal Bridge 默认保持 `ssh` 模式。
- fixture schema 或 scheduler 回滚不影响现有 KBD revision。
- KBD revision 保持不可变，测试场景引用旧 revision 时不改写原数据。
- 若 hci-sim 不可用，dev CI 应明确失败或跳过，不得自动切换真实 HCI。
