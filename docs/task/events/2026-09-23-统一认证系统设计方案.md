## 一、执行原则

1. **每阶段可独立回滚**：`AUTHN_ENFORCE_ADMIN` / `AUTHN_ENFORCE_CUSTOMER` 双 feature flag 独立控制，关闭即恢复匿名行为
2. **现有建单主链路零改动**：case-service 按 `client_id` UPSERT `user` → 建 `case` 的路径保持不变，认证只在其上叠加
3. **数据库变更走 Atlas 声明式**：`database/desired_schema.sql` 为单一真实来源，同步 `database/atlas-migrations/`，数据修复走 `database/data-migrations/`
4. **文档门禁同步**：每阶段合并时同步更新方案文档「影响范围」列出的现行全量文档
