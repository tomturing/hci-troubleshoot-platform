## Phase 0：立即修复

### T-EXEC-01：修复双通道 stderr 解析异常

- **优先级**：P0
- **文件**：`backend/agent-service/app/tools/acli/executor.py`
- **问题**：双通道分支存在 `stdout/stderr` 时没有定义旧变量 `output`，但 `exit_code != 0` 后仍执行 `output.lower()`，导致真实 stderr 被“结果解析失败”覆盖。

**改动要求**：

- 使用 `check_text = f"{stdout}\n{stderr}".lower()`。
- 单通道兼容分支继续保留。
- `exec_result_parse_error` 只用于真正的 JSON/结构异常，不覆盖合法 stderr。

**验收标准**：

- [x] `exit_code=2`、`stderr="xxx"` 的双通道结果返回 `ExecResult.stderr == "xxx"`。
- [ ] 页面工具卡片展示 `stderr`。（前端已有双通道渲染能力，本轮未新增前端回归截图）
- [x] 不再出现 `cannot access local variable 'output' where it is not associated with a value`。

### T-EXEC-02：补充双通道失败单元测试

- **优先级**：P0
- **文件**：`backend/agent-service/tests/tools/test_executor.py`

**测试用例**：

- Redis 回传 `{"stdout": "", "stderr": "invalid option", "exit_code": 2}`。
- 断言 `result.exit_code == 2`。
- 断言 `result.stderr` 包含 `invalid option`。
- 断言 `result.exit_code_meaning` 不因解析异常变为错误文本。

## Phase 1：`bash_exec` 容器化契约

### T-EXEC-03：更新 `bash_exec` 工具定义 schema

- **优先级**：P0
- **文件**：

- `database/seeds/01_tool_definitions.sql`
- 如存在运行时热更新脚本，同步更新对应 seed 或迁移脚本

**改动要求**：

- `bash_exec.parameters_schema.properties` 新增 `container`。
- `container.enum = ["asv-con", "vn-con", "vn-agent", "vs-cp-manager"]`。
- `required` 改为 `["container", "command", "reason"]`。
- `additionalProperties` 设置为 `false`。
- description 明确禁止在 `command` 内写容器进入命令。

**验收标准**：

- [x] DB seed 重放后 `bash_exec` schema 包含必填 `container`。
- [ ] Agent 启动后 `get_tools_for_llm()` 暴露的新 schema 与 DB 一致。

### T-EXEC-04：实现 `ToolSemanticValidator`

- **优先级**：P0
- **文件**：新增 `backend/agent-service/app/tools/acli/semantic_validator.py`

**职责**：

- 输入 `tool_name,args,tool_def,context`。
- 输出 `ValidationResult(ok, issues)`。
- 内置 `bash_exec` 和 `acli_exec` 的语义规则。

**`bash_exec` 规则**：

- 缺少 `container`：error。
- 非法 `container`：error。
- `command` 包含 `docker exec`、`kubectl exec`、`nsenter`、`acli`：error。
- `command` 为空或超长：error。
- 命中高危命令：交给 RiskClassifier，但语义校验可提前附加 warning。

**验收标准**：

- [x] 单元测试覆盖缺容器、非法容器、容器前缀注入、合法命令。
- [x] 校验结果包含稳定 `code`，便于指标统计。

### T-EXEC-05：实现容器执行命令构造器

- **优先级**：P1
- **文件**：新增 `backend/agent-service/app/tools/acli/container_exec.py`

**职责**：

- `ContainerCommandBuilder.build(container, command, node_context) -> BuiltCommand`
- 服务端拼装实际执行命令，禁止使用 LLM 拼出的容器进入前缀。
- 优先支持 aCLI `--container` + `system` 命令映射。
- 对无法映射的 Bash 命令，走受控 `ContainerExecAdapter`。
- 无法确认运行时则 fail-closed。

**验收标准**：

- [ ] 构造结果保留 `container`、`original_command`、`built_command`。（当前最小实现保留结构化参数并下发拼装命令，尚未抽象 `BuiltCommand`）
- [ ] 审计日志能记录拼装后的实际命令。
- [ ] 不支持的运行时返回明确校验错误，不执行。（待 `ContainerExecAdapter` 支持运行时探测）

## Phase 2：aCLI catalog 与执行前校验闭环

### T-EXEC-07：`acli_exec` 命令路径校验

- **优先级**：P1
- **文件**：`backend/agent-service/app/tools/acli/semantic_validator.py`

**规则**：

- 必须以 `acli` 开头。
- 全局参数位置合法。
- 去除 `--formatter/--cluster/--timeout/--force/--container` 后，命令路径必须命中 catalog。
- `acli ... --help` 和 `acli acli command list` 作为探索命令放行。
- `system` 命令如需要容器，应校验 `--container` 或结构化 `container`。

**验收标准**：

- [x] `acli storage disk list` 被拦截并提示不在 catalog。
- [x] `acli storage asan disk list` 通过校验。
- [x] `acli --formatter json vm list` 通过校验。
- [ ] `acli vm list --formatter json` 返回全局参数位置 warning 或 error（按实现策略确定）。

### T-EXEC-08：ReactEngine 校验失败自修正

## 手动验收场景

| 场景 | 输入 | 预期 |
|------|------|------|
| stderr 保留 | 双通道返回 `stderr` 且 `exit_code=2` | 页面显示真实 stderr |
| bash 缺容器 | `bash_exec(command="ps aux")` | 不执行，LLM 重新规划 |
| bash 合法容器 | `bash_exec(container="asv-con", command="ps aux")` | 执行前校验通过 |
| aCLI 不支持 | `acli storage disk list` | catalog 拦截 |
| aCLI 支持 | `acli storage asan disk list` | 校验通过并执行 |
| 工具管理错误 schema | 删除 `bash_exec.container` | 保存阻断 |
| SOP 命令不合法 | SOP 包含无容器 bash | 发布产生 validation issue |
