# SSH 输入路由与空工单日志丢失修复

## 背景

现网反馈两个现象（同一工单 Q2026101401683 复现）：

1. SSH 连接弹框停在「Bridge 未运行」引导态时，点「取消」没有任何反应，只能点右上角 X 关闭。
2. SSH 终端显示「已连接」，但输入任何命令都没有任何回显，也没有任何报错。

排查中额外发现一个日志链路缺陷：远端 `bridge_execution_logs` 比 bridge 本地日志文件少 14 条，
少的全部是 `bridge.startup` / `listening` / `WebSocket_请求` / `connected` / `disconnected`
这类「无 case_id 的生命周期事件」——恰恰是排查「Bridge 起不来/连不上」时最需要的证据。

## 根因

### 1. 取消按钮无反应（回归 #1221）

`SshConnectSection` 的取消按钮只 `emit('cancelled')`，而 `SshConnectDialog` 只把收尾逻辑挂在
`el-dialog @close` 上，从未监听 `cancelled`。抽取组件时把 `handleCancel()`（内部直接
`closeSshFlowDialog()`）搬进了 section，但「按钮 → 关框」这条连线丢了。

产物级证据：线上 `customer-ui` 的 `App-*.js` 中 `state-change` 出现 2 次（emit 声明在），
`onCancelled` 出现 0 次（父组件从未绑定）。

### 2. 终端输入被静默丢弃（回归 #1229）

`#1229` 为对齐日志收集，让浏览器在 `ssh_connect` 里带上 `node_ip`，bridge 的会话键因此变成
`caseID@nodeIP`；但 `ssh_input` / `ssh_inject_command` 仍只查 `sessionKey(caseID, "")`：

```go
case "ssh_input":
    defaultKey := sessionKey(msg.CaseID, "")
    if s := b.get(defaultKey); s != nil { s.send(msg.Data) }   // 查不到就什么都不做
```

查不到时既不回包也不写日志，于是「字打进去了、回车了、什么都没发生，日志里还干干净净」。

`acli_sync` / `log_collect` / `ssh_exec_process` 走 `resolveSession`（带 node_ip 精确匹配），
所以 acli 能装成功、日志收集能跑，唯独人手输入全丢。

数据库证据（`bridge_execution_logs`）：

| 时间 (UTC) | event | 关键内容 |
|---|---|---|
| 17:53:04.189 | `ssh.connected` | `key = Q2026101401683@172.28.24.129` |
| 17:53:04.343 | `bridge.resolveSession` | `精确匹配 key=Q2026101401683@172.28.24.129`（acli 通道命中） |
| 17:53:08.192 | `bridge.收到消息` | `type=ssh_input case=Q2026101401683 node=`（**node 为空**） |
| 17:50:58.401 | `ssh.output` | `timed out waiting for input: auto-logout`（PTY 活着但收不到按键） |

### 3. 空 case_id 生命周期日志永久丢失

四条机制叠加：

1. `publish` 只把事件推给「当时在线」的订阅者，无订阅者时仅落本地文件与环形缓冲；
2. `handle()` 中 `blog("bridge.connected")` 在 `addSubscriber` **之前**，连接自己的 connected 谁都收不到；
3. `setCase` 回放条件是 `e.CaseID == caseID`，把无 case_id 的事件全部排除，重连也补不回来；
4. 前端 `forwardBridgeLog` 在无 `currentCase` 时直接丢弃无 case_id 的条目。

同实例逐条比对：本地 seq 2063–2095（33 条），远端 seq 2077–2098（22 条）；
2077–2095 共 19 条 `event_id` 逐字相同（零丢包），缺的正是 2063–2076 这 14 条无 case_id 事件。

## 修复

### terminal_bridge

- `resolveInputSession`：输入专用解析器，顺序为
  精确键（`caseID@nodeIP`）→ 本连接 `activeKey`（最近一次 `ssh_connect` 的会话）→
  本连接所属工单会话 → 本工单唯一会话（多节点时不猜）。
  输入不触发自动建连（建连属于 exec 语义）。
- 解析失败不再静默：`blog("ERROR","ssh_input.session_missing", …)` + 回 `ssh_input_rejected`
  （3 秒节流）。**不回 `ssh_error`**，避免一条拒绝回包把已连接终端踢掉。
- `addSubscriber` 前移到 `blog("bridge.connected")` 之前，连接能收到自己的 connected。
- `setCase` 回放口径放宽：本工单全部事件 + 5 分钟窗口内无 case_id 的事件；
  新增 `deliveredThrough` 游标做增量回放，`bridgeSubscriber` 切换工单时重置。
  库侧有 `event_id` / `(bridge_instance_id, seq)` 唯一索引 + 入库 `ON CONFLICT DO NOTHING`，
  重复回放幂等。

### frontend/customer

- `SshConnectDialog` 绑定 `@cancelled`，按钮只负责关框，收尾统一由 `el-dialog @close` 单点执行
  （与 X / ESC 同路径，不重复断开、不重复导航）。
- `buildInputMessage` / `buildInjectCommandMessage` 增加 `node_ip`，发送侧传 `sshCurrentConfig.host`。
- `forwardBridgeLog` 无工单上下文时改为暂存（500 条上限 / 30 分钟 TTL），
  `currentCase` 建立后 `adoptOrphanBridgeLogs` 回填；`event_id`/`seq` 原样保留。
- 新增 `sshTerminalNotice`，`ssh_input_rejected` 只写终端提示，不参与连接状态机。

## 验证

- `terminal_bridge`：`go build ./...`、`go vet ./...`、`go test ./...` 全绿；
  新增 `ssh_input_routing_test.go` 覆盖带 IP 会话键命中、多节点不串台、
  空 case 事件回放窗口、增量回放不重复、游标不回退、`sessionKeyCase` 解析。
- 前端：`pnpm build`（`vue-tsc` 类型检查）+ `pnpm test`。
- 真机验收（必须）：连接 → 手敲 `ls` 有回显 → 断线重连 → 再敲仍有回显；
  同时确认 `acli_sync` 与 `log_collect` 未回归；弹框「取消」与右上角 X 行为一致。

## 影响面与注意事项

- 修复在 bridge 侧，**必须重建并重新分发** `terminal_bridge.exe`（桌面模式）
  与集群 Pod 镜像；只发前端无效。桌面端可据 `bridge_hello.message`（版本号）提示升级。
- 放宽回放后，每次重连会补回窗口内的无 case_id 事件；因库侧唯一索引 + `ON CONFLICT DO NOTHING`
  不会产生重复行，但前端「近期日志」环形缓冲会短暂变大，属预期。
