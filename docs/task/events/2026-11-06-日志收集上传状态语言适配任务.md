# 任务：上传状态（`upload_state`）判定语言无关

## 背景

PR #1445 把 `terminal_bridge/log_collect.go` 的进度解析改成语言无关，但**前端对解析结果
的语义判定**仍在硬编码中文。2026-11-06 21:10（北京）本地英文环境的实测回包：

```
parse_ok=true
status_text="Collect task has been completed!"
upload_url="http://acli.sangfor.com.cn:5888/"
upload_state="Success"
node_state=completed, hosts_count=1, percent=100
```

`frontend/customer/src/components/LogCollectPanel.vue` 有三处用中文字面量判断这段文本：

| 位置 | 旧判定 | 作用 | 英文下的后果 |
|------|--------|------|--------------|
| `applyNodeStage` | `/发送中\|上传中/` | 点亮步骤条的「上传」阶段 | `Sending` 不点亮，视觉上像卡在采集 |
| `deliveryEvidenceOf` | `includes('成功')` / `includes('失败')` | 自动对账推断 P1 是否交付 | `Success` 返回 undefined，拿不到交付证据，结果页会挂「上传到平台」 |
| `finishP1` | `!includes('成功')` 就抛错 | P1 收尾放行 | **`Success` 抛「日志服务器上传失败：Success，可改用 P2 中转」，任务无法标记完成** |

前两处是展示/对账退化，第三处是功能性阻断。

**为什么 21:10 那次验证没有暴露它**：当时只是打开面板对历史工单触发自动轮询
（12:50 UTC 之后 `log_collect.create` 事件 0 条），没有点「开始收集」，
因此 `finishP1` 未被调用。该次验证只覆盖解析层。

## 任务清单

### T1: 抽出语义归一化函数
- 描述：`frontend/customer/src/services/logCollectSync.ts` 新增
  `classifyUploadState()`（`delivered / failed / uploading / unknown`）与
  `isP1UploadDelivered()`。按词义判定，中英文共用一条路径。
- 设计约束：`failed` 必须最先判——英文 `Sending failed` 同时含 `sending` 与 `failed`，
  先判 uploading 会吞掉失败；`isP1UploadDelivered` 刻意保留旧语义，
  `upload_state` 缺失时放行，只有明确给了状态且非成功才阻断。
- 状态：已完成

### T2: 三处判定点统一复用
- 描述：`LogCollectPanel.vue` 的 `applyNodeStage`、`deliveryEvidenceOf`、`finishP1`
  全部改为调用上述函数，删除中文正则与 `includes('成功')`。
- 文件变更：`frontend/customer/src/components/LogCollectPanel.vue`
- 状态：已完成

### T3: 中文零回归 + 英文全分支单测
- 描述：`logCollectSync.spec.ts` 表驱动覆盖 18 组样本（中文成功/发送中/上传中/失败/错误，
  英文 `Success`/`Succeed`/`Completed`/`Sending`/`Uploading`/`In progress`/`Failed`/
  `Sending failed`/`401 Unauthorized`/`Timeout`，空值与乱文本），另测 `isP1UploadDelivered`
  的放行与阻断边界；`LogCollectPanel.spec.ts` 增加组件级用例，用英文 `Success` 回包
  断言补登 `delivery_status=delivered` 且不出现「上传到平台」入口。
- 状态：已完成
