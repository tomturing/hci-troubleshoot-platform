# 集成与安全门禁自守修复

前因文档：[主干后端门禁按影响范围收敛任务](./2026-09-16-主干后端门禁按影响范围收敛任务.md)

## 1. 现象

main 分支自 2026-09-22 10:14 起，`ci.yml` 的 push run 持续 FAILURE，断点精确落在
`e1e5bb4c`（#1065 WS 身份信任链对齐）合入时：

| 时间 | 提交 | ci.yml push run |
|---|---|---|
| 2026-09-21 18:18 | `b4d54e64` | success |
| 2026-09-22 10:14 | `e1e5bb4c`（#1065） | failure |
| 2026-09-22 11:02 | `d7bb3aa1`（#1066） | failure |

失败点为 `tests/integration/test_websocket.py`：`WebSocket rejected: identity cookie
missing or mismatched`。但这两笔合入在 PR 阶段看到的检查均为绿。

## 2. 根因

### 2.1 直接原因：#1065 的 WS 信任链未同步到集成测试

#1065 要求 WS 路径中的 `client_id` 必须与网关签发的身份 Cookie 一致（关闭自报
`client_id` 的 IDOR 通道），而集成测试仍以自报 `client_id` 直连，握手以 1008 拒绝。

### 2.2 门禁原因：集成/安全 job 挂在与本意不符的开关上

`integration-tests` 与 `security-tests` 在 PR 阶段的触发条件为
`needs.changes.outputs.unit_test_mode == 'full'`。`unit_test_mode` 由
`scripts/ci/resolve_pr_fast_test_targets.py` 产出，语义是「快速**单测**如何收敛」，
却顺带决定了两条**集成/安全**门禁是否执行。

该脚本只按「服务目录 → 测试目录」映射识别 Python 测试：

- #1065 变更集 → `targeted`（仅覆盖 `backend/api-gateway/tests/unit`）；
- 纯集成测试改动（如本次修复）→ `none`，理由是「本次 PR 未修改 Python 测试或后端源码」，
  尽管根级 `tests/integration/**` 正是由 `-m integration` 收集的用例。

于是形成两处空档：

1. **集成/安全门禁被单测收敛策略误关**，红灯在 PR 阶段不可见；
2. **PR 判据与 main push 判据不一致**（后者用 `backend_gate_required`，默认 `true`），
   同一份代码两阶段执行的门禁集合不同，差异只能在合入 main 后暴露。

用任意 PR 变更集喂该脚本即可本地复现判定结果：

```bash
git diff --name-only <base> <head> > /tmp/changed.txt
python3 scripts/ci/resolve_pr_fast_test_targets.py --changed-files /tmp/changed.txt
```

## 3. 修复清单

| # | 修复 | 状态 | 产物 |
|---|---|---|---|
| 1 | WS 集成测试改用网关签发的身份（`issue_identity`）构造路径与 Cookie | ✅ 完成 | `tests/integration/test_websocket.py` |
| 2 | 补充负向门禁：缺失 Cookie / 身份不匹配均须以 1008 拒绝握手 | ✅ 完成 | `tests/integration/test_websocket.py` |
| 3 | `changes` job 新增 `integration_tests_changed` / `security_tests_changed` 输出 | ✅ 完成 | `ci.yml` changes job |
| 4 | 两条 job 的 PR 条件增加「触及对应测试即无条件执行」 | ✅ 完成 | `integration-tests` / `security-tests` |

设计取舍：第 3/4 项只对触及 `tests/integration/**`、`tests/security/**`
（含服务内同名目录）的 PR 生效，不把所有后端 PR 拉回全量集成回归，避免显著拉长 CI 关键路径。

## 5. 遗留项

- 更彻底的收敛（例如让集成范围判定与单测范围判定共用同一份输入契约、统一 PR 与
  main push 的判据）尚未进行，本次仅按「改了哪类测试就跑哪类门禁」的最小语义收口。
- `unit_test_mode` 与门禁 job 的耦合关系仍存在，后续若新增同类 job，不应继续复用
  单测 mode 作为触发条件。
