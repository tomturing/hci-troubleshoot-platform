# KBD 任务管理命令与参数重构任务

## 目标

依据[方案事件](../../solution/events/2026-08-09-KBD任务管理命令与参数重构方案.md)，把 KBD 六阶段实现为一个统一任务管理器，清理旧参数和旧入口，并让运行计划、历史范围、阶段依赖和子任务状态可审计。

## 实施清单

- [x] 增加 `TaskMode`、阶段解析、重做状态解析和三选一参数校验。
- [x] 增加跨运行 `task-state.json` 账本和不可变 execution manifest。
- [x] 增加统一 `task` 入口及六个阶段便捷别名，恢复 `cli` 为统一任务模型的交互式前端。
- [x] 交互式任务范围按频率排序：手动 ID、历史 run-id、ID 文件、Excel；历史任务列出最近 10 个 manifest。
- [x] `--rework` 状态选择扩展为 `draft`、`published`、`rejected`、`archived`，支持多选。
- [x] 将阶段计划传入编排器；依赖阶段只在未满足时执行，失败依赖阻断下游。
- [x] 将 `rework` 传递到分类、Vision、Signal 抽取；空信号文档（`NULL`、`[]`、`{}` 或空 signals）均可进入正常抽取。
- [ ] 补充 Vision `seq` 级 item_states 的完整持久化（当前保留账本契约，等待服务端返回逐图结果）。
- [ ] 对 published rework 接入 maintenance working revision 的真实 API 闭环，并补充发布门禁集成测试。
- [x] 更新 CLI/数据管道手册和单元测试。
- [ ] 完成真实环境 1 条冒烟、5 条回归和故障注入验收。

## 验证清单

```text
pytest tests/unit/kbd
pytest backend/kb-service/tests
ruff check data-pipeline tests backend
git diff --check
```

验收时必须核对：计划摘要中的 requested/resolved/selected；默认、resume、failed、rework 的实际调用集合；依赖已成功时不重复调用；依赖失败时下游明确 blocked；`--run-id` 读取的是 manifest；Vision 逐图状态和 Stage 4 案例聚合一致。

## 完成定义

代码级改造和自动测试完成后，状态仍保持 `in_progress`，直到真实 Provider/数据库环境完成上述冒烟、回归和重做门禁验证；不能用单元测试结果替代现场验收。
