# 2026-09-23 信号下拉文案统一（变量检查 / 日志检查）

## 背景

测试反馈：KBD 审核页「新增信号」下拉中，`qfk_var` 与 `qfk_log` 显示为「变量」「日志」，
而同下拉的 qfk 家族其余项均为「XX检查」（系统检查 / 服务检查 / 虚拟机检查 / 网络检查 /
存储检查 / 硬件检查 / 平台检查）；「编辑信号」弹窗的「采集类型」下拉又是另一套
（qfk 家族全部不带「检查」）。两处文案不一致，且 `qfk_var` / `qfk_log` 缺少「检查」后缀。

## 修复

统一 `frontend/admin/src/views/KbdReviewView.vue` 两处下拉文案为同一套
「XX检查」命名：

- 新增信号下拉（`el-dropdown-item`）：`变量 qfk_var` → `变量检查 qfk_var`、
  `日志 qfk_log` → `日志检查 qfk_log`。
- 编辑信号「采集类型」下拉（`el-option`）：qfk 家族全部补「检查」后缀
  （变量检查 / 日志检查 / 系统检查 / 服务检查 / 虚拟机检查 / 网络检查 / 存储检查 /
  硬件检查 / 平台检查），与新增信号下拉完全一致。

## 影响面

- 纯展示文案改动，不改任何 `command` / `value` 值与业务逻辑；
- 全前端无测试断言这些 label 文本（已核对 admin 下所有 spec）；
- 「采集类型」下拉为 `filterable`，补「检查」后仍可按「变量」「日志」「系统」等
  关键词过滤。
