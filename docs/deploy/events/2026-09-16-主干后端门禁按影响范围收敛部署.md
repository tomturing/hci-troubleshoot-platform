# 主干后端门禁按影响范围收敛部署

对应方案：[主干后端门禁按影响范围收敛方案](../../solution/events/2026-09-16-主干后端门禁按影响范围收敛方案.md)；
现行发布流程见[发布指南](../发布指南.md)。

## 1. 生效方式

改动全部位于 `.github/workflows/ci.yml` 与 `scripts/ci/`，随分支合并到 main 立即生效，
**无需**镜像重建、Helm 变更、环境仓库同步或 ArgoCD 干预。判定发生在 `changes` job
（显示名 `docs-governance`）内，属于发布链最上游，下游 `prepare` /
`build-and-push` / `auto-deploy-non-prod` 逻辑均未修改。

## 2. 上线后观测点

在 Actions 中打开对应 run，按以下顺序核对：

1. `changes` job 的「解析主干后端门禁影响范围」step 日志：应打印
   `主干后端门禁范围：required / not-required` 与原因，并给出基线 SHA、HEAD SHA 与
   变更文件数。
2. `Lint` / `unit-tests` / `integration-tests` / `security-tests` 的结论：
   - 纯前端/文档 push 应为 `skipped`；
   - 含后端门禁输入的 push 应为 `success`。
3. `发布元数据产物` 与 `Prepare` 应正常 `success`（`skipped` 不再阻断）。
4. 端到端时长：纯前端 push 应降到「变更探测 + 镜像构建 + 晋级」量级（实测参照
   约 3 分钟，改前约 7 分钟）。

## 3. 风险与兜底

| 场景 | 行为 | 是否需人工介入 |
|---|---|---|
| 取不到发布基线或 diff 失败 | step 输出 `::warning::`，清单清空 → `required=true`，四个 job 全跑 | 否，观察告警即可 |
| 变更清单为空（例如重复推送同一 commit） | 回落到完整后端回归（不会跳过） | 否 |
| 判定结果与预期不符（该跑却没跑） | 立即用 **CI → Run workflow**（`workflow_dispatch`）手动触发：手动路径不走影响范围判定，始终执行完整后端门禁，可完成补偿 | 是 |
| 上一轮 push 的后端回归被取消 | 下一轮 push 的 diff 起点是"最近一次成功发布基线"，该段变更仍计入清单，`required` 保持 `true` | 否 |

## 4. 回滚方式

若判定出现误跳过并已影响发布可信度：

1. 用 `workflow_dispatch` 手动触发一次完整门禁，作为即时补偿；
2. 回滚 `.github/workflows/ci.yml` 中四个门禁 job 与发布链 job 的条件（恢复为
   `github.event_name == 'push' && github.ref == 'refs/heads/main'` 与三个测试
   job 必须 `success`），合并后立即恢复改前行为；
3. `scripts/ci/resolve_main_test_scope.py` 与单测可保留（不再被引用），或一并回滚。

回滚不影响已发布的镜像与环境仓库 tag：判定只决定"跑哪些检查"，不参与制品内容与
晋级目标的计算。

## 5. 常见误判排查

| 现象 | 排查方向 |
|---|---|
| 纯前端 push 仍跑了后端门禁 | 检查 `required=true` 的原因文本里报出的路径；该路径是否真的不在白名单内（例如混入了根级配置文件） |
| 该跳过却全跑，原因文本为"无法获得主干变更清单" | 检查 `resolve_release_baseline.py` 是否拿到基线（历史 run 是否全部失败/取消） |
| 后端变更却被判 not-required | 不可能发生的前提是白名单未被扩大；若有人扩大白名单，必须同步复核被加入路径是否被任一后端门禁步骤读取 |

## 6. 相关契约

- 判定脚本：`scripts/ci/resolve_main_test_scope.py`（白名单 + 失败关闭）
- 单测：`scripts/ci/test_resolve_main_test_scope.py`
- 基线来源：`scripts/ci/resolve_release_baseline.py`
- 被收敛的 job：`Lint`、`unit-tests`、`integration-tests`、`security-tests`
- 不受影响的发布链：`release-metadata`、`prepare`、`build-and-push`、
  `auto-deploy-non-prod`、`db-migrate` 相关 job
