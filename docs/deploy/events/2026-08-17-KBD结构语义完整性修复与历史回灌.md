# KBD 结构语义完整性修复与历史回灌

## 背景

Support 原文中的 `<pre>`、`<ol>`、图片及其相对顺序是不可丢失的事实。此前转换器先抽取普通文本、再补列表和图片，导致代码块内容/围栏丢失、有序步骤序号丢失，以及 Admin UI 中图片锚点相对步骤偏移。

本次修复采用第一性原理校验：以 Support 原始 HTML 为事实源，分别校验代码载荷哈希、图片序号、有序列表数量和 `ol/pre/img` 结构事件顺序；再用对抗性审查阻断无法表达或存在专家改动冲突的记录。

## 代码与门禁

- `data-pipeline/kbd/converter.py` 按 DOM 子节点顺序渲染段落、列表、代码块、图片和表格。
- `<ol start>`、`<li value>` 和嵌套列表保留真实序号。
- `<pre>` 使用动态长度 fenced code block；代码内容包含反引号时不会截断。
- `<pre>` 内嵌图片在代码围栏外保留图片锚点；行内包装图片也参与结构事件校验。
- 生产转换默认 `strict_integrity=True`，失败时写入 `cache/{support_id}/integrity.json` 并阻止写库。
- `data-pipeline/kbd/semantic_repair.py` 使用 Proposal 基线、当前稿、重新生成稿三方合并；冲突必须显式决议并绑定当前字段 SHA-256。
