# CI 发布链路按影响范围收敛部署

本次部署的是 GitHub Actions workflow 行为，不涉及 Kubernetes manifest 或运行中服务重启。

合并后，main push 将先在 `changes` job 生成镜像影响闭包：

1. 若没有业务镜像或 db-migrate 输入变化，发布构建与环境同步均 skipped；
2. 若只有一个业务服务变化，只构建并同步该服务；
3. 若只有 schema 输入变化，只构建并同步 dbMigrate；
4. 手动运行 `CI` 时强制全量构建，作为发布复核和回滚逃生路径；
5. `CI 时延基线报告（手动）` 可在 Actions 页面按需运行，输出最近已完成 run 的 Queue/执行/端到端 P50/P95。

操作员应在首次合并后检查 `CI / docs-governance` 的“生成最小镜像构建计划”日志，确认 matrix 与本次变更一致；若发现计划异常，不应手工补推单个 tag，而应通过手动 CI 全量构建并修复影响映射后再恢复自动路径。
