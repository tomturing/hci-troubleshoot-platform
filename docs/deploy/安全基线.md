# 安全基线：凭据管理与泄露处置

> 版本：v1.0
> 日期：2026-10-22
> 适用：所有部署形态（K3s / 单机 / 客户自建）
> 关联：[部署指南](./部署指南.md)、[配置契约清单](./配置契约清单.md)、[k8s 坑位](./pitfalls/k8s.md)

## 一、为什么有这份文档

本仓库是**公开仓库**。2026-10-22 的安全扫描发现两类真实凭据曾被写入代码或文档：

| 类型 | 曾出现位置 | 当前状态 |
|---|---|---|
| 默认管理员口令 | 种子文件注释、2 篇事件文档、CHANGELOG、pitfalls 示例 | 已全部脱敏 |
| aCLI 下载 `api_key` | `terminal_bridge/main.go` 默认常量、1 篇验证文档 | 文档已脱敏；代码常量待迁移（§四） |

**关键结论：脱敏不等于修复。**

明文一旦进入公开仓库（含 git 历史），必须视为**已泄露**。删除当前文件只是阻止继续扩散，唯一有效的补救是**轮换凭据**。

---

## 二、强制规则

1. 代码、SQL 种子、文档、注释、示例、CHANGELOG 中**禁止出现任何真实凭据**。
2. 示例只允许明显假值：`P@ssw0rd`、`<API_KEY>`、`sk-xxxx`。
3. 凭据只能通过部署时注入：Helm values / K8s Secret / 环境变量。
4. 进入日志的命令与响应必须脱敏（`redactCommand`）。
5. 提交前自查（§五），有命中即阻断。

---

## 三、轮换步骤（必须执行）

### 3.1 管理员口令

历史默认口令已公开，**所有现存部署升级后必须改密**，新部署不得复用历史值。

```sql
-- 1) 写入新的 argon2id 哈希（由 auth-service 工具生成，勿手写明文）
UPDATE user_credential
SET secret = '<new_argon2id_hash>', updated_at = now()
WHERE credential_type = 'password' AND identifier = 'admin';

-- 2) 递增 token_version，使已签发的 JWT 立即失效
UPDATE "user"
SET token_version = token_version + 1
WHERE user_id = '00000000-0000-0000-0000-000000000001'::uuid;
```

要点：

- 改密后必须验证旧口令已失效（用旧值登录应返回 401）；
- 初始口令只在部署时通过 Secret 注入，禁止写入仓库或部署文档。

### 3.2 aCLI 下载 `api_key`

- 向深信服侧申请**轮换**，旧 key 作废；
- 新 key 通过 `ACLI_DOWNLOAD_API_KEY` 环境变量或 `acli_url` 消息字段注入；
- 若短期无法轮换，至少确认该 key 仅具备下载能力、无其他权限。
